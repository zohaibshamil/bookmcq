📝 Transport Layer Introduction (9 MCQs)

Transport Layer Placement and Process-to-Process Communication

The transport layer occupies OSI Layer 4 and the corresponding transport layer of the TCP/IP architecture. It provides logical communication between application processes running on different hosts, extending IP host-to-host delivery with port-based endpoint identification. Depending on the protocol, it can provide segmentation, multiplexing, reliable sequencing, flow regulation, and congestion control. These services connect application requirements to the packet-delivery service supplied by the network layer.

Why IP Delivery Is Not Enough for Applications

IP identifies destination hosts and forwards packets, but it does not identify which application process should receive each payload or guarantee that data arrives intact and in order. A computer may run many network applications simultaneously, each with different timing and reliability needs. The transport layer supplies process addressing and optional delivery mechanisms without requiring applications to implement every network function themselves.

Port Selection, Encapsulation and Receiving-Process Delivery

An application submits data through a transport endpoint. The sender selects source and destination ports, adds a protocol-specific header, and passes the resulting segment or datagram to IP. At the destination, the transport protocol examines the header, identifies the receiving socket, and performs any supported validation, reassembly, acknowledgment, or recovery before making the data available to the application.

Tracing a TCP Transfer from Client to Web Server

Suppose a client at 192.0.2.10 uses source port 51500 to contact a server at 198.51.100.20 on port 443. TCP identifies the connection using both endpoint addresses and ports. If the application supplies 3,000 bytes and the illustrative MSS is 1,460 bytes, TCP may segment the stream into payloads of 1,460, 1,460, and 80 bytes.

Application Uses, Performance Benefits and Protocol Limits

Web transfers, email, remote login, streaming, and online games all rely on transport services, but they do not require identical behaviour. TCP adds ordered reliable delivery and congestion control at the cost of state, acknowledgments, and possible retransmission delay. UDP avoids connection setup and preserves datagram boundaries, but applications must handle any recovery or ordering they require.

Correcting Confusion About Layers and Transport Guarantees

'IP delivers data directly to an application' is incorrect: IP delivers packets to a host, and transport ports help select the process. 'Every transport protocol guarantees reliability' is false: UDP has no built-in retransmission or ordering. 'One application write always becomes one TCP segment' is false: TCP is a byte stream, and buffering, MSS, and network conditions influence segmentation.

Exam Focus: Layer Assignment, Ports and TCP Byte Numbering

Be able to locate transport functions at Layer 4, distinguish host-to-host from process-to-process delivery, and interpret source and destination ports. Compare TCP and UDP, identify where segmentation occurs, and explain how TCP sequence numbers count bytes rather than application messages. Questions may also ask you to distinguish flow control, which protects the receiver, from congestion control, which responds to network load.

Key Terms for Transport Layer Introduction

  • Port number - identifies a transport endpoint.
  • Segment - TCP transport data unit.
  • Datagram - independently framed UDP message.
  • Multiplexing - combines data from application endpoints.
  • Demultiplexing - delivers received data to a socket.
  • MSS - maximum TCP payload in a segment.

📝 All Transport Layer Introduction MCQs

Q1. Which layer of the TCP/IP model is situated between the application layer and the network layer?

A.Network layer
B.Transport layer ✅
C.Data Link layer
D.Physical layer
💡 Difficulty: easy | ✅ Correct: B

📖 Explanation: The transport layer is positioned directly above the network layer and directly below the application layer in the TCP/IP hierarchy. It handles end‑to‑end data transfer services for applications, making it the layer described in the question.

Q2. If a transport‑layer protocol provides connection‑oriented service, what effect does this have on data delivery compared to a connectionless protocol?

A.Guarantees ordering but no error detection
B.Provides best‑effort delivery with possible duplication
C.Eliminates need for flow control
D.Ensures ordered, reliable delivery with congestion control ✅
💡 Difficulty: medium | ✅ Correct: D

📖 Explanation: Connection‑oriented protocols, such as TCP, establish a session that tracks sequence numbers and acknowledgments, resulting in ordered and reliable delivery. They also implement congestion control mechanisms, unlike connectionless protocols like UDP, which offer best‑effort, unordered delivery without reliability guarantees.

Q3. Suppose two applications on the same host use the same transport‑layer protocol but different port numbers. How does multiplexing affect their ability to communicate simultaneously?

A.Multiplexing allows the transport layer to distinguish streams by port numbers, enabling concurrent communication ✅
B.Multiplexing merges the streams causing data interleaving
C.It requires separate network interfaces for each application
D.Multiplexing only works for connectionless protocols
💡 Difficulty: hard | ✅ Correct: A

📖 Explanation: Multiplexing combines data from multiple application processes into a single stream for transmission, tagging each segment with a unique port number. At the receiver, demultiplexing uses those port numbers to separate the streams, allowing both applications to operate concurrently without interference.

Q4. Which of the following statements correctly contrasts UDP with TCP?

A.UDP provides retransmission, TCP does not
B.TCP is connectionless, UDP is connection‑oriented
C.UDP offers no guarantee of delivery, while TCP provides reliable, ordered delivery ✅
D.TCP uses fixed‑size packets, UDP uses variable size
💡 Difficulty: easy | ✅ Correct: C

📖 Explanation: UDP is a connectionless protocol that does not guarantee delivery, ordering, or retransmission. TCP, on the other hand, establishes a connection and ensures that data arrives reliably and in order, employing mechanisms such as acknowledgments and retransmissions.

Q5. For a live video streaming application, which transport‑layer service is most critical to maintain smooth playback?

A.Strict reliability with retransmission
B.Low latency with minimal retransmission ✅
C.Congestion avoidance only
D.Strong flow control without regard to delay
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: Live video streaming prioritizes timely delivery; excessive retransmissions can cause buffering delays. Therefore, a transport service that minimizes latency and avoids unnecessary retransmission—while still providing enough reliability to handle occasional loss—is most important for smooth playback.

Q6. How does error control versus flow control differently influence the effective throughput of a TCP connection?

A.Error control reduces throughput by causing retransmissions; flow control limits throughput by restricting window size ✅
B.Both error and flow control increase throughput
C.Error control only affects latency, flow control only affects reliability
D.Flow control causes packet loss, error control prevents it
💡 Difficulty: hard | ✅ Correct: A

📖 Explanation: Error control detects corrupted segments and triggers retransmissions, which consume bandwidth and lower throughput. Flow control, implemented via the receive window, limits the sender’s rate to avoid overwhelming the receiver, directly capping the amount of data in flight and thus also affecting throughput.

Q7. According to the end‑to‑end principle, which responsibility should reside in the transport layer rather than the network layer?

A.Routing packets across multiple hops
B.Detecting and correcting bit errors in frames
C.Ensuring reliable data transfer between end hosts ✅
D.Managing physical media access
💡 Difficulty: medium | ✅ Correct: C

📖 Explanation: The end‑to‑end principle states that reliability and error recovery should be handled by the communicating end hosts. The transport layer provides mechanisms such as acknowledgments, sequencing, and retransmission to ensure reliable end‑to‑end delivery, whereas routing and media access are functions of lower layers.

Q8. Designing a new transport protocol for IoT sensors that require low power and occasional data bursts, which combination of features best satisfies these constraints?

A.Connection‑oriented, heavy flow control, and reliable delivery
B.Connectionless, minimal header overhead, and optional reliability ✅
C.Full congestion control, large windows, and strict ordering
D.Fixed‑size packets with mandatory acknowledgments
💡 Difficulty: hard | ✅ Correct: B

📖 Explanation: A connectionless design keeps header size small and reduces state maintenance, conserving power. Optional reliability lets sensors request acknowledgment only when needed, and minimal congestion mechanisms avoid unnecessary processing, matching the low‑power, bursty traffic characteristics of many IoT devices.

Q9. What is the relationship between multiplexing and demultiplexing in the transport layer?

A.Multiplexing combines multiple streams into one, demultiplexing separates them at the receiver ✅
B.They are unrelated processes
C.Demultiplexing occurs before multiplexing
D.Both refer to error detection mechanisms
💡 Difficulty: easy | ✅ Correct: A

📖 Explanation: Multiplexing aggregates data from several application processes into a single transport stream, assigning distinct port numbers. At the destination, demultiplexing uses those port numbers to separate the combined stream back into the original application streams, ensuring each process receives its intended data.
