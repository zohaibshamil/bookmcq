📝 Bidirectional piggybacking in data link layer

📖 From Data Communication and Networks • 23. Introduction to Transport Layer • 10 questions available

What is Bidirectional piggybacking in data link layer?

Although primarily a data link concept often discussed alongside transport reliability, bidirectional piggybacking improves efficiency by attaching an acknowledgment for received data onto an outgoing data frame, eliminating the need for separate acknowledgment-only transmissions when both parties are sending data simultaneously.

Q1. In a TCP connection, when the receiver has data to send back to the sender, how does piggybacking the ACK on that data segment affect the round‑trip time compared to sending a pure ACK?

A. Increases RTT because the combined segment is larger.
B. Decreases RTT because the ACK is delivered with the data without extra transmission. ✅
C. No effect on RTT; ACK timing is independent of data.
D. Causes RTT to be unpredictable due to variable segment sizes.

💡 Difficulty: easy | ✅ Correct: B

📖 Explanation:

Piggybacking merges the acknowledgment with an outbound data segment, so the receiver does not need to transmit a separate ACK packet. This eliminates one transmission round, allowing the acknowledgment to reach the sender sooner and effectively reducing the measured round‑trip time.

Q2. Suppose a sender transmits a window of 4 segments and the receiver acknowledges the first two using piggybacked ACKs, but the last two are lost. What is the most likely consequence for the sender's congestion control?

A. It will immediately reduce its congestion window to 1 MSS.
B. It will wait for a timeout before adjusting the window.
C. It will interpret the missing ACKs as duplicate ACKs and trigger fast retransmit. ✅
D. It will continue sending new data assuming the loss is negligible.

💡 Difficulty: medium | ✅ Correct: C

📖 Explanation:

When two consecutive ACKs are missing, the sender perceives duplicate ACKs for the same sequence number. TCP's fast‑retransmit algorithm interprets three duplicate ACKs as an indication of packet loss, prompting the sender to retransmit the missing segment and halve its congestion window, thereby reacting quickly without waiting for a timeout.

Q3. Consider a bidirectional TCP connection where both ends frequently have data to send. If each side always piggybacks its ACKs, which timing anomaly could arise, potentially leading to a deadlock?

A. Both sides wait for the other to send data before ACKing, causing indefinite postponement. ✅
B. The congestion window grows without bound due to constant piggybacking.
C. Sequence numbers become unsynchronized, leading to duplicate data.
D. The retransmission timer never expires because ACKs are always delayed.

💡 Difficulty: hard | ✅ Correct: A

📖 Explanation:

If both peers rely solely on piggybacked ACKs and neither has data to send, each will wait for the other to transmit a data segment before acknowledging the previously received data. This mutual waiting can stall the exchange indefinitely, creating a deadlock situation where no pure ACKs are sent to break the stalemate.

Q4. Compare pure ACK transmission with piggybacked ACK in terms of bandwidth utilization. Which statement best captures the difference?

A. Pure ACK uses more bandwidth because it adds an extra segment for each acknowledgment. ✅
B. Piggybacked ACK uses more bandwidth because it combines data and acknowledgment.
C. Both methods use identical bandwidth because ACK size is negligible.
D. Pure ACK uses less bandwidth because it can be compressed.

💡 Difficulty: easy | ✅ Correct: A

📖 Explanation:

A separate ACK packet consumes header space and payload overhead for every acknowledgment, adding to the total bandwidth used on the link. Piggybacking eliminates the need for a distinct ACK segment by attaching the acknowledgment to an existing data packet, thereby reducing the number of transmitted frames and saving bandwidth.

Q5. Evaluate the impact of piggybacking on TCP's delayed ACK algorithm. Which of the following statements is most accurate?

A. Piggybacking eliminates the need for delayed ACKs because acknowledgments are always immediate.
B. Delayed ACKs are still used; piggybacking simply allows the ACK to be sent within the delay interval when data is present. ✅
C. Piggybacking forces the receiver to send ACKs immediately, overriding the delayed ACK timer.
D. Delayed ACKs are disabled in any connection that employs piggybacking.

💡 Difficulty: medium | ✅ Correct: B

📖 Explanation:

The delayed ACK algorithm permits the receiver to wait briefly (typically up to 200 ms) before sending an ACK, hoping to piggyback it on outgoing data. When data is available within that interval, the ACK is attached to the data segment, satisfying both the delayed‑ACK timer and the piggybacking requirement without sending a separate ACK.

Q6. In a scenario where the round‑trip propagation delay is high, how does piggybacking influence the overall throughput compared to sending separate ACKs, assuming the same packet loss rate? Choose the most precise assessment.

A. Throughput improves significantly because the reduction in ACK packets cuts the number of transmissions, outweighing any added processing delay. ✅
B. Throughput remains unchanged because the bottleneck is the propagation delay, not the ACK overhead.
C. Throughput may degrade because piggybacked ACKs increase packet size, leading to higher probability of loss.
D. Throughput improvement is marginal; the main benefit is reduced header overhead, which is negligible at high propagation delays.

💡 Difficulty: hard | ✅ Correct: A

📖 Explanation:

When propagation delay dominates the link performance, each additional packet incurs a substantial time cost. By eliminating pure ACK packets, piggybacking reduces the total number of transmissions required for the same amount of data, thereby decreasing the time spent waiting for acknowledgments and boosting effective throughput despite any minor increase in packet size.

Q7. Apply the principle of piggybacking: If a receiver has no data to send, what mechanism does TCP use to still provide timely acknowledgments?

A. It discards the ACK until data becomes available.
B. It sends a pure ACK segment after a short timeout (delayed ACK). ✅
C. It forces the sender to retransmit the data to trigger an ACK.
D. It uses a negative acknowledgment (NACK) instead.

💡 Difficulty: easy | ✅ Correct: B

📖 Explanation:

When there is no outbound data to attach an acknowledgment to, TCP's delayed ACK timer ensures that a pure ACK is still transmitted after a brief waiting period (commonly up to 200 ms). This guarantees that the sender receives timely feedback even in the absence of piggybacked data, preserving reliability.

Q8. Synthesize how piggybacking interacts with flow control windows. Which statement correctly describes this interaction?

A. Piggybacked ACKs automatically increase the receiver's advertised window size.
B. The receiver can convey its current window size within the piggybacked ACK, allowing the sender to adjust its sending rate without extra packets. ✅
C. Flow control windows are irrelevant when piggybacking is used because acknowledgments are embedded.
D. Piggybacking disables the sliding window mechanism, requiring fixed-size transmissions.

💡 Difficulty: medium | ✅ Correct: B

📖 Explanation:

A piggybacked ACK can carry the receiver's advertised window field along with the acknowledgment number. This enables the sender to learn about the available buffer space without sending a separate window‑update segment, maintaining efficient flow control while still benefiting from reduced packet overhead.

Q9. When designing a custom transport protocol that adopts piggybacking, what key consideration must be addressed to avoid starvation of acknowledgments in low‑traffic scenarios? Choose the most comprehensive answer.

A. Implement a timer that forces a pure ACK after a maximum waiting period if no data is pending. ✅
B. Require the sender to always include a dummy payload to trigger piggybacked ACKs.
C. Disable piggybacking entirely and rely on separate ACKs for reliability.
D. Use a priority queue that always sends ACKs before data packets.

💡 Difficulty: hard | ✅ Correct: A

📖 Explanation:

In low‑traffic conditions, a receiver may wait indefinitely for outbound data to piggyback an ACK, leading to acknowledgment starvation. Introducing a timeout ensures that, after a predefined interval, the receiver transmits a standalone ACK, guaranteeing progress even when no data is available to combine with the acknowledgment.

Q10. According to the TCP specification, what is the default maximum delay before a receiver must send a pure ACK if it has no data to piggyback?

A. 100 ms
B. 200 ms ✅
C. 500 ms
D. 1 second

💡 Difficulty: medium | ✅ Correct: B

📖 Explanation:

TCP's delayed‑ACK algorithm specifies that a receiver may wait up to 200 ms for outbound data before sending a pure ACK. If no data arrives within this interval, the receiver must generate a standalone ACK to ensure the sender receives timely acknowledgment, preventing excessive retransmission delays.
