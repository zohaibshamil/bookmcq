What is Transition from IPv4 to IPv6?

The transition from IPv4 to IPv6 refers to the gradual migration process required because the two protocols are not directly compatible, necessitating special mechanisms to allow IPv4 and IPv6 networks and devices to coexist and communicate during the extended deployment period.

Q1. When a router converts an IPv6 compatible address ::0:0:0:0:0:0:192.0.2.1 to the IPv4 address 192.0.2.1 for UDP transmission, how does the UDP checksum get affected?

A. It is recomputed using the IPv4 pseudo‑header.
B. It remains the same because the extra zero bits do not change the checksum. ✅
C. It becomes zero and must be recalculated.
D. It is doubled due to the address length change.

💡 Difficulty: easy | ✅ Correct: B

📖 Explanation:

The UDP checksum uses a pseudo‑header that contains the source and destination addresses. In a compatible address the leading 96 bits are zero, forming six 16‑bit zero words that add nothing in one’s‑complement addition. Replacing the address with its IPv4 form therefore leaves the checksum unchanged.

Q2. A host embeds the IPv4 address 203.0.113.5 into an IPv6 mapped address. Which IPv6 representation correctly reflects this mapping?

A. ::ffff:203.0.113.5 ✅
B. ::ffff:0:203.0.113.5
C. ::ffff:0:0:203.0.113.5
D. ::ffff:0:0:0:203.0.113.5

💡 Difficulty: medium | ✅ Correct: A

📖 Explanation:

IPv4‑mapped IPv6 addresses use the prefix ::ffff:/96 followed directly by the IPv4 address. The canonical textual form therefore is ::ffff:203.0.113.5. Adding extra zero groups changes the prefix and no longer matches the defined mapped format, making option A the correct representation.

Q3. Suppose a packet traverses a router that replaces a source IPv6 compatible address ::0:0:0:0:10.0.0.1 with the IPv4 address 10.0.0.1. If the original TCP checksum was computed with the IPv6 pseudo‑header, which statement is true after conversion?

A. The checksum must be recomputed because the pseudo‑header length changes.
B. The checksum will be invalid unless the router also adjusts it by adding a constant.
C. The checksum remains valid because the 96 zero bits contribute nothing to the one's complement sum. ✅
D. The checksum becomes zero, forcing the receiver to ignore it.

💡 Difficulty: hard | ✅ Correct: C

📖 Explanation:

TCP checksum calculation includes the pseudo‑header, but the 96 leading zero bits of a compatible IPv6 address are grouped into six 16‑bit words that sum to zero. When the router swaps the address for its IPv4 form, those zero contributions disappear, yet they added no value originally, so the checksum stays valid.

Q4. Compare the size of a typical IPv6 unique local unicast site prefix (FC00::/48) with the IPv4 private block 10.0.0.0/8. Which statement is accurate?

A. Both provide 2^24 addresses.
B. IPv6 site prefix provides 2^80 addresses, far larger than IPv4's 2^24. ✅
C. IPv4 block provides more addresses.
D. They are equal.

💡 Difficulty: easy | ✅ Correct: B

📖 Explanation:

A /48 IPv6 prefix leaves 80 host bits, giving 2^80 possible addresses. The IPv4 private block 10.0.0.0/8 contains only 2^24 addresses. The disparity is enormous, making the IPv6 site prefix vastly larger; option B captures this difference correctly.

Q5. Evaluate the impact on routing when a host uses a link‑local IPv6 address (fe80::/10) versus a unique local unicast address (fc00::/7). Which best describes the difference?

A. Link‑local addresses are routable across the Internet, unique local addresses are not.
B. Both address types are confined to the local link, but unique local addresses can be aggregated for site‑wide routing.
C. Link‑local addresses are limited to a single physical or logical link, while unique local addresses can be routed within a private site but not beyond. ✅
D. Unique local addresses are deprecated, while link‑local addresses are the preferred private addressing scheme.

💡 Difficulty: medium | ✅ Correct: C

📖 Explanation:

Link‑local addresses are automatically scoped to the local link and are never forwarded by routers. Unique local addresses are intended for private intra‑site communication; they can be advertised within an organization’s routing domain but are not announced on the global Internet. Hence option C correctly captures the routing distinction.

Q6. An organization plans to allocate IPv6 multicast addresses from the block ff00::/8. They need a permanent group address that can be identified by any host without prior configuration. Which address format satisfies this requirement?

A. ff02::1 (link‑local all‑nodes multicast)
B. ff05::2 (site‑local all‑routers multicast)
C. ff0e::1 (global scope permanent multicast) ✅
D. ff00::1234 (reserved for future use)

💡 Difficulty: hard | ✅ Correct: C

📖 Explanation:

IPv6 multicast addresses start with ff00::/8, where the next 4 bits define scope. A scope value of 0xe indicates global scope, meaning the address is globally reachable and permanent. ff0e::1 therefore represents a global‑scope permanent multicast address usable by any host without configuration, making option C correct.

Q7. Apply the principle of checksum invariance to explain why a router can change a packet’s source from an IPv6 compatible address to an IPv4 address without altering the UDP checksum. Which principle is being used?

A. The checksum only depends on the payload, not the addresses.
B. Zero‑filled high‑order bits contribute a sum of zero in one's‑complement arithmetic. ✅
C. IPv4 and IPv6 use different checksum algorithms that happen to produce the same result.
D. The router recomputes the checksum automatically, preserving integrity.

💡 Difficulty: easy | ✅ Correct: B

📖 Explanation:

In one’s‑complement addition, groups of 16‑bit zeros add nothing to the total sum. IPv6 compatible addresses have 96 leading zero bits, which form six zero words. When those zeros are removed during conversion to an IPv4 address, the checksum remains unchanged because the removed bits contributed zero to the original sum. This invariance is the key principle.

Q8. Synthesize how the random 40‑bit global identifier in a unique local IPv6 address reduces the risk of address collision when two organizations independently generate the same /48 subnet. Which statement best captures this effect?

A. The 40‑bit identifier guarantees uniqueness because it is assigned by a central authority.
B. The probability of collision is \(1/2^{40}\), making accidental overlap extremely unlikely. ✅
C. Collisions are prevented by using the same prefix for all organizations.
D. The identifier is ignored by routers, so collisions are irrelevant.

💡 Difficulty: medium | ✅ Correct: B

📖 Explanation:

Each organization selects a 40‑bit random number to form its unique local subnet identifier within fc00::/7. The chance that two independent selections match is 1 in 2^40 (about one in a trillion), which is negligible. Consequently, the likelihood of two sites accidentally using the same /48 prefix is extremely low, ensuring practical uniqueness.

Q9. Using the concept of address translation, infer why IPv4‑mapped IPv6 addresses are preferred for communication from an IPv6‑only host to an IPv4‑only server, rather than using a compatible address. Choose the most accurate inference.

A. Mapped addresses embed the IPv4 address in the low‑order 32 bits, allowing the IPv6 host to recognize the need for IPv4 translation. ✅
B. Compatible addresses are reserved for DNS queries only.
C. Mapped addresses automatically trigger NAT64 translation, whereas compatible addresses do not.
D. Compatible addresses cannot be represented in the IPv6 header.

💡 Difficulty: medium | ✅ Correct: A

📖 Explanation:

IPv4‑mapped IPv6 addresses have the format ::ffff:0:0/96 followed by the IPv4 address, explicitly signalling that the destination is an IPv4 host. This clear embedding enables IPv6‑only systems and translation mechanisms (e.g., NAT64) to detect the need for IPv4 handling. Compatible addresses lack the 0xFFFF marker and are intended for IPv6‑to‑IPv6 traffic, making them unsuitable for IPv4‑only destinations. Option A captures this reasoning.
