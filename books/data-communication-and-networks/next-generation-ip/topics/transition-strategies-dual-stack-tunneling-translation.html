Q1. Which BGP message type is used to establish a TCP connection between two peers?

🔹 A. Open
🔹 B. Update
🔹 C. Keepalive
🔹 D. Notification

💡 Difficulty: easy | ✅ Correct: A

📖 Explanation:

The Open message is the first packet a BGP speaker sends after establishing a TCP connection. It carries parameters such as BGP version, autonomous system number, hold time, and optional capabilities. Successful exchange of Open messages confirms that the two routers are ready to begin BGP communication, making Open the correct choice.

Q2. Which discretionary BGP attribute indicates that a destination prefix is not aggregated and therefore contains a single network?

🔹 A. Atomic-aggregate
🔹 B. Aggregator
🔹 C. LOCAL-PREF
🔹 D. MED

💡 Difficulty: easy | ✅ Correct: A

📖 Explanation:

Atomic-aggregate is defined as a well‑known discretionary attribute whose presence signals that the advertised prefix represents a single, non‑aggregated network. It carries no value field, meaning its length is zero. Because it explicitly declares the prefix as not being the result of aggregation, the correct answer is Atomic‑aggregate.

Q3. If two received routes have identical LOCAL-PREF values, what attribute does BGP evaluate next to decide between them?

🔹 A. MED
🔹 B. AS_PATH length
🔹 C. Origin type
🔹 D. Aggregator

💡 Difficulty: easy | ✅ Correct: B

📖 Explanation:

When LOCAL-PREF values are equal, BGP proceeds to the next decision criterion, which is the length of the AS_PATH attribute. The route with the shorter AS_PATH is preferred because it indicates a path that traverses fewer autonomous systems, reducing potential policy complexity and risk. Hence, BGP examines AS_PATH length next.

Q4. Given the administrator’s assigned values of 400 for AS1→AS2→AS5, 300 for AS1→AS3→AS5, and 50 for AS1→AS4→AS5, which path will be selected if AS2 becomes unavailable?

🔹 A. AS1→AS2→AS5
🔹 B. AS1→AS4→AS5
🔹 C. AS1→AS3→AS5
🔹 D. No path

💡 Difficulty: medium | ✅ Correct: C

📖 Explanation:

The administrator’s preference ranking assigns the highest value to the path through AS2, followed by the path through AS3, and finally the path through AS4. If AS2 is unavailable, the next highest valued and still available path is AS1→AS3→AS5, making it the chosen route according to the described preferences.

Q5. An update message withdraws three prefixes and advertises one new prefix with identical path attributes. To later announce another new prefix with different attributes, the router must:

🔹 A. Add it to the same update message
🔹 B. Resend the same update with modified attributes
🔹 C. Wait until the next keepalive
🔹 D. Send a separate update message

💡 Difficulty: medium | ✅ Correct: D

📖 Explanation:

BGP permits a single UPDATE message to withdraw multiple destinations while advertising only one new destination (or multiple destinations sharing identical attributes). If a subsequent advertisement requires different path attributes, the router must generate a distinct UPDATE message, because a single UPDATE cannot carry two separate attribute sets. Therefore, a separate update is required.

Q6. Under what circumstance could a route with a shorter AS_PATH be preferred over another route that has a higher LOCAL-PREF?

🔹 A. Never, because LOCAL-PREF is evaluated before AS_PATH
🔹 B. If the higher LOCAL-PREF route is from an iBGP peer
🔹 C. When the shorter AS_PATH route also has a lower MED
🔹 D. If the router is configured to ignore LOCAL-PREF

💡 Difficulty: medium | ✅ Correct: A

📖 Explanation:

BGP always evaluates LOCAL-PREF before considering AS_PATH length. A route with a higher LOCAL-PREF will be chosen regardless of how many autonomous systems its path traverses. Consequently, a route with a shorter AS_PATH can never outrank a route with a higher LOCAL-PREF, making the situation impossible under standard BGP decision rules.

Q7. How does the Atomic-aggregate attribute differ from the Aggregator attribute in terms of the information they convey?

🔹 A. Atomic-aggregate indicates the prefix is aggregated, Aggregator indicates the prefix is not aggregated
🔹 B. Atomic-aggregate signals that the prefix is not aggregated, while Aggregator identifies the last AS and router that performed aggregation
🔹 C. Both attributes are optional and carry no mandatory information
🔹 D. Atomic-aggregate provides the AS number, Aggregator provides the IP address of the originating router

💡 Difficulty: easy | ✅ Correct: B

📖 Explanation:

Atomic-aggregate is a well‑known discretionary attribute that specifies the advertised prefix has not been aggregated, meaning it represents a single network. In contrast, the Aggregator attribute is optional and transitive; it records the autonomous system number and IP address of the router that performed the aggregation. Thus, the two attributes convey opposite aggregation states and different metadata.

Q8. Why does BGP employ four distinct message types (Open, Update, Keepalive, Notification) rather than a single generic message type?

🔹 A. To reduce packet size
🔹 B. To simplify router configuration
🔹 C. To separate session establishment, route advertisement, liveness checks, and error handling, making processing more efficient
🔹 D. Because TCP requires four message types

💡 Difficulty: medium | ✅ Correct: C

📖 Explanation:

BGP’s design separates concerns: Open messages negotiate session parameters, Update messages carry route advertisements and withdrawals, Keepalive messages confirm that peers are still reachable, and Notification messages report errors or terminate sessions. This modularity allows each message type to be processed independently, improves protocol robustness, and simplifies debugging, which is why multiple distinct message types are used.

Q9. When both LOCAL-PREF and MED are present in competing routes, which attribute has priority and why?

🔹 A. MED, because it reflects external distance
🔹 B. LOCAL-PREF, because it is evaluated before MED in the BGP decision process
🔹 C. Both are considered simultaneously
🔹 D. The attribute with the lower numeric value wins

💡 Difficulty: medium | ✅ Correct: B

📖 Explanation:

BGP’s best‑path algorithm first compares the LOCAL-PREF attribute; the route with the highest LOCAL-PREF is preferred regardless of MED values. Only after LOCAL‑PREFs are equal does BGP examine MED (Multi‑Exit Discriminator). Therefore, LOCAL‑PREF has priority because it is evaluated earlier in the decision sequence.

Q10. If two routes are identical in all attributes except that one includes an Aggregator attribute, how does this affect the BGP best‑path selection?

🔹 A. The route with the Aggregator attribute is preferred because it provides additional information
🔹 B. Both routes are considered equal; the Aggregator attribute does not influence selection
🔹 C. The route lacking the Aggregator attribute is discarded as incomplete
🔹 D. The router will select the route with the lower AS number

💡 Difficulty: hard | ✅ Correct: B

📖 Explanation:

The Aggregator attribute is informational; it records which AS performed the aggregation but does not influence the BGP decision process. When all other attributes are identical, BGP treats the routes as equal and proceeds to subsequent tie‑breaking steps (e.g., IGP metric, router ID). Consequently, the presence of an Aggregator attribute alone does not affect the selection.

Q11. What is the first attribute examined by BGP when selecting the best path among multiple routes?

🔹 A. AS_PATH
🔹 B. LOCAL-PREF
🔹 C. MED
🔹 D. Origin

💡 Difficulty: easy | ✅ Correct: B

📖 Explanation:

The BGP decision process begins by comparing the LOCAL‑PREF attribute, which is a locally assigned value reflecting administrative preference. The route with the highest LOCAL‑PREF is chosen before any other attribute (such as AS_PATH length or MED) is considered. Therefore, LOCAL‑PREF is the initial attribute examined.

Q12. If an Atomic-aggregate attribute is received with a non‑zero length field, what should a BGP speaker infer and how must it react according to the protocol?

🔹 A. Treat it as a normal attribute and ignore the length
🔹 B. Accept the attribute but log a warning
🔹 C. Consider the update malformed and discard the attribute
🔹 D. Replace the length with zero and continue

💡 Difficulty: medium | ✅ Correct: C

📖 Explanation:

According to RFC 4271, the Atomic‑aggregate attribute must have a zero‑length field because it carries no value. A non‑zero length indicates a malformed attribute. Consequently, a BGP speaker must treat the UPDATE as containing an invalid attribute, discard that attribute (and possibly the entire UPDATE), and may generate a Notification if required.

Q13. An administrator originally prefers the path AS1→AS2→AS5 (value 400) over AS1→AS3→AS5 (value 300). If the policy changes to prioritize security level of intermediate ASes over numeric values, which path is likely to be chosen?

🔹 A. AS1→AS4→AS5
🔹 B. AS1→AS3→AS5
🔹 C. AS1→AS2→AS5
🔹 D. No path is selected

💡 Difficulty: medium | ✅ Correct: C

📖 Explanation:

The narrative states that AS2 is regarded as the most secured AS for the administrator, while AS4 is the least secured. When security becomes the dominant criterion, the route traversing the most secure intermediate AS (AS2) will be favored regardless of its numeric value. Hence, the path AS1→AS2→AS5 remains the preferred choice.

Q14. When a BGP router receives routes from both eBGP and iBGP peers that are identical in all attributes, which tie‑breaking steps are applied in order until a single route remains?

🔹 A. Prefer the route with the lowest IGP metric, then the oldest route, then the router ID
🔹 B. Prefer the eBGP route, then the lowest IGP metric to the next hop, then the oldest route, then the lowest router ID
🔹 C. Prefer the route learned from the highest router ID, then the eBGP route
🔹 D. Prefer the route with the highest MED, then the eBGP route

💡 Difficulty: hard | ✅ Correct: B

📖 Explanation:

If all preceding attributes are equal, BGP first prefers routes learned via eBGP over iBGP, reflecting a bias toward external paths. If a tie still exists, it compares the IGP metric to the next‑hop router, choosing the lower metric. Subsequent tie‑breakers include the oldest route (based on timestamp) and finally the lowest router ID. This ordered sequence resolves the tie.

Q15. If a BGP UPDATE contains both an Aggregator attribute and an Atomic‑aggregate attribute for the same prefix, what does this indicate about the update's validity and how should the receiving speaker handle it?

🔹 A. The update is malformed because the two attributes are mutually exclusive; the speaker should discard the update
🔹 B. The Aggregator attribute overrides the Atomic‑aggregate attribute, so the prefix is considered aggregated
🔹 C. Both attributes are accepted, and the prefix is treated as aggregated
🔹 D. The speaker must send a Notification message with a Bad Update error

💡 Difficulty: hard | ✅ Correct: A

📖 Explanation:

Atomic‑aggregate declares that a prefix is not the result of aggregation, while the Aggregator attribute records information about a performed aggregation. Because these two attributes convey contradictory statements, their simultaneous presence violates the BGP specification, rendering the UPDATE malformed. The correct handling is to discard the update (or generate a Notification), as indicated.

Q16. If a BGP router receives an UPDATE that includes an unknown optional transitive attribute, what action should it take regarding that attribute?

🔹 A. Discard the entire UPDATE message
🔹 B. Ignore the unknown attribute and process the rest of the UPDATE
🔹 C. Treat the attribute as mandatory and reject the route
🔹 D. Send a Notification message immediately

💡 Difficulty: medium | ✅ Correct: B

📖 Explanation:

Optional transitive attributes are allowed to be passed along even if a router does not understand them. The proper behavior is to silently ignore the unknown attribute while still processing the remainder of the UPDATE. This ensures interoperability without causing unnecessary session termination or route loss.

Q17. Consider two routes with identical attributes except that one has a lower IGP metric to its next‑hop router. Assuming all previous BGP decision steps resulted in a tie, which route will be selected and why?

🔹 A. The route with the lower IGP metric, because BGP uses the IGP metric as the final tie‑breaker
🔹 B. The route with the higher IGP metric, as BGP prefers higher cost paths
🔹 C. Both routes remain tied and the router selects the one with the lowest router ID
🔹 D. The decision is made randomly

💡 Difficulty: hard | ✅ Correct: A

📖 Explanation:

When BGP reaches the final tie‑breaking stage, it examines the IGP metric to the next‑hop router. The route with the lower metric indicates a less costly path within the interior gateway protocol domain, and BGP selects it as the preferred route. Hence, the lower IGP metric determines the outcome.
