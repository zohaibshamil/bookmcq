What is SCTP flow control balloon memory manager?

SCTP employs a receiver-advertised window similar to TCP but enhances it with per-stream flow control and memory management strategies to balance buffer allocation across multiple streams and prevent starvation.

Q1. In the Selective Repeat (SR) protocol, what does the variable \(S_f\) represent?

A. The sequence number of the next packet the sender will transmit
B. The lower edge of the sender's sliding window ✅
C. The acknowledgment number expected from the receiver
D. The size of the sender's window

💡 Difficulty: easy | ✅ Correct: B

📖 Explanation:

The variable \(S_f\) marks the first sequence number within the sender's current sliding window. It is the lowest unacknowledged sequence number, so when an ACK with ackNo equal to \(S_f\) arrives, the window can slide forward. Therefore, \(S_f\) defines the lower edge of the sender's window, not the next packet to send or the window size.

Q2. When the sender in the ready state receives an error‑free ACK with ackNo = \(S_f\), which of the following actions is performed first?

A. The timer is stopped immediately
B. All outstanding packets are retransmitted
C. The window slides right until the first unacknowledged packet ✅
D. The sender moves to the blocking state

💡 Difficulty: medium | ✅ Correct: C

📖 Explanation:

According to the SR FSM, an ACK that matches \(S_f\) triggers a window slide. The protocol first moves the lower edge of the window to the next unacknowledged packet, effectively discarding all consecutive acknowledged packets. Only after the slide does the sender consider timer actions, making the slide the initial operation.

Q3. Which statement correctly distinguishes the timer handling between the ready and blocking states of the SR sender?

A. In both states the timer is never restarted after an ACK
B. In the ready state the timer is stopped only when no outstanding packets remain, whereas in the blocking state the timer is always restarted after any ACK
C. In the ready state the timer may be stopped when the window becomes empty, while in the blocking state the timer is restarted only after a timeout ✅
D. In the ready state the timer is always running, while in the blocking state it is started only after a timeout

💡 Difficulty: medium | ✅ Correct: C

📖 Explanation:

In the ready state, after processing an ACK the sender restarts the timer if there are still unacknowledged packets; if the window becomes empty the timer is stopped. In the blocking state, the timer is only touched when a timeout occurs, because ACK handling does not affect the timer unless the window slides. This distinction matches option C.

Q4. If a corrupted ACK arrives while the sender is in the blocking state, what does the SR protocol dictate?

A. The sender retransmits all unacknowledged packets immediately
B. The sender moves to the ready state
C. The timer is stopped
D. The ACK is discarded and no other action is taken ✅

💡 Difficulty: easy | ✅ Correct: D

📖 Explanation:

When an ACK is corrupted, the SR FSM treats it as invalid information. The protocol specifies that such ACKs are simply discarded, and no timer manipulation or retransmission is triggered. This behavior prevents unnecessary state changes or packet loss, ensuring that only valid acknowledgments influence the sender's operation.

Q5. How does increasing the sender's window size \(S_{size}\) affect the number of packets retransmitted after a timeout in the SR protocol?

A. A larger window may increase the number of retransmitted packets because more unacknowledged packets reside in the window ✅
B. Increasing the window size forces the sender to retransmit only the oldest unacknowledged packet
C. Larger window size always reduces the number of retransmissions to zero
D. Window size has no impact on retransmissions; only the timeout duration matters

💡 Difficulty: medium | ✅ Correct: A

📖 Explanation:

With a larger sliding window, more packets can be in flight simultaneously. If a timeout occurs, the SR sender must resend every packet that remains unacknowledged within the window. Therefore, a bigger window can lead to a higher count of retransmissions, contrary to the idea that a larger window automatically improves reliability.

Q6. If the current sequence number is \(S_n = 7\) and the modulus is \(2^m = 8\), what will be the next sequence number after incrementing?

A. \(S_n = 0\) ✅
B. \(S_n = 6\)
C. \(S_n = 8\)
D. \(S_n = 7\)

💡 Difficulty: medium | ✅ Correct: A

📖 Explanation:

The next sequence number is computed as \((S_n + 1) \bmod 2^m\). Substituting \(S_n = 7\) and \(2^m = 8\) gives \((7+1) \bmod 8 = 8 \bmod 8 = 0\). Hence the sequence wraps around to zero, which is represented by option A.

Q7. When the sender in the ready state receives an error‑free ACK with ackNo that corresponds to an outstanding packet but not equal to \(S_f\), what happens to the timer?

A. The timer is stopped
B. The timer continues unchanged
C. The timer is restarted ✅
D. The timer is reset to zero but not restarted

💡 Difficulty: medium | ✅ Correct: C

📖 Explanation:

For any ACK that acknowledges a packet still inside the window, the SR protocol restarts the timer if there remain other unacknowledged packets. Since the ACK does not equal \(S_f\), the window does not slide, but the timer must be refreshed to reflect the remaining outstanding packets, making option C correct.

Q8. Which of the following best explains why the Selective Repeat protocol can achieve higher throughput than Go‑Back‑N in the presence of occasional packet loss?

A. SR retransmits only the lost packet, while GBN must retransmit the entire window ✅
B. SR uses larger sequence numbers than GBN
C. SR does not require acknowledgments, unlike GBN
D. SR operates only on the receiver side, eliminating sender‑side delays

💡 Difficulty: hard | ✅ Correct: A

📖 Explanation:

Selective Repeat maintains individual acknowledgments for each packet, allowing the sender to resend only those that were lost or corrupted. In contrast, Go‑Back‑N treats any loss as a reason to resend all packets from the lost one onward, causing unnecessary traffic and lower throughput. This selective retransmission is the key efficiency gain.

Q9. Why does the receiver in the SR protocol never leave the ready state?

A. Because it never needs to store any packets
B. Because it only sends ACKs and never waits for timer events
C. Because its behavior is defined solely by packet arrival, which does not require a separate blocking state ✅
D. Because it has an infinite buffer and never experiences overflow

💡 Difficulty: easy | ✅ Correct: C

📖 Explanation:

The receiver's FSM is driven only by incoming packets. It stores correctly received packets, sends ACKs, and possibly delivers buffered data, but it never needs to wait for other events such as timers. Consequently, there is no need for a distinct blocking state, and the receiver remains in the ready state throughout operation.

Q10. Consider the following event sequence for the SR sender: (1) Window becomes full, moving to blocking state; (2) An error‑free ACK with ackNo = \(S_f\) arrives; (3) No more outstanding packets remain. After processing these events, which state does the sender occupy?

A. Ready state with timer running
B. Ready state with timer stopped ✅
C. Blocking state with timer running
D. Blocking state with timer stopped

💡 Difficulty: hard | ✅ Correct: B

📖 Explanation:

When the window is full, the sender enters blocking. Receiving an ACK that matches \(S_f\) slides the window; because all packets are now acknowledged, the sender has no outstanding data. The FSM rule states that after a slide, the sender returns to the ready state, and with no pending packets the timer is stopped, yielding option B.

Q11. If the receiver discards an error‑free packet whose seqNo lies outside its current window, what ACK does it send back to the sender?

A. An ACK with ackNo equal to the received seqNo
B. An ACK with ackNo set to zero
C. No ACK is sent
D. An ACK with ackNo equal to the next expected sequence number \(R_n\) ✅

💡 Difficulty: easy | ✅ Correct: D

📖 Explanation:

When a packet arrives outside the receiver's window, the SR protocol still sends an ACK indicating the lowest sequence number it is still expecting, namely \(R_n\). This informs the sender that the receiver's window has not advanced, prompting possible retransmission or window sliding. Therefore the correct ACK contains \(R_n\) as its acknowledgment number.
