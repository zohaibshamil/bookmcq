What is UDP datagram header format?

Definition:
The UDP header is a simple 8-byte structure consisting of four fields, each 2 bytes long. These fields are Source Port, Destination Port, Length, and Checksum. The Source and Destination Ports identify the sending and receiving applications. The Length field specifies the total length of the UDP datagram (header plus data). The Checksum provides basic error detection for the header and data, ensuring data integrity during transmission across the network.

Working:
When creating a UDP datagram, the sender fills in the source port (often dynamic) and destination port (well-known or registered). The Length field is calculated as \( 8 + \text{data length} \). The Checksum is computed over a pseudo-header (including IP addresses), the UDP header, and the data. If the checksum calculation results in zero, it is transmitted as all ones. The receiver verifies the checksum; if it fails, the datagram is silently discarded.

Example:
Suppose a DNS query is sent from client port \( 55000 \) to server port \( 53 \). The data payload is \( 40 \) bytes. The Length field will be \( 8 + 40 = 48 \) bytes. The header looks like: Source Port \( 55000 \), Destination Port \( 53 \), Length \( 48 \), Checksum (calculated value). This compact header allows quick processing by routers and endpoints, minimizing delay for time-sensitive DNS lookups that require rapid responses.

Reason:
The simplicity of the UDP header reduces processing overhead, enabling fast transmission. Including only essential fields (ports, length, checksum) keeps the header small. The checksum, while optional in IPv4, is mandatory in IPv6, providing basic error detection without the complexity of TCP's extensive error control mechanisms. This design aligns with UDP's goal of minimal latency and maximum efficiency for suitable applications.

Common MisConceptions:
Students often confuse the UDP Length field with just the data length; it includes the 8-byte header. Another misconception is that the checksum is always used; in IPv4, it can be set to zero (disabled), though this is discouraged. Some think UDP headers contain sequence numbers or acknowledgment fields, but they do not. Also, the pseudo-header used for checksum calculation is not transmitted but is essential for verification.

Exam Preparation Tips: How to prepare this topic
Memorize the four fields of the UDP header and their sizes (2 bytes each). Practice calculating the Length field given data size. Understand how the checksum is calculated using the pseudo-header. Compare UDP header size (8 bytes) with TCP header size (minimum 20 bytes). Learn why the pseudo-header includes IP addresses for checksum calculation. Review IPv4 vs. IPv6 requirements for UDP checksums.

Key Terms:

  • Source Port - 16-bit field identifying the sending application.
  • Destination Port - 16-bit field identifying the receiving application.
  • Length - Total length of UDP datagram (header + data) in bytes.
  • Checksum - 16-bit field for error detection of header and data.
  • Pseudo-Header - Virtual header used in checksum calculation, not transmitted.

📝 All UDP datagram header format MCQs

Q1. What is the range of well‑known port numbers defined for Internet services?

A.0–1023 ✅
B.1024–49151
C.49152–65535
D.1024–65535
💡 Difficulty: easy | ✅ Correct: A

📖 Explanation: Well‑known ports are reserved for standardized services and occupy the lowest range of port numbers, specifically from 0 up to 1023. This ensures that common protocols such as HTTP (port 80) and DNS (port 53) have predictable identifiers, while higher ranges are used for registered or dynamic ports.

Q2. A client sends a UDP datagram from source port 5000 to destination port 161. Which service is most likely being accessed?

A.Domain Name Service (DNS)
B.Simple Mail Transfer Protocol (SMTP)
C.Simple Network Management Protocol (SNMP) ✅
D.Hypertext Transfer Protocol (HTTP)
💡 Difficulty: easy | ✅ Correct: C

📖 Explanation: Port 161 is the well‑known port assigned to the Simple Network Management Protocol (SNMP). When a client directs a UDP packet to this port, it is typically interacting with an SNMP agent on the server, making SNMP the most probable service in this scenario.

Q3. Which statement best differentiates UDP from TCP regarding error handling?

A.UDP guarantees delivery, while TCP does not
B.TCP includes retransmission mechanisms, whereas UDP does not ✅
C.Both protocols use checksums, but only TCP uses acknowledgments
D.UDP uses flow control, TCP does not
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: TCP provides reliability through mechanisms such as acknowledgments, retransmissions, and flow control, ensuring lost or corrupted segments are resent. UDP, in contrast, offers only a checksum for basic error detection and does not attempt to recover from errors, leaving reliability to the application layer.

Q4. How many distinct socket addresses can be formed using the full IPv4 address space and all possible port numbers?

A.\(2^{48}\) ✅
B.\ (2^{64})
C.\(2^{32}\)
D.\(2^{16}\)
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: An IPv4 address consists of \(2^{32}\) possible values, and each port number adds \(2^{16}\) possibilities. The combination yields \(2^{32}\times2^{16}=2^{48}\) unique socket addresses, representing every possible pairing of host address and port.

Q5. If two different hosts each run a UDP server bound to port 8080, can a client on a third host communicate with both simultaneously without ambiguity?

A.Yes, because the destination IP distinguishes the servers ✅
B.No, because ports must be unique across the Internet
C.Only if the servers use different transport protocols
D.Only when NAT is disabled
💡 Difficulty: easy | ✅ Correct: A

📖 Explanation: Each UDP datagram is addressed by both a destination IP address and a destination port number. Even though the port number is identical, the differing IP addresses uniquely identify the two server processes, allowing the client to target either one unambiguously.

Q6. When a UDP packet traverses a NAT device, which component of the socket address is most likely to be altered?

A.Source IP address
B.Destination port number
C.Destination IP address
D.Source port number ✅
💡 Difficulty: medium | ✅ Correct: D

📖 Explanation: Network Address Translation rewrites the source information of outbound packets so that multiple internal hosts can share a single external address. Typically, the source IP address and source port number are replaced with the NAT’s public IP and a newly allocated external port, preserving the destination unchanged.

Q7. To add ordered delivery to a UDP‑based protocol, which additional header field is essential?

A.Checksum
B.Window Size
C.Acknowledgment Number
D.Sequence Number ✅
💡 Difficulty: hard | ✅ Correct: D

📖 Explanation: Ordered delivery requires the receiver to know the intended position of each datagram. Introducing a sequence number field enables the application to detect out‑of‑order arrivals and reorder them appropriately, a capability absent from standard UDP which lacks any sequencing mechanism.

Q8. If a UDP application implements stop‑and‑wait with a 5 % packet loss probability, what is the expected total number of transmissions required to successfully deliver a single datagram?

A.1.05 ✅
B.1.1
C.1.2
D.1.25
💡 Difficulty: hard | ✅ Correct: A

📖 Explanation: The expected number of transmissions for a success probability of \(1-p\) is \(1/(1-p)\). With a loss probability \(p=0.05\), the expectation is \(1/0.95\approx1.0526\), which rounds to about 1.05 transmissions on average for each datagram.

Q9. Which statement best reflects the security impact of using dynamic (private) ports versus well‑known ports for a client application?

A.Dynamic ports are less likely to be blocked by firewalls, reducing exposure
B.Well‑known ports are more vulnerable because they are targeted by attackers ✅
C.Using well‑known ports for clients simplifies auditing and improves security
D.Dynamic ports hide the application identity, making intrusion detection harder
💡 Difficulty: hard | ✅ Correct: B

📖 Explanation: Well‑known ports are publicly documented and frequently scanned by attackers looking for vulnerable services. By using dynamic, privately allocated ports for client‑side communication, the application reduces its visibility to opportunistic scans, thereby lowering the likelihood of targeted attacks.

Q10. In UDP communication, how do the destination IP address and destination port number together determine the server process that receives the datagram?

A.The IP address selects the network interface, while the port selects the transport protocol
B.The IP address identifies the host, and the port identifies the specific process on that host ✅
C.Both values are combined into a single identifier that the OS uses to route the packet
D.The port number overrides the IP address when multiple processes listen on the same host
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: The destination IP address pinpoints the target host on the network, while the destination port number pinpoints the particular application or process listening on that host. Together they form the unique socket address that the operating system uses to deliver the incoming UDP datagram to the correct server process.
