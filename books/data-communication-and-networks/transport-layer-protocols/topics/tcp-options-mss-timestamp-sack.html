What is TCP options MSS timestamp SACK?

TCP options extend functionality beyond the base header, including Maximum Segment Size (MSS) negotiation, timestamps for RTT measurement and PAWS protection, and Selective Acknowledgment (SACK) for efficient recovery from multiple losses.

Q1. If the send window size is 3 (which is less than 2^m) and all three acknowledgments are lost, what does the receiver do when the sender retransmits the three packets?

A. Discard them as duplicates ✅
B. Accept them as new data
C. Send NACKs
D. Ignore them

💡 Difficulty: easy | ✅ Correct: A

📖 Explanation:

Because the receiver’s expected sequence number after the loss is 3, the retransmitted packets carry sequence numbers 0‑2, which are outside the current window. Go‑Back‑N discards any packet whose sequence number does not match the next expected one, treating them as duplicates. Hence the three packets are correctly discarded.

Q2. In the Go‑Back‑N protocol, what is the size of the receive window?

A. 0
B. 1 ✅
C. 2
D. Equal to the send window

💡 Difficulty: easy | ✅ Correct: B

📖 Explanation:

Go‑Back‑N specifies a receive window of size one because the receiver only needs to keep track of the single next expected sequence number. Any out‑of‑order packet is discarded, simplifying the protocol and ensuring that the receiver processes packets in strict order.

Q3. When the send window size equals 2^m and all acknowledgments are lost, why does the receiver accept the duplicate packet 0 as new data?

A. Because its expected sequence number wraps around ✅
B. Because the timer resets
C. Because the receiver's window size increases
D. Because the sender changes its sequence numbers

💡 Difficulty: medium | ✅ Correct: A

📖 Explanation:

When the send window reaches the maximum value 2^m, the sequence numbers wrap around to zero. Because the receiver’s expected sequence number also wraps, the duplicate packet 0 aligns with the next expected value, so the receiver treats it as the first packet of the new cycle rather than a duplicate.

Q4. Compare the outcomes for send window sizes of 3 and 4 under identical ACK‑loss conditions. Which statement correctly describes the difference?

A. Both discard duplicates
B. Window‑3 discards, window‑4 accepts as new ✅
C. Window‑4 discards, window‑3 accepts
D. Both accept as new

💡 Difficulty: medium | ✅ Correct: B

📖 Explanation:

With a window of 3 (<2^m) the receiver expects packet 3 after the loss, so the retransmitted packets 0‑2 are out of range and discarded. With a window of 4 (=2^m) the receiver’s expectation wraps to 0, causing the duplicate packet 0 to be accepted as the start of the next transmission cycle, which is erroneous.

Q5. How do cumulative acknowledgments help when ACK 2 is lost but ACK 3 arrives in a Go‑Back‑N session?

A. They cause retransmission of packet 2
B. They implicitly acknowledge packets 2 and 3 ✅
C. They reset the timer
D. They indicate a channel error

💡 Difficulty: medium | ✅ Correct: B

📖 Explanation:

Cumulative acknowledgments mean that ACK 3 implicitly confirms receipt of all preceding packets, including packet 2. Therefore, even though ACK 2 is lost, the arrival of ACK 3 informs the sender that both packets 2 and 3 have been successfully received, avoiding unnecessary retransmission.

Q6. If the sequence number field uses m bits, what is the theoretical maximum send window size, and how does increasing m affect the probability of the error described in the text?

A. Maximum is 2^m‑1; larger m reduces error probability ✅
B. Maximum is 2^m; larger m increases error probability
C. Maximum is 2^m‑1; larger m does not affect error probability
D. Maximum is 2^m; larger m reduces error probability

💡 Difficulty: hard | ✅ Correct: A

📖 Explanation:

The maximum send window in Go‑Back‑N is \(2^{m}-1\) because the sequence number space must contain one unused value to differentiate new transmissions from old ones. Increasing the number of bits m enlarges this space, reducing the chance that the window reaches the critical \(2^{m}\) boundary where the error described can occur.

Q7. In a scenario where the forward channel is reliable but the reverse channel loses ACKs, what role does the sender’s timeout mechanism play in maintaining correct data delivery?

A. It prevents any retransmission
B. It triggers retransmission only after all packets are sent
C. It ensures lost ACKs are compensated by resending unacknowledged packets ✅
D. It disables Go‑Back‑N operation

💡 Difficulty: hard | ✅ Correct: C

📖 Explanation:

When ACKs are lost on the reverse path, the sender’s timer acts as a safety net. If the timer expires before an acknowledgment arrives, the sender retransmits the unacknowledged packet(s). This mechanism ensures that lost ACKs do not result in permanent data loss, preserving reliability despite the unreliable reverse channel.

Q8. If the sender’s timer expires after sending a duplicate of packet 0 while the receiver’s window expects packet 0 in the next cycle, what is the most likely result?

A. The packet is discarded as a duplicate
B. The packet is accepted as new data ✅
C. The receiver sends a NACK
D. The session is terminated

💡 Difficulty: medium | ✅ Correct: B

📖 Explanation:

Because the receiver’s window has wrapped and now expects packet 0, the duplicate transmission of packet 0 is interpreted as the first packet of a new cycle rather than a duplicate. Consequently, the receiver accepts and delivers it as new data, which can lead to data duplication if the original packet was already processed.
