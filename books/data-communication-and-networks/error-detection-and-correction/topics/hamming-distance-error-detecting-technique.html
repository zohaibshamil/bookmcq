What is Hamming Distance Error Detecting Technique?

Hamming distance is a metric used to measure the number of differing bit positions between two codewords, and establishing a minimum Hamming distance within a code defines its theoretical capacity to detect and correct a specific number of errors.

📝 All Hamming Distance Error Detecting Technique MCQs

Q1. What operation is performed on the final sum to obtain the checksum in the traditional checksum algorithm?

A. One's complement addition
B. Two's complement addition
C. One's complement (bitwise NOT) ✅
D. Left shift by 1

💡 Difficulty: easy | ✅ Correct: C

📖 Explanation:

The checksum is formed by taking the bitwise complement (one's complement) of the accumulated sum, so the correct operation is the one's complement of the sum.

Q2. If a single 16‑bit word in a message is altered during transmission, will the traditional checksum detect the error?

A. Detected only if error changes parity
B. Not detected if error is zero
C. May go undetected if error cancels with another error
D. Always detected ✅

💡 Difficulty: medium | ✅ Correct: D

📖 Explanation:

A single‑word error changes the total sum, so after complementing the receiver obtains a non‑zero checksum, causing the message to be rejected.

Q3. Compared with a cyclic redundancy check (CRC), the traditional 16‑bit checksum

A. Detects all burst errors up to length 16
B. Is computationally heavier
C. Detects fewer error patterns and is weaker ✅
D. Cannot detect single‑bit errors

💡 Difficulty: medium | ✅ Correct: C

📖 Explanation:

A CRC is designed to detect a wider variety of error patterns, including many burst errors, whereas a simple checksum can miss some errors, making it less robust.

Q4. Which characteristic of the Fletcher checksum allows it to catch transposition errors that the traditional checksum cannot?

A. Use of one's complement arithmetic
B. Truncation to 16 bits
C. Adding overflow back into the sum
D. Weighting each word by its position index ✅

💡 Difficulty: hard | ✅ Correct: D

📖 Explanation:

The Fletcher algorithm multiplies each data word by its position (or accumulates running sums), so swapping two words changes the weighted total and the checksum, revealing the transposition.

Q5. Two different messages produce the same checksum value. What can be inferred about the transmission?

A. At least one error went undetected ✅
B. The messages are identical
C. The checksum algorithm failed entirely
D. Both messages have even parity

💡 Difficulty: medium | ✅ Correct: A

📖 Explanation:

Identical checksum values for distinct messages indicate that the error pattern was not captured by the checksum, meaning an error could have occurred without being flagged.

Q6. If one 16‑bit word is increased by \(k\) and another is decreased by \(k\) before checksum calculation, what is the effect on the resulting checksum?

A. The checksum changes by \(2k\)
B. The checksum remains unchanged ✅
C. The checksum becomes the complement of \(k\)
D. The checksum becomes zero only when \(k=0\)

💡 Difficulty: hard | ✅ Correct: B

📖 Explanation:

Because the addition and subtraction cancel each other, the overall sum fed into the complement operation is the same as without the modifications, leaving the checksum unchanged.

Q7. Using one's complement addition, what is the checksum for the two 16‑bit words \(0x1234\) and \(0xABCD\)?

A. 48896
B. 24079
C. 49663
D. 16894 ✅

💡 Difficulty: easy | ✅ Correct: D

📖 Explanation:

Adding the words gives \(0x1234+0xABCD=0xBE01\). The one's complement of \(0xBE01\) is \(0x41FE\), which is the checksum transmitted with the data.

Q8. A transmitted message differs from the received one by a Hamming distance of 2. Can the traditional checksum always detect this error?

A. It always detects the error
B. It may fail because the checksum is a linear function ✅
C. It detects only if the checksum word itself is altered
D. It detects only if both errors occur in the same 16‑bit word

💡 Difficulty: hard | ✅ Correct: B

📖 Explanation:

The checksum is linear with respect to bitwise addition; two independent bit flips can cancel each other's effect on the sum, so a distance‑2 error is not guaranteed to be caught.

Q9. What is the main difference between wrapping overflow (adding left and right halves) and simply truncating the sum before complementing?

A. Truncating loses the carry bit entirely
B. Both methods yield identical checksums
C. Wrapping is only used in CRC calculations
D. Wrapping preserves the modulo \(2^{16}\) property of one's complement addition ✅

💡 Difficulty: medium | ✅ Correct: D

📖 Explanation:

In one's complement arithmetic, any carry out of the most‑significant bit is added back to the least‑significant bit, effectively performing a modulo \(2^{16}\) operation and ensuring correct checksum behavior.

Q10. If after adding all 16‑bit words the intermediate sum equals \(0xFFFF\), what is the final checksum transmitted?

A. 65535
B. 65534
C. 0 ✅
D. 1

💡 Difficulty: medium | ✅ Correct: C

📖 Explanation:

The algorithm complements the sum; the one's complement of \(0xFFFF\) is \(0x0000\), so the checksum sent is all zeros, which the receiver interprets as a valid message.

Q11. Why is the accumulator variable for the sum defined as 32 bits while each data word is only 16 bits?

A. To store two checksums simultaneously
B. To accommodate possible overflow during addition ✅
C. To enable left‑shift operations
D. To match network byte order

💡 Difficulty: easy | ✅ Correct: B

📖 Explanation:

During the addition of many 16‑bit words, carries can propagate beyond 16 bits; using a 32‑bit accumulator prevents loss of these overflow bits before they are wrapped back.
