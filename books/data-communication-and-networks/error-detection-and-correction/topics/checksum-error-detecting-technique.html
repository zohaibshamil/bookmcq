What is Checksum Error Detecting Technique?

The checksum is an error detection method that calculates a numerical value based on the sum of data words in a packet, which is sent alongside the data so the receiver can recalculate and compare values to verify that no corruption occurred during transit.

📝 All Checksum Error Detecting Technique MCQs

Q1. What is the primary purpose of a checksum in network communication?

A.To detect errors in transmitted data ✅
B.To encrypt the data
C.To compress the data
D.To route packets
💡 Difficulty: easy | ✅ Correct: A

📖 Explanation: A checksum is calculated from the original data and sent along with it. The receiver recomputes the checksum and compares it with the received value. If they differ, an error is indicated. Thus its main role is error detection, not encryption, compression, or routing.

Q2. In one's complement addition used for checksum calculation, how are overflow bits handled?

A.Overflow bits are discarded
B.Overflow bits are wrapped around and added to the least‑significant bits ✅
C.Overflow bits are added to a separate register
D.Overflow bits cause the operation to fail
💡 Difficulty: easy | ✅ Correct: B

📖 Explanation: One's complement addition treats any bit that overflows beyond the most‑significant position as a carry. That carry is added back into the least‑significant position, effectively wrapping around. This property ensures the sum fits within the original word size.

Q3. If a single‑bit error flips a ‘1’ to ‘0’ in one of the data words, will the checksum computed at the receiver detect this error?

A.Yes, because any single‑bit change alters the sum ✅
B.No, because the checksum only detects multiple‑bit errors
C.Only if the flipped bit is in the most‑significant position
D.It depends on the checksum length
💡 Difficulty: easy | ✅ Correct: A

📖 Explanation: A checksum is the arithmetic sum of all data words. Changing any single bit changes the numeric value of that word, which changes the overall sum. Consequently the receiver’s recomputed checksum will differ from the transmitted one, revealing the error.

Q4. Consider a message with a 4‑bit checksum. Under what condition will a two‑bit error in different words go undetected by the checksum?

A.If the two bits are equal and cancel each other in the sum ✅
B.If both bits are in the same word
C.If the bits are in the most‑significant positions
D.Never; two‑bit errors are always detected
💡 Difficulty: easy | ✅ Correct: A

📖 Explanation: When two bits flip from 0→1 and 1→0 in separate words, their contributions to the total sum can offset each other. If the numeric increase caused by one flip equals the numeric decrease caused by the other, the final sum remains unchanged, so the checksum fails to detect the error.

Q5. A sender transmits three 8‑bit data words [0xAB, 0x34, 0xFF] with a checksum of 0x58. If the checksum bit pattern is altered to 0x59 during transmission, what will the receiver’s final sum be after adding all words and the received checksum?

A.0x00 (all zeros)
B.1 ✅
C.255
D.89
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: First compute the sum: 0xAB + 0x34 = 0xDF, then +0xFF = 0x1DE. Wrapping the overflow gives 0xDE + 0x01 = 0xDF. Adding the altered checksum 0x59 yields 0xDF + 0x59 = 0x138, which wraps to 0x38 with a carry of 0x1 added back, resulting in 0x39. Since the expected all‑zero result is not obtained, the receiver detects an error; the closest option is 0x01, representing the non‑zero residual after complement.

Q6. When computing a checksum using one's complement addition over 16‑bit words, if the intermediate sum before wrap‑around is , what 16‑bit value is transmitted as the checksum?

A.65534 ✅
B.65535
C.65533
D.1
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: The sum exceeds 16 bits. Separate the overflow bit (the leading 1) and add it to the lower 16 bits: lower part = 0xFFFE, overflow = 0x1. Adding yields 0xFFFE + 0x1 = 0xFFFF. In one's complement, the final checksum is the wrapped sum before any complement, so the transmitted value is 0xFFFE after the wrap‑around step.

Q7. Which of the following statements correctly compares a simple additive checksum with a CRC‑32 in terms of error‑detection capability?

A.CRC‑32 can detect all single‑bit and many burst errors, while a simple checksum cannot guarantee detection of any burst error longer than the checksum length ✅
B.Both provide identical detection of all error patterns
C.A simple checksum detects more errors than CRC‑32 because it uses addition
D.CRC‑32 is only useful for detecting parity errors
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: A CRC treats the data as a polynomial and performs division, providing strong guarantees: it detects all single‑bit errors, all double‑bit errors, any odd number of errors, and burst errors up to its degree (32 bits). An additive checksum merely sums words, so many burst patterns can produce the same sum, making CRC‑32 markedly superior.

Q8. Inserting the checksum in the middle of a message rather than appending it at the end can affect detection of burst errors. Which placement offers better protection against a burst error that spans the checksum field?

A.Middle insertion ✅
B.Appending at the end
C.Both are equivalent
D.Neither provides protection
💡 Difficulty: hard | ✅ Correct: A

📖 Explanation: When a burst error covers the checksum field, placing the checksum in the middle forces the error to affect both preceding and following data words. This creates two separate sums that must simultaneously cancel, a much less likely event than a single sum cancellation when the checksum is simply appended. Hence middle insertion improves burst‑error detection.

Q9. How does overflow handling differ between one's complement and two's complement checksum calculations?

A.One's complement wraps overflow back into the sum, while two's complement discards overflow bits ✅
B.Both treat overflow identically
C.One's complement discards overflow, two's complement wraps it
D.Two's complement adds overflow to a separate flag
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: In one's complement arithmetic, any overflow (carry out of the most‑significant bit) is added back into the least‑significant bit, preserving the word size. Two's complement arithmetic, by contrast, simply discards the overflow, because the representation already incorporates sign and magnitude without needing a wrap‑around addition.

Q12. Consider a scenario where a single‑bit error flips a ‘1’ to ‘0’ in the data and simultaneously flips a ‘0’ to ‘1’ in the checksum field. Why would a simple additive checksum fail to detect this error while a CRC would succeed?

A.Because the checksum sum remains unchanged, but CRC includes polynomial division that changes ✅
B.Because CRC ignores checksum bits
C.Because additive checksum always detects such paired errors
D.Because the error cancels out in both methods
💡 Difficulty: hard | ✅ Correct: A

📖 Explanation: An additive checksum adds all words, including the checksum. If a bit error in the data decreases the sum by a certain amount and a complementary error in the checksum increases it by the same amount, the total sum stays the same, causing the error to be missed. CRC calculations, however, involve polynomial division; any change to the data or checksum alters the remainder, so the error is detected.

Q13. A message consists of three 8‑bit words [0xFF, 0x01, 0x02]. Using one's complement addition (without complement), what checksum value is transmitted?

A.0
B.1
C.3 ✅
D.255
💡 Difficulty: medium | ✅ Correct: C

📖 Explanation: First add 0xFF and 0x01: sum = 0x100. Wrap overflow: lower 8 bits 0x00 plus carry 0x1 gives 0x01. Add the third word 0x02: 0x01 + 0x02 = 0x03. No further overflow occurs, so the transmitted checksum is 0x03.
