What is Two approaches to multicasting source-based and group-shared?

Definition:
Multicast routing protocols use two main tree structures: Source-Based Trees (Shortest Path Trees) and Group-Shared Trees (Core-Based Trees). Source-based trees create a separate distribution tree for each source-group pair (S,G)(S, G)(S,G), optimizing paths from that specific source. Group-shared trees use a single common tree for all sources in a group, typically rooted at a Rendezvous Point (RP) or core router, reducing state information in routers.

Working:
In source-based trees, each router maintains state for every active source, creating optimal paths but high memory usage. Traffic flows along the shortest path from source to receivers. In group-shared trees, all sources send data to a central RP, which then distributes it down the shared tree to receivers. This reduces the number of states routers must maintain but may result in suboptimal paths (triangular routing) as traffic detours through the RP.

Example:
Source S1 sends to Group G. In source-based (PIM-SM SPT), routers build a tree specifically for (S1,G)(S1, G)(S1,G). If S2 also sends to G, a separate tree (S2,G)(S2, G)(S2,G) is built. In group-shared (PIM-SM Shared Tree), both S1 and S2 send to RP. Receivers join the tree rooted at RP (∗,G)(*, G)(∗,G). Traffic from S1 goes S1 -> RP -> Receivers, even if a direct path S1 -> Receivers is shorter.

Reason:
Source-based trees offer optimal latency and bandwidth usage per source but scale poorly due to state explosion O(S×G)O(S \times G)O(S×G). Group-shared trees scale better O(G)O(G)O(G) by aggregating state but sacrifice path optimality. Networks often use a hybrid approach: start with a shared tree for efficiency and switch to source-based trees for high-bandwidth sources to optimize performance.

Common MisConceptions:
Students often believe group-shared trees are always slower. While they may have longer paths, they reduce router CPU and memory load significantly. Another misconception is that source-based trees cannot coexist with shared trees; modern protocols like PIM-SM allow switching from shared to source-based trees dynamically based on traffic thresholds.

Exam Preparation Tips: How to prepare this topic
Compare state requirements: Source-based N×MN \times MN×M states vs Group-shared MMM states. Understand the trade-off: Optimality vs Scalability. Learn how PIM-SM uses both: starts with (∗,G)(*, G)(∗,G) shared tree and switches to (S,G)(S, G)(S,G) source tree if data rate exceeds threshold. Draw both tree types for clarity.

Key Terms:

  • Source-Based Tree - Shortest Path Tree rooted at the source (S,G)(S, G)(S,G).
  • Group-Shared Tree - Common tree rooted at a core/RP (∗,G)(*, G)(∗,G).
  • Rendezvous Point (RP) - Central router for group-shared trees.
  • State Scalability - Group-shared trees require less state memory.

Q1. Suppose a node receives a new vector and updates all its cells as described in lines 17‑20. Which immediate effect is most likely on the multicast routing table?

A.It discards all previously stored routes
B.It adds new routes without removing any old ones
C.It replaces only the entries that differ from the old vector ✅
D.It leaves the routing table unchanged
💡 Difficulty: easy | ✅ Correct: C

📖 Explanation: When a node updates every cell of its vector, the routing table must reflect the new state. Cells that differ indicate changed next‑hop information, so those entries are replaced while unchanged cells remain. This selective replacement ensures the table stays consistent with the latest vector while avoiding unnecessary deletions.

Q2. If every entry in a vector is refreshed after a new vector arrives, what can be inferred about the convergence speed of the multicast protocol?

A.Convergence slows because more updates are needed
B.Convergence speeds up due to simultaneous updates ✅
C.Convergence is unaffected by the update strategy
D.Convergence becomes unpredictable and may diverge
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: Refreshing all entries at once allows the network to propagate the newest state in a single wave, reducing the number of incremental adjustments required. Consequently, the protocol converges more quickly than approaches that update entries piecemeal, assuming no conflicts arise during the bulk operation.

Q3. A network implements the full‑vector update described in lines 17‑20. Two nodes receive the new vector at nearly the same time and update their vectors concurrently. What logical deduction explains a possible inconsistency?

A.Both nodes will always end with identical vectors
B.Concurrent updates guarantee eventual consistency
C.Race conditions may cause temporary mismatches ✅
D.The protocol prevents any inconsistency by design
💡 Difficulty: hard | ✅ Correct: C

📖 Explanation: When two nodes apply bulk updates simultaneously, they may read each other's intermediate states before the operation completes, leading to a race condition. This can produce transient discrepancies until the next synchronization round, illustrating that concurrent bulk updates can momentarily break consistency despite eventual convergence.

Q4. Given that lines 17‑20 cause every cell to be updated, what cause‑effect chain explains why packet loss might increase during a burst of updates?

A.More updates mean larger packets, which increase loss
B.Frequent vector changes trigger more control messages, occupying bandwidth ✅
C.Updating all cells reduces processing time, lowering loss
D.The approach has no impact on loss rates
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: Each full‑vector broadcast generates a control message containing the entire vector. When many updates occur in quick succession, the aggregate control traffic consumes a significant portion of the link capacity, leaving fewer resources for data packets and thereby raising the probability of packet loss.

Q5. Compare the source‑based tree approach with the receiver‑initiated approach in terms of bandwidth consumption when many receivers join a group. Which statement is accurate?

A.Source‑based trees use less bandwidth because they avoid duplicate paths
B.Receiver‑initiated trees use less bandwidth by sharing downstream links ✅
C.Both approaches consume equal bandwidth regardless of group size
D.Bandwidth consumption depends solely on packet size, not the approach
💡 Difficulty: easy | ✅ Correct: B

📖 Explanation: Receiver‑initiated (or reverse‑path) trees allow multiple receivers to share common downstream links, reducing duplicate transmissions. In contrast, source‑based trees often create separate branches for each receiver, leading to higher aggregate bandwidth usage as the number of receivers grows.

Q6. Evaluate the reliability trade‑off between the two multicast approaches when a link failure occurs. Which evaluation is correct?

A.Source‑based trees recover faster because they recompute the whole tree
B.Receiver‑initiated trees recover faster by locally repairing affected branches
C.Both approaches have identical recovery times ✅
D.Reliability is unrelated to the chosen approach
💡 Difficulty: medium | ✅ Correct: C

📖 Explanation: When a link fails, both approaches must detect the loss and rebuild affected portions of the multicast structure. The detection mechanisms and repair procedures are similar in complexity, resulting in comparable recovery times. Thus, reliability differences stem more from implementation details than from the fundamental approach.

Q7. Differentiate scenarios where the source‑based approach is preferable over the receiver‑initiated approach. Which scenario best fits the source‑based method?

A.Highly dynamic receiver membership with frequent joins/leaves
B.Sparse receivers spread over a large topology
C.Environments requiring strict QoS guarantees from the source ✅
D.Networks with unreliable links causing frequent failures
💡 Difficulty: hard | ✅ Correct: C

📖 Explanation: When strict Quality‑of‑Service (QoS) guarantees are needed, the source can control the path and allocate resources centrally, ensuring that bandwidth and latency requirements are met. The source‑based approach provides this centralized control, making it ideal for applications demanding deterministic performance.

Q8. Analyze the impact of vector length (number of entries) on scalability for the full‑vector update method. Which statement correctly describes the relationship?

A.Longer vectors improve scalability by providing more detail
B.Vector length has no effect on scalability
C.Shorter vectors enhance scalability by reducing control overhead ✅
D.Scalability depends only on the number of nodes, not vector size
💡 Difficulty: medium | ✅ Correct: C

📖 Explanation: A shorter vector reduces the size of each control message, decreasing the bandwidth consumed by updates. This lower overhead allows the protocol to scale to larger networks more efficiently, whereas longer vectors increase per‑message cost and can become a bottleneck as the network grows.

Q9. Apply the principle of updating all vector cells to a scenario where a new node joins a multicast group. What is the most appropriate action for existing nodes?

A.Ignore the new node until the next periodic update
B.Broadcast the entire updated vector to all existing nodes ✅
C.Send a single incremental update containing only the new entry
D.Wait for the new node to request the current vector
💡 Difficulty: easy | ✅ Correct: B

📖 Explanation: When a node joins, the group’s state changes, requiring all nodes to have a consistent view. Broadcasting the full updated vector ensures every node receives the complete, synchronized information, aligning with the protocol’s design of updating all cells after any change.

Q10. Synthesize a hybrid multicast strategy that leverages both source‑based and receiver‑initiated approaches to minimize latency and control overhead. Which hybrid design best achieves this goal?

A.Use source‑based trees for all traffic, adding receiver‑initiated repairs as needed ✅
B.Employ receiver‑initiated trees for data and source‑based trees for control messages
C.Alternate between the two approaches every few seconds
D.Maintain separate trees for each receiver, switching based on network load
💡 Difficulty: hard | ✅ Correct: A

📖 Explanation: A hybrid that primarily uses source‑based trees for data delivery ensures low latency through a predetermined path, while invoking receiver‑initiated repairs only when failures occur combines the strengths of both methods. This reduces control traffic compared to always using receiver‑initiated trees and preserves the fast data forwarding of source‑based trees.

Q11. In a network where nodes frequently update their vectors, which conceptual advantage does the full‑vector update provide over incremental updates?

A.It eliminates the need for sequence numbers
B.It guarantees that all nodes have an identical view after each update ✅
C.It reduces the total number of messages exchanged
D.It simplifies the routing algorithm by removing the vector concept
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: By transmitting the complete vector each time, every node receives the same snapshot of the multicast state, ensuring uniformity across the network. This holistic view removes ambiguity that can arise with incremental changes, thereby providing a clear, consistent state after each update cycle.
