📝 IGMP encapsulation in IP

📖 From Data Communication and Networks • 21. Multicast Routing • 8 questions available

What is IGMP encapsulation in IP?

IGMP messages are encapsulated directly inside IP packets with protocol number 2 and use TTL=1 to ensure they remain within the local subnet, allowing routers and hosts to exchange group management information without requiring transport-layer protocols like TCP or UDP.

Q1. In the OSI model, which layer adds the header that enables data link layer addressing?

A. Physical
B. Data Link ✅
C. Network
D. Transport

💡 Difficulty: easy | ✅ Correct: B

📖 Explanation:

The Data Link layer (Layer 2) frames the raw bits from the Physical layer and appends a header containing source and destination MAC addresses. This header provides the necessary addressing for devices on the same LAN to identify each other, enabling local delivery. Hence, the Data Link layer adds the addressing header.

Q2. If a packet is encapsulated with an additional MPLS label, what immediate effect does this have on the packet size?

A. Decreases size
B. No change
C. Increases size by the label length ✅
D. Compresses payload

💡 Difficulty: easy | ✅ Correct: C

📖 Explanation:

An MPLS label is inserted between the existing network layer header and the payload, typically adding 4 bytes (or more for multiple labels). This insertion enlarges the overall packet size by the length of the label(s). Therefore the packet size increases by the label length.

Q3. Which of the following best compares the encapsulation process of TCP and UDP regarding reliability and header overhead?

A. TCP adds sequence numbers, acknowledgments, and flow control fields, resulting in larger overhead but reliable delivery, while UDP adds only ports, giving minimal overhead and no reliability guarantees. ✅
B. TCP and UDP have identical header sizes, differing only in checksum fields.
C. UDP provides reliability through retransmission, whereas TCP does not.
D. Both protocols embed routing policies in their headers.

💡 Difficulty: medium | ✅ Correct: A

📖 Explanation:

TCP encapsulation includes sequence numbers, acknowledgment numbers, window size, and flags, which increase header size but enable reliable, ordered delivery. UDP encapsulation consists of source and destination ports, length, and checksum only, resulting in a smaller header and no built‑in reliability. Thus TCP offers reliability with higher overhead, while UDP offers minimal overhead without reliability.

Q4. In a path‑vector routing environment, the policy information defined by a source is most directly carried in which encapsulation layer of the BGP message?

A. Network
B. Transport
C. Application ✅
D. Data Link

💡 Difficulty: medium | ✅ Correct: C

📖 Explanation:

BGP is an application‑layer protocol that carries routing policies, path attributes, and policy decisions within its own message format. Although BGP messages travel over TCP (Transport layer), the policy data itself is encapsulated at the Application layer, making that the most direct carrier of the source‑imposed policy.

Q5. A network administrator configures a policy that forbids node D from appearing as an intermediate hop. Considering encapsulation, which header field must be examined to verify compliance with this policy?

A. TTL field in the IP header
B. Next‑hop address in the routing protocol's path vector ✅
C. Source MAC address in the Ethernet frame
D. Port number in the TCP header

💡 Difficulty: hard | ✅ Correct: B

📖 Explanation:

The path‑vector routing protocol records each hop in its own vector field. To enforce a policy that excludes a specific node, the router must inspect the next‑hop address listed in that vector. The IP TTL, MAC address, and TCP port do not convey the sequence of intermediate nodes, so the path vector field is the correct point of verification.

Q6. Adding an extra encapsulation header of 20 bytes to a packet destined for a network with an MTU of 1500 bytes may cause which of the following outcomes in path‑vector routing decisions?

A. The packet will always be accepted because routing protocols ignore MTU.
B. The packet size exceeds the MTU, causing fragmentation at the source, which may be prohibited by policy.
C. The increased size could trigger a route change to a path with a larger MTU, affecting the selected spanning tree. ✅
D. Encapsulation headers do not affect routing decisions.

💡 Difficulty: hard | ✅ Correct: C

📖 Explanation:

When the packet grows beyond the MTU due to an added 20‑byte header, routers may need to select an alternate path whose links support a larger MTU to avoid fragmentation. Path‑vector routing can incorporate such MTU considerations into its policy, potentially altering the chosen spanning tree to satisfy the size constraint.

Q7. Designing a new encapsulation scheme to support policy‑based routing, which feature is essential to allow each router to enforce its own path selection criteria?

A. A fixed‑size header that never changes
B. A variable‑length field that can carry router‑specific policy data ✅
C. Only a checksum for error detection
D. Absence of sequence numbers

💡 Difficulty: medium | ✅ Correct: B

📖 Explanation:

A variable‑length field enables routers to embed their own policy attributes—such as preferred metrics, prohibited nodes, or bandwidth requirements—directly within the packet. This flexibility allows each router to read and apply its own criteria when making forwarding decisions, which a fixed‑size, unchanging header cannot provide.

Q8. How does encapsulation facilitate hierarchical routing in large networks?

A. By embedding the entire network topology in each packet header
B. By allowing each layer to ignore lower‑layer details and focus on its own addressing scheme ✅
C. By requiring routers to process all encapsulation layers equally
D. By preventing aggregation of routes across domains

💡 Difficulty: medium | ✅ Correct: B

📖 Explanation:

Encapsulation separates concerns by letting each protocol layer add its own header with addresses relevant only to that layer. Upper layers do not need to understand the specifics of lower‑layer headers, enabling routers to aggregate routes and make decisions based on the most appropriate layer's address (e.g., IP for inter‑domain routing), thus supporting hierarchical routing.
