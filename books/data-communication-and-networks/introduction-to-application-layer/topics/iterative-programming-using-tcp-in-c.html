What is Iterative Programming Using TCP in C?

Iterative programming using TCP in C shows how to build reliable sequential servers and clients using socket functions like socket(), bind(), listen(), accept(), read(), and write() to establish connections and exchange streams of data, ensuring complete and ordered message delivery for each client session.

Q1. Which function converts a short integer from host byte order to network byte order?

A.htons ✅
B.htonl
C.ntohs
D.ntohl

📖 Explanation: The htons function translates a 16‑bit value from the host’s native byte ordering to the standardized network byte ordering, ensuring that port numbers are correctly interpreted by remote hosts regardless of endianness.

Q3. If the socket() call returns -1, what will the program do next?

A.Continue execution
B.Print an error message and exit ✅
C.Retry the socket call
D.Ignore the error and proceed
💡 Difficulty: easy | ✅ Correct: B

📖 Explanation: A return value of -1 signals failure; the surrounding if‑statement detects this condition, prints an informative error, and terminates the program to avoid undefined behavior from an invalid descriptor.

Q4. Suppose htons(8080) is used to set the port. What would happen if the programmer mistakenly used htonl instead?

A.The port would be set correctly
B.The port field would become corrupted, causing bind() to fail ✅
C.The program would crash immediately
D.There would be no effect on the program
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: htonl converts a 32‑bit value, not a 16‑bit port; placing the result in sin_port corrupts the field, so bind() receives an invalid port and typically returns an error such as EINVAL.

Q5. Which approach provides earlier detection of failures in a TCP server initialization?

A.Checking the return value of socket() immediately after the call
B.Checking the return value of bind() after socket() succeeds
C.Both checks detect failures at the same stage
D.Neither check is necessary for error detection ✅
💡 Difficulty: easy | ✅ Correct: D

📖 Explanation: Detecting an error right after socket() gives the earliest possible feedback; if socket() fails, there is no point in proceeding to bind(), making the early check the most proactive strategy.

Q6. Why must the IP address be converted with htonl before being placed in the sockaddr_in structure?

A.To ensure the address is in network byte order ✅
B.To compress the address into fewer bytes
C.To encrypt the address for security
D.To increase the speed of transmission
💡 Difficulty: easy | ✅ Correct: A

📖 Explanation: Network protocols expect addresses in big‑endian order; htonl transforms the host‑order 32‑bit address into this format, guaranteeing that the receiving side interprets the address correctly across differing architectures.

Q7. Given that len holds the length of the incoming string, what is the effect of calling recv(s, buffer, len, 0) when len is larger than the actual data received?

A.It causes a buffer overflow
B.Only the actual number of bytes received are written to the buffer ✅
C.The excess bytes are filled with zeros
D.The socket is automatically closed
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: recv() writes at most the number of bytes actually transmitted; if len exceeds that amount, the function simply returns the smaller count, leaving the remainder of the buffer unchanged.

Q8. Which of the following best describes the difference between iterative and concurrent server designs in the context of TCP socket programming?

A.Iterative servers handle one client at a time, while concurrent servers use fork or threads to handle multiple clients simultaneously
B.Iterative servers use select() to multiplex connections, while concurrent servers use poll()
C.Iterative servers rely on UDP, whereas concurrent servers rely on TCP
D.Both designs are identical in their handling of client connections ✅
💡 Difficulty: medium | ✅ Correct: D

📖 Explanation: Concurrent servers create a new execution context (process or thread) for each accepted connection, allowing multiple clients to be served in parallel, whereas iterative servers process one client completely before returning to accept the next.

Q9. If a server repeatedly calls accept() inside a while loop, how does this pattern contribute to the iterative model’s ability to serve multiple clients?

A.It creates new processes for each client
B.It sequentially handles each client, returning to accept() only after the current client’s session ends ✅
C.It buffers incoming data for all clients simultaneously
D.It changes the underlying transport protocol from TCP to UDP
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: The loop blocks on accept() until a client connects; after the server finishes communicating with that client, the loop iterates and calls accept() again, thereby serving clients one after another in a deterministic sequence.

Q10. Assume the server socket is bound to port 0 (letting the OS choose). After bind(), which function can retrieve the assigned port, and why is this useful for iterative servers?

A.getsockname
B.getpeername
C.inet_ntoa
D.getsockname ✅
💡 Difficulty: medium | ✅ Correct: D

📖 Explanation: getsockname extracts the local address information of a bound socket, including the automatically assigned port number; knowing this port enables the server to advertise or log the actual listening endpoint, which is essential when the port is chosen dynamically.

Q11. Evaluate the impact of not calling close(s) after finishing communication with a client in an iterative TCP server.

A.It leads to a resource leak that can exhaust file descriptors ✅
B.It causes the server to terminate immediately
C.The operating system automatically reclaims the descriptor, so there is no impact
D.It improves performance by keeping the descriptor open
💡 Difficulty: easy | ✅ Correct: A

📖 Explanation: Each successful close releases the underlying file descriptor back to the OS; omitting it leaves descriptors allocated, and after enough iterations the process can run out of descriptors, preventing new connections from being accepted.

Q12. How does converting both the port and IP address to network byte order affect portability across big‑endian and little‑endian architectures?

A.It eliminates endianness issues, allowing the same binary to run on any architecture
B.It doubles the transmission time due to extra conversion steps
C.It requires additional code but offers no practical benefit
D.It ensures correct interpretation of the values on both big‑endian and little‑endian systems ✅
💡 Difficulty: medium | ✅ Correct: D

📖 Explanation: By presenting the port and address in the standardized big‑endian (network) format, the server guarantees that any peer—regardless of its native byte ordering—will decode the values correctly, which is the core of portable network programming.

Q13. If a programmer mistakenly swaps the arguments of htons and htonl when setting sin_port and sin_addr, respectively, which of the following sequences of events is most likely?

A.bind() succeeds and the server listens on the intended address
B.bind() fails with EINVAL due to an invalid address structure ✅
C.The server receives data but interprets it incorrectly
D.The server crashes during socket creation
💡 Difficulty: hard | ✅ Correct: B

📖 Explanation: Applying htons to a 32‑bit address and htonl to a 16‑bit port corrupts both fields; bind() validates the address family and port, detects the malformed values, and typically returns an error such as EINVAL.

Q14. Consider two implementations of an iterative server: one uses a fixed-size buffer of 256 bytes, the other dynamically allocates a buffer based on len. Which approach better adheres to the principle of resource efficiency, and why?

A.The fixed buffer is more efficient because allocation overhead is avoided
B.The dynamic approach avoids wasting memory when messages are small, aligning resource usage with actual demand ✅
C.Both approaches are equally efficient in modern operating systems
D.The fixed buffer is better because it simplifies code and reduces fragmentation
💡 Difficulty: hard | ✅ Correct: B

📖 Explanation: Allocating exactly the amount of memory required for each message prevents over‑provisioning; although dynamic allocation incurs a small overhead, it scales with the workload and prevents the server from holding unnecessary memory for short messages.

Q16. When the server receives a SIGINT during a blocking accept() call, what is the typical behavior of the accept() function, and how should the program respond to ensure graceful shutdown?

A.accept() returns -1 with errno set to EINTR, and the program should close the listening socket and exit cleanly ✅
B.accept() continues waiting for a new connection, ignoring the signal
C.accept() raises a C++ exception that must be caught
D.accept() automatically closes the socket and terminates the process
💡 Difficulty: hard | ✅ Correct: A

📖 Explanation: POSIX specifies that a signal interrupting a blocking system call causes the call to fail with EINTR; detecting this return value lets the server break out of the accept loop, close resources, and shut down in an orderly manner.

Q17. Compare the effect of using SOCK_STREAM versus SOCK_DGRAM when creating the socket descriptor for an iterative TCP server. Which statement is accurate?

A.SOCK_STREAM provides a reliable, ordered byte stream suitable for TCP, while SOCK_DGRAM provides message‑oriented, unordered datagrams suitable for UDP ✅
B.SOCK_STREAM provides ordered datagrams, while SOCK_DGRAM provides a reliable stream
C.SOCK_STREAM is used only for IPv6, whereas SOCK_DGRAM is for IPv4
D.Both constants are interchangeable for TCP servers
💡 Difficulty: hard | ✅ Correct: A

📖 Explanation: TCP requires SOCK_STREAM because it guarantees delivery, ordering, and flow control; SOCK_DGRAM corresponds to UDP, which lacks these guarantees and therefore cannot be used for a traditional iterative TCP server.

Q18. Explain why an iterative TCP server cannot handle a client that remains idle for an extended period without affecting other clients, and propose a modification to mitigate this limitation.

A.Because the server uses UDP, which does not maintain connections
B.Because the server closes the socket after each request, preventing idle connections
C.Because the server blocks on recv() for the active client, preventing the loop from reaching accept() for new connections ✅
D.Because the server operates only on IPv6 addresses
💡 Difficulty: hard | ✅ Correct: C

📖 Explanation: An iterative server processes one client at a time; if that client blocks on recv(), the server never returns to accept() and therefore cannot serve additional clients. Using non‑blocking sockets or multiplexing with select()/poll() allows the server to detect idle periods and continue accepting new connections.
