Q1. Which protocol is commonly used by the World Wide Web for client‑server communication?

🔹 A. FTP
🔹 B. HTTP
🔹 C. SMTP
🔹 D. DNS

💡 Difficulty: easy | ✅ Correct: B

📖 Explanation:

HTTP is the foundational protocol for the World Wide Web. It defines how clients request resources and how servers respond, enabling web browsers to retrieve pages, images, and other content. Because of its ubiquity and support across platforms, HTTP remains the standard client‑server communication method for web services.

Q2. When a server becomes overloaded because many clients connect simultaneously, which immediate effect is most likely observed?

🔹 A. Decreased bandwidth
🔹 B. Improved reliability
🔹 C. Increased latency
🔹 D. Reduced security

💡 Difficulty: easy | ✅ Correct: C

📖 Explanation:

When a server is overloaded, its processing queues become longer, causing each client’s request to wait longer before being serviced. This delay manifests as increased response time, or latency, perceived by users as slower page loads or sluggish interactions. Bandwidth and reliability may stay unchanged, but the primary symptom is higher latency.

Q3. To evenly distribute incoming client requests among multiple servers, which technique is most effective?

🔹 A. Client‑side caching
🔹 B. Single‑threaded server
🔹 C. Static IP
🔹 D. Round‑robin DNS

💡 Difficulty: easy | ✅ Correct: D

📖 Explanation:

Round‑robin DNS cycles through a list of server IP addresses, returning a different address for each client query. By distributing client requests across multiple servers, it balances load and prevents any single server from becoming a bottleneck. This method is simple, widely supported, and effectively spreads traffic in many client‑server deployments.

Q4. If a server’s processing capacity is doubled and the system scales linearly, how does the maximum number of concurrent clients it can handle change?

🔹 A. Stays the same
🔹 B. Doubles
🔹 C. Halves
🔹 D. Increases by 50%

💡 Difficulty: medium | ✅ Correct: B

📖 Explanation:

Linear scaling assumes that doubling the server’s processing capability directly doubles the number of clients it can serve simultaneously. If the original capacity allowed C concurrent connections, after a two‑fold increase the capacity becomes 2C. Therefore, the maximum concurrent client count also doubles, reflecting proportional growth.

Q5. When comparing a dedicated powerful server to a cloud auto‑scaling solution for handling peak traffic, which advantage best describes the cloud approach?

🔹 A. Higher latency
🔹 B. Better security
🔹 C. Lower upfront cost
🔹 D. Less control

💡 Difficulty: medium | ✅ Correct: C

📖 Explanation:

Cloud auto‑scaling provisions additional compute resources only when demand spikes, eliminating the need for large upfront hardware investments. Organizations pay for capacity on a pay‑as‑you‑go basis, matching expenses to actual usage. This financial flexibility, combined with rapid elasticity, makes cloud scaling advantageous over maintaining a permanently powered dedicated server.

Q6. Among load‑balancing algorithms, which one assigns a new request to the server currently handling the fewest active connections?

🔹 A. Round‑robin DNS
🔹 B. Least connections
🔹 C. Client‑side caching
🔹 D. Static IP

💡 Difficulty: medium | ✅ Correct: A

📖 Explanation:

The least‑connections algorithm monitors the number of active sessions on each backend server and directs new requests to the server with the fewest current connections. By continuously favoring the least‑loaded machine, it helps prevent overload on any single server and improves overall response times in dynamic, high‑traffic environments.

Q7. Considering protocol behavior, which statement correctly distinguishes HTTP and FTP regarding statefulness?

🔹 A. Both are stateless
🔹 B. Both are stateful
🔹 C. HTTP is stateful, FTP is stateless
🔹 D. HTTP is stateless, FTP is stateful

💡 Difficulty: medium | ✅ Correct: D

📖 Explanation:

HTTP operates as a stateless protocol; each request contains all information needed, and the server does not retain session data between requests. FTP, in contrast, establishes a persistent connection for file transfers, maintaining state such as current directory and transfer mode. This distinction means HTTP is stateless while FTP is stateful.

Q8. A single‑threaded server processes each request in \( t \) seconds. If it must serve \( N \) clients sequentially, the total processing time is best expressed as which of the following?

🔹 A. \( t/N \)
🔹 B. \( N \times t \)
🔹 C. \( N + t \)
🔹 D. \( \sqrt{N} \times t \)

💡 Difficulty: medium | ✅ Correct: B

📖 Explanation:

When a server processes requests sequentially, the time required for each request (\( t \) seconds) accumulates across all \( N \) clients. The total processing duration is therefore the product of the number of clients and the per‑request time, expressed mathematically as \( N \times t \). This linear relationship assumes no parallelism.

Q9. If the request queue length on a server grows as \( 2^{k} \) over successive time intervals, what is the most plausible underlying cause?

🔹 A. Client‑side caching
🔹 B. Load balancing
🔹 C. Network congestion
🔹 D. Insufficient processing power

💡 Difficulty: hard | ✅ Correct: D

📖 Explanation:

An exponential increase in queue length, modeled by \( 2^{k} \), indicates that the server cannot process incoming requests as quickly as they arrive. The most plausible cause is insufficient processing power or resources, leading to a backlog that grows rapidly. Network congestion or caching issues typically produce different patterns, whereas a lack of capacity drives exponential queue growth.

Q10. Evaluating scalability, which drawback is most directly associated with relying on a single powerful server instead of a distributed micro‑service architecture?

🔹 A. Easier to maintain
🔹 B. Lower latency
🔹 C. Single point of failure
🔹 D. Better resource utilization

💡 Difficulty: hard | ✅ Correct: C

📖 Explanation:

Relying on a single powerful server creates a single point of failure; if that server crashes or becomes unavailable, the entire service is disrupted. In contrast, a distributed micro‑service architecture spreads functionality across many nodes, providing redundancy and fault tolerance. This architectural drawback highlights the risk inherent in centralizing all processing on one machine.)
