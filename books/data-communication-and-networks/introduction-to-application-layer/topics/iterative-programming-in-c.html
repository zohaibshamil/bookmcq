What is Iterative Programming in C?

Iterative programming in C involves writing network applications using the C language's socket library to create simple servers and clients that process requests in a sequential loop, providing direct control over memory and system calls while requiring careful manual management of network resources.

Q1. How many fields are defined in the C socket structure as described in the passage?

A. Four
B. Five ✅
C. Six
D. Seven

💡 Difficulty: easy | ✅ Correct: B

📖 Explanation:

The passage explicitly states that the C socket is defined as a structure consisting of five fields. Therefore, the correct count is five, making option B the accurate answer. This count includes the address family, port number, IP address, protocol, and a reserved field, which together form the complete socket descriptor in C.

Q2. If a socket has no internal buffer, which component must the operating system provide to enable successful data transmission?

A. Kernel‑level buffers ✅
B. User‑level queue
C. Hardware interrupt handling
D. Compile‑time constants

💡 Difficulty: easy | ✅ Correct: A

📖 Explanation:

Because the socket itself holds no storage, the kernel must allocate buffers on its behalf. These kernel‑level buffers temporarily hold outgoing and incoming bytes, allowing the socket to interface with the network hardware. Without such buffers, the application would have nowhere to place data for transmission, so option A is correct.

Q3. Which statement best compares a C socket to a Unix file descriptor in terms of their abstraction role?

A. A socket only handles network I/O while a file descriptor handles only file I/O
B. Both act as integer handles that the kernel maps to underlying resources
C. Sockets are higher‑level than file descriptors and do not require system calls
D. Both serve as opaque references that the kernel uses to manage I/O resources ✅

💡 Difficulty: medium | ✅ Correct: D

📖 Explanation:

Both sockets and file descriptors are opaque identifiers that the kernel uses to reference underlying resources. They hide implementation details from the programmer, allowing uniform system‑call interfaces for I/O. This conceptual similarity makes option D the most accurate description.

Q4. In an iterative server written in C, which pattern correctly implements handling of successive client connections without spawning new threads?

A. Create a new process for each client using fork()
B. Use a while loop that calls accept() and processes the client before returning to accept() ✅
C. Employ recursion to handle each client
D. Use a timer interrupt to poll sockets

💡 Difficulty: medium | ✅ Correct: B

📖 Explanation:

An iterative server typically runs a single loop: it calls accept() to obtain a client socket, processes the request sequentially, closes the connection, and then returns to accept() for the next client. This pattern avoids thread creation and keeps the control flow simple, matching option B.

Q5. When the recv() function returns 0 for a connected socket, what can be logically inferred about the peer?

A. The peer has sent an empty message
B. The peer has performed an orderly shutdown ✅
C. The socket buffer is full
D. An error occurred

💡 Difficulty: medium | ✅ Correct: B

📖 Explanation:

A return value of zero from recv() indicates that the remote endpoint has closed its sending side gracefully. This is the standard signal of an orderly shutdown, meaning no more data will arrive. Therefore, the correct inference is option B.

Q6. If a server switches from a multithreaded design to a single‑threaded design using select(), what is the most direct effect on CPU utilization under high connection load?

A. CPU usage may decrease because the thread context switches are eliminated ✅
B. CPU usage will increase due to busy‑waiting in select()
C. CPU usage remains unchanged because network I/O dominates
D. CPU usage becomes unpredictable

💡 Difficulty: hard | ✅ Correct: A

📖 Explanation:

Using select() removes the overhead of creating and scheduling multiple threads. The kernel monitors multiple descriptors within a single thread, so the costly context‑switch operations disappear. Consequently, overall CPU consumption tends to drop, especially when many connections are active, making option A the correct outcome.

Q7. How can an iterative C program be adapted to work with non‑blocking sockets while still preserving the sequential processing order of client requests?

A. Insert sleep() calls between recv() attempts
B. Use a state machine that retries EAGAIN until data is ready ✅
C. Replace recv() with read() without checking return values
D. Close and reopen the socket for each attempt

💡 Difficulty: hard | ✅ Correct: B

📖 Explanation:

A non‑blocking socket returns EAGAIN when no data is available. By implementing a state machine that repeatedly attempts recv() and only proceeds when data is received, the program can keep the logical order of processing while avoiding blocking. This approach matches option B.

Q8. Considering the five‑field socket structure, which field is most critical for ensuring that two processes on different hosts can locate each other?

A. Address family
B. Protocol
C. Port number
D. IP address ✅

💡 Difficulty: medium | ✅ Correct: D

📖 Explanation:

The IP address field identifies the network host on which a process resides, enabling remote machines to route packets correctly. While the port number distinguishes services on that host, the fundamental ability to locate the host itself depends on the IP address, making option D the most essential field for cross‑host discovery.
