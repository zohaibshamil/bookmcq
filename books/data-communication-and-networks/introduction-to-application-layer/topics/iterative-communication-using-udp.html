What is Iterative Communication Using UDP?

Iterative communication using UDP involves a simple server design that processes one client request at a time using the connectionless User Datagram Protocol, making it suitable for lightweight applications where speed is prioritized over reliability and each request can be handled quickly without maintaining state.

Q1. If a client sends a UDP packet to a server expecting an iterative response, and the server does not send a reply, what is the most likely cause?

A.The packet was lost in the network ✅
B.The server is using TCP instead of UDP
C.The client timed out before sending
D.The server deliberately ignored the request
💡 Difficulty: easy | ✅ Correct: A

📖 Explanation: Because UDP does not provide delivery guarantees, the most common reason a client receives no reply is that the packet was lost in transit or the server’s response never arrived. UDP lacks retransmission mechanisms, so unlike TCP the absence of a response usually indicates network loss rather than a protocol error.

Q4. A UDP iterative system uses sequence numbers modulo 256. After receiving packets with numbers 250, 251, 252, 0, 1, what logical deduction about wrap‑around handling is required?

A.Sequence numbers should be reset to zero manually
B.Packets 0 and 1 are out of order and should be discarded
C.The sender should increase the modulo base
D.The receiver must recognize that 0 and 1 follow 252 due to wrap‑around ✅
💡 Difficulty: hard | ✅ Correct: D

📖 Explanation: Sequence numbers modulo 256 wrap from 255 back to 0. Receiving 250, 251, 252 followed by 0 and 1 indicates that the sender has crossed the wrap‑around point. The receiver must treat 0 and 1 as the logical successors of 252, recognizing the modulo arithmetic to maintain correct ordering.

Q5. Compare UDP iterative communication with TCP's request‑response model in terms of connection state.

A.Both maintain persistent connections
B.UDP is connectionless, while TCP maintains a stateful connection ✅
C.TCP does not guarantee order, UDP does
D.UDP requires a three‑way handshake, TCP does not
💡 Difficulty: easy | ✅ Correct: B

📖 Explanation: UDP is a connectionless protocol; it does not maintain any persistent state between endpoints. TCP, by contrast, establishes a stateful connection through a three‑way handshake and retains connection information for the duration of the session. Thus, iterative communication over UDP lacks the connection state inherent to TCP’s request‑response model.

Q6. Evaluate the impact of using a fixed timeout versus an adaptive timeout in UDP iterative queries on network efficiency.

A.Adaptive timeouts reduce unnecessary retransmissions by matching network conditions ✅
B.Fixed timeouts always improve throughput
C.Adaptive timeouts increase packet size
D.Fixed timeouts eliminate the need for sequence numbers
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: An adaptive timeout measures round‑trip times and adjusts the waiting period, reducing unnecessary retransmissions when the network is fast and increasing patience when latency grows. A fixed timeout cannot respond to changing conditions, often causing premature retries or excessive waiting, which lowers overall network efficiency.

C.Server‑side control uses TCP windows
D.Client‑side control adjusts packet size while server‑side control adjusts timeout ✅
💡 Difficulty: medium | ✅ Correct: D

📖 Explanation: Client‑side flow control typically regulates how fast the client sends packets, possibly by adjusting send intervals or packet sizes. Server‑side control can influence the client by varying the timeout or acknowledgment strategy. Combining both allows the system to balance outbound and inbound traffic without relying on TCP’s built‑in windows.

Q9. Apply the principle of idempotence to UDP iterative requests; which design ensures safe retries?

A.Include a random payload each time
B.Change the destination port on each retry
C.Send a different command on each attempt
D.Use the same request identifier and make the operation idempotent ✅
💡 Difficulty: easy | ✅ Correct: D

📖 Explanation: Idempotent operations produce the same result regardless of how many times they are executed. By assigning a unique request identifier and ensuring the server’s operation is idempotent, retries caused by UDP’s lack of acknowledgment become safe, as duplicate requests do not alter the system state.

Q11. Synthesize a strategy that combines sequence numbers and timestamps to mitigate out‑of‑order delivery in UDP iterative exchanges.

A.Attach both a monotonically increasing sequence number and the send timestamp; discard packets with older timestamps or lower sequence numbers ✅
B.Use only timestamps and ignore sequence numbers
C.Rely on the network to reorder packets automatically
D.Send packets twice for redundancy
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: A combined approach attaches a monotonically increasing sequence number and a precise send timestamp to each packet. Upon receipt, the receiver discards any packet whose sequence number is lower than the highest seen or whose timestamp is older than the most recent valid packet, thereby filtering out‑of‑order deliveries.

Q12. Propose a method to achieve reliable ordered delivery in an otherwise unreliable UDP iterative protocol without resorting to TCP, and justify its feasibility.

A.Add a checksum and hope for the best
B.Use UDP multicast to increase redundancy
C.Implement a simple stop‑and‑wait ARQ with sequence numbers and acknowledgments ✅
D.Switch to TCP entirely
💡 Difficulty: hard | ✅ Correct: C

📖 Explanation: Implementing a stop‑and‑wait ARQ scheme over UDP adds sequence numbers and acknowledgments, allowing the sender to retransmit only unacknowledged packets. This method provides reliable, ordered delivery while preserving UDP’s lightweight nature, making it feasible for applications that need reliability without the overhead of a full TCP stack.

Q13. What does UDP stand for?

A.Universal Data Protocol
B.User Datagram Process
C.User Datagram Protocol ✅
D.Unreliable Data Package
💡 Difficulty: easy | ✅ Correct: C

📖 Explanation: UDP stands for User Datagram Protocol, a core Internet protocol that provides a simple, connectionless service for sending datagrams without guaranteeing delivery, ordering, or duplicate protection. It is defined in RFC 768 and is widely used for applications such as DNS, streaming media, and online gaming where low latency is more important than guaranteed delivery.
