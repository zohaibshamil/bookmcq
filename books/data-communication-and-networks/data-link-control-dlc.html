📖 Data Link Control (DLC)

Data Link Control For Reliable Frame Exchange

Data Link Control coordinates the exchange of frames between directly connected devices through framing, flow control, and error control. Connectionless and connection-oriented services provide different delivery arrangements, while simple protocols and Stop-and-Wait ARQ demonstrate acknowledgment and retransmission mechanisms. Piggybacking combines acknowledgments with outgoing data. HDLC and PPP provide structured framing and link-management procedures, including bit stuffing, byte stuffing, and protocol negotiation. These mechanisms build on physical addressing and error detection to support organized, reliable communication across network links.


Framing And Acknowledgment Basics

Students should understand binary data, frames, physical transmission media, and data-link addressing. Knowledge of transmission errors, checksums, and frame boundaries supports the study of error control. Familiarity with sender-receiver communication, timers, acknowledgments, and network protocols also helps explain retransmission and link establishment.


Skills For Reliable Link Exchanges

Students should be able to explain framing, flow control, and error control, distinguish connectionless from connection-oriented services, and trace simple data-link protocol operations. They should calculate Stop-and-Wait transmission behaviour, explain piggybacking, identify HDLC frame fields and configurations, distinguish bit stuffing from byte stuffing, and describe PPP services, LCP and IPCP transitions, and protocol multiplexing.


From Frame Boundaries To Link Protocols

  • Framing Techniques - Establishes frame boundaries using length fields, delimiters, and stuffing methods.
  • Flow And Error Control - Coordinates transmission rates, acknowledgments, lost frames, and retransmission procedures.
  • Data Link Services And Basic Protocols - Compares connectionless and connection-oriented services through simple communication protocol operations.
  • Stop-and-Wait ARQ And Piggybacking - Explains acknowledgment timing, retransmission, sequence numbers, and combined data acknowledgments.
  • HDLC Frame Structure And Bit Stuffing - Covers HDLC configurations, frame fields, control information, and bit-oriented framing.
  • PPP Framing And Link Management - Explains PPP services, byte stuffing, LCP, IPCP, and protocol identification.

A Study Sequence From Framing To PPP

Start with framing because receivers must recognize individual frames before processing their contents. Continue with flow and error control, then compare connectionless and connection-oriented services. Study simple protocols, Stop-and-Wait ARQ, and piggybacking to understand acknowledgment mechanisms. Next, examine HDLC frame structures and bit stuffing. Finish with PPP framing, byte stuffing, link establishment through LCP, network configuration through IPCP, and protocol identification.


How Framing And Control Mechanisms Work Together

Framing establishes recognizable boundaries for transmitted data, allowing receivers to identify individual frames. Flow control regulates transmission according to receiver readiness, while error control handles corrupted or missing frames. Stop-and-Wait ARQ combines sequence numbers, acknowledgments, and retransmission; piggybacking places acknowledgments alongside outgoing data. HDLC and PPP apply defined framing conventions, while PPP's LCP and IPCP coordinate link establishment and network-layer configuration.


A Frame Exchange Using Stop And Wait ARQ

Two computers exchange data over a point-to-point link using Stop-and-Wait ARQ. The sender transmits a 512-byte frame marked with sequence number 0 and starts a timer. The receiver checks the frame, accepts valid data, and returns an acknowledgment. Suppose the acknowledgment is lost; the sender times out and retransmits sequence 0. The receiver recognizes the duplicate, avoids delivering the same data twice, and acknowledges it again. The sender then advances to sequence number 1.


Why Link Control Prevents Unreliable Exchanges

Without framing, receivers cannot reliably separate consecutive data units. Without flow control, fast senders may overwhelm receiving devices, while missing acknowledgments can cause lost or duplicated data. HDLC and PPP provide standardized link procedures that support interoperability, structured transmission, and communication across different network technologies.


Distinguishing Framing Stuffing And Acknowledgments

Students may say 'bit stuffing and byte stuffing use the same operation'; HDLC inserts bits after specified consecutive ones, whereas asynchronous PPP uses escape bytes. They may say 'flow control detects corrupted frames'; flow control regulates transmission rates, while error control identifies and handles transmission failures. They may also say 'piggybacking removes acknowledgments'; it attaches acknowledgments to outgoing data frames instead.


Protocol Tracing And Frame Structure Questions

Exam questions commonly test framing methods, flow-control operations, and error-control procedures. Numerical and sequence-based problems focus on Stop-and-Wait ARQ, acknowledgment loss, retransmission, and duplicate recognition. HDLC questions examine frame fields, configurations, and bit stuffing, while PPP questions test byte stuffing, LCP and IPCP phases, and protocol identification. Students should also compare the services and operating mechanisms of both protocols.


How Link Protocols Coordinate Data Delivery

Data-link communication depends on clearly defined frame boundaries and coordinated sender-receiver behaviour. Flow control regulates transmission, while error control protects exchanges against transmission failures. Basic protocols demonstrate these responsibilities through acknowledgments and retransmissions, and piggybacking improves acknowledgment efficiency. HDLC and PPP provide established framing structures and control procedures, allowing network devices to exchange different types of information over point-to-point and other supported links.


Technical Specifications For HDLC And PPP

  • ISO/IEC 13239 - Defines HDLC procedures and frame structures for data-link communication.
  • RFC 1661 - Specifies the Point-to-Point Protocol, including link establishment, configuration, and network-layer protocol handling.
  • RFC 1662 - Describes PPP framing using HDLC-like framing procedures, including asynchronous byte stuffing.
  • RFC 1332 - Specifies the Internet Protocol Control Protocol used to configure IPv4 over PPP links.

Essential Terms For Data Link Control

  • Framing - Divides a continuous bit stream into identifiable data-link units.
  • Flow Control - Regulates the transmission rate to prevent a sender from overwhelming a receiver.
  • Automatic Repeat Request - Uses acknowledgments and retransmissions to recover from transmission failures.
  • Piggybacking - Combines an acknowledgment with an outgoing data frame in bidirectional communication.
  • HDLC - A bit-oriented data-link protocol supporting structured framing and link control.
  • PPP - A point-to-point protocol providing framing and multiprotocol encapsulation.
  • LCP - Establishes, configures, tests, and terminates a PPP data-link connection.
  • IPCP - Negotiates IPv4 network-layer configuration parameters over a PPP connection.
