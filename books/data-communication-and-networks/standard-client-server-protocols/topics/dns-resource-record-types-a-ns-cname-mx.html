What is DNS resource record types A NS CNAME MX?

Definition:
DNS Resource Records (RR) are data entries in the DNS database that provide specific information about a domain. Key types include A records mapping domains to IPv4 addresses, NS records specifying authoritative name servers, CNAME records creating aliases for canonical names, and MX records directing email to mail servers. These records collectively define how traffic and services are routed for a domain.

Working:
When a query is made, the DNS server looks up the relevant RR type. An A record query returns an IPv4 address. An MX query returns mail server priorities and hostnames. A CNAME query redirects to another domain name, which is then resolved. NS records tell resolvers which servers are authoritative for the zone, guiding the resolution hierarchy correctly.

NS record:example.com→ns1.provider.comNS \ record: example.com \rightarrow ns1.provider.comNS record:example.com→ns1.provider.com
These records guide web and email traffic appropriately.

Reason:
Different services require different routing information. Web browsers need IP addresses (A records). Email servers need mail exchange hosts (MX records). Aliases simplify management (CNAME). Delegating authority requires NS records. Separating these functions allows flexible infrastructure management, such as hosting web and email on different servers or using CDNs for content delivery.

Common MisConceptions:
Students often confuse A records with CNAME records. An A record points to an IP; a CNAME points to another domain name. Another error is thinking MX records point to IP addresses; they point to domain names, which must then be resolved to IPs via A records. Also, CNAME records cannot coexist with other records for the same name.

Exam Preparation Tips: How to prepare this topic
Memorize the purpose of each record type: A (IPv4), AAAA (IPv6), CNAME (Alias), MX (Mail), NS (Name Server), PTR (Reverse DNS). Practice writing sample DNS zone files. Understand priority values in MX records. Learn restrictions, like CNAME limitations. Compare A and AAAA records for IPv4 vs IPv6 support.

Key Terms:

  • A Record - Maps domain to IPv4 address.
  • CNAME - Canonical Name, alias for another domain.
  • MX Record - Mail Exchange, directs email traffic.
  • NS Record - Name Server, delegates authority.

📝 All DNS resource record types A NS CNAME MX MCQs

Q1. Which DNS resource record type is used to map a domain name to its IPv4 address?

A.TXT
B.A ✅
C.CNAME
D.MX
💡 Difficulty: easy | ✅ Correct: B

📖 Explanation: An A record stores the IPv4 address associated with a host name. The other listed types serve different purposes: MX directs mail, CNAME creates an alias, and TXT holds arbitrary text. Therefore, the correct choice is the A record used in DNS queries to resolve the domain to its numeric address.

Q2. If a DNS zone file contains an A record for www.example.com pointing to 192.0.2.1 and also a CNAME record for the same name to alias.example.com, what is the effect?

A.Both records will be returned
B.Resolver will ignore the CNAME
C.Configuration is invalid and resolver will return an error ✅
D.The A record will override the CNAME
💡 Difficulty: easy | ✅ Correct: C

📖 Explanation: DNS specifications forbid a name from having both an A (or AAAA) record and a CNAME record simultaneously. When a resolver encounters such a configuration, it treats it as a zone error and returns a SERVFAIL response, indicating that the data is inconsistent. Thus the resolver will not return any of the records and the configuration is considered invalid.

Q3. If an MX record has priority 10 pointing to mail1.example.com and another MX with priority 20 pointing to mail2.example.com, and mail1.example.com is temporarily unreachable, what will the resolver do?

A.Use the next highest priority (20) ✅
B.Return no MX records
C.Retry mail1 indefinitely
D.Return an error
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: MX records are prioritized by their numeric preference value; lower numbers indicate higher priority. If the primary mail server (priority 10) cannot be reached, a compliant resolver will automatically fall back to the next available MX record with the lowest remaining priority, which in this case is the record with priority 20. This fallback mechanism ensures continued mail delivery without manual intervention.

Q4. Consider a DNSSEC‑signed zone where the DS record at the parent zone does not match the child zone's KSK. What is the expected validation outcome for queries to that child zone?

A.Queries succeed but signatures are ignored ✅
B.Validation fails and resolvers treat the responses as insecure
C.Validation succeeds because DS mismatch is tolerated
D.Validation fails and resolvers discard the responses
💡 Difficulty: hard | ✅ Correct: A

📖 Explanation: In DNSSEC, the parent zone's DS record must match the child zone's key signing key (KSK) fingerprint. A mismatch indicates a break in the chain of trust, causing validation to fail. Resolvers that enforce DNSSEC will then discard the unsigned answer and return a validation failure, typically indicated by a SERVFAIL status. The response is not treated as secure or insecure; it is rejected.

Q5. Compare the purpose of an A record and an AAAA record. Which statement correctly distinguishes them?

A.A records map IPv4, AAAA map IPv6 ✅
B.A records map hostnames to MAC addresses
C.AAAA records provide load balancing
D.A records are only used for email
💡 Difficulty: easy | ✅ Correct: A

📖 Explanation: An A record maps a domain name to a 32‑bit IPv4 address, while an AAAA record performs the same function for a 128‑bit IPv6 address. The two record types differ only in the address family they represent; they do not convey mail routing, load‑balancing, or textual information. Hence, the distinguishing statement is that A records map IPv4 and AAAA map IPv6.

Q6. Evaluate the impact of using a CNAME record at the apex of a zone (e.g., example.com). Which of the following is a valid consequence?

A.It allows delegation of the apex to another domain
B.It breaks DNSSEC chain of trust
C.It is prohibited by RFC 1034 ✅
D.It causes additional query latency but works in all resolvers
💡 Difficulty: medium | ✅ Correct: C

📖 Explanation: Placing a CNAME at the zone apex (the root of a domain, e.g., example.com) violates RFC 1034, which requires the apex to contain NS and SOA records. Because the apex cannot be an alias, most resolvers will reject the zone or ignore the CNAME, leading to resolution failures. Therefore, the correct consequence is that such a configuration is prohibited by the standard.

Q7. Differentiate between a TXT record used for SPF and a TXT record used for DKIM. Which statement correctly captures the difference?

A.SPF TXT contains a public key, DKIM TXT contains allowed IPs
B.SPF TXT defines authorized sending hosts, DKIM TXT stores a public key for signature verification ✅
C.Both store the same data format
D.DKIM TXT is only used for IPv6
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: SPF information is stored in a TXT record that lists the IP addresses or hostnames authorized to send mail for the domain. DKIM, on the other hand, places a public key in a TXT record under a selector subdomain, which receivers use to verify the cryptographic signature attached to the message. Thus, SPF defines sending hosts, while DKIM provides a public key for signature verification.

Q8. Apply the principle of least privilege to DNS zone transfers. Which configuration best embodies this principle?

A.Allow any IP to perform AXFR
B.Restrict AXFR to a specific secondary server IP ✅
C.Use TCP for all queries
D.Disable DNSSEC
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: The principle of least privilege dictates that services should be granted only the permissions necessary to perform their function. By restricting AXFR (full zone transfer) to the known IP address of a secondary authoritative server, the primary server limits exposure to potential attackers, reducing the attack surface while still allowing legitimate replication.

Q9. Synthesize a strategy for mitigating DNS cache poisoning in a recursive resolver that does not support DNSSEC. Which combination of techniques provides the strongest defense?

A.Randomize source ports and transaction IDs
B.Enable query name minimization
C.Both A and B ✅
D.None of the above
💡 Difficulty: hard | ✅ Correct: C

📖 Explanation: When DNSSEC is unavailable, combining source‑port and transaction‑ID randomization with query name minimization offers a layered defense against cache poisoning. Randomizing ports and IDs makes it harder for an attacker to guess the correct values, while name minimization limits the amount of data exposed to untrusted servers, reducing the chance of successful injection. Together they provide the strongest non‑DNSSEC protection.

Q10. Explain how DNS SRV records are used by a client application to select a service endpoint. Which process correctly describes the selection algorithm?

A.Randomly pick any SRV record
B.Sort by priority, then weight for load balancing within same priority ✅
C.Choose the record with the highest weight regardless of priority
D.Use only the first SRV record returned
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: Clients that use SRV records first sort all returned records by the priority field, selecting the lowest value(s). Within records sharing the same priority, the weight field determines the probability of selection, allowing load balancing. This two‑step process ensures that higher‑priority services are preferred while still distributing traffic among equally‑prioritized servers.
