📝 DNSSEC and DNS security threats

📖 From Data Communication and Networks • 26. Standard Client Server Protocols • 10 questions available

What is DNSSEC and DNS security threats?

DNSSEC adds cryptographic signatures to DNS records to verify authenticity and prevent cache poisoning and spoofing attacks, addressing inherent vulnerabilities in the original DNS protocol that lacked built-in validation mechanisms.

Q1. If an attacker successfully poisons a DNS resolver’s cache with a forged record mapping www.bank.com to 192.0.2.5, what is the most immediate effect on a user who later types www.bank.com in their browser?

A. The browser will display a DNS error
B. The browser will connect to 192.0.2.5 ✅
C. The DNS server will block the request
D. The connection will be encrypted with the original certificate

💡 Difficulty: easy | ✅ Correct: B

📖 Explanation:

The poisoned cache causes the resolver to return the forged IP address. When the user requests www.bank.com, the browser receives 192.0.2.5 and attempts to establish a TCP connection to that host, regardless of the legitimate site’s certificate. This direct redirection is the immediate observable effect of cache poisoning.

Q2. Which of the following is NOT directly provided by DNSSEC?

A. Data origin authentication
B. Data integrity
C. Protection against cache poisoning
D. Confidentiality of query data ✅

💡 Difficulty: medium | ✅ Correct: D

📖 Explanation:

DNSSEC adds cryptographic signatures to DNS records, enabling resolvers to verify that data originates from the authoritative source and has not been altered, which covers authentication, integrity, and mitigates cache poisoning. However, it does not encrypt the queries or responses, so confidentiality of the DNS traffic is not a feature of DNSSEC.

Q3. An open DNS resolver is used in a reflection attack that sends queries with a spoofed source IP of a victim. If each query elicits a response of 500 bytes while the query itself is only 50 bytes, what amplification factor does the attacker achieve?

A. 10 ✅
B. 5
C. 0.1
D. 100

💡 Difficulty: hard | ✅ Correct: A

📖 Explanation:

The amplification factor is calculated by dividing the size of the response by the size of the request: \( \frac{500\text{ bytes}}{50\text{ bytes}} = 10 \). This means the attacker can generate ten times more traffic toward the victim than the amount they send to the open resolver, a classic DDoS amplification technique.

Q4. Which statement best differentiates DNS over HTTPS (DoH) from DNS over TLS (DoT) in terms of network visibility?

A. DoH encrypts queries but still uses UDP
B. DoT hides DNS traffic inside standard TLS port 443
C. DoH disguises DNS as regular HTTPS traffic, making it harder to block ✅
D. DoT provides no encryption

💡 Difficulty: easy | ✅ Correct: C

📖 Explanation:

DoH tunnels DNS queries inside HTTPS connections, typically over port 443, which blends with ordinary web traffic and can bypass network filters that allow HTTPS. DoT, on the other hand, uses TLS directly on a dedicated port (853), making its traffic more identifiable to monitoring tools. Hence, the primary visibility difference is DoH’s camouflage within normal HTTPS.

Q5. If a DNS server disables recursive queries for external clients, which of the following outcomes is most likely?

A. The server becomes vulnerable to cache poisoning
B. Internal clients lose access to the internet
C. All external lookups succeed faster
D. External clients must query authoritative servers directly ✅

💡 Difficulty: medium | ✅ Correct: D

📖 Explanation:

Disabling recursion for external clients means the server will no longer follow referrals to obtain answers on their behalf. Consequently, external users must send queries directly to the authoritative name servers for the zones they need, increasing their workload but preventing the server from being abused as an open resolver. The other options describe unrelated effects.

Q6. When a resolver validates a DNSSEC‑signed zone, which of the following must be present to establish a complete chain of trust?

A. Only the zone’s DS record
B. Only the parent zone’s DNSKEY
C. The zone’s DNSKEY and a matching DS record in the parent ✅
D. No additional records, as DNSSEC works without a chain

💡 Difficulty: hard | ✅ Correct: C

📖 Explanation:

A full DNSSEC validation requires the zone’s DNSKEY record, which contains the public key used to verify its signatures, and a Delegation Signer (DS) record in the parent zone that links the child’s key to the parent’s trust anchor. The resolver checks that the DNSKEY matches the DS, then continues up the hierarchy to the root key, establishing an unbroken chain of trust.

Q7. Applying the principle of least privilege to DNS administration, which practice most reduces the risk of unauthorized zone modifications?

A. Using role‑based access control to limit write rights to specific zones ✅
B. Granting all admins write access to every zone
C. Storing zone files on a publicly accessible web server
D. Disabling logging of DNS changes

💡 Difficulty: easy | ✅ Correct: A

📖 Explanation:

Role‑based access control (RBAC) allows administrators to be assigned only the permissions necessary for their duties. By restricting write privileges to the zones they manage, the chance that a compromised account or insider inadvertently modifies an unrelated zone is minimized. Broad write access or insecure storage dramatically increase exposure, while logging is a detection rather than prevention measure.

Q8. How does DNS‑based Authentication of Named Entities (DANE) leverage DNSSEC to improve TLS certificate validation?

A. DANE replaces DNSSEC signatures with TLS handshakes
B. DANE encrypts DNS queries to hide certificate data
C. DANE disables certificate authorities entirely
D. DANE uses DNSSEC‑validated TLSA records to bind certificates to domain names ✅

💡 Difficulty: medium | ✅ Correct: D

📖 Explanation:

DANE defines TLSA records that specify expected TLS certificate or public key information for a service. Because these TLSA records are secured by DNSSEC, a resolver can trust that the information has not been tampered with. This allows clients to verify that the presented certificate matches the DNS‑published expectation, augmenting or even replacing traditional CA‑based validation.

Q9. During a ZSK rollover, a resolver receives both the old and new DNSKEY records signed with the same RRSIG. Which of the following best explains why the resolver can still validate the zone?

A. The resolver validates signatures with any key listed in the DNSKEY RRset as long as at least one matches the DS ✅
B. The resolver trusts the newer key because of its later inception date
C. The resolver discards the old key and uses only the new one
D. The resolver cannot validate until the old key is removed

💡 Difficulty: medium | ✅ Correct: A

📖 Explanation:

In a rollover, both the old and new DNSKEY records are published simultaneously, and the DS record in the parent zone points to the key set as a whole. As long as at least one of the DNSKEYs in the RRset matches the DS, the resolver can verify the RRSIGs. This overlapping period ensures continuous validation while the new key becomes active.

Q10. What does the acronym 'DNSSEC' stand for?

A. Domain Name System Secure
B. Domain Name System Security Extensions ✅
C. Distributed Network System Encryption
D. Data Network Service Encryption

💡 Difficulty: medium | ✅ Correct: B

📖 Explanation:

DNSSEC stands for Domain Name System Security Extensions. It is an add‑on to the original DNS protocol that introduces digital signatures and a chain of trust, allowing resolvers to verify the authenticity and integrity of DNS data. The other options are common misconceptions but do not reflect the official terminology.
