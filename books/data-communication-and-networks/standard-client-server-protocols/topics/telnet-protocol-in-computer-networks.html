What is TELNET protocol in computer networks?

TELNET is a legacy network protocol that provides a virtual terminal interface for remote command-line access to another computer over TCP/IP, allowing users to execute commands on a remote host as if they were sitting at its console.

Q1. If a program requires guaranteed delivery of data, which Java class should be chosen and why?

A. DatagramSocket because it handles retransmission automatically
B. Socket because it provides a TCP connection with reliability ✅
C. Both classes provide the same reliability
D. Neither; reliability must be implemented manually

💡 Difficulty: easy | ✅ Correct: B

📖 Explanation:

Socket uses TCP, which ensures ordered, loss‑free delivery through acknowledgments and retransmissions. DatagramSocket relies on UDP, which offers no such guarantees, so the correct choice for reliability is the Socket class.

Q2. When a client creates a DatagramSocket using the no‑argument constructor, how does the socket become bound to a local address?

A. The OS assigns an arbitrary local port and IP at the moment of the first send ✅
B. The constructor explicitly binds to 0.0.0.0:0
C. The socket remains unbound until bind() is called
D. It throws an exception because binding is mandatory

💡 Difficulty: easy | ✅ Correct: A

📖 Explanation:

The no‑arg constructor creates an unbound socket; the first call to send() triggers the OS to allocate an available local port and bind the socket to the appropriate local IP, satisfying the requirement that a socket be bound before communication.

Q3. Explain the mechanism by which the UDP client in Table 25.13 blocks execution until the server’s response arrives.

A. It uses a busy‑wait loop checking a flag
B. It calls receive() on a DatagramSocket, which is a blocking call ✅
C. It sleeps for a fixed time then checks the socket
D. It registers a callback with the OS

💡 Difficulty: hard | ✅ Correct: B

📖 Explanation:

DatagramSocket.receive(Packet) is a blocking operation; the thread halts until a datagram arrives or a timeout occurs. This design lets the client pause execution without consuming CPU cycles, effectively “sleeping” until the server’s reply is placed in the packet buffer.

Q4. Which of the following statements correctly compares the two DatagramPacket constructors regarding their suitability for sending data?

A. The constructor with byte[] buffer, length, address, port is used for sending ✅
B. The constructor with only byte[] buffer and length is used for sending
C. Both constructors can be used interchangeably for sending
D. Neither constructor is appropriate for sending

💡 Difficulty: medium | ✅ Correct: A

📖 Explanation:

To send a datagram, the packet must contain the destination address and port, which are supplied by the constructor that accepts those parameters. The simpler constructor lacks this information and is intended for receiving packets, where the source is filled by the system.

Q5. In what fundamental way does ServerSocket differ from Socket in Java network programming?

A. ServerSocket listens for incoming connections while Socket represents an active connection ✅
B. ServerSocket can send data directly, Socket cannot
C. Socket can accept multiple clients, ServerSocket handles only one
D. There is no difference; they are aliases

💡 Difficulty: easy | ✅ Correct: A

📖 Explanation:

A ServerSocket binds to a local port and invokes accept() to create a new Socket for each client, establishing a dedicated two‑way channel. A Socket, by contrast, represents one end of an already‑established TCP connection and is used for data exchange, not for listening.

Q6. Given two methods that convert an IPv4 address string to a 32‑bit integer, which approach is more efficient and why?

A. Using String.split and Integer.parseInt for each octet
B. Using a regular expression to parse the whole address
C. Using java.net.InetAddress.getByName and getAddress() ✅
D. Using a lookup table of pre‑computed values

💡 Difficulty: medium | ✅ Correct: C

📖 Explanation:

InetAddress.getByName parses the textual address once and returns a byte array; converting that array to an integer is straightforward and avoids repeated string manipulation. The other methods involve multiple allocations or regex processing, which are slower and consume more memory.

Q10. Why does the TCP client program avoid using high‑level input stream classes such as Scanner directly on the socket?

A. Because Scanner cannot handle binary data and may block on delimiters ✅
B. Because Scanner is deprecated for network I/O
C. Because high‑level streams are slower than low‑level byte streams
D. Because the socket does not support character encoding

💡 Difficulty: hard | ✅ Correct: A

📖 Explanation:

Scanner parses input based on delimiters (whitespace, line breaks) and assumes a character encoding, which can cause it to block or misinterpret binary protocols. Directly using InputStreamReader and BufferedReader gives precise control over encoding and avoids unintended waiting for delimiters that may never appear.

Q12. Consider the two methods getPort() and getLocalPort() of a Socket object. Which statement best evaluates their differences in the context of a client connecting to a server?

A. getPort() returns the remote server’s port, while getLocalPort() returns the client‑side ephemeral port ✅
B. Both methods return the same value after connection is established
C. getPort() can be used before connect(), getLocalPort() only after
D. getLocalPort() returns the remote port, getPort() returns the local port

💡 Difficulty: medium | ✅ Correct: A

📖 Explanation:

When a client socket connects, getPort() yields the destination (server) port number, whereas getLocalPort() reveals the automatically assigned local (ephemeral) port on the client side. This distinction is crucial for logging, firewall rules, or when multiple connections share the same remote endpoint.

Q13. Write a Java method that converts a 32‑bit unsigned integer to a dotted‑decimal IP string; which of the following implementations is correct?

A. String ip = ((addr>>24)&0xFF)+\.\+((addr>>16)&0xFF)+\.\+((addr>>8)&0xFF)+\.\+(addr&0xFF); ✅
B. String ip = (addr&0xFF)+\.\+((addr>>8)&0xFF)+\.\+((addr>>16)&0xFF)+\.\+((addr>>24)&0xFF);
C. String ip = Integer.toBinaryString(addr).replaceAll(\(.{8})\,\$1.\);
D. String ip = InetAddress.getByAddress(ByteBuffer.allocate(4).putInt(addr).array()).getHostAddress();

💡 Difficulty: medium | ✅ Correct: A

📖 Explanation:

The first option extracts each octet by shifting the integer right by 24, 16, and 8 bits and masking with 0xFF, then concatenates them with periods. This yields the standard dotted‑decimal notation. The second option reverses the order, the third produces binary groups, and the fourth requires handling signedness, making option A the correct implementation.
