What is DNS query and response message format?

DNS messages consist of a header with identification and flags, a question section specifying the queried name and type, and optional answer, authority, and additional sections containing resource records that provide the resolution data.

📝 All DNS query and response message format MCQs

Q1. In a standard DNS message header, which field specifies the number of resource records returned in the answer section?

A.Answer Count ✅
B.Question Count
C.Authority Count
D.Additional Count
💡 Difficulty: easy | ✅ Correct: A

📖 Explanation: The DNS header includes a 16‑bit Answer RRs field that tells the resolver how many resource records appear in the answer section. This count is separate from the Question Count, Authority Count, and Additional Count fields, each of which tracks a different part of the message.

Q2. When a DNS response has the TC (truncated) flag set, what is the most appropriate action for the resolver?

A.Resend the query using UDP
B.Retry the query over TCP ✅
C.Discard the response
D.Send an ICMP error message
💡 Difficulty: easy | ✅ Correct: B

📖 Explanation: The TC flag indicates that the response was cut short because it exceeded the UDP payload limit. The resolver should therefore re‑issue the same query using TCP, which can carry the full message without truncation, ensuring complete data retrieval.

Q3. Which statement correctly contrasts the QR flag usage in a DNS query versus a DNS response?

A.QR is 0 in queries and 1 in responses ✅
B.QR is 1 in queries and 0 in responses
C.QR is always 0
D.QR is always 1
💡 Difficulty: easy | ✅ Correct: A

📖 Explanation: The QR (Query/Response) flag distinguishes a message's purpose: it is cleared (0) for a query sent by a client and set (1) for a response generated by a server. This binary distinction allows receivers to quickly interpret the direction of the message.

Q4. A resolver wants the authoritative server to perform recursion. Which flag must be set, and what value should the RD bit have in the query header?

A.RD set to 0
B.RD set to 1 ✅
C.RA set to 1
D.RA set to 0
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: The Recursion Desired (RD) flag tells the server that the client wishes the server to pursue recursive resolution on its behalf. Setting RD to 1 in the query header signals this intent, while the Recursion Available (RA) flag is set by the server in its response.

Q5. If a DNS response returns an RCODE of 3 (NXDOMAIN), what can the resolver infer about the queried domain name?

A.The domain definitely does not exist ✅
B.The domain exists but has no records
C.The server refused to answer
D.The response is malformed
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: An RCODE of 3 means NXDOMAIN, indicating that the queried name does not exist in the DNS namespace. The resolver can safely conclude that the domain name is invalid and should not be retried without modification.

Q6. Suppose a resolver advertises an EDNS0 UDP payload size of \(4096\) bytes, but the authoritative server sends a response of \(4500\) bytes. What is the likely outcome?

A.The response is truncated and the TC flag is set ✅
B.The server will switch to TCP automatically
C.The resolver will ignore the extra bytes
D.The response will be delivered over UDP without issue
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: When a response exceeds the advertised UDP payload, the server sets the TC (truncated) flag, indicating that the full answer is larger than can be sent in a single UDP packet. The resolver then typically retries the query over TCP to obtain the complete data.

Q7. How does the TTL field in each resource record influence a resolver’s caching strategy when multiple responses with differing TTLs are received for the same query?

A.Resolver uses the smallest TTL ✅
B.Resolver uses the largest TTL
C.Resolver averages the TTLs
D.TTL is ignored for caching
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: Each RR is cached with its own TTL, and the overall cache entry expires when the shortest remaining TTL among the set of records elapses. This ensures that no stale data persists longer than the least‑fresh record, preserving consistency across cached answers.

Q8. A resolver receives a DNS response whose transaction ID does not match the ID of any outstanding query. Assuming no network attacks, what is the most plausible explanation?

A.The resolver reused an ID too quickly
B.The response is from a previous query still in transit ✅
C.The server generated a random ID
D.The response was corrupted in transit
💡 Difficulty: hard | ✅ Correct: B

📖 Explanation: The most likely scenario is that the response belongs to an earlier query that was delayed in the network. Because the resolver had already reused the transaction ID for a newer query, the unexpected ID appears mismatched, reflecting normal out‑of‑order delivery.

Q9. An attacker sends a DNS query of size \(60\) bytes to an open resolver that supports EDNS0 with a UDP payload size of \(4096\) bytes, requesting a DNSSEC‑signed response. If the response is \(4{,}000\) bytes, calculate the amplification factor and explain why this poses a security risk.

A.Amplification factor ≈ 66.7 ✅
B.Amplification factor ≈ 40
C.Amplification factor ≈ 100
D.Amplification factor ≈ 20
💡 Difficulty: hard | ✅ Correct: A

📖 Explanation: The amplification factor is the response size divided by the query size: \(4{,}000 ÷ 60 ≈ 66.7\). Such a large multiplier enables attackers to flood a victim with far more traffic than they send, turning modest queries into massive responses and facilitating DDoS attacks.

Q10. When constructing a DNS response that includes DNSSEC RRSIG records, which sections must be present and how do they interrelate to ensure authenticity?

A.Question and Answer sections only
B.Answer and Authority sections with matching RRSIG
C.Answer, Authority, and Additional sections with RRSIG covering each RRset ✅
D.Only the Additional section is needed
💡 Difficulty: hard | ✅ Correct: C

📖 Explanation: A DNSSEC‑enabled response must contain the original RRsets (Answer, Authority, and sometimes Additional) together with corresponding RRSIG records that cryptographically cover each RRset. The RRSIGs provide signatures that validators can verify using the appropriate DNSKEY, establishing the integrity and authenticity of the entire response.
