What is Recursive vs iterative DNS resolution?

Definition:
DNS resolution can occur via recursive or iterative queries. In a recursive query, the DNS server takes full responsibility for resolving the name, querying other servers on behalf of the client until it finds the answer or an error. In an iterative query, the server returns the best answer it has, often a referral to another server, leaving the client to continue the query process with the referred server.

Working:
In recursive resolution, the client asks its local resolver, 'What is the IP for example.com?' The resolver queries root, TLD, and authoritative servers sequentially, hiding this complexity from the client. In iterative resolution, the client asks the root server, which replies, 'Ask the .com server.' The client then asks the .com server, which replies, 'Ask example.com's server,' and so on.

Example:
Recursive: Your PC asks ISP DNS for yahoo.comyahoo.comyahoo.com. ISP DNS does all the work, querying roots, TLDs, and Yahoo's servers, then returns the final IP to your PC. Iterative: Your PC asks root server. Root says 'Ask .com server'. Your PC asks .com server. It says 'Ask yahoo.com server'. Your PC asks Yahoo's server, which gives the IP. Your PC did the legwork.

Reason:
Recursive queries reduce load on client devices and simplify client software, as the heavy lifting is done by powerful resolvers. Iterative queries distribute the load across the DNS infrastructure, preventing any single server from being overwhelmed by complex resolution tasks. Most end-users experience recursive resolution, while servers use iterative queries among themselves.

Common MisConceptions:
Students often think iterative queries are faster. In reality, recursive queries are faster for the end-user because the resolver often has cached results. Iterative queries require multiple round-trips from the client. Another error is believing that only one type exists; in practice, a mix is used, with clients sending recursive queries to resolvers, which use iterative queries to find answers.

Exam Preparation Tips: How to prepare this topic
Draw flowcharts for both recursive and iterative processes. Identify who does the work in each case (client vs server). Understand that most stub clients send recursive queries to resolvers. Resolvers send iterative queries to other DNS servers. Practice explaining the pros and cons of each method in terms of load and complexity.

Key Terms:

  • Recursive Query - Server resolves fully for client.
  • Iterative Query - Server refers client to next server.
  • Stub Resolver - Client-side DNS component.
  • Referral - Pointer to another authoritative server.

Q1. Which function creates a UDP socket?

A.socket(PF_INET, SOCK_DGRAM, 0) ✅
B.socket(AF_INET, SOCK_STREAM, 0)
C.socket(PF_INET, SOCK_STREAM, 0)
D.socket(AF_INET, SOCK_DGRAM, 0)
💡 Difficulty: easy | ✅ Correct: A

📖 Explanation: The UDP socket is created by calling socket with the domain PF_INET (or AF_INET), the type SOCK_DGRAM, and protocol 0. This combination selects the datagram service of IPv4. The other options specify either stream sockets or the wrong domain, which would not produce a UDP socket.

Q2. Why is a null character appended to the echoed message before printing?

A.To terminate the string for proper display ✅
B.To indicate end‑of‑file
C.To signal a network error
D.To reset the socket buffer
💡 Difficulty: easy | ✅ Correct: A

📖 Explanation: Appending '\0' creates a C‑style string terminator, allowing functions like printf or puts to know where the text ends. Without it, the printing routine would continue reading beyond the intended message, potentially outputting garbage data. This step is purely for safe, readable debugging output.

Q3. Which statement best compares TCP and UDP regarding reliability?

A.TCP guarantees ordered delivery, UDP does not ✅
B.UDP guarantees ordered delivery, TCP does not
C.Both guarantee ordered delivery
D.Neither guarantees ordered delivery
💡 Difficulty: easy | ✅ Correct: A

📖 Explanation: TCP is connection‑oriented and provides sequencing, acknowledgments, and retransmission, ensuring that data arrives in order. UDP is connectionless and sends datagrams without such guarantees; packets may arrive out of order, be duplicated, or be lost. Therefore, only TCP offers reliable, ordered delivery.

Q4. What is the purpose of the htons function in the code snippet servAddr.sin_port = htons(servPort);?

A.Convert host byte order to network byte order for the port ✅
B.Convert network byte order to host byte order for the port
C.Encrypt the port number
D.Validate the port range
💡 Difficulty: easy | ✅ Correct: A

📖 Explanation: Network protocols use big‑endian (network) byte order. htons (“host to network short”) transforms a 16‑bit port number from the host’s native ordering to network ordering, ensuring that the receiving side interprets the port correctly. Without this conversion, mismatched byte orders could cause connection failures.

Q5. If sendto returns -1, what can be logically inferred?

A.An error occurred during transmission ✅
B.The message was delivered successfully
C.The socket was closed automatically
D.The server responded with an ACK
💡 Difficulty: easy | ✅ Correct: A

📖 Explanation: A return value of -1 from sendto indicates that the system call failed, typically setting errno to describe the problem (e.g., EACCES, ENOTCONN). It means the data was not transmitted, and the program should handle the error before proceeding.

Q6. How does the error‑handling block if ((s = socket(PF_INET, SOCK_DGRAM, 0) < 0)) affect program robustness?

A.It detects socket creation failure and exits gracefully ✅
B.It silently ignores failures
C.It retries socket creation indefinitely
D.It changes the socket type to TCP
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: The conditional checks whether the socket call returned a negative descriptor, which signals failure. By invoking perror and exit(1), the program reports the issue and terminates, preventing subsequent undefined behavior. This defensive pattern improves robustness by ensuring resources are valid before use.

Q7. Why is it important to close the socket with close(s) before exiting the program?

A.It releases the file descriptor and frees associated resources ✅
B.It encrypts the transmitted data
C.It flushes pending TCP acknowledgments
D.It resets the network interface
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: Closing the socket returns the file descriptor to the operating system, allowing other processes to reuse it and preventing resource leaks. For UDP, it also discards any pending datagrams. Failing to close may leave descriptors open, consuming kernel resources and potentially causing exhaustion in long‑running applications.

Q8. What would be the effect of omitting the null character when printing the echoed message?

A.Garbage characters may appear after the intended text ✅
B.The program would crash immediately
C.The message would be sent twice
D.The socket would be closed automatically
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: Without a terminating '\0', printing functions treat the buffer as a C‑string and continue reading memory until a zero byte is encountered. This can result in extra, unintended characters being displayed, possibly exposing sensitive data or causing confusing output during debugging.

Q9. Compare send and sendto when used with UDP sockets. Which statement is accurate?

A.Both can transmit datagrams, but sendto requires destination address each call ✅
B.Only send works with UDP, sendto requires TCP
C.send automatically retries on loss, sendto does not
D.sendto adds encryption, send  does not
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: When a UDP socket is unconnected, sendto allows specifying the target address with each call, while send can be used after a prior connect to fix the peer. Both functions place datagrams on the network; neither provides reliability or retransmission, which are intrinsic to TCP only.

Q10. How does the connection‑oriented nature of TCP influence the sequence of socket calls compared to UDP?

A.TCP requires connect before send/recv, UDP does not ✅
B.UDP requires connect before send/recv, TCP does not
C.Both require connect before any data transfer
D.Neither requires connect for data transfer
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: TCP establishes a reliable session via connect, which negotiates sequence numbers and flow control. After this handshake, send and recv operate on the established connection. UDP is connectionless; it can send datagrams directly with sendto without a prior connect, though an optional connect can set a default peer.

Q11. If the programmer forgets to apply htons to servPort, what is the most likely outcome?

A.The server will bind to an unintended port number ✅
B.The socket will automatically correct the order
C.The program will compile with a warning
D.The port number will be encrypted
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: Omitting htons leaves the port in host byte order. On little‑endian machines this swaps the high and low bytes, causing the socket to bind to a different numeric port than intended. The server will then listen on the wrong port, and clients will fail to connect.

Q14. What logical consequence follows if the client specifies an incorrect servPort value?

A.The client’s packets will be directed to the wrong service or be dropped ✅
B.The server will automatically adjust the port
C.The operating system will correct the port number
