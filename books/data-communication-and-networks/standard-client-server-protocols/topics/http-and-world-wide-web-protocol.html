📝 HTTP and World Wide Web protocol (8 MCQs)

HTTP as the Web's Application-Layer Exchange

The Hypertext Transfer Protocol (HTTP) enables web clients and servers to exchange representations of resources across an IP network. A browser sends requests for documents, images, scripts or other resources, and a web server returns responses describing the result. HTTP belongs to the application layer; it defines message semantics while lower layers provide transport, addressing and delivery. These shared semantics let different browsers and servers interoperate reliably across different operating environments.

Resources, URLs and Client–Server Roles

A resource is identified by a Uniform Resource Identifier, commonly a URL containing a scheme, host and path. The client identifies the target and selects a method, while the server maps the request to a resource or application. Headers carry metadata such as content type, caching instructions and authentication information; the message body carries optional content.

Request and Response Message Processing

The client resolves the server name, establishes an appropriate transport connection, and sends an HTTP request. The server parses the method, target and headers, performs the requested operation, then returns a status code, response headers and possibly a representation. The client interprets the result and may request additional page resources through further exchanges.

Retrieving a Web Page from an Origin Server

When a browser requests https://example.com/index.html, it first obtains an IP address for example.com and establishes a protected connection. It sends a GET request for /index.html with a Host field in HTTP/1.1. A successful server response commonly carries status 200, a Content-Type field and the HTML document for rendering.

HTTP's Relationship with TCP, TLS and QUIC

HTTP commonly uses TCP for HTTP/1.1 and HTTP/2, with TLS protecting HTTPS sessions. HTTP/3 retains HTTP semantics but maps them over QUIC, which uses UDP. DNS helps locate the host, while TCP or QUIC transports messages and IP forwards packets; HTTP itself does not perform routing or link-level delivery.

Misunderstandings About Web Protocol Behavior

'HTTP encrypts every message by itself' is incorrect because encryption is supplied by HTTPS security using TLS or by the secure transport arrangement. 'HTTP remembers every user automatically' is false because HTTP semantics are stateless unless applications add state. 'A 404 means the server is offline' is wrong because it reports that the target resource was not found.

Interpreting HTTP Methods, Status Codes and Headers

Be able to distinguish a URL from an IP address, a request method from a status code, and a header from a message body. Interpret GET, POST, PUT and DELETE by their defined semantics; classify 2xx, 3xx, 4xx and 5xx responses; and explain how DNS, transport protocols and TLS support a web exchange without becoming HTTP functions.

HTTP and Web Communication Terms

  • HTTP - Carries requests and responses for web resources.
  • URL - Identifies a resource and its location.
  • Method - Specifies the intended operation on a resource.
  • Header field - Carries metadata about a message.
  • Status code - Reports the result of request processing.
  • Origin server - Hosts the requested resource.

📝 All HTTP and World Wide Web protocol MCQs

Q1. If a web page contains a hyperlink to another page on a different server, what is the most direct effect on the user’s request?

A.Browser sends a DNS query to resolve the original site’s address
B.The original server redirects the request to the target server
C.Browser initiates a new HTTP request to the target server ✅
D.No network activity occurs
💡 Difficulty: easy | ✅ Correct: C

📖 Explanation: When the user clicks the link, the browser must locate the target resource. It does this by creating a new HTTP request directed at the server that hosts the linked page, using the URL provided. This request is independent of the original page’s connection, so the correct effect is a new HTTP request to the target server.

Q2. Which of the following best compares the GET and POST methods when a web form includes a file upload?

A.GET appends form data to the URL, making it unsuitable for large binary files, while POST includes data in the request body, allowing file uploads. ✅
B.GET encrypts the file data, whereas POST sends it in plain text.
C.GET can only be used for retrieving resources, not for submitting any form data.
D.POST always results in a cached response, while GET never does.
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: GET places all form data in the query string of the URL, which is limited in length and visible to observers, so it cannot reliably carry large binary files. POST places the data in the request body, supporting arbitrarily large payloads and keeping the URL clean, making it the appropriate method for file uploads.

Q3. HTTP is described as a stateless protocol. Which mechanism most effectively allows a web application to maintain a user’s login state across multiple requests?

A.Using cookies with session identifiers ✅
B.Embedding user credentials in every URL
C.Relying on the client’s IP address
D.Keeping a persistent TCP connection
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: Because HTTP does not retain information between requests, the server issues a cookie containing a unique session identifier. The browser returns this cookie with each subsequent request, allowing the server to associate the request with the previously authenticated session. This approach preserves login state without violating HTTP’s stateless nature.

Q4. What does the acronym URL stand for?

A.Uniform Resource Locator ✅
B.Universal Retrieval Link
C.Unified Resource List
D.Unique Reference Link
💡 Difficulty: easy | ✅ Correct: A

📖 Explanation: The term URL is a standard abbreviation in web technology that means Uniform Resource Locator. It specifies the address used to access a resource on the Internet, indicating the protocol, host, and path needed to retrieve the resource.

Q5. A browser has cached a resource with ETag \abc123\. The server later updates the resource. The browser sends a conditional GET with If-None-Match \abc123\. What is the most likely server response?

A.Server returns 200 OK with new content ✅
B.Server returns 304 Not Modified
C.Server returns 404 Not Found
D.Server returns 500 Internal Server Error
💡 Difficulty: hard | ✅ Correct: A

📖 Explanation: When the server detects that the ETag supplied by the client does not match the current version of the resource, it knows the cached copy is stale. Consequently, it sends a fresh representation with a 200 OK status, providing the updated content to the browser.

Q6. Which statement best explains why HTTPS provides better security than HTTP?

A.HTTPS uses larger packet sizes
B.HTTPS encrypts the payload using TLS, ensuring confidentiality and integrity ✅
C.HTTPS disables caching
D.HTTPS forces browsers to use IPv6
💡 Difficulty: hard | ✅ Correct: B

📖 Explanation: HTTPS adds a TLS (or SSL) layer on top of HTTP, encrypting the entire request and response payload. This encryption protects data from eavesdropping, while TLS also provides authentication of the server and integrity checks, preventing tampering and man‑in‑the‑middle attacks.

Q7. In HTTP/1.1 persistent connections, which sequence correctly describes a client retrieving two resources from the same server without closing the connection?

A.Open connection → GET resource1 → Close → Open new → GET resource2 → Close
B.Open connection → GET resource1 → GET resource2 → Close ✅
C.Open connection → GET resource1 → Wait for server to close → GET resource2
D.Open connection → POST resource1 → GET resource2 → Close
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: HTTP/1.1 allows a single TCP connection to stay open for multiple requests. After establishing the connection, the client can issue a GET for the first resource, immediately follow it with a second GET for the next resource, and finally close the socket when all transfers are complete.

Q8. How does hypermedia extend the concept of hypertext in the modern Web?

A.Hypermedia includes text, images, audio, and video as linked resources ✅
B.Hypermedia restricts links to only textual content
C.Hypermedia eliminates the need for URLs
D.Hypermedia requires proprietary browsers to function
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: Originally, hypertext referred only to linked textual documents. Modern hypermedia expands this idea by allowing any type of media—pictures, sound, video, and interactive content—to be linked and retrieved via hyperlinks. This broader definition reflects the diverse nature of contemporary web pages, which often combine multiple media types in a single navigable experience.
