Q1. Which function is used to bind a socket to an address?

🔹 A. bind
🔹 B. connect
🔹 C. listen
🔹 D. accept

💡 Difficulty: easy | ✅ Correct: A

📖 Explanation:

The bind function associates a socket descriptor with a specific local address and port, which is necessary before the server can receive datagrams. It does not establish a connection (connect), listen for connections (listen), or accept incoming connections (accept). Hence option A is correct.

Q2. What is the primary purpose of the perror function in the echo server code?

🔹 A. Print a descriptive error message to stderr
🔹 B. Terminate the program immediately
🔹 C. Send an error packet to the client
🔹 D. Allocate memory for the buffer

💡 Difficulty: medium | ✅ Correct: A

📖 Explanation:

perror examines the global errno variable and prints a human‑readable description of the last error, prefixed by a custom string. It aids debugging but does not affect program flow, memory allocation, or network transmission, making option A the accurate description.

Q3. If the recvfrom call blocks indefinitely, which of the following is the most likely cause?

🔹 A. The client never sent a datagram
🔹 B. The socket is non‑blocking
🔹 C. The server called bind incorrectly
🔹 D. The buffer size is too small

💡 Difficulty: easy | ✅ Correct: A

📖 Explanation:

recvfrom is a blocking call that waits for incoming data. If it never returns, the usual reason is that no datagram arrived from any client. Non‑blocking mode would cause an immediate error, and bind or buffer size issues would be detected earlier, so option A is correct.

Q4. Given the code fragment \( \text{len}= \text{recvfrom}(s, buffer, sizeof(buffer), 0, (struct sockaddr*)&clntAddr, &clntAddrLen); \), what logical inference can be made about the value of len after a successful call?

🔹 A. len equals the number of bytes received
🔹 B. len is always zero
🔹 C. len contains the client’s IP address
🔹 D. len is the size of clntAddrLen

💡 Difficulty: medium | ✅ Correct: A

📖 Explanation:

recvfrom returns the number of bytes placed into the buffer, which is stored in len. It never returns zero on success unless an empty datagram is received, and it does not return address information, so the correct inference is that len equals the byte count.

Q5. Why might the server choose to call sendto with sizeof(clntAddr) instead of clntAddrLen when responding to the client?

🔹 A. To ensure the entire address structure is transmitted
🔹 B. Because sizeof(clntAddr) is always smaller
🔹 C. Because clntAddrLen is uninitialized
🔹 D. To avoid blocking the call

💡 Difficulty: hard | ✅ Correct: A

📖 Explanation:

Using sizeof(clntAddr) guarantees that the full sockaddr structure is supplied, regardless of the actual length stored in clntAddrLen. This prevents truncation errors that could arise if clntAddrLen were smaller than the structure size, making option A the most logical justification.

Q6. In the infinite loop of the server, which logical relationship best describes the sequence of operations?

🔹 A. recvfrom → sendto → repeat
🔹 B. sendto → recvfrom → repeat
🔹 C. bind → recvfrom → repeat
🔹 D. recvfrom → bind → repeat

💡 Difficulty: easy | ✅ Correct: A

📖 Explanation:

Each iteration first receives a client request via recvfrom, then immediately echoes it back with sendto, after which the loop repeats. The bind operation occurs only once before the loop, so the correct order is recvfrom followed by sendto.

Q7. If the server receives a datagram larger than sizeof(buffer), what is the most probable outcome?

🔹 A. The excess bytes are discarded
🔹 B. The server crashes
🔹 C. The buffer is automatically resized
🔹 D. recvfrom returns an error code

💡 Difficulty: medium | ✅ Correct: A

📖 Explanation:

recvfrom copies up to the size of the supplied buffer; any bytes beyond that are silently dropped. It does not cause a crash nor resize the buffer, and it still returns the number of bytes copied, making option A correct.

Q8. Consider two UDP echo servers: one uses a fixed‑size buffer, the other dynamically allocates a buffer based on the incoming datagram size. Which analytical comparison is most accurate?

🔹 A. Dynamic allocation reduces memory waste but adds allocation overhead
🔹 B. Fixed buffers always improve performance
🔹 C. Dynamic allocation prevents any packet loss
🔹 D. Fixed buffers guarantee security

💡 Difficulty: medium | ✅ Correct: A

📖 Explanation:

A dynamically sized buffer matches the exact datagram length, minimizing unused space, yet each recvfrom incurs malloc/free overhead. Fixed buffers avoid allocation cost but may waste memory or truncate data. Hence option A captures the trade‑off accurately.

Q9. How does the use of a separate clntAddrLen variable affect the reliability of the recvfrom call?

🔹 A. It tells recvfrom the size of the address structure
🔹 B. It determines the maximum datagram size
🔹 C. It stores the received data length
🔹 D. It configures socket timeout

💡 Difficulty: easy | ✅ Correct: A

📖 Explanation:

clntAddrLen is passed by reference; recvfrom updates it with the actual size of the client’s address. This allows the program to know precisely how many bytes of address information were filled, which is essential for correct subsequent use of the address.

Q10. A developer replaces the blocking recvfrom with a non‑blocking version and adds a sleep(1) inside the loop. Which logical consequence is most likely?

🔹 A. CPU usage will increase due to busy‑waiting
🔹 B. The server will stop receiving packets
🔹 C. Latency will decrease dramatically
🔹 D. The socket will close automatically

💡 Difficulty: hard | ✅ Correct: A

📖 Explanation:

Non‑blocking recvfrom returns immediately if no data is present, causing the loop to iterate rapidly. Adding sleep(1) reduces the busy‑wait but still results in periodic polling, increasing overall CPU usage compared to a true blocking call. Hence option A reflects the most plausible effect.

Q11. When evaluating error handling, why is it important to check the return value of bind before entering the main loop?

🔹 A. A failed bind means the socket cannot receive any datagrams
🔹 B. bind errors are harmless and can be ignored
🔹 C. bind returns the number of clients connected
🔹 D. bind automatically retries on failure

💡 Difficulty: medium | ✅ Correct: A

📖 Explanation:

If bind fails, the socket is not associated with any local address, so any subsequent recvfrom or sendto operations will fail. Early detection prevents the server from entering an infinite loop that cannot serve clients, making option A the correct evaluation.

Q12. Which conceptual principle explains why UDP does not require a listen or accept step before receiving data?

🔹 A. Connectionless communication model
🔹 B. Reliability guarantees
🔹 C. Flow control mechanisms
🔹 D. Three‑way handshake

💡 Difficulty: easy | ✅ Correct: A

📖 Explanation:

UDP operates without establishing a dedicated connection; therefore, a server can receive datagrams as soon as the socket is bound, without invoking listen or accept. This reflects the connectionless principle, making option A correct.

Q15. Which logical reasoning best explains why the server uses an infinite loop after successful bind?

🔹 A. It must continuously listen for new client datagrams
🔹 B. It needs to re‑bind for each client
🔹 C. It wants to allocate a new socket each iteration
🔹 D. It aims to close the socket after one message

💡 Difficulty: easy | ✅ Correct: A

📖 Explanation:

After binding, the socket is ready to receive datagrams. An infinite loop ensures the server remains active, handling each incoming request in turn. Re‑binding or closing would prevent further communication, so option A correctly captures the reasoning.

Q16. In a scenario where multiple clients send datagrams simultaneously, how does the UDP echo server handle concurrent requests?

🔹 A. It processes them sequentially as they arrive
🔹 B. It spawns a new thread for each client
🔹 C. It merges the datagrams into one response
🔹 D. It drops all but the first datagram

💡 Difficulty: medium | ✅ Correct: A

📖 Explanation:

UDP sockets deliver datagrams to the kernel queue; the server’s single‑threaded loop dequeues them one by one, effectively handling requests sequentially. No automatic threading or merging occurs, making option A the correct description.

UDP is connectionless and does not assure that datagrams arrive, arrive in order, or are not duplicated. TCP, by contrast, provides reliable, ordered delivery. Hence option A correctly contrasts the reliability aspects.

Q25. Why is it unnecessary for the UDP server to call listen or accept before invoking recvfrom?

🔹 A. UDP sockets are already ready to receive after bind
🔹 B. listen is only for client sockets
🔹 C. accept is used only with raw sockets
🔹 D. recvfrom internally calls listen

💡 Difficulty: easy | ✅ Correct: A

📖 Explanation:

In the UDP model, binding makes the socket ready to receive datagrams. There is no concept of listening for connections or accepting them, which are TCP‑specific operations. Therefore option A explains the necessity.
