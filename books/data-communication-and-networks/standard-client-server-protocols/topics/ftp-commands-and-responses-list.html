What is FTP commands and responses list?

FTP relies on text-based commands like USER, PASS, RETR, STOR, and LIST sent over the control connection, with the server replying using three-digit numeric codes such as 220 for ready, 331 for password required, and 550 for file unavailable.

Q1. If a client attempts to initiate a TCP connection before the server program has called listen(), what is the most likely outcome?

A.Connection succeeds immediately
B.Operating system automatically starts the server
C.Client receives a connection‑refused error ✅
D.Server queues the request until it starts listening
💡 Difficulty: easy | ✅ Correct: C

📖 Explanation: When the server has not called listen(), there is no socket bound to the destination port, so the TCP three‑way handshake cannot be completed. The client’s connect() call fails and returns an error such as ECONNREFUSED, indicating that the remote side actively refused the connection.

Q2. Which statement best compares the socket API with the Transport Layer Interface (TLI) regarding portability and usage?

A.Socket API is less portable but offers richer features
B.Socket API is more portable and widely adopted ✅
C.TLI provides higher‑level abstractions than sockets
D.Both are identical in functionality
💡 Difficulty: easy | ✅ Correct: B

📖 Explanation: The socket API originated on BSD Unix and was quickly adopted across many operating systems, making it highly portable and the de‑facto standard for network programming. TLI, while standardized, saw limited implementation and is less commonly used, so sockets are generally considered more portable and widely supported.

Q3. In the TCP/IP stack, the socket API primarily abstracts which layer for the application programmer?

A.Transport layer (TCP/UDP) ✅
B.Network layer (IP)
C.Data link layer (Ethernet)
D.Physical layer (hardware)
💡 Difficulty: easy | ✅ Correct: A

📖 Explanation: The socket interface presents functions such as socket(), bind(), listen(), and send()/recv() that operate on transport‑layer protocols like TCP and UDP. It hides lower‑level details of IP routing and framing, allowing applications to work directly with reliable streams or datagrams without dealing with network‑layer or link‑layer specifics.

Q4. A server process crashes and restarts without re‑binding its listening socket. What problem is most likely to occur when a client later connects?

A.Clients will receive corrupted data
B.Server will accept connections but cannot read data
C.Clients will be redirected to another server
D.Bind error because the address is already in use ✅
💡 Difficulty: medium | ✅ Correct: D

📖 Explanation: When the server restarts without rebinding, the operating system still holds the previous socket binding. Attempting to bind the same address and port results in an EADDRINUSE error, preventing the server from listening for new connections until the old socket is released or the address is cleared.

Q5. Why is the client’s lifetime typically finite while the server’s lifetime is considered infinite in a client‑server model?

A.Clients have limited memory, servers have unlimited memory
B.Clients generate requests and terminate after handling responses, servers must remain to accept new requests ✅
C.Servers are run on more reliable hardware
D.Clients cannot open sockets
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: A client initiates a request, processes the response, and then exits, giving it a bounded execution period. In contrast, a server must stay active to accept successive requests from many clients over time, so it is designed to run continuously, often until the system is shut down.

Q6. Which sequence of socket API calls must a server perform to accept a connection from a client that has called connect()?

A.socket(), bind(), listen(), accept() ✅
B.socket(), connect(), listen(), accept()
C.bind(), socket(), accept(), listen()
D.listen(), socket(), bind(), accept()
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: The typical server setup is: create a socket with socket(), assign a local address with bind(), mark it as passive with listen(), and finally block awaiting a client using accept(). Only this order correctly prepares the socket to receive incoming connection requests.

Q7. If a server processes each client request sequentially in a single‑threaded loop, what is the most likely effect when several clients connect at the same time?

A.All clients are served concurrently
B.Later clients experience increased latency ✅
C.Server will crash due to overload
D.Clients will be denied connection
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: A single‑threaded server handles one request at a time; while it processes the first client, subsequent clients must wait. This queueing introduces additional waiting time, so later clients experience higher latency, even though no connections are refused unless resources are exhausted.

Q8. Between a multi‑threaded server that creates a thread per client and an event‑driven server using non‑blocking I/O, which design generally scales better under high concurrency and why?

A.Multi‑threaded scales better because threads isolate clients
B.Event‑driven scales better because it avoids thread‑creation overhead and context switches ✅
C.Both scale equally
D.Multi‑threaded scales better because it uses more CPU cores
💡 Difficulty: hard | ✅ Correct: B

📖 Explanation: Event‑driven architectures keep a small number of threads that multiplex many connections via non‑blocking I/O and readiness notifications. This eliminates the cost of creating, scheduling, and context‑switching thousands of threads, allowing the server to handle far more concurrent connections with lower memory and CPU overhead.

Q9. To guarantee that a client detects server unavailability within 2 seconds, which combination of TCP keepalive and application‑level heartbeat settings is most appropriate?

A.keepalive time 5 s, interval 1 s, 3 probes; heartbeat every 3 s
B.keepalive disabled; heartbeat every 2 s
C.keepalive time 1 s, interval 0.5 s, 2 probes; heartbeat every 1 s ✅
D.keepalive time 10 s, interval 2 s, 5 probes; heartbeat every 5 s
💡 Difficulty: hard | ✅ Correct: C

📖 Explanation: Setting TCP keepalive to trigger after 1 second, probing every 0.5 seconds with two attempts ensures the kernel detects a dead peer within roughly 2 seconds. Complementing this with an application‑level heartbeat sent every 1 second provides an additional safety net, guaranteeing detection well before the 2‑second deadline.

Q10. A client sends a request but receives no response before its timeout expires. Which recovery action is most appropriate according to reliable communication principles?

A.Retransmit the request after confirming the connection is still open ✅
B.Abort the operation and close the socket permanently
C.Switch to UDP and resend the data
D.Ignore the timeout and wait indefinitely
💡 Difficulty: hard | ✅ Correct: A

📖 Explanation: The standard approach is to verify that the TCP connection remains established and then retransmit the request. TCP will handle any required retransmissions at the transport level, but an explicit application‑level retry ensures the request is not lost while preserving the session.

Q11. What does the term “socket” denote in TCP/IP programming?

A.A hardware port on the network card
B.An endpoint for communication identified by IP address and port number ✅
C.A type of encryption algorithm
D.A file system directory
💡 Difficulty: easy | ✅ Correct: B

📖 Explanation: A socket is a software abstraction that represents one endpoint of a network communication channel. It is uniquely identified by the combination of an IP address and a port number, allowing processes to send and receive data over TCP or UDP without dealing directly with lower‑level protocol details.

Q12. If a server calls close() on a socket while there is still unsent data in the send buffer, what is the most likely consequence?

A.The data is guaranteed to be delivered before the connection terminates
B.The operating system discards the unsent data and terminates the connection
C.The client receives an error indicating incomplete transmission
D.The server must call shutdown() before close() to ensure delivery ✅
💡 Difficulty: medium | ✅ Correct: D

📖 Explanation: Calling close() initiates an active close, which may abort transmission of any data still queued in the send buffer. To guarantee that all pending data is transmitted before the connection is closed, the application should first invoke shutdown() with the appropriate flag (e.g., SHUT_WR) and then close() once the peer acknowledges receipt.
