📖 Transport Layer Protocols

Transport Layer Protocols And Application Delivery

Transport Layer Protocols coordinate communication between application processes on different hosts. Port numbers identify service endpoints, while UDP, TCP, and SCTP provide different delivery models. UDP carries independent datagrams with minimal transport control; TCP delivers a reliable, ordered byte stream; SCTP transfers messages through multistreamed, multihomed associations. Their headers, connection procedures, windows, timers, and recovery mechanisms determine how applications exchange data over IP networks. Multiplexing allows multiple applications to share network access while keeping their communication channels distinct.

Ports And Packets Before Transport Processing

IPv4 addresses and packet encapsulation explain how data reaches another host before transport processing begins. Students should recognize application processes, binary port values, checksums, and client-server exchanges. Familiarity with sequence numbers, acknowledgments, timers, and IP delivery helps distinguish transport reliability from network-layer forwarding.

Skills For Comparing UDP TCP And SCTP

Students should classify port ranges and interpret UDP, TCP, and SCTP headers and services. They should compare UDP datagrams with TCP byte streams, trace TCP connection states, and explain flow control, congestion control, retransmission, timers, and options. They should also describe SCTP chunks, TSN, SI and SSN numbering, four-way cookie setup, multistreaming, multihoming, advertised receiver windows, and SACK-based error recovery.

A Study Sequence From Ports To SCTP

Begin with transport services and port ranges, then compare UDP with TCP to separate datagram delivery from reliable byte-stream communication. Follow TCP from its segment header and handshake through connection states, windows, loss recovery, congestion control, timers, and options. Finish with SCTP packet structure, association establishment, multistreaming, multihoming, and SACK. This sequence moves from shared transport concepts to protocol-specific mechanisms.

How Protocol Features Control Application Delivery

Port numbers direct incoming data to the appropriate application process, and each protocol interprets its own header. UDP provides datagram delivery without built-in retransmission or ordering guarantees. TCP adds sequencing, acknowledgments, receiver flow control, and network congestion control. SCTP uses TSNs for reliable data transfer and stream identifiers for independent message ordering. Its advertised receiver window manages buffer capacity, while multihoming provides alternative communication paths.

DNS Queries And TCP Connections In Practice

A client at 192.0.2.10 sends a DNS query from UDP port 53000 to resolver 198.51.100.53 on port 53. UDP identifies both application endpoints without guaranteeing delivery. After resolving a server address, the client opens TCP from port 51514 to 198.51.100.80 on port 443 using SYN, SYN-ACK, and ACK. MSS and window options are negotiated; rwnd limits receiver load, cwnd limits network transmission, and RTO controls timeout-based recovery. An SCTP application could instead use multiple streams and network paths.

Why Transport Reliability Supports Applications

Without transport multiplexing, hosts could not distinguish concurrent application conversations. Without TCP sequencing, retransmission, flow control, and congestion control, reliable bulk transfer would be difficult to provide consistently. UDP and SCTP offer different alternatives for applications requiring datagram delivery, independent message streams, or multiple network paths.

Separating TCP Windows And SCTP Identifiers

Students may say 'rwnd controls network congestion'; rwnd limits transmission according to receiver capacity, while cwnd controls network congestion. They may say 'SCTP TSN and SSN are interchangeable'; TSN sequences reliable association data, while SSN orders messages within a stream. The phrase 'SCTP balloon memory manager' confuses transport flow control with hypervisor memory ballooning; SCTP uses an advertised receiver window called a_rwnd.

Numerical Problems On Transport Protocol Behaviour

Exam questions commonly test port ranges, UDP and TCP header fields, and protocol selection. TCP problems trace three-way establishment, connection teardown, sequence numbers, acknowledgments, rwnd, cwnd, and retransmission. Congestion questions compare slow start, AIMD, Reno, and Tahoe responses. Timer questions distinguish RTO, persistence, keepalive, and TIME-WAIT. SCTP questions test packet chunks, TSN, SI, SSN, multihoming, SACK, and cookie-based association establishment.

How Three Protocols Serve Different Applications

UDP, TCP, and SCTP multiplex application traffic through port numbers but provide different transfer characteristics. TCP combines sequencing, timers, flow control, and congestion algorithms for reliable stream delivery. UDP keeps datagram communication simple, while SCTP combines reliable message transfer with separate streams and multiple network paths. Their architectural differences connect application requirements with transport-layer behaviour and help explain real network communication.

Standards Behind UDP TCP And SCTP

  • RFC 9293 And RFC 5681 - Define TCP operation and major congestion-control mechanisms, including slow start, congestion avoidance, fast retransmit, and fast recovery; RFC 5681 is updated by RFC 9438.
  • RFC 768 - Specifies the UDP header format and connectionless datagram delivery services.
  • RFC 9260 - Defines SCTP packet structure, associations, multistreaming, multihoming, flow control, and error recovery.
  • RFC 6335 - Specifies IANA procedures and the classification of well-known, registered, and dynamic transport port numbers.

Essential Terms In Transport Layer Protocols

  • Port Number - A 16-bit identifier used to distinguish application endpoints within a transport protocol.
  • UDP Datagram - A connectionless transport unit containing source and destination ports, length, checksum, and application data.
  • TCP Segment - A transport unit containing sequence information, acknowledgment fields, control flags, and application data.
  • Receive Window (rwnd) - The advertised receiver capacity that limits how much unacknowledged data a sender can transmit.
  • Congestion Window (cwnd) - A sender-controlled limit on outstanding data used to manage network congestion.
  • Retransmission Timeout (RTO) - A timer value that determines when unacknowledged TCP data should be retransmitted.
  • SCTP Association - A logical communication relationship between SCTP endpoints supporting reliable message exchange.
  • SCTP Sequence Identifiers - TSN tracks association-level data delivery, while SI and SSN identify streams and message ordering within them.
