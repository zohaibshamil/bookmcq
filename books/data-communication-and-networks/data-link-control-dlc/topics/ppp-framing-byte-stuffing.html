What is PPP framing byte stuffing?

PPP uses byte stuffing with escape characters to handle flag bytes appearing within data payloads, ensuring that special control characters are not misinterpreted as frame delimiters during transmission over asynchronous serial links.

Q1. What does “character-oriented framing” primarily use to delimit frames?

A. Start and stop bits
B. Special character sequences ✅
C. Fixed‑length fields
D. Parity bits

💡 Difficulty: easy | ✅ Correct: B

📖 Explanation:

The definition of character‑oriented (or byte‑oriented) framing states that frames are separated by special character sequences such as flag bytes. This makes option B the correct choice, while the other options describe different framing or error‑checking mechanisms.

Q2. If a protocol removes its unique start‑delimiter byte from the stream, what immediate effect occurs on frame detection?

A. Frames become longer
B. Frames can no longer be distinguished ✅
C. Error detection improves
D. Transmission speed increases

💡 Difficulty: easy | ✅ Correct: B

📖 Explanation:

Eliminating the start delimiter eliminates the explicit marker that tells the receiver where a frame begins, so frames cannot be reliably distinguished. This cause‑effect relationship makes option B correct; the other options do not follow logically.

Q3. Which statement best contrasts character‑oriented and bit‑oriented framing regarding overhead?

A. Bit‑oriented adds more start/stop bits per byte
B. Character‑oriented requires escape bytes only when delimiter appears ✅
C. Bit‑oriented always uses a fixed‑size header
D. Character‑oriented never needs padding

💡 Difficulty: easy | ✅ Correct: B

📖 Explanation:

Character‑oriented framing only inserts extra bytes when the delimiter occurs, whereas bit‑oriented framing may insert bits for stuffing regardless of data content. Therefore option B accurately captures the overhead difference; the other statements misrepresent the mechanisms.

Q4. A network uses a unique start delimiter to mark frames. How should a receiver detect a corrupted frame?

A. Check parity of the delimiter
B. Verify CRC placed after the delimiter ✅
C. Count the number of bytes between delimiters
D. Ignore the delimiter and rely on timing

💡 Difficulty: easy | ✅ Correct: B

📖 Explanation:

The standard approach is to compute a CRC (or similar check) over the payload and compare it with the transmitted value placed after the delimiter. This reliably signals corruption, making option B correct; the other methods are ineffective for detecting payload errors.

Q5. A protocol escapes any occurrence of the delimiter byte inside the payload. What is the primary impact on bandwidth?

A. Bandwidth is unchanged
B. Bandwidth decreases due to added escape bytes ✅
C. Bandwidth increases because of compression
D. Bandwidth becomes unpredictable

💡 Difficulty: medium | ✅ Correct: B

📖 Explanation:

Escaping delimiter bytes inserts extra escape characters whenever the delimiter appears, thus adding overhead and reducing effective bandwidth. The other options either contradict the added overhead or describe unrelated effects.

Q6. Why does bit‑oriented framing generally outperform character‑oriented framing in noisy environments?

A. It uses larger frames that mask errors
B. It employs bit stuffing which introduces fewer extra symbols ✅
C. It relies on start/stop bits that are error‑resilient
D. It avoids any form of framing altogether

💡 Difficulty: medium | ✅ Correct: B

📖 Explanation:

Bit stuffing adds only a single extra bit when a prohibited pattern occurs, resulting in less overhead than byte stuffing, which may add whole bytes. Less overhead means fewer bits that can be corrupted, giving bit‑oriented framing an advantage in noisy settings.

Q7. Designing a hybrid scheme that combines byte‑stuffing and bit‑stuffing primarily aims to achieve which benefit?

A. Maximum possible throughput
B. Simplified hardware implementation
C. Flexibility to handle both ASCII and binary data efficiently ✅
D. Elimination of error‑checking codes

💡 Difficulty: medium | ✅ Correct: C

📖 Explanation:

A hybrid approach leverages the strengths of both methods: byte‑stuffing handles ASCII‑friendly delimiters while bit‑stuffing efficiently encodes arbitrary binary patterns. This flexibility improves handling of mixed data types, making option C the most appropriate benefit.

Q8. In a stream where the flag byte is 0x7E and the escape byte is 0x7D, how is a data byte 0x7E transmitted?

A. 0x7E 0x7E
B. 0x7D 0x7E
C. 0x7D 0x5E ✅
D. 0x5E 0x7D

💡 Difficulty: hard | ✅ Correct: C

📖 Explanation:

When the data byte equals the flag, it must be escaped. The escape byte 0x7D is sent followed by the original byte XOR‑ed with 0x20, yielding 0x5E. Hence the transmitted sequence is 0x7D 0x5E, which corresponds to option C.

Q9. Assuming random payload data, which protocol typically yields lower average overhead: byte‑stuffing or bit‑stuffing?

A. Byte‑stuffing always lower
B. Bit‑stuffing always lower ✅
C. Both have identical overhead
D. It depends on the link speed

💡 Difficulty: hard | ✅ Correct: B

📖 Explanation:

With random data, the probability of encountering a delimiter byte is higher than encountering the specific bit pattern that triggers bit stuffing. Consequently, bit‑stuffing inserts fewer extra symbols on average, giving it lower overhead than byte‑stuffing.

Q10. Why is placing the CRC after the frame delimiter preferable in variable‑size framing?

A. It allows the CRC to be computed without knowing the frame length
B. It ensures the CRC is not affected by bit‑stuffing ✅
C. It guarantees the CRC is transmitted before any escape sequences
D. It simplifies synchronization with the receiver’s clock

💡 Difficulty: hard | ✅ Correct: B

📖 Explanation:

When bit‑oriented framing is used, stuffing may insert extra bits after the delimiter. By positioning the CRC after the delimiter (and after any stuffing), the CRC calculation includes the exact transmitted bits, preserving integrity despite stuffing. Hence option B correctly describes the advantage.

Q11. If a receiver mistakenly treats an escaped delimiter as a real delimiter, what is the most likely result?

A. The current frame is accepted correctly
B. The next frame is merged with the current one
C. Subsequent frames become misaligned until resynchronization ✅
D. All frames are discarded automatically

💡 Difficulty: medium | ✅ Correct: C

📖 Explanation:

Misinterpreting an escaped delimiter causes the receiver to think the frame ended early, leading to loss of the remaining payload and a shift in the parsing of following frames. This misalignment persists until a new proper delimiter restores synchronization, matching option C.

Q12. How do synchronous and asynchronous character‑oriented framing differ regarding start/stop bits?

A. Synchronous framing uses start/stop bits for each byte, asynchronous does not
B. Asynchronous framing adds start/stop bits to each byte, synchronous relies on a continuous clock ✅
C. Both use identical start/stop bit patterns
D. Synchronous framing never uses start/stop bits

💡 Difficulty: medium | ✅ Correct: B

📖 Explanation:

In asynchronous transmission, each byte is framed by start and stop bits, allowing the receiver to recover timing independently. Synchronous framing, by contrast, transmits a continuous stream synchronized to a shared clock, eliminating per‑byte start/stop bits. Thus option B captures the key distinction.

Q13. In a network where some links support only bit‑oriented framing, how should a gateway handle incoming character‑oriented frames?

A. Convert the frame to a fixed‑size packet
B. Strip the delimiters and forward raw bits
C. Perform byte‑to‑bit stuffing to embed the delimiters as bit patterns ✅
D. Drop the frames entirely

💡 Difficulty: medium | ✅ Correct: C

📖 Explanation:

The gateway must translate the byte‑oriented delimiters into a bit‑oriented representation, typically by applying bit‑stuffing so that the delimiter pattern can be recognized in the bit stream. This conversion enables the frame to traverse links that only understand bit‑oriented framing, making option C correct.
