Q1. If a data byte identical to the flag pattern appears in the payload and no byte stuffing is performed, what will the receiver incorrectly interpret?

🔹 A. A: A checksum error
🔹 B. B: The end of the frame
🔹 C. C: An escape sequence
🔹 D. D: A start of a new frame

💡 Difficulty: easy | ✅ Correct: B

📖 Explanation:

The receiver scans the incoming stream for the flag pattern to mark frame boundaries. Without stuffing, the identical payload byte is indistinguishable from the flag, so the receiver assumes it has reached the frame's end, discarding any subsequent data as a new frame.

Q2. Suppose a transmitted frame contains the escape character (ESC) followed by a byte equal to the flag pattern, but the receiver's software mistakenly treats the ESC as ordinary data. What consequence follows?

🔹 A. A: The flag will be duplicated
🔹 B. B: The frame will be extended by one byte
🔹 C. C: The receiver will drop the next byte
🔹 D. D: The frame will be prematurely terminated

💡 Difficulty: medium | ✅ Correct: D

📖 Explanation:

When ESC is ignored, the following flag‑like byte is taken as a delimiter. The receiver therefore believes the frame ended at that point, truncating the remaining payload and causing an early termination of the frame.

Q3. Consider a stream where the flag pattern occurs three times consecutively within the payload, and byte stuffing inserts an ESC before each flag byte. How many flag delimiters will the receiver detect after destuffing?

🔹 A. A: One
🔹 B. B: Two
🔹 C. C: Three
🔹 D. D: Four

💡 Difficulty: hard | ✅ Correct: A

📖 Explanation:

Each occurrence of the flag pattern is preceded by an ESC, so during destuffing the ESC bytes are removed and the following bytes are treated as data, not delimiters. Consequently, none of the three inserted flags are interpreted as boundaries, leaving only the original start and end flags, i.e., a single delimiter pair.

Q4. Which statement best compares the overhead introduced by byte stuffing versus bit stuffing?

🔹 A. A: Bit stuffing always adds fewer bits than byte stuffing
🔹 B. B: Byte stuffing adds a whole byte only when a flag byte appears, while bit stuffing adds a single bit for each five consecutive ones
🔹 C. C: Both methods add the same amount of overhead on average
🔹 D. D: Byte stuffing adds overhead only in error‑free transmissions

💡 Difficulty: easy | ✅ Correct: B

📖 Explanation:

Byte stuffing inserts an entire escape byte each time the flag byte occurs in the data, causing a burst of overhead only at those points. Bit stuffing, however, inserts a single bit after any sequence of five consecutive '1' bits, spreading the overhead more evenly but potentially adding many bits if long runs occur.

Q5. When choosing an escape character for a protocol, which factor most directly influences the trade‑off between transmission efficiency and robustness?

🔹 A. A: The frequency of the escape character in typical payloads
🔹 B. B: The length of the flag pattern
🔹 C. C: The baud rate of the link
🔹 D. D: The type of error‑detecting code used

💡 Difficulty: medium | ✅ Correct: A

📖 Explanation:

If the escape character appears often in normal data, many stuffing operations will be required, reducing efficiency. Conversely, a rarely used escape character minimizes stuffing but may be less convenient for implementation. Hence the occurrence rate of the escape byte is the primary determinant of the efficiency‑robustness balance.

Q6. In a high‑error environment where bit errors are frequent, how does the use of byte stuffing affect throughput compared to bit stuffing?

🔹 A. A: Byte stuffing provides higher throughput because it adds fewer bits overall
🔹 B. B: Bit stuffing is more resilient because it adap’t to error patterns
🔹 C. C: Byte stuffing can degrade throughput more severely due to whole‑byte insertions when errors corrupt flag‑like patterns
🔹 D. D: Both techniques suffer equally, so throughput is unchanged

💡 Difficulty: hard | ✅ Correct: C

📖 Explanation:

Frequent errors can corrupt data so that random byte patterns resemble the flag, forcing the transmitter to insert an escape byte for each occurrence. This whole‑byte insertion inflates the frame size much more than the single‑bit insertions used in bit stuffing, thus reducing throughput noticeably in noisy channels.

Q7. If a protocol defines the flag as the ASCII character ‘~’ (0x7E) and the escape character as ‘}’ (0x7D), what steps must the transmitter take when the payload contains the byte 0x7E?

🔹 A. A: Replace 0x7E with 0x7D followed by 0x5E
🔹 B. B: Replace 0x7E with 0x7D followed by 0x7E
🔹 C. C: Insert a parity bit after 0x7E
🔹 D. D: Send 0x7E unchanged because it is already a flag

💡 Difficulty: medium | ✅ Correct: B

📖 Explanation:

The transmitter detects the flag byte in the payload and inserts the escape character before it to prevent misinterpretation. According to the defined rule, the original 0x7E is transmitted as the two‑byte sequence 0x7D 0x7E, ensuring the receiver will treat the second byte as data after removing the preceding escape byte.

Q8. Describe the sequence the receiver follows to reconstruct the original data after receiving a stuffed frame.

🔹 A. A: Detect start flag, copy bytes until end flag, then discard any ESC bytes
🔹 B. B: Scan for ESC, remove it, and treat the following byte as literal, repeating until the end flag is reached
🔹 C. C: Replace every flag byte with ESC and then remove all ESC bytes
🔹 D. D: Ignore the flag and process only the trailer

💡 Difficulty: medium | ✅ Correct: B

📖 Explanation:

The receiver first locates the start flag, then reads each subsequent byte. When it encounters the escape character, it discards the ESC and copies the next byte directly to the output buffer, interpreting it as ordinary data. This process repeats until the end flag is encountered, yielding the original, unstuffed payload.

Q9. In data link protocols, what does the term 'piggybacking' refer to?

🔹 A. A: Appending a checksum to each frame
🔹 B. B: Carrying an acknowledgment within a data frame
🔹 C. C: Using a larger frame size to improve efficiency
🔹 D. D: Repeating the same frame multiple times

💡 Difficulty: easy | ✅ Correct: B

📖 Explanation:

Piggybacking means that a node combines its acknowledgment for a previously received frame with its own outgoing data frame, rather than sending a separate ACK. This reduces the number of frames on the link and improves overall efficiency.
