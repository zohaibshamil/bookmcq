Q1. In a simple character‑oriented data‑link protocol, what primary function does the escape character serve?

🔹 A. Marks the start of a frame
🔹 B. Indicates error detection
🔹 C. Allows special control bytes to be transmitted as data
🔹 D. Synchronizes sender and receiver clocks

💡 Difficulty: easy | ✅ Correct: C

📖 Explanation:

The escape character enables the protocol to embed bytes that would otherwise be interpreted as control symbols (such as frame delimiters) within the payload. By preceding such a byte with an escape, the receiver knows to treat the following byte as data, preserving the intended information without altering the framing structure.

Q2. If a frame contains the byte sequence 0x7E (the designated flag) and the protocol does not double an escape character that appears in the payload, what is the most likely immediate consequence at the receiver?

🔹 A. The receiver will treat the 0x7E as the end of the frame and truncate the payload
🔹 B. The receiver will discard the entire frame as corrupted
🔹 C. The receiver will request a retransmission via a NACK
🔹 D. The receiver will interpret the next byte as a checksum

💡 Difficulty: easy | ✅ Correct: A

📖 Explanation:

When the escape character is omitted, the receiver sees the flag byte 0x7E inside the payload and assumes it marks the frame’s termination. Consequently, the remaining data after that byte is ignored, resulting in a truncated payload and loss of information, even though the original frame was correctly transmitted.

Q3. Consider a scenario where the escape character 0x7D appears twice consecutively in the payload. If the protocol only adds one extra escape before each occurrence, what inference can be made about the receiver’s interpretation of the subsequent bytes?

🔹 A. Both escape characters will be removed, causing loss of data
🔹 B. The first escape will be treated as a data byte, and the second will trigger removal of the following byte
🔹 C. The receiver will misidentify the frame boundary, potentially merging two frames
🔹 D. The receiver will correctly reconstruct the original payload

💡 Difficulty: medium | ✅ Correct: B

📖 Explanation:

The first 0x7D is seen as an escape that signals the next byte is data, so it is retained. The second 0x7D, interpreted as an escape, causes the receiver to discard the following byte, assuming it is part of an escaped sequence. This leads to misinterpretation of the payload and potential data loss.

Q4. Which of the following best compares the double‑escape method to a length‑field framing technique in terms of handling variable‑length data?

🔹 A. Double‑escape adds overhead only when special bytes appear, while length‑field requires a fixed header for every frame
🔹 B. Length‑field framing eliminates the need for escape characters entirely, but cannot detect bit errors
🔹 C. Double‑escape simplifies synchronization but makes payload compression impossible
🔹 D. Length‑field framing always uses more bits than double‑escape for short payloads

💡 Difficulty: easy | ✅ Correct: D

📖 Explanation:

A length‑field header must be transmitted for every frame, regardless of its content, adding a constant overhead. In contrast, the double‑escape approach only introduces extra bytes when a flag or escape character appears within the payload, which can be more efficient for short frames that contain few or no special bytes.

Q5. When integrating Unicode (which may use multibyte characters) with an escape‑character protocol, which evaluation is most accurate regarding throughput?

🔹 A. Throughput decreases linearly with the number of Unicode code points
🔹 B. The need to escape additional bytes can cause variable overhead, reducing average throughput compared to ASCII‑only data
🔹 C. Unicode eliminates the need for escape characters, thus increasing throughput
🔹 D. Throughput is unaffected because escape processing is independent of character encoding

💡 Difficulty: medium | ✅ Correct: B

📖 Explanation:

Unicode characters often occupy multiple bytes, increasing the chance that one of those bytes matches the escape or flag values. When such matches occur, the protocol must insert extra escape bytes, creating variable overhead. This additional data reduces the effective payload size per transmission, lowering average throughput relative to an equivalent ASCII‑only stream.

Q6. Differentiate between bit‑stuffing and byte‑stuffing as mechanisms for delimiting frames. Which statement correctly reflects their impact on error propagation?

🔹 A. Bit‑stuffing can cause a single bit error to corrupt multiple subsequent bits, while byte‑stuffing isolates errors to the affected byte
🔹 B. Byte‑stuffing spreads a single bit error across the entire frame, whereas bit‑stuffing confines it to the stuffed bit
🔹 C. Both techniques have identical error propagation characteristics, differing only in implementation complexity
🔹 D. Bit‑stuffing generally results in less error propagation because errors are detected at the bit level before byte reconstruction

💡 Difficulty: hard | ✅ Correct: A

📖 Explanation:

In bit‑stuffing, a bit error can alter the pattern that determines where stuffing occurs, potentially causing the receiver to mis‑interpret the location of subsequent stuffed bits and thus corrupt multiple following bits. Byte‑stuffing, by contrast, treats each byte independently, so an error typically affects only that specific byte, limiting the spread of corruption.

Q7. Applying the principle of transparent data transmission, how should a simple protocol be designed to ensure that an escape character appearing in the payload is correctly interpreted?

🔹 A. By preceding every occurrence of the escape character with another escape character, and having the receiver remove one layer of escaping
🔹 B. By replacing the escape character with a unique sentinel value that never occurs in the payload
🔹 C. By sending a separate control frame that lists all positions of escape characters in the payload
🔹 D. By using a fixed‑size payload that never includes the escape character

💡 Difficulty: medium | ✅ Correct: A

📖 Explanation:

Transparent transmission requires that data be delivered exactly as sent. The standard solution is to double the escape byte whenever it occurs in the payload, so the receiver knows to strip one level and retain the original byte. This method preserves the original information while allowing the protocol to distinguish between control symbols and data.

Q8. Synthesize a protocol that supports both escape‑character handling and Unicode text transmission. Which combination of mechanisms best maintains frame integrity while minimizing overhead?

🔹 A. Use a two‑byte escape sequence (0x7D 0x7D) for any escape byte, and a length field encoded in UTF‑8 before the payload
🔹 B. Employ byte‑stuffing for the flag byte only, and encode Unicode characters with UTF‑16, relying on a start‑of‑frame delimiter
🔹 C. Implement a dynamic escape table that maps each Unicode code point to a unique escape, together with a checksum at the end
🔹 D. Adopt a length‑prefixed frame where the length counts bytes after escape processing, and double‑escape any 0x7D that appears in the UTF‑8 payload

💡 Difficulty: hard | ✅ Correct: D

📖 Explanation:

A length‑prefixed approach lets the receiver know exactly how many bytes to read, eliminating ambiguity about frame boundaries. By counting bytes after escape processing, the protocol avoids counting added escape bytes, preserving the true payload length. Doubling any 0x7D in the UTF‑8 payload ensures that the escape character itself is transmitted safely, keeping overhead low while supporting Unicode.

Q9. If a receiver mistakenly interprets an escaped data byte as the frame terminator, what deduction can be made about the protocol's robustness to synchronization errors?

🔹 A. The protocol lacks sufficient mechanisms to distinguish control symbols from data, making it vulnerable to synchronization loss
🔹 B. The protocol's error‑checking code will automatically correct the misinterpretation
🔹 C. The sender must resend the frame using a different escape character
🔹 D. The issue can be resolved by increasing the baud rate

💡 Difficulty: medium | ✅ Correct: A

📖 Explanation:

When the receiver confuses an escaped byte with a frame delimiter, it indicates that the protocol does not provide a clear, unambiguous method for separating control symbols from payload data. This weakness makes the system prone to synchronization errors, as any occurrence of a control‑like byte in the payload can cause premature termination of the frame.
