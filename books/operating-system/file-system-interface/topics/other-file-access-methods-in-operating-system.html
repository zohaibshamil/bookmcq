What is Other file access methods in Operating System?

Definition:
Alternative access methods include \( indexed-sequential \) access combining ordered keys with overflow areas, and \( hashed \) access using functions \( h(key) \to bucket \) for constant-time average retrieval.

Example:
ISAM (Indexed Sequential Access Method) maintains a sparse index allowing binary search \( O(\log n) \) to locate a starting point, then switches to sequential scanning within that block range.

Reason:
Hybrid approaches balance the space efficiency of sequential storage with the speed of direct access, accommodating workloads that require both range queries and exact-match lookups simultaneously.

Q1. A Java program needs to ensure that two different threads can write to the first half of a file while multiple threads read the second half concurrently. Which lock strategy using FileChannel.lock best satisfies this requirement?

A.Use an exclusive lock on the first half and a shared lock on the second half.
B.Use a shared lock on the first half and an exclusive lock on the second half. ✅
C.Lock the entire file exclusively.
D.Do not use any lock.
💡 Difficulty: hard | ✅ Correct: B

📖 Explanation: The exclusive lock guarantees that only one thread can modify the first half, preventing race conditions. The shared lock on the second half allows many threads to read simultaneously, increasing throughput. Option B swaps the lock types, which would block readers on the first half. Option C needlessly restricts access to the whole file. Option D provides no protection, so concurrent writes could corrupt data. In real applications, this pattern enables safe writes while keeping read‑only sections available to many users.

Q2. Suppose a logging service writes to log.txt and a monitoring tool reads the same file. The service acquires an exclusive lock on the first 100 bytes, then releases it. The tool later attempts to acquire a shared lock on the entire file. Which outcome is most likely?

A.The tool fails because the exclusive lock permanently blocks all accesses. ✅
B.The tool succeeds because the exclusive lock was released and the lock type is advisory.
C.The tool acquires an exclusive lock automatically.
D.The tool receives an IOException and cannot proceed.
💡 Difficulty: hard | ✅ Correct: A

📖 Explanation: When the exclusive lock is released, the operating system no longer blocks other processes, so the advisory shared lock can be granted. Option A is wrong because exclusive locks are not permanent; they only block while held. Option C is incorrect because a shared lock does not upgrade automatically. Option D suggests an error that does not occur under normal advisory locking. In practice, releasing a lock frees the region, allowing monitoring tools to read the file safely.

Q3. A developer wants to lock the second half of a file only if the file size is an even number. Which code snippet correctly implements this using FileChannel.lock?

A.FileChannel ch = new RandomAccessFile(\data.txt\,\rw\).getChannel(); if (ch.size() % 2 == 0) { ch.lock(ch.size()/2, ch.size()/2, true); }
B.FileChannel ch = new RandomAccessFile(\data.txt\,\rw\).getChannel(); ch.lock(0, ch.size(), false);
C.FileChannel ch = new RandomAccessFile(\data.txt\,\rw\).getChannel(); if ((ch.size() & 1) == 0) { ch.lock(ch.size()/2, ch.size()/2, true); } ✅
D.FileChannel ch = new RandomAccessFile(\data.txt\,\rw\).getChannel(); ch.lock(0, ch.size()/2, true);
💡 Difficulty: hard | ✅ Correct: C

📖 Explanation: The snippet in option C checks the low‑order bit with \( \text{ch.size()} \& 1 \) to confirm the size is even, then locks the second half using \( \text{ch.size()}/2 \) as both position and length, and sets the shared flag to true. Option A uses the modulus operator correctly but the condition is the same; however, option A’s comment does not clarify the shared flag, making it ambiguous. Option B locks the whole file exclusively, which is not the requirement. Option D locks the first half, not the second. In real code, precise condition checking and correct parameters ensure only the intended region is protected.

Q4. If a process acquires an exclusive lock on the first 200 bytes of a file, what will happen when another process attempts to acquire a shared lock on bytes 150‑250?

A.The shared lock will be granted for the non‑overlapping part. ✅
B.The shared lock will be granted after the exclusive lock is released.
C.Both locks will be merged into a single lock.
D.The shared lock will be denied because the overlapping region is already exclusively locked.
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: An exclusive lock prevents any other lock—shared or exclusive—from being granted on overlapping bytes. Since bytes 150‑200 overlap, the request must be denied. Option A is wrong because the lock cannot be split; the overlapping portion blocks the whole request. Option B assumes the exclusive lock is released automatically, which is not true. Option C suggests merging locks, which the OS does not do. In practice, overlapping exclusive and shared requests lead to denial, protecting the first region from concurrent reads.

Q5. A file is 1,000 bytes long. The code `ch.lock(0, 500, false)` is executed. Which portion of the file is locked and what type of lock is it?

A.First 500 bytes, exclusive lock
B.First 500 bytes, shared lock ✅
C.Last 500 bytes, exclusive lock
D.Last 500 bytes, shared lock
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: The call locks from position 0 for a length of 500 bytes, and the boolean false indicates an exclusive lock, meaning no other process can acquire any lock on that region. Option B incorrectly labels the lock as shared. Options C and D refer to the second half of the file, which is not affected by the given parameters. Understanding these arguments lets developers protect critical sections of a file while allowing other parts to remain accessible.

Q6. What is the main difference between mandatory and advisory file locking?

A.Mandatory locks rely on processes to check for locks, while advisory locks are enforced by the operating system. ✅
B.Mandatory locks are enforced by the operating system, while advisory locks depend on processes to check for locks.
C.Mandatory locks allow multiple writers, advisory locks allow only one writer.
D.Mandatory locks are faster than advisory locks.
💡 Difficulty: easy | ✅ Correct: A

📖 Explanation: Mandatory locking is imposed by the OS; any attempt to access a region under an exclusive mandatory lock is blocked regardless of the program's behavior. Advisory locking, by contrast, requires cooperating processes to query and respect the lock before accessing the file. Option A reverses the definitions, making it incorrect. Option C confuses lock semantics with concurrency limits. Option D claims a performance difference that is not defined by the locking mode. In real systems, choosing between mandatory and advisory determines whether the OS alone protects the file or whether all programs must cooperate.

Q7. Why might a program choose a shared lock for the second half of a file after modifying the first half?

A.To prevent any access to the second half. ✅
B.To lock the whole file implicitly.
C.To upgrade the lock to exclusive later.
D.To allow concurrent reads of the unchanged part.
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: A shared lock permits multiple readers while preventing writers, which is ideal for a region that is not being modified. After changing the first half exclusively, the program can safely let other threads or processes read the second half simultaneously, improving performance. Option A would block all access, defeating the purpose of a shared lock. Option B suggests an implicit whole‑file lock, which does not happen. Option D misstates the effect; the lock does not upgrade automatically. In practice, this pattern balances safety for modified data with accessibility for stable data.

Q8. If a process holds an exclusive lock on a file region and then attempts to acquire a shared lock on the same region without releasing the exclusive lock first, what is the likely result?

A.Concurrency increases because the shared lock is added. ✅
B.Concurrency decreases because the exclusive lock remains.
C.A deadlock occurs.
D.The request is ignored and the lock state remains exclusive.
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: The operating system will reject the second request because the region is already locked exclusively; the lock state does not change, and the process continues to hold the exclusive lock only. Option A is wrong because the shared lock cannot be added while the exclusive lock is active. Option B misinterprets the effect—no new lock is granted. Option C suggests a deadlock, which does not happen; the call simply fails. Real‑world code must release an exclusive lock before requesting a shared lock to avoid such failures.

Q9. Which Java class provides a getChannel() method that returns a FileChannel suitable for locking?

A.RandomAccessFile ✅
B.FileInputStream
C.FileOutputStream
D.BufferedReader
💡 Difficulty: easy | ✅ Correct: A

📖 Explanation: RandomAccessFile’s getChannel() method returns a java.nio.channels.FileChannel, which supports locking operations such as lock() and tryLock(). While FileInputStream and FileOutputStream also expose getChannel(), their channels are primarily for streaming I/O and may not support full locking semantics on all platforms. BufferedReader does not have a getChannel() method at all. Therefore, RandomAccessFile is the most reliable choice for acquiring file locks in Java.

Q10. What constant value is used in the LockingExample code to indicate a shared lock?

A.false ✅
B.true
C.FileChannel.SHARED
D.java.nio.channels.FileLock.SHARED
💡 Difficulty: easy | ✅ Correct: A

📖 Explanation: In the example, the boolean constant SHARED is set to true, and this value is passed to FileChannel.lock to request a shared (read‑only) lock. Option A (false) represents an exclusive lock. Options C and D refer to nonexistent constants; the lock type is determined solely by the boolean argument. Recognizing that true signals a shared lock helps developers correctly specify the desired lock mode when using the lock API.
