What is Access control in File System Interface Protection?

Definition:
Access control implements authorization decisions verifying whether subject \( S \) possesses required rights \( R \) on object \( O \) using mechanisms like DAC (owner-controlled), MAC (label-based), or RBAC (role-based).

Example:
SELinux enforces MAC where process labeled \( httpd_t \) can only access files labeled \( httpd_sys_content_t \); even root cannot bypass policy violations without explicit relabeling.

Reason:
Robust access control prevents privilege escalation and lateral movement attacks by binding permissions to identities and contexts rather than mere ownership, addressing limitations of traditional Unix DAC in high-security environments.

📝 All Access control in File System Interface Protection MCQs

Q1. A system administrator wants to isolate user data by creating separate file system volumes on a single hard disk. Which method best achieves this isolation while allowing each volume to have its own access control settings?

A.Partition the disk into multiple volumes ✅
B.Use a single volume with directories
C.Store files in a single index file
D.Create RAID 0 across the whole disk
💡 Difficulty: easy | ✅ Correct: A

📖 Explanation: Partitioning divides the physical disk into distinct logical sections, each becoming its own volume with separate metadata, including permission tables. This lets the admin assign unique access rights per volume. A single volume with directories shares the same permission set, while an index file does not provide isolation, and RAID 0 merely stripes data without creating separate access control domains.

Q2. A developer needs to ensure that a critical configuration file is only readable by the system service that owns it. Which file‑system feature should be used to enforce this rule?

A.File‑system ACLs ✅
B.File‑system partitioning
C.RAID mirroring
D.Index file structure
💡 Difficulty: easy | ✅ Correct: A

📖 Explanation: Access Control Lists (ACLs) allow fine‑grained permissions on individual files, specifying which user or service may read, write, or execute. Partitioning separates storage but does not control per‑file rights. RAID mirroring provides redundancy, not security. An index file is a data‑retrieval structure, unrelated to permission enforcement. Therefore ACLs directly satisfy the requirement to limit read access to the owning service.

Q3. Why does storing a file system on a RAID 1 set improve reliability but not directly affect access control decisions?

A.RAID 1 duplicates data for fault tolerance ✅
B.RAID 1 encrypts data
C.RAID 1 partitions the disk
D.RAID 1 provides ACLs
💡 Difficulty: easy | ✅ Correct: A

📖 Explanation: RAID 1 creates an exact copy of data on two disks, so if one fails the other continues serving the same files, enhancing reliability. However, RAID operates below the file‑system layer and does not manage who can access files; permissions are still handled by the file system’s ACLs or mode bits. Encryption, partitioning, and ACL provision are unrelated to RAID 1’s duplication purpose.

Q4. Which term describes a logical collection of files and directories that includes metadata about each file?

A.Volume
B.Device directory ✅
C.Index file
D.Relative file
💡 Difficulty: easy | ✅ Correct: B

📖 Explanation: A device directory (often called a table of contents) stores entries for every file on a volume, recording attributes such as name, size, and location. A volume is the storage container itself, while an index file maps keys to record locations, and a relative file uses record numbers for access. The directory’s role is to provide the system with the necessary metadata to locate and manage files.

Q5. In a scenario where a disk is divided into four equal parts, each part holds a different file system type. What primary advantage does this partitioning provide?

A.Allows distinct access‑control policies per file system ✅
B.Increases total storage capacity
C.Eliminates need for backups
D.Improves CPU performance
💡 Difficulty: easy | ✅ Correct: A

📖 Explanation: Partitioning creates separate logical areas, enabling each file system to enforce its own permission model, mount options, and security policies. The total capacity remains the same, backups are still required, and CPU performance is unaffected by the logical division. Thus the main benefit is the ability to apply different access‑control regimes on each partition.

Q6. Which of the following best describes a relative file organization?

A.Records are accessed by logical record number ✅
B.Records are accessed via a hash index
C.Files are stored in a single continuous block
D.Access is based on file name hashing
💡 Difficulty: easy | ✅ Correct: A

📖 Explanation: Relative files store data as fixed‑length records and retrieve them using a logical record number, which the system translates to a physical offset. This differs from hash‑based indexing, which uses a key to locate records, and from name‑based access, which relies on directory lookups. The relative method is simple but requires knowledge of the record number to retrieve data.

Q7. A company needs to store confidential logs on a volume that is also mirrored for redundancy. Which combination of storage features ensures both confidentiality and fault tolerance?

A.RAID 1 with file‑system encryption ✅
B.RAID 0 with ACLs
C.Partitioning without RAID
D.Index file with no redundancy
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: RAID 1 creates an identical copy of the volume on two disks, protecting against hardware failure. Adding file‑system level encryption (or encrypted volumes) ensures that the data remains unreadable to unauthorized parties, preserving confidentiality. RAID 0 provides no redundancy, and ACLs alone do not encrypt data. Partitioning without RAID lacks fault tolerance, and an index file does not address either security or redundancy.

Q8. If a file system uses an index file to map user IDs to record locations, what is a potential drawback when the number of users grows dramatically?

A.Index file becomes large, slowing lookups ✅
B.Index file prevents RAID usage
C.Index file eliminates need for ACLs
D.Index file forces fixed‑size partitions
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: As more users are added, the index file grows proportionally, potentially exceeding memory caches and causing longer search times for each lookup. This scalability issue does not affect RAID compatibility, does not replace ACLs (which still control permissions), and does not dictate partition sizes. Therefore the main concern is performance degradation due to a larger index structure.

Q9. Which statement accurately reflects the relationship between volumes and access control mechanisms?

A.Volumes provide the storage context in which file‑system ACLs operate ✅
B.Volumes enforce access control independently of the file system
C.Volumes replace the need for directories
D.Volumes automatically inherit permissions from the underlying device
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: A volume is the logical disk that houses a file system; the file system implements ACLs or mode bits that control who may read, write, or execute files within that volume. The volume itself does not enforce permissions; it merely provides the space. Directories are part of the file system, not a substitute for ACLs, and permissions are not automatically derived from the physical device without file‑system logic.

Q10. A system stores user records in a relative file where each record is 256 bytes. If a user’s logical record number is 150, what is the byte offset of the record’s start?

A.\(256 \times 150 = 38{,}400\) bytes ✅
B.\(256 + 150 = 406\) bytes
C.\(150 - 256 = -106\) bytes
D.\(256 \times 151 = 38{,}656\) bytes
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: In a relative file, the offset is calculated by multiplying the record size by the logical record number (starting at zero). Thus \(256 \times 150 = 38{,}400\) bytes gives the start position. Adding the size would shift to the next record, subtraction yields a negative, and using 151 would point to the following record. The correct offset lets the system retrieve the exact user data.

Q11. When a volume is created by combining multiple physical disks into a RAID 5 set, how does this affect the implementation of file‑system permissions?

A.Permissions are still managed by the file system, unchanged by RAID level ✅
B.RAID 5 adds its own permission layer
C.RAID 5 encrypts all data automatically
D.RAID 5 disables ACLs
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: RAID 5 provides block‑level striping with parity for fault tolerance but operates beneath the file system. Consequently, the file system continues to enforce its own ACLs or mode bits without alteration. RAID 5 does not introduce a separate permission model, nor does it encrypt data by default, and it certainly does not disable existing ACL mechanisms.

Q12. A developer designs a file system where each file’s metadata includes an owner ID and a group ID. Which access‑control model does this represent?

A.Discretionary Access Control (DAC) ✅
B.Mandatory Access Control (MAC)
C.Role‑Based Access Control (RBAC)
D.Attribute‑Based Access Control (ABAC)
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: Storing owner and group identifiers aligns with the classic DAC model, where the file owner can grant or restrict permissions to users and groups. MAC relies on system‑wide labels, RBAC assigns permissions based on roles, and ABAC evaluates arbitrary attributes. Therefore the described metadata structure is characteristic of discretionary control.

Q13. In a scenario where a volume is partitioned into a swap area, a raw disk for database storage, and two file‑system partitions, which of the following statements is true regarding access control?

A.Only the file‑system partitions can enforce ACLs ✅
B.The swap area enforces user permissions
C.The raw disk automatically inherits ACLs
D.All partitions share the same ACL set
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: ACLs are a feature of file systems; only the partitions formatted with a file system can define and enforce permission lists. Swap space and raw disks lack a file‑system layer, so they cannot apply ACLs. Consequently, each file‑system partition can have its own distinct ACLs, while the other areas remain unmanaged by the file‑system permission model.

Q14. A server uses an index file to locate records by employee number. If the index becomes corrupted, what is the most likely impact on access control?

A.Authorized users may be unable to locate their records ✅
B.All file permissions are revoked
C.The RAID set will fail
D.The volume will be unmountable
💡 Difficulty: hard | ✅ Correct: A

📖 Explanation: Corruption of the index file prevents the system from mapping employee numbers to physical locations, making it impossible for authorized users to retrieve their records even though they have permission. This does not affect the underlying RAID redundancy, nor does it alter file‑system permissions or prevent the volume from being mounted; it merely disrupts record lookup.

Q15. Consider a file system that stores sensitive audit logs on a volume encrypted with a hardware‑based key. Which of the following best describes the combined effect on confidentiality and integrity?

A.Encryption protects confidentiality; hardware key ensures integrity against tampering ✅
B.Encryption guarantees both confidentiality and integrity automatically
C.Hardware key replaces the need for ACLs
D.Encryption makes ACLs unnecessary
💡 Difficulty: hard | ✅ Correct: A

📖 Explanation: Hardware‑based encryption secures the data at rest, preventing unauthorized reading (confidentiality). While encryption does not inherently provide integrity, the hardware key can be tied to secure boot processes that detect tampering, enhancing integrity. ACLs still control who may access the decrypted logs, so they remain necessary. Encryption alone does not guarantee integrity, nor does it eliminate permission checks.

Q16. A database administrator wants to store user profiles in a relative file where each profile occupies exactly one record. If the file currently has 10,000 records and a new profile is added at the end, what logical record number will the new profile have?

A.10{,}001
B.9{,}999
C.10{,}000 ✅
D.0
💡 Difficulty: hard | ✅ Correct: C

📖 Explanation: Logical record numbers typically start at zero; thus the first record is 0, and the 10,000th record is numbered 9,999. Adding a new record after the existing 10,000 entries assigns it the next sequential number, which is 10,000. Therefore the correct logical record number for the new profile is 10,000.

Q17. If a volume is created by concatenating three disks without any RAID, what security implication does this have compared to using RAID 1 for each disk?

A.Compromise of any single disk exposes all data ✅
B.RAID 1 provides better confidentiality
C.Concatenation automatically encrypts data
D.Concatenation enforces stricter ACLs
💡 Difficulty: hard | ✅ Correct: A

📖 Explanation: When disks are simply concatenated, the data from each resides on its respective disk; if an attacker gains access to any one disk, they can read the portion stored there, potentially exposing the entire volume's contents. RAID 1 mirrors data, but does not inherently improve confidentiality; it merely duplicates for redundancy. Concatenation does not encrypt data nor affect ACL enforcement.

Q18. A system administrator plans to use a RAID 6 set for a volume that stores critical system binaries. Which statement correctly describes how RAID 6 interacts with file‑system access control?

A.RAID 6 provides redundancy, while the file system still governs permissions ✅
B.RAID 6 replaces the need for ACLs
C.RAID 6 encrypts files automatically
D.RAID 6 prevents any permission changes
💡 Difficulty: hard | ✅ Correct: A

📖 Explanation: RAID 6 adds dual parity, allowing the volume to survive two simultaneous disk failures, enhancing availability. However, it operates beneath the file system and does not modify or replace the file‑system's permission mechanisms. ACLs, mode bits, and other access‑control features remain fully responsible for who can read, write, or execute the system binaries.

Q19. When a file system uses an index file that maps usernames to file locations, what is a security risk if the index file is not protected by proper ACLs?

A.Unauthorized users could locate and access other users' files ✅
B.The index file will become corrupted
C.The file system will lose all data
D.RAID will fail
💡 Difficulty: hard | ✅ Correct: A

📖 Explanation: If the index file itself is exposed, anyone with read access can discover the mapping between usernames and file locations, effectively bypassing normal permission checks and allowing data exfiltration. Corruption of the index does not directly stem from lack of ACLs, and loss of data or RAID failure are unrelated to index exposure.

Q20. A cloud service provider partitions a storage device into separate volumes for each tenant. Which access‑control principle does this design primarily enforce?

A.Isolation (least privilege) between tenants ✅
B.Mandatory labeling of data
C.Role‑based delegation across tenants
D.Attribute‑based encryption
💡 Difficulty: hard | ✅ Correct: A

📖 Explanation: By allocating distinct volumes per tenant, the provider ensures that each tenant's data resides in an isolated logical container, preventing other tenants from accessing it—an embodiment of the least‑privilege and isolation principle. Mandatory labeling, RBAC, and ABAC pertain to labeling and role or attribute decisions, not the physical‑logical separation achieved through partitioning.

Q21. In a file system that supports both ACLs and traditional Unix mode bits, which mechanism provides the most granular permission control?

A.ACLs ✅
B.Unix mode bits
C.RAID level
D.Index file structure
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: ACLs allow specifying permissions for multiple individual users and groups, beyond the three categories (owner, group, others) offered by Unix mode bits. This granularity enables precise access definitions. RAID levels and index file structures are unrelated to permission granularity. Therefore ACLs are the most detailed method for controlling who can access a file.

Q22. A developer must choose between storing a large collection of logs in an index file versus a relative file. Which factor most influences the decision from an access‑control perspective?

A.Ability to enforce per‑record ACLs ✅
B.Maximum storage capacity
C.Speed of sequential reads
D.Compatibility with RAID 0
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: Index files map keys to locations but typically do not support individual ACLs for each record; a relative file can assign permissions at the file level, allowing per‑record control if each record is treated as a separate file. Storage capacity and sequential read speed affect performance, while RAID compatibility is unrelated to access control. Thus permission granularity drives the choice.

Q23. If a volume containing a file system is mounted with the 'nosuid' option, what effect does this have on access control?

A.Set‑uid bits are ignored, preventing privilege escalation ✅
B.All ACLs are disabled
C.The volume cannot be written to
D.RAID redundancy is disabled
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: The 'nosuid' mount option tells the kernel to ignore the set‑uid and set‑gid bits on executable files within that file system, mitigating the risk that a user could gain elevated privileges. ACLs remain active, write operations are allowed, and RAID functionality is unaffected. Hence the primary impact is on set‑uid behavior.

Q24. A networked storage system uses a partitioned volume for user home directories and another partition for system logs. Which scenario best illustrates the benefit of this partitioning for access control?

A.Home directories can have user‑specific ACLs, while logs are protected by system‑only ACLs ✅
B.Both partitions share identical permissions
C.Partitioning eliminates the need for ACLs
D.Partitioned logs automatically inherit user permissions
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: Separating home directories from system logs allows administrators to assign fine‑grained, user‑specific ACLs to home directories while applying stricter, system‑only ACLs to log files. Sharing identical permissions would defeat the purpose, and partitioning does not remove the need for ACLs; instead, it enables distinct permission sets per partition.

Q25. When a file system employs a relative file organization with fixed‑size records, what is a limitation concerning access control?

A.Permissions can only be set at the file level, not per record ✅
B.Records cannot be encrypted
C.RAID cannot be used with relative files
D.Index files are required for ACLs
💡 Difficulty: hard | ✅ Correct: A

📖 Explanation: Relative files treat the entire file as a sequence of records, and the file system typically applies permissions to the whole file, not to individual records. Consequently, fine‑grained per‑record ACLs are not possible. Encryption, RAID compatibility, and index files are unrelated to this limitation.

Q26. A security audit reveals that a volume's index file is world‑readable. What risk does this pose regarding confidentiality?

A.Any user can discover the location of sensitive files ✅
B.The volume will lose all data
C.RAID redundancy will be compromised
D.All ACLs become ineffective
💡 Difficulty: hard | ✅ Correct: A

📖 Explanation: If the index file is readable by all users, they can map usernames or keys to actual file locations, effectively bypassing normal permission checks and exposing confidential data. This does not cause data loss, affect RAID redundancy, nor nullify existing ACLs; it merely provides a shortcut to locate protected files.
