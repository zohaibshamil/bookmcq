What is File System Mounting in Operating System?

Definition:
Mounting attaches a filesystem rooted at a specific device or partition to an existing directory mount point \( mp \), integrating it into the unified namespace visible at path \( mp \).

Example:
Executing \( mount /dev/sdb1 /mnt/usb \) makes the USB drive's contents accessible under \( /mnt/usb/photos \); unmounting detaches it safely after flushing pending writes.

Reason:
Mounting enables modular storage management, allowing heterogeneous filesystems (NTFS, ext4, NFS) to coexist transparently and permitting dynamic addition/removal of storage without rebooting or restructuring the primary hierarchy.

Q1. What term describes the unused space that remains in the last allocated block of a file because the file size is not an exact multiple of the block size?

A.Internal fragmentation ✅
B.External fragmentation
C.Slippage
D.Padding
💡 Difficulty: easy | ✅ Correct: A

📖 Explanation: The correct answer is Internal fragmentation because the leftover bytes in the final block cannot be used for other data, which is exactly what internal fragmentation means. External fragmentation refers to gaps between allocated blocks, not space inside a block. Slippage and padding are unrelated concepts. Recognizing internal fragmentation helps students understand why some storage appears wasted even though the file fits within its allocated blocks.

Q2. In sequential-access files, what is the primary role of the file pointer after a read operation?

A.To locate the next block on disk
B.To advance to the start of the file
C.To track the current I/O location for the next read or write ✅
D.To close the file automatically
💡 Difficulty: easy | ✅ Correct: C

📖 Explanation: The file pointer tracks the current I/O location, so after a read it points to the next byte or record to be processed. This enables the system to know where to continue reading or writing. Options A and B describe different actions, and D is unrelated. Understanding the pointer’s role clarifies how sequential access progresses through a file.

Q3. Why does increasing the block size generally increase internal fragmentation in a file system?

A.Because more bytes are allocated per block, causing larger unused portions in the final block ✅
B.Because larger blocks reduce the number of files
C.Because the operating system compresses data
D.Because larger blocks cause external fragmentation
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: Larger block sizes allocate more space for each block, so the remainder of the last block is often bigger, leading to greater internal fragmentation. The other options describe unrelated effects: reducing file count, compression, or external fragmentation, none of which directly explain the waste inside a block. This concept explains why designers must balance block size against wasted space.

Q4. A file of 3,000 bytes is stored on a disk with a block size of 1,024 bytes. How many bytes are wasted due to internal fragmentation?

A.48 ✅
B.72
C.96
D.120
💡 Difficulty: easy | ✅ Correct: A

📖 Explanation: Three blocks are needed (3 × 1,024 = 3,072 bytes). The file occupies 3,000 bytes, leaving 3,072 − 3,000 = 72 bytes unused, which is internal fragmentation. Option A (48) and C (96) are incorrect calculations, and D (120) overestimates the waste. Knowing how to compute wasted space lets students evaluate storage efficiency for different block sizes.

Q5. How does the tape model influence the design of sequential-access methods for modern file systems?

A.It requires random access capabilities
B.It encourages reading records in order and using a file pointer that moves forward ✅
C.It mandates fixed-size records only
D.It eliminates need for buffering
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: The tape model treats a file like a linear stream, so sequential-access methods read records in order and rely on a moving file pointer. This design simplifies implementation and matches many applications. Options A and C impose constraints not inherent to the tape model, and D is false because buffering remains important for performance. The model’s influence explains why sequential APIs are still common.

Q6. A database stores records averaging 1,800 bytes. To minimize internal fragmentation, which block size should an administrator choose?

A.512 bytes
B.1,024 bytes
C.2,048 bytes ✅
D.4,096 bytes
💡 Difficulty: medium | ✅ Correct: C

📖 Explanation: Choosing a block size just larger than the average record (2,048 bytes) ensures each record fits in a single block, limiting waste to the difference between block size and record size (≈248 bytes). Smaller blocks would require multiple blocks per record, increasing total waste, while a larger block (4,096 bytes) would double the unused space. This decision illustrates the trade‑off between block size and fragmentation.

Q7. Which statement correctly distinguishes internal fragmentation from external fragmentation?

A.Internal fragmentation occurs within allocated blocks, external occurs between allocated blocks ✅
B.Internal fragmentation is caused by variable‑length records
C.External fragmentation is only a concern for sequential files
D.Internal fragmentation can be eliminated by using larger blocks
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: Internal fragmentation is the unused space inside a block that has been allocated, whereas external fragmentation refers to free gaps between allocated blocks on the disk. The other options mischaracterize causes or scope: variable‑length records affect allocation strategy, not fragmentation type; sequential files can still suffer external fragmentation; and larger blocks often increase, not eliminate, internal fragmentation.

Q8. A program using sequential access wants to skip forward two records after reading the third record. Which operation best describes this action?

A.read_next() twice
B.seek(n) with n=2 ✅
C.write_next() with empty data
D.reset() then read_next()
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: The seek operation with n = 2 tells the system to move the file pointer ahead by two records, effectively skipping them. Using read_next() twice would also work but is less direct; write_next() does not affect reading, and reset() would return to the file start. This scenario tests understanding of how to programmatically move past records in a sequential file.

Q9. How does internal fragmentation impact overall storage efficiency on a disk with many small files?

A.It reduces efficiency because each file may waste a significant portion of its last block ✅
B.It improves efficiency by consolidating free space
C.It has no impact on efficiency
D.It only affects large files
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: When many small files are stored, each file’s final block can contain a large unused portion, cumulatively reducing usable storage and lowering efficiency. The other options are inaccurate: internal fragmentation does not consolidate free space, it does affect efficiency, and it is more pronounced for small files, not just large ones. Recognizing this effect guides decisions about block size for mixed workloads.

Q10. Three files have sizes 2,500 bytes, 4,700 bytes, and 9,200 bytes. If the disk block size is 1,024 bytes, what total wasted space results from internal fragmentation?

A.904 bytes
B.1,008 bytes ✅
C.1,120 bytes
D.1,240 bytes
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: File 1 needs 3 blocks (3 × 1,024 = 3,072) → waste = 572 bytes. File 2 needs 5 blocks (5 × 1,024 = 5,120) → waste = 420 bytes. File 3 needs 9 blocks (9 × 1,024 = 9,216) → waste = 16 bytes. Total waste = 572 + 420 + 16 = 1,008 bytes. The other options result from mis‑adding or mis‑calculating block counts. This calculation shows how fragmentation adds up across many files.

Q11. After performing write_next() to append 600 bytes to a file that currently ends at byte offset 2,048, where will the file pointer be positioned?

A.2048 ✅
B.2600
C.2648
D.3200
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: The write_next() call adds 600 bytes, moving the end of the file from 2,048 to 2,648 bytes; the file pointer is automatically placed at the new end. Option A leaves the pointer unchanged, B miscalculates the offset, and D adds an extra 552 bytes. Understanding pointer movement after writes is essential for correct sequential file handling.

Q12. Which of the following best explains the trade‑off between larger block sizes and internal fragmentation when designing a file system for a workload dominated by large multimedia files?

A.Larger blocks reduce the number of I/O operations but increase internal fragmentation for small files ✅
B.Larger blocks eliminate internal fragmentation entirely
C.Smaller blocks improve transfer rates for large files
D.Larger blocks cause external fragmentation
💡 Difficulty: hard | ✅ Correct: A

📖 Explanation: Larger blocks mean fewer I/O operations because each read/write transfers more data, which benefits large multimedia files. However, for any small files that exist, the last block can waste more space, increasing internal fragmentation. The other statements are false: larger blocks do not eliminate fragmentation, they do not improve transfer rates for large files compared to optimal sizing, and they do not directly cause external fragmentation.

Q13. A system stores 10,000 files whose sizes follow a uniform distribution between 200 bytes and 2,000 bytes. Which block size minimizes expected internal fragmentation?

A.256 bytes
B.512 bytes
C.1,024 bytes ✅
D.2,048 bytes
💡 Difficulty: hard | ✅ Correct: C

📖 Explanation: For a uniform distribution, the expected waste per file equals half the block size. To minimize waste, the smallest practical block size should be chosen; 512 bytes is the smallest common size among the options, yielding an expected waste of 256 bytes per file. Larger block sizes would double or quadruple the average waste. This reasoning illustrates how statistical file size patterns guide block‑size decisions.

Q14. A sequential file allows skipping backward by one record only. If a program reads record 5, then skips back one record, which record will be read next?

A.Record 4 ✅
B.Record 5
C.Record 6
D.Record 7
💡 Difficulty: hard | ✅ Correct: A

📖 Explanation: Skipping back one record moves the file pointer to the previous record, so after reading record 5 and moving back, the next read returns record 4. Options B, C, and D ignore the backward movement or assume forward skipping, which contradicts the given limitation. This scenario tests understanding of pointer manipulation in constrained sequential access.

Q15. Why might an operating system still provide a sequential‑access interface for files stored on random‑access media?

A.Because many applications process data in order and benefit from simplified API and caching
B.Because random‑access media cannot support random reads ✅
C.Because sequential access reduces disk wear
D.Because it forces files to be stored contiguously
💡 Difficulty: hard | ✅ Correct: B

📖 Explanation: Sequential access matches the natural order of many workloads (e.g., log processing) and allows the OS to implement efficient read‑ahead buffering and caching, simplifying program design. Random‑access media can still perform random reads, so option B is false; sequential access does not inherently reduce wear or force contiguity, making C and D incorrect. Recognizing this rationale explains why both access methods coexist.

Q16. A disk has a capacity of 500 GB and uses a block size of 4 KB. If internal fragmentation wastes an average of 1 KB per file and there are 1 million files, what fraction of the disk capacity is lost to internal fragmentation?

A.0.001
B.0.002 ✅
C.0.005
D.0.01
💡 Difficulty: hard | ✅ Correct: B

📖 Explanation: Total waste = 1 KB × 1,000,000 = 1,000,000 KB = 1,000 MB = 1 GB. Fraction of 500 GB = 1 GB ÷ 500 GB = 0.002 = 0.2 %. The other percentages result from mis‑calculating the waste or total capacity. This problem shows how even small per‑file waste can add up across many files, influencing storage planning.

Q17. A program reads the first 3 records of a sequential file, then calls reset(). What will be the next record read?

A.Record 1
B.Record 4 ✅
C.Record 3
D.End‑of‑file
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: The reset() operation returns the file pointer to the beginning of the file, so the subsequent read retrieves the first record again. Option B would be correct without reset, C repeats the last read record, and D incorrectly assumes the file ends. Understanding reset behavior is crucial for correctly restarting processing of sequential data.

Q18. When a sequential‑access system permits skipping forward only one record at a time, what limitation does this impose on algorithm design?

A.It prevents any form of random access
B.It forces algorithms to process records in strict order or use additional buffering ✅
C.It eliminates need for file pointers
D.It allows unlimited backward jumps
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: Limiting skips to one record forces programs to handle data in order or maintain their own buffers if they need to look ahead, effectively restricting algorithmic flexibility. The other statements misrepresent the effect: skipping one record does not entirely block random access, does not remove file pointers, and does not enable unlimited backward jumps. Recognizing this constraint helps developers design efficient sequential algorithms.

Q19. If a file of 1,949 bytes is stored using 256‑byte blocks, how many bytes are wasted due to internal fragmentation?

A.99 ✅
B.48
C.128
D.0
💡 Difficulty: easy | ✅ Correct: A

📖 Explanation: The file requires ceil(1,949 ÷ 256) = 8 blocks, giving 8 × 256 = 2,048 bytes allocated. Waste = 2,048 − 1,949 = 99 bytes. Options B, C, and D are incorrect calculations. Knowing how to compute waste for a given block size lets students evaluate the impact of block‑size choices on storage efficiency.

Q20. How does sequential access enable more effective read‑ahead buffering compared to random access?

A.Because the next record location is predictable, allowing the system to prefetch data ✅
B.Because it disables caching
C.Because it forces the OS to read the entire file at once
D.Because it requires the disk head to move randomly
💡 Difficulty: hard | ✅ Correct: A

📖 Explanation: When access is sequential, the system knows that the next record follows the current one, so it can load subsequent blocks into memory before they are requested, reducing latency. The other options are false: sequential access does not disable caching, does not demand full‑file reads, and does not cause random head movement. This principle underlies performance optimizations for streaming data.

Q21. A file currently ends at byte offset 5,120. A program performs three consecutive write_next() calls each writing 300 bytes. What will be the final file pointer offset?

A.5420
B.5920
C.6020 ✅
D.6120
💡 Difficulty: medium | ✅ Correct: C

📖 Explanation: Each write adds 300 bytes, so three writes add 900 bytes total. Adding this to the original offset of 5,120 bytes yields 6,020 bytes, which is where the file pointer ends. Options A and B underestimate the total added bytes, while D adds an extra 100 bytes. Understanding cumulative pointer movement after multiple writes is essential for correct file size tracking.
