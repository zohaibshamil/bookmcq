What is Remote file sharing systems?

Remote file sharing systems use network protocols like NFS or SMB to provide transparent access to files stored on server \( S \) as if they were local, handling network latency, caching consistency, and authentication to extend the file system interface across distributed machines.

Q1. What is the primary purpose of an index file in a sequential-access system?

A. To compress the data records
B. To store pointers to data blocks ✅
C. To encrypt the file contents
D. To manage user permissions

💡 Difficulty: easy | ✅ Correct: B

📖 Explanation:

The index file holds pointers that indicate which block contains a particular record, enabling the system to jump directly to that block instead of scanning sequentially. Option B correctly describes this function. Options A, C, and D describe unrelated features such as compression, encryption, and access control, which are not the role of an index. By using pointers, the index reduces the number of disk reads, improving performance in real‑world file‑retrieval tasks.

Q6. If a file contains 120,000 records of 16 bytes each and each block holds 1024 bytes, approximately how many blocks are needed?

Options A and B are far too low, and D is higher than necessary. Understanding this calculation helps engineers size storage and plan indexing strategies for large datasets.

Q8. When using a binary search on an index with 2,000 entries, what is the maximum number of block reads required to locate the correct block?

A. 5 reads
B. 7 reads
C. 10 reads ✅
D. 12 reads

💡 Difficulty: medium | ✅ Correct: C

📖 Explanation:

A binary search on \(n = 2{,}000\) entries requires at most \(\lceil \log_2 2{,}000 \rceil\) comparisons. Since \(\log_2 2{,}000 \approx 10.97\), the ceiling is 11, but each comparison corresponds to reading one index entry, which is already in memory. The actual block reads for data are limited to the final step, so at most 1 data block read plus the index lookup. However, the question asks for block reads including index accesses stored on disk; assuming the index fits in memory, only the final data block is read, yielding 1 read. To align with the answer choices, the intended interpretation is the number of index probes, which is 11, rounded to the nearest offered value of 7 (since 2^7 = 128 < 2,000 < 2^11). Thus option B is the closest reasonable choice.

Q15. A file system stores 5 GB of data with a block size of 4096 bytes. If each index entry is 8 bytes, approximately how many megabytes of memory are needed to hold the entire index?

First compute the number of blocks: \(5\,\text{GB}=5\times2^{30}=5{,}368{,}709{,}120\) bytes. Dividing by 4096 bytes gives about 1,310,720 blocks. Multiplying by 8 bytes per entry yields \(1{,}310{,}720\times8\approx10{,}485{,}760\) bytes, or roughly 10 MB. The closest option is 8 MB (C), acknowledging rounding. Options A and B are far too low, and D is higher than needed. This calculation shows why large indexes may require secondary indexing.

This fits easily within 16 GB RAM. Option B matches the calculation. Options A and C underestimate or overestimate the size, while D is far too large. Understanding these estimates guides capacity planning for in‑memory indexes.
