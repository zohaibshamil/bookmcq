📝 Deadlocks and Starvation in Semaphore (36 MCQs)

Indefinite Waiting and Resource Deadlocks

Deadlock and starvation are synchronization problems that may occur when processes coordinate resource access through semaphores. Deadlock describes a situation in which processes remain permanently blocked because each waits for an event or resource that another blocked process must provide. Starvation occurs when a process waits indefinitely because competing processes repeatedly receive access or scheduling priority.

How Incorrect Semaphore Ordering Creates Circular Wait

Processes may acquire several resources in different orders, producing circular dependencies. If P1 holds resource A and waits for B while P2 holds B and waits for A, neither can proceed. Starvation can arise separately when a semaphore's wake-up policy repeatedly favours other waiting processes, even though the system continues making progress.

Semaphore Acquisition, Waiting Queues, and Release

Each process performs wait operations before using protected resources and signal operations after releasing them. Deadlock occurs when competing processes retain acquired resources while requesting additional unavailable resources. Starvation occurs when the waiting-queue policy fails to provide fair access. Consistent resource ordering, deadlock avoidance, and fair queue management address these different problems.

Two Semaphores Producing a Circular Wait

Suppose P1 acquires semaphore A and then waits for B, while P2 acquires B and then waits for A. Both semaphore permits are unavailable, so neither process can reach its signal operation. The processes remain blocked indefinitely. Requiring both processes to acquire A before B prevents this particular circular-wait pattern.

System Progress, Fairness, and Resource Utilisation

Deadlock can permanently reduce system throughput and leave allocated resources unavailable. Starvation can produce severe delays for individual processes even when other work completes. Semaphore-based systems require consistent resource ordering, suitable timeout or recovery policies where appropriate, and fair wake-up mechanisms. A fair queue can reduce starvation but does not independently eliminate every possible deadlock.

Misconceptions About Deadlock and Starvation

'Deadlock and starvation mean exactly the same thing' is incorrect because deadlock prevents participating processes from progressing, while starvation can occur amid system progress. 'Every waiting process is deadlocked' is incorrect because ordinary resource waiting may eventually end. 'Fair semaphore queues eliminate circular wait' is incorrect because queue fairness does not prevent resource dependency cycles.

Exam Focus: Detecting Circular Wait and Indefinite Postponement

Trace wait and signal sequences to identify held resources and blocked requests. Draw a resource-allocation graph and identify circular dependencies. Distinguish deadlock from starvation and ordinary blocking. Questions may test the four necessary deadlock conditions, resource ordering, fair semaphore queues, and strategies that prevent or reduce indefinite waiting.

Key Terms of Semaphore Deadlocks and Starvation

  • Deadlock - Processes permanently waiting on one another.
  • Starvation - Indefinite postponement of one process.
  • Circular wait - Closed chain of resource dependencies.
  • Resource ordering - Consistent sequence of resource acquisition.
  • Fairness - Equitable opportunity for resource access.
  • Recovery - Action restoring progress after deadlock.

📝 All Deadlocks and Starvation in Semaphore MCQs

Q1. In a semaphore-based program, P and Q are both blocked. Each is waiting for a signal that only the other blocked process can issue. What condition best describes this state?

A.Starvation of one process while the other continues
B.Deadlock between the two processes ✅
C.Busy waiting by both processes
D.Ordinary contention for a resource that will soon be released
💡 Difficulty: easy | ✅ Correct: B

📖 Explanation: Deadlock exists when every process in the set waits for an event that only another process in that same set can produce. Because both signal-producing actions are unreachable, neither process can progress.

Q2. P acquires semaphore S. Q waits while P performs finite work and is guaranteed to signal S before requesting anything else. Which conclusion is justified?

A.Q is temporarily blocked; the stated execution does not establish deadlock ✅
B.P and Q are deadlocked because Q cannot enter immediately
C.Q is starving even though P will soon release S
D.The semaphore has lost a permit because one process is waiting
💡 Difficulty: easy | ✅ Correct: A

📖 Explanation: Waiting for an occupied semaphore is normal contention when its owner can finish and signal. Deadlock requires a dependency that prevents the needed signal from occurring, which this execution explicitly rules out.

Q3. Binary semaphores S and Q both start at 1. P0 executes wait(S) successfully; P1 executes wait(Q) successfully; P0 then blocks at wait(Q); P1 then blocks at wait(S). What is the resulting state?

A.Both processes are ready but waiting for CPU time
B.Only P0 is deadlocked; P1 can continue
C.P0 and P1 are deadlocked while holding opposite semaphores ✅
D.Neither process is blocked because both initial values were 1
💡 Difficulty: medium | ✅ Correct: C

📖 Explanation: P0 holds S and waits for Q, while P1 holds Q and waits for S. Each required signal depends on the other process progressing, so neither can release its held semaphore without external intervention.

Q4. A student labels every process blocked in wait(S) as deadlocked. Which correction identifies the flaw in this reasoning?

A.A blocked process is always executing a signal operation
B.A process can wait only when the semaphore value is positive
C.Deadlock occurs only when exactly one process is blocked
D.Blocking alone is insufficient; the needed event may still be produced by a process that can progress ✅
💡 Difficulty: easy | ✅ Correct: D

📖 Explanation: The flawed step equates waiting with deadlock. A semaphore owner may still be executing and later signal, so the analyst must establish a closed dependency preventing every relevant process from producing its required event.

Q5. A dependency graph has edges P → S1, S1 → Q, Q → S2, and S2 → P. Each semaphore has one permit, both processes are blocked, and neither can release its held permit independently. What does the graph show?

A.A one-way wait that will end when the scheduler runs P
B.A circular wait consistent with deadlock ✅
C.Starvation caused only by an unfair queue
D.A safe state because each process owns one semaphore
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: The edges show P requesting S1 held by Q and Q requesting S2 held by P. With one permit per semaphore and no independent release path, the cycle prevents either process from advancing.

Q6. Two processes are deadlocked because each holds a semaphore needed by the other. The scheduler is changed to round-robin with equal time slices. What should be expected?

A.The scheduler will make both blocked processes execute their signal calls
B.The deadlock becomes starvation because time slices are equal
C.The dependency remains; CPU fairness cannot run processes that are blocked on unavailable permits ✅
D.Both semaphores automatically become available at each context switch
💡 Difficulty: medium | ✅ Correct: C

📖 Explanation: Round-robin scheduling allocates CPU time among runnable processes, not blocked ones. Since each process needs a permit held by the other, changing the time-slice policy does not break the resource dependency.

Q7. Several processes may request semaphore A and semaphore B. Which rule most directly prevents the described deadlock pattern in which different processes acquire them in opposite orders?

A.Require every process to acquire semaphores in one shared global order ✅
B.Let each process choose its own acquisition order
C.Make every wait operation retry more frequently
D.Increase the CPU priority of whichever process waits longest
💡 Difficulty: easy | ✅ Correct: A

📖 Explanation: A consistent global order prevents one process from holding a later resource while requesting an earlier one. Opposite acquisition orders can create circular wait; a shared order removes that possibility for these resources.

Q8. An allocation diagram for multiple-instance counting semaphores contains a cycle. One process in the diagram can finish finite work and signal its held semaphore without waiting for another permit. What conclusion is safest?

A.The cycle proves deadlock regardless of semaphore counts
B.Starvation is impossible because a permit remains available
C.All processes in the graph must terminate immediately
D.The cycle alone does not prove deadlock; an available permit may let a process progress and break the dependency ✅
💡 Difficulty: medium | ✅ Correct: D

📖 Explanation: A cycle in a multiple-instance allocation diagram is not conclusive when a holder can release a permit independently. That signal may break the dependency and let another process continue, so execution details matter.

Q9. P holds semaphore S1 and waits for S2. Q holds S2 but can complete a finite independent operation and signal S2 without acquiring another semaphore. Is the pair necessarily deadlocked?

A.Yes, because P already holds one semaphore
B.Yes, because two processes hold two different semaphores
C.No; Q can still signal S2, allowing P to proceed ✅
D.No; semaphores cannot participate in deadlock
💡 Difficulty: easy | ✅ Correct: C

📖 Explanation: Q has an independent path to signal S2, so the event needed by P can still occur. Holding a resource while another process waits is not sufficient for deadlock when the holder can release it.

Q10. A blocked process is repeatedly denied semaphore S. An engineer raises its CPU priority and claims that this guarantees progress. What is wrong with the claim?

A.Higher priority always decreases the semaphore count
B.A blocked process cannot use CPU priority to obtain a permit that another process still holds ✅
C.Priority changes convert binary semaphores into counting semaphores
D.A priority increase forces every current owner to signal immediately
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: The flawed step treats scheduling priority as resource ownership. Priority affects which runnable process receives CPU time, but a blocked process still needs the semaphore holder to release a permit or the protocol to change.

Q11. A monitoring table records (checkpoint, completed jobs, cumulative wait of P in minutes): (1,4,5); (2,5,10); (3,6,15); (4,7,20); (5,8,25). Which interpretation best fits these data?

A.The whole system is deadlocked because P has not completed
B.P is making progress because total job completions are increasing
C.The data prove that semaphore S has a negative count
D.P may be starving while other jobs continue to complete ✅
💡 Difficulty: medium | ✅ Correct: D

📖 Explanation: Completed jobs increase at every checkpoint, while P’s cumulative wait grows steadily. This indicates overall system progress alongside indefinite postponement of one process, which is consistent with starvation rather than total deadlock.

Q12. A semaphore uses a FIFO wait queue. After being awakened, the oldest waiter is repeatedly preempted by higher-priority work and never runs long enough to complete its critical section. What remains possible?

A.Starvation due to CPU scheduling despite FIFO selection from the semaphore queue ✅
B.Deadlock is impossible because FIFO always guarantees execution
C.The FIFO queue must reorder waiters after every preemption
D.The semaphore automatically grants a second permit to the awakened process
💡 Difficulty: hard | ✅ Correct: A

📖 Explanation: FIFO controls which blocked waiter is selected when a permit is released. It does not guarantee CPU service after wake-up, so repeated preemption can still prevent that process from progressing and cause starvation.

Q13. A semaphore implementation removes waiters in LIFO order. New processes keep arriving, and the oldest waiter is never selected. Which problem can result?

A.Mutual exclusion failure
B.Indefinite blocking or starvation of the older waiter ✅
C.Guaranteed deadlock of every process
D.A semaphore count that must increase on every arrival
💡 Difficulty: easy | ✅ Correct: B

📖 Explanation: LIFO selection favors the newest waiter. Under continuing arrivals, an older process can be bypassed repeatedly even while others acquire the semaphore, producing indefinite blocking or starvation despite continued system progress.

Q14. A system imposes the order S1 before S2 for every process. A process currently holds S2 and now needs S1. Which action follows the ordering policy?

A.Wait for S1 while continuing to hold S2
B.Acquire S1 by decrementing its count twice
C.Release S2, acquire S1 first, and then request S2 again when needed ✅
D.Ask the scheduler to swap the semaphore order for this process
💡 Difficulty: medium | ✅ Correct: C

📖 Explanation: The policy requires S1 to be acquired before S2. Holding S2 while requesting S1 violates the order and can recreate circular wait; releasing S2 lets the process restart acquisition in the permitted sequence.

Q15. A developer argues that a FIFO queue for every semaphore makes deadlock impossible. Which reasoning exposes the error?

A.FIFO can reduce bypassing, but processes may still hold different semaphores while waiting for one another ✅
B.FIFO queues cannot be used with binary semaphores
C.Deadlock requires a LIFO queue and cannot occur with any other policy
D.FIFO causes every process to release all resources before waiting
💡 Difficulty: hard | ✅ Correct: A

📖 Explanation: The mistaken claim confuses fairness within one queue with the absence of resource cycles. FIFO may reduce starvation among waiters, but inconsistent acquisition orders can still leave processes holding permits needed by one another.

Q16. Which description best identifies starvation in semaphore use?

A.Every process is blocked because each waits for an event from another blocked process
B.A process releases its semaphore before finishing its work
C.A semaphore begins with a count greater than one
D.One process waits indefinitely while other processes continue acquiring and releasing the semaphore ✅
💡 Difficulty: easy | ✅ Correct: D

📖 Explanation: Starvation is process-specific indefinite postponement. Unlike deadlock, the system may continue completing work because other processes obtain the semaphore, while one unlucky waiter is repeatedly bypassed despite ongoing system progress elsewhere.

Q17. P holds semaphore S while waiting for a message. The only sender can send that message only after acquiring S. Which protocol change most directly removes this dependency?

A.Increase P’s priority while it continues holding S
B.Make the sender poll S more frequently
C.Arrange for P to release S before waiting for the message, when the shared-state protocol permits it ✅
D.Let both processes decrement S even when no permit is available
💡 Difficulty: medium | ✅ Correct: C

📖 Explanation: P cannot receive the message while retaining S if the sender needs S to send it. Releasing S before the event wait, when safe for the shared data, removes the resource-dependent circular wait.

Q18. A dependency graph shows P holding A and requesting B, Q holding B and requesting C, and R holding C and requesting A. Each process keeps its held semaphore until the next request succeeds. What does the graph indicate?

A.A safe chain because each process owns one resource
B.A circular wait among P, Q, and R that can produce deadlock ✅
C.Starvation of R only, because it requests A
D.No synchronization problem unless the CPU is idle
💡 Difficulty: hard | ✅ Correct: B

📖 Explanation: P waits for Q, Q waits for R, and R waits for P through the held semaphores. Because none releases its current permit before its next request succeeds, the closed cycle prevents progress.

Q19. A high-priority process is blocked on S1. The process holding S1 is itself blocked on S2, which is held by a third process waiting for S1. Why does raising the first process’s priority not resolve the situation?

A.The processes are blocked by a resource cycle, not by lack of CPU priority ✅
B.The high-priority process automatically loses its semaphore request
C.Raising priority changes S1 into a counting semaphore
D.The scheduler must terminate the process holding S2
💡 Difficulty: hard | ✅ Correct: A

📖 Explanation: The dependency chain closes back on S1, so each process needs another holder to act first. CPU priority only helps runnable processes; it cannot grant a blocked process a permit held within the cycle.

Q20. Counting semaphore S starts at 2. P and Q each acquire one permit, then perform finite computations that require no further semaphore. Both will signal S afterward. Which conclusion is correct?

A.Deadlock exists because the count has reached zero
B.Starvation is certain because no permit is currently free
C.The semaphore is corrupted because two processes hold permits at once
D.Both processes can finish and release their permits; using all current permits does not itself imply deadlock ✅
💡 Difficulty: easy | ✅ Correct: D

📖 Explanation: Both holders can complete without acquiring anything else, so each can eventually signal the semaphore. A zero available count indicates current occupancy, not deadlock, unless required progress depends on unavailable permits.

Q21. A student sees all permits of a counting semaphore in use and concludes that the system is deadlocked. Which missing check is essential?

A.Whether the semaphore was declared globally
B.Whether holders can finish and release permits without waiting for additional unavailable resources ✅
C.Whether the processes have different identifiers
D.Whether the scheduler uses round-robin rather than first-come scheduling
💡 Difficulty: hard | ✅ Correct: B

📖 Explanation: The flawed inference treats complete occupancy as proof of deadlock. The analyst must determine whether permit holders can continue and signal; if they can, the current wait is temporary contention rather than deadlock.

Q22. A FIFO semaphore queue contains waiting processes in this order: P, then Q, then R. Two separate signal operations each wake one waiter, and no new process arrives. Who remains waiting afterward?

A.R ✅
B.P
C.Q
D.No process; each signal wakes every waiter
💡 Difficulty: easy | ✅ Correct: A

📖 Explanation: FIFO removes the oldest waiter first. The first signal wakes P and the second wakes Q, leaving R at the queue head; this ordering reduces the chance that an older waiter is repeatedly bypassed.

Q23. A deadlock has already been detected. The operating system terminates one process in the cycle and safely releases the semaphores it owned so another process can continue. How is this action classified?

A.Deadlock avoidance before allocation
B.Starvation prevention through queue ordering
C.Deadlock recovery by process termination ✅
D.Circular-wait creation
💡 Difficulty: easy | ✅ Correct: C

📖 Explanation: The system acts after deadlock detection and breaks the resource cycle by terminating a participant. Because the action responds to an existing deadlock rather than preventing its conditions, it is recovery.

Q24. At five checkpoints, observations for processes P, Q, and R are: P wait = (2,4,6,8,10) seconds; Q wait = (2,1,2,1,2); R wait = (1,2,1,2,1). At each checkpoint another process acquires the semaphore. Which process is the strongest starvation candidate?

A.Q, because its wait sometimes decreases
B.R, because its wait alternates
C.All three equally, because every process has a nonzero wait
D.P, because its wait rises continuously while others continue to obtain the permit ✅
💡 Difficulty: medium | ✅ Correct: D

📖 Explanation: P’s waiting time increases at every observation, while Q and R repeatedly obtain opportunities to proceed. The pattern supports process-specific starvation for P, not a system-wide deadlock affecting every waiter.

Q25. A program enforces a global order on all semaphores, preventing processes from requesting them in reverse order. Each semaphore still selects waiters randomly. Which statement is accurate?

A.Circular wait can be prevented while an individual process may still starve under the random selection policy ✅
B.The global order guarantees every waiter receives a permit within a fixed time
C.Random selection necessarily creates a deadlock cycle
D.The global order makes semaphore signals unnecessary
💡 Difficulty: hard | ✅ Correct: A

📖 Explanation: A global order addresses circular wait, one source of deadlock. It does not guarantee fair selection from each waiting queue, so random selection can repeatedly bypass a process and allow starvation.

Q26. Two processes need semaphores A and B together. The system grants both permits as one indivisible reservation or grants neither. Which deadlock condition is directly reduced by this design?

A.Mutual exclusion
B.Hold and wait ✅
C.Circular wait in every possible resource set
D.The possibility of a process being preempted
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: A process never keeps only A while waiting for B, because it obtains both or neither. This removes hold-and-wait for the specified pair, although other resources and unfair allocation can still cause problems.

Q27. After detecting a deadlock, an administrator releases every semaphore held by P but lets P continue as though it still owns those resources. What is the main flaw?

A.P will automatically stop at the next instruction
B.Other processes can no longer acquire the released permits
C.P may access shared data concurrently with new owners, violating the ownership protocol and corrupting state ✅
D.The operation converts all semaphores into mutex locks
💡 Difficulty: hard | ✅ Correct: C

📖 Explanation: The recovery step revokes ownership without changing P’s execution state. P may continue modifying shared data after another process acquires the permit, so safe recovery must coordinate termination, rollback, or explicit reacquisition.

Q28. A program adds timeouts to semaphore waits. A timeout can identify a prolonged wait, but the program does not release resources or restore shared state when it expires. Which statement is correct?

A.Timeouts prevent circular wait before it forms
B.Timeouts guarantee that every waiter eventually acquires the semaphore
C.The timeout automatically releases every permit held by other processes
D.Timeouts can reveal a stalled wait, but safe recovery still requires handling held resources and shared state ✅
💡 Difficulty: hard | ✅ Correct: D

📖 Explanation: A timeout reports that a wait exceeded a chosen interval; it does not by itself undo resource ownership or repair partially updated data. Recovery logic must safely release, reacquire, roll back, or terminate as appropriate.

Q29. Which semaphore queue policy most directly reduces starvation caused by newer arrivals repeatedly bypassing older waiters, assuming awakened processes eventually receive CPU time?

A.Random selection
B.FIFO selection ✅
C.LIFO selection
D.Selection by newest process identifier
💡 Difficulty: easy | ✅ Correct: B

📖 Explanation: FIFO selects waiters in arrival order, so a newly arriving process cannot continually jump ahead of an older queued process. The guarantee still assumes permit holders release resources and awakened processes receive CPU service.

Q30. P holds semaphore S and waits for event E. The only process able to produce E must first acquire S. Which protocol change most directly breaks the circular dependency, assuming shared data can be left consistent?

A.Have P release S before waiting for E, then reacquire it when needed ✅
B.Increase P’s priority while it continues holding S
C.Make the event producer repeat wait(S) until it succeeds
D.Increase the semaphore count without changing actual resource availability
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: The current protocol makes the event producer wait for S while P waits for the event. Releasing S before the event wait allows the producer to proceed; P can reacquire the semaphore afterward.

Q31. A system orders semaphores A before B before C. P holds A and requests B; Q holds B and requests C; R holds C and requests A. To preserve the order and break this cycle, what must R do?

A.Keep C and repeatedly retry A
B.Ask P to increase its CPU priority
C.Acquire A before signaling C
D.Release C, restart by acquiring A first, and request C only after earlier resources in the order ✅
💡 Difficulty: hard | ✅ Correct: D

📖 Explanation: The request from R to acquire A while holding later-ordered C violates the global order. Releasing C and restarting with A before C removes that reverse edge, breaking the circular-wait pattern.

Q32. P and Q form a closed semaphore dependency cycle and cannot proceed, while unrelated process R continues completing jobs. Which interpretation is most accurate?

A.No deadlock exists because at least one process completes work
B.The entire operating system must be stopped
C.P and Q can be deadlocked as a subset even while unrelated processes continue making progress ✅
D.R’s progress guarantees that P and Q will eventually be scheduled
💡 Difficulty: hard | ✅ Correct: C

📖 Explanation: Deadlock can affect a subset of processes rather than every process in the system. R’s progress does not break the closed dependency between P and Q, whose required semaphore events remain unreachable.

Q33. A thread acquires a non-reentrant semaphore S and, before signaling it, calls wait(S) again. No other thread can signal S on its behalf. What is the likely result?

A.The thread blocks waiting for a permit that it cannot release while blocked, causing self-deadlock ✅
B.The semaphore automatically recognizes the same owner and grants another permit
C.The second wait is ignored because the first acquisition succeeded
D.The semaphore count increases and another thread enters
💡 Difficulty: easy | ✅ Correct: A

📖 Explanation: The thread already owns the only permit and blocks on its own second wait. Because it cannot execute the later signal while blocked, the event needed to resume itself cannot occur.

Q34. P holds A and needs B; Q holds B and needs A. The program is redesigned so a process that cannot obtain its next semaphore releases every semaphore it currently holds before retrying. Which effect is intended?

A.It guarantees FIFO service for every semaphore

C.It guarantees that no process can ever be delayed
D.It makes both semaphores available to all processes simultaneously
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: A process no longer keeps one semaphore while waiting for another unavailable semaphore. Releasing held permits before retrying removes hold-and-wait in this protocol and prevents the stated two-resource cycle, avoiding partial ownership during the wait.

Q35. A semaphore queue is fair, but its current owner waits indefinitely for a user event while still holding the permit. Other processes cannot acquire it. What does queue fairness fail to guarantee?

A.That wait operations are atomic
B.That the semaphore has an initial value
C.That a permit will become available when the owner never releases it ✅
D.That the process holding the permit can enter its critical section
💡 Difficulty: hard | ✅ Correct: C

📖 Explanation: Fair selection applies only after a permit becomes available. It cannot force the current owner to signal, so indefinite resource holding can block every queued process and may participate in deadlock.

Q36. P holds X and waits for Y, while Q holds Y and waits for X. Neither needs the CPU for further computation before its second wait succeeds. Which redesign most directly removes the cycle without relying on scheduling?

A.Give P a larger time slice than Q
B.Wake Q before P regardless of resource ownership
C.Let both processes retry their waits more often
D.Require each process to acquire the needed resource set atomically or release all held resources before waiting ✅
💡 Difficulty: hard | ✅ Correct: D

📖 Explanation: The cycle persists because each process retains one permit while waiting for the other. Atomic acquisition or releasing held permits before waiting removes that partial ownership, breaking the described hold-and-wait cycle.
