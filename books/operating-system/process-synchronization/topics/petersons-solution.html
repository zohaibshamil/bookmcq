What is Peterson's Solution?

Definition:
Peterson's solution is a software-based algorithm for the critical section problem involving two processes. It uses two shared variables: an integer `turn` and a boolean array `flag`. It satisfies mutual exclusion, progress, and bounded waiting without requiring special hardware instructions, making it a classic theoretical solution.

Working:
Each process sets its flag to true, indicating intent to enter. It then sets `turn` to the other process. It waits while the other process's flag is true and `turn` favors the other. This ensures only one enters. After exiting, it sets its flag to false.

Example:
Process P0 sets `flag[0]=true` and `turn=1`. If P1 also wants to enter, it sets `flag[1]=true` and `turn=0`. P0 checks `while(flag[1] && turn==1)`. Since `turn` is 0, P0 enters. P1 waits because `turn` is not 1. This ensures mutual exclusion.

Reason:
It provides a pure software solution for two processes, demonstrating that mutual exclusion can be achieved without hardware support. It is useful for understanding the logic behind synchronization before introducing complex hardware primitives or semaphores in operating system design.

Common MisConceptions:
Students often think it works for more than two processes. It strictly works for only two. Another misconception is that it is efficient; it uses busy waiting, which consumes CPU cycles, making it unsuitable for long critical sections or real-time systems.

Exam Preparation Tips: How to prepare this topic
Draw the flowchart for both processes. Trace the execution step-by-step for scenarios where both want to enter simultaneously. Verify how mutual exclusion and bounded waiting are satisfied. Note that it does not work for N processes without modification.

Key Terms:

  • Flag Array - indicates process interest in entering.
  • Turn Variable - indicates whose turn it is to enter.
  • Busy Waiting - continuously checking a condition in a loop.

📝 All Peterson's Solution MCQs

Q1. Two processes use Peterson's algorithm with separate intent flags and a shared turn variable. Both set their flags to true, and P sets turn to Q while Q sets turn to P. Assuming sequentially consistent memory, which process can enter the critical section?

A.Both processes must enter because both intent flags are true
B.Neither process can enter because both flags are true
C.Only P can enter regardless of the final value of turn
D.Only the process whose intent is favored by the final turn value can enter ✅
💡 Difficulty: hard | ✅ Correct: D

📖 Explanation: Each process checks whether the other process is interested and whether priority has been given to the other. When both flags are true, the final turn value determines which process waits. The process favored by the turn condition can enter, while the other remains in its entry loop.

Q2. A programmer changes the entry sequence so a process writes turn first and sets its own intent flag afterward. Why can this modification break correctness?

A.The turn variable becomes impossible to represent as a process identifier
B.A process may inspect the other's intent before the intended competing state has been established, invalidating the original synchronization reasoning ✅
C.The algorithm automatically becomes a counting semaphore
D.The modified sequence guarantees stronger bounded waiting
💡 Difficulty: hard | ✅ Correct: B

📖 Explanation: Peterson's algorithm relies on a specific ordering of publishing intent and yielding priority. Changing that order can expose an interleaving in which the other process makes its entry decision based on incomplete state. The original correctness argument no longer necessarily applies, so the modified algorithm requires a separate proof.

Q3. A student claims that Peterson's algorithm works for any number of processes if each process receives a unique flag index and the same turn variable is retained. What is the key error?

A.Intent flags cannot be represented by arrays
B.The algorithm requires exactly two competing processes, and extending it needs a different coordination design ✅
C.A turn variable must always be a Boolean
D.Peterson's algorithm never uses shared memory
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: The standard Peterson algorithm coordinates two processes using two intent flags and a turn variable whose values distinguish those processes. A single turn variable and the same entry logic do not directly establish mutual exclusion and progress for an arbitrary number of contenders. A generalized algorithm requires additional reasoning and structure.

Q4. In Peterson's algorithm, a process clears its own intent flag immediately after entering the critical section rather than when leaving it. What is the most serious consequence?

A.The other process may conclude that the critical section is available and enter concurrently ✅
B.The process can no longer execute ordinary arithmetic
C.The turn variable becomes permanently undefined
D.The algorithm automatically guarantees FIFO scheduling
💡 Difficulty: hard | ✅ Correct: A

📖 Explanation: The intent flag indicates that a process is competing for access and must remain true throughout its critical-section occupancy. Clearing it prematurely tells the other process that no competing request exists, even though the first process is still inside. This can undermine mutual exclusion.

Q5. A two-process implementation has correct shared variables and entry conditions, but a process forgets to set its flag to true before waiting. Which property is most directly endangered?

A.The ability to represent process identifiers
B.The number of available CPU cores
C.Mutual exclusion, because the other process may not recognize the pending competition ✅
D.The ability to execute a noncritical section
💡 Difficulty: hard | ✅ Correct: C

📖 Explanation: The intent flag communicates that a process wishes to enter its critical section. If a process omits this declaration, the other process may treat the shared region as uncontested and enter without yielding. The original algorithm depends on publishing intent before making the entry decision.

Q6. A code review finds that the exit section of each process sets turn to the other process but does not clear its own intent flag. What is the likely effect?

A.The algorithm becomes equivalent to a semaphore initialized to two
B.The algorithm guarantees that each process enters exactly once
C.The other process may continue believing that the exiting process is interested, causing unnecessary blocking or loss of progress ✅
D.The turn variable becomes irrelevant to all future entries
💡 Difficulty: hard | ✅ Correct: C

📖 Explanation: Clearing the exiting process's intent flag communicates that it no longer competes for the critical section. If the flag remains true, the other process may wait based on an outdated indication of interest. Depending on the remaining state and future execution, this can prevent progress or cause indefinite waiting.

Q7. A programmer initializes both flags to false but leaves turn uninitialized. At startup, only P wants to enter and Q's flag remains false. What is the best conclusion under the standard condition?

A.P's entry condition is satisfied because Q's flag is false, so the initial turn value is not needed for this uncontended entry ✅
B.P must wait forever until turn is initialized
C.Q enters even though it never requested entry
D.Mutual exclusion fails immediately whenever turn is uninitialized
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: If only P is interested and flag[Q] is false, P's condition permits entry regardless of the turn value. Therefore, this particular uncontended entry does not require a valid initial turn. However, the implementation should still initialize shared state correctly before concurrent use to ensure reliable behavior in all scenarios.

Q8. A process executes the entry code repeatedly and enters its critical section, but the algorithm is deployed on hardware where ordinary shared writes may become visible out of order. Which issue should be investigated first?

A.Whether process names are alphabetically ordered

C.Whether the scheduler uses round-robin scheduling

📖 Explanation: Peterson's proof assumes a particular ordering and visibility of shared-memory operations. Weak memory models or compiler reordering may let one process observe flags and turn in an order that invalidates the proof. Correct implementation requires appropriate atomic operations and memory-ordering guarantees.

Q9. P has flag[P] equal to true, flag[Q] equal to false, and turn equal to Q. What does the standard entry condition imply for P?

A.P waits until turn becomes P
B.P can enter because Q is not requesting the critical section ✅
C.P enters only if Q enters first
D.P must clear both flags before proceeding
💡 Difficulty: easy | ✅ Correct: B

📖 Explanation: P waits only while Q's flag is true and turn equals Q. Since flag[Q] is false, the combined waiting condition is false. P can therefore enter the critical section, showing that the algorithm does not require strict alternation when only one process is interested.

Q10. A student says Peterson's algorithm prevents starvation because the turn variable always gives one process priority. What is the strongest qualification?

A.The turn variable is never updated during execution
B.Starvation is impossible even if the scheduler never runs a waiting process
C.The algorithm supports bounded waiting under its assumptions, but scheduling and memory-model assumptions still matter ✅
D.The algorithm guarantees that every process receives equal CPU time
💡 Difficulty: hard | ✅ Correct: C

📖 Explanation: Peterson's algorithm provides bounded waiting for two processes under its standard assumptions, preventing one continuously competing process from being overtaken indefinitely. It does not force an unfair or stalled operating-system scheduler to execute a waiting process, and its software-level proof relies on valid memory semantics.

Q11. Both processes are outside their critical sections, and neither currently wants to enter. The shared turn variable equals Q. P now requests entry alone. What should happen?

A.P must wait for Q to enter and leave first
B.Q enters automatically because its turn value is stored
C.Neither process can enter until the turn variable changes
D.P can enter because Q's intent flag is false ✅
💡 Difficulty: easy | ✅ Correct: D

📖 Explanation: The turn variable resolves competition when both processes are interested. If Q is not interested, flag[Q] is false and P's waiting condition is false regardless of the current turn. P can therefore enter without requiring Q to participate.

Q12. A compiler optimization moves P's flag[P] = true assignment after P's entry-condition test. What is the primary correctness concern?

A.P may test the condition before announcing its interest, allowing the other process to make an incompatible entry decision ✅
B.The flag becomes impossible to reset
C.The turn variable automatically prevents every race despite the reordering
D.The algorithm becomes a hardware semaphore
💡 Difficulty: hard | ✅ Correct: A

📖 Explanation: The intent flag must be published before the process evaluates whether it may enter. Moving the write after the test can make the other process observe no competing request while P is proceeding into the critical section. The ordering is part of the algorithm's correctness argument and must be preserved.

Q13. A researcher wants to verify mutual exclusion in Peterson's algorithm. Which state would directly contradict the required property under the standard model?

A.Both flags are false while both processes are outside their critical sections
B.One process is inside and the other is waiting
C.Both processes are simultaneously inside their critical sections ✅
D.One process is in its noncritical section while the other enters
💡 Difficulty: easy | ✅ Correct: C

📖 Explanation: Mutual exclusion means that the critical sections of the two processes cannot overlap. A state in which both processes are simultaneously inside their critical sections is a direct violation. Other states, such as one process waiting while the other enters, are compatible with correct operation.

Q14. A developer changes the waiting condition from flag[other] && turn == other to flag[other] || turn == other. What is the likely consequence?

A.The algorithm becomes fairer because the process always yields
B.A process may wait even when the other process has no intent, preventing progress ✅
C.The algorithm no longer needs intent flags
D.The algorithm guarantees simultaneous entry for both processes
💡 Difficulty: hard | ✅ Correct: B

📖 Explanation: The standard waiting condition blocks a process only when the other process is interested and priority favors that other process. Replacing the conjunction with a disjunction causes waiting whenever either condition alone is true. This can block a process even when the other flag is false, undermining progress.

Q15. A model checker finds no mutual-exclusion violation but finds a state where P wants to enter, Q does not want to enter, and P cannot progress. Under the standard algorithm and assumptions, what should be investigated?

A.Whether the model incorrectly represents the entry condition or whether the implementation differs from the standard protocol ✅
B.Whether the critical section is too short to use flags
C.Whether the turn variable should contain a random value on every instruction
D.Whether mutual exclusion must be abandoned to guarantee progress
💡 Difficulty: hard | ✅ Correct: A

📖 Explanation: Under the standard Peterson protocol, a process should not be blocked by an uninterested competitor because the other process's false intent flag makes the waiting condition false. A counterexample of this kind suggests a modeling error, an incorrect condition, unexpected memory semantics, or a deviation from the intended algorithm.

Q16. A process enters its critical section, gets preempted, and remains there for a long time. The other process waits correctly. Which statement is most accurate?

A.Peterson's algorithm must violate mutual exclusion whenever preemption occurs
B.Preemption automatically clears the running process's flag
C.The waiting process must enter after a fixed number of CPU cycles
D.Mutual exclusion can remain intact even though progress is delayed by the paused critical-section owner ✅
💡 Difficulty: medium | ✅ Correct: D

📖 Explanation: Preemption does not automatically invalidate Peterson's algorithm. The waiting process remains excluded while the other process's intent flag and turn state indicate that it has priority. However, if the owner is not scheduled again, the waiter may experience a practical delay even though the algorithm's mutual-exclusion property remains intact.

Q17. A student argues that Peterson's algorithm requires disabling interrupts to work on a single processor. Which response is best?

💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: Peterson's algorithm is a software coordination method for two processes. Its proof relies on atomic reads and writes under the assumed memory model and correct operation ordering. Disabling interrupts is not the defining mechanism and is not generally necessary for its textbook sequentially consistent model.

Q19. A performance test shows one process repeatedly yielding and spinning while the other executes a long critical section. What is the most accurate interpretation?

📖 Explanation: Peterson's algorithm uses a loop to repeatedly check shared state while waiting for permission. This can enforce mutual exclusion under the assumed model, but it consumes processor cycles during the wait. For long critical sections or many contenders, blocking synchronization may be more efficient.

📖 Explanation: Intent flags should initially indicate that neither process is requesting entry. If both are initialized as true, each process begins as though the other has an active request. The turn variable may allow one to enter, but incorrect initialization can introduce unnecessary waiting and invalidates the intended startup assumptions.

Q21. A developer wants to replace the shared turn variable with two independent local variables, one per process, while keeping the same entry conditions. What is the main flaw?

💡 Difficulty: hard | ✅ Correct: D

📖 Explanation: The turn variable is shared state that lets the processes resolve simultaneous intent by yielding priority to one another. Independent local copies cannot communicate which process should defer. Without a shared coordination mechanism, the original mutual-exclusion reasoning no longer applies.

📖 Explanation: Peterson's bounded-waiting property concerns how many times another process can enter before a waiting request is granted.
