What is Monitors Usage in Process synchronization?

Definition:
Monitor usage involves defining shared data within the monitor and providing procedures to access it. Processes invoke these procedures to perform operations. The monitor ensures that only one process is active inside at any time, using condition variables to handle situations where a process must wait for a specific state.

Working:
Define a monitor with private data. Implement entry procedures. Use `x.wait()` to block if a condition is false. Use `x.signal()` to wake a blocked process when the condition becomes true. The monitor handles locking and unlocking automatically around procedure calls.

Example:
Monitor `BankAccount` has balance. Procedure `withdraw(amount)` checks if balance >= amount. If not, it waits on `insufficientFunds`. Procedure `deposit(amount)` adds to balance and signals `insufficientFunds` if any waiters exist. This ensures safe transactions.

Reason:
This usage pattern simplifies code by hiding synchronization details. It prevents race conditions on shared data by enforcing mutual exclusion. It also makes the code more readable and maintainable compared to manual semaphore management.

Common MisConceptions:
A common error is thinking that signal() continues execution immediately. In many implementations, the signaler exits or waits, allowing the signaled process to run. Also, students may forget that condition variables must be associated with a specific condition.

Exam Preparation Tips: How to prepare this topic
Practice writing monitor code for classical problems. Understand the difference between Hoare and Mesa semantics for signal(). Focus on how condition variables are used to coordinate processes. Identify the critical sections within monitor procedures.

Key Terms:

  • Entry Procedure - method invoked to access monitor data.
  • Private Data - data accessible only within the monitor.
  • Hoare Semantics - signaler waits, signaled runs immediately.

Q1. A producer-consumer application uses a monitor to manage a bounded queue. A consumer discovers that the queue is empty. What should it do to avoid busy-waiting while still allowing producers to make progress?

A.Keep the monitor lock and repeatedly inspect the queue
B.Return a fabricated item to avoid blocking
C.Wait on an appropriate condition variable, atomically releasing the monitor lock while blocked ✅
D.Disable the producer threads until the consumer resumes
💡 Difficulty: medium | ✅ Correct: C

📖 Explanation: A condition wait allows the consumer to sleep instead of repeatedly checking the queue. Correct monitor waiting releases the lock while blocked and reacquires it before returning, enabling producers to enter the monitor and insert data.

Q2. A monitor manages a resource pool. Its available count is initially 3. Two threads each acquire one resource, and a third thread requests two resources atomically. If the first two resources remain allocated, what should the third thread do?

A.Wait until at least two resources are available before atomically claiming them ✅
B.Claim one resource immediately and wait while holding it for the second
C.Change the available count to two because the request is valid
D.Proceed because the initial count was greater than the request
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: After two acquisitions, only one resource remains available. The third thread cannot satisfy a two-resource request, so it should wait without partially reserving resources if the operation is intended to be atomic, then recheck availability when notified.

Q3. A monitor has a condition variable named spaceAvailable. A producer checks whether a buffer is full using an if statement and waits if it is full. After being signaled, the producer inserts an item without rechecking. Under Mesa-style semantics, what is the defect?

A.A producer can never wait on a condition variable
B.Another producer may fill the available slot before the awakened producer resumes ✅
C.The signal permanently reserves one buffer slot for the producer
D.Mesa-style semantics require every condition variable to be replaced with a semaphore
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: Under Mesa-style semantics, signaling does not immediately transfer the monitor to the waiting producer or reserve a slot. Another producer may enter first and fill the buffer, so the awakened producer must recheck the full condition in a while loop.

Q4. A file-processing service uses a monitor to protect a shared job queue. One monitor method removes a job and then performs a slow network upload before returning. Other threads cannot enqueue jobs during the upload. What is the best improvement?

A.Keep the monitor locked for an even longer interval to prevent queue changes
B.Remove synchronization from every queue operation
C.Remove or reserve the job under the monitor, release the lock, and perform the slow upload outside the critical section when safe ✅
D.Allow every thread to remove the same job concurrently
💡 Difficulty: medium | ✅ Correct: C

📖 Explanation: Queue consistency may require a short protected operation to remove or reserve a job, but the network upload does not necessarily need the monitor lock. Performing slow external work outside the critical section improves concurrency while preserving a clear job-ownership policy.

Q5. A monitor uses a condition variable to wait until a task queue is nonempty. The code checks the queue under the monitor lock, releases the lock, and only then registers the thread as waiting. A producer may insert and signal during this gap. What can occur?

A.The queue becomes permanently empty
B.The producer is prevented from inserting any tasks
C.The monitor automatically records the signal for future waiters
D.A lost wake-up can leave the consumer asleep even though the queue contains a task ✅
💡 Difficulty: medium | ✅ Correct: D

📖 Explanation: If the consumer releases the lock before atomically registering its wait, a producer can insert a task and signal when no waiter is registered. The consumer may then sleep despite the condition being true; correct condition waiting closes this gap.

Q6. A monitor contains methods deposit(amount) and withdraw(amount). The withdraw method waits while the balance is insufficient. A deposit makes the balance sufficient and signals the waiting condition. Why must withdraw still recheck the balance after waking?

A.The balance may have changed again before the withdrawing thread reacquires the monitor ✅
B.A condition signal always decreases the balance
C.The monitor lock is permanently released after a signal
D.A waiting thread cannot inspect shared variables after waking
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: Under signal-and-continue semantics, the depositing thread may continue running after signaling. Other withdrawals can change the balance before the waiting thread resumes, so the withdrawing method must verify the predicate again under the monitor lock.

Q7. A monitor-based cache uses one method to check whether an entry exists and a separate method to insert it if absent. Two threads call these methods in sequence. Both initially observe that the entry is absent. What is the best correction?

A.Keep the methods separate because monitor calls cannot interleave
B.Create one monitor operation that checks and inserts atomically, or otherwise coordinates the complete check-then-act sequence ✅
C.Remove the monitor because the cache is shared
D.Allow duplicate entries and overwrite the cache without checking
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: Each monitor method may be mutually exclusive individually, but another thread can run between two separate calls. Combining the check and insertion into one protected operation prevents both threads from acting on the same stale observation.

Q8. A monitor controls access to a shared configuration object. A thread reads several fields through separate monitor calls, while another thread updates all fields in a single call. The reader observes a mixture of old and new values. Why can this happen?

A.The reader's separate calls may be interleaved with the update, so each read is safe individually but the overall snapshot is not atomic ✅
B.Monitor methods never protect fields
C.The update must have been executed simultaneously by two threads
D.A configuration object cannot be protected by a monitor
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: A monitor normally provides mutual exclusion for each method invocation, not necessarily for a sequence of separate calls. The writer may update the configuration between the reader's calls, so a single snapshot method or versioning strategy may be required.

Q9. A monitor uses a while loop to wait for available storage space. After waking, a thread reacquires the monitor and finds that space is still unavailable. What is the correct next action?

A.Proceed because the thread has already been signaled once
B.Set the available-space count to one
C.Return to waiting while the predicate remains false ✅
D.Disable the condition variable permanently
💡 Difficulty: medium | ✅ Correct: C

📖 Explanation: The loop ensures that the operation proceeds only when the shared-state condition is true. If another thread has consumed the available space, the awakened thread must wait again rather than assuming the earlier signal guarantees availability.

Q10. A monitor uses two condition variables: itemAvailable for consumers and spaceAvailable for producers. A consumer removes an item from a full buffer, making one slot available. Which action most directly helps a blocked producer progress?

A.Signal itemAvailable because a removed item is new data
B.Signal spaceAvailable after the state update ✅
C.Signal neither variable because condition variables store their own state
D.Increase the buffer capacity to its maximum possible integer value
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: Removing an item from a full buffer creates a free slot, potentially satisfying a producer's waiting predicate. Signaling spaceAvailable after updating the buffer allows a producer to wake and recheck whether capacity remains.

Q11. A monitor's resource-release method updates the available-resource count but fails to signal any waiting thread. The count becomes positive, yet all waiters remain blocked. Which diagnosis is most appropriate?

A.The state change may not wake blocked threads, causing a missed-notification or progress problem ✅
B.The monitor must have violated mutual exclusion by updating the count
C.A positive resource count means every waiter executes immediately
D.Condition variables automatically wake all waiters whenever any shared variable changes
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: Changing a shared variable does not automatically wake threads waiting on a condition variable. If release makes a waiting predicate true but no notification occurs, blocked threads may remain asleep until some unrelated event causes them to resume.

Q12. A monitor procedure acquires a non-reentrant lock and invokes another procedure that attempts to acquire the same lock. The first procedure has not released it. What is the most likely outcome?

A.The second procedure runs concurrently because both belong to the same monitor
B.The lock converts automatically into a semaphore with two permits
C.The thread can block waiting for a lock it already owns, causing self-deadlock ✅
D.The first procedure immediately loses ownership of the lock
💡 Difficulty: medium | ✅ Correct: C

📖 Explanation: A non-reentrant lock cannot be acquired again by its current owner. Nested acquisition therefore blocks the thread on its own lock unless the design avoids re-acquisition or uses an appropriate reentrant mechanism.

Q13. A monitor-based service wakes the oldest waiting thread first, but does not reserve the resource for that thread. New requests frequently acquire the resource before the awakened thread resumes. Which conclusion is correct?

A.Oldest-first wake-up always guarantees bounded waiting
B.The service can preserve wake-up order yet still fail to guarantee fair resource allocation ✅
C.The resource must be available to all waiting threads simultaneously
D.The monitor has no mutual-exclusion mechanism
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: Choosing the oldest waiter for notification does not necessarily grant it immediate ownership. If newcomers can claim the resource first, an awakened thread may repeatedly lose the race; stronger queue-based admission may be required for fairness.

Q14. A monitor provides a method that reads a shared balance without acquiring the monitor lock, while all writes occur through protected methods. Which problem is possible?

A.The balance becomes constant after the first write
B.All reads automatically block until every thread terminates
C.The monitor guarantees a consistent read because writes are protected
D.A read can race with a write and observe an inconsistent or stale value because the reader bypasses the synchronization protocol ✅
💡 Difficulty: medium | ✅ Correct: D

📖 Explanation: Protecting writes alone does not coordinate them with unsynchronized readers. A read may overlap a write or lack the required visibility guarantees, so reads and writes of shared state should follow a consistent locking or atomic-access discipline.

Q15. A monitor-based work queue has five waiting consumers and one newly inserted job. The producer broadcasts to all consumers. Which result is correct if the queue stores only one job?

A.All five consumers can remove the same job because they woke together
B.At most one consumer can successfully claim the job; the others must recheck and wait if the queue becomes empty ✅
C.The queue must automatically duplicate the job for each waiter
D.The producer has violated mutual exclusion by broadcasting
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: A broadcast changes waiter eligibility, not the number of jobs in the queue. The monitor lock and correct predicate checks ensure that one consumer removes the job, while other consumers discover that no item remains and return to waiting.

Q16. A monitor method updates a shared state and then raises an exception before releasing its lock. Other threads need the monitor to continue processing. What programming practice best prevents this failure?

A.Use guaranteed cleanup, such as a finally-style mechanism or scoped lock management, to release the lock on every exit path ✅
B.Catch the exception only after the program terminates
C.Allow the lock to remain held because the state has changed
D.Remove all error handling from monitor methods
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: Exceptions can bypass ordinary release statements and leave a monitor permanently locked. Guaranteed cleanup mechanisms release the lock on normal and exceptional exits, preserving the monitor's availability even when an operation fails.

Q17. A monitor's method checks whether a task is pending, marks it as running, and then starts an external worker. The worker may fail to start. Which design concern is most important?

A.A monitor must never store task states
B.A failed worker automatically resets all shared state
C.The implementation needs a defined rollback or failure-state transition so the task is not left permanently marked as running ✅
D.The task should be marked completed before the worker starts
💡 Difficulty: medium | ✅ Correct: C

📖 Explanation: If the worker fails after the task is marked as running, the shared state may no longer reflect reality and future callers may believe work is active forever. A defined failure path should restore or transition the state safely.

Q18. A monitor protects a shared counter and exposes a method to increment it by a supplied amount. One caller passes a negative amount when only positive increments are valid. Which responsibility remains necessary even with correct monitor synchronization?

A.Mutual exclusion automatically validates every argument
B.The monitor should validate the argument and reject values outside the operation's contract ✅
C.A negative amount cannot change a counter
D.The operating system will reject the call before entering the monitor
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: Synchronization prevents conflicting interleavings but does not establish that an operation's input is valid. The monitor must enforce its semantic rules, including rejecting negative increments if the method contract requires a positive amount.

Q19. A monitor uses a condition variable to wait until two resources are available. A release operation makes only one resource available and signals the condition variable. What should a woken thread do?

A.Acquire both resources because the signal represents the full request
B.Change the resource count to two to complete the request
C.Proceed with the operation even though one resource is missing
D.Recheck whether the full two-resource predicate is satisfied and continue waiting if it is not ✅
💡 Difficulty: medium | ✅ Correct: D

📖 Explanation: The waiting condition represents availability of two resources, not merely a change in the resource count. A single release may be insufficient, so the awakened thread must recheck the full predicate before acquiring resources or proceeding.

Q20. A monitor protects a shared task queue. The producer inserts a task and signals one consumer. A second task is then inserted before the first consumer resumes. Only one signal was sent. What can be inferred?

A.Both tasks must be lost because only one signal was sent
B.The queue may safely contain both tasks, but another waiting consumer might remain asleep until another notification or a later state change ✅
C.The first consumer is guaranteed to remove both tasks
D.The signal count automatically becomes two when two tasks are present
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: The queue's correctness depends on protected insertion and removal, while notifications control when blocked consumers reconsider their conditions. One signal may wake only one waiter, so an additional waiter could remain asleep despite another queued task unless the design sends sufficient notifications or uses broadcast.

Q21. A monitor has a method that waits for a condition and then calls a second method that assumes the condition is true. The second method is callable by other threads independently. What is the safest design approach?

A.Make the precondition explicit and enforce it within the operation that relies on it, or restrict access so callers cannot bypass the required protocol ✅
B.Assume every caller has already waited correctly
C.Remove the condition check because methods execute inside a monitor
D.Allow the second method to execute without acquiring the monitor
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: A monitor serializes method execution but does not automatically guarantee that callers follow a required multi-method sequence. Enforcing the precondition within the operation, or encapsulating the sequence, prevents callers from invoking it in an invalid state.

Q22. A monitor manages a pool of three connections. Two threads each acquire one connection. A third thread requests two connections and waits without acquiring either. Why can this design be preferable to acquiring one connection and waiting for the second?

A.It guarantees that no thread ever waits
B.It makes the pool capacity irrelevant
C.It avoids partial resource ownership by the third thread, reducing hold-and-wait risks while preserving the all-or-nothing request ✅
D.It allows the third thread to use a connection already owned by another thread
💡 Difficulty: medium | ✅ Correct: C

📖 Explanation: The two allocated connections leave only one free, which is insufficient for the third thread's two-connection request. Waiting without acquiring a partial allocation avoids holding one resource while waiting for another, a pattern that can contribute to deadlock.

Q23. A monitor implementation has a method that checks whether a resource is free and then returns a Boolean result. The caller later invokes another method to acquire the resource. Why is this API potentially unsafe?

A.Returning a Boolean always reserves the resource for the caller
B.The resource can be acquired by another thread between the check and the later acquisition, so the API exposes a check-then-act race ✅
C.A Boolean cannot represent resource availability
D.The monitor must be converted into a condition variable
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: The availability result is only a snapshot at the time of the first call. Another thread can acquire the resource before the caller invokes the second method, so checking and claiming should be combined into one atomic monitor operation.

Q24. A monitor signals a waiter after a state update. The waiter wakes and reacquires the monitor, but another thread changes the state before the waiter can run its protected operation. What does this demonstrate?

A.A condition-variable signal does not guarantee that the predicate remains true until the waiter acts ✅
B.The monitor lock failed because a signal was sent
C.The state must be immutable whenever a condition variable exists
D.A waiter can safely ignore the current state after being signaled
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: The monitor lock protects state only while a thread holds it. After signaling, the current owner may continue and later threads may change the state before the waiter reacquires the lock, which is why predicate checks must be repeated.

Q25. A team observes that a monitor-based service never corrupts its shared data but sometimes leaves one client waiting indefinitely while other clients continue receiving service. Which conclusion best distinguishes safety from liveness?

A.The service has violated mutual exclusion because waiting is possible
B.The service must be deadlocked because any delay proves no progress
C.The service has guaranteed fairness because data corruption never occurs
D.Safety may hold while liveness or fairness fails, so starvation and scheduling behavior must be investigated separately ✅
💡 Difficulty: medium | ✅ Correct: D

📖 Explanation: Safety concerns whether forbidden states or data corruption occur, while liveness concerns whether operations eventually progress. A monitor can protect shared data correctly yet still permit starvation if its admission or scheduling policy repeatedly favors other clients.

Q26. A monitor method removes a job from a queue and records its identifier in a processing set. The queue removal succeeds, but recording the identifier can fail. What is the best consistency requirement?

📖 Explanation: The queue and processing set represent related parts of one logical state transition. If the job is removed but not recorded, it may become unreachable to the service; atomic updates or a recovery mechanism must preserve the invariant across failures.

💡 Difficulty: medium | ✅ Correct: C

📖 Explanation: The signal should notify waiters after the shared state has been updated to reflect the released resource. Otherwise, a waiter may wake, observe the old unavailable state, and return to waiting before the count is increased.

📖 Explanation: The wait operation allows other threads to enter the monitor and modify shared state while the caller is blocked. After reacquiring the lock, the caller must use current values rather than relying on data read before waiting.

📖 Explanation: Monitor mutual exclusion normally protects individual method invocations, not a sequence of calls separated by lock releases. Other threads can modify the list between iterations, so the application may need a single protected operation or a stable snapshot.

📖 Explanation: Even when one waiter is signaled, another thread may alter the queue before that waiter reacquires the monitor, depending on the implementation and scheduling. Rechecking the predicate makes the operation robust against these interleavings.

📖 Explanation: A global monitor can serialize operations that do not conflict, limiting throughput. Finer-grained protection allows independent accounts to proceed concurrently, but transactions involving multiple accounts need a consistent lock-ordering policy to avoid introducing deadlocks.

Q32. A monitor-based task scheduler wakes all workers whenever a single task arrives. The queue contains one task, and every worker checks the queue under the monitor lock. Which trade-off is most likely?

📖 Explanation: The monitor prevents multiple workers from removing the same task, but a broadcast wakes more threads than the available work requires. The resulting competition can increase scheduling overhead; signaling one waiter may be more efficient when one task becomes available.

💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: Holding a scarce resource or monitor lock while waiting for external work can create circular dependencies across threads and services. Releasing resources when the operation's invariants permit, then reacquiring and revalidating state, reduces deadlock risk.

📖 Explanation: A single arbitrary signal may select a waiter whose threshold is not satisfied, while leaving an eligible waiter asleep. Separate condition variables for distinct predicates or a carefully chosen broadcast can prevent this mismatch from delaying progress.

📖 Explanation: Without following the monitor's locking discipline, the logging thread may read one field before a protected update and another afterward. The resulting combination may never have represented a valid state; a synchronized snapshot or suitable versioning is needed.
