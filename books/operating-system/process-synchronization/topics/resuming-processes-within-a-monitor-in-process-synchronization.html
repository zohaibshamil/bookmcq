What is Resuming Processes within a Monitor in Process synchronization?

Definition:
Resuming processes within a monitor involves deciding which process runs after a signal() operation. In Hoare semantics, the signaled process runs immediately, and the signaler suspends. In Mesa semantics, the signaler continues, and the signaled process moves to the ready queue, re-checking the condition later.

Working:
In Hoare style, signal() transfers control directly to the waiting process. The signaler must wait. In Mesa style, signal() just wakes the waiter. The waiter must re-evaluate the condition because the state may have changed by the time it runs. Mesa is more common in practice.

Example:
Hoare: P1 signals cond. P1 suspends. P2 (waiter) runs immediately. P2 finishes, P1 resumes. Mesa: P1 signals cond. P1 continues. P2 moves to ready queue. P1 finishes monitor. P2 enters, re-checks condition, and proceeds if true.

Reason:
Hoare semantics are simpler to reason about but harder to implement efficiently. Mesa semantics are more flexible and efficient but require programmers to use loops to re-check conditions (while loops instead of if statements) to handle spurious wakeups or state changes.

Common MisConceptions:
Students often assume signal() guarantees the condition is still true when the waiter runs. In Mesa, it does not. This is why `while` loops are used instead of `if`. Also, they may think Hoare is always better; it is not, due to implementation complexity.

Exam Preparation Tips: How to prepare this topic
Know the difference between Hoare and Mesa. Understand why Mesa requires re-checking conditions. Be able to explain the trade-offs. Practice writing monitor code with while loops for condition checks to accommodate Mesa semantics.

Key Terms:

  • Hoare Semantics - signaled process runs immediately.
  • Mesa Semantics - signaled process goes to ready queue.
  • Spurious Wakeup - process wakes but condition is false.

📝 All Resuming Processes within a Monitor in Process synchronization MCQs

Q1. A monitor's condition wait returns after notification, but the caller assumes it owns the monitor lock because the wait function returned. The implementation actually returns before reacquisition finishes. What is the required fix?

A.Remove the entry semaphore from all procedures
B.Allow the caller to access shared state while reacquisition occurs
C.Replace every condition with a global Boolean
D.Ensure the wait operation does not return control to protected code until monitor access has been reacquired ✅
💡 Difficulty: easy | ✅ Correct: D

📖 Explanation: The contract of a monitor wait must ensure that protected code resumes only after the caller has reacquired exclusive monitor access. Returning earlier exposes shared state to races because the caller may execute concurrently with another thread inside the monitor.

Q2. A process is signaled from condition c and reacquires the monitor. It finds the predicate true, but another operation it must perform requires condition d, which is false. Which approach best preserves correctness?

A.Ignore d because c was signaled first
B.Perform the operation anyway and repair the state later
C.Check the additional prerequisite and wait on d using the correct monitor wait protocol if it is not satisfied ✅
D.Signal c again until d becomes true
💡 Difficulty: easy | ✅ Correct: C

📖 Explanation: A process may need several prerequisites to perform a safe operation. Satisfaction of one condition does not imply that every other requirement holds, so the process must check each relevant predicate under monitor protection and wait on the appropriate condition when necessary.

Q3. A performance trace shows that a signal-and-wait monitor repeatedly transfers control between a signaler and a waiter, while a signal-and-continue design has fewer immediate handoffs but more predicate rechecks. What is the most defensible conclusion?

A.Signal-and-wait is always superior because it uses more handoffs
B.The preferred policy depends on workload, correctness requirements, and the relative costs of handoffs, lock contention, and rechecking ✅
C.Signal-and-continue is always superior because fewer handoffs guarantee better throughput
D.The traces prove that condition variables are unnecessary
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: The two policies trade off control-transfer overhead against the ordering and reasoning benefits of immediate handoff. Performance depends on how often waiters can proceed, how expensive handoffs are, and how much additional contention or predicate rechecking occurs.

Q4. Under Hoare signal-and-wait semantics, what happens to the signaler?

A.It keeps running and changes state
B.It terminates immediately
C.It is suspended until the resumed waiter leaves the monitor ✅
D.It releases the lock to all waiters
💡 Difficulty: hard | ✅ Correct: C

📖 Explanation: With signal-and-wait, the monitor passes directly to the resumed waiter, and the signaler waits on the urgent queue until that waiter exits.

Q5. What does signal-and-continue allow the signaling thread to do?

A.Hand the monitor directly to the waiter
B.Exit the program
C.Skip the monitor lock
D.Keep executing inside the monitor after signaling ✅
💡 Difficulty: medium | ✅ Correct: D

📖 Explanation: Under signal-and-continue, the signaler retains the monitor and keeps running. The waiter resumes only after the signaler leaves or releases the lock.

Q6. A thread resumes from wait but the condition it needs is false. What should it do?

A.Proceed because it was signaled
B.Wait again, since another thread may have consumed the condition ✅
C.Release the mutex permanently
D.Terminate the process
💡 Difficulty: easy | ✅ Correct: B

📖 Explanation: A notification does not guarantee the predicate still holds. The thread should return to waiting and let a later signal reflect the true state.

Q7. Why is a signal not stored in a condition variable?

A.Signals are queued forever
B.Signals reserve resources
C.A signal with no waiter has no lasting effect ✅
D.Signals stop the scheduler
💡 Difficulty: medium | ✅ Correct: C

📖 Explanation: Condition variables are not counters. A signal sent when no thread waits is lost, so waiters must check the shared state rather than rely on past signals.

Q8. What does broadcast on a condition variable do?

A.Wakes exactly one thread in priority order
B.Disables the monitor
C.Creates a new condition variable
D.Wakes all threads waiting on that condition variable ✅
💡 Difficulty: easy | ✅ Correct: D

📖 Explanation: Broadcast makes every thread waiting on the condition eligible to run. Each must still reacquire the lock and recheck its predicate.

Q9. When should broadcast be used instead of signal?

A.When several waiters may all be able to proceed ✅
B.When exactly one resource unit appears
C.Whenever a lock is released
D.Never in monitors
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: Broadcast suits cases where a state change may enable many waiters at once. Signal is preferable when only one waiter can use the change.

Q10. What is a lost wakeup?

A.A signal is delivered twice
B.A signal occurs before the waiter registers, so it sleeps despite the condition being true ✅
C.A thread never sleeps
D.A lock is released early
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: If notification happens between a check and the start of waiting, the waiter may sleep forever. Atomic release-and-wait prevents this window.

Q11. Why must wait atomically release the monitor lock?

A.To increase CPU speed
B.To prevent condition variables from existing
C.So other threads can enter and change the predicate the waiter needs ✅
D.To make signals persistent
💡 Difficulty: medium | ✅ Correct: C

📖 Explanation: If the waiter kept the lock, no other thread could enter the monitor to satisfy the condition, so the waiter would block indefinitely.

Q12. Which statement about Mesa semantics is correct?

A.A signal transfers ownership of the resource
B.Signals always run the waiter immediately
C.Mesa monitors have no condition variables
D.A signal only makes a waiter eligible; the waiter must recheck ✅
💡 Difficulty: hard | ✅ Correct: D

📖 Explanation: Under Mesa semantics the signaled thread competes again for the lock and the state, so the predicate must be rechecked before proceeding.

Q13. A monitor protects a bounded buffer. A consumer waits while count equals zero. After being signaled, it reacquires the monitor and discovers that another consumer has removed the only item. Which implementation is correct?

A.Allow the consumer to proceed because notification guarantees one item was reserved
B.Check the predicate once before waiting and never check it again
C.Recheck count inside a while loop and wait again if count equals zero ✅
D.Replace the condition variable with a Boolean that remains true after the first signal
💡 Difficulty: hard | ✅ Correct: C

📖 Explanation: Under signal-and-continue semantics, a notification does not reserve an item for the awakened consumer. Another consumer may acquire the monitor first and change the buffer state. A while loop ensures the consumer proceeds only when the predicate is true while holding the monitor lock.

Q14. A monitor uses Hoare signal-and-wait semantics. Thread A signals thread B, which is waiting for condition c. Which execution order best describes the immediate transfer of control?

A.A continues modifying shared state while B waits for the monitor to become free
B.B immediately executes inside the monitor, while A waits on the urgent queue ✅
C.Both threads execute monitor code simultaneously until B finishes
D.A releases the monitor permanently, allowing every waiting thread to enter
💡 Difficulty: hard | ✅ Correct: B

📖 Explanation: Under classical Hoare semantics, signaling transfers monitor control directly to the selected waiter. The signaler is suspended on an urgent queue and can resume after the awakened thread relinquishes monitor control, preserving the intended immediate-handoff semantics.

Q15. A developer changes a monitor from signal-and-wait to signal-and-continue but leaves every if-based condition check unchanged. Tests now occasionally fail when several consumers compete for one item. What is the best diagnosis?

A.Signal-and-continue makes every condition variable permanently true
B.The monitor lock is no longer needed after notification
C.The compiler must automatically convert each condition variable into a semaphore
D.The code incorrectly assumes notification guarantees that the waiting thread's predicate remains true ✅
💡 Difficulty: hard | ✅ Correct: D

📖 Explanation: Signal-and-continue allows the signaling thread to continue executing before the waiter reacquires the monitor. Other threads may consume or invalidate the resource first. Replacing if checks with while loops makes the predicate validation robust against these intervening state changes.

Q16. A monitor has three waiting threads: one requires count greater than zero, another requires count below capacity, and a third requires shutdown to be true. A state update makes only shutdown true. Which design most directly avoids unnecessary wakeups?

A.Signal the shutdown condition variable after updating shutdown under the monitor lock ✅
B.Broadcast every condition variable after every state change, regardless of its effect
C.Signal the count-greater-than-zero condition because all waiters share the same monitor
D.Wake the thread that has waited longest, without checking its predicate
💡 Difficulty: hard | ✅ Correct: A

📖 Explanation: Separate condition variables allow notifications to target threads waiting for predicates affected by a particular state transition. Updating shutdown under the monitor lock and signaling its associated condition avoids needlessly waking consumers or producers whose requirements remain unsatisfied.

Q17. A thread checks that a queue is empty while holding a monitor lock. It then releases the lock and only afterward registers itself as waiting. A producer inserts an item and signals during this interval. What is the principal defect?

A.The producer necessarily violates mutual exclusion by inserting an item
B.The signal is stored indefinitely, causing duplicate item consumption
C.The consumer can miss the notification and block even though an item is available ✅
D.The queue becomes full because releasing the lock duplicates its contents
💡 Difficulty: hard | ✅ Correct: C

📖 Explanation: The check, release, and registration sequence contains a lost-wakeup window. A producer can change the predicate and signal before the consumer becomes a registered waiter. A correct condition-wait operation atomically releases the monitor lock and blocks, preventing this race.

Q18. A timed condition wait expires while the desired predicate is still false. The thread returns with the monitor lock reacquired. What should the thread do if the operation is no longer worth waiting for?

A.Assume timeout means the predicate became true briefly
B.Inspect the timeout result and predicate under the lock, then leave or retry according to the operation's policy ✅
C.Continue accessing the resource without checking its state
D.Send a signal to itself and treat the resource as available
💡 Difficulty: hard | ✅ Correct: B

📖 Explanation: A timeout reports that the waiting interval expired, not that the desired state was achieved. Because the monitor lock has been reacquired, the thread can safely inspect shared state and decide whether to abandon the request, retry, or continue if its predicate is satisfied.

Q19. A monitor broadcasts to eight consumers after inserting one item. All eight wake, but only one can remove the item. Which consequence should the designer expect under signal-and-continue semantics?

A.Every consumer obtains a private copy of the item
B.Broadcast automatically transfers the monitor lock to all eight consumers simultaneously
C.The remaining consumers can proceed without testing the queue again
D.The consumers compete to reacquire the monitor, and those finding the queue empty must wait again ✅
💡 Difficulty: hard | ✅ Correct: D

📖 Explanation: Broadcast makes all current waiters eligible to resume but does not create additional resources or grant simultaneous monitor ownership. Consumers reacquire the lock separately, and all but a successful consumer may discover that the queue is empty and need to wait again.

Q20. A monitor's signaling operation is called when no thread is waiting on its condition variable. A thread begins waiting later. Which statement correctly describes the earlier signal?

A.It normally has no lasting effect, so the new waiter must rely on the shared-state predicate ✅
B.It is retained as a permit that automatically releases the next waiter
C.It forces the next thread to enter the monitor without acquiring its lock
D.It changes the condition variable's predicate to true permanently
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: Condition variables generally do not retain notifications as counting permits. If no thread is waiting when signal is called, a later waiter does not receive that past signal. Correct monitor designs protect and check the shared-state predicate rather than treating notifications as stored resources.

Q21. A monitor's wait operation returns before the waiting thread has reacquired exclusive access. The thread immediately reads and updates a shared counter. What is the essential correction?

A.Allow all awakened threads to access the counter before the lock is available
B.Require the thread to reacquire monitor ownership before returning to protected code ✅
C.Remove synchronization from counter updates to prevent deadlock
D.Make condition signals persistent so that the counter cannot change
💡 Difficulty: hard | ✅ Correct: B

📖 Explanation: A monitor's mutual-exclusion guarantee applies to all protected operations, including code executed after a condition wait. The wait operation must not return control to protected code until the caller owns the monitor again; otherwise concurrent access can cause races and inconsistent counter values.

Q22. A producer increments a buffer count and signals a consumer while still inside the monitor. Under signal-and-continue semantics, the producer then removes an item before exiting. What must the consumer assume when it eventually resumes?

A.The count must still be positive because signaling reserved the item
B.The producer is prohibited from changing the count after signaling
C.The condition may have become false, so the consumer must recheck the predicate under the lock ✅
D.The signal is automatically canceled if the producer performs another operation
💡 Difficulty: hard | ✅ Correct: C

📖 Explanation: Under signal-and-continue semantics, the producer retains monitor control after signaling and may change the shared state before the consumer runs. The notification does not reserve the item or guarantee the predicate remains true, so the consumer must recheck the predicate under the lock before proceeding.
