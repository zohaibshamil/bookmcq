What is Monitors in Process synchronization?

Definition:
A monitor is a high-level synchronization construct that encapsulates shared data and operations on that data. It ensures mutual exclusion by allowing only one process to execute within the monitor at a time. Monitors provide condition variables for process coordination, simplifying synchronization logic.

Working:
Processes call monitor procedures. Entry is mutually exclusive. If a condition is not met, the process waits on a condition variable, releasing the monitor. Another process can then enter. When the condition is met, a signal wakes a waiting process, which re-acquires the monitor.

Example:
A monitor for a printer has a `print()` procedure. If the printer is busy, the calling process waits on the `busy` condition variable. When the current job finishes, the process signals `busy`, waking the next waiter. Only one process prints at a time.

Reason:
Monitors are easier to use and less error-prone than semaphores because the mutual exclusion is implicit. Programmers don't need to remember to place wait/signal pairs correctly. They provide a structured approach to synchronization, reducing bugs like forgotten signals.

Common MisConceptions:
Students often confuse condition variables with semaphores. Condition variables have no memory; if no one is waiting, a signal is lost. Semaphores retain the signal. Also, monitors do not automatically prevent deadlock; careful design is still required.

Exam Preparation Tips: How to prepare this topic
Understand the structure: shared data, procedures, condition variables. Learn the semantics of wait() and signal() on condition variables. Compare monitors with semaphores. Practice writing simple monitors for problems like bounded buffer.

Key Terms:

  • Monitor - module with mutual exclusion and condition variables.
  • Condition Variable - queue for processes waiting for a condition.
  • Signal - wakes one waiting process on a condition variable.

📝 All Monitors in Process synchronization MCQs

Q1. Two threads call a monitor procedure that increments a shared counter. The procedure reads the counter, adds one, and writes it back. If the monitor guarantees that only one thread executes a monitor procedure at a time, what is the principal benefit?

A.The counter becomes a separate copy for every thread
B.The read-modify-write sequence is protected from concurrent execution by other monitor procedures ✅
C.The operating system no longer needs to schedule threads
D.The counter can be incremented without accessing shared memory
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: Mutual exclusion inside the monitor prevents two threads from interleaving their counter updates. This protects the complete read-modify-write sequence from lost updates, although it does not automatically protect accesses that bypass the monitor.

Q2. A thread enters a monitor and discovers that a required resource is unavailable. It waits on a condition variable. Under Mesa-style semantics, what should the thread do after it is awakened and reacquires the monitor lock?

A.Assume the resource is available because a signal was received
B.Return immediately without checking the shared state
C.Recheck the condition in a loop before proceeding ✅
D.Release the monitor permanently
💡 Difficulty: medium | ✅ Correct: C

📖 Explanation: Under Mesa-style semantics, signaling makes a waiting thread eligible to run but does not transfer immediate control or reserve the resource for it. Another thread may change the state first, so the condition must be checked again in a loop.

Q3. A monitor contains a shared buffer and a condition variable notEmpty. A consumer executes if bufferIsEmpty then wait(notEmpty). A producer can insert an item and signal notEmpty. What is the main defect in using this single if check under Mesa-style semantics?

A.The consumer may wake after another consumer has removed the item and proceed without rechecking that the buffer is nonempty ✅
B.The producer cannot modify a buffer protected by a monitor
C.Condition variables automatically prevent multiple consumers from waking
D.The consumer will always hold the monitor lock while asleep
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: A wake-up does not guarantee that the buffer remains nonempty when the consumer resumes. Another consumer may take the item first, so an if statement can permit an invalid removal; a while loop safely rechecks the condition.

Q4. Two procedures in a monitor update the same inventory count. Each procedure is individually correct, but one programmer moves the count update into an external helper that can be called without acquiring the monitor. What is the key risk?

A.The monitor will automatically serialize every call to the external helper
B.The inventory count becomes immutable
C.The helper must execute only after the program terminates
D.Concurrent callers may bypass the monitor's mutual-exclusion protection and race on the shared count ✅
💡 Difficulty: medium | ✅ Correct: D

📖 Explanation: Monitor guarantees apply to operations performed under its synchronization discipline. If an external helper accesses shared state without acquiring the monitor, its updates can interleave with protected procedures and invalidate the monitor's safety guarantees.

Q5. A monitor procedure checks whether a bank account has sufficient funds, then subtracts the requested amount. The check and subtraction occur within one monitor call. Why is this safer than performing them in separate unsynchronized operations?

A.It ensures that the balance cannot change through another monitor procedure between the check and the subtraction ✅
B.It guarantees that every withdrawal will succeed regardless of the balance
C.It removes the need to validate the requested amount
D.It makes all bank transactions execute simultaneously
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: The check and subtraction form one protected operation, so another monitor procedure cannot interleave a conflicting balance update between them. This prevents a classic check-then-act race, although other validation rules are still required.

Q6. A thread signals a condition variable when a resource becomes available. No threads are waiting at that moment. Later, another thread begins waiting on the same condition variable. Which statement is generally correct for ordinary condition variables?

A.The earlier signal remains stored until a waiter arrives
B.The later waiter is guaranteed to receive the earlier signal
C.The earlier signal is not remembered, so the later thread must check the shared predicate before waiting ✅
D.The monitor becomes permanently unavailable after signaling without waiters
💡 Difficulty: medium | ✅ Correct: C

📖 Explanation: Condition variables typically do not store signals as persistent resource tokens. A thread must test the shared-state predicate while holding the monitor lock and wait only if the condition is false, preventing missed-state assumptions.

Q7. A monitor uses a condition variable hasSpace. A producer checks the buffer state while holding the monitor lock, then calls wait(hasSpace), which atomically releases the lock and blocks. Why is the atomic release-and-wait transition important?

A.It prevents producers from ever needing to reacquire the monitor
B.It allows the producer to insert an item while asleep
C.It guarantees that the buffer will remain nonempty
D.It prevents a race in which a state change and signal occur between releasing the lock and actually becoming a waiter ✅
💡 Difficulty: medium | ✅ Correct: D

📖 Explanation: If a producer released the monitor lock before registering as a waiter, a consumer could create space and signal during that gap. The producer might then sleep despite space being available; atomic release-and-wait avoids this lost-wakeup race.

Q8. A monitor implements a queue using a condition variable. Three threads are waiting. One thread changes the queue state and calls signal once. What can safely be concluded without assuming a specific condition-variable scheduling policy?

A.Exactly three threads will resume immediately
B.At most one waiting thread is selected by that signal, while the others may remain waiting until further notifications or state changes ✅
C.All waiting threads must enter the monitor simultaneously
D.The signal guarantees that the selected thread can perform its operation without checking the queue state
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: A single signal normally wakes or makes eligible one waiter, not every waiting thread. The selected thread must still verify its predicate, and other waiters may need additional signals or broadcasts as the shared state changes.

Q9. A thread waits on condition variable dataReady. Another thread inserts data and signals dataReady, but then immediately removes the data before the waiting thread resumes. Under Mesa-style semantics, what should the waiting thread do?

A.Proceed because the signal permanently reserves the inserted data
B.Assume the data was never inserted
C.Recheck the predicate and wait again if the data is no longer available ✅
D.Exit the monitor without examining the buffer
💡 Difficulty: medium | ✅ Correct: C

📖 Explanation: Mesa-style signaling does not hand the monitor directly to the waiter or reserve the resource. The signaling thread may continue and alter the state before the waiter runs, so the waiter must recheck the predicate.

Q10. A monitor guarantees that only one thread executes inside it, but a thread calls wait(condition) while holding the monitor lock. The wait implementation blocks without releasing the lock. What is the likely result if another thread must enter the monitor to make the condition true?

A.The waiting thread will be awakened automatically after a fixed timeout
B.The condition will become true because the lock is held
C.The monitor will permit the other thread to enter concurrently
D.The system may deadlock because the waiter retains the lock needed by the thread that could satisfy its condition ✅
💡 Difficulty: medium | ✅ Correct: D

📖 Explanation: A correct condition wait must release the monitor lock while the thread is blocked and reacquire it before returning. If the waiter retains the lock, the producer or other thread needed to change the condition cannot enter.

Q11. A program replaces a monitor-protected queue with a thread-safe queue but leaves a separate unsynchronized variable queueCount that is updated after each insertion or removal. What can happen?

A.The queue must stop accepting items because monitors are mandatory for every queue
B.The queue operations may remain safe while queueCount becomes inconsistent due to races ✅
C.The separate counter automatically updates atomically with queue operations
D.The queue becomes deadlock-free and starvation-free by definition
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: A thread-safe queue protects its own internal operations, but a separate counter is not necessarily updated atomically with those operations. Concurrent insertions and removals can cause lost updates or temporary disagreement between the counter and actual queue contents.

Q12. A monitor uses signal-and-continue semantics. Thread A holds the monitor, changes a state, and signals thread B. A then continues executing and changes the state again before exiting. Which design rule best protects B from acting on stale assumptions?

A.Require B to recheck its condition after reacquiring the monitor ✅
B.Assume B executes immediately at the signal statement
C.Allow B to read shared state without reacquiring the monitor
D.Make every signal permanently preserve the signaled state
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: Under signal-and-continue semantics, A continues running after signaling, so B may not resume until A exits the monitor. Because A can change the state again, B must reacquire the lock and recheck the condition before proceeding.

Q13. A monitor protects a shared resource with a Boolean available flag. A waiting thread wakes and immediately sets available to false without checking its value again. Two threads may have been awakened by a broadcast. What is the correct assessment?

A.Broadcast guarantees that only one thread wakes
B.A Boolean flag eliminates all races without locking
C.Both threads can incorrectly assume ownership unless the condition is rechecked and ownership is established under the monitor lock ✅
D.The flag must be replaced with a condition variable that stores every signal
💡 Difficulty: medium | ✅ Correct: C

📖 Explanation: A broadcast can make several waiters eligible to run, but only one may find the resource available. Each thread must check the predicate and claim the resource while holding the monitor lock, preventing multiple threads from claiming one resource.

Q14. A condition variable protects a predicate that becomes true only when two independent events have occurred. A thread wakes after the first event and observes that the predicate is still false. What should happen next?

A.The thread should continue waiting until the complete predicate is satisfied ✅
B.The thread should proceed because any event satisfies a condition variable
C.The thread should signal itself repeatedly until the second event occurs
D.The thread should release the monitor permanently
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: A condition variable is associated with a predicate over shared state, not with a guarantee that a particular event has completed every prerequisite. The thread must continue waiting while the full predicate remains false and recheck it after wake-ups.

Q15. A monitor uses broadcast when a resource becomes available. Ten threads wake, but only one resource unit exists. Which behavior is correct?

A.All ten threads should decrement the resource count because broadcast indicates ten available units
B.Every awakened thread must proceed once it has received a wake-up
C.One eligible thread may claim the unit, while the others must observe the unavailable state and wait again ✅
D.The resource count should be increased to match the number of awakened threads
💡 Difficulty: medium | ✅ Correct: C

📖 Explanation: Broadcast notifies all waiters that the state may have changed; it does not create additional resource units. Threads must compete under the monitor lock, and those that cannot claim the resource should return to waiting.

Q16. A developer uses a monitor to protect a linked list but returns a direct pointer to an internal node. The caller modifies that node after the monitor method returns. Why may the monitor's guarantee be insufficient?

A.The monitor automatically locks every pointer returned to callers
B.External modifications occur outside the monitor's protected execution and may race with other list operations ✅
C.Returning a pointer converts the linked list into a condition variable
D.A monitor cannot contain a linked list
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: The monitor serializes operations performed inside its protected methods, but it cannot automatically control later writes through an exposed pointer. Returning internal mutable state can let callers bypass the synchronization discipline and corrupt the list.

Q17. A thread enters a monitor, detects that a queue is empty, and waits on notEmpty. A producer inserts an item and signals notEmpty while holding the same monitor. Why does the monitor lock matter during this sequence?

A.It prevents the producer from ever changing the queue
B.It makes condition variables unnecessary in every implementation
C.It guarantees that the consumer must run before the producer continues
D.It coordinates state inspection and updates so the consumer can safely recheck the queue after waking ✅
💡 Difficulty: medium | ✅ Correct: D

📖 Explanation: The monitor lock ensures that shared queue state is inspected and modified in a coordinated way. A correct wait atomically releases the lock while blocking, and the awakened consumer reacquires it before checking whether the queue is still nonempty.

Q18. A monitor maintains a count of available machines. A thread checks count greater than zero, waits if it is zero, and decrements the count before using a machine. Why must the check and decrement occur under the same monitor lock?

A.To ensure two threads cannot both observe one available machine and claim it ✅
B.To force the count to remain zero throughout execution
C.To guarantee that machine usage never overlaps in time
D.To avoid using condition variables for all resource waits
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: If the check and decrement are separated by unsynchronized execution, two threads can both observe a count of one and both claim the same machine. Performing them under the monitor lock makes the availability test and reservation atomic relative to other monitor procedures.

Q19. A graph of thread states shows T1 holding monitor M1 while waiting for M2, and T2 holding M2 while waiting for M1. Both monitors use exclusive locks. What does this graph indicate?

A.The threads are guaranteed to finish because they each hold a lock
B.The system has starvation but cannot have deadlock
C.A circular lock dependency can deadlock both threads ✅
D.The monitors have violated mutual exclusion because each lock has one owner
💡 Difficulty: medium | ✅ Correct: C

📖 Explanation: T1 cannot acquire M2 until T2 releases it, and T2 cannot acquire M1 until T1 releases it. This forms a circular wait between exclusive locks, so neither thread can proceed without an external intervention.

Q20. A programmer replaces a while loop around condition waiting with a do-while loop that executes the protected operation once before testing the predicate. The predicate states that the queue must be nonempty before removal. What is the likely error?

A.The loop checks the predicate too often
B.The operation can execute before the required condition has been established, causing an invalid removal from an empty queue ✅
C.A do-while loop automatically makes the monitor reentrant
D.The queue will become full after the first removal
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: The required predicate must be true before the protected operation executes. A do-while loop executes its body first, so it may attempt removal from an empty queue before checking whether data is available.

Q21. A monitor has a condition variable workersAvailable. A manager broadcasts after increasing the worker count from zero to three. Five waiting tasks wake. What should each task do?

A.Assume all five tasks have been allocated workers because a broadcast occurred
B.Decrease the worker count before acquiring the monitor
C.Proceed without checking because the count cannot change after broadcast
D.Recheck the worker count under the monitor lock and claim a worker only if one remains available ✅
💡 Difficulty: medium | ✅ Correct: D

📖 Explanation: The broadcast informs waiting tasks that availability may have changed, but only three workers exist. Each task must recheck and claim a worker under synchronization; later tasks must wait again once the count reaches zero.

Q22. A monitor's condition variable is signaled after a state update, but the signaling thread exits without releasing the monitor because an exception bypasses the unlock operation. What is the most serious likely consequence?

A.The signal is converted into a permanent resource token
B.The waiting thread receives the monitor lock immediately under all semantics
C.The monitor may remain locked, preventing waiting or new threads from entering and potentially causing a deadlock ✅
D.The shared state automatically returns to its previous value
💡 Difficulty: medium | ✅ Correct: C

📖 Explanation: If exception handling fails to release the monitor lock, other threads may be unable to enter the monitor to check conditions or release resources. This can cause system-wide blockage even if the state update and signal were otherwise correct.

Q23. A monitor procedure validates a request, updates a shared account balance, and then writes an audit record to a slow external service while still holding the monitor lock. What is the best design improvement if audit writing does not need to be atomic with the balance update?

A.Keep the lock held longer so all other account operations wait for the audit
B.Remove synchronization from the balance update as well
C.Move the entire balance update outside the monitor
D.Complete the consistent balance update under the monitor, then perform the slow audit operation outside the critical section with appropriate failure handling ✅
💡 Difficulty: medium | ✅ Correct: D

📖 Explanation: The balance validation and update require coordinated access, but a slow audit operation may not need to hold the monitor lock. Separating them reduces contention, while the system must still define how audit failures and consistency requirements are handled.

Q24. A condition variable is associated with the predicate availableUnits greater than zero. A thread wakes and sees availableUnits equal to zero because another thread consumed the final unit. Which response preserves correctness?

A.Wait again while the predicate is false ✅
B.Proceed because the original signal cannot be withdrawn
C.Change availableUnits to one without acquiring the resource
D.Terminate all other waiting threads
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: The resource predicate is currently false, so the awakened thread must not proceed. Re-entering the wait loop while holding the monitor lock preserves correctness and allows the thread to resume when a later state change makes a unit available.

Q25. A monitor's wait method releases the lock and blocks the caller. When awakened, it reacquires the lock before returning. What does reacquiring the lock guarantee, assuming all shared-state accesses use the monitor correctly?

A.The waiting thread is guaranteed to find its condition true
B.The waiting thread can safely inspect shared state without concurrent monitor procedures modifying it during that inspection ✅
C.The thread is guaranteed to run before every other ready thread
D.The resource it was waiting for has been reserved exclusively for it
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: Reacquiring the monitor lock restores the mutual-exclusion discipline, allowing the thread to inspect shared state without another monitor procedure interleaving during that inspection. It does not guarantee the predicate is true or reserve the resource.

Q26. A monitor uses a condition variable and signals one waiter whenever a resource is released. Several different predicates depend on that resource, but the same condition variable is used for all of them. A signaled thread wakes and finds its own predicate false, while another eligible thread remains asleep. What is a possible remedy?

A.Delete all predicate checks because the signal selected a waiter
B.Make every waiting thread ignore the shared resource state
C.Use a single signal only when no threads are waiting
D.Use separate condition variables for distinct predicates or broadcast when necessary, with each waiter rechecking its own condition ✅
💡 Difficulty: medium | ✅ Correct: D

📖 Explanation: If waiters use one condition variable for different predicates, signaling an ineligible waiter can leave an eligible waiter asleep. Separate condition variables can target the appropriate class of waiter, while broadcast can be useful when several predicates may have become true.

Q27. A monitor protects a shared list and offers an operation that returns the list's current length. A caller repeatedly invokes the length operation and later removes that many items through separate calls. Why can the overall sequence still be incorrect despite each operation being individually protected?

A.The length operation automatically locks the monitor for the caller's entire workflow
B.Separate monitor calls may have other operations interleave between them, so the length observed earlier may no longer match the list when removals occur ✅
C.A monitor forbids a method from returning an integer
D.The list length cannot change while any thread exists
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: Mutual exclusion normally applies to one monitor operation at a time, not to an entire sequence of separate calls. Another thread may modify the list between the length query and removals, so a combined atomic operation may be necessary.

Q28. A monitor implements a bounded queue with a while loop around wait(notFull). A reviewer suggests replacing the loop with if because the monitor already provides mutual exclusion. Which response is correct under Mesa-style semantics?

A.The loop remains necessary because the predicate may become false before the awakened thread reacquires the monitor ✅
B.The reviewer is correct because mutual exclusion reserves every resource after signaling
C.The loop should be replaced with an unconditional wait
D.The loop is needed only when more than one producer exists
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: Mutual exclusion prevents simultaneous execution inside the monitor, but it does not reserve a free slot for a particular waiter. Another producer may insert first after a wake-up, so the condition must be checked again before inserting.

Q29. A monitor's internal state includes a counter and a condition variable. The counter is updated correctly, but a signal is issued before the update occurs. Waiting threads wake, reacquire the monitor, and observe the old counter value. What is the main lesson?

A.Condition-variable signals automatically reorder all later operations
B.Signals permanently store the intended counter value
C.The shared-state predicate should be updated consistently before notifying waiters, and waiters must still recheck it ✅
D.A counter should never be modified inside a monitor
💡 Difficulty: medium | ✅ Correct: C

📖 Explanation: A notification should correspond to a meaningful state change that may satisfy a waiter's predicate. Updating the state before signaling makes the intended condition visible to a waiter that later reacquires the lock, though predicate rechecking remains necessary.

Q30. A team compares a monitor with a collection of independent semaphores. The monitor groups shared data and procedures behind one synchronization boundary. What is the strongest practical advantage of this organization?

A.It eliminates the need for correct algorithms and state invariants
B.It guarantees that no thread can ever starve
C.It permits all shared-data operations to occur without locks
D.It centralizes synchronization and encapsulates shared-state access, making it easier to enforce invariants consistently ✅
💡 Difficulty: medium | ✅ Correct: D

📖 Explanation: A monitor packages shared state with the operations that manipulate it, reducing the chance that callers perform unsynchronized updates. This structure improves reasoning about invariants, but correctness and fairness still depend on the procedures and scheduling policy.

Q31. A monitor-based resource pool appears correct in ordinary tests. Under heavy load, threads remain blocked even though the pool sometimes contains free resources. Investigation shows that a release path updates the resource count but never signals or broadcasts the relevant condition variable. What is the likely diagnosis?

A.A possible missed-notification problem leaves eligible waiters asleep despite a state change that could satisfy their predicate ✅
B.The resource count must be negative because the monitor is active
C.Mutual exclusion always prevents resource release
D.The condition variable is storing too many signals
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: When a release changes the predicate from unavailable to available, waiters may need notification so they can recheck the condition. Without signaling, eligible threads can remain asleep indefinitely even though the resource state would allow progress.

Q32. A monitor implementation wakes a waiting thread while continuing to hold the monitor lock. The awakened thread becomes ready but cannot inspect the shared state until the signaling thread exits. Which description best matches this behavior?

A.The awakened thread immediately owns every resource managed by the monitor
B.The notification makes the waiter eligible to resume, but it must wait to reacquire the monitor before examining protected state ✅
C.The signal permanently releases the monitor lock to every waiter
D.The waiter executes concurrently inside the monitor with the signaling thread
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: In signal-and-continue behavior, the signaling thread retains control of the monitor until it exits or releases the lock. The awakened thread becomes eligible to run but must reacquire the lock before safely checking shared state.

Q33. A monitor method accepts a callback and invokes it while holding the monitor lock. The callback may call back into the same monitor or acquire a second lock used by another thread. Which design principle most directly reduces the risk of deadlock and excessive contention?

A.Invoke callbacks only after the protected state has been made consistent and the monitor lock has been released, when semantics permit ✅
B.Require every callback to acquire the monitor lock again before returning
C.Hold every lock in the program throughout the callback
D.Remove all validation from the monitor method
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: Calling external or user-controlled code while holding a monitor can create unpredictable lock dependencies and long critical sections. Releasing the monitor after completing the protected state transition reduces contention and avoids many reentrant or cross-lock deadlock patterns.

Q34. A condition-variable queue uses a loop to test the predicate and correctly releases the monitor lock during waiting. However, the scheduler never runs one particular ready thread, even after it is signaled repeatedly. Which conclusion is correct?

A.Correct monitor synchronization guarantees execution regardless of scheduler behavior
B.Repeated signaling automatically gives the thread CPU time
C.The monitor can preserve safety while starvation remains possible because progress also depends on scheduling fairness ✅
D.The thread must already have acquired the resource
💡 Difficulty: medium | ✅ Correct: C

📖 Explanation: Monitors coordinate access to shared state but do not independently guarantee that every ready thread receives processor time. If the scheduler continually ignores one thread, it may starve even though the monitor's locking and condition logic are correct.
