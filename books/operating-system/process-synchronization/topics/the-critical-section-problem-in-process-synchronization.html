What is The Critical Section Problem in Process Synchronization?

Definition:
The critical section problem involves designing a protocol that allows cooperating processes to share data without interference. Each process has a code segment called the critical section where shared resources are accessed. The solution must ensure mutual exclusion, progress, and bounded waiting to maintain system stability and data integrity effectively.

Working:
A solution consists of an entry section, critical section, exit section, and remainder section. The entry section requests permission to enter. The critical section executes the shared code. The exit section signals completion. The remainder section contains other code. This structure ensures safe access.

Example:
Consider two threads updating a bank balance. Thread A enters the critical section, locks the account, reads balance \($100 \), adds \($50 \), writes \( $150 \), and exits. Thread B waits until A exits, then proceeds, ensuring the balance is never corrupted by simultaneous updates.

Reason:
Without solving this problem, concurrent processes could overwrite each other's changes. For instance, if two threads read the same initial value and update it independently, one update is lost. Solving this ensures atomicity of operations on shared data structures.

Common MisConceptions:
A common error is assuming that disabling interrupts solves the problem for multiprocessor systems. It only works for single-processor systems. Also, students often confuse busy waiting with blocking; busy waiting wastes CPU cycles while blocking puts the process to sleep.

Exam Preparation Tips: How to prepare this topic
Memorize the three requirements: Mutual Exclusion, Progress, and Bounded Waiting. Be able to explain why each is necessary. Practice identifying critical sections in code snippets. Understand the difference between software and hardware solutions to this problem.

Key Terms:

  • Entry Section - code requesting entry to critical section.
  • Exit Section - code signaling exit from critical section.
  • Bounded Waiting - limit on times other processes enter after request.

📝 All The Critical Section Problem in Process Synchronization MCQs

Q1. Two processes update a shared bank balance. Each checks the balance, calculates a withdrawal, and writes the result. Both can enter the update region simultaneously. Which property is directly violated?

A.Bounded waiting
B.Progress
C.Mutual exclusion ✅
D.Deadlock prevention
💡 Difficulty: easy | ✅ Correct: C

📖 Explanation: Mutual exclusion requires that at most one process execute its critical section at a time when the section protects shared state that must not be modified concurrently. Allowing both withdrawal operations to overlap can produce lost updates or inconsistent balances, even if both processes eventually finish.

Q2. A process repeatedly requests entry to a critical section, but the section is empty and no process wants to enter. The algorithm nevertheless waits for another process to change a turn variable. Which requirement is violated?

A.Progress ✅
B.Mutual exclusion
C.Atomicity of arithmetic operations
D.Resource preemption
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: Progress requires that the decision about which process enters should not be postponed indefinitely when the critical section is free and processes wish to enter. An algorithm that depends on an uninterested process changing a turn variable can block an eligible process unnecessarily.

Q3. Process P requests entry and remains waiting while Q enters the critical section repeatedly. The section becomes free between Q's visits, but P never enters. Which property is missing?

A.Mutual exclusion
B.Bounded waiting ✅
C.Data encapsulation
D.Instruction-level parallelism
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: Bounded waiting limits the number of times other processes may enter their critical sections after a process has requested entry and before its request is granted. If Q can repeatedly overtake P without a bound, P may suffer starvation despite the critical section being used correctly by Q.

Q4. A proposed solution ensures that two processes never occupy their critical sections simultaneously. However, when both want to enter, it can keep postponing both forever. What is the best evaluation?

A.It satisfies all requirements because simultaneous entry never occurs
B.It violates mutual exclusion but satisfies progress
C.It satisfies bounded waiting because neither process enters
D.It satisfies mutual exclusion but fails progress ✅
💡 Difficulty: hard | ✅ Correct: D

📖 Explanation: Mutual exclusion addresses safety by preventing simultaneous critical-section execution. Progress addresses whether an eligible process can be selected when the section is free. An algorithm that leaves both processes waiting indefinitely can satisfy mutual exclusion while violating progress.

Q5. A developer claims that adding a delay before entering a critical section guarantees exclusive access because competing processes will probably arrive at different times. Which response is correct?

A.A delay changes timing but does not establish a correctness guarantee against all possible interleavings ✅
B.Any delay longer than one millisecond guarantees mutual exclusion
C.Delays automatically make shared-variable reads atomic
D.A delay guarantees bounded waiting even when a process crashes
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: Timing delays cannot replace synchronization because process scheduling, processor speed, interrupts, and workload vary. Two processes may still overlap after the delay, and a delayed process can be overtaken indefinitely. Correctness requires a synchronization protocol rather than a timing assumption.

Q6. A process enters its critical section, updates shared state, and exits. It then performs file compression using only private data. Which design is generally preferable?

A.Keep the lock held until compression finishes to prevent every possible race
B.Release the critical-section lock before compressing private data ✅
C.Acquire every available lock before leaving the critical section
D.Disable process scheduling during compression
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: A lock should normally protect only the operations that require coordinated access to shared state. Releasing it before unrelated private computation shortens the critical section, reduces contention, and allows other processes to make progress without compromising the protected update.

Q7. A critical-section algorithm is tested with two processes and no overlap is observed in one billion iterations. Which conclusion is scientifically justified?

A.The algorithm is formally correct because the test was extensive
B.The algorithm cannot fail on a faster processor
C.Testing provides evidence but does not prove that every possible interleaving is safe ✅
D.Mutual exclusion is unnecessary if a race is rare
💡 Difficulty: hard | ✅ Correct: C

📖 Explanation: Concurrency errors can depend on rare scheduling and memory-ordering events that testing does not reproduce. Extensive testing is useful for detecting defects, but it cannot by itself prove correctness for all execution interleavings. A sound algorithm also requires valid synchronization semantics and rigorous reasoning.

Q8. A process sets a shared occupied flag to true when entering a critical section and resets it to false when leaving. A crash occurs before the reset. What is the likely consequence if recovery is absent?

A.Other processes may remain blocked even though the critical section is no longer active ✅
B.All other processes automatically reset the flag
C.Mutual exclusion becomes impossible because the flag is true
D.The operating system must restart every process immediately
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: If the flag remains true after its owner crashes, other processes may interpret the resource as permanently occupied and refuse entry. This can cause a liveness failure. Robust synchronization must account for ownership, process termination, and recovery rather than assuming every execution reaches the release instruction.

Q9. An algorithm allows a process to enter the critical section only after receiving a grant from a coordinator. The coordinator grants access to one process at a time but may stop responding permanently. Which conclusion is best?

A.Mutual exclusion is necessarily violated whenever the coordinator fails
B.The algorithm guarantees progress because the coordinator exists
C.Bounded waiting is guaranteed by the use of messages
D.Safety may hold while progress fails if the coordinator stops issuing grants ✅
💡 Difficulty: hard | ✅ Correct: D

📖 Explanation: A coordinator can preserve mutual exclusion by granting access to only one process at a time. However, if it fails and no recovery or leader-replacement mechanism exists, waiting processes may never receive permission to enter. Safety and liveness are distinct correctness properties.

Q10. A developer uses a lock around a shared update but accidentally places the unlock instruction before the final write. What is the most likely result?

A.The lock makes the final write atomic regardless of its location
B.The process is guaranteed to be the only runnable process
C.Another process may enter and observe or modify shared state before the update is complete ✅
D.The unlock instruction automatically repeats the final write
💡 Difficulty: medium | ✅ Correct: C

📖 Explanation: Releasing a lock before the protected operation is complete allows another process to access the same shared state while the first update remains unfinished. This can expose intermediate values or cause conflicting writes. The unlock must occur after all operations requiring mutual exclusion have completed.

Q11. Two processes use an atomic exchange instruction to acquire a lock. Only one can change the unlocked state to the locked state successfully. Which property does this mechanism directly support?

A.Mutual exclusion ✅
B.Guaranteed FIFO ordering
C.Freedom from every form of starvation
D.Progress despite permanent process failure
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: An atomic exchange allows competing processes to coordinate acquisition through one indivisible operation. A correctly implemented lock can therefore prevent two processes from successfully acquiring the same unlocked state simultaneously. Atomic exchange alone does not guarantee fairness, starvation freedom, or recovery from a failed lock holder.

Q12. A lock algorithm ensures that every waiting process eventually enters if the lock holder continues to release it and scheduling is fair. Which additional issue could still invalidate the conclusion in practice?

A.The critical section contains shared data
B.The system uses more than one process
C.The lock variable is represented as a Boolean
D.The implementation lacks required atomicity or memory-ordering guarantees ✅
💡 Difficulty: hard | ✅ Correct: D

📖 Explanation: A proof depends on its assumptions about machine operations and memory visibility. If the implementation allows non-atomic lock acquisition or hides relevant writes through reordering, the actual program may not implement the proven algorithm. Hardware atomicity and suitable memory-ordering semantics are essential.

Q13. A system uses a ticket lock. Each arriving process obtains a unique increasing ticket and waits until its ticket is served. Which benefit does this design primarily provide?

A.It guarantees that critical sections cannot be interrupted
B.It prevents every possible deadlock involving unrelated resources
C.It gives contenders an ordered acquisition sequence, supporting fairness and bounded overtaking ✅
D.It eliminates all overhead associated with waiting
💡 Difficulty: medium | ✅ Correct: C

📖 Explanation: A ticket lock assigns each contender a place in an ordered queue. The serving counter advances in ticket order, so later arrivals cannot continually overtake an earlier waiter. This improves fairness and bounds overtaking, although waiters may still consume CPU while spinning.

Q14. A process holds a mutex while performing a network request that may take several seconds. Other processes need the same mutex for short updates. What is the most appropriate design concern?

A.The mutex must remain held for the entire network request in every design
B.The long critical section creates unnecessary contention and may block unrelated short operations ✅
C.Network requests cannot execute while a mutex exists
D.The lock should be replaced with an ordinary Boolean without further analysis
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: Holding a mutex across slow external I/O can prevent other processes from accessing protected state for an extended period. Where correctness permits, the design should separate state preparation from the network request and reacquire the lock only for necessary shared-state changes.

Q15. A program uses two locks, A and B. P acquires A then B, while Q acquires B then A. Each enters its first protected region and waits for the second lock. Which statement is most accurate?

A.The algorithm violates mutual exclusion because locks are always ineffective
B.The algorithm guarantees progress because both locks are atomic
C.The algorithm is safe because each process owns one lock
D.The opposing acquisition orders can create circular wait and deadlock ✅
💡 Difficulty: hard | ✅ Correct: D

📖 Explanation: P can hold A while waiting for B, and Q can hold B while waiting for A. Each waits for a resource held by the other, producing circular wait. A consistent lock ordering or a redesigned acquisition protocol can eliminate this particular deadlock pattern.

Q16. A shared counter is updated with an atomic increment, but a separate condition check and event notification must happen exactly once when the counter reaches 50. Why may the atomic increment alone be insufficient?

A.The increment can never change a counter's value
B.The condition check and notification may race unless the whole logical decision is coordinated ✅
C.Atomic instructions cannot be used with counters
D.The event must be triggered by every thread regardless of the counter value
💡 Difficulty: hard | ✅ Correct: B

📖 Explanation: Atomic increment prevents lost updates to the counter, but it does not necessarily make a subsequent condition check and event notification part of the same indivisible operation. Multiple threads may independently observe a relevant value or trigger an event incorrectly unless the transition is coordinated.

Q17. A graph displays the number of waiting processes over time. The count rises steadily, while completed critical-section operations continue at a constant rate. Which interpretation is most plausible?

A.The system has no contention because operations continue completing
B.Mutual exclusion must be violated because the queue grows
C.Arrivals may be exceeding service capacity, causing increasing contention and delays ✅
D.Every waiting process has already entered its critical section
💡 Difficulty: medium | ✅ Correct: C

📖 Explanation: A growing waiting count alongside continuing completions suggests that requests arrive faster than the system serves them. This indicates increasing contention or insufficient service capacity, but it does not alone prove deadlock or a violation of mutual exclusion. Arrival rates, lock duration, and scheduling should be examined.

Q18. An execution timeline shows P requesting entry at time 1, Q entering and leaving at times 2 and 4, Q entering and leaving again at times 5 and 7, and P entering at time 8. Which property is most directly demonstrated by this trace?

A.Mutual exclusion is necessarily violated
B.The algorithm guarantees freedom from deadlock in all circumstances
C.Progress is violated because Q enters twice
D.P experiences finite overtaking in this particular execution, but the trace alone does not prove a general bounded-waiting guarantee ✅
💡 Difficulty: hard | ✅ Correct: D

📖 Explanation: The trace shows Q entering twice after P's request before P finally enters. This demonstrates finite overtaking in one execution. Bounded waiting is a general guarantee limiting overtaking across all valid executions, so one finite trace cannot establish that the algorithm always satisfies the property.

Q19. A process enters its critical section after reading a shared pointer. Another process changes and frees the pointed-to object because the pointer read was not protected. What is the central issue?

A.A critical-section protocol must protect the shared object's lifetime and relevant pointer operations, not merely the pointer's numeric value ✅
B.Pointers cannot be shared safely under any circumstances
C.Freeing memory always terminates every process that holds a pointer
D.The first process automatically receives ownership of the object by reading its address
💡 Difficulty: hard | ✅ Correct: A

📖 Explanation: A pointer can retain the same numeric value even after the referenced object has been freed. If object lifetime and access are not coordinated, a process may dereference invalid memory. Suitable locking, reference counting, ownership rules, or safe reclamation methods can protect concurrent access.

Q20. A student says that a process executing inside a critical section cannot be interrupted because mutual exclusion requires uninterrupted execution. What is the correct response?

A.Mutual exclusion is possible only with disabled interrupts on every system
B.Mutual exclusion means other processes cannot enter the protected section, not that the owner cannot be preempted ✅
C.Every critical section must execute as one machine instruction
D.Interrupting a critical-section owner automatically releases all locks
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: Mutual exclusion concerns access to a shared protected region rather than uninterrupted CPU execution. A process may be preempted while holding a lock, and other processes must remain excluded until it releases that lock. Disabling interrupts is not a universal requirement for user-space synchronization.

Q21. A proposed algorithm guarantees that only one process enters the critical section but requires all processes to acquire permission in a fixed order, even when earlier processes have no pending work. What trade-off does this illustrate?

A.It necessarily increases mutual exclusion violations
B.It proves that all fixed-order algorithms are invalid
C.It may preserve safety at the cost of unnecessary waiting and reduced progress ✅
D.It guarantees maximum throughput because requests are ordered
💡 Difficulty: hard | ✅ Correct: C

📖 Explanation: Fixed-order permission can prevent conflicting entry, but it may make an active contender wait for a process that has no interest in entering. This can reduce concurrency and violate progress. A good design coordinates actual requests rather than relying unnecessarily on an inactive process.

Q22. A mutex is initialized as unlocked, but two independent copies of the program each use their own private copy of the mutex while modifying the same shared file. Why is mutual exclusion not guaranteed?

A.Every mutex automatically coordinates all processes on a computer
B.File access cannot be synchronized by any locking mechanism
C.A mutex protects only writes and never reads
D.Separate private mutex instances do not coordinate access to the common resource ✅
💡 Difficulty: medium | ✅ Correct: D

📖 Explanation: Mutual exclusion works only when competing participants coordinate through the same synchronization mechanism or a suitable shared locking service. Independent private mutex instances can each appear unlocked, allowing both programs to modify the same file concurrently. The design needs an interprocess or file-level locking mechanism.

Q23. A process checks whether a shared queue is empty and then removes an item in separate unsynchronized steps. Another process can remove the final item between these steps. Which failure may occur?

A.The first process may attempt to remove an item from an empty queue ✅
B.The queue automatically duplicates the final item
C.The scheduler must merge both processes into one
D.The check becomes atomic because the queue is shared
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: Checking emptiness and removing an item are separate operations unless a synchronization mechanism makes them one coordinated action. Another process can remove the final item after the check, leaving the first process with an invalid assumption. Protecting the predicate and removal together prevents this race.

Q24. A test-and-set spinlock is used on a heavily contended multiprocessor. All waiting threads repeatedly write the same lock variable. Which change may reduce coherence traffic while retaining a suitable lock design?

A.Increase the number of unsynchronized writes to the shared variable
B.Use a queue-based or test-and-test-and-set design appropriate to the platform ✅
C.Make every thread acquire the lock twice
D.Replace the atomic operation with an ordinary load followed by a store
💡 Difficulty: hard | ✅ Correct: B

📖 Explanation: Repeated atomic writes to one shared cache line can cause substantial coherence traffic under contention. Test-and-test-and-set designs reduce repeated write attempts while the lock appears held, and queue-based locks can distribute waiting. The best design depends on the processor architecture and expected contention.

Q25. A system has a single critical section protecting a tiny update. A proposed solution disables interrupts around the update in a user application. What is the strongest objection?

A.Interrupts are the only possible synchronization mechanism
B.Disabling interrupts automatically coordinates every processor core
C.Ordinary user applications generally cannot safely or legitimately disable system interrupts, and this does not solve multiprocessor coordination by itself ✅
D.Interrupt disabling guarantees bounded waiting for every process
💡 Difficulty: hard | ✅ Correct: C

📖 Explanation: Interrupt masking is generally a privileged operation and is not an appropriate general-purpose synchronization method for ordinary user applications. Even where interrupts can be masked on one processor, other processors may still access shared memory. Appropriate atomic operations and locks are usually required.

Q26. A critical-section algorithm satisfies mutual exclusion and progress, but no bound exists on how many times other processes may enter before a waiting process is selected. Which assessment is best?

A.It necessarily violates mutual exclusion
B.It necessarily violates progress
C.It guarantees fairness because the section eventually becomes free
D.It may satisfy the first two properties while failing bounded waiting ✅
💡 Difficulty: hard | ✅ Correct: D

📖 Explanation: Mutual exclusion prevents simultaneous entry, while progress prevents indefinite postponement when entry is possible. Neither property alone establishes a finite bound on how often other processes may overtake a waiting process. Therefore, starvation may remain possible without bounded waiting.

Q27. Two threads acquire a lock in a correct protocol, but one thread forgets to release it on an error path. Which improvement best addresses this programming defect?

C.Let every waiting thread reset the lock without checking ownership
D.Remove error handling so the release instruction is never skipped
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: Locks must be released on normal and exceptional control-flow paths. Scope-based guards, structured cleanup, or equivalent resource-management patterns reduce the risk that an error or early return leaves a lock permanently held. Recovery still depends on the synchronization primitive and failure model.

Q28. A shared data structure has a global lock. Developers split it into separate locks for its left and right halves to increase parallelism. What new correctness concern must they evaluate?

💡 Difficulty: hard | ✅ Correct: B

📖 Explanation: Fine-grained locking can improve concurrency by allowing independent operations to proceed in parallel. However, operations spanning both halves may need to acquire both locks. Without a consistent ordering and a precise protocol, the redesign can introduce deadlocks, races, or inconsistent cross-partition state.

Q29. A waiting process repeatedly checks a lock and consumes a full CPU core while the lock holder is waiting for another task to run. What is the most likely performance problem?

💡 Difficulty: medium | ✅ Correct: C

📖 Explanation: Busy waiting repeatedly consumes processor cycles while the process cannot enter the critical section. If the lock holder needs CPU time to complete its work and release the lock, a waiter may even delay that progress. Blocking or a more suitable synchronization design may be preferable.

Q30. A synchronization timeline shows no overlapping critical sections, but a process waits forever while other processes repeatedly enter and exit. Which conclusion follows?

📖 Explanation: The absence of overlapping intervals supports mutual exclusion for the observed execution. However, repeated entries by other processes while one process waits indefinitely indicate possible starvation. Safety can hold even when fairness and liveness requirements are not satisfied.

Q31. A process writes a shared result while holding a mutex and releases the mutex. Another process acquires the same mutex before reading that result. Under a memory model that gives mutex operations the usual synchronization guarantees, what should occur?

📖 Explanation: Mutex synchronization generally establishes a happens-before relationship between writes performed before release and reads performed after a subsequent successful acquisition. This provides the necessary visibility for the protected update under the relevant memory model, assuming both threads follow the same locking protocol.

Q32. A system allows only one process in a critical section, but the process can be terminated while holding the lock. Which additional requirement is important for a robust design?

💡 Difficulty: hard | ✅ Correct: A

📖 Explanation: Mutual exclusion during normal execution does not automatically handle owner failure. A robust system needs an explicit policy for detecting abandoned locks and determining whether ownership can be recovered safely. Releasing a lock without repairing partially updated state could expose corrupted data.

Q33. A developer argues that using one critical section for an entire transaction is always better than protecting individual shared updates. What is the strongest counterargument?

💡 Difficulty: medium | ✅ Correct: C

📖 Explanation: A critical section must cover the complete set of operations needed to preserve shared-state invariants, but it need not include unrelated computation. An unnecessarily large region increases lock holding time and reduces concurrency. An overly small region can introduce races, so the correct boundary depends on the logical operation.

Q34. A two-process solution uses atomic flags and a turn variable. A code review discovers that each process resets its flag before the other process has finished the protected operation. What is the main concern?

💡 Difficulty: hard | ✅ Correct: B

📖 Explanation: A process must maintain its claim to exclusive access for the entire interval in which it uses protected shared state. Clearing an intent or ownership flag too early may let another process believe the region is available while the first process is still inside. The entry and exit protocol must preserve its invariants.

Q35. A lock acquisition function returns success, but the caller assumes that this also means its shared-data update has completed. What is the conceptual error?

💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: Acquiring a lock establishes permission to enter the protected region; it does not perform the caller's intended update automatically. The caller must execute the protected operations and release the lock afterward. Confusing permission to access shared state with completion of the operation can lead to incorrect program logic.

Q36. An algorithm grants access to one process at a time using a centralized queue. The queue preserves request order, but a process at the front crashes without withdrawing its request. What can happen without failure handling?

💡 Difficulty: hard | ✅ Correct: D

📖 Explanation: A centralized queue can preserve acquisition order, but an abandoned request at the front may prevent later contenders from receiving permission. This demonstrates that ordering and mutual exclusion do not by themselves guarantee progress under process failure. The coordinator needs timeout, cancellation, or failure-detection rules.

Q37. A graph of lock wait times shows one thread waiting 1 ms, 2 ms, 4 ms, 8 ms, and then 16 ms on successive attempts, while other threads continue completing work. What is the most reasonable diagnosis?

💡 Difficulty: hard | ✅ Correct: C

📖 Explanation: Increasing wait times while other threads continue making progress can indicate rising contention, an unfair lock policy, or a changing workload. It does not alone prove deadlock, because system-wide progress continues. Detailed acquisition traces, queue lengths, and scheduling information can identify the cause.

Q38. A process performs a shared update, then writes a log entry outside the lock. Another process can perform its own update and log before the first process writes its log. Which conclusion is most accurate?

💡 Difficulty: hard | ✅ Correct: B

📖 Explanation: The mutex may correctly protect the shared update while leaving log operations unordered relative to updates by other processes. If the application requires logs to reflect the exact update order, it needs a protocol that preserves that relationship, such as sequence numbers or a carefully designed transactional logging mechanism.

Q39. A developer removes locking from a shared read because reads do not modify data. Another thread may concurrently update the same object, and the language memory model does not permit unsynchronized conflicting access. What is the main risk?

A.Concurrent reads always cause lost updates

💡 Difficulty: hard | ✅ Correct: D

📖 Explanation: A read does not modify data, but it can still conflict with another thread's write. Without suitable synchronization, the program may exhibit a data race, stale observations, or inconsistent multi-field state, depending on the language and memory model. Read-write locks, immutable snapshots, or atomic access may be appropriate.

Q40. A critical section protects a linked list, and each operation locks the list before changing pointers. A new optimization reads a pointer before acquiring the lock and uses it after acquiring the lock. Why can this be unsafe?

💡 Difficulty: hard | ✅ Correct: A

📖 Explanation: Reading a pointer before acquiring the lock does not protect the referenced object or guarantee that the pointer remains valid. Another thread may remove, free, or replace the object before the lock is acquired. Pointer acquisition and use must follow an appropriate lifetime and synchronization protocol.

Q41. A process enters a critical section, then waits on a condition variable while still holding the associated mutex using an operation that does not release the mutex atomically. The producer needs that mutex to change the condition. What can occur?

A.The condition becomes true automatically after a timeout

💡 Difficulty: hard | ✅ Correct: C

📖 Explanation: Condition-variable waiting normally releases the associated mutex atomically as part of entering the wait state, allowing another thread to acquire the mutex and change the predicate. If the consumer waits while retaining the mutex, the producer may be unable to update the condition that would wake the consumer.

Q42. A process is waiting to enter a critical section. The lock holder releases the lock, but a newly arriving process acquires it first. This repeats indefinitely. Which conclusion is most accurate?

A.The algorithm must violate mutual exclusion on every iteration
B.The algorithm may preserve mutual exclusion while violating bounded waiting and allowing starvation ✅
C.The new process cannot acquire a released lock
D.Progress is always violated whenever a lock has more than one contender
💡 Difficulty: hard | ✅ Correct: B

📖 Explanation: A lock can allow only one owner at a time and still be unfair. If new arrivals repeatedly acquire it before an existing waiter, mutual exclusion remains intact but bounded waiting may fail. A fair queueing policy can prevent later arrivals from continually overtaking an earlier request.

Q43. A proposed critical-section solution uses a global lock for a short shared update but also locks the same global lock inside a helper function called during that update. The mutex is non-recursive. What should the code reviewer flag?

A.The inner acquisition always improves performance
B.The helper must execute on a separate processor
C.The global lock automatically detects recursive calls and releases itself
D.The nested acquisition can cause self-deadlock because the caller already holds the mutex ✅
💡 Difficulty: medium | ✅ Correct: D

📖 Explanation: If a thread holding a non-recursive mutex calls a helper that tries to acquire that same mutex, the second acquisition may block indefinitely. The caller cannot reach the unlock until the helper returns, and the helper cannot return until the lock is available. The locking responsibilities should be clarified.
