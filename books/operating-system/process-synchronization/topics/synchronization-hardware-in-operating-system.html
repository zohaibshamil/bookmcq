What is Synchronization hardware in operating system?

Definition:
Synchronization hardware refers to specialized machine instructions that support atomic operations, such as TestAndSet or CompareAndSwap. These instructions execute indivisibly, preventing interruption during execution. They provide efficient mechanisms for implementing mutual exclusion in multiprocessor systems without the overhead of software-only solutions.

Working:
The hardware guarantees that certain operations, like reading and writing a memory location, happen as a single uninterruptible unit. For example, TestAndSet reads a boolean value and sets it to true atomically. This ensures that no two processes can see the same state simultaneously.

Example:
Using TestAndSet: A shared lock variable is initialized to false. A process calls `TestAndSet(lock)`. If it returns false, the process enters the critical section. If true, it waits. This atomic check-and-set prevents race conditions on the lock variable itself.

Reason:
Software solutions like Peterson's are complex and limited to two processes. Hardware solutions are simpler, scalable to many processes, and more efficient on multiprocessor systems because they rely on atomic instructions supported directly by the CPU architecture.

Common MisConceptions:
A common mistake is thinking hardware solutions eliminate busy waiting. Most basic hardware solutions still use busy waiting. Also, students may assume these instructions are available on all architectures, but some older or embedded systems may lack them.

Exam Preparation Tips: How to prepare this topic
Understand the pseudocode for TestAndSet and CompareAndSwap. Explain why atomicity is crucial. Compare hardware solutions with software solutions in terms of complexity and scalability. Practice writing simple mutex implementations using these instructions.

Key Terms:

  • Atomic Operation - executes completely without interruption.
  • TestAndSet - atomically tests and sets a memory location.
  • CompareAndSwap - compares and swaps values atomically.

📝 All Synchronization hardware in operating system MCQs

Q1. Two processes execute an atomic test-and-set instruction on the same lock, initially false. Which outcome is possible when both attempt acquisition concurrently?

A.Both processes must read false and enter the critical section
B.Exactly one process can obtain the lock, while the other observes it as held ✅
C.Neither process can acquire the lock because atomic instructions reject concurrency
D.Both processes acquire the lock if their instructions begin in the same clock cycle
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: Test-and-set atomically returns the previous lock value and sets the lock to true. Only one competing operation can observe the initial false value and acquire the lock successfully; the other observes true and must wait or retry.

Q2. A programmer replaces an atomic test-and-set operation with separate instructions that read a lock and then write true. What is the principal flaw?

A.The lock cannot represent an unlocked state
B.The processor must disable virtual memory
C.Two processes can read false before either writes true, allowing both to enter ✅
D.The lock becomes permanently true after the first read
💡 Difficulty: medium | ✅ Correct: C

📖 Explanation: Separate read and write instructions do not form one indivisible operation. Two processes may both read false, then both write true and enter their critical sections, violating mutual exclusion despite each process apparently following the locking protocol.

Q3. A spinlock uses an atomic exchange instruction. Process P acquires the lock and is then preempted for a long time. Process Q repeatedly exchanges the lock value while waiting. What is the most direct consequence?

A.Q may waste CPU cycles while P is not running ✅
B.Q can safely enter because P is preempted
C.The exchange instruction automatically schedules P immediately
D.The lock guarantees bounded waiting regardless of scheduling
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: A spinlock repeatedly checks or modifies the lock while consuming processor time. Preemption does not release the lock, so Q may waste CPU cycles until P runs again and releases it; atomicity alone does not guarantee fairness or bounded waiting.

Q4. A system uses compare-and-swap with expected value 0 and desired value 1 to acquire a lock. The current lock value is 1. What should the operation report, assuming conventional compare-and-swap semantics?

A.Success, because desired value is always written
B.Success, but the lock remains 1
C.Failure, and the lock is changed to 0
D.Failure, and the lock remains 1 ✅
💡 Difficulty: medium | ✅ Correct: D

📖 Explanation: Compare-and-swap updates the memory location only when its current value equals the expected value. Since the lock is already 1 rather than 0, the comparison fails and the location remains unchanged, indicating that another process holds the lock.

Q5. A developer argues that an atomic increment can implement a counter but cannot help implement synchronization. Which assessment is most accurate?

A.Correct, because only test-and-set can coordinate processes
B.Incorrect, because atomic read-modify-write operations can support synchronization primitives such as counters and semaphores ✅
C.Correct, because increment instructions always execute in separate unprotected stages
D.Incorrect, because any ordinary arithmetic instruction automatically prevents races
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: Atomic increment makes a read-modify-write update indivisible, preventing lost updates to a shared counter. Such primitives can support synchronization mechanisms, although correct waiting, signaling, memory ordering, and higher-level protocol design may still be necessary.

Q6. Two threads increment a shared variable 1000 times each using an ordinary load, add, and store sequence. The final value is 1530 rather than 2000. Which explanation best fits the result?

A.The processor necessarily skipped 470 arithmetic instructions
B.The variable exceeded its representable range
C.Overlapping updates caused some increments to be lost ✅
D.The scheduler converted every increment into a decrement
💡 Difficulty: medium | ✅ Correct: C

📖 Explanation: A non-atomic increment involves reading the value, computing a new value, and storing it. Interleaving can cause both threads to read the same old value and overwrite one another's updates, so fewer than 2000 increments are reflected in the final result.

Q7. A lock is acquired using an atomic instruction, but ordinary writes inside the critical section become visible to another CPU only after that CPU enters the protected region. What additional requirement may be missing?

A.A larger integer type for the lock
B.A longer delay after every write
C.A rule that all processes use the same stack
D.Appropriate memory-ordering guarantees around lock acquisition and release ✅
💡 Difficulty: hard | ✅ Correct: D

📖 Explanation: Atomic lock manipulation alone does not necessarily establish the required visibility ordering for protected data. Acquire and release semantics, or equivalent memory barriers, ensure that critical-section writes become visible according to the synchronization protocol.

Q8. A student says, 'If test-and-set guarantees mutual exclusion, every process will eventually obtain the lock.' Which counterexample disproves the second claim?

A.One process repeatedly reacquires the lock before another waiting process succeeds ✅
B.The lock begins in the unlocked state
C.The processor supports atomic instructions
D.A process releases the lock after completing its work
💡 Difficulty: hard | ✅ Correct: A

📖 Explanation: Test-and-set can guarantee that no more than one process holds the lock at a time, but it does not inherently enforce fairness. A process that repeatedly reacquires the lock may starve another process that keeps losing the competition.

Q9. A process executes an atomic exchange to set a lock to 1 and receives the old value 0. Before it enters the critical section, another process executes the same exchange and receives 1. Which conclusion follows?

A.The first process acquired the lock; the second must not enter ✅
B.Both processes acquired the lock because exchange is atomic
C.The second process owns the lock because it executed later
D.Neither process owns the lock until both release it
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: The first exchange observes the unlocked value and changes it to locked, so that process acquires the lock. The second exchange observes the locked value, meaning it did not acquire ownership and must wait or retry under the protocol.

Q10. A shared lock variable is initialized to false. A process checks that it is false, is interrupted, and another process performs the same check before either sets it true. What change directly prevents both processes from passing acquisition?

A.Increase the lock variable's storage size
B.Combine checking and setting into one atomic operation ✅
C.Insert an ordinary delay between the check and set
D.Place the variable in a separate source-code file
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: The failure occurs because checking and updating are separate operations. An atomic test-and-set, exchange, or successful compare-and-swap combines the decisive check and state change so only one competing process can acquire the initially free lock.

Q11. A developer implements a binary semaphore by repeatedly setting its value to 1 with an atomic exchange. Which key requirement is still missing if the implementation never checks the previous value?

A.The semaphore must be stored as a floating-point number
B.Every process must use a separate semaphore variable
C.The code must determine whether acquisition actually found the semaphore available ✅
D.The exchange instruction must be replaced with an ordinary assignment
💡 Difficulty: hard | ✅ Correct: C

📖 Explanation: Atomic exchange changes the semaphore value but also returns its previous value. A correct acquisition protocol must inspect that returned value to distinguish successful acquisition from encountering an already-held semaphore; ignoring it can allow multiple entrants.

Q12. Two threads use an atomic fetch-and-add operation to reserve unique ticket numbers. The shared counter starts at 20. Thread A receives 20 and thread B receives 21. What property makes this useful for a ticket lock?

A.Each atomic operation can assign a distinct position in a serialized order ✅
B.The operation guarantees that thread A will execute every instruction first
C.The counter prevents all context switches until both threads finish
D.Ticket numbers automatically release the lock when assigned
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: Fetch-and-add atomically returns the old counter value and increments the counter. Concurrent callers therefore obtain distinct ticket numbers that define an order, allowing a ticket-lock protocol to make waiting more orderly than an unrestricted test-and-set loop.

Q13. A program uses compare-and-swap to update a linked stack without a lock. A node is removed, freed, and later allocated again at the same address before another thread completes its comparison. Which problem may occur?

A.The processor refuses to compare pointer values
B.The stack automatically loses its top pointer permanently
C.An ABA problem, where the pointer appears unchanged despite intervening changes ✅
D.A guarantee that the stack becomes linearizable without further design
💡 Difficulty: hard | ✅ Correct: C

📖 Explanation: The ABA problem occurs when a location changes from value A to B and then back to A. Compare-and-swap may see the expected pointer value and succeed even though the structure changed in between; tagged pointers or reclamation techniques can help.

Q14. A lock-free counter uses compare-and-swap in a retry loop. One thread repeatedly succeeds while another repeatedly fails. What is the best interpretation?

A.System-wide progress may occur even though an individual thread experiences starvation ✅
B.The failed thread must have acquired the counter twice
C.Compare-and-swap guarantees equal CPU time for all threads
D.The algorithm is necessarily blocking because retries occur
💡 Difficulty: hard | ✅ Correct: A

📖 Explanation: Lock-free algorithms aim to ensure that some operation completes within a finite sequence of system-wide steps, not that every thread progresses fairly. Repeated compare-and-swap failures can starve an individual thread despite overall system progress.

Q15. A programmer replaces a lock-protected increment with an atomic increment. The increment itself is correct, but the program must also ensure that a related balance check and update happen together. What is the best conclusion?

A.Atomic increment protects every statement that follows it
B.A single atomic operation makes all nearby shared data consistent
C.The balance check can be omitted because the counter is atomic
D.The compound invariant still needs a suitable synchronization protocol ✅
💡 Difficulty: hard | ✅ Correct: D

📖 Explanation: Atomicity applies to the specific operation, not automatically to a multi-step transaction involving related variables. If correctness depends on a balance check and a subsequent update occurring together, a lock or an appropriate atomic state-transition design is still needed.

Q16. A graph plots the number of waiting threads against time for a spinlock whose owner is preempted from time t1 to t2. The waiting-thread count rises steadily during that interval. Which explanation is most plausible?

A.Every waiting thread is performing disk I/O
B.The threads repeatedly retry acquisition while the owner cannot release the lock ✅
C.The lock is being released by each failed attempt
D.The graph proves that mutual exclusion has failed
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: When the owner is preempted, it cannot execute the release operation. Waiting threads may continue spinning and retrying acquisition, causing CPU consumption and a growing waiting population without necessarily violating mutual exclusion.

Q17. A timing graph shows lock acquisition latency increasing sharply as the number of competing CPUs rises. Which explanation is most consistent with a heavily contended test-and-set lock?

A.Atomic instructions become logically invalid with more CPUs
B.Every additional CPU makes the critical section shorter
C.Repeated writes to the shared lock cache line create contention and coherence traffic ✅
D.The lock stops being stored in shared memory
💡 Difficulty: hard | ✅ Correct: C

📖 Explanation: Under heavy contention, many CPUs repeatedly attempt read-modify-write operations on the same cache line. Cache-coherence traffic and retries can increase latency substantially, even though the atomic instruction continues to provide correct mutual exclusion.

Q18. A test-and-set lock is held by process P. Process Q performs test-and-set and receives true, then immediately repeats the operation. What should Q do under a basic spinlock protocol?

A.Continue waiting or retry until it observes successful acquisition, without entering yet ✅
B.Enter the critical section because true confirms ownership
C.Set the lock to false to help P finish
D.Assume P has crashed and terminate it
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: A returned value of true indicates that the lock was already held when Q attempted acquisition. Q has not obtained ownership, so it must keep waiting or use an appropriate backoff or blocking strategy rather than enter the protected section.

Q19. A system uses a compare-and-swap operation to change a lock from 0 to 1. Two CPUs issue the operation simultaneously. Why can only one succeed when the lock initially equals 0?

A.The operating system executes only one process per machine
B.The instruction delays the second CPU by a fixed number of milliseconds
C.The first CPU permanently disables the second CPU
D.The comparison and conditional update occur atomically at the shared location ✅
💡 Difficulty: medium | ✅ Correct: D

📖 Explanation: Compare-and-swap performs its comparison and conditional update as one atomic operation on the shared location. The competing operations are serialized with respect to that location, so after one changes 0 to 1, the other no longer finds the expected value.

Q20. A developer uses a hardware atomic instruction to acquire a lock but releases it with a plain store. Which condition is important for the release to be correct?

A.The release store must write a value larger than the acquire value
B.The release must publish the unlocked state with appropriate ordering for prior critical-section writes ✅
C.The releasing process must terminate immediately afterward
D.The store must be performed only when no other process exists
💡 Difficulty: hard | ✅ Correct: B

📖 Explanation: Correct lock release generally requires that prior protected writes become visible before another thread successfully acquires the lock. A release store or equivalent memory-ordering operation provides this ordering; a plain store may be insufficient on some architectures or under a language memory model.

Q21. A student claims that because an atomic instruction cannot be interrupted halfway through, a process using it can never be starved. What is the flaw in this reasoning?

A.Atomic instructions are always slower than ordinary instructions
B.Starvation is possible only when interrupts are disabled
C.Indivisibility of one operation does not guarantee fair scheduling or fair lock acquisition ✅
D.Atomic instructions cannot access shared memory
💡 Difficulty: hard | ✅ Correct: C

📖 Explanation: Atomicity prevents competing operations from observing an intermediate state of that atomic operation. Starvation concerns whether a particular process eventually gains access, which depends on the lock algorithm, scheduling, and contention rather than atomicity alone.

Q22. A hardware instruction atomically swaps a register value with a memory location. A thread wants to acquire a lock initially equal to 0. Which returned value indicates successful acquisition under the usual exchange-based protocol?

A.0, because the previous state was unlocked ✅
B.1, because the new state is locked
C.Any value, because exchange always grants ownership
D.A negative value, because it signals an available lock
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: The exchange operation returns the old memory value while storing the register value into memory. If the old lock value was 0, the thread changed it to 1 and acquired it; an old value of 1 indicates that another thread already held it.

Q23. A lock-free algorithm uses a compare-and-swap loop that retries whenever another thread changes the shared value. Why is it usually incorrect to say that every failed retry represents a system failure?

A.Every failed comparison corrupts the processor cache
B.A retry always means memory has been deallocated
C.The algorithm can succeed only if all other threads stop permanently
D.Failure may simply indicate that another concurrent operation changed the value first ✅
💡 Difficulty: medium | ✅ Correct: D

📖 Explanation: A failed compare-and-swap indicates that the expected value did not match at the atomic comparison point. This often means another thread made progress first, so the current thread must reread state and retry rather than treating the failure as hardware malfunction.

Q24. A multicore application uses a spinlock around a task that takes several milliseconds. Which change is most likely to improve performance when contention is frequent and the task may sleep?

A.Use a larger lock integer to reduce collisions
B.Use a blocking mutex or redesign the critical section to avoid lengthy lock holding ✅
C.Make every waiting thread retry more frequently
D.Disable interrupts on every CPU indefinitely
💡 Difficulty: hard | ✅ Correct: B

📖 Explanation: Spinning is efficient mainly when lock hold times are short. If critical sections are lengthy or can sleep, waiting threads waste processor cycles; a blocking mutex can suspend waiters, while shortening or restructuring the protected work can reduce contention.

Q25. A process uses atomic fetch-and-add to increment a shared counter and later reads the counter to decide whether a resource is available. What must be considered if the decision and resource allocation must be indivisible?

A.Fetch-and-add automatically protects all later reads
B.The counter must be converted to a character array
C.The separate decision and allocation may need a combined atomic protocol or lock ✅
D.The counter can never be read by another thread
💡 Difficulty: hard | ✅ Correct: C

📖 Explanation: Fetch-and-add makes its own counter update atomic, but it does not combine that update with later resource checks and allocation. If correctness requires those actions to be one indivisible state transition, the design needs a suitable compare-and-swap loop or broader lock.

Q26. A lock uses a Boolean variable and an atomic exchange. After the owner releases it, two waiting threads race to acquire it. What does the basic exchange operation guarantee about which waiter wins?

A.It guarantees the thread with the smallest process identifier wins
B.It guarantees the longest-waiting thread wins
C.It guarantees that both waiters enter together
D.It guarantees at most one successful acquisition at a time, but not necessarily a fair winner ✅
💡 Difficulty: medium | ✅ Correct: D

📖 Explanation: Atomic exchange serializes competing modifications and prevents multiple threads from simultaneously acquiring an initially free lock. However, it does not inherently prioritize older waiters or guarantee fair scheduling, so the winner can depend on timing and hardware behavior.

Q27. A programmer uses an atomic bit-test-and-set instruction on a bit that marks a resource busy. The instruction reports that the bit was previously clear and sets it. What is the correct inference?

A.The caller atomically claimed the resource, provided all users follow the same protocol ✅
B.The resource is still free because the old bit was clear
C.Every other process has been terminated
D.The instruction releases the resource automatically
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: Bit-test-and-set can atomically test a designated bit and set it. A previously clear bit indicates that the caller acquired the resource under the protocol; other participants must use the same synchronization discipline and release the bit correctly.

Q28. A multiprocessor system protects a shared queue using atomic locks, yet queue entries are occasionally read before their initialization writes become visible. Which diagnosis is most likely?

A.Atomic locks cannot operate on queues
B.The queue must contain duplicate entries by definition
C.The synchronization protocol lacks adequate memory visibility or ordering guarantees ✅
D.The system needs to replace all pointers with floating-point values
💡 Difficulty: hard | ✅ Correct: C

📖 Explanation: Mutual exclusion and memory visibility are related but distinct requirements. If lock operations do not provide suitable acquire-release ordering, a thread may observe stale or improperly ordered data; using correct synchronization semantics ensures initialization is visible after acquisition.

Q29. A benchmark compares a test-and-set spinlock with a ticket lock under high contention. The ticket lock shows more predictable waiting order but similar total CPU consumption. What is the best interpretation?

A.Ticket locks eliminate all spinning by definition
B.Ticket allocation improves ordering fairness, but waiters may still spin while waiting for service ✅
C.Test-and-set locks guarantee fairness whenever CPU use is high
D.Similar CPU consumption proves both algorithms have identical correctness properties
💡 Difficulty: hard | ✅ Correct: B

📖 Explanation: A ticket lock assigns positions that generally prevent later arrivals from overtaking earlier ones. However, a spinning ticket lock still consumes CPU cycles while waiting for its ticket to be served, so improved ordering does not necessarily eliminate spinning costs.

Q30. A thread acquires a lock and increments a shared counter. It then releases the lock before updating a second shared variable that must always equal the counter. What can go wrong?

A.The lock prevents all future counter changes
B.The second variable is guaranteed to update automatically
C.Atomic lock acquisition makes both variables one indivisible object
D.Another thread may observe an inconsistent pair because the invariant spans operations outside the lock ✅
💡 Difficulty: hard | ✅ Correct: D

📖 Explanation: A lock protects only the operations performed within its correctly synchronized critical section. If an invariant relates the counter and another variable, updating them under separate protection can expose intermediate inconsistent states to other threads.

Q31. A developer says that an atomic exchange lock cannot deadlock because the hardware instruction always finishes. Which response best identifies the error?

A.The exchange instruction may be infinitely long on every CPU
B.Deadlock means the processor cannot execute atomic instructions
C.The instruction may finish normally while a lock protocol leaves processes waiting indefinitely ✅
D.Atomic instructions always release every acquired resource
💡 Difficulty: hard | ✅ Correct: C

📖 Explanation: Hardware progress for an individual instruction does not guarantee progress for a synchronization protocol. Processes can still deadlock if they wait on resources in a cycle or if a lock is never released, even when each atomic instruction completes correctly.

Q32. A programmer replaces a global lock with separate atomic locks for each queue. What is the main potential benefit if operations usually touch only one queue?

A.All synchronization is eliminated even when queues share data
B.Unrelated queue operations can proceed concurrently with less contention ✅
C.Every queue is guaranteed to have identical throughput
D.Atomic operations no longer require correct release logic
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: Separating locks can reduce contention when independent operations access different queues. This allows more operations to proceed in parallel, although shared invariants spanning multiple queues may require additional coordination and careful lock-ordering rules.

Q33. A process repeatedly executes test-and-set while another process holds the lock. The waiting loop is changed to pause briefly between attempts. What is the most likely purpose?

A.To make the atomic instruction non-atomic
B.To guarantee that the waiting process enters first
C.To reduce aggressive retrying and cache-coherence traffic under contention ✅
D.To release the lock on behalf of its owner
💡 Difficulty: medium | ✅ Correct: C

📖 Explanation: A pause or backoff strategy reduces the frequency of repeated lock attempts. This can lower coherence traffic and contention when many processors compete, although it does not itself guarantee fairness, mutual exclusion without a correct lock, or eventual acquisition.

Q34. A program uses an atomic compare-and-swap to change a shared state from READY to RUNNING. If the state is already RUNNING, the operation fails. Why is this a useful state transition design?

A.It permits the transition only when the observed state matches the expected predecessor ✅
B.It changes every possible state to RUNNING regardless of its previous value
C.It ensures that no other process can ever read the state
D.It eliminates the need to handle failed transitions
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: Compare-and-swap allows a state transition to occur only if the current state equals the expected value. This prevents competing threads from both claiming a resource from the same READY state, but callers must still handle failures and later state changes.

Q35. A lock implementation uses an atomic instruction correctly, but a thread returns from the critical section through an error path that skips unlocking. What is the likely effect?

C.The lock changes to free when the thread exits any function
D.The lock may remain held, blocking other threads indefinitely ✅
💡 Difficulty: medium | ✅ Correct: D

📖 Explanation: Atomic acquisition does not automatically release a lock when control leaves a function or an error occurs. If an execution path skips unlocking, the lock may remain held and cause indefinite waiting; structured cleanup or scoped lock management helps prevent this.

Q36. A student compares disabling interrupts with a hardware atomic read-modify-write instruction for protecting shared data on a multicore system. Which statement is most accurate?

C.Interrupt disabling always guarantees fairness better than every lock
D.Atomic instructions work only when there is one processor
💡 Difficulty: hard | ✅ Correct: B

📖 Explanation: Disabling interrupts can prevent local interrupt-driven preemption but generally does not prevent another CPU from accessing shared memory. Atomic read-modify-write instructions coordinate concurrent updates to a shared location and are commonly used to build multiprocessor locks.

Q37. A shared variable is updated by a lock-free algorithm using compare-and-swap. A thread reads an old value, pauses, and later succeeds in a comparison against that same value. What additional risk should the designer consider beyond ordinary retry failure?

A.A successful comparison proves no intervening operations occurred
B.A paused thread cannot resume after another thread writes
C.The value may have changed away and back, making the comparison insufficient to detect history ✅
D.Compare-and-swap always returns a random value
💡 Difficulty: hard | ✅ Correct: C

📖 Explanation: A value can change from A to B and later return to A before a paused thread compares it. The comparison may then succeed even though intervening changes occurred, creating an ABA risk in structures where the history or node lifetime matters.

Q38. An atomic instruction protects acquisition of a lock, but two processes still corrupt a linked list because one updates the head pointer while another updates a node's next pointer outside the lock. What is the best correction?

B.Increase the processor clock speed until the race disappears
C.Keep the lock only around reading the head pointer

💡 Difficulty: hard | ✅ Correct: A

📖 Explanation: Even atomic pointer assignments do not make a multi-step data-structure update indivisible. When head and next-pointer changes must preserve a shared structural invariant, all conflicting updates need coordinated protection or a correctly designed lock-free algorithm.

Q39. A lock is initialized to 1, where 1 means held and 0 means free. The first thread executes test-and-set and receives 1. A developer concludes the thread owns the lock because it successfully executed the instruction. What is the correction?

A.Any completed atomic instruction implies ownership
B.The returned old value indicates the lock was already held, so this attempt did not acquire it ✅
C.The instruction must have changed the lock to 0
D.The thread should enter before checking the returned value
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: Test-and-set typically returns the previous value and sets the lock to true. A returned 1 indicates that the lock was already held at the time of the operation, so the caller must not enter the critical section and should retry or wait.

Q40. A system uses a hardware atomic instruction for a lock, and every process follows the acquisition and release protocol. Which property is most directly ensured by a correctly implemented mutual-exclusion lock?

A.Every process finishes in a bounded amount of time
B.No process can ever be interrupted while holding the lock
C.At most one process at a time enters the protected critical section ✅
D.All processes receive equal processor time
💡 Difficulty: medium | ✅ Correct: C

📖 Explanation: A correctly implemented mutual-exclusion lock ensures that only one participating process holds the lock and executes the protected region at a time. It does not automatically guarantee bounded waiting, equal scheduling, absence of deadlock, or completion.

Q41. A test-and-set lock works correctly on one CPU but fails when moved to a system where the lock variable is cached independently on several CPUs and the instruction is not truly atomic across them. What is the root issue?

A.The implementation lacks a globally effective atomic operation and suitable coherence guarantees ✅
B.The lock variable must be declared as a decimal number
C.The operating system cannot schedule multiple processes
D.The critical section must contain no arithmetic operations
💡 Difficulty: hard | ✅ Correct: A

📖 Explanation: Mutual exclusion requires atomicity with respect to all competing processors that access the shared lock. If the instruction only appears atomic locally or caches are not coherently coordinated, multiple CPUs may acquire the lock; hardware and memory-system guarantees must support shared atomicity.

Q42. A resource manager uses an atomic decrement on an available-resource count. Two threads both need one resource, and the count starts at 1. What additional logic is needed to avoid representing an unavailable resource as a successful allocation?

A.The count should be decremented twice before checking it

D.The operation's result must be checked, with a safe protocol to reject or undo acquisition when no resource was available ✅
💡 Difficulty: hard | ✅ Correct: D

📖 Explanation: Atomic decrement prevents lost updates but does not automatically enforce a nonnegative-resource invariant. The algorithm must check the prior count or use a conditional atomic transition so that only a thread observing an available resource can claim it successfully.

Q43. A developer uses a single atomic flag to protect two different critical sections that never access the same data. Under heavy load, both sections experience long waits. Which design change is most likely to improve independent concurrency?

A.Make the shared flag larger but keep one lock

C.Remove every lock and rely on the scheduler

💡 Difficulty: hard | ✅ Correct: B

📖 Explanation: A single global lock serializes even unrelated operations, creating unnecessary contention. Separate locks can allow independent critical sections to execute concurrently, provided operations involving multiple resources use a safe coordination strategy and maintain consistent lock ordering.
