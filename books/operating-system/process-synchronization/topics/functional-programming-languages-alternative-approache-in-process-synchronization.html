📝 Functional Programming Languages Alternative Approache in Process Synchronization (36 MCQs)

Functional Programming and Reduced Shared-State Dependencies

Functional programming provides an alternative approach to concurrency by emphasising pure functions, immutable data, and expressions that produce results without modifying shared state. In operating system and parallel application contexts, these properties reduce many synchronization requirements because independent operations can safely read the same immutable values. Execution systems can distribute functional computations across threads or processor cores with fewer shared-memory conflicts.

Why Mutable Shared Variables Complicate Concurrent Execution

Imperative concurrent programs often modify shared variables, creating race conditions when multiple threads access them without coordination. Functional programming reduces this problem by discouraging shared mutable state and favouring new values instead of in-place modification. This approach makes independent computations easier to execute concurrently, although external side effects and mutable references still require appropriate coordination.

Pure Functions, Immutable Data, and Parallel Evaluation

A pure function produces the same result for the same input without changing external state. Immutable data cannot be modified after creation, allowing several execution threads to read it safely. Parallel evaluation frameworks distribute independent function calls or collection operations across available workers, while controlled mechanisms handle necessary input-output operations and mutable interactions.

Parallel Processing of an Immutable Data Collection

Suppose a program contains 10,000 immutable numerical values and must calculate their squares. Four worker threads process separate portions using the same pure function. Each computation produces independent results without modifying the original collection. The runtime can combine the resulting values after the tasks finish, reducing the need for locks around the input data.

Reduced Locking, Parallel Scalability, and Remaining Limitations

Functional programming can simplify parallel computation by reducing shared mutable state and the synchronization required to protect it. It is useful in data processing, scientific applications, and concurrent services. However, file access, network communication, mutable references, and other side effects still require coordination. Immutable data may also increase memory allocation and copying costs in some implementations.

Misconceptions About Functional Programming and Concurrency

'Functional programs never use mutable state' is incorrect because many languages permit controlled mutation. 'Pure functions require locks for every shared input' is incorrect because immutable input can be read concurrently. 'Functional programming eliminates all synchronization' is incorrect because external side effects and resource coordination still require controlled execution.

Exam Focus: Pure Functions and Lock-Free Parallel Computation

Distinguish pure functions, immutable values, and side effects, and explain why immutable shared data reduces race conditions. Trace independent functional operations across multiple worker threads. Questions may compare functional and imperative synchronization approaches, assess parallel data processing, and identify situations where external resource access or mutable state still requires coordination.

Key Terms of Functional Concurrency

  • Pure function - Produces results without external side effects.
  • Immutability - Prevents modification after value creation.
  • Side effect - Operation changing external program state.
  • Referential transparency - Expression replaceable by its result.
  • Parallel evaluation - Independent computations execute simultaneously.
  • Shared mutable state - Modifiable data accessed by threads.

Q1. Which description best characterizes the functional approach when several computations may run concurrently?

A.Programs are expressed as evaluations of functions and expressions, with little reliance on commands that mutate shared state. ✅
B.Programs coordinate every expression through one global mutex.
C.Programs require each function to update a shared status variable.
D.Programs replace concurrent execution with a single permanent process.
💡 Difficulty: easy | ✅ Correct: A

📖 Explanation: Functional programs describe computation by evaluating expressions and composing functions. They reduce reliance on assignment commands and changing shared state, removing many common synchronization conflicts between concurrent tasks in parallel systems.

Q2. A data-processing service expresses each stage as a function whose result feeds the next stage. Why can this style simplify concurrent execution?

A.Every stage must execute on the same thread to preserve variable values.
B.The data dependencies identify required ordering, while independent stages need not coordinate through shared mutable variables. ✅
C.Function composition automatically creates a lock for each stage.
D.The operating system must execute composed functions in source-code order.
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: Functional descriptions emphasize the values produced and the dependencies between expressions, rather than a sequence of mutations. Independent expressions can therefore run in different orders when dependencies permit, without changing the specified result.

Q3. A service defines f(x) = x + 3 and g(x) = 2x. If it evaluates g(f(4)) as a composed computation, what value is returned?

A.11
B.8
C.14 ✅
D.10
💡 Difficulty: easy | ✅ Correct: C

📖 Explanation: First evaluate the inner function: f(4) = 4 + 3 = 7. Then apply the outer function: g(7) = 2 × 7 = 14. Composition preserves this dependency order rather than permitting reversal of their order.

Q4. A student says a function is pure because it returns the same displayed answer each time, even though it increments a global call counter. Which part of the reasoning is flawed?

A.A pure function must always return a different value on each call.
B.Changing a local temporary variable is always a shared-state race.
C.A function is pure only when it is executed by the kernel.
D.The function changes external state, so identical displayed return values do not make it pure. ✅
💡 Difficulty: medium | ✅ Correct: D

📖 Explanation: The flawed step is treating an unchanged return value as sufficient proof of purity. Incrementing a global counter is an observable side effect; a pure function must not modify external state.

Q6. Two worker threads receive the same immutable request and independently calculate a checksum and a category. Why can the operating system schedule these calculations in either order safely?

A.The scheduler guarantees that the first worker always finishes before the second.

C.Immutable input automatically serializes the workers at the hardware level.
D.The workers share a counter whose updates are atomic by definition.
💡 Difficulty: hard | ✅ Correct: B

📖 Explanation: The computations read the same stable input and do not mutate it. Their results are independent, so scheduling order does not create a race on request data, although later side effects may still require coordination.

Q7. Which pair of properties most directly identifies a pure function?

A.The function uses recursion and always runs on one processor.
B.The function reads global variables but never writes them.

D.The function returns a value and also updates a shared cache.
💡 Difficulty: easy | ✅ Correct: C

📖 Explanation: Purity combines deterministic behavior for a given input with the absence of external side effects. Reading mutable external state can also break purity because the result may depend on conditions outside the arguments.

Q8. A function calculates shipping cost using its argument for package weight but reads a mutable global fuel surcharge. Why is it not pure?

A.A pure function is not permitted to perform multiplication.

💡 Difficulty: medium | ✅ Correct: D

📖 Explanation: The global surcharge can change between calls without changing the explicit argument. The function therefore has a hidden dependency; passing the surcharge as an argument makes the calculation's inputs explicit.

Q9. A functional data pipeline applies a pure doubling function to the list [2, 4, 5]. What list should the mapping operation return?

B.[2, 4, 5]

📖 Explanation: Mapping the doubling function applies it independently to every element: 2 becomes 4, 4 becomes 8, and 5 becomes 10. The resulting list is [4, 8, 10], while the original input remains unchanged.

Q10. A developer claims that a calculation function is pure because it never changes its numeric result, but it writes a diagnostic line to a file on every call. What is the error?

A.Writing a file is pure whenever the function returns a number.

💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: The flawed reasoning ignores the file write. File output changes external state and can be observed independently of the returned number, so the operation must be kept outside the pure calculation or modeled explicitly.

Q12. Let f(x) = x + 2 and g(x) = 3x, both pure. A developer evaluates g(f(4)) but mistakenly reverses the composition. Which pair gives the correct result and the mistaken reversed result?

📖 Explanation: The correct order gives f(4) = 6, then g(6) = 18. Reversing the functions gives g(4) = 12, then f(12) = 14; composition order matters even for pure functions without altering their definitions.

Q13. What does immutability mean for a data value shared by several threads?

A.Once created, that value cannot be changed; an update produces a different value instead. ✅
B.The value can be changed only by the thread that created it.
C.The value is automatically copied into a private address space for every read.
D.The value is locked permanently after its first access.
💡 Difficulty: easy | ✅ Correct: A

📖 Explanation: An immutable value remains unchanged after creation. Code that needs a modified result creates a new value or version, allowing concurrent readers to share the original without racing over updates to it.

Q14. A reporting service allows many workers to read the same immutable configuration object. Why can those reads normally proceed without a mutex protecting the object?

A.A mutex is unnecessary because read operations always execute atomically.
B.No worker can change the shared object, so concurrent reads cannot conflict with writes to that object. ✅
C.The operating system converts every read into a private copy automatically.
D.Immutable objects cannot be stored in shared memory.
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: A read-read overlap is safe when the object cannot be mutated by any participant. Immutability removes the write side of the race, although other mutable resources accessed by the workers may still need protection.

Q15. A client holds the immutable list [A, B, C]. It needs a new list with D appended while preserving the original for another worker. Which result meets that requirement?

💡 Difficulty: easy | ✅ Correct: C

📖 Explanation: The update must produce a new list containing A, B, C, and D while retaining the original value. This lets another worker continue reading the earlier version without observing a partial mutation.

Q16. A programmer passes a constant reference to a list into two workers and concludes that the list is immutable. Another alias can still modify the same list. What is wrong with the conclusion?

A.A constant reference forces every alias to become constant automatically.
B.The list is immutable only when both workers run on separate processors.

💡 Difficulty: medium | ✅ Correct: D

📖 Explanation: The flawed step equates a read-only access path with deep immutability. Another alias may still mutate the underlying object, so safe sharing requires controlling all mutation paths or using a genuinely immutable value.

Q17. A team records the number of elements visible in its original immutable list after each derived version. The data are (version, original-list size): (0,5), (1,5), (2,5), (3,5), (4,5). What conclusion is supported?

💡 Difficulty: hard | ✅ Correct: A

📖 Explanation: Every recorded version still observes five elements in the original value. This is consistent with immutable updates creating separate versions rather than changing the shared original list in place across all versions.

Q18. Two workers start from the same immutable balance record. One produces a new record adding a deposit; the other produces a new record subtracting a fee. What does immutability guarantee, and what remains necessary?

A.The operating system automatically merges both new records into one correct balance.

💡 Difficulty: hard | ✅ Correct: B

📖 Explanation: Immutability prevents either worker from changing the common starting record, so their calculations do not race on it. A merge or ordering policy is still needed to incorporate both results correctly.

Q19. What is referential transparency in a functional program?

A.A variable can be reassigned whenever another thread requests it.
B.A function call must be repeated to refresh its stored result.
C.An expression can be replaced by its value without changing the program's observable behavior. ✅
D.Every expression must execute exactly once and in source order.
💡 Difficulty: easy | ✅ Correct: C

📖 Explanation: Referential transparency allows an expression to be substituted by its value in any valid context. This relies on the expression having no hidden state changes or dependencies that make the substitution observable.

Q20. A compiler wants to evaluate two independent expressions in parallel. How does referential transparency help it reason about this transformation?

A.It guarantees that every expression consumes equal CPU time.
B.It removes data dependencies between expressions that use one another's results.

D.Pure expressions can be substituted by their values, so changing their evaluation order does not introduce hidden state changes. ✅
💡 Difficulty: medium | ✅ Correct: D

📖 Explanation: Referentially transparent expressions have no hidden side effects, so their evaluation can be moved or repeated when data dependencies allow. The property does not remove genuine dependencies between one expression and another.

📖 Explanation: The replacement removes the function's global counter update. Although the numeric result may match, the program's observable state differs, so the function call is not referentially transparent and cannot be freely substituted.

Q24. A program runs pure calculations concurrently and then writes each result to a shared log in a required chronological order. Which design best respects both requirements?

Q25. Which operation is an example of a side effect that a pure calculation should not perform directly?

📖 Explanation: A useful program must read input, display results, and communicate with external services. Functional design controls where these effects occur so the core computations remain easier to reason about and test.
