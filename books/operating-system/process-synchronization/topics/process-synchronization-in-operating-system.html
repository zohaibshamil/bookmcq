What is Process Synchronization in operating system?

Definition:
Process synchronization is a mechanism that ensures multiple concurrent processes execute in an orderly manner to prevent race conditions. It coordinates access to shared resources, ensuring data consistency and integrity by allowing only one process to manipulate shared data at any given time through specific protocols.

Working:
This works by defining critical sections where shared variables are accessed. The system enforces mutual exclusion, progress, and bounded waiting. Processes must request entry, execute the critical section, and then exit, allowing others to proceed without conflict or data corruption.

Example:
Two processes, P1 and P2, share a variable `count`. If both read `count=5`, increment it, and write back, the result might be 6 instead of 7. Synchronization ensures P1 finishes updating before P2 starts, resulting in the correct value of 7.

Reason:
This is necessary because modern operating systems run multiple processes concurrently. Without synchronization, simultaneous access to shared memory leads to inconsistent data states, known as race conditions, which cause unpredictable program behavior and system errors.

Common MisConceptions:
Students often think synchronization slows down all processes equally. In reality, it only blocks processes competing for the same resource. Another misconception is that it prevents all deadlocks; improper implementation can actually cause deadlocks if not carefully designed.

Exam Preparation Tips: How to prepare this topic
Focus on understanding the three requirements: Mutual Exclusion, Progress, and Bounded Waiting. Practice drawing timing diagrams for race conditions. Compare software solutions like Peterson's with hardware solutions. Memorize the definitions of critical section and race condition thoroughly.

Key Terms:

  • Race Condition - when output depends on the sequence of execution.
  • Critical Section - code segment accessing shared resources.
  • Mutual Exclusion - only one process in critical section at a time.

📝 All Process Synchronization in operating system MCQs

Q1. Two processes increment a shared counter initially set to 0. Each performs 100 increments using separate read and write instructions without synchronization. Which conclusion is most accurate?

A.The final counter must equal 200 because both processes execute 100 increments
B.The final counter may be below 200 because concurrent updates can overwrite each other ✅
C.The final counter must equal 100 because only one process can access memory at a time
D.The final counter will be 200 if both processes have equal priority
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: Each increment consists of reading the counter, adding one, and writing the result. If both processes read the same old value, one write can overwrite the other. Consequently, some increments are lost, and the final counter may be less than 200 unless synchronization prevents the race.

Q2. A program checks whether a shared inventory quantity is positive and then decreases it. Two processes simultaneously observe a quantity of 1. Which modification most directly prevents both processes from selling the final item?

A.Increase the scheduling priority of the inventory process
B.Make the inventory variable globally accessible
C.Protect the check-and-decrement sequence with one mutual-exclusion mechanism ✅
D.Insert a delay between checking the quantity and decrementing it
💡 Difficulty: medium | ✅ Correct: C

📖 Explanation: The availability check and decrement form one logical transaction. A mutual-exclusion mechanism must protect the entire sequence so that another process cannot change the quantity between the check and update. A delay or priority adjustment cannot reliably guarantee this property.

Q3. A critical section is protected by a lock, but the process releases the lock immediately after reading a shared value and performs its update afterward. What is the principal flaw?

A.The shared value becomes immutable after the read
B.The process no longer guarantees exclusive access throughout the complete update ✅
C.The lock automatically converts the update into an atomic operation
D.The scheduler cannot interrupt a process that owns a released lock
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: Mutual exclusion protects only the operations performed while the lock is held. Releasing the lock after reading allows another process to modify the value before the first process writes its result. The entire read-modify-write sequence must be protected when it must behave atomically.

Q4. Two processes repeatedly execute a test-and-set instruction on the same lock. Only one obtains the unlocked state at a time, but losing processes continuously retry. Which property is guaranteed by the lock alone?

A.Every waiting process eventually acquires the lock
B.The system cannot experience starvation
C.At most one process enters the protected critical section at a time ✅
D.All processes receive equal CPU time
💡 Difficulty: medium | ✅ Correct: C

📖 Explanation: An atomic test-and-set lock can enforce mutual exclusion because only one process successfully changes the unlocked state and acquires ownership. However, continuous retrying does not guarantee fair scheduling or eventual acquisition, so starvation and excessive CPU consumption remain possible.

Q5. A developer claims that a program is race-free because every shared variable is declared volatile. Which response best identifies the error?

A.Volatile variables cannot be accessed by multiple processes
B.Volatile automatically provides mutual exclusion for every compound operation
C.Volatile guarantees that every update is performed by the highest-priority process
D.Visibility-related guarantees do not automatically make compound operations atomic or provide mutual exclusion ✅
💡 Difficulty: hard | ✅ Correct: D

📖 Explanation: Volatile semantics depend on the programming language and execution environment. Even when they ensure visibility or constrain certain compiler optimizations, they do not generally make a sequence such as read, increment, and write indivisible. A suitable atomic operation or synchronization primitive is required.

Q6. A system has two processes, P and Q, that must never execute their critical sections simultaneously. Which execution trace violates mutual exclusion?

A.P enters, P exits, Q enters, Q exits
B.Q enters, Q exits, P enters, P exits
C.P enters, Q enters, P exits, Q exits ✅
D.Q enters, Q exits, Q enters, Q exits
💡 Difficulty: easy | ✅ Correct: C

📖 Explanation: Mutual exclusion requires that no more than one process occupy the critical section at any instant. In the third trace, P enters and remains inside when Q enters. The overlapping intervals violate the fundamental safety requirement even if both processes eventually exit.

Q7. A synchronization algorithm guarantees that processes outside their critical sections cannot prevent an eligible process from entering. Which correctness requirement does this most closely express?

A.Bounded waiting
B.Progress ✅
C.Mutual exclusion
D.Deadlock freedom under every possible scheduling policy
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: Progress requires that when no process is executing in the critical section and some processes wish to enter, selecting the next entrant must not be postponed indefinitely by irrelevant processes. The algorithm must allow an eligible contender to proceed rather than permit arbitrary indefinite delay.

Q8. A developer uses a single shared Boolean flag to indicate that the critical section is occupied. Each process first checks the flag and then sets it to true in a separate instruction. Why can this design fail?

A.Both processes can observe false before either sets the flag to true ✅
B.A Boolean variable cannot represent two possible states
C.Setting a flag always releases every waiting process
D.The operating system automatically serializes all reads and writes to shared flags
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: Checking and setting the flag are separate operations. Both processes can read false before either writes true, after which each may believe it has acquired the lock. The algorithm therefore lacks an atomic acquisition operation and does not guarantee mutual exclusion.

Q9. A producer writes a new data item into a shared buffer and then signals a consumer. The consumer sometimes receives the signal but reads the old item. Which investigation is most relevant?

A.Whether the producer has a higher process identifier
B.Whether the consumer uses more CPU time
C.Whether synchronization correctly orders publication of the data before the consumer reads it ✅
D.Whether the buffer variable has a descriptive name
💡 Difficulty: hard | ✅ Correct: C

📖 Explanation: Correct synchronization must establish the required ordering between the producer's writes and the consumer's reads. If the signal does not provide the necessary memory-ordering guarantees, the consumer may observe stale data. The implementation must use synchronization primitives with suitable visibility semantics.

Q10. A counting semaphore initialized to 3 controls access to a resource pool containing three identical devices. What should happen when three processes each successfully acquire one device?

A.The semaphore becomes 3 because each acquisition records ownership
B.The semaphore becomes 0, and another acquisition must wait until a device is released ✅
C.The semaphore becomes negative immediately after the third acquisition
D.All three processes must enter the same critical section simultaneously
💡 Difficulty: easy | ✅ Correct: B

📖 Explanation: A counting semaphore represents the number of available resource instances. Starting at 3, each successful acquisition reduces the count by one, leaving 0 after three acquisitions. A further acquisition cannot proceed until a release makes a resource available again.

Q11. A semaphore starts at 0. Process P executes wait on it, while process Q later executes signal. Assuming conventional blocking semaphore semantics, what is the expected behavior?

A.P completes wait immediately because zero means unlimited resources
B.P terminates because a zero-valued semaphore is invalid
C.Q must wait until P executes signal
D.P blocks until Q signals, after which P can continue ✅
💡 Difficulty: medium | ✅ Correct: D

📖 Explanation: A conventional semaphore wait operation cannot consume a resource when the count is zero, so P blocks. When Q signals, the semaphore operation enables a waiting process to proceed, subject to the implementation's scheduling and wake-up semantics.

Q12. A programmer replaces a semaphore's atomic wait operation with an ordinary decrement of a shared integer. Two processes execute the decrement concurrently. What is the main risk?

A.The semaphore may never be initialized to a positive number
B.The integer automatically changes into a mutex
C.Concurrent decrements can be lost, breaking resource-count correctness ✅
D.The decrement forces both processes to run sequentially
💡 Difficulty: medium | ✅ Correct: C

📖 Explanation: Semaphore operations must be atomic because the count represents shared synchronization state. Ordinary decrements can interleave so that one update overwrites another, leaving an incorrect count. This may permit excess resource acquisition or incorrectly block processes despite available resources.

Q13. A bounded buffer has capacity 5, initially empty. A producer must reserve an empty slot before inserting an item. Which initial semaphore values correctly represent empty and full slots?

A.empty = 5 and full = 0 ✅
B.empty = 0 and full = 5
C.empty = 5 and full = 5
D.empty = 1 and full = 1
💡 Difficulty: easy | ✅ Correct: A

📖 Explanation: An empty buffer of capacity 5 has five available slots and no occupied slots. Therefore, the empty-slot semaphore begins at 5 and the full-slot semaphore begins at 0. These counts prevent producers from exceeding capacity and consumers from removing nonexistent items.

Q14. In a producer-consumer implementation, a producer performs wait(empty), wait(mutex), inserts an item, signal(mutex), and signal(full). Why is the ordering important?

A.It ensures the producer obtains exclusive access before checking whether a slot exists
B.It guarantees that the consumer always runs immediately after insertion
C.It allows the producer to insert into a full buffer without blocking
D.It reserves capacity before entering the protected buffer update and publishes availability after insertion ✅
💡 Difficulty: hard | ✅ Correct: D

📖 Explanation: The producer first reserves an empty slot, preventing insertion beyond capacity. It then locks the buffer for the actual update and releases the mutex before signaling that an item is available. Signaling full only after insertion prevents consumers from being notified about data that has not yet been published.

Q15. Two processes use a binary semaphore as a mutex. P acquires it and later signals it twice because of an error. Which concern is most appropriate?

A.The extra signal may violate the intended ownership protocol and allow incorrect concurrent entry, depending on semaphore semantics ✅
B.The semaphore necessarily changes into a counting semaphore with unlimited capacity
C.The extra signal guarantees that P can never deadlock
D.A binary semaphore always ignores every signal made by its owner
💡 Difficulty: hard | ✅ Correct: A

📖 Explanation: A mutex protocol normally requires that the process releasing the lock is the process that acquired it, and that release occurs exactly once. An extra signal can make the semaphore available while the critical section is still active, depending on implementation semantics, undermining mutual exclusion.

Q16. A system protects a shared data structure with a mutex. A process locks the mutex, calls a function that tries to lock the same non-recursive mutex again, and waits indefinitely. What best explains the problem?

A.The mutex has been converted into a counting semaphore
B.The process attempts to reacquire a lock it already owns, creating self-deadlock ✅
C.Mutual exclusion requires the same process to acquire the lock twice
D.The scheduler must terminate every process that requests a mutex
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: A non-recursive mutex cannot normally be acquired again by its current owner without first being released. The second lock attempt blocks while the process itself holds the lock, so the process cannot reach the release operation. This is a form of self-deadlock.

Q17. Two independent counters are updated by different threads. Each counter has its own lock, and neither operation accesses the other counter. What is the primary advantage of this design over one global lock?

A.It eliminates the need for synchronization primitives
B.It guarantees that all updates execute in a fixed global order
C.It prevents all possible deadlocks in the complete application
D.It permits independent operations to proceed concurrently while preserving protection for each counter ✅
💡 Difficulty: medium | ✅ Correct: D

📖 Explanation: Separate locks allow operations on independent counters to proceed simultaneously, reducing unnecessary contention. A single global lock would serialize otherwise unrelated work. However, multiple locks still require careful ordering if future operations acquire more than one lock.

Q18. A thread acquires lock A and then lock B. Another thread acquires lock B and then lock A. Both now wait for the other lock. Which change most directly addresses this deadlock pattern?

A.Make every critical section longer
B.Increase both threads' priorities
C.Require every thread to acquire locks in one consistent global order ✅
D.Replace all locks with ordinary shared Boolean variables
💡 Difficulty: medium | ✅ Correct: C

📖 Explanation: The deadlock occurs because the threads acquire the same locks in opposite orders, creating a circular wait. A consistent global lock ordering prevents one thread from holding a later lock while waiting for an earlier one, removing this particular source of circular dependency.

Q19. A researcher compares a spinlock and a blocking mutex on a single-core machine. A lock holder is descheduled while another process spins. Why can spinning be especially inefficient?

A.The waiting process may consume the CPU needed by the descheduled lock holder to make progress ✅
B.The spinlock automatically releases itself when its owner is descheduled
C.A single-core CPU can execute both processes simultaneously while spinning
D.The blocked process always has priority over the lock holder
💡 Difficulty: hard | ✅ Correct: A

📖 Explanation: On a single-core processor, a spinning waiter repeatedly consumes CPU cycles without doing useful work. If the lock holder is not running, the waiter may delay the very process that must release the lock. Blocking can be more efficient when waiting is expected to last a significant time.

Q20. A developer chooses a spinlock for a critical section that performs disk I/O and may wait several milliseconds. What is the strongest objection?

A.Spinlocks are incapable of enforcing mutual exclusion
B.A long wait can waste substantial CPU time while the lock holder waits for I/O ✅
C.Disk I/O automatically releases all locks
D.A spinlock guarantees that the waiting process will be scheduled first
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: Spinlocks are most appropriate for very short critical sections where the owner is expected to release the lock quickly. Holding one across potentially slow disk I/O can cause other processors to waste many cycles spinning instead of sleeping until the resource becomes available.

Q21. A test-and-set lock is fair only if the hardware instruction is atomic. A student argues that atomicity alone guarantees FIFO acquisition. Which correction is valid?

A.Atomic instructions are unnecessary when processes share memory
B.FIFO ordering follows automatically from equal process priorities
C.Atomicity guarantees that every waiting process eventually acquires the lock in arrival order
D.Atomicity prevents simultaneous successful acquisition but does not by itself impose a waiting order ✅
💡 Difficulty: hard | ✅ Correct: D

📖 Explanation: Atomic test-and-set ensures that competing attempts to change the lock state are serialized, preserving mutual exclusion. It does not necessarily record arrival order or guarantee fairness. A process that repeatedly loses the race may starve unless the lock design includes a fairness mechanism.

Q22. A program uses Peterson's algorithm for two processes, but its implementation runs on a modern weak-memory-ordering architecture without suitable atomic operations or memory barriers. What is the key concern?

A.Peterson's algorithm works only when one process exists
B.The algorithm requires processes to have identical instruction counts
C.Reordering or visibility effects may invalidate the assumptions behind the textbook algorithm ✅
D.Peterson's algorithm requires a counting semaphore initialized to zero
💡 Difficulty: hard | ✅ Correct: C

📖 Explanation: Peterson's algorithm relies on shared-memory reads and writes becoming visible in the expected order. Modern compilers and processors may reorder or delay observations unless appropriate language-level atomic operations and memory-ordering guarantees are used. A textbook proof does not automatically validate an unsafe implementation.

Q23. In a two-process turn-based solution, process P is allowed to enter only when turn equals P. If P repeatedly wants to enter while Q remains outside and never changes turn, what is the flaw?

A.The algorithm can violate mutual exclusion only when both processes enter together
B.Strict alternation may prevent progress even when the other process has no interest in entering ✅
C.Turn-based synchronization always guarantees bounded waiting and progress
D.The turn variable must be replaced with a floating-point number
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: Strict alternation can enforce mutual exclusion but may violate progress. If the turn belongs to Q and Q never requests entry or changes the turn, P can remain blocked despite the critical section being free. Correct synchronization should not depend unnecessarily on an uninterested process.

Q24. A process checks a shared flag and then enters a critical section only if the flag is false. Another process can change the flag between the check and the entry. Which design principle is violated?

A.The principle that the condition check and protected acquisition must form an indivisible or correctly synchronized operation ✅
B.The principle that all variables must be stored on disk
C.The principle that processes must always run in a fixed sequence
D.The principle that critical sections must contain no arithmetic
💡 Difficulty: hard | ✅ Correct: A

📖 Explanation: The check and subsequent entry must be coordinated so that another process cannot invalidate the condition between them. Otherwise, both processes may act on stale observations and enter simultaneously. Atomic acquisition primitives or a correct locking protocol prevent this time-of-check-to-time-of-use race.

Q25. A database worker reads a balance of 500. Two concurrent withdrawals of 400 each both validate the balance before either commits. What is the likely synchronization failure?

A.The balance is automatically doubled by concurrent reads
B.The CPU must execute both withdrawals in one instruction
C.The database cannot store negative integers
D.The validation and update are not isolated as one correctly synchronized transaction ✅
💡 Difficulty: medium | ✅ Correct: D

📖 Explanation: Both withdrawals may independently observe a sufficient balance and approve an amount that exceeds the available funds in combination. Proper transaction isolation, locking, or suitable atomic conditional updates ensure that one withdrawal observes the effect of the other before committing.

Q26. A synchronization graph shows P1 waiting for a lock held by P2, P2 waiting for a lock held by P3, and P3 waiting for a lock held by P1. What does the cycle establish when each lock has one instance?

A.All three processes have completed their critical sections
B.The processes form a circular wait that implies deadlock ✅
C.The scheduler will necessarily resolve the situation by changing priorities
D.Only P1 can be deadlocked because it appears first in the graph
💡 Difficulty: hard | ✅ Correct: B

📖 Explanation: With single-instance resources, the cycle represents P1 waiting for P2, P2 waiting for P3, and P3 waiting for P1. Each process holds a resource required by another member of the cycle, so none can proceed to release its resource. This is a deadlock.

Q27. A resource-allocation graph contains a cycle, but one resource type has several interchangeable instances. What can be concluded from the cycle alone?

A.The system is definitely deadlocked in every possible allocation
B.Every process in the system must be terminated
C.The cycle indicates possible deadlock, but additional resource-instance information is needed ✅
D.The cycle proves that mutual exclusion has been eliminated
💡 Difficulty: hard | ✅ Correct: C

📖 Explanation: For resource types with multiple instances, a cycle in a resource-allocation graph is not sufficient by itself to establish deadlock. Another instance may become available and allow a process to finish, releasing resources. The allocation state and outstanding requests must also be considered.

Q28. Two processes each hold one resource and wait for the resource held by the other. Which deadlock condition is directly demonstrated by their waiting relationship?

A.Circular wait ✅
B.Preemption
C.Guaranteed progress
D.Bounded waiting
💡 Difficulty: easy | ✅ Correct: A

📖 Explanation: Circular wait occurs when a chain of processes exists in which each process waits for a resource held by the next process, eventually returning to the first. In this scenario, each process waits on the other, forming a cycle that can prevent both from progressing.

Q29. An operating system allows a process to forcibly take a resource from another process under carefully defined recovery rules. Which deadlock condition is this policy intended to weaken?

A.Mutual exclusion
B.Circular wait
C.Hold and wait
D.No preemption ✅
💡 Difficulty: medium | ✅ Correct: D

📖 Explanation: The no-preemption condition means resources cannot be forcibly taken away and must be released voluntarily. A controlled preemption policy can break this condition by reclaiming resources under defined circumstances, although recovery may require saving state or restarting affected work.

Q30. A team prevents deadlock by requiring processes to request all necessary resources before execution begins. What is the main trade-off?

A.Every resource is guaranteed to remain fully utilized
B.Processes may hold resources while not using them, reducing utilization and concurrency ✅
C.Processes can acquire resources in any order without reservation
D.Starvation becomes mathematically impossible in all implementations
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: Requesting all resources in advance can prevent hold-and-wait because a process does not retain a partial allocation while requesting additional resources. However, it may reserve resources long before they are needed, lowering utilization and preventing other processes from using otherwise idle resources.

Q31. A system uses a deadlock-avoidance algorithm that grants a resource request only if the resulting allocation leaves the system in a safe state. What does a safe state mean?

A.Every process can finish immediately without waiting
B.No process will ever request another resource
C.There exists at least one order in which all processes can finish using available resources and resources released by earlier completions ✅
D.Every resource is currently unallocated
💡 Difficulty: hard | ✅ Correct: C

📖 Explanation: A safe state has at least one safe sequence in which each process can obtain its remaining required resources, complete, and release its allocation. This does not mean every process can finish immediately; it means a feasible completion order exists under the stated maximum-demand assumptions.

Q32. Three processes require at most 5, 4, and 3 units of a resource, respectively. Their current allocations are 2, 1, and 1 units, and 2 units are available. Which process can finish first using the available units under the stated maximum demands?

A.The third process, because it needs only 2 additional units ✅
B.The second process, because it needs 3 additional units
C.The first process, because it needs 4 additional units
D.None, because all processes already hold resources
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: Remaining needs are 3 units for the first process, 3 for the second, and 2 for the third, obtained by subtracting allocation from maximum demand. With 2 units available, only the third process can be satisfied and finish first.

Q33. A programmer replaces a mutex with a semaphore initialized to 4, assuming both provide identical exclusive access. What is the most important correction?

A.A semaphore initialized to 4 can permit up to four successful concurrent acquisitions, so it does not automatically provide binary mutual exclusion ✅
B.A semaphore always protects only one process, regardless of its initial value
C.A mutex permits four owners whenever four CPU cores exist
D.A mutex and a semaphore cannot both be used in synchronization
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: A counting semaphore initialized to 4 represents four available permits and can admit multiple concurrent holders if each acquisition consumes one permit. Exclusive access to a single critical section generally requires a mutex or a binary semaphore used correctly with an initial value of one.

Q34. A thread waits on a condition variable until a shared queue becomes nonempty. Why should the wait normally occur inside a loop that rechecks the queue condition?

A.A condition variable automatically inserts an item into the queue
B.The loop guarantees that the thread is scheduled before every producer
C.Wake-ups can occur spuriously or another thread can consume the item before the awakened thread reacquires the lock ✅
D.The queue becomes immutable whenever a thread waits
💡 Difficulty: hard | ✅ Correct: C

📖 Explanation: A condition-variable wake-up does not guarantee that the condition remains true when the thread resumes. Spurious wake-ups are also possible. Rechecking the predicate while holding the associated mutex ensures the thread proceeds only when the queue is actually nonempty.

Q35. A thread signals a condition variable before updating the shared condition, and a waiting thread may wake immediately and inspect the old value. Which correction is generally appropriate?

A.Remove the shared condition from the program
B.Update the protected state under the mutex before signaling the condition variable ✅
C.Signal the condition variable repeatedly without acquiring any lock
D.Replace the condition variable with a longer sleep interval
💡 Difficulty: hard | ✅ Correct: B

📖 Explanation: The shared predicate should be updated while holding the associated mutex, and notification should follow the state change according to the synchronization protocol. This ordering helps ensure that a waking thread can acquire the mutex and observe the updated condition instead of acting on stale state.

Q36. A reader-writer lock permits several readers or one writer. A continuous stream of new readers arrives while a writer waits. Which design issue can arise?

A.Mutual exclusion between writers becomes impossible by definition
B.Readers must always write to shared data
C.Every reader automatically blocks when a writer arrives, regardless of policy
D.The writer may starve if the lock policy continually favors arriving readers ✅
💡 Difficulty: hard | ✅ Correct: D

📖 Explanation: Some reader-preference implementations allow new readers to enter whenever no writer currently holds the lock, even when a writer is waiting. A sustained stream of readers can therefore delay the writer indefinitely. Writer-preference or fair policies can mitigate this problem.

Q37. A program protects every shared operation with one global mutex. It is correct but performs poorly as thread count increases. What is the most likely explanation?

A.The mutex causes all threads to execute simultaneously
B.The operating system cannot schedule a process that uses a mutex
C.Lock contention serializes unrelated operations and increases waiting time ✅
D.Mutual exclusion always increases the number of available CPU cores
💡 Difficulty: medium | ✅ Correct: C

📖 Explanation: A global mutex can force otherwise independent operations to execute sequentially. As thread count increases, more threads compete for the same lock, creating contention and limiting parallelism. More granular locks or redesigning shared state can improve throughput when their additional complexity is managed carefully.

Q38. A graph plots completed operations per second against the number of worker threads. Throughput rises from 1 to 4 threads, remains nearly flat from 4 to 8, and declines from 8 to 16. Which explanation best fits this pattern?

A.Synchronization overhead and contention may outweigh the benefits of additional parallelism ✅
B.More threads always reduce the total number of available resources to zero
C.The graph proves that mutual exclusion is unnecessary below 4 threads
D.The decline proves that every worker has entered a deadlock
💡 Difficulty: hard | ✅ Correct: A

📖 Explanation: Initial threads can increase parallelism, but eventually the workload may become limited by a shared lock, memory bandwidth, or scheduling overhead. Beyond that point, additional workers add contention rather than useful throughput. The graph alone does not establish deadlock or identify one unique bottleneck.

Q39. A timing graph shows process P entering a critical section at time 2 and leaving at time 8. Process Q enters at time 6 and leaves at time 9. What can be inferred?

A.Mutual exclusion holds because P entered first
B.Mutual exclusion is violated because the critical-section intervals overlap from time 6 to time 8 ✅
C.Bounded waiting is guaranteed because both processes eventually exit
D.The graph proves that P and Q use a counting semaphore correctly
💡 Difficulty: easy | ✅ Correct: B

📖 Explanation: P's critical-section interval is from time 2 to time 8, while Q's interval is from time 6 to time 9. The intervals overlap between times 6 and 8, meaning both processes are inside simultaneously. This directly violates mutual exclusion regardless of their eventual completion.

Q40. A benchmark reports that a lock-free counter outperforms a mutex-protected counter for short updates but performs worse under heavy contention. Which interpretation is most reasonable?

A.Lock-free algorithms always guarantee higher throughput for every workload
B.A lock-free algorithm cannot use atomic hardware instructions
C.The result must be invalid because synchronization costs never depend on contention
D.Atomic retry loops can become expensive when many threads repeatedly compete to update the same location ✅
💡 Difficulty: hard | ✅ Correct: D

📖 Explanation: Lock-free structures can avoid blocking but may rely on repeated compare-and-swap attempts. Under heavy contention, many attempts can fail and must retry, wasting work and cache-coherence traffic. Performance depends on workload, hardware, retry behavior, and the costs of blocking versus nonblocking synchronization.

Q41. A system uses atomic compare-and-swap to update a shared counter only when its observed value remains unchanged. Two threads read 10 and both attempt to change it to 11. What should happen if both operations are correctly atomic?

A.Both operations succeed because they started from the same value
B.The counter becomes 12 without either thread retrying
C.Only one change from 10 to 11 succeeds; the other thread must recheck or retry if it still needs to increment ✅
D.The counter becomes 10 because compare-and-swap prevents updates
💡 Difficulty: medium | ✅ Correct: C

📖 Explanation: Compare-and-swap checks the current value and performs the update atomically only if the expected value matches. Once one thread changes 10 to 11, the other thread's expectation of 10 no longer matches, so its attempt fails. A retry using the new value can perform the second increment.

Q42. A distributed service uses a local mutex on each server to protect a shared account stored across multiple servers. Why is a local mutex insufficient by itself?

A.It protects only threads sharing that particular local synchronization object, not concurrent operations on other servers ✅
B.A local mutex automatically transfers ownership to every remote server
C.A mutex can only protect data that contains integers
D.Distributed systems cannot use any form of synchronization
💡 Difficulty: hard | ✅ Correct: A

📖 Explanation: A local mutex coordinates threads that use the same lock instance within its synchronization domain. Other servers have independent memory and lock instances, so their operations may proceed concurrently. Distributed coordination requires an appropriate shared service, transactional mechanism, distributed lock, or other protocol with suitable failure handling.

Q43. A distributed lock service grants a lease to client A, but A pauses for a long time and continues writing after its lease expires and client B receives a new lease. Which technique most directly helps reject A's stale writes?

A.Increase A's local thread priority
B.Use monotonically increasing fencing tokens and have the protected resource reject older tokens ✅
C.Allow both clients to write without coordination
D.Extend the local sleep duration after each write
💡 Difficulty: hard | ✅ Correct: B

📖 Explanation: A lease alone may not stop a paused client from resuming and issuing stale writes. A fencing-token scheme assigns increasing token values to successive lock holders, and the protected resource rejects operations carrying an older token. This protects against delayed actions from expired lease holders.

Q44. A system has a critical section that updates two related variables, balance and transaction_count. A thread protects only the balance update with a lock. What problem can remain?

A.The transaction count is guaranteed to update atomically with the balance
B.The lock automatically includes every variable in the same program
C.The two variables cannot be read by any other process
D.Another thread may observe or create an inconsistent relationship between the two variables ✅
💡 Difficulty: medium | ✅ Correct: D

📖 Explanation: The lock protects only the operations included in its protocol. If balance and transaction_count represent one logical state change, protecting just one variable can expose an inconsistent combination or allow interleaving updates. The synchronization boundary should cover the invariant that links both values.

Q45. A producer-consumer application uses an unbounded queue protected by a mutex. Producers are fast, while consumers are slow. Which conclusion is justified?

A.The mutex guarantees that queue memory usage remains constant
B.The application must deadlock because producers are faster
C.The queue can grow without bound unless backpressure or a capacity policy limits production ✅
D.Consumers will automatically receive higher scheduling priority
💡 Difficulty: medium | ✅ Correct: C

📖 Explanation: A mutex prevents conflicting queue operations but does not control how much data accumulates. If producers consistently generate items faster than consumers remove them, the queue may grow indefinitely. A bounded queue, backpressure, rate limiting, or workload adjustment is needed to control memory use.

Q46. A student argues that a deadlock-free system cannot suffer starvation. Which counterexample best refutes the claim?

A.One process repeatedly loses a lock race while other processes acquire and release the lock successfully ✅
B.Every process completes its work and releases all resources
C.The system never allocates more resources than exist
D.All processes acquire locks in a consistent order and finish
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: Deadlock means a set of processes cannot progress because of circular resource dependencies. Starvation can occur even when the overall system continues making progress: other processes repeatedly acquire the resource while one process waits indefinitely. Thus, deadlock freedom does not imply fairness.

Q47. A process increments a shared value using an atomic fetch-and-add instruction. Another process reads the value concurrently. Which statement is correct?

A.The read must always return the value after every pending increment
B.The increment operation is indivisible, but the reader may observe a value corresponding to a particular point in the concurrent execution ✅
C.The atomic increment prevents all future reads until the process terminates
D.The reader can never observe the initial value
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: Atomic fetch-and-add ensures that each increment occurs as one indivisible update, preventing lost increments from competing updates using the same atomic operation. A concurrent reader may nevertheless observe an earlier or later valid value depending on timing and memory-ordering guarantees.

Q48. A team replaces a busy-wait loop with a blocking mutex. Under which condition is the blocking design most likely to improve efficiency?

A.The protected operation always completes in a few processor instructions and waiting is nearly impossible
B.The system must guarantee that no context switch ever occurs
C.The lock is never acquired by any process
D.Lock holders may be delayed long enough that sleeping waiters would avoid wasting substantial CPU time ✅
💡 Difficulty: medium | ✅ Correct: D

📖 Explanation: Blocking synchronization can avoid consuming CPU cycles while waiting for a lock that remains unavailable for a significant interval. If the critical section is extremely short, the cost of sleeping and waking may exceed the cost of spinning, so the best choice depends on expected wait duration and platform behavior.

Q49. An implementation protects a queue with a mutex but signals a waiting consumer before placing the new item into the queue. The consumer wakes, finds the queue empty, and sleeps again. Which design correction is best?

A.Remove all consumer checks so every notification causes a dequeue
B.Signal before acquiring the mutex in every possible execution
C.Insert the item while holding the appropriate mutex, then notify the consumer according to the condition-variable protocol ✅
D.Assume that notifications permanently store an item for later consumption
💡 Difficulty: hard | ✅ Correct: C

📖 Explanation: A notification communicates that a condition may have changed; it does not store a queue item or guarantee the predicate is true. Updating the queue under its mutex before notifying consumers ensures that a waking consumer can inspect the updated state. The consumer must still recheck the condition in a loop.

Q50. Two processes synchronize through shared memory. P writes data and then sets a ready flag; Q waits until ready is true and reads the data. Which condition is necessary for reliable publication?

A.The synchronization mechanism must establish suitable ordering and visibility between P's data writes and Q's data reads ✅
B.The ready flag must be stored as a decimal string
C.P must always execute on a faster processor than Q
D.Q must read the data before checking the ready flag
💡 Difficulty: hard | ✅ Correct: A

📖 Explanation: Correct publication requires more than observing the ready flag's value. The memory model and synchronization primitives must ensure that writes performed before publishing readiness become visible to the consumer after it observes readiness. Release-acquire operations or an equivalent correctly implemented synchronization protocol can provide this guarantee.

Q51. A service uses a semaphore to limit concurrent database operations to 6. Initially, six permits are available. If seven workers simultaneously request permits, what is the expected maximum number of workers admitted at once?

A.Seven, because simultaneous requests are processed as one group
B.One, because every semaphore behaves as a mutex
C.Six, because each successful acquisition consumes one of the six permits ✅
D.Zero, because simultaneous acquisition invalidates the semaphore
💡 Difficulty: easy | ✅ Correct: C

📖 Explanation: A counting semaphore initialized to six allows at most six successful acquisitions to remain outstanding at once. If seven workers request permits and no permit has yet been released, six may proceed while the remaining worker must wait until a permit becomes available.

Q52. A critical section has an average execution time of 2 microseconds, but acquiring and releasing a lock costs 8 microseconds. What is the most sensible initial performance investigation?

A.Increase the critical section duration to make locking worthwhile
B.Remove the lock without checking whether shared state is accessed concurrently
C.Force every thread to run at the highest priority
D.Measure contention and consider batching, reducing lock frequency, or redesigning shared-state access while preserving correctness ✅
💡 Difficulty: hard | ✅ Correct: D

📖 Explanation: Lock overhead substantially exceeds the useful work inside the critical section, so synchronization may dominate execution time. Profiling can determine whether batching operations, reducing shared-state access, or changing the data structure improves performance. Simply removing the lock would be unsafe if concurrent access still requires protection.

Q53. A test harness runs two threads for millions of iterations and never observes a race in a counter protected by an ordinary check-then-set flag. What is the strongest conclusion?

A.The implementation is correct because extensive testing proves every interleaving safe
B.The test has not established correctness because a rare interleaving may still allow both threads to enter ✅
C.The flag must be atomic because the test did not detect a failure
D.The scheduler permanently prevents simultaneous execution of the threads
💡 Difficulty: hard | ✅ Correct: B

📖 Explanation: Concurrency bugs depend on timing and interleavings, and testing may fail to reproduce the conditions needed to expose a race. A non-atomic check-then-set protocol remains vulnerable even if many executions appear correct. Correctness should be established through valid synchronization semantics and reasoning, supported by testing.

Q54. A bounded waiting algorithm permits a maximum of three successful entries by other processes after a request is made. Which observation would contradict the stated guarantee?

A.The requesting process enters after two other successful entries
B.The requesting process enters immediately when the critical section is free
C.Four other successful entries occur before the requesting process enters ✅
D.The requesting process waits while another process is inside the critical section
💡 Difficulty: medium | ✅ Correct: C

📖 Explanation: The stated bounded-waiting guarantee limits overtaking to three successful entries by other processes after the request. If four such entries occur before the requester enters, the implementation violates its specified bound. Waiting for an active critical section or entering immediately does not contradict the guarantee.

Q55. A system protects a shared linked list with a reader-writer lock. A reader traverses the list while another thread removes and frees a node without taking the lock. What is the most serious risk?

A.The list automatically restores every removed node
B.Readers become writers whenever a node is freed
C.The lock prevents all memory reclamation regardless of how it is used
D.The reader may dereference freed memory because the removal bypasses the synchronization protocol ✅
💡 Difficulty: hard | ✅ Correct: D

📖 Explanation: A reader-writer lock protects the data structure only when all relevant accesses follow the locking protocol. Removing and freeing a node without the lock can invalidate a pointer that a reader is using, leading to use-after-free errors, crashes, or data corruption.

Q56. A system's timeline shows a lock holder repeatedly releasing and immediately reacquiring a mutex before a waiting thread can run. Which problem may this pattern indicate?

A.The mutex has ceased to provide mutual exclusion
B.The system guarantees FIFO fairness because the lock is reacquired quickly
C.The waiting thread may experience starvation due to unfair lock acquisition or scheduling ✅
D.The critical section has become permanently non-preemptible
💡 Difficulty: hard | ✅ Correct: C

📖 Explanation: Some mutex implementations and scheduling policies allow a running thread to reacquire a lock before a waiting thread gets CPU time or wins the next acquisition. Repeated reacquisition can delay the waiter indefinitely. Fairness mechanisms or scheduling adjustments may be needed when bounded waiting matters.

Q57. A program needs to increment a shared counter and then, only if the new value is 100, trigger an event exactly once. Which approach best preserves this requirement under concurrent updates?

A.Use an atomic update or a lock to protect both the increment and the condition-trigger decision ✅
B.Increment atomically but test and trigger using an unrelated unsynchronized read
C.Let each thread maintain its own copy and trigger whenever its local copy reaches 100
D.Use a sleep interval after every increment and assume no other thread runs
💡 Difficulty: hard | ✅ Correct: A

📖 Explanation: The increment and the decision to trigger the event form one logical operation. Protecting only the increment leaves a race in which multiple threads can observe the threshold and trigger the event more than once. An atomic state transition or a lock covering both steps can enforce exactly-once behavior.
