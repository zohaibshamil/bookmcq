What is Reconfiguration in Robustness?

Definition:
Reconfiguration dynamically adjusts system structure following failures or additions, maintaining service continuity through state transfer and membership updates.

Example:
Kubernetes automatically rescheduling pods to healthy nodes when worker fails, updating service endpoints accordingly.

Reason:
Dynamic reconfiguration preserves functionality despite topology changes, ensuring distributed systems adapt autonomously to maintain desired service levels.

Q1. Which layer in the OSI model is functionally equivalent to the transport layer in the TCP/IP model?

A. Network
B. Data-link
C. Session
D. Transport ✅

💡 Difficulty: easy | ✅ Correct: D

📖 Explanation:

The transport layer in TCP/IP provides end-to-end reliability, flow control, and segmentation, which correspond to the OSI transport layer (layer 4). Therefore option D is correct. The Network layer (option A) handles routing and addressing, not transport functions. The Data-link layer (option B) works at layer 2, dealing with frames and physical media. The Session layer (option C) manages dialogs but does not provide the transport services defined by TCP/IP. Understanding this mapping helps engineers translate configurations between the two models.

Q2. A company replaces its legacy OSI‑based network with a TCP/IP stack. What is the first reconfiguration task the network administrator should perform?

A. Update the physical cabling ✅
B. Map OSI layers to TCP/IP layers
C. Change the IP addresses of all hosts
D. Install new application software

💡 Difficulty: easy | ✅ Correct: A

📖 Explanation:

In a migration from an OSI‑based stack to TCP/IP, the administrator must first understand how the seven OSI layers collapse into the four TCP/IP layers. Mapping each OSI function to its TCP/IP counterpart ensures that services such as routing, transport, and application are preserved. Updating physical cabling (option A) is unrelated to protocol conversion. Changing IP addresses (option C) may be needed later, but only after the layer mapping. Installing new application software (option D) does not address the underlying protocol stack.

Q3. Why does the TCP/IP model contain fewer layers than the OSI model?

A. Because it merges several OSI functions into single layers ✅
B. Because it omits the physical layer
C. Because it uses a different addressing scheme
D. Because it eliminates the need for a presentation layer

💡 Difficulty: medium | ✅ Correct: A

📖 Explanation:

TCP/IP combines several OSI layers, which reduces the total number of layers and often simplifies implementation. For example, the OSI presentation and session layers are merged into the application layer of TCP/IP, while the OSI network and data‑link functions are handled by the Internet layer. This consolidation leads to fewer interfaces between layers, decreasing overhead and easing development. Option A correctly states that TCP/IP has fewer layers because it merges OSI functions. Options B, C, and D misrepresent the reason, suggesting hardware changes or unrelated factors.

Q4. In a network where a large packet must be sent, which layer is responsible for fragmenting the packet to fit the link's maximum transmission unit?

A. Network layer ✅
B. Transport layer
C. Data-link layer
D. Application layer

💡 Difficulty: medium | ✅ Correct: A

📖 Explanation:

Fragmentation of large packets is performed by the network layer, which divides packets to fit the maximum transmission unit of the underlying link. In the OSI model this is layer 3, while the transport layer (layer 4) deals with end‑to‑end reliability, not fragmentation. Therefore option A is correct. The transport layer (option B) does not break packets into smaller frames. The data‑link layer (option C) may add its own framing but does not fragment IP‑level packets. The application layer (option D) is unrelated to packet size constraints.

Q5. A system must be reconfigured to meet a new reliability requirement. Which action directly addresses this need?

A. Replace the physical layer ✅
B. Add an extra session layer
C. Change the presentation syntax
D. Select a transport protocol that matches the required reliability

💡 Difficulty: medium | ✅ Correct: A

📖 Explanation:

When reconfiguring a system to meet specific reliability requirements, the appropriate action is to select a transport protocol that matches those needs. TCP provides reliable, ordered delivery, while UDP offers low‑latency, best‑effort service. Changing the physical layer (option A) would not affect reliability. Adding an extra session layer (option B) does not address transport reliability. Changing the presentation syntax (option C) concerns data formatting only. Thus option D correctly identifies the step of choosing the suitable transport protocol.

Q6. During a reconfiguration that changes the underlying transport protocol, which layer must be adjusted to preserve session semantics?

A. Network
B. Session ✅
C. Presentation
D. Physical

💡 Difficulty: medium | ✅ Correct: B

📖 Explanation:

The session layer maintains the state of dialogues between applications, while the transport layer ensures reliable data transfer. If the underlying transport protocol changes (e.g., from TCP to UDP), the session layer must be adjusted to preserve session semantics such as sequencing and checkpointing. Option B correctly identifies the session layer as needing modification. The network layer (option A) deals with routing, not session state. The presentation layer (option C) handles data formatting, and the physical layer (option D) concerns hardware signals.

Q7. A security policy requires encryption and authentication for data in transit. Which layers must be modified to implement this policy?

A. Presentation and Transport ✅
B. Network and Data-link
C. Application and Session
D. Physical and Network

💡 Difficulty: hard | ✅ Correct: A

📖 Explanation:

A security policy that mandates encryption and authentication for data in transit typically requires changes at both the presentation and transport layers. The presentation layer can apply encryption (e.g., TLS) before handing data to the transport layer, which can then provide integrity checks. Option A correctly lists these two layers. Modifying the network and data‑link layers (option B) would affect routing and framing but not provide end‑to‑end encryption. Changing the application and session layers (option C) might add security at higher levels but would not secure lower‑layer traffic. Physical and network layers (option D) are unrelated to encryption.

Q8. When moving from the OSI model to the TCP/IP model, where does end‑to‑end error control reside?

A. Error control is eliminated
B. Error control moves to the application layer
C. Error control remains in the transport layer ✅
D. Error control is handled by the link layer only

💡 Difficulty: hard | ✅ Correct: C

📖 Explanation:

In both OSI and TCP/IP models, end‑to‑end error control is a function of the transport layer. When moving from OSI to TCP/IP, the responsibility for detecting and correcting errors in the data stream remains with the transport protocol (TCP). Therefore option C is correct. Option A incorrectly claims error control is eliminated. Option B suggests it moves to the application layer, which is not standard practice. Option D limits error control to the link layer, ignoring the need for end‑to‑end reliability across multiple hops.

Q9. Given an OSI header of 50 bytes and a TCP/IP header of 40 bytes, what is the payload size when using TCP/IP for a 1500‑byte packet?

A. 1450 bytes
B. 1460 bytes ✅
C. 1490 bytes
D. 1500 bytes

💡 Difficulty: hard | ✅ Correct: B

📖 Explanation:

To find the payload size with TCP/IP, subtract the header length from the total packet size. The TCP/IP header is 40 bytes, so the usable data is \(1500 - 40 = 1460\) bytes, which matches option B. Option A uses the larger OSI header of 50 bytes, yielding 1450 bytes, but the question asks for TCP/IP payload. Option C (1490 bytes) would result from a 10‑byte header, which is not given. Option D (1500 bytes) assumes no header overhead, which is unrealistic. Thus the correct answer is B.

Q10. If a system replaces its OSI flow‑control mechanisms with those of TCP, what primary change occurs?

A. Flow control moves from the data‑link layer to the transport layer ✅
B. Flow control is eliminated
C. Flow control becomes hardware‑based
D. Flow control is handled by the application layer

💡 Difficulty: medium | ✅ Correct: A

📖 Explanation:

In the OSI model, flow control mechanisms are often implemented in the data‑link layer to prevent a fast sender from overwhelming a slower receiver. TCP moves flow control to the transport layer, using sliding windows to manage data rates across the network. Therefore option A correctly describes the shift. Options B and C incorrectly state that flow control is removed or becomes hardware‑based. Option D suggests the application layer handles flow control, which is not the primary mechanism in TCP/IP.

Q11. A new node is added to a distributed system that uses a different link‑layer technology (e.g., Wi‑Fi instead of Ethernet). Which layer must be reconfigured to accommodate this change?

A. Network layer
B. Presentation layer
C. Data-link layer ✅
D. Session layer

💡 Difficulty: hard | ✅ Correct: C

📖 Explanation:

Introducing a node that uses a different link‑layer technology, such as switching from Ethernet to Wi‑Fi, requires reconfiguration at the data‑link layer, which defines framing, addressing, and media access methods. Option C correctly identifies this layer. The network layer (option A) handles routing but does not manage the physical media specifics. The presentation layer (option B) deals with data representation, unrelated to link technology. The session layer (option D) manages dialogues between applications and is not involved in adapting to a new link‑layer medium.)
