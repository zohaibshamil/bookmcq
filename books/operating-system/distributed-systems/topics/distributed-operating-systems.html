What is Distributed operating systems?

Definition:
Distributed operating systems present multiple machines as a single unified computational entity with global resource management and location transparency.

Example:
Amoeba or Plan 9 where processes migrate seamlessly between nodes and files are accessed identically regardless of physical location.

Reason:
This abstraction hides distribution complexity from applications, enabling true parallelism and automatic load balancing without programmer intervention.

Q1. A distributed system loses communication with Site X. Which sequence of actions correctly restores correct operation according to fault‑tolerance principles?

A.Immediately restart all processes on remaining sites, ignore Site X, and later re‑add it without synchronization.
B.Detect the failure, stop using Site X’s services, migrate its functions to another site, and reintegrate X after it recovers and synchronizes state. ✅
C.Continue using Site X’s services while it is offline, assuming eventual consistency will resolve issues.
D.Shut down the entire system until Site X is repaired.
💡 Difficulty: easy | ✅ Correct: B

📖 Explanation: Option B is correct because fault‑tolerant distributed systems must first detect a site failure, cease relying on its services, and, if possible, transfer the failed site’s responsibilities to another operational site. After the failed site is repaired, its state must be synchronized before it re‑joins, ensuring consistency. Option A ignores failure detection and synchronization, leading to inconsistent state. Option C incorrectly assumes services can be used while offline. Option D needlessly halts the whole system, wasting resources. This sequence mirrors real‑world recovery procedures.

Q2. A company wants to guarantee that any single site failure does not disrupt file access. Which redundancy strategy best meets this requirement while minimizing extra hardware?

A.Store one copy of each file on a dedicated backup server that is powered off until a failure occurs.
B.Maintain two complete replicas of every file on two separate active sites, updating both simultaneously.
C.Use a single central server with RAID‑5 disks and rely on disk‑level redundancy only.
D.Distribute file fragments across three sites using erasure coding, requiring any two sites to reconstruct the file. ✅
💡 Difficulty: medium | ✅ Correct: D

📖 Explanation: Option D is correct because erasure coding spreads fragments so that the loss of any one site still leaves enough information on the remaining sites to rebuild the original file, providing fault tolerance with less storage overhead than full duplication. Option A leaves the backup server idle, causing delay when it must be powered on. Option B doubles storage cost without additional benefit. Option C protects only against disk failures, not whole‑site outages. Thus D balances resilience and hardware efficiency, matching real‑world redundancy needs.

Q3. An organization is deciding between a traditional mainframe and a distributed network of workstations for a high‑throughput transaction system. Which statement most accurately reflects the trade‑off they must consider?

A.Workstations always provide lower latency than a mainframe because they are closer to users.
B.A mainframe offers higher single‑point performance, but a distributed system can achieve comparable throughput with better fault tolerance and scalability. ✅
C.Distributed systems cannot support remote procedure calls, making them unsuitable for transaction processing.
D.Mainframes are cheaper to purchase and maintain than clusters of workstations.
💡 Difficulty: hard | ✅ Correct: B

📖 Explanation: Option B captures the essential trade‑off: mainframes excel at centralized, high‑speed processing, yet a well‑designed distributed cluster can match that throughput while adding redundancy and the ability to grow by adding nodes. Option A is false because latency depends on network conditions, not just proximity. Option C is incorrect; distributed systems routinely implement RPC. Option D misstates cost trends, as mainframes typically involve higher acquisition and maintenance expenses. Understanding this balance helps managers choose the architecture that aligns with performance, reliability, and budget goals.

Q4. Why is rapid detection of a site failure essential in a distributed operating system that provides redundant services?

A.It allows the system to immediately shut down all other sites to prevent data loss.
B.It enables the system to reallocate tasks to functioning sites before users experience service interruptions. ✅
C.It ensures that the failed site can continue processing its local tasks unnoticed.
D.It guarantees that no network messages are ever lost.
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: Option B is correct because quick detection lets the system promptly redirect work to healthy sites, preserving availability and minimizing user impact. Option A is counterproductive, as shutting down healthy sites reduces overall capacity. Option C ignores the need for system‑wide consistency; a failed site cannot safely continue processing. Option D is unrealistic—some messages may be lost during a failure, and protocols must handle such loss. Rapid detection therefore underpins the fault‑tolerance mechanisms that keep distributed services running smoothly.

Q5. How does low‑level message passing in a distributed system enable higher‑level services such as remote procedure calls (RPC) and file transfer?

A.Message passing abstracts network details, allowing developers to build RPC and file transfer protocols on top of a reliable communication primitive. ✅
B.Message passing directly encrypts all data, making additional security layers unnecessary for RPC.
C.Message passing replaces the need for any operating system services, rendering RPC obsolete.
D.Message passing forces all communication to be synchronous, which is required for file transfer.
💡 Difficulty: hard | ✅ Correct: A

📖 Explanation: Option A is correct because message passing provides a basic, reliable way to exchange data between nodes, and higher‑level protocols like RPC and file transfer are constructed by layering additional semantics on this primitive. Option B is false; encryption is a separate concern. Option C misrepresents the role of OS services, which remain necessary for resource management. Option D is inaccurate because message passing can be asynchronous; synchronous communication is not a prerequisite for file transfer. Recognizing this layering explains how complex distributed functionalities are built from simple message exchanges.

Q6. A company needs to move user files from an old server to a new one while keeping user downtime as short as possible. Which migration step best achieves this goal?

A.Perform incremental sync after the initial bulk copy
B.Shut down the old server before copying any data ✅
C.Transfer data using unsecured FTP
D.Delete old data before verifying the transfer
💡 Difficulty: easy | ✅ Correct: B

📖 Explanation: Incremental synchronization after the initial bulk copy lets the bulk transfer happen during off‑peak hours and then only the changed files are moved later, reducing the window when users cannot access their data. Shutting down the old server (B) would increase downtime, unsecured FTP (C) risks data loss, and deleting old data before verification (D) can cause irreversible errors. By using an incremental approach, the organization maintains service continuity and can quickly roll back if problems appear, which aligns with best practices for minimizing disruption during data migration.

D.Deleting old files after a system upgrade

📖 Explanation: Data migration refers to the systematic transfer of information from one storage medium, format, or computer system to another, typically to improve performance, consolidate resources, or replace legacy hardware. Option A describes backup, which preserves copies rather than moving the primary dataset. Option C focuses on encryption, a security measure unrelated to relocation. Option D suggests discarding data, which is the opposite of migration. Therefore, the correct choice captures the core activity of relocating data while maintaining its accessibility and integrity in the new environment.

Q8. Why is data validation considered a critical step after completing a migration?

A.To improve network speed ✅
B.To reduce storage cost
C.To increase user count
D.To ensure data integrity
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: Validation checks compare source and target datasets to confirm that every record, field, and relationship survived the transfer unchanged, which is essential for maintaining trustworthy operations. Enhancing network speed (A) is unrelated to post‑migration checks, and reducing storage cost (B) or increasing user count (C) are outcomes that depend on correct data, not on the validation process itself. By detecting missing or corrupted records early, validation allows administrators to remediate errors before users rely on the new system, thereby protecting business continuity and data quality.

Q9. During a large‑scale data migration, a remote site becomes unreachable after half of the files have been transferred. Which strategy most effectively preserves progress while handling the failure?

A.Abort migration and roll back ✅
B.Continue without checking
C.Use a checkpoint and resume after the site is restored
D.Ignore the failure and proceed
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: Implementing checkpointing records the state of the transfer at defined intervals, so when the site recovers the process can resume from the last successful point instead of starting over. Aborting and rolling back (A) would waste the already transferred data, while continuing without verification (B) risks data loss or duplication. Ignoring the failure (D) could lead to inconsistent datasets across sites. Checkpointing balances efficiency and reliability, enabling administrators to maintain continuity and reduce overall migration time despite intermittent connectivity issues.

Q10. How does system redundancy influence planning for a data migration project?

A.It reduces risk by providing fallback
B.It eliminates need for testing ✅
C.It allows parallel migrations
D.It makes migration slower
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: Redundancy means that duplicate resources or data copies exist, so if a migration step fails, the original remains intact, allowing a safe rollback or retry without service interruption. This safety net lowers the risk profile and lets planners schedule migrations with confidence. Redundancy does not remove the necessity for thorough testing (B), nor does it automatically enable parallel migrations (C), which require additional coordination. While extra copies might add some overhead, the primary impact is improved resilience, not slower performance.

Q11. A company must transfer 5 TB of data over a network that provides a sustained 200 Mbps throughput. Ignoring protocol overhead, approximately how many hours will the bulk transfer require?

A.~25 hours
B.~55 hours ✅
C.~110 hours
D.~220 hours
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: First convert 5 TB to bits: 5 TB × 8 = 40 Tb (terabits). Dividing by the 200 Mbps link gives 40 Tb / 0.2 Gbps = 200 000 seconds. Converting seconds to hours (200 000 ÷ 3600) yields about 55.6 hours, which rounds to roughly 55 hours. Option B matches this estimate. The other choices either underestimate or overestimate the time by factors of two or four, reflecting common miscalculations such as ignoring the bit‑to‑byte conversion or using incorrect unit scales. Accurate timing helps schedule migrations to minimize impact on business operations.

Q12. In a multi‑site data migration that uses a two‑phase commit protocol, what is the primary responsibility of the coordinator node?

A.It writes data locally on each participant ✅
B.It validates data after the commit decision
C.It replicates data to all sites
D.It collects votes from participants and decides to commit or abort
💡 Difficulty: hard | ✅ Correct: A

📖 Explanation: The coordinator orchestrates the two‑phase commit by first asking each participant to prepare and report readiness (vote). Based on unanimous readiness, it then issues a commit command; if any participant signals a problem, it sends an abort. This central decision ensures atomicity across distributed sites. Writing data locally (A) is the participant’s task, and validation after commit (B) is not part of the protocol’s decision phase. Replication (C) may occur separately but does not define the coordinator’s role in the commit process. Proper coordination prevents partial migrations that could corrupt the system.

Q13. Why is incremental data migration often preferred over a single, full‑scale migration in distributed environments?

A.Because it allows continuous operation and lower risk
B.Because it reduces storage requirements ✅
C.Because it eliminates the need for testing
D.Because it speeds up the network
💡 Difficulty: hard | ✅ Correct: B

📖 Explanation: Incremental migration moves only changed or new data after an initial baseline copy, letting the original system stay online and users continue their work, which dramatically cuts downtime. It also confines any errors to smaller batches, making troubleshooting easier and reducing the chance of a catastrophic failure. The approach does not inherently reduce the amount of storage needed (B), nor does it remove the necessity for thorough testing (C). While network usage may be spread over time, the primary advantage is operational continuity and risk mitigation, essential for large, geographically dispersed systems.

Q14. What is computation migration in a distributed operating system?

A.The process of moving data files from one server to another for backup.
B.The transfer of an executing process's state from one node to another to continue execution. ✅
C.The replication of user accounts across multiple machines.
D.The conversion of binary code into source code for debugging.
💡 Difficulty: easy | ✅ Correct: B

📖 Explanation: The correct answer is B because computation migration refers to moving the execution context of a running process—including its registers, memory pages, and open resources—from one node to another so that it can continue without interruption. Option A describes data backup, not process movement. Option C talks about user account replication, which is unrelated. Option D mentions decompilation, which is a debugging activity. Understanding this definition is key to recognizing how distributed systems keep applications alive across different hardware.

Option A is wrong; a failed site cannot reliably send messages. Option B misinterprets detection as a means to maximize bandwidth, which is unrelated to correctness. Option C confuses failure detection with load‑balancing decisions. Accurate failure detection is essential for maintaining system integrity during migration.

Q16. How does computation migration contribute to fault tolerance in a distributed environment?

A.By permanently disabling the failed node.
B.By replicating the same computation on every node simultaneously.
C.By moving the computation to a healthy node, allowing continued service. ✅
D.By converting the computation into a static file.
💡 Difficulty: medium | ✅ Correct: C

📖 Explanation: The correct answer is C. By moving the computation to a node that is still operational, the system preserves the service the computation provides, thereby contributing to fault tolerance. Option A suggests disabling the node, which does not help the computation continue. Option B describes replication, which is a different fault‑tolerance technique and incurs higher overhead. Option D is irrelevant because converting a computation to a static file does not keep it running. Migration thus enables the system to survive individual node failures.

Q17. When a previously failed site rejoins the system, what mechanism is essential for smooth reintegration?

A.A handshake protocol that synchronizes state and updates routing tables. ✅
B.Immediate reallocation of all its previous tasks without verification.
C.Disabling the site until all other sites are rebooted.
D.Automatic deletion of its stored data to avoid conflicts.
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: The correct answer is A. A handshake or similar synchronization protocol allows the rejoining site to exchange its current state, update routing and resource tables, and confirm that its data is consistent with the rest of the system, ensuring a smooth reintegration. Option B would risk assigning tasks to a node that may still be unstable. Option C unnecessarily shuts down the node, defeating the purpose of reintegration. Option D deletes valuable data, which could cause loss of information. Proper synchronization is therefore critical when a previously failed site returns.

Q18. A site fails while running a transaction that has partially updated a database. Which migration strategy best ensures consistency?

A.Suspend the transaction, migrate its state to Site B, and resume. ✅
B.Abort the transaction and restart it entirely on Site B.
C.Continue the transaction on Site A assuming it will recover.
D.Duplicate the transaction on both Site A and Site B.
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: The correct answer is A. Suspending the transaction, migrating its partial state to a healthy node, and then resuming preserves the work already done while maintaining atomicity and consistency of the transaction. Option B aborts the work, causing loss of the completed portion and requiring a full restart. Option C assumes the failed site will recover, which is unsafe for critical data. Option D creates duplicate work, risking conflicts and violating transaction isolation. By moving the in‑progress state, the system ensures that the transaction can finish correctly on the new site.

Q19. A cluster experiences uneven load, with Node 3 at 90% CPU while Node 5 is idle. Which computation migration technique should the scheduler employ?

A.Migrate the entire operating system from Node 3 to Node 5.
B.Migrate selected high‑CPU processes from Node 3 to Node 5. ✅
C.Shut down Node 3 to force tasks onto Node 5.
D.Increase the clock speed of Node 3.
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: The correct answer is B because moving only the high‑CPU processes from the overloaded Node 3 to the idle Node 5 balances the load without disturbing other system services, reducing overall response time. Option A is unrealistic; transferring an entire operating system is unnecessary and disruptive. Option C would halt all work on Node 3, causing downtime. Option D merely speeds up Node 3 but does not address the imbalance. Selective process migration is the standard technique for dynamic load balancing in distributed environments.

Q20. An image‑processing job consists of three stages: preprocessing (Stage 1), filtering (Stage 2), and rendering (Stage 3). The job starts on Node X, but Node X fails after completing Stage 1. Which migration plan minimizes total execution time?

A.Migrate the whole job to Node Y, restarting from Stage 1.
B.Migrate only Stage 2 and Stage 3 state to Node Y, resuming from Stage 2. ✅
C.Migrate only Stage 3 to Node Y, redoing Stage 2 on Node X after recovery.
D.Abort the job and schedule a new one on Node Y.
💡 Difficulty: hard | ✅ Correct: B

📖 Explanation: The correct answer is B. By transferring only the state needed for Stage 2 and Stage 3 to Node Y, the system can resume processing from the point where the failure occurred, avoiding the cost of re‑executing Stage 1. Option A would restart the whole job, incurring unnecessary work. Option C assumes Node X will recover to redo Stage 2, which may delay completion. Option D discards the partially finished work, wasting resources. Migrating the remaining stages preserves the work already done and minimizes total execution time.

Q21. A remote procedure call (RPC) is in progress between Client C on Site 1 and Server S on Site 2. Mid‑execution, Site 2 experiences a hardware fault. Which approach ensures the RPC completes correctly?

A.Terminate the RPC and require the client to retry later.
B.Migrate the server process and its current RPC state to a backup server on Site 3. ✅
C.Redirect the client to a different server without moving the RPC state.
D.Ignore the fault and continue assuming the server will recover.
💡 Difficulty: hard | ✅ Correct: B

📖 Explanation: The correct answer is B. Migrating the server process together with the current RPC state to a backup server on Site 3 allows the call to continue where it left off, preserving both client expectations and server progress. Option A forces the client to restart, which may be unacceptable for long‑running calls. Option C redirects the client but loses the in‑progress state, leading to incorrect results. Option D ignores the fault, risking loss of the RPC. State‑ful migration therefore ensures the RPC completes correctly despite the hardware failure.

Q22. What is process migration in distributed operating systems?

C.Shutting down a node permanently
D.Executing a process only on the originating node

📖 Explanation: Process migration means moving the complete execution context—code, memory, registers, and open resources—of a running process from one machine to another so that it resumes execution without restarting. Option A describes this accurately. Options B and C describe file transfer and shutdown, which are unrelated actions. Option D suggests no movement, which contradicts the definition. Understanding this core concept is essential for grasping how distributed systems maintain flexibility and resilience.

Q26. Three sites have CPU utilizations of 80 %, 30 %, and 20 %. A process requiring 25 % CPU is running on the 80 % site. Which migration decision best balances the load?

A.Move the process to the 30 % site ✅
B.Move the process to the 20 % site
C.Keep the process on the 80 % site
D.Terminate the process
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: Transferring the process to the site with 30 % utilization (option A) results in loads of 55 % and 55 % on the two sites, achieving a more even distribution than moving it to the 20 % site, which would create a 105 % overload. Keeping it (option C) leaves the original site overloaded, and termination (option D) defeats the purpose of migration. This analysis shows how migration decisions are guided by quantitative load data.

Ignoring the site (option B) would be a mistake; however, the correct answer reflects the need for a deliberate decision rather than forced reintegration. Q29. In systems supporting both pre‑copy and post‑copy migration, under which condition is pre‑copy generally preferred?

A.When network bandwidth is high and process state size is large
B.When network bandwidth is low and latency is critical
C.When the process has no open files
D.When the destination node has no memory ✅
💡 Difficulty: hard | ✅ Correct: D

📖 Explanation: Pre‑copy migration copies memory pages before the process stops, requiring sufficient bandwidth; however, when the destination node has ample memory (option D), the overhead of copying can be managed efficiently, making pre‑copy advantageous. Low bandwidth (option A) favors post‑copy to reduce data transfer before suspension. Options B and C describe unrelated scenarios. Understanding these trade‑offs guides system designers in selecting the appropriate migration technique.

Q30. A process with 2 GB of memory needs to be moved over a 100 Mbps link. Which migration technique minimizes downtime?

A.Pre‑copy migration ✅
B.Post‑copy migration
C.Live migration with incremental checkpointing
D.Cold migration after shutting down the process
💡 Difficulty: hard | ✅ Correct: A

📖 Explanation: Post‑copy migration transfers execution state first, then streams memory pages, allowing the process to resume quickly on the destination, thus minimizing downtime. Pre‑copy (option A) would require multiple rounds of copying, extending pause time. Incremental checkpointing (option C) adds overhead, and cold migration (option D) involves stopping the process entirely, leading to the longest interruption. Selecting the technique that reduces pause is crucial for time‑sensitive applications.

Q31. A node will be taken offline for a hardware upgrade. Which sequence best ensures minimal service interruption using process migration?

A.Migrate all critical processes to other nodes, upgrade, then reintegrate them ✅
B.Shut down the node, upgrade, then restart processes on the same node
C.Duplicate processes on the node before upgrade, then delete duplicates
D.Ignore migration and rely on redundancy only
💡 Difficulty: hard | ✅ Correct: A

📖 Explanation: The optimal approach is to first migrate essential processes to healthy nodes, perform the upgrade without affecting active workloads, and later move processes back if desired. This sequence (option A) maintains continuity. Shutting down without migration (option B) would cause downtime. Duplicating processes (option C) wastes resources, and ignoring migration (option D) relies solely on redundancy, which may not cover all services. This plan demonstrates practical use of migration for planned maintenance.
