What is Fault tolerance in Distributed Systems?

Fault tolerance is the system's ability to continue correct operation despite component failures, achieved through redundancy where critical functions have \( k+1 \) replicas so that up to \( k \) simultaneous failures can be masked without affecting service availability or data consistency.

Q1. What is the definition of fault tolerance in computer systems?

A. The ability to prevent any errors from occurring
B. The ability of a system to continue operating despite failures ✅
C. A method to increase processing speed
D. A technique for encrypting data

💡 Difficulty: easy | ✅ Correct: B

📖 Explanation:

Fault tolerance means that a system keeps working even when some components fail. Answer B captures this idea by stating that the system continues operating despite failures. Answer A is incorrect because no system can completely prevent errors. Answer C describes performance improvement, not reliability. Answer D is about security, not fault tolerance. In real-world servers, redundant power supplies illustrate this concept by allowing operation after a power‑supply fault.

Q2. A sensor node sends a packet that is lost on the wireless link. Which mechanism at the data‑link layer should the node use to ensure the packet is eventually received?

A. Flow control
B. Routing
C. Automatic repeat request (ARQ) ✅
D. Address translation

💡 Difficulty: easy | ✅ Correct: C

📖 Explanation:

Automatic repeat request (ARQ) causes the sender to retransmit a frame when it does not receive an acknowledgment, directly handling lost packets. This makes ARQ the correct choice (C). Flow control (A) manages data rate, routing (B) determines the path, and address translation (D) maps addresses; none address loss. In practice, Wi‑Fi devices employ ARQ to recover from intermittent interference, demonstrating fault‑tolerant communication.

Q3. Why does the data‑link layer implement error detection and correction mechanisms?

A. Because it can correct errors locally before they propagate ✅
B. Because it reduces overall network bandwidth usage
C. Because it handles routing decisions
D. Because it encrypts transmitted data

💡 Difficulty: medium | ✅ Correct: A

📖 Explanation:

The data‑link layer sits between physical hardware and higher protocols, so it can detect and fix corrupted bits before they travel further, preventing error propagation – that is why answer A is correct. Reducing bandwidth (B) is a side effect, not the primary purpose. Routing (C) is performed at the network layer, and encryption (D) belongs to higher layers. For example, Ethernet frames use CRC at the data‑link layer to catch errors early, enhancing fault tolerance.

Q4. How does the TCP/IP model provide fault‑tolerance differently from the OSI model?

A. TCP/IP has more layers, each adding redundancy
B. OSI relies solely on end‑to‑end error handling
C. TCP/IP combines transport and network error handling in one layer
D. OSI includes a dedicated session layer for recovery ✅

💡 Difficulty: medium | ✅ Correct: D

📖 Explanation:

The OSI model defines a separate session layer that can manage synchronization and recovery, giving it a distinct fault‑tolerance component; therefore D is correct. TCP/IP merges many functions, so it does not have a distinct session layer, making its fault handling rely on transport (TCP) and network (IP) mechanisms. Options A and B mischaracterize the models, and C is inaccurate because TCP/IP does not combine transport and network error handling into a single layer. Real‑world TCP retransmissions illustrate the model’s approach.

Q5. A company wants to add redundancy to its LAN while keeping costs low. Which design best improves fault tolerance?

A. Add a parallel link between every pair of switches
B. Add a single backup link that forms a ring ✅
C. Use a star topology without any backup links
D. Rely exclusively on a wireless backup network

💡 Difficulty: medium | ✅ Correct: B

📖 Explanation:

Creating a ring with a single backup link provides an alternate path if any single link fails, delivering fault tolerance with minimal extra hardware—answer B. Adding parallel links between every switch (A) is costly. A star without backup (C) offers no redundancy. A wireless backup (D) may suffer interference and does not guarantee reliability. In many office networks, a ring topology is chosen to achieve high availability without excessive expense.

Q6. Which error‑detection method offers the best trade‑off between detection capability and computational overhead for a high‑speed Ethernet link?

A. Parity bit ✅
B. Checksum
C. Cyclic Redundancy Check (CRC)
D. Hamming code

💡 Difficulty: medium | ✅ Correct: A

📖 Explanation:

Cyclic Redundancy Check (CRC) provides strong error detection while remaining fast enough for high‑speed Ethernet, making C correct. Parity bits (A) detect only single‑bit errors and are too weak. Checksums (B) are simpler but less reliable for burst errors. Hamming codes (D) correct errors but require more processing. In practice, Ethernet frames embed a 32‑bit CRC, balancing detection strength and hardware efficiency, thereby supporting fault‑tolerant communication.

Q7. A message arrives at the receiver with a corrupted payload despite using CRC at the data‑link layer. Which layer most likely failed to discard the corrupted frame?

A. Physical layer
B. Network layer
C. Data link layer ✅
D. Application layer

💡 Difficulty: medium | ✅ Correct: C

📖 Explanation:

The CRC checksum is computed and checked at the data‑link layer; if the frame is still corrupted, that layer failed to reject it, so C is correct. The physical layer (A) deals with signal transmission, not checksums. The network layer (B) handles routing and does not verify CRC. The application layer (D) works with higher‑level data and would not see a corrupted frame directly. This scenario highlights the importance of proper CRC handling for fault tolerance.

Q8. How does hop‑by‑hop error control improve overall system reliability compared to end‑to‑end control?

A. It reduces total retransmissions across the network
B. It masks errors early at each intermediate node ✅
C. It provides faster recovery after a failure
D. It increases overall latency

💡 Difficulty: hard | ✅ Correct: B

📖 Explanation:

Hop‑by‑hop error control detects and corrects errors at each link, preventing corrupted data from traveling further, which enhances reliability—answer B. Reducing total retransmissions (A) is more characteristic of end‑to‑end schemes. Faster recovery (C) can be achieved by either method, but hop‑by‑hop does not guarantee speed. Increased latency (D) may occur but is not a reliability benefit. In satellite networks, hop‑by‑hop checks help maintain data integrity across multiple ground stations.

Q9. What is the primary purpose of checkpoint/restart mechanisms in distributed computations?

A. To save system state periodically so computation can resume after a failure
B. To increase network latency for each operation ✅
C. To eliminate the need for any redundancy in the system
D. To store only static configuration data

💡 Difficulty: hard | ✅ Correct: B

📖 Explanation:

Checkpoint/restart periodically records the state of a computation, allowing it to roll back to a recent point after a failure, making A correct. Increasing latency (B) is a side effect, not the goal. Eliminating redundancy (C) is false; checkpoints complement redundancy. Storing only static data (D) does not address dynamic computation recovery. In large‑scale scientific simulations, checkpointing enables fault‑tolerant progress despite node crashes.

Q10. How does majority voting among replicated servers enhance fault tolerance?

A. It masks a single faulty replica by choosing the majority result ✅
B. It doubles the overall system throughput
C. It eliminates the need for any error‑detection mechanisms
D. It reduces the amount of network traffic required

💡 Difficulty: hard | ✅ Correct: A

📖 Explanation:

When multiple servers process the same request, the system selects the result returned by the majority, thereby hiding a single faulty replica—answer A. Doubling throughput (B) is unrelated to voting. Eliminating error detection (C) is incorrect because voting assumes correct detection of mismatches. Reducing traffic (D) is not a direct effect. Real‑world databases use quorum consensus to achieve high availability despite individual server failures.

Q11. A web service cluster has three servers, each failing independently with probability 0.02 per day. What is the probability that at least one server remains operational on a given day?

A. 0.94
B. 0.98
C. 0.06
D. 0.99999 ✅

💡 Difficulty: hard | ✅ Correct: D

📖 Explanation:

The probability that all three servers fail is \(0.02^3 = 0.000008\). Therefore, the chance that at least one stays up is \(1 - 0.000008 = 0.999992\), which rounds to 0.99999, matching option D. Options A, B, and C represent much higher failure rates and are therefore incorrect. This calculation shows how redundancy dramatically lowers the risk of total service outage, a key principle of fault‑tolerant design.

Q12. In which layer would you implement a timeout‑based retransmission mechanism to achieve fault tolerance for lost packets?

A. Physical layer ✅
B. Network layer
C. Transport layer
D. Application layer

💡 Difficulty: medium | ✅ Correct: A

📖 Explanation:

Timeout‑based retransmissions are handled by the transport layer (e.g., TCP), making C correct. The physical layer (A) deals with raw bits, not timers. The network layer (B) routes packets but does not manage retransmission timers. The application layer (D) may implement its own retries but relies on lower‑layer services for reliable delivery. Implementing retransmission at the transport layer ensures end‑to‑end fault tolerance, as seen in TCP’s reliable communication model.
