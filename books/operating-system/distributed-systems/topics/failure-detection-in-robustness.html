What is Failure detection in Robustness?

Definition:
Failure detection identifies malfunctioning components through heartbeat monitoring or timeout mechanisms, with detection time \( T_d \) and accuracy trade-offs.

Example:
ZooKeeper ensemble detecting leader failure when heartbeats cease for configured interval.

Reason:
Timely and accurate failure detection enables rapid response, preventing cascading failures and maintaining system availability in distributed environments.

📝 All Failure detection in Robustness MCQs

Q1. Which technique commonly used for failure detection involves processes periodically sending short messages to each other?

A.Heartbeat ✅
B.Token passing
C.Checkpointing
D.Election
💡 Difficulty: easy | ✅ Correct: A

📖 Explanation: Heartbeat messages are tiny signals that each process sends at regular intervals to indicate it is alive. When a heartbeat stops, the receiver suspects a failure. Token passing is a mutual‑exclusion protocol, checkpointing records state for recovery, and election selects a leader. In real systems, heartbeats let a monitoring service quickly notice a crashed server and trigger a replacement or fail‑over.

Q2. Why is failure detection considered more challenging in asynchronous distributed systems than in synchronous systems?

A.Because clocks are synchronized
B.Because message delays are unpredictable ✅
C.Because there are fewer nodes
D.Because network bandwidth is unlimited
💡 Difficulty: easy | ✅ Correct: B

📖 Explanation: Asynchronous systems make no assumptions about upper bounds on message delivery time or processing speed, so a delayed message can be mistaken for a failure. Without a known bound, detectors must balance speed against false alarms. Synchronous systems provide guaranteed timing, simplifying detection. In practice, cloud services must tune timeouts carefully because network latency can vary widely, increasing detection difficulty.

Q3. How does the timeout interval affect the trade‑off between detection speed and false positives in a failure detector?

A.Shorter timeout leads to slower detection but fewer false positives
B.Longer timeout leads to faster detection
C.Shorter timeout leads to faster detection but more false positives ✅
D.Timeout does not affect false positives
💡 Difficulty: medium | ✅ Correct: C

📖 Explanation: A short timeout lets a detector declare a failure quickly, but if the network is slow it may mistakenly suspect a healthy node, creating false positives. A longer timeout reduces the chance of mistaken suspicions but delays real failure recognition. The correct choice depends on the expected network latency and the cost of false alarms. Real‑world monitoring tools often expose this timeout as a configurable parameter.

Q4. What is the main advantage of using a failure detector that provides 'suspicions' rather than definitive crash reports?

A.It guarantees no false suspicions
B.It reduces network traffic to zero
C.It eliminates the need for retries
D.It allows the system to continue operating while handling uncertainty ✅
💡 Difficulty: medium | ✅ Correct: D

📖 Explanation: Suspicion‑based detectors acknowledge that information may be incomplete; they flag a process as possibly failed, allowing other components to proceed while awaiting confirmation. This avoids halting the whole system due to a single ambiguous event. Guarantees of no false suspicions are impossible in asynchronous environments, and traffic is not eliminated. Systems like peer‑to‑peer overlays rely on such probabilistic detectors to maintain progress despite occasional uncertainty.

Q5. In a system employing a gossip‑based failure detection protocol, what property ensures that information about a suspected failure eventually reaches all nodes?

A.Epidemic spread ✅
B.Centralized coordinator
C.Fixed routing tables
D.Deterministic broadcast
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: Gossip protocols work by each node periodically selecting random peers and exchanging state, causing information to spread exponentially—an epidemic. This property ensures that, given enough rounds, a suspicion about a failure propagates to every participant. A centralized coordinator would create a single point of failure, fixed routing tables limit flexibility, and deterministic broadcast assumes a stable schedule, none of which provide the robustness of epidemic dissemination in dynamic networks.

Q6. A distributed database uses a heartbeat interval of 2 seconds and a timeout of 5 seconds. If a network partition causes a delay of 4 seconds for heartbeats, which outcome is most likely?

A.The detector will immediately declare the node dead
B.The detector will suspect failure of the partitioned node ✅
C.No suspicion will be raised
D.The system will increase the heartbeat interval automatically
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: With a 2‑second heartbeat, the next signal arrives 4 seconds late, so the elapsed time since the last heartbeat becomes 4 s + 2 s = 6 s, exceeding the 5‑second timeout. The detector therefore marks the node as suspected. It will not instantly declare the node dead because the timeout threshold has not been crossed yet, and automatic interval adjustments are not typically triggered without explicit logic.

Q7. Consider a system with N processes where each process sends a ping to every other process every \(T\) seconds. The network can deliver messages with latency up to \(L\) seconds. To guarantee that a real crash is detected within \(D\) seconds with at most one false suspicion, which inequality must hold?

A.\(D \ge T + L\) and \(T \le L\)
B.\(D \ge 2T\) and \(L < T\)
C.\(D \ge T + L\) and \(T > L\) ✅
D.\(D \ge L\) and \(T = D\)
💡 Difficulty: hard | ✅ Correct: C

📖 Explanation: A crash will be noticed after the last successful ping plus the maximum latency, so detection time must be at least \(T + L\). To avoid false suspicions, the ping period must exceed the worst‑case latency, i.e., \(T > L\). Option C captures both requirements, while the other options either reverse the inequality or ignore the latency constraint, leading to either premature suspicions or delayed crash detection.

Q8. A microservice architecture uses a failure detector that adapts its timeout based on observed round‑trip times (RTT). After a sudden increase in network latency, the detector's timeout is set to \( \mu + 3\sigma \) where \( \mu = 100\) ms and \( \sigma = 20\) ms. What timeout value does the detector use, and how does this choice affect detection?

A.140 ms; it may cause many false suspicions
B.120 ms; it speeds detection but increases false positives
C.200 ms; it greatly delays detection
D.160 ms; it balances detection speed and false positives ✅
💡 Difficulty: hard | ✅ Correct: D

📖 Explanation: Plugging the numbers gives \(100 + 3 \times 20 = 160\) ms. Setting the timeout three standard deviations above the mean protects against typical jitter while still reacting relatively quickly to genuine failures. A shorter timeout (e.g., 120 ms) would raise false alarms during normal latency spikes, whereas a much larger timeout (200 ms) would delay failure recognition, potentially harming service‑level objectives.

Q9. In a blockchain network, nodes employ a failure detector that marks a peer as suspected after missing \(k\) consecutive block proposals. If blocks are generated every 10 seconds and the network experiences occasional delays of up to 6 seconds, what is the maximum \(k\) that balances timely detection with low false suspicion?

A.1
B.2 ✅
C.3
D.4
💡 Difficulty: hard | ✅ Correct: B

📖 Explanation: If a block is delayed by 6 s, the interval between two successive proposals can stretch to 16 s. Missing two proposals would imply a gap of up to 32 s, far exceeding typical delay, so a suspicion after two missed blocks is reasonable. One missed block (k = 1) could be a normal delay, leading to premature suspicions. Larger values (k = 3 or 4) would postpone detection unnecessarily. Thus, \(k = 2\) offers the best trade‑off.

Q10. Which statement correctly describes the relationship between strong completeness and eventual accuracy in failure detectors?

A.Strong completeness guarantees that every crashed process is eventually suspected, while eventual accuracy guarantees that no correct process is permanently suspected ✅
B.Strong completeness guarantees no false suspicions
C.Eventual accuracy means all failures are detected instantly
D.Strong completeness and eventual accuracy are unrelated
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: Strong completeness means that every process that actually crashes will, at some point, be suspected by every other correct process. Eventual accuracy ensures that a correct process is not forever suspected; any temporary suspicion must eventually be cleared. The other options either deny false suspicions (impossible in asynchronous settings), claim instant detection (unrealistic), or suggest no connection, which contradicts the formal definitions used in distributed algorithms.

Q11. Why might a system choose an unreliable failure detector over a reliable one despite higher risk of false suspicions?

A.Because it reduces detection latency ✅
B.Because it eliminates the need for heartbeats
C.Because it ensures zero false positives
D.Because it simplifies implementation
💡 Difficulty: hard | ✅ Correct: A

📖 Explanation: Unreliable detectors can declare a failure quickly, often using short timeouts or minimal communication, which is valuable when rapid response outweighs occasional false alarms—for example, in high‑frequency trading where milliseconds matter. The other options are inaccurate: eliminating heartbeats is rare, guaranteeing zero false positives is impossible in asynchronous environments, and implementation simplicity is not the primary driver for choosing unreliability.]
