What is Naming and transparency in Distributed Systems?

Definition:
Naming and transparency hide distribution aspects so resources appear local, achieving access, location, migration, and replication transparency simultaneously.

Example:
NFS mounting remote directory locally where applications read/write files without knowing physical server location.

Reason:
Transparency simplifies application development and enhances portability by decoupling logical resource usage from physical deployment topology.

Q1. A network administrator pins the ARP entry for a heavily used server. Which outcome is most likely?

A.The server's MAC address will never change in the cache ✅
B.The ARP entry will be refreshed every 30 seconds
C.The server will be unreachable
D.The ARP cache will grow indefinitely
💡 Difficulty: easy | ✅ Correct: A

📖 Explanation: Pinning an ARP entry means the cache entry is kept even if the normal timeout expires. Therefore the MAC address remains stored and is not removed, ensuring fast look‑ups for that host. Option A describes this behavior, so it is correct. Option B is wrong because pinning prevents periodic refreshes; the entry stays static until manually changed. Option C is incorrect because pinning does not block communication. Option D is false because the cache size is unchanged; only the entry is protected from eviction. In practice, keeping the MAC address cached reduces latency for frequent traffic.

Q3. Why does the Ethernet data‑link‑layer header often change as a packet traverses routers?

D.Routers add a new IP header without touching the Ethernet header
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: Each router operates at the data‑link layer only for the local segment, so it must insert the MAC address of the next hop as the destination and its own interface MAC as the source. Option C misstates the behavior; the Ethernet header is rewritten, not left untouched. Option D confuses the IP layer with the Ethernet layer; routers modify the Ethernet header, not merely add an IP header. The change ensures proper delivery across each segment of the network.

Option C describes a broadcast, which is not used for unicast routing. Option D confuses name resolution (DNS) with MAC address resolution; DNS provides an IP, not a MAC. Understanding this flow is key for designing routing and addressing schemes.

Updating the server’s routing table (option C) is unrelated to the client’s ARP problem. Promptly correcting the ARP entry restores proper layer‑2 communication.

Q7. What is the primary purpose of the checksum in the Ethernet trailer, and what would likely occur if it were omitted?

D.It acts as a routing tag; without it, switches could not forward the frame
💡 Difficulty: hard | ✅ Correct: A

📖 Explanation: The Ethernet trailer contains a cyclic redundancy check (CRC) value that receivers recompute to verify that the frame arrived without bit errors. Encryption (option B) is not performed by the Ethernet trailer. Timestamping (option C) is not a function of the CRC. Routing tags (option D) are unrelated to Ethernet framing; switches use MAC addresses, not checksums, for forwarding. Maintaining the checksum is essential for reliable Ethernet communication.

Q11. Why is the Ethernet (MAC) address placed at the start of an Ethernet frame?

A.Because the data‑link layer uses it to determine the frame’s length.

This early check prevents unnecessary processing of unrelated traffic. Length determination is handled by the length/type field, not the MAC address, and routers modify only the outer Ethernet header, not the address itself. Checksums are located in the trailer, not the leading address.

Q13. When a packet traverses two routers, which part of the packet is typically rewritten at each hop?

The application payload is never altered by routers, making options B, C, and D incorrect.

This request prompts the correct host to reply with its MAC, after which the router can encapsulate the packet and forward it. Dropping the packet or sending ICMP would be premature, and using the default gateway's MAC would not reach the intended next hop.

Q38. When an Ethernet frame leaves a LAN and enters a WAN via a router, which part of the frame is most likely to be rewritten?

A.Destination MAC address ✅
B.Source MAC address
C.EtherType field
D.Payload data
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: The router replaces the source MAC address with its own MAC for the outgoing interface, ensuring that the next device sees the correct sender. The destination MAC is preserved until the frame reaches the final host on the LAN. EtherType remains unchanged because it identifies the encapsulated protocol, and the payload is not altered by the router. This rewrite is essential for proper link‑layer forwarding across different network segments.

Q39. How does the ARP cache help improve network performance on a LAN?

A.It stores recent IP‑to‑MAC mappings, reducing broadcast traffic
B.It encrypts all outgoing frames ✅
C.It assigns IP addresses to new hosts
D.It prioritizes traffic based on MAC addresses
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: By caching IP‑to‑MAC associations, the ARP cache eliminates the need for repeated broadcast ARP requests each time a host communicates with a known peer. This reduces unnecessary network traffic and speeds up frame construction. Encryption and address assignment are handled by other protocols, and traffic prioritization is a function of Quality of Service mechanisms, not ARP caching.

Q40. What is the role of the Ethernet trailer checksum in ensuring data integrity?

A.It allows the receiver to detect corruption during transmission
B.It determines the frame's maximum length
C.It signals the end of a TCP segment ✅
D.It indicates the type of service requested
💡 Difficulty: medium | ✅ Correct: C

📖 Explanation: The trailer checksum provides a simple error‑detecting code that the receiving NIC can verify against the computed checksum of the received bits. If a mismatch occurs, the frame is discarded, preventing corrupted data from reaching higher‑layer protocols. Frame length is defined by the length field, TCP segmentation is managed by the TCP header, and service type is indicated elsewhere, not by the checksum.

Q41. Why must all headers above the 802.3 layer be included as data in Ethernet packets?

A.Because lower layers only encapsulate higher‑layer data, preserving end‑to‑end information
B.Because Ethernet cannot process higher‑layer protocols directly
C.Because it simplifies routing decisions
D.Because it reduces packet size ✅
💡 Difficulty: medium | ✅ Correct: D

📖 Explanation: Higher‑layer protocols (IP, TCP, etc.) rely on their headers to route and reassemble data correctly. Ethernet, as a data‑link layer, treats everything above 802.3 as payload, so those headers must travel unchanged within the frame. This design maintains the integrity of the original message across multiple hops. Ethernet does not interpret these headers, routing is performed by network‑layer devices, and packet size is governed by the MTU, not by header inclusion.

Q42. If a host is removed from the network but its MAC address remains pinned in another host's ARP cache, what is the most likely outcome when the latter sends a packet to the removed host?

A.The packet is delivered to the wrong host ✅
B.The packet is dropped after a timeout
C.The packet is sent to the pinned MAC but receives no response
D.The router corrects the address automatically
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: The sending host will address the frame to the stale MAC address, causing the frame to be placed on the medium. Since the original host is no longer present, no device will recognize the MAC, and the frame will be ignored, leading to no response. The sender may eventually retransmit after higher‑layer timeouts. The network does not automatically correct the address, and the packet is not delivered to a different host unless MAC address reuse occurs.

Q43. Two hosts, X and Y, are on different VLANs but share the same IP address due to a misconfiguration. Both have their correct MAC addresses pinned in each other's ARP caches. When X sends a packet to Y's IP, what is the most probable behavior on the network?

A.Both hosts will receive the frame and may respond, causing duplicate ARP replies
B.The switch will drop the frame because of a MAC address conflict ✅
C.The router will generate an ICMP redirect
D.The packet will be delivered to X itself due to loopback
💡 Difficulty: hard | ✅ Correct: B

📖 Explanation: Because the Ethernet switch forwards frames based on MAC addresses, the frame destined for Y's MAC will arrive at the port where X is connected, causing a collision of address expectations. The duplicate IP creates ambiguity, and the switch may discard the frame to avoid forwarding to an incorrect destination. ICMP redirects are generated by routers, not switches, and loopback would not occur in this scenario.

Q44. A router periodically ages out ARP entries after 20 minutes of inactivity. A host sends a burst of traffic to a remote server, then remains idle for 25 minutes before sending another packet. What must the router do to forward the new packet?

A.Re‑broadcast an ARP request for the next‑hop MAC
B.Use the stale MAC entry
C.Send an ICMP Time Exceeded message ✅
D.Drop the packet silently
💡 Difficulty: hard | ✅ Correct: C

📖 Explanation: Since the ARP entry has expired, the router no longer knows the MAC address of the next hop. It must issue a new ARP request on the appropriate interface to learn the current MAC, then forward the packet once the reply is received. Using a stale entry could result in misdelivery, and ICMP Time Exceeded applies to TTL expiration, not ARP aging. Silent dropping would cause unnecessary packet loss.

Q45. Why are Ethernet frames not suitable for direct transmission over WAN links without encapsulation?

A.WAN technologies use different physical and data‑link protocols, requiring appropriate encapsulation
B.Ethernet frames are too large for WAN MTU limits
C.Ethernet frames lack routing information
D.WAN links cannot handle Ethernet's checksum ✅
💡 Difficulty: hard | ✅ Correct: D

📖 Explanation: WAN media such as MPLS, PPP, or ATM employ distinct framing and signaling mechanisms that cannot interpret raw Ethernet frames. Therefore, Ethernet frames must be encapsulated within the WAN's own data‑link protocol to traverse the link correctly. While MTU and routing considerations are also factors, the primary reason is the incompatibility of the underlying link‑layer formats.

Q46. During a high‑traffic period, a NIC receives an Ethernet frame whose trailer checksum does not match the computed value. What action does the NIC typically take, and what downstream effect does this have on the TCP connection?

A.Discard the frame and request retransmission, causing TCP to trigger fast retransmit ✅
B.Accept the frame but flag an error for the OS
C.Forward the frame with an error flag to upper layers
D.Modify the checksum to match the computed value
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: When a checksum mismatch is detected, the NIC drops the corrupted frame and does not pass it upward. The TCP layer, unaware of the loss, will eventually notice the missing acknowledgment and invoke its retransmission mechanisms, often entering fast retransmit after duplicate ACKs. Accepting the frame would propagate errors, and altering the checksum would conceal corruption, both of which are not standard NIC behavior.
