What is Wide-area networks in Distributed Systems?

Definition:
Wide-area networks (WANs) connect geographically dispersed sites over long distances using leased lines or internet, with higher latency \( L \gg L_{\text{LAN}} \).

Example:
Multinational corporation linking branch offices across continents via MPLS or VPN tunnels.

Reason:
WANs enable global distribution of services and data, supporting truly distributed systems despite inherent performance trade-offs compared to LANs.

Q1. What is the definition of process migration in a distributed computing environment?

A.Transferring data files from one server to another
B.Moving an executing process or its parts from one host to another to continue execution ✅
C.Duplicating a process on multiple machines simultaneously
D.Shutting down a process after completion
💡 Difficulty: easy | ✅ Correct: B

📖 Explanation: The correct answer is B because process migration specifically refers to moving a live process—or portions of it—from one machine to another so that execution can continue without starting over. Option A describes data transfer, not execution state movement. Option C suggests replication, which is a different concept called cloning. Option D is about termination, which is the opposite of migration. In real systems, migration lets a job continue on a less‑loaded server, preserving work already done.

Q2. Which term describes the distribution of work across multiple computers to improve overall system performance?

A.Caching
B.Load balancing ✅
C.Routing
D.Virtualization
💡 Difficulty: easy | ✅ Correct: B

📖 Explanation: Load balancing is the practice of spreading tasks among several computers so that no single machine becomes a bottleneck, thereby boosting performance. Caching stores copies of data for faster access, not workload distribution. Routing determines paths for network packets, unrelated to task allocation. Virtualization abstracts hardware resources but does not inherently balance load. In a data‑center, load balancing ensures web requests are spread across servers, keeping response times low.

Q3. Why might a system choose to migrate a process to a site with specialized hardware?

A.Because the specialized hardware can execute certain operations more efficiently ✅
B.Because the remote site has a higher bandwidth connection
C.Because the user prefers a different operating system
D.Because it reduces the number of processes overall
💡 Difficulty: easy | ✅ Correct: A

📖 Explanation: Option A is correct: specialized hardware—such as an array processor for matrix inversion—can perform specific calculations far faster than a general‑purpose CPU, making migration advantageous. Option B mentions bandwidth, which matters for data transfer but not for execution speed. Option C focuses on OS preference, which is a software issue, not hardware capability. Option D misinterprets migration as reducing process count, which is not the primary goal. In practice, moving a simulation to a GPU‑enabled node speeds up results dramatically.

Q4. A research lab needs to run a large‑scale simulation that requires an array processor unavailable locally. Which migration approach should they use?

A.Implicit migration handled automatically by the system
B.Explicit migration specified by the user
C.No migration; they must wait for hardware upgrade ✅
D.Hybrid migration combining both methods
💡 Difficulty: medium | ✅ Correct: C

📖 Explanation: The correct choice is B because the lab must explicitly direct the simulation to the remote site that hosts the array processor; the system cannot guess this hardware preference automatically. Implicit migration (A) works well for load balancing on homogeneous machines but does not consider unique hardware needs. Option C wastes time waiting for upgrades, and hybrid (D) adds unnecessary complexity. By explicitly requesting migration, the lab ensures the simulation runs on the optimal hardware, achieving faster turnaround.

Q5. How does data‑access locality influence the decision to migrate a process?

A.Processes are moved only when data size exceeds network bandwidth
B.Processes are moved if the required data resides close to the execution site ✅
C.Data is always transferred before any migration occurs
D.Locality has no impact on migration decisions
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: Option B is correct: when the data needed by a process is already stored near a remote computer, moving the process to that location reduces the amount of data that must travel across the network, improving efficiency. Option A incorrectly ties the decision solely to bandwidth thresholds, ignoring the benefit of proximity. Option C assumes data must move first, which defeats the purpose of migration. Option D dismisses locality, contrary to real‑world practice where proximity often dictates migration choices. For example, moving a data‑intensive analytics job to the storage node cuts transfer time dramatically.

Q6. A cloud provider has ten identical servers handling web requests. To prevent any single server from becoming overloaded, which technique should be used?

A.Explicit user‑specified migration
B.Implicit migration hidden from the client ✅
C.Manual redistribution of processes each hour
D.Disabling migration entirely
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: Implicit migration (B) is the appropriate technique because it automatically balances load across homogeneous servers without requiring the client to alter code or specify locations. Explicit migration (A) would need user input and is unnecessary for simple load balancing. Manual redistribution (C) is inefficient and prone to error. Disabling migration (D) would worsen overload problems. In practice, the provider’s load balancer silently redirects sessions to less‑busy instances, maintaining smooth performance.

Q7. What is the primary advantage of using process migration for computation speedup?

A.It allows a process to run on multiple machines simultaneously ✅
B.It reduces the total turnaround time by executing subprocesses concurrently on different sites
C.It eliminates the need for any data transfer
D.It guarantees lower power consumption
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: The key benefit is B: by splitting a process into subprocesses that run concurrently on separate machines, the overall execution time can be shortened, achieving speedup. Option A describes parallel execution, not migration of a single process. Option C is false because some data movement is often required. Option D may be a side effect but is not the main reason for speedup. For instance, a video‑encoding task divided across several nodes finishes faster than when run on a single server.

Q8. A software firm has a legacy analytics library that only runs on a Windows server. Which migration strategy should they adopt for a Linux‑based client needing the analytics?

A.Implicit migration without user involvement
B.Explicit migration where the client specifies the Windows server ✅
C.Do not migrate; rewrite the library for Linux
D.Transfer the library code to the client machine
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: Explicit migration (B) is correct because the client must direct its job to the Windows server that hosts the required library; the system cannot automatically infer this software dependency. Implicit migration (A) works for homogeneous environments but cannot handle a specific OS requirement. Rewriting the library (C) is costly and beyond the immediate need. Transferring the code (D) would violate licensing or compatibility constraints. By explicitly invoking the Windows server, the client accesses the needed functionality while preserving existing assets.

Q9. A multinational corporation must process large datasets originating from Europe, but its compute cluster is in Asia. Bandwidth is limited, and latency is high. Which migration decision best balances performance and network cost?

A.Migrate the entire dataset to Asia and run locally ✅
B.Migrate the process to Europe and execute near the data
C.Split the data evenly between both continents
D.Do not migrate; process data sequentially on the original site
💡 Difficulty: hard | ✅ Correct: A

📖 Explanation: The optimal choice is B: moving the process to the European site where the data resides avoids transferring huge datasets over a constrained link, reducing latency and bandwidth expenses while still achieving computation. Option A would require moving massive data across the network, incurring high cost and delay. Option C still necessitates significant cross‑regional transfers. Option D leaves the process unchanged, missing the opportunity for speedup. In real deployments, placing compute close to data—often called “data‑locality‑aware migration”—yields the best trade‑off.

Q10. Why is process migration more challenging in heterogeneous environments than in homogeneous ones?

A.Because heterogeneous systems have identical instruction sets
B.Because resource differences require explicit handling of code compatibility and data formats ✅
C.Because homogeneous systems cannot share processes
D.Because heterogeneity eliminates the need for migration
💡 Difficulty: hard | ✅ Correct: B

📖 Explanation: Option B is correct: heterogeneous machines differ in CPU architecture, operating systems, and available libraries, so migrating a process demands translation of binaries, adaptation of data representations, and possibly recompilation, making it complex. Option A is false; identical instruction sets simplify migration. Option C misstates that homogeneous systems cannot share processes—they actually can do so easily. Option D incorrectly claims heterogeneity removes migration need. In practice, moving a Windows binary to a Linux server often fails without compatibility layers, illustrating the added difficulty.

Q11. Explain how limited network bandwidth affects the choice between moving a process versus moving its data.

A.Low bandwidth always favors moving data
B.Low bandwidth always favors moving the process
C.The decision depends on the relative sizes of the process state and the dataset ✅
D.Bandwidth does not influence migration decisions
💡 Difficulty: hard | ✅ Correct: C

📖 Explanation: The correct answer is C because when bandwidth is scarce, the optimal strategy hinges on whether the process’s state (code, stack, etc.) is smaller than the dataset it needs. If the state is tiny, moving the process saves bandwidth; if the dataset is smaller, transferring data is preferable. Option A and B are absolute statements that ignore this trade‑off. Option D denies bandwidth’s impact, which is contrary to real‑world networking considerations. For example, a lightweight analytics script may be shipped to a remote server to avoid sending gigabytes of raw logs.

Q12. A real‑time video‑streaming service must decide whether to migrate a transcoding process to a remote edge node. Which factor is most critical to maintain low latency?

A.The processing power of the edge node
B.The distance between the client and the edge node ✅
C.The size of the source video file
D.The number of concurrent users
💡 Difficulty: hard | ✅ Correct: B

📖 Explanation: Option B is most critical because latency is primarily driven by the physical distance (and thus propagation delay) between the client and the processing location; moving transcoding closer to the client reduces round‑trip time. While processing power (A) matters for throughput, it does not directly affect latency if the node is far away. The source file size (C) influences transfer time but is secondary to distance in real‑time constraints. The number of users (D) impacts load but not the fundamental latency of a single stream. Edge computing therefore places transcoding at the nearest node to keep delays minimal.

Q13. A government agency restricts process migration to servers within the same security domain. Which migration approach complies with this policy while still allowing load balancing?

A.Implicit migration across all networked servers
B.Explicit migration that specifies a destination within the same domain ✅
C.Hybrid migration that randomly selects any server
D.Disabling migration entirely
💡 Difficulty: hard | ✅ Correct: B

📖 Explanation: Explicit migration (B) satisfies the policy because the user can direct the process to a server that resides in the authorized security domain, ensuring compliance while still enabling load distribution. Implicit migration (A) might inadvertently select unauthorized servers. Hybrid migration (C) introduces randomness that could violate domain restrictions. Disabling migration (D) eliminates load balancing benefits. In practice, administrators often require users to specify target hosts that meet security criteria, preserving both policy adherence and performance gains.

Q14. How does process migration differ from computation migration?

A.Process migration moves only data, while computation migration moves both code and data ✅
B.Process migration involves moving a running process, whereas computation migration typically moves a task or job before execution
C.Process migration requires no network communication, unlike computation migration
D.Both terms describe the exact same operation
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: The correct distinction is B: process migration concerns relocating an already executing process—including its state, stack, and open resources—while computation migration generally refers to moving a task or job that has not yet started, transferring only code and input data. Option A reverses the roles of code and data. Option C is incorrect because both techniques rely on network communication to transfer state or code. Option D falsely claims they are identical. Understanding this difference helps designers choose the right strategy; for example, a live service may need process migration to avoid downtime, whereas a batch job can use computation migration.
