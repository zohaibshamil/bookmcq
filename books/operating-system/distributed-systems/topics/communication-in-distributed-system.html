What is Communication in distributed system?

Definition:
Communication is the fundamental mechanism enabling message exchange between distributed processes, characterized by latency and bandwidth .

Example:
Microservices exchanging JSON payloads via REST APIs to coordinate order processing in an e-commerce application.

Reason:
Without reliable communication primitives, distributed components cannot coordinate state, share results, or maintain consistency across the system.

📝 All Communication in distributed system MCQs

Q1. What term describes a node that provides resources to other nodes in a distributed system?

A.Server ✅
B.Client
C.Site
D.Host
💡 Difficulty: easy | ✅ Correct: A

📖 Explanation: A server is the node that offers resources such as files, printers, or processing power to other nodes. The client requests those resources, while a site refers to a physical location and a host is a generic term for a machine. Choosing the server reflects the role of providing services, which matches the definition. The other options describe requesters or broader categories, not the provider.

Q2. Why does resource sharing increase overall system efficiency in a distributed environment?

A.Because local resources are always faster
B.Because remote resources reduce duplication of hardware
C.Because it allows parallel processing across nodes ✅
D.Because it eliminates the need for a network
💡 Difficulty: medium | ✅ Correct: C

📖 Explanation: Resource sharing lets multiple nodes work on different parts of a task simultaneously, which speeds up overall execution. By using remote resources, idle machines become productive, reducing the need to purchase duplicate hardware. Parallel processing is the key benefit, whereas the other choices either misstate the effect of locality, ignore the advantage of parallelism, or incorrectly claim that networks become unnecessary.

Q3. How does reliability improve when several nodes can provide the same service?

A.Through load balancing
B.Through redundancy ✅
C.By increasing network latency
D.By decreasing throughput
💡 Difficulty: hard | ✅ Correct: B

📖 Explanation: When multiple nodes can supply identical services, the system gains redundancy: if one node fails, others can take over, maintaining service continuity. Load balancing distributes work but does not directly address failure. Increased latency and decreased throughput are negative effects that would reduce reliability. Redundancy directly supports fault tolerance, which is why the correct answer is redundancy, reflecting the core principle of reliable distributed design.

Q4. A company has a high‑speed printer at site B, and users at site A need to print documents. Which action best uses a distributed‑system advantage?

A.Install a local printer at site A
B.Send the print job over the network to the printer at site B ✅
C.Email the document to a colleague at site B for manual printing
D.Copy files to a USB drive and transport them to site B
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: Transmitting the print job across the network leverages resource sharing, allowing users to access a remote device without duplicate hardware. Installing a local printer ignores the sharing benefit, emailing still requires manual handling, and using a USB drive adds unnecessary latency. The networked approach demonstrates how distributed systems enable remote resource utilization efficiently.

Q5. A scientific task can run on a single 2.5 GHz supercomputer or be divided among three sites with speeds 2 GHz (A), 1.5 GHz (B), and 2.5 GHz (C). Which strategy gives the greatest speedup?

A.Run the whole task on site C only
B.Run the whole task on site A only
C.Distribute subtasks proportionally to each site’s speed ✅
D.Run the whole task on site B only
💡 Difficulty: hard | ✅ Correct: C

📖 Explanation: Dividing the workload proportionally matches each node’s processing capability, allowing faster nodes to handle more work while slower nodes still contribute. This parallelism reduces total execution time more than using any single node alone. Choosing only site C or A ignores the extra computing power available elsewhere, and using only site B would be the slowest option. The proportional distribution therefore yields the maximum speedup.

Q6. A distributed database must keep copies consistent after updates. Which communication pattern most reliably spreads changes?

A.Broadcast
B.Unicast
C.Multicast
D.Gossip ✅
💡 Difficulty: medium | ✅ Correct: D

📖 Explanation: Gossip protocols repeatedly exchange state information between random peers, ensuring that updates eventually reach all nodes even if some links fail. Broadcast sends to all nodes at once but can overwhelm the network; unicast targets a single node and would require many separate messages; multicast reaches a group but still depends on reliable group management. Gossip’s resilience and eventual consistency make it the best choice for reliable propagation in a distributed setting.

Q7. What is the key distinction between a \site\ and a \node\ in distributed‑system terminology?

A.A site is a physical location, while a node is the logical system at that location ✅
B.A site is software, a node is hardware
C.A site always acts as a client, a node always acts as a server
D.They are interchangeable terms
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: A site refers to the geographic or network location where a machine resides, whereas a node denotes the actual computing entity (hardware and software) operating at that site. This separation clarifies design discussions. The other options incorrectly equate site with software, fix roles as client or server, or claim the terms are synonymous, which does not reflect standard terminology.

Q8. A user at site A needs to read a file stored on a server at site B. Which communication model is typically used?

A.Client‑server ✅
B.Peer‑to‑peer
C.Broadcast
D.Multicast
💡 Difficulty: easy | ✅ Correct: A

📖 Explanation: In a client‑server model, the user’s machine (client) sends a request to the remote server, which then provides the file. Peer‑to‑peer treats all machines as equals, which is unnecessary for a simple request. Broadcast and multicast send data to many recipients, wasting bandwidth when only one client needs the file. Therefore, the client‑server approach correctly describes the typical interaction for remote file access.
