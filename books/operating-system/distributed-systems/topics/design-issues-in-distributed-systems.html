What is Design Issues in Distributed Systems?

Definition:
Design issues encompass fundamental challenges including heterogeneity, openness, security, scalability, and concurrency control in distributed environments.

Example:
Choosing between strong consistency (CAP theorem trade-off) versus availability when designing globally distributed database.

Reason:
Addressing these issues systematically prevents architectural flaws that compromise system correctness, performance, or maintainability in production deployments.

📝 All Design Issues in Distributed Systems MCQs

Q1. Which transport-layer protocol provides reliable, connection‑oriented communication?

A.UDP
B.TCP ✅
C.IP
D.FTP
💡 Difficulty: easy | ✅ Correct: B

📖 Explanation: The correct answer is TCP because it establishes a connection, ensures ordered delivery, and retransmits lost segments, providing reliability. UDP is connectionless and does not guarantee delivery, so it is incorrect. IP operates at the network layer and does not handle reliability. FTP is an application‑layer protocol that relies on TCP for transport, making it unsuitable as the answer. Understanding TCP’s role helps students choose the right protocol for dependable data transfer.

Q2. Why were many early Internet protocols designed with weak authentication and clear‑text transmission?

A.To simplify implementation
B.To reduce latency
C.To conserve bandwidth
D.All of the above ✅
💡 Difficulty: easy | ✅ Correct: D

📖 Explanation: All three reasons contributed to the design choices: developers favored simple code that could be written quickly, minimized processing delays, and saved scarce bandwidth on early networks. Consequently, protocols often omitted strong authentication and sent data in clear text. Options A, B, and C each capture part of this rationale, but only D combines them, reflecting the historical trade‑off between security and performance.

Q3. How does the TCP/IP model differ from the OSI model regarding the link and physical layers?

A.It merges them into a single layer
B.It omits them entirely ✅
C.It defines them as separate
D.It treats them as optional
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: The TCP/IP model does not formally define separate link and physical layers, allowing its protocols to run over any underlying network technology. This omission distinguishes it from the OSI model, which explicitly includes Data Link and Physical layers. Therefore option B is correct. Options A, C, and D misrepresent the TCP/IP architecture, which relies on the underlying network without naming those layers.

Q4. What is the primary security benefit of adding strong authentication to a protocol that already uses encryption?

A.Prevents data loss
B.Guarantees data integrity
C.Confirms identity of parties ✅
D.Increases throughput
💡 Difficulty: medium | ✅ Correct: C

📖 Explanation: Strong authentication verifies that the communicating entities are who they claim to be, which is essential even when data is encrypted. Encryption protects confidentiality, but without authentication an attacker could impersonate a legitimate party. Options A and B describe other security goals, while D is unrelated. Thus, confirming identity (option C) is the key advantage of adding authentication.

Q5. In the TCP/IP stack, which layer is responsible for routing packets across different networks?

A.Application
B.Transport
C.Internet ✅
D.Data link
💡 Difficulty: medium | ✅ Correct: C

📖 Explanation: The Internet layer handles logical addressing and routing, determining how packets travel from source to destination across multiple networks. This is the core function of the IP protocol. The Application layer provides end‑user services, the Transport layer manages end‑to‑end communication, and the Data Link layer deals with local network framing. Therefore, option C correctly identifies the routing responsibility.

Q6. Explain why adding a multistep handshake for authentication can impact performance in high‑traffic environments.

A.It adds extra round‑trips
B.It requires more CPU
C.It increases packet size
D.All of the above ✅
💡 Difficulty: hard | ✅ Correct: D

📖 Explanation: A multistep handshake introduces additional round‑trip messages, consumes CPU cycles for cryptographic operations, and often enlarges packets with authentication data, all of which can degrade throughput and increase latency under heavy load. Options A, B, and C each describe a component of this impact, but the most complete answer is D, which encompasses all performance‑affecting factors.

Q7. A company needs to securely transfer large backup files nightly to a remote site. Which protocol combination best meets the need for reliability and confidentiality?

A.FTP
B.FTP over TLS ✅
C.HTTP
D.UDP
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: FTP over TLS (often called FTPS) provides the reliable, ordered delivery of TCP‑based FTP while encrypting the data channel, satisfying both reliability and confidentiality requirements. Plain FTP lacks encryption, HTTP is not designed for large file transfers, and UDP does not guarantee delivery. Therefore, option B is the optimal choice for secure nightly backups.

Q8. An IoT sensor uses UDP to send frequent status updates. Which security mechanism can be added with minimal overhead to protect against replay attacks?

A.Full TLS handshake
B.Pre‑shared symmetric MAC ✅
C.RSA signatures
D.No security needed
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: A pre‑shared symmetric message authentication code (MAC) can be appended to each UDP packet, providing integrity and replay protection with very low computational cost, suitable for constrained IoT devices. Full TLS requires a handshake and more processing, RSA signatures are computationally heavy, and ignoring security leaves the sensor vulnerable. Hence, option B offers the best balance of security and efficiency.

Q9. A network administrator must choose a protocol for internal name resolution that does not expose query data to eavesdroppers. Which protocol should be selected?

A.UDP DNS
B.DNS over HTTPS ✅
C.NetBIOS
D.ARP
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: DNS over HTTPS (DoH) encrypts DNS queries within HTTPS, preventing eavesdropping on internal name resolution. Traditional UDP DNS sends queries in clear text, NetBIOS is unrelated to DNS, and ARP resolves MAC addresses, not hostnames. Therefore, option B provides the required confidentiality while preserving standard DNS functionality.

Q10. A developer designs a custom application layer protocol that runs over TCP. To ensure end‑to‑end authentication without modifying the TCP handshake, which technique should be employed?

A.Insert a token in the first data segment
B.Use TCP option field
C.Perform a separate TLS handshake after TCP connection ✅
D.Rely on IP source address
💡 Difficulty: hard | ✅ Correct: C

📖 Explanation: Performing a separate TLS handshake after establishing the TCP connection adds a robust authentication layer without altering TCP itself. Inserting a token or using TCP options would require changes to the TCP implementation, and IP source addresses can be spoofed. Thus, option C is the correct method for secure authentication.

Q11. During a penetration test, an attacker discovers that a legacy FTP server transmits credentials in clear text. Which mitigation strategy provides the most comprehensive protection while preserving existing client software?

A.Switch to SFTP
B.Wrap FTP in SSH tunnel
C.Enable TLS on FTP (FTPS) ✅
D.Use IPsec tunnel
💡 Difficulty: hard | ✅ Correct: C

📖 Explanation: Enabling TLS on FTP (FTPS) encrypts the control and data channels, protecting credentials while allowing existing FTP clients to connect with minimal configuration changes. Switching to SFTP would require a different server and client, wrapping FTP in an SSH tunnel adds complexity, and IPsec protects at the network layer but may not be feasible across all network segments. Hence, option C offers the most comprehensive yet compatible solution.

Q12. Consider a scenario where a web service must authenticate clients and encrypt data, but the underlying network may drop packets. Which combination of protocols best satisfies reliability, confidentiality, and authentication?

A.UDP + DTLS
B.TCP + TLS ✅
C.TCP + IPsec
D.HTTP + Basic Auth
💡 Difficulty: hard | ✅ Correct: B

📖 Explanation: TCP provides reliable, ordered delivery, while TLS adds encryption and mutual authentication, meeting all three requirements despite packet loss. UDP with DTLS lacks reliability, TCP with IPsec encrypts at the network layer but does not inherently provide application‑level authentication, and HTTP with Basic Auth offers only weak authentication without encryption. Therefore, option B is the optimal combination.
