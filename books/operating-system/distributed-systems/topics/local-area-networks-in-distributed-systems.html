What is Local area networks in Distributed Systems?

Definition:
Local area networks (LANs) provide high-bandwidth, low-latency connectivity within limited geographical areas, typically with throughput \( T > 1 \text{ Gbps} \).

Example:
Ethernet-connected workstations in an office building sharing files and printers via a switched network.

Reason:
LANs form the foundational infrastructure for tightly coupled distributed systems where frequent, fast communication is essential for coordination.

Q1. What is process migration?

A. The transfer of a complete file from one server to another
B. The relocation of a running process or its parts to a different node in a network ✅
C. The duplication of a database across multiple sites
D. The shutdown of a process after completion

💡 Difficulty: easy | ✅ Correct: B

📖 Explanation:

Process migration means moving an executing process, or portions of it, to another computer in the network. Option B correctly captures this definition. Options A and C describe unrelated activities (file transfer and database replication), while D describes termination, not migration. Understanding this core idea is essential for any LAN scenario involving distributed execution.

Q2. Why does load balancing often rely on process migration in homogeneous systems?

A. It reduces the number of processes overall
B. It moves processes to under‑utilized machines to spread work evenly ✅
C. It eliminates the need for network communication
D. It guarantees faster hardware execution

💡 Difficulty: easy | ✅ Correct: B

📖 Explanation:

Load balancing aims to distribute work evenly across similar machines. By moving processes to under‑utilized nodes, the system evens out the workload, improving overall performance. Option B states this purpose directly. Option A is incorrect because migration does not reduce process count, C is irrelevant to balancing, and D misstates that migration guarantees hardware speed, which is not its primary goal.

Q3. How does a hardware preference influence the decision to migrate a process?

A. Processes are always executed where they originated
B. Migration is chosen only when software licenses are unavailable
C. The process is moved to a node with specialized hardware that can execute it more efficiently ✅
D. Hardware preference never affects migration decisions

💡 Difficulty: medium | ✅ Correct: C

📖 Explanation:

When a process benefits from specialized hardware (e.g., an array processor for matrix inversion), moving it to a node possessing that hardware can dramatically improve execution speed. Option C correctly describes this rationale. Option A ignores migration benefits, B mixes hardware with software concerns, and D incorrectly claims hardware never matters, contradicting common practice in LAN environments.

Q4. Which statement best distinguishes transparent migration from explicit migration?

A. Transparent migration requires user code changes, explicit migration does not
B. Transparent migration hides the move from the program, explicit migration requires the programmer to specify where and when to move ✅
C. Both methods are identical in practice
D. Explicit migration always results in slower performance

💡 Difficulty: medium | ✅ Correct: B

📖 Explanation:

Transparent migration abstracts the move, allowing the program to continue without awareness of the relocation, which is useful for load balancing in homogeneous systems. Explicit migration asks the programmer to define migration points, often needed for hardware or software constraints. Option B captures this contrast. Option A reverses the definitions, C wrongly claims they are the same, and D incorrectly links explicit migration to performance degradation.

Q5. When data volume is high, why might moving the process rather than the data be advantageous?

A. Moving data is always faster than moving a process
B. Process migration eliminates the need to transfer large datasets across the network, reducing bandwidth usage
C. Transferring data improves security more than moving processes ✅
D. Process migration increases network latency more than data transfer

💡 Difficulty: hard | ✅ Correct: C

📖 Explanation:

If a process requires access to massive datasets, relocating the process to the data's location avoids sending large amounts of data over the network, conserving bandwidth and reducing transfer time. Option C correctly emphasizes the bandwidth advantage. Option A is false because data transfer can be costly; D misstates security benefits; D incorrectly claims migration worsens latency, whereas it often reduces it by proximity to data.

Q6. A company splits a large simulation into three subprocesses to run concurrently on different LAN nodes. Which migration approach is most appropriate?

A. Transparent migration ✅
B. Explicit migration
C. No migration is needed
D. Batch processing

💡 Difficulty: medium | ✅ Correct: A

📖 Explanation:

When the goal is to achieve computation speedup by concurrently executing subprocesses on homogeneous machines, transparent migration lets the system automatically distribute work without programmer intervention. This matches the scenario of a simulation split across nodes. Option A is correct. Explicit migration (B) would require manual placement, unnecessary here. Options C and D do not address the need for concurrent execution across the network.

Q7. In a LAN of identical workstations, an administrator wants to keep CPU usage balanced without user involvement. Which migration technique should be employed?

A. Explicit migration requiring user scripts
B. Transparent migration handled by the OS ✅
C. Manual process relocation by the admin each hour
D. No migration, just add more hardware

💡 Difficulty: medium | ✅ Correct: B

📖 Explanation:

Transparent migration automatically relocates processes to maintain balanced CPU loads, fitting the requirement of no user involvement. The operating system can detect overloads and move processes silently. Option B reflects this. Explicit migration (A) would need user scripts, contradicting the no‑involvement goal. Manual relocation (C) is impractical for dynamic balancing, and D ignores migration altogether.

Q8. A scientific application needs an array processor for matrix inversion, which is only available on a specific server. Which migration method ensures the process runs on the appropriate hardware?

A. Transparent migration
B. Explicit migration specifying the target server ✅
C. Random migration across any node
D. No migration, run locally on a standard CPU

💡 Difficulty: medium | ✅ Correct: B

📖 Explanation:

When a process requires specialized hardware not present on most nodes, the programmer must explicitly direct the process to the server that hosts the array processor. Explicit migration (option B) allows this precise placement. Option A would not guarantee the correct hardware, C is random and unsuitable, and D would force execution on inadequate hardware, leading to poor performance.

Q9. A client must run a program that needs both a GPU for rendering and a licensed database only on a remote server. Which sequence of migrations best satisfies both constraints?

A. First migrate to GPU node, then to database server
B. Migrate simultaneously to both nodes
C. Migrate to database server, then offload rendering to GPU node via remote calls ✅
D. Do not migrate; run locally and access resources over the network

💡 Difficulty: hard | ✅ Correct: C

📖 Explanation:

The program should first move to the server that hosts the licensed database (ensuring software availability), then use remote procedure calls or similar mechanisms to leverage the GPU on another node for rendering tasks. This respects both hardware and software preferences. Option C describes this two‑step approach. Option A reverses the order, potentially violating software licensing, B is infeasible, and D ignores migration benefits.

Q10. In a bandwidth‑constrained LAN, a large data set must be processed. Should the system migrate the process to the data location or transfer the data to the process?

A. Transfer the data to the process regardless of size
B. Migrate the process to the data location to minimize network traffic ✅
C. Always duplicate both data and process
D. Use a third‑party cloud service

💡 Difficulty: hard | ✅ Correct: B

📖 Explanation:

When network bandwidth is limited, moving the process to where the data resides avoids transmitting the large dataset, conserving bandwidth and often reducing overall execution time. Option B correctly identifies this strategy. Option A would overload the network, C is wasteful, and D introduces external variables not addressed in the LAN context.

Q11. How does process migration affect network latency and overall throughput in a LAN environment?

A. It always increases latency and decreases throughput
B. It can reduce latency for data‑intensive tasks by moving computation closer to data, thereby improving throughput ✅
C. It has no impact on latency or throughput
D. It only affects CPU utilization, not network characteristics

💡 Difficulty: hard | ✅ Correct: B

📖 Explanation:

By relocating a process nearer to the required data, the time taken for data requests (latency) decreases, allowing more efficient use of the network and raising overall throughput. Option B captures this benefit. Option A is the opposite of typical behavior, C ignores the network effects, and D mistakenly limits impact to CPU usage, overlooking the interplay between computation and communication.

Q12. A developer wants to run a legacy application that depends on a proprietary library installed only on a specific LAN node. Which migration strategy should be used?

A. Transparent migration to any node
B. Explicit migration directing the process to the node with the library ✅
C. No migration; rewrite the application
D. Random migration across the network

💡 Difficulty: medium | ✅ Correct: B

📖 Explanation:

Because the required library cannot be moved, the process must be explicitly sent to the node that already contains it. Explicit migration (option B) lets the developer specify this target. Transparent migration (A) would not guarantee the correct node, rewriting (C) is unnecessary, and random migration (D) risks missing the needed library, causing failure.
