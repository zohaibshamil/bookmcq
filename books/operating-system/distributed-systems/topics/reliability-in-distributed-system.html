What is Reliability in distributed system?

Definition:
Reliability is the probability that a distributed system continues functioning correctly despite component failures, quantified as for independent components.

Example:
A banking transaction system remains operational even when one data center goes offline due to power failure.

Reason:
Redundancy and replication ensure no single point of failure compromises critical services, maintaining continuous availability for users.

Q1. What is the definition of reliability in a distributed system?

A.Probability that a component performs its intended function without failure for a specified period ✅
B.Speed at which data is transferred
C.Amount of resources shared
D.Degree of coupling between nodes
💡 Difficulty: easy | ✅ Correct: A

📖 Explanation: The correct answer is A because reliability is defined as the probability that a component or system performs its intended function without failure for a given time period. Options B, C, and D describe unrelated concepts such as throughput, resource sharing, and coupling, which do not measure failure avoidance. Understanding this definition helps students recognize that reliability quantifies uptime, a key metric when evaluating distributed systems in real‑world deployments.

Q2. Why does replicating a service on multiple nodes increase the reliability of a distributed system?

A.It reduces network latency
B.It balances load among users
C.If one node fails the others can still provide the service ✅
D.It decreases the amount of code needed
💡 Difficulty: medium | ✅ Correct: C

📖 Explanation: The correct answer is C because when a service is replicated on several nodes, the failure of a single node does not make the service unavailable; the remaining replicas can continue to handle requests. Option A is incorrect since replication does not primarily affect latency. Option B describes load balancing, which is a side effect but not the main reliability benefit. Option D is wrong because replication actually increases code complexity. Recognizing replication’s role in fault tolerance explains why designers use it to achieve higher reliability in production systems.

Q3. How does the concept of fault tolerance relate to reliability in distributed systems?

A.Fault tolerance is unrelated to reliability
B.Fault tolerance mechanisms enable a system to continue operating despite failures, thereby improving reliability ✅
C.Fault tolerance only concerns security
D.Fault tolerance reduces the need for replication
💡 Difficulty: hard | ✅ Correct: B

📖 Explanation: The correct answer is B because fault tolerance refers to a system’s ability to keep operating despite component failures, and this capability directly raises the overall reliability of a distributed system. Option A is false; fault tolerance is a major factor in reliability. Option C is inaccurate because fault tolerance deals with availability, not security. Option D is misleading; while replication is a fault‑tolerance technique, it does not eliminate the need for other mechanisms. Understanding that fault‑tolerant designs preserve service continuity helps explain why reliability improves as more failure‑handling strategies are added.

Q4. Which factor most directly reduces reliability when network latency increases significantly?

A.Higher bandwidth
B.More CPU cycles
C.Larger storage capacity
D.Longer response times ✅
💡 Difficulty: medium | ✅ Correct: D

📖 Explanation: The correct answer is D because longer response times are a direct symptom of increased latency, and they can cause timeouts or user dissatisfaction, which lower the perceived reliability of the system. Option A describes higher bandwidth, which actually helps mitigate latency effects. Option B mentions more CPU cycles, which does not address network delay. Option C refers to larger storage capacity, unrelated to reliability. Recognizing that latency‑induced delays degrade reliability helps engineers prioritize low‑latency network design when building dependable distributed services.

Q5. A client at site A needs a file stored on a server at site B. If the server crashes, which mechanism should the system use to keep the service reliable?

A.Notify the user of failure
B.Redirect the request to a different application
C.Failover to a replica server at site C ✅
D.Cache the file locally
💡 Difficulty: easy | ✅ Correct: C

📖 Explanation: The correct answer is C because a replica server at site C can take over the role of the failed server at site B, ensuring the client still obtains the needed file and the service remains reliable. Option A merely informs the user, which does not maintain service continuity. Option B redirects to a different application, which does not provide the same file. Option D caches the file locally, but caching may be outdated and does not address the immediate failure. Using failover to a replica illustrates a practical technique for preserving reliability in real‑world distributed environments.

Q6. In a system that stores data with a replication factor of 3, how many node failures can be tolerated without losing data?

A.Zero
B.Two ✅
C.Three
D.One
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: The correct answer is B because with a replication factor of three the data is stored on three separate nodes, so the system can lose up to two nodes and still have at least one copy remaining, preserving data availability. Option A suggests no failures can be tolerated, which is false. Option C claims three failures can be tolerated, which would mean no copies left. Option D says only one failure is allowed, which underutilizes the redundancy. Knowing the tolerance level helps architects decide how many replicas are needed to meet reliability goals in fault‑prone environments.

Q7. A company can add either redundant network links or additional backup power supplies to improve reliability. Which choice directly addresses reliability due to hardware failures?

A.Add redundant network links ✅
B.Add backup power supplies
C.Upgrade software version
D.Increase user training
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: The correct answer is A because adding redundant network links creates alternative paths for data, so if one link fails the traffic can be rerouted, directly improving reliability against hardware failures. Option B, backup power supplies, helps with power outages but does not address failures of the network hardware itself. Option C, upgrading software, may improve performance but is not a hardware reliability measure. Option D, increasing user training, does not affect the physical durability of the system. Selecting redundant links illustrates a concrete step engineers take to keep distributed services operational despite component failures.
