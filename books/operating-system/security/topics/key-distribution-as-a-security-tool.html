📝 Key distribution as a Security Tool

📖 From Operating System • 15. Security • 7 questions available

What is Key distribution as a Security Tool?

Definition:
Key distribution encompasses protocols and infrastructure for securely generating, exchanging, storing, and revoking cryptographic keys throughout their lifecycle while maintaining confidentiality and authenticity.

Example:
Diffie-Hellman key exchange where parties derive shared secret \( s = g^{ab} \mod p \) over insecure channels without transmitting \( a \) or \( b \) enables forward-secure session establishment.

Reason:
Cryptographic security depends entirely on key secrecy and integrity; compromised key distribution renders even strong algorithms useless, making robust PKI, key escrow policies, and hardware security modules essential operational components.

Q1. What is the primary purpose of a key distribution center (KDC) in symmetric cryptography?

A. To generate and securely deliver session keys to communicating parties ✅
B. To encrypt data transmitted over the network
C. To authenticate users via public keys
D. To store passwords in plaintext

💡 Difficulty: easy | ✅ Correct: A

📖 Explanation:

The KDC's main role is to create fresh symmetric session keys and transmit them securely to the two parties that will communicate. By enabling both sides to encrypt and decrypt messages without exposing the key to eavesdroppers. Options B and D describe unrelated functions, and option C refers to public‑key authentication, which is not the KDC's purpose in symmetric systems. Therefore A is correct.

Q2. Why does overwriting the return address in a stack frame allow an attacker to execute arbitrary code?

A. It changes the function's local variables
B. Control flow is redirected to the address stored in the overwritten return address ✅
C. It disables the operating system's scheduler
D. It clears the stack

💡 Difficulty: easy | ✅ Correct: B

📖 Explanation:

When a function returns, the CPU fetches the address stored in the return‑address slot of the stack frame and jumps to that location. Overwriting this slot replaces the legitimate address with the address of the attacker’s shellcode, causing execution to continue at the malicious code. Changing local variables (A) does not affect control flow, disabling the scheduler (C) is unrelated, and clearing the stack (D) would crash the program. Hence B is correct.

Q3. How does a NOP sled facilitate successful execution of shellcode after a buffer overflow?

A. It encrypts the shellcode to evade detection
B. It shortens the distance to the return address
C. It provides a sequence of no‑operation instructions that slides execution into the shellcode ✅
D. It disables security checks in the operating system

💡 Difficulty: medium | ✅ Correct: C

📖 Explanation:

A NOP sled is a sequence of no‑operation instructions placed before the actual shellcode. Because NOPs do nothing, the processor can slide through them until it reaches the first executable instruction of the payload. This makes the exact jump address less critical: any address that lands anywhere inside the sled will eventually reach the shellcode. Options A and D describe unrelated mechanisms, and B suggests the sled encrypts the code, which is false. Therefore C correctly explains the role of a NOP sled.

Q4. A program allocates a buffer of 64 bytes (BUFFER_SIZE = 64) on the stack. An attacker wants to overwrite the saved return address, which is located immediately after the buffer and the saved frame pointer (4 bytes). Which of the following byte counts must the attacker supply to reach the return address?

A. 64
B. 68
C. 70
D. 72 ✅

💡 Difficulty: medium | ✅ Correct: D

📖 Explanation:

The buffer occupies 64 bytes, so the attacker must first fill those bytes to reach the next stack element. Directly after the buffer the saved frame pointer consumes 4 bytes, bringing the total to 68 bytes. The following 4 bytes hold the saved return address; overwriting it requires an additional 4 bytes. Therefore the attacker must supply 68 + 4 = 72 bytes to control the return address, making option D the correct choice.

Q5. Which of the following techniques is most effective at preventing a buffer‑overflow attack that overwrites the return address?

A. Disabling user accounts ✅
B. Stack canaries
C. Increasing password length
D. Using a VPN

💡 Difficulty: medium | ✅ Correct: A

📖 Explanation:

The most direct way to stop an overflow that overwrites the return address is to place a known canary value just before the saved return address. At function exit the program checks whether the canary has been altered; if it has, the process aborts before using the corrupted address. Disabling accounts (A) does not affect memory safety, increasing password length (C) is unrelated, and using a VPN (D) only protects network traffic. Thus B is the effective mitigation.

Q6. Assume a 32‑bit system where the stack grows downward. The buffer starts at address \(0xBFFFF0\) and occupies 12 bytes. The saved frame pointer is at \(0xBFFFFC\) and the return address is at \(0xBFFFF8\). If an attacker writes 16 bytes of data starting at the buffer, which address will the CPU use for the next return?

A. \(0xBFFFF8\) ✅
B. \(0xBFFFFC\)
C. \(0xBFFFF0\)
D. \(0xBFFFF4\)

💡 Difficulty: hard | ✅ Correct: A

📖 Explanation:

On a 32‑bit little‑endian system the stack grows toward lower addresses. The buffer starts at \(0xBFFFF0\) and occupies 12 bytes, so it ends at \(0xBFFFFB\). The next 4 bytes (at \(0xBFFFFC\)–\(0xBFFFFF\)) hold the saved frame pointer, and the following 4 bytes (at \(0xBFFFF8\)–\(0xBFFFFB\)) contain the return address. Writing 16 bytes overwrites the buffer and the saved frame pointer, and the first four bytes of the overwritten return address are taken as the new jump target. Consequently the CPU will use the address at \(0xBFFFF8\), making option A correct.

Q7. When designing a key‑distribution protocol for a network service that runs with elevated privileges, which design principle most directly reduces the risk of a buffer‑overflow exploit?

A. Use asymmetric encryption for all messages ✅
B. Store keys in plaintext on the server
C. Perform input validation on all parameters before copying into fixed‑size buffers
D. Rotate keys every hour

💡 Difficulty: hard | ✅ Correct: A

📖 Explanation:

Input validation directly limits the amount of data that can be copied into a fixed‑size buffer, preventing the overflow from ever reaching the saved return address. By checking lengths and rejecting overly long inputs, the program ensures that the memory layout remains intact, which is the most reliable way to avoid exploitation. Using asymmetric encryption (A) does not affect memory copying, storing keys in plaintext (B) creates other risks, and rotating keys (D)
