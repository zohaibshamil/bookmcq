What is Password vulnerabilities in operating system?

Definition:
Password vulnerabilities include weak hashing algorithms, insufficient salting, predictable generation patterns, reuse across systems, and inadequate lockout policies that enable offline cracking or online guessing attacks.

Example:
MD5-hashed passwords without salts where \( h = \text{MD5}(password) \) allow rainbow table attacks recovering millions of passwords in hours due to precomputed hash chains.

Reason:
Password vulnerabilities persist due to legacy system constraints and developer ignorance, requiring mandatory migration to modern KDFs, breach monitoring, and user education since technical fixes alone cannot address behavioral factors like password reuse.

Q1. What is a polymorphic virus?

A. A virus that encrypts its code before execution
B. A virus that changes its code each time it infects a system ✅
C. A virus that hides by modifying system calls
D. A virus that spreads through macro scripts

💡 Difficulty: easy | ✅ Correct: B

📖 Explanation:

A polymorphic virus alters its internal code on each infection, keeping its functionality while changing its signature. Option B correctly describes this behavior. Option A describes an encrypted virus, Option C a stealth virus, and Option D a macro virus. Recognizing the definition helps differentiate detection challenges, as polymorphic changes evade signature‑based scanners, which is essential for real‑world malware defenses.

Q2. Which type of virus includes decryption code to hide its payload?

A. Polymorphic virus
B. Encrypted virus ✅
C. Stealth virus
D. Tunneling virus

💡 Difficulty: easy | ✅ Correct: B

📖 Explanation:

An encrypted virus carries decryption code that runs before the malicious payload, obscuring its contents from static analysis. Option B matches this definition. Polymorphic viruses change their code but do not necessarily encrypt it (Option A). Stealth viruses modify system behavior to conceal themselves (Option C). Tunneling viruses embed themselves in interrupt handlers (Option D). Understanding this helps select appropriate detection tools that can handle encrypted payloads.

Q3. Why does a boot‑sector virus replace the original boot block at system startup?

A. To increase available disk space
B. To ensure its code runs first ✅
C. To hide from the user
D. To improve system performance

💡 Difficulty: easy | ✅ Correct: B

📖 Explanation:

A boot‑sector virus swaps the original boot block so that its code executes before the operating system, guaranteeing control over the boot process. Option B captures this purpose. Increasing disk space (Option A) is unrelated, as is hiding from the user (Option C) which is a secondary effect. Improving performance (Option D) is not a goal of malware. This behavior explains why protecting the boot sector is critical.

Q4. How does a stealth virus evade detection by modifying system calls?

A. It changes the read system call to return the original file content ✅
B. It encrypts its payload before execution
C. It installs itself in the interrupt‑handler chain
D. It replaces the boot sector with malicious code

💡 Difficulty: medium | ✅ Correct: A

📖 Explanation:

A stealth virus can intercept the read system call and supply the uninfected version of a file, so scanners see a clean file while the infected version remains hidden. Option A describes this technique. Encrypting payloads (Option B) defines encrypted viruses, not stealth. Installing in interrupt handlers (Option C) describes tunneling viruses. Replacing the boot sector (Option D) is characteristic of boot‑sector viruses. This knowledge aids in designing detection that monitors system call integrity.

C. By modifying macro scripts

💡 Difficulty: medium | ✅ Correct: A

📖 Explanation:

A tunneling virus embeds its code in the interrupt‑handler chain, allowing it to survive reboots and evade many traditional scans. Option A correctly identifies this persistence method. Encryption (Option B) pertains to encrypted viruses, macro modification (Option C) to macro viruses, and boot‑sector replacement (Option D) to boot‑sector viruses. Recognizing the mechanism guides defenders to monitor low‑level system structures for unauthorized hooks.

Q7. Explain how the logic bomb component of a boot virus can affect system stability beyond initial infection.

C. It copies the boot sector to an unused location
D. It increases the visible memory limit

💡 Difficulty: hard | ✅ Correct: A

📖 Explanation:

A logic bomb embedded in a boot virus is programmed to activate on a certain date or condition, often causing a crash, data loss, or other destructive actions, thereby destabilizing the system long after the initial infection. Option A describes this effect. Hiding the boot sector (Option B) is a stealth tactic, copying to an unused location (Option C) is for concealment, and increasing memory limits (Option D) relates to memory‑hiding techniques. Q8. A user opens a spreadsheet that contains a macro virus. Which action triggers the infection?

A. Saving the file
B. Printing the file
C. Enabling macros ✅
D. Closing the file

💡 Difficulty: easy | ✅ Correct: C

📖 Explanation:

Macro viruses are dormant until the host application is instructed to execute embedded macros. Enabling macros (Option C) activates the malicious code, causing infection. Simply saving (Option A) or printing (Option B) does not run the macros, and closing the file (Option D) ends the session without execution. This scenario illustrates why organizations disable macro execution by default to prevent such infections.

Boot‑sector replacement (Option C) affects the boot process, not memory usage. Tunneling in drivers (Option D) targets interrupt handling, not RAM consumption.

Q10. If a virus copies the boot sector to an unused location X, what is the likely purpose?

A. To preserve the original boot for later restoration
B. To increase overall storage capacity
C. To hide malicious code away from casual inspection ✅
D. To speed up the boot process

💡 Difficulty: medium | ✅ Correct: C

📖 Explanation:

Copying the boot sector to an unused area allows the virus to retain a hidden copy of its malicious code, making detection harder because the active boot sector appears normal while the payload resides elsewhere. Option C captures this intent. Preserving the original boot (Option A) is not typical for malware. Increasing storage (Option B) and speeding boot (Option D) are unrelated benefits.

USB restrictions (Option D) mitigate removable media threats, not macro-based attacks.

Q13. Given a scenario where a virus changes its code each infection but maintains functionality, which detection method would be least effective?

A. Heuristic analysis
B. Behavior monitoring
C. Signature‑based scanning ✅
D. Sandbox execution

💡 Difficulty: hard | ✅ Correct: C

📖 Explanation:

Signature‑based scanning relies on matching known byte patterns; a virus that mutates its code each infection defeats this approach, making it the least effective method. Option C reflects this limitation. Heuristic analysis (Option A) looks for suspicious patterns, behavior monitoring (Option B) tracks actions, and sandbox execution (Option D) observes runtime behavior, all of which can still detect such malware despite code changes.

Q14. A forensic exam reveals a virus that modifies the read system call to return original file content. What mitigation technique can reveal the hidden code?

A. Disable all read system calls permanently
B. Use integrity‑checking tools that compare file hashes to known good values ✅
C. Reboot the system in safe mode only
D. Reinstall the operating system from scratch

💡 Difficulty: hard | ✅ Correct: B

📖 Explanation:

Integrity‑checking utilities compute cryptographic hashes of files and compare them against trusted baselines, exposing discrepancies introduced by a stealth virus that returns clean data to normal reads. Option B is the appropriate technique. Disabling reads (Option A) would cripple the system. Safe‑mode boot (Option C) may bypass some malware but not reveal hidden modifications. Full OS reinstall (Option D) removes the virus but does not specifically uncover the altered system call behavior.

Disk encryption (Option D) protects data at rest but not active malware.

Q17. Compare and contrast encrypted and polymorphic viruses in terms of detection challenges for antivirus software.

A. Encrypted viruses hide code while polymorphic viruses hide their signature ✅
B. Both use the same technique to avoid detection
C. Encrypted viruses never change, polymorphic viruses constantly change
D. None of the above

💡 Difficulty: hard | ✅ Correct: A

📖 Explanation:

Encrypted viruses conceal their payload by storing it in an encrypted form and decrypting it at runtime, while polymorphic viruses continuously modify their code to generate new signatures, both complicating detection. Option A accurately captures this distinction. Option B is incorrect because the techniques differ. Option C misstates that encrypted viruses are static; they can also change. Option D offers no useful information. Understanding these differences informs the selection of heuristic and behavior‑based defenses.

Q18. During a security audit, you find that the interrupt‑handler chain has been altered. Which virus class does this indicate and what is a recommended remediation step?

A. Macro virus; reinstall office suite
B. Tunneling virus; restore original interrupt vectors ✅
C. Stealth virus; update antivirus signatures
D. Polymorphic virus; run heuristic scan

💡 Difficulty: medium | ✅ Correct: B

📖 Explanation:

Alteration of the interrupt‑handler chain is a hallmark of tunneling viruses, which embed malicious code within low‑level system handlers to persist. Restoring the original interrupt vectors (Option B) corrects the tampering and removes the hidden payload. Macro viruses (Option A) affect document macros, not interrupt tables. Stealth viruses (Option C) modify system calls, and polymorphic viruses (Option D) change their code signatures but do not typically modify interrupt chains.
