📝 System and Network Threats (10 MCQs)

Definition:

System and network threats are attacks that target operating system services, communication channels, connected devices, and shared infrastructure. They can exploit network weaknesses or misuse system resources. Without suitable defenses, attackers may intercept communications, disrupt services, spread malicious software, or gain unauthorized control.

Working:

An attacker identifies an exposed service, vulnerable device, or weak communication protocol. The attacker sends malicious traffic, exploits a weakness, or abuses available resources. The target may experience unauthorized access, information disclosure, resource exhaustion, or interrupted communication.

Example:

A network server normally handles 100 legitimate requests per second. An attacker sends a large volume of artificial requests, exhausting available connection resources. Legitimate users experience delays or failed connections even though their own devices operate normally.

Reason:

Network defenses are necessary because protecting individual files does not protect communication infrastructure. Host-only security cannot fully prevent traffic-based attacks. Firewalls, secure protocols, monitoring, and resource limits provide additional protection at network boundaries and endpoints.

Common Misconceptions:

'Network threats always require malware installation.' Correction: malicious traffic can disrupt services without installing software. 'Firewalls stop every network attack.' Correction: permitted traffic may still contain attacks. 'Only servers face network threats.' Correction: clients and network devices can also be targets.

Exam Preparation Tips: How to prepare this topic

Separate system-level attacks from network-level attacks. Explain interception, spoofing, and service disruption. Match defenses to different threats. Exams commonly ask about attack categories, network weaknesses, and the purpose of layered defenses.

Key Terms:

  • Network threat - Risk involving network communication or services.
  • Endpoint - Device connected to a network.
  • Traffic - Data transmitted across a network.
  • Spoofing - Falsifying an identity or network address.
  • Resource exhaustion - Consumption of resources until services become unavailable.

📝 All System and Network Threats MCQs

Q1. What is the definition of masquerading in network security?

A.An attacker pretends to be another host or user ✅
B.An attacker blocks all traffic between two hosts
C.An attacker encrypts data to hide it from monitors
D.An attacker deletes system logs to cover tracks
💡 Difficulty: easy | ✅ Correct: A

📖 Explanation: Masquerading involves an attacker assuming the identity of a legitimate host or user, allowing unauthorized actions. Option A correctly describes this behavior. Option B describes a denial‑of‑service style block, not identity theft. Option C refers to encryption, which does not involve impersonation. Option D talks about log deletion, a cover‑up technique unrelated to identity spoofing. Understanding masquerading is essential because it directly undermines authentication mechanisms in real‑world attacks.

Q2. Why does masquerading breach authentication mechanisms?

A.It changes the encryption algorithm used by the system
B.It substitutes a false identity for a legitimate one ✅
C.It overloads the network with traffic
D.It disables the firewall
💡 Difficulty: easy | ✅ Correct: B

📖 Explanation: Authentication relies on confirming who a user or host truly is. Masquerading replaces the genuine identity with a false one, causing the system to accept the impostor as legitimate. Option B captures this core problem. Option A misidentifies the issue by focusing on encryption, which is unrelated to identity verification. Option C describes a bandwidth problem, not an authentication flaw. Option D suggests disabling a firewall, which is a separate security control. Recognizing this helps students see how identity spoofing directly defeats authentication.

Q3. How does a replay attack differ from a man‑in‑the‑middle attack?

A.Replay reuses old messages without alteration, while MITM intercepts and may modify live traffic ✅
B.Replay modifies messages, whereas MITM only records them
C.Replay works only on encrypted data, MITM only on plaintext
D.Replay requires physical access, MITM does not
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: A replay attack simply repeats a previously captured valid transmission, often unchanged, to trick a system into accepting it again. In contrast, a man‑in‑the‑middle attack actively intercepts ongoing communication and can alter or inject messages before forwarding them. Option A correctly contrasts these behaviors. Option B reverses the roles of modification and recording. Option C incorrectly ties the attacks to encryption status. Option D adds an unnecessary physical‑access requirement. Knowing this distinction aids in selecting appropriate detection and mitigation techniques.

Q4. A bank receives a duplicate transaction request that appears identical to a previous one. Which defense mechanism most effectively prevents a replay attack?

A.Use timestamps and a unique nonce for each request ✅
B.Increase password length for all users
C.Install an intrusion‑detection system on the network
D.Disable remote logins to the banking server
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: Timestamps and nonces ensure each transaction is unique and fresh, so a duplicated message will be rejected as stale or duplicate. Option A directly addresses replay by providing freshness guarantees. Option B improves password strength but does not stop replayed messages. Option C can alert to abnormal traffic but does not inherently prevent the attack. Option D removes remote access entirely, which is impractical and unrelated to replay prevention. Implementing nonces and timestamps is a standard countermeasure in financial systems to protect against replay exploits.

Q5. During a TLS session, which indicator most reliably suggests that a session hijacking attempt is occurring?

A.A sudden change in the client’s IP address ✅
B.A noticeable increase in server CPU usage
C.The appearance of a new certificate authority in the chain
D.Duplicate MAC addresses on the network
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: Session hijacking often involves an attacker taking over an existing connection from a different network location, causing the client’s IP address to change abruptly. Monitoring IP continuity can reveal such anomalies, making option A the best choice. Option B may result from many unrelated processes. Option C involves certificate changes, which are not typical of hijacking. Option D concerns layer‑2 collisions, unrelated to TLS session integrity. Detecting IP shifts helps administrators intervene quickly to terminate compromised sessions.

Q6. Why might detecting a denial‑of‑service attack be considered sufficient in some security strategies?

A.Because DoS attacks are always short‑lived
B.Because mitigation measures can be applied after detection ✅
C.Because detection automatically stops the attack
D.Because DoS attacks never cause any damage
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: DoS attacks aim to overwhelm resources, and immediate prevention may be impractical; however, once an attack is detected, administrators can activate rate‑limiting, traffic filtering, or resource scaling to mitigate impact. Option B captures this rationale. Option A is false; attacks can persist. Option C incorrectly assumes detection alone halts the traffic. Option D is inaccurate; DoS attacks can cause significant downtime and financial loss. Understanding that detection enables timely countermeasures clarifies why many organizations focus on rapid identification alongside other defenses.

Q7. An attacker steals a user’s credentials and uses them to gain administrative rights through masquerading. Which security control would most likely have prevented this privilege escalation?

A.Role‑based access control that limits privileges
B.Network segmentation separating user and admin zones
C.Multi‑factor authentication for privileged actions ✅
D.Anti‑virus scanning on user workstations
💡 Difficulty: medium | ✅ Correct: C

📖 Explanation: Multi‑factor authentication requires something beyond a password, such as a token or biometric, making it much harder for an attacker who only possesses stolen credentials to assume an admin identity. Option C therefore blocks the escalation. Option A limits what roles can do but does not stop an attacker from presenting a valid admin identity. Option B isolates traffic but does not address credential misuse. Option D protects against malware, not credential theft. Deploying MFA for privileged accounts is a proven defense against masquerading‑based privilege escalation.

Q8. An attacker first hijacks a TLS session, then performs a man‑in‑the‑middle attack, and finally replays a modified request to transfer funds. Which layered defense strategy best mitigates this multi‑stage attack?

A.Use TLS with mutual authentication, enforce per‑message nonces, and monitor anomalous transaction patterns ✅
B.Deploy a perimeter firewall only
C.Rely solely on password complexity requirements
D.Apply static IP filtering for all clients
💡 Difficulty: hard | ✅ Correct: A

📖 Explanation: Mutual TLS ensures both parties prove their identities, preventing the attacker from impersonating either side. Per‑message nonces provide freshness, so replayed or altered messages are rejected. Transaction monitoring detects unusual fund transfers, enabling rapid response. Option A combines cryptographic, protocol, and behavioral safeguards, addressing each attack phase. Option B’s firewall cannot stop credential misuse inside an encrypted tunnel. Option C’s password policy does not stop session hijacking or replay. Option D’s static IP filter is easily bypassed and does not protect against encrypted attacks. The layered approach is essential for complex threats.

Q9. In terms of attack‑cost deterrence, how does increasing the effort required for an attacker affect the overall security posture of a system?

A.It guarantees that no attacks will ever occur
B.It raises the economic barrier, reducing the likelihood of successful attacks ✅
C.It slows network performance for legitimate users
D.It eliminates the need for encryption altogether
💡 Difficulty: hard | ✅ Correct: B

📖 Explanation: Raising the required effort—through stronger authentication, frequent key rotation, or complex configurations—makes attacks more expensive in time and resources, thereby lowering their attractiveness. Option B correctly describes this economic deterrence. Option A overstates the effect; determined attackers may still succeed. Option C mistakenly assumes defensive measures always degrade performance for users. Option D incorrectly suggests that higher effort removes the need for encryption, which remains essential for confidentiality. Understanding cost‑based deterrence helps designers prioritize controls that make attacks uneconomical.

Q10. An IoT device uses a reused symmetric key for each message sent to a cloud server, allowing a replay attack. Which protocol change most effectively eliminates this vulnerability?

A.Introduce a per‑message nonce and include it in the MAC calculation ✅
B.Increase the key size from 128‑bit to 256‑bit
C.Switch the communication protocol from TCP to UDP
D.Add a simple checksum to each packet
💡 Difficulty: hard | ✅ Correct: A

📖 Explanation: A per‑message nonce ensures each transmission is unique; when combined with a MAC, any replayed message will fail verification because the nonce will have already been used. Option A directly addresses the replay weakness. Option B strengthens cryptographic strength but does not prevent reuse of the same ciphertext. Option C changes transport reliability but does not add freshness. Option D’s checksum only detects corruption, not replay. Incorporating nonces and MACs is a standard practice for securing IoT communications against replay attacks.)
