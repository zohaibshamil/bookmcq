What is Intrusion detection system in operating system?

Definition:
Intrusion detection systems (IDS) monitor system and network activities for malicious behavior or policy violations using signature matching, anomaly detection, or machine learning to alert administrators of potential breaches.

Example:
Host-based IDS detecting privilege escalation where \( \text{process\_integrity\_level} \) unexpectedly increases from medium to high triggers alert based on behavioral baseline deviation.

Reason:
IDS provides visibility into attacks that bypass preventive controls, but generates false positives requiring tuning and correlation with other logs since detection alone cannot stop attacks without integrated response capabilities.

Q1. What is the primary purpose of the UNIX utility rsh in the context of worm propagation?

A. To encrypt network traffic between hosts
B. To execute commands on a remote host without requiring a password each time ✅
C. To monitor system logs for suspicious activity
D. To provide a graphical interface for managing services

💡 Difficulty: easy | ✅ Correct: B

📖 Explanation:

The rsh utility is designed to let a user run a command on another machine without interactive password entry when the .rhosts file lists trusted host‑login pairs. This capability is exactly what a worm can exploit to launch code on remote systems automatically. Option B states this function, making it correct. Option A describes encryption, which rsh does not provide; Option C refers to monitoring, a different security task; Option D mentions a graphical interface, which rsh lacks. Understanding rsh’s purpose helps recognize why it is attractive to malware.

Q2. Which exact buffer size did the Morris worm use to overflow the finger daemon?

A. 256 bytes
B. 1024 bytes
C. 536 bytes ✅
D. 128 bytes

💡 Difficulty: easy | ✅ Correct: C

📖 Explanation:

The Morris worm crafted a 536‑byte string to overflow the finger daemon’s input buffer. This specific length is remembered because it exceeds the allocated buffer and overwrites the return address on the stack. Option C gives the exact number, so it is correct. Options A, B, and D propose different sizes (256, 1024, 128) which do not match the documented exploit. Knowing the exact overflow size is essential for reproducing the attack in a controlled lab.

Q3. Why do .rhosts files increase the risk of unauthorized remote access?

A. They disable firewall rules on the host
B. They encrypt all outgoing traffic
C. They allow password‑less logins for listed hosts
D. They limit user privileges on the local machine ✅

💡 Difficulty: medium | ✅ Correct: D

📖 Explanation:

Files like .rhosts list host‑login pairs that rsh trusts, allowing password‑less logins. When such files are present, any user or process on a trusted host can execute commands on the local machine, creating a shortcut for worms to spread. Option D correctly describes this risk, while Option A suggests encryption, which is unrelated; Option B mentions logging, which does not increase risk; Option C claims it disables firewalls, which is inaccurate. Recognizing this trust relationship explains why attackers target .rhosts configurations.

Q5. How does a buffer overflow in the finger daemon lead to execution of /bin/sh?

A. The daemon crashes and restarts automatically
B. The overflow overwrites the return address to point to shellcode in the payload
C. The overflow triggers an email alert to the administrator ✅
D. The overflow causes the daemon to log the attacker’s IP address

💡 Difficulty: medium | ✅ Correct: C

📖 Explanation:

When the finger daemon receives input longer than its buffer, the excess bytes overwrite the saved return address on the stack. The overwritten address can point to shellcode embedded in the overflow string, which typically launches /bin/sh. Option C states this mechanism, making it correct. Option A suggests the daemon simply crashes, which is not the goal of the exploit; Option B claims it sends an email, which is unrelated; Option D says it logs the IP, which does not explain code execution. Understanding this chain connects the overflow to remote shell creation.

Q6. A network monitor shows repeated finger queries containing unusually long strings. Which mitigation step is most effective?

C. Block TCP port 79 at the perimeter firewall
D. Disable rsh on all internal hosts

💡 Difficulty: medium | ✅ Correct: B

📖 Explanation:

Updating the finger daemon to a patched version that validates input length directly removes the vulnerability that allows the overflow, preventing the worm from executing its payload. Option B therefore offers the most effective mitigation. Installing an IDS signature (Option A) can detect the attack but does not stop it. Blocking port 79 (Option C) would hinder legitimate finger usage but may not stop the worm if it uses other ports. Disabling rsh (Option D) does not address the finger-specific overflow. Patching the vulnerable service is the definitive fix.

Q10. What is the relationship between overwriting a stack frame and control‑flow hijacking in buffer‑overflow attacks?

A. Overwriting the stack frame changes file permissions
B. Overwriting the stack frame modifies the return address, redirecting execution to attacker‑controlled code ✅
C. Overwriting the stack frame clears all environment variables
D. Overwriting the stack frame disables the CPU cache

💡 Difficulty: hard | ✅ Correct: B

📖 Explanation:

In a buffer‑overflow, excess data writes beyond the intended buffer and can corrupt the saved return address stored in the stack frame. By overwriting this address, the attacker redirects the program’s execution flow to malicious code placed in the overflow payload, achieving control‑flow hijacking. Option B accurately describes this process. Options A, C, and D describe unrelated effects that do not lead to execution redirection. Understanding this mechanism clarifies why precise payload construction is crucial for successful exploitation.
