What is One time passwords OTP in operating system?

Definition:
One-time passwords (OTPs) generate unique, time-limited or event-synchronized authentication codes valid for single use, eliminating replay attack risks associated with static credentials.

Example:
TOTP generating codes via provides 30-second validity windows synchronized between authenticator app and server.

Reason:
OTPs mitigate credential theft and phishing by ensuring captured codes cannot be reused, but require secure seed provisioning and backup mechanisms since device loss or clock desynchronization can cause legitimate user lockouts.

Q1. What best describes a one-time password (OTP)?

A.A password that never expires
B.A password that is valid for only a single authentication session ✅
C.A password that is shared among multiple users
D.A password stored in plaintext on the server
💡 Difficulty: easy | ✅ Correct: B

📖 Explanation: A one-time password is designed to be usable for only one authentication event, after which it becomes invalid. Option B captures this definition precisely. Option A is incorrect because OTPs are short‑lived, not permanent. Option C mischaracterizes OTPs as shared, which defeats their purpose. Option D describes poor storage practice, not the OTP concept. Understanding this definition is essential for recognizing why OTPs improve security in real‑world login systems.

Q2. A user receives a six‑digit OTP via SMS to access their bank account. Which action should the user take to maintain security?

A.Enter the OTP on any website that asks for a code
B.Save the OTP in a notes app for future use
C.Enter the OTP only on the bank’s official login page ✅
D.Share the OTP with a trusted friend for verification
💡 Difficulty: easy | ✅ Correct: C

📖 Explanation: The OTP must be entered on the legitimate service that generated it—in this case, the bank’s official login page. Option C is correct because it prevents man‑in‑the‑middle attacks. Option A risks phishing, as any site could request the code. Option B creates a persistent record that could be stolen. Option D exposes the secret to another party, compromising the authentication process.

Q3. In a Time‑Based OTP (TOTP) system, how is the current password generated?

A.By hashing a secret key with the current Unix timestamp divided by a time step ✅
B.By incrementing a counter each time a password is requested
C.By encrypting the user’s static password with a random nonce
D.By storing pre‑computed passwords on the server
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: TOTP algorithms compute the OTP by applying a hash function to a shared secret key and the current time interval, typically the Unix time divided by a step (e.g., 30 seconds). Option A reflects this process accurately. Option B describes an event‑based HOTP approach. Option C mixes concepts of encryption and static passwords, which is not how OTPs are derived. Option D suggests a server‑side store, contrary to the stateless nature of TOTP.

Q4. A system uses an HMAC‑based OTP (HOTP) where the counter is stored on the client. What must the server do to verify the OTP?

A.Synchronize its own counter with the client’s counter each time
B.Compute the HMAC using the shared secret and the counter value received from the client ✅
C.Ignore the counter and only check the HMAC output length
D.Reset the counter to zero after each login attempt
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: In HOTP, the client sends the current counter value along with the OTP. The server reproduces the HMAC using the same secret and the received counter to validate the code, making option B correct. Option A is unnecessary because the server does not need to keep its own counter; it trusts the client’s value. Option C ignores the essential counter component, and option D would cause mismatches after the first use.

Q5. Why are OTPs considered more secure than static passwords?

A.They are longer in length
B.They change after every use, reducing the window for replay attacks ✅
C.They are stored in encrypted form on the server
D.They require biometric verification
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: OTP security stems from their one‑time nature: each code becomes useless after a single authentication, dramatically limiting an attacker’s chance to reuse a captured credential. Option B captures this advantage. Option A may be true but is not the primary security benefit. Option C refers to storage practices, not the dynamic property of OTPs. Option D introduces biometrics, which is a separate factor not intrinsic to OTP mechanisms.

Q6. An attacker intercepts an OTP transmitted over an insecure channel and attempts to reuse it immediately. Which OTP design mitigates this replay attack most effectively?

A.A static password combined with OTP
B.A time‑based OTP that expires after 30 seconds ✅
C.A longer OTP with 12 digits
D.An OTP that is generated on the server only
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: Time‑based OTPs have a short validity period (often 30 seconds), so even if an attacker captures the code, it quickly becomes invalid, preventing replay. Option B reflects this protection. Option A still relies on a reusable static password, leaving a replay gap. Option C increases complexity but does not address timing. Option D does not specify expiration, so it does not inherently stop replay attacks.

Q7. Which statement correctly differentiates event‑based (HOTP) and time‑based (TOTP) OTPs?

A.HOTP requires synchronized clocks, while TOTP uses a counter
B.TOTP changes only when the user logs in, HOTP changes every minute
C.HOTP generates passwords based on a moving counter, TOTP generates passwords based on the current time interval ✅
D.Both HOTP and TOTP rely on user‑entered random numbers
💡 Difficulty: medium | ✅ Correct: C

📖 Explanation: HOTP and TOTP differ in their input: HOTP uses a counter that increments with each use, whereas TOTP derives the code from the current time slice, typically a 30‑second interval. Option C accurately describes this distinction. Option A reverses the mechanisms. Option B misstates the behavior of both types. Option D introduces random numbers, which are not part of the standard OTP generation process.

Q8. A company wants to implement OTP for remote VPN access. Which deployment ensures minimal user friction while maintaining strong security?

D.Ask users to answer security questions instead of OTP
💡 Difficulty: medium | ✅ Correct: C

📖 Explanation: Mobile authenticator apps generate TOTP codes offline, eliminating the need for network delivery and hardware tokens, thus balancing usability and security. Option C is the best choice. Option A depends on email delivery latency and possible compromise. Option B adds hardware costs and inconvenience. Option D replaces OTP with weaker knowledge‑based factors.

Q9. If an attacker obtains the shared secret used for TOTP generation, what is the impact on the system’s security?

A.The attacker can generate valid OTPs for any time interval ✅

C.The attacker can replay previously captured OTPs indefinitely
D.The attacker’s knowledge has no effect without the user’s device
💡 Difficulty: hard | ✅ Correct: A

📖 Explanation: Possessing the secret key enables the attacker to compute the correct OTP for any future time interval, effectively compromising the authentication mechanism. Option A reflects this severe impact. Option B underestimates the attacker’s capability; the secret allows deterministic generation, not random guessing. Option C describes a replay scenario, but with the secret, the attacker can generate fresh codes. Option D is false because the secret alone is sufficient.

Q12. A server and a client use TOTP with a 30‑second time step. If their clocks drift apart by up to 45 seconds, what is the maximum number of time steps the server should accept to still validate the OTP?

A.1
B.2
C.3 ✅
D.4
💡 Difficulty: hard | ✅ Correct: C

📖 Explanation: With a 30‑second step, a 45‑second drift could place the client’s code one step ahead or behind.
