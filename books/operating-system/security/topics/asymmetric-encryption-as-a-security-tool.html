What is Asymmetric encryption as a Security Tool?

Definition:
Asymmetric encryption uses mathematically related public and private key pairs where encryption with one key can only be decrypted with the other, enabling secure key exchange and digital signatures without shared secrets.

Example:
RSA encryption where \( C = M^e \mod n \) and \( M = C^d \mod n \) allows secure session key establishment in TLS handshakes without pre-shared keys.

Reason:
Asymmetric cryptography solves the key distribution problem inherent in symmetric systems and enables authentication and non-repudiation, though computational overhead restricts its use to small data like keys and signatures rather than bulk encryption.

Q1. What is a buffer overflow in the context of stack memory?

A. An error that occurs when a program reads from an uninitialized variable
B. An error that occurs when data exceeds the allocated space for a buffer, overwriting adjacent memory ✅
C. A technique to encrypt data using asymmetric keys
D. A method to compress files

💡 Difficulty: easy | ✅ Correct: B

📖 Explanation:

A buffer overflow happens when more data is written to a stack-allocated buffer than it can hold, causing the excess to overwrite neighboring memory such as saved registers or the return address. Option B describes this precisely. Option A confuses reading with writing, Option C refers to encryption unrelated to memory safety, and Option D describes compression, which is unrelated to overflow. Understanding this basic definition is essential for recognizing why attackers can hijack execution flow.

Q2. Why do attackers often prepend a series of NOP instructions (a NOP sled) before their shellcode in an overflow exploit?

A. To increase the overall size of the payload so it fits the buffer
B. To align the shellcode on a word boundary for the processor
C. To provide a large landing area that safely slides execution into the actual shellcode regardless of the exact jump address ✅
D. To confuse debugging tools and make analysis harder

💡 Difficulty: easy | ✅ Correct: C

📖 Explanation:

A NOP sled consists of many no‑operation instructions (\( \text{NOP} \)) placed before the malicious code. If the overwritten return address lands anywhere within the sled, execution will slide forward until it reaches the real shellcode, improving reliability despite minor address miscalculations. Option C captures this purpose. Option A misstates the goal, Option B is about alignment not reliability, and Option D exaggerates the effect on debugging; NOPs mainly aid landing accuracy.

Q3. A program copies user input from argv[1] into a local array buffer[64] using strcpy without bounds checking. Which step is most critical for an attacker to gain control of execution?

A. Overwriting the saved frame pointer
B. Overwriting the saved return address ✅
C. Injecting a large amount of NOPs before the shellcode
D. Changing the environment variable PATH

💡 Difficulty: medium | ✅ Correct: B

📖 Explanation:

When strcpy copies unchecked data, the attacker can write past buffer[64] and reach the saved return address stored just above it on the stack. Overwriting this address with the location of injected shellcode redirects execution when the function returns. Option B directly targets the return address, which is the decisive control point. Overwriting the frame pointer (A) may cause a crash but not necessarily control flow; NOPs (C) aid landing but require the address overwrite first; modifying PATH ( D) does not affect the stack layout.

Q4. How does the saved frame pointer relate to the return address in a typical stack frame?

A. They occupy the same memory location
B. The frame pointer points to the saved return address
C. The return address is stored at a higher address than the saved frame pointer ✅
D. Both are stored in the heap, not the stack

💡 Difficulty: medium | ✅ Correct: C

📖 Explanation:

In a conventional stack frame, the saved frame pointer (\( \text{EBP} \) or \( \text{RBP} \)) is pushed first, followed by the saved return address. Consequently, the return address resides at a higher memory address (closer to the top of the stack) than the saved frame pointer. Option C correctly describes this ordering. Option A is false because they are distinct entries; Option B reverses the relationship; Option D incorrectly places them in the heap, which is unrelated to stack‑based overflow attacks.

Q5. If a buffer holds 64 bytes and an attacker needs to overwrite a 4‑byte return address located 72 bytes from the start of the buffer, how many NOP bytes must the attacker prepend to a 20‑byte shellcode to reach the return address?

A. 8
B. 12 ✅
C. 16
D. 20

💡 Difficulty: medium | ✅ Correct: B

📖 Explanation:

The distance from the buffer start to the return address is 72 bytes. Subtract the 20‑byte shellcode gives 52 bytes needed for filler. Since the attacker also wants a NOP sled, the remaining space after the shellcode is 52 − 20 = 32 bytes. However, only the bytes before the shellcode count as NOPs; the attacker places the return address after the NOP sled, so the NOP count equals 72 − 64 = 8 bytes. Option B (12) is the correct calculation when accounting for the 4‑byte saved frame pointer preceding the return address, yielding 12 NOPs.

Q6. Which mitigation technique directly protects the saved return address from being overwritten by a buffer overflow?

A. Address Space Layout Randomization (ASLR)
B. Data Execution Prevention (DEP)
C. Stack canaries (stack cookies) ✅
D. Position‑Independent Executable (PIE)

💡 Difficulty: medium | ✅ Correct: C

📖 Explanation:

Stack canaries are special guard values placed between local buffers and control data like the saved return address. Before a function returns, the program checks whether the canary was altered; if it was, the program aborts, preventing the overwritten return address from being used. Option C describes this protection. ASLR (A) randomizes memory locations but does not stop overwriting; DEP (B) marks pages non‑executable but does not protect the address itself; PIE (D) makes code position‑independent, which helps with ASLR but does not guard the stack.

Q7. A vulnerable function uses strcpy(buf, input) where buf is 48 bytes long. The attacker discovers that the saved return address is 56 bytes from the start of buf. What offset (in bytes) must the attacker use to reach the return address?

A. 48
B. 56 ✅
C. 64
D. 72

💡 Difficulty: hard | ✅ Correct: B

📖 Explanation:

The offset equals the number of bytes from the beginning of buf to the saved return address. Since the return address resides 56 bytes away, the attacker must supply 56 bytes of data before the overwritten address. Therefore, the correct offset is 56 bytes, matching option B. Option A gives the size of buf but not the distance to the return address; Option C and D add extra bytes beyond the needed offset, which would overshoot and likely cause a crash.

Q8. How does Address Space Layout Randomization (ASLR) reduce the reliability of a buffer‑overflow exploit that uses a fixed return‑address value?

A. It encrypts the payload so the attacker cannot read it
B. It randomizes the location of the stack, making the exact address of the injected shellcode unpredictable ✅
C. It disables the use of NOP sleds
D. It forces the program to run in a virtual machine

💡 Difficulty: hard | ✅ Correct: B

📖 Explanation:

ASLR randomizes the base address of memory regions such as the stack, heap, and libraries each time a program runs. Because the attacker’s payload relies on a known address (e.g., the start of the shellcode), the randomization makes that address differ across executions, causing the exploit to fail unless the attacker can guess or leak the address. Option B captures this effect. Option A is unrelated to address randomization, Option C incorrectly claims NOP sleds are disabled, and Option D misrepresents ASLR’s function.

Q9. When constructing a payload to execute /bin/sh after a stack overflow, which component must be placed at the overwritten return address?

A. The address of the printf function
B. The address of the injected /bin/sh shellcode ✅
C. A NOP instruction
D. The size of the buffer

💡 Difficulty: hard | ✅ Correct: B

📖 Explanation:

The overwritten return address determines where execution resumes after the vulnerable function returns. To launch a shell, the attacker places the address that points directly to the injected /bin/sh shellcode at this location, causing the processor to jump to the malicious code. Option B is therefore correct. Option A would call printf instead of the shell, Option C (a NOP) would not transfer control, and Option D (buffer size) is irrelevant to the control‑flow redirection.

Q10. What is the primary difference between a code‑injection attack and a return‑to‑libc (RET2LIBC) attack?

A. Code‑injection overwrites the return address with a library function, while RET2LIBC injects new shellcode
B. Code‑injection places custom shellcode in memory, whereas RET2LIBC reuses existing library code without injecting new code ✅
C. Both techniques rely on disabling DEP
D. Both require the same amount of NOP sleds to be effective

💡 Difficulty: hard | ✅ Correct: B

📖 Explanation:

In a code‑injection attack, the attacker writes custom shellcode into a writable region and then redirects execution to it. In a return‑to‑libc (RET2LIBC) attack, the attacker does not inject new code; instead, they overwrite the return address with the address of an existing library function (e.g., system) and supply appropriate arguments. Option B correctly describes this distinction. Option A reverses the roles, Option C incorrectly asserts both need DEP disabled, and Option D misstates the NOP requirement, which varies with the technique.

Q11. If a system employs a non‑executable stack but the attacker cannot overwrite the return address, which alternative technique could still allow execution of malicious code?

A. Heap spraying ✅
B. Return‑oriented programming (ROP)
C. Format string exploitation
D. SQL injection

💡 Difficulty: hard | ✅ Correct: A

📖 Explanation:

When the stack is marked non‑executable, traditional shellcode on the stack cannot run. However, heap spraying places malicious code in the heap, which may be executable, allowing the attacker to redirect execution there. Option A (heap spraying) is thus viable. Return‑oriented programming (B) still needs a writable, executable region for gadgets; Format string exploits (C) target different vulnerabilities; SQL injection (D) is unrelated to binary exploitation. Hence, heap spraying is the appropriate fallback.
