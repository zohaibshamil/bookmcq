Q1. What is a logic bomb in computer security?

🔹 A. Malicious code that activates when a specific condition is met
🔹 B. A type of ransomware that encrypts files
🔹 C. A firewall rule that blocks traffic
🔹 D. An antivirus signature update

💡 Difficulty: easy | ✅ Correct: A

📖 Explanation:

A logic bomb is malicious code designed to remain dormant until a predefined condition—such as a date, user action, or system event—triggers its execution. Option A correctly captures this behavior. Option B describes ransomware, which encrypts data rather than waiting for a condition. Option C refers to a firewall rule, a network control, not malicious code. Option D mentions an antivirus update, a defensive measure. Recognizing the definition helps identify stealthy threats in real systems.

Q2. How does a logic bomb differ from a traditional computer virus?

🔹 A. A logic bomb encrypts files, whereas a virus only displays messages
🔹 B. A logic bomb modifies hardware, while a virus alters software
🔹 C. A logic bomb activates based on a condition, while a virus spreads by replicating itself
🔹 D. A logic bomb requires user interaction, while a virus operates automatically

💡 Difficulty: medium | ✅ Correct: C

📖 Explanation:

The key distinction is that a logic bomb waits for a trigger condition before executing, whereas a virus actively replicates itself to spread across systems. Option C states this accurately. Option A confuses ransomware behavior with logic bombs. Option B incorrectly suggests hardware modification, which is not typical for either. Option D mischaracterizes the need for user interaction; many viruses run autonomously. Understanding this difference aids analysts in selecting appropriate detection strategies.

Q3. Why are logic bombs often embedded in legitimate applications rather than delivered as separate files?

🔹 A. Because they need large storage space only available in apps
🔹 B. To exploit trusted execution rights and avoid suspicion
🔹 C. To increase network bandwidth usage
🔹 D. Because they cannot run without a graphical interface

💡 Difficulty: medium | ✅ Correct: B

📖 Explanation:

Embedding a logic bomb in a trusted application allows it to inherit the application's legitimate access rights, making detection harder and avoiding user suspicion. Option B correctly explains this motive. Option A is inaccurate; logic bombs are typically small. Option C misstates any effect on bandwidth, which is unrelated. Option D incorrectly claims a graphical interface is required. Knowing this tactic helps defenders scrutinize privileged software for hidden malicious code.

Q4. A company discovers a logic bomb that will delete logs on March 1. Which detection method is most likely to identify it before activation?

🔹 A. Signature‑based scanning of files
🔹 B. Network traffic analysis of outbound connections
🔹 C. Regular password policy audits
🔹 D. Heuristic behavior monitoring of processes

💡 Difficulty: medium | ✅ Correct: D

📖 Explanation:

Heuristic behavior monitoring examines program actions for suspicious patterns, such as scheduled deletions, and can flag a dormant payload before its trigger date. Option D therefore offers the best chance of early detection. Signature‑based scanning (Option A) relies on known code signatures, which a custom logic bomb lacks. Network traffic analysis (Option B) would miss a local file‑based trigger. Password audits (Option C) address credential strength, not malicious code behavior. Applying heuristics aligns with proactive security.

Q5. A logic bomb is programmed to elevate privileges and install a backdoor when a specific admin account logs in. Which mitigation strategy provides the strongest defense?

🔹 A. Mandatory access controls that restrict privilege escalation
🔹 B. Regular operating‑system patching
🔹 C. Disabling all admin accounts permanently
🔹 D. Encrypting the file system with full‑disk encryption

💡 Difficulty: hard | ✅ Correct: A

📖 Explanation:

Mandatory access controls (MAC) enforce strict policies that prevent processes from exceeding their authorized privileges, even if a logic bomb attempts escalation, making it the most robust defense. Option A is correct. Regular patching (Option B) improves overall security but does not stop a correctly coded privilege‑escalation payload. Disabling admin accounts (Option C) is impractical for needed operations. Full‑disk encryption (Option D) protects data at rest, not runtime privilege abuse. Hence MAC directly mitigates the bomb’s core objective.

Q6. Why are signature‑based antivirus tools generally ineffective against logic bombs?

🔹 A. Because logic bombs hide in encrypted archives
🔹 B. Because they trigger only under rare conditions
🔹 C. Because they are only active on mobile devices
🔹 D. Because they use polymorphic code to change appearance

💡 Difficulty: hard | ✅ Correct: B

📖 Explanation:

Signature‑based AV relies on known code patterns; a logic bomb remains inert until a specific, often rare, trigger occurs, so its malicious code never appears during a scan. Option B correctly identifies this limitation. Option A suggests encryption hiding, which is not the primary issue. Option C incorrectly limits activity to mobile platforms. Option D mentions polymorphism, which affects detection but is not the main reason logic bombs evade signatures. Understanding this helps organizations adopt behavior‑based defenses.

Q7. A company uses scheduled tasks to run maintenance scripts. Which policy reduces the risk of logic bomb insertion?

🔹 A. Allow any user to edit the scripts freely
🔹 B. Require code signing for all scheduled scripts
🔹 C. Store scripts on a shared network drive without restrictions
🔹 D. Disable system logging to improve performance

💡 Difficulty: medium | ✅ Correct: C

📖 Explanation:

Requiring code signing ensures that only authenticated, trusted scripts can be scheduled, preventing unauthorized modifications that could embed a logic bomb. Option C correctly reflects this protective measure. Allowing unrestricted editing (Option A) opens the door for malicious inserts. Storing scripts on an unrestricted shared drive (Option B) does not guarantee integrity. Disabling logging (Option D) removes valuable forensic data, worsening detection. Code signing directly addresses integrity of scheduled tasks.

Q8. What is the relationship between insider threats and logic bombs?

🔹 A. Insider threats are unrelated to logic bombs
🔹 B. Logic bombs are only external threats
🔹 C. Insiders cannot create logic bombs
🔹 D. Insiders often plant logic bombs to cause delayed damage

💡 Difficulty: medium | ✅ Correct: D

📖 Explanation:

Insiders, who have legitimate access, can embed logic bombs within trusted systems to cause damage at a later, often covert, time, making option D correct. Option A denies any connection, which is false. Option B incorrectly limits logic bombs to external actors. Option C suggests insiders lack capability, which is inaccurate. Recognizing that insiders may plant logic bombs underscores the need for insider‑risk monitoring and strict change‑control processes.

Q9. Which term describes malicious code that activates at a specific date or event?

🔹 A. Logic bomb
🔹 B. Worm
🔹 C. Spyware
🔹 D. Rootkit

💡 Difficulty: easy | ✅ Correct: A

📖 Explanation:

The definition matches a logic bomb, which is malicious code designed to trigger on a predefined date or event. Option A correctly names this threat. A worm (Option B) spreads autonomously without a timed trigger. Spyware (Option C) covertly gathers information, not necessarily timed. A rootkit (Option D) hides its presence and grants privileged access, but does not rely on a specific activation condition. Knowing the term helps security teams classify and respond to time‑based attacks.
