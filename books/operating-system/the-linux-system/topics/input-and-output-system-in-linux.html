What is Input and Output system in Linux?

Definition:
Input and Output system in Linux implements a layered architecture with VFS at top, device-independent buffering/caching in middle, and device-specific drivers at bottom, unified through file descriptors and system calls.

Example:
Writing to \( /dev/sda \) passes through VFS → block layer → SCSI driver → SATA controller, with request merging and scheduling optimizing throughput for sequential \( 1MB \) writes.

Reason:
Layered I/O design balances performance, portability, and usability by caching frequent accesses, batching operations, and hiding hardware complexity behind consistent abstractions.

📝 All Input and Output system in Linux MCQs

Q1. What is the primary purpose of the page cache in Linux I/O?

A.To store metadata about files
B.To hold entire pages of file contents for faster access ✅
C.To manage network sockets
D.To schedule CPU time
💡 Difficulty: easy | ✅ Correct: B

📖 Explanation: The page cache is a memory area that keeps full pages of file data, allowing subsequent reads to be served from RAM instead of disk. Option B describes this exactly. Option A confuses the cache with inode metadata, which is not cached here. Option C refers to networking, unrelated to file caching. Option D describes CPU scheduling, which the page cache does not affect. By keeping pages in memory, the system reduces I/O latency and improves overall performance.

Q2. How does the virtual memory system interact with the page cache when a process reads a file?

A.The virtual memory system directly writes to disk bypassing the page cache
B.The page cache updates the process's CPU registers
C.The page cache stores pages, and the virtual memory system maps those pages into the process's address space ✅
D.The virtual memory system deletes pages from the cache after each read
💡 Difficulty: medium | ✅ Correct: C

📖 Explanation: When a file is read, the kernel first loads the needed page into the page cache. The virtual memory subsystem then creates a mapping so the process can access that cached page via its address space. Option C captures this two‑step interaction. Option A is false because writes go through the cache, not directly to disk. Option B misstates the role of registers. Option D is incorrect; pages remain cached for reuse.

Q3. A web server reads a large static file repeatedly. Which configuration change most directly reduces disk I/O for subsequent reads?

A.Increase the size of the page cache
B.Disable NFS ✅
C.Reduce the file's permissions
D.Increase CPU frequency
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: Expanding the page cache gives the kernel more RAM to retain file pages, so later reads can be satisfied from memory without hitting the disk. This directly cuts I/O. Disabling NFS (option B) is irrelevant if the file is local. Changing permissions (option C) does not affect caching. Raising CPU speed (option D) may speed processing but does not eliminate disk accesses. Hence, option A is the correct performance‑focused tweak.

Q4. When a client accesses a file over NFS, which mechanism allows cached network data to be reused without re‑fetching from the server?

A.Inode revalidation
B.Write‑through caching
C.Page cache storing networked pages ✅
D.Swap space
💡 Difficulty: medium | ✅ Correct: C

📖 Explanation: NFS data can be stored in the same page cache used for local files; pages that contain networked file data remain in RAM and can be reused, avoiding another network round‑trip. Option C describes this behavior. Inode revalidation (option A) checks metadata, not data reuse. Write‑through caching (option B) forces writes to disk immediately, not relevant for reads. Swap space (option D) is for paging out memory, not caching remote file data.

Q5. A program calls mmap() to map a 4 KB file region. Which sequence correctly describes what happens inside the kernel?

A.Kernel allocates a new page, copies file data into it, updates page tables, and adds an entry to the vm_area_struct tree ✅
B.Kernel writes directly to the disk block, bypassing the page cache
C.Kernel creates a socket, sends data to a remote server, and stores result in swap
D.Kernel deletes existing vm_area_struct entries
💡 Difficulty: hard | ✅ Correct: A

📖 Explanation: When mmap() is used, the kernel first ensures a page exists in the page cache, copies the file's contents if needed, then updates the process's page tables to point to that page, and finally records the region in a vm_area_struct node linked in a balanced tree. This full sequence matches option A. Direct disk writes (option B) ignore caching, which is not how mmap works. Option C describes network I/O, unrelated to memory mapping. Option D would remove the mapping, not create it.

Q6. Why are vm_area_struct objects linked in a balanced binary tree rather than a simple list?

A.To enable concurrent modifications without locking
B.To allow faster page fault handling by reducing lookup time to O(log n) ✅
C.To store file contents directly
D.To simplify swapping
💡 Difficulty: hard | ✅ Correct: B

📖 Explanation: A balanced binary tree provides logarithmic search time, so the kernel can quickly locate the region that contains a given virtual address during a page fault. This efficiency is essential for performance. Option B captures this reason. Option A is inaccurate; locking is still required. Option C confuses the structure with data storage, which it does not do. Option D is unrelated; swapping concerns pages, not the organization of vm_area_struct nodes.

Q7. A system under memory pressure decides to swap out pages belonging to a process's anonymous region. Which characteristic of those pages makes them eligible for swapping?

A.They are mapped to a file on disk
B.They are dirty and not yet written to the page cache
C.They are not currently referenced and reside only in RAM ✅
D.They are part of the kernel's page tables
💡 Difficulty: medium | ✅ Correct: C

📖 Explanation: Anonymous pages have no backing store on disk; when they are not referenced, the kernel can write their contents to swap space to free RAM. This matches option C. Pages mapped to a file (option A) can be dropped because the file provides the data. Dirty pages (option B) must be written back before swapping, not a direct eligibility criterion. Kernel page tables (option D) are not swapped; they remain in memory.

Q8. When defining a new memory region for a process, why must the region be page‑aligned?

A.Because the CPU only accesses memory in 8‑byte chunks
B.Because page tables map memory at page granularity ✅
C.Because it reduces network latency
D.Because it improves disk scheduling
💡 Difficulty: easy | ✅ Correct: B

📖 Explanation: Memory management hardware works with pages, typically 4 KB in size. Page tables store entries that describe entire pages, so any region must start at a page boundary to be represented correctly. Option B states this requirement. The other options describe unrelated effects: CPU alignment is finer than page size (option A), network latency (option C) and disk scheduling (option D) are not determined by alignment of virtual regions.

Q9. If a process reads a file page that is not present in the page cache, what is the immediate effect on the page cache?

A.The page cache allocates a new page and loads the data from disk into it ✅
B.The page cache clears all existing pages
C.The page cache sends a signal to the network interface
D.The page cache disables further reads until the page is written
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: When a miss occurs, the kernel brings the missing page into the page cache by allocating a fresh page frame and reading the data from storage. This is exactly what option A describes. Clearing all pages (option B) would be wasteful and never happens on a miss. Sending a network signal (option C) is unrelated unless the file is remote, which is not implied. Disabling reads (option D) would halt I/O, which is not the kernel's behavior.
