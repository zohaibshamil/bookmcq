Execution and Loading of User Programs in The Linux System parses executable formats (ELF), sets up virtual memory mappings, resolves dynamic symbols, and transfers control to entry points via execve() system call infrastructure.

Q1. What system call creates a new process by duplicating the calling process without loading a new executable image?

A.execve()
B.fork() ✅
C.clone()
D.wait()
💡 Difficulty: easy | ✅ Correct: B

📖 Explanation: The fork() call duplicates the current process, creating a child that starts execution at the same point but with its own copy of the parent’s memory and resources. execve() replaces a process image, clone() can create threads or processes depending on flags, and wait() merely pauses the parent. Therefore fork() is the only call that matches the description, making it the correct choice. The other options either load a new program or perform unrelated actions.

Q2. How does the behavior of clone() differ from fork() when no sharing flags are specified?

A.clone() always shares memory
B.clone() creates a thread
C.clone() behaves like fork() ✅
D.clone() fails and returns an error
💡 Difficulty: medium | ✅ Correct: C

📖 Explanation: When clone() is invoked without any CLONE_* flags, it does not share resources with the parent, so it creates a new task that is functionally equivalent to a process created by fork(). It does not automatically share memory or act as a thread, and it does not fail; it succeeds in creating a separate task. Thus the correct answer is that clone() behaves like fork() under these conditions, while the other statements mischaracterize its behavior.

Q10. Why does Linux treat threads and processes as tasks rather than separate entities?

A.Because tasks are faster to schedule than processes.
B.Because Linux stores each context component in separate substructures, allowing selective sharing. ✅
C.Because threads cannot have their own memory space.
D.Because processes are deprecated in modern Linux kernels.
💡 Difficulty: easy | ✅ Correct: B

📖 Explanation: Linux represents every execution flow as a task because the kernel keeps the various parts of a context—such as the file‑system view, memory map, and signal table—in independent structures. This design lets the kernel decide which parts to share when a new task is created, turning a clone into a thread or a fork into a separate process. By using a single task type, the scheduler and accounting code remain simple, and resources can be shared or isolated flexibly. Hence the correct answer is that Linux stores each context component in separate substructures, enabling selective sharing.

Q17. What is the primary difference between static and dynamic linking?

A.Static linking copies all library code into the executable at build time ✅
B.Dynamic linking loads library code into memory only when the program starts
C.Static linking requires a loader to resolve symbols at runtime
D.Dynamic linking embeds library code directly into the executable
💡 Difficulty: easy | ✅ Correct: A

📖 Explanation: Static linking embeds the entire library into the final binary, so the program contains its own copy of needed functions. This makes the executable larger but independent of external files. Dynamic linking keeps the executable small and resolves symbols when the program runs, pulling code from shared libraries. Options B and C confuse the timing of symbol resolution, while D reverses the roles of the two techniques.

Q24. A system needs to load optional plugins at runtime. Which linking mechanism best supports this requirement?
