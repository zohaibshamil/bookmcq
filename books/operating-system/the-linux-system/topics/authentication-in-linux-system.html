What is Authentication in Linux System?

Definition:
Authentication in Linux System verifies user identity through pluggable modules (PAM), supporting passwords, SSH keys, biometrics, and LDAP/RADIUS backends via standardized configuration in /etc/pam.d/.

Example:
Login attempts invoke pam_unix.so for local password check against /etc/shadow/etc/shadow/etc/shadow hash, falling back to pam_ldap.so for enterprise directory authentication based on service-specific PAM stack.

Reason:
PAM decouples authentication logic from applications, enabling centralized policy updates and multi-factor support without modifying sshd, sudo, or login binaries individually.

Q1. A system administrator wants to allow SSH connections (port 22) only from the trusted IP 192.168.1.10. Which firewall chain ordering will correctly enforce this rule without exposing the SSH service to other hosts?

A.Place the allow rule in the INPUT chain after a generic deny‑all rule.
B.Place the allow rule in the INPUT chain before the generic deny‑all rule. ✅
C.Place the allow rule in the FORWARD chain before any other rules.
D.Place the allow rule in the OUTPUT chain.
💡 Difficulty: easy | ✅ Correct: B

📖 Explanation: The correct answer is B because placing the allow rule before the generic deny‑all rule ensures the packet matches the specific permit condition first, so the SSH connection from 192.168.1.10 is accepted. Option A would never be reached because the deny‑all rule blocks the packet earlier. Option C applies to forwarded traffic, not locally‑destined packets, so it would not affect SSH input. Option D affects outbound traffic, which is irrelevant for incoming SSH. By ordering the rule correctly, the firewall enforces authentication by limiting access to the trusted host.

Q2. If a route‑caching entry for destination 10.0.0.5 expires after a period with no hits, what is the most likely effect on an authentication server that relies on that route for client connections?

A.Clients will receive faster responses because the cache is cleared. ✅
B.The server will drop all incoming packets from that destination.
C.Authentication will be bypassed due to missing route information.
D.Increased latency as each new packet requires a full FIB lookup before reaching the server.
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: When the cached route for 10.0.0.5 expires, the IP layer must perform a full FIB lookup for each new packet. This adds latency before the packet reaches the authentication server, potentially causing time‑outs for clients expecting quick responses. Option A suggests faster delivery, which is incorrect because the route must be recomputed. Option B claims the server will drop packets, which is not true; packets are still forwarded after the lookup. Option C mentions a security breach, which is unrelated to caching. Option D correctly identifies increased latency due to the extra lookup.

Q3. Why does the route cache store only exact destinations and never wildcard entries?

A.Because each cached entry must map one address to a single next‑hop for O(1) retrieval.
B.Because wildcard entries exceed kernel memory limits. ✅
C.Because wildcards are illegal in Linux routing tables.
D.Because storing wildcards would create security vulnerabilities.
💡 Difficulty: easy | ✅ Correct: B

📖 Explanation: The cache stores exact destinations because wildcard entries would match many destinations, defeating the purpose of quick look‑ups; each cached entry must map one address to a single next‑hop, guaranteeing O(1) retrieval. Option B suggests memory limits, which is not the primary reason. Option C claims wildcards are illegal, which is false. Option D states wildcards cause security holes, which is not accurate. By caching only specific routes, the system ensures deterministic performance and avoids ambiguous matches.

Q4. How does IP fragmentation impact the ability to authenticate the integrity of a packet?

A.Each fragment is independently authenticated, so integrity is checked per fragment. ✅
B.Fragmentation improves authentication by spreading checksums across fragments.
C.Authentication can only be performed after all fragments are reassembled and the payload checksum is verified.
D.Fragmentation automatically bypasses authentication mechanisms.
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: Fragmentation splits a large packet into smaller pieces, each carrying its own header but sharing the original payload checksum. The receiver must reassemble the fragments before verifying the end‑to‑end integrity checksum, so authentication can only be performed after reassembly. Option A says each fragment is independently authenticated, which is incorrect because the checksum covers the whole payload. Option B claims fragmentation improves authentication, which is misleading. Option D suggests authentication is bypassed, which is not true if reassembly is done correctly. Therefore, proper reassembly is essential for reliable authentication.

Q5. During reassembly, which step ensures that a fragmented packet has not been tampered with before authentication?

A.Verifying the payload checksum of the reconstructed packet after all fragments arrive.
B.Checking the MAC address of each individual fragment. ✅
C.Applying TLS verification to each fragment separately.
D.Discarding fragments that exceed a predefined size limit.
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: The IP driver computes the header checksum for each fragment and, after all fragments arrive, verifies the payload checksum of the reconstructed packet. This final checksum verification guarantees that no bits were altered during transmission. Option B suggests checking the MAC address of each fragment, which is not part of IP reassembly. Option C mentions using TLS, which operates above IP and is unrelated to fragment handling. Option D proposes discarding fragments based on size, which does not address integrity. Thus, the checksum step is the decisive safeguard.

Q6. An administrator notices that overlapping rules in the INPUT and FORWARD chains allow unauthenticated traffic to reach a protected service. Which configuration change most effectively closes the bypass?

A.Add a deny‑all rule to the OUTPUT chain. ✅
B.Reorder the existing rules in the INPUT chain only.
C.Place a deny‑all rule at the top of both INPUT and FORWARD chains.
D.Disable the FORWARD chain entirely.
💡 Difficulty: hard | ✅ Correct: A

📖 Explanation: Moving the deny‑all rule to the top of both INPUT and FORWARD chains ensures that any packet not explicitly permitted is dropped before it can be forwarded, eliminating the overlap that creates the bypass. Option A, adding a rule to the OUTPUT chain, does not affect inbound traffic. Option B, changing the rule order in only one chain, leaves the other chain vulnerable. Option D, disabling the FORWARD chain, would stop all forwarded traffic but also break legitimate routing. Therefore, placing a top‑level deny rule in both chains is the safest fix.

Q7. Why does separating firewall rules into distinct INPUT, OUTPUT, and FORWARD chains improve authentication enforcement?

A.It reduces the overall processing time for each packet. ✅
B.It allows policies to be applied based on packet direction, preventing rules from unintentionally permitting traffic in the wrong direction.
C.It simplifies the routing tables used by the kernel.
D.It eliminates the need for network address translation.
💡 Difficulty: hard | ✅ Correct: A

📖 Explanation: Distinct chains allow policies to be applied based on the packet’s direction relative to the host, so authentication checks can be tailored for inbound, outbound, and transit traffic. This separation prevents a rule intended for one direction from unintentionally permitting traffic in another direction. Option A claims it reduces processing time, which is a secondary effect. Option C suggests it simplifies routing tables, which is unrelated. Option D states it eliminates the need for NAT, which is false. By isolating rule sets, administrators can enforce authentication consistently and avoid accidental rule interactions.

Q8. An attacker sends overlapping IP fragments designed to confuse the reassembly process and inject malicious code that bypasses authentication. Which mitigation provides the strongest protection?

A.Encrypt each fragment separately before transmission. ✅
B.Increase the route‑cache timeout to keep entries longer.
C.Disable the firewall entirely to allow all traffic.
D.Enforce strict fragment reassembly policies that reject overlapping fragments and require the final fragment before processing.
💡 Difficulty: hard | ✅ Correct: A

📖 Explanation: Enforcing strict fragment reassembly policies—such as rejecting overlapping fragments, limiting the number of fragments per packet, and requiring the final fragment before processing—prevents the attacker from exploiting reassembly ambiguities. Option A, encrypting each fragment separately, is impractical and does not address reassembly logic. Option B, increasing the route‑cache timeout, does not affect fragment handling. Option C, disabling the firewall, would remove security altogether. Therefore, robust fragment validation is the most effective defense against this type of bypass.

Understanding that skbuff represents the packet container is essential for grasping how firewall and fragmentation modules manipulate network traffic.

Option A claims it speeds up authentication, which is false because stale entries must be refreshed. Option B suggests it has no effect, ignoring the extra lookup time. Option D states it improves security, which is indirect. Therefore, the timeout introduces latency proportional to the cache refresh interval, impacting time‑sensitive authentication.)
