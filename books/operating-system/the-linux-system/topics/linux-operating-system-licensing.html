📝 All Linux Operating System licensing MCQs

Q1. In which year did Linus Torvalds begin developing the Linux kernel?

🔹 A. 1990
🔹 B. 1992
🔹 C. 1991
🔹 D. 1993

💡 Difficulty: easy | ✅ Correct: C

📖 Explanation:

The correct answer is 1991 because Linus Torvalds started the project in that year, marking the birth of Linux. The other years are close but incorrect: 1990 predates the actual start, 1992 and 1993 refer to later milestones. Knowing the start date helps students place Linux in the timeline of operating‑system evolution, which is useful when comparing it to other UNIX‑like systems.

Q2. Why was releasing the Linux source code with minimal distribution restrictions important for its early growth?

🔹 A. It encouraged worldwide collaboration
🔹 B. It allowed commercial profit
🔹 C. It prevented any modifications
🔹 D. It required users to pay licensing fees

💡 Difficulty: easy | ✅ Correct: A

📖 Explanation:

Option A is correct because low barriers let developers across the globe contribute, creating a vibrant community that accelerated feature development. Option B is false; the intent was not to generate profit. Option C contradicts the open‑source model, and option D is wrong because no fees were imposed. Understanding this motivation shows how open licensing can drive rapid adoption in real‑world projects.

Q3. A company plans to ship a hardware product that includes a modified Linux kernel. Which action satisfies the GPL requirements for the kernel?

🔹 A. Keep the source code private
🔹 B. Release the modified source under the GPL
🔹 C. Charge a fee for the source code
🔹 D. Distribute only the compiled binaries

💡 Difficulty: medium | ✅ Correct: A

📖 Explanation:

Releasing the modified source under the GPL fulfills the license’s copyleft clause, ensuring that anyone receiving the binary can also obtain the corresponding source. Keeping the source private (A) violates the GPL, charging a fee (C) is not required and may be prohibited, and distributing only binaries (D) fails to provide the required source. This mirrors real‑world compliance steps for embedded Linux products.

Q4. A developer adds a new driver to the Linux kernel and shares the compiled module publicly but not the source. Which statement is true under the GPL?

🔹 A. There is no obligation to share the source
🔹 B. The driver must be rewritten under a proprietary license
🔹 C. The driver’s source must be provided to recipients
🔹 D. The driver must be removed from the distribution

💡 Difficulty: medium | ✅ Correct: C

📖 Explanation:

The GPL obliges anyone who distributes a derivative work, such as a new driver, to provide the complete corresponding source. Therefore option C is correct. Option A ignores the copyleft requirement, option B is impossible because the GPL does not allow relicensing as proprietary, and option D is unnecessary if the source is supplied. This reflects typical community expectations for contributed kernel code.

Q5. A university customizes the Linux kernel for internal research but does not distribute the resulting system outside the campus. What licensing requirement applies?

🔹 A. No requirement to release the source
🔹 B. They must publish the source publicly
🔹 C. They must obtain a commercial license
🔹 D. They must replace the GPL with a BSD license

💡 Difficulty: medium | ✅ Correct: A

📖 Explanation:

When the modified kernel is used only internally and never distributed, the GPL does not trigger the source‑release obligation, making option A correct. Publishing the source (B) is only required upon distribution, a commercial license (C) is unnecessary, and changing the license (D) is not permitted. This scenario helps students see how internal use differs from commercial distribution under open‑source licenses.

Q6. A startup sells embedded devices that contain a Linux kernel with proprietary modifications. What must they include with each device to comply with GPLv2?

🔹 A. A handwritten note describing the changes
🔹 B. Only the compiled binary files
🔹 C. No source code is needed if the device is sealed
🔹 D. The full source code of the kernel and all modifications

💡 Difficulty: hard | ✅ Correct: D

📖 Explanation:

GPLv2 requires that anyone who distributes binaries also provide the complete corresponding source, so the startup must ship the full source (option D). A handwritten note (A) is insufficient, providing only binaries (B) violates the license, and claiming the device is sealed (C) does not exempt them from source distribution. This mirrors legal obligations for commercial products using GPL‑licensed code.

Q7. A software vendor wants to combine the GPL‑licensed Linux kernel with a proprietary user‑space application. Which approach lets them keep the application proprietary without violating the GPL?

🔹 A. Dual‑license the kernel
🔹 B. Keep the kernel GPL and keep the application proprietary but separate
🔹 C. Re‑license the kernel under the MIT license
🔹 D. Release the entire system under the GPL

💡 Difficulty: hard | ✅ Correct: B

📖 Explanation:

The GPL covers the kernel, but it does not automatically impose its terms on separate user‑space programs that merely run on top of the kernel. Keeping the kernel GPL and the application proprietary (option B) is permissible as long as they remain distinct works. Dual‑licensing (A) or re‑licensing (C) would require the kernel author's consent, and releasing everything under GPL (D) would unnecessarily open the proprietary code. This reflects common licensing strategies in the industry.

Q8. How does the distinction between the Linux kernel and the complete Linux system affect licensing considerations for developers?

🔹 A. Kernel is GPL while system components are all proprietary
🔹 B. Kernel is GPL while other components may have different licenses
🔹 C. All components must be GPL
🔹 D. Licensing is irrelevant to development decisions

💡 Difficulty: medium | ✅ Correct: D

📖 Explanation:

Option D is correct because the kernel’s GPL status does not dictate the licenses of all surrounding tools, libraries, or desktop environments, which can be GPL, BSD, MIT, or proprietary. Option A incorrectly assumes all system parts are proprietary, option B is partially true but not the best answer here, and option C is false. Recognizing this separation helps developers choose compatible components for their projects.

Q9. What is the primary reason the GPL license was chosen for the Linux kernel instead of a permissive license?

🔹 A. To ensure that improvements remain free
🔹 B. To maximize profit for the original author
🔹 C. To restrict any use of the kernel
🔹 D. To simplify the code base

💡 Difficulty: medium | ✅ Correct: A

📖 Explanation:

The GPL’s copyleft clause guarantees that any enhancements to the kernel stay freely available, which aligns with the community’s goal of shared progress (option A). Maximizing profit (B) contradicts the open‑source philosophy, restricting use (C) is not a GPL characteristic, and simplifying the code (D) is unrelated to licensing choice. This reasoning explains why many large‑scale open‑source projects adopt the GPL.
