What is Linux Operating System licensing?

Definition:
Linux Operating System licensing primarily uses the GNU General Public License version 2 (GPLv2), which guarantees users freedom to run, study, modify, and redistribute the software while requiring derivative works to remain under the same license terms.

Example:
If a company modifies the Linux kernel and distributes it, they must release their changes under GPLv2, ensuring for all recipients.

Reason:
This copyleft licensing model prevents proprietary enclosure of improvements, fostering collaborative development and ensuring the ecosystem remains perpetually open and accessible to all.

📝 All Linux Operating System licensing MCQs

Q1. Which of the following best describes the fundamental philosophy of the GNU General Public License (GPL) regarding software distribution?

A.It permits users to modify and redistribute the software under any license of their choice, including proprietary ones.
B.It ensures that the source code of derivative works must be made available to the end-user under the same GPL terms when the software is distributed. ✅
C.It restricts the commercial use of the software by charging a per-copy royalty fee to the distributor.
D.It allows developers to keep their modifications private forever, as long as they do not distribute the binary.
💡 Difficulty: hard | ✅ Correct: B

📖 Explanation: The GPL's core philosophy is 'copyleft', which mandates that anyone who distributes a modified version of the software must also distribute the source code under the same license terms. This ensures freedoms are preserved for all recipients. Option A is incorrect because the GPL specifically prohibits sublicensing under a different license. Option C is a common misconception as the GPL does not prohibit commercial use or charge fees; it just requires source sharing. Option D describes the core of proprietary software, which is the exact opposite of the GPL.

Q2. A developer creates a new program by linking to a dynamically linked library (libfoo.so) that is licensed under the GNU GPL. The developer writes their own main code and distributes the entire application as a binary. Under strict interpretation of the GPL, what must the developer do?

A.They must only release the source code for the library (libfoo), not for their own main application.
B.They must release the source code for the entire work under the GPL, as the combined program is considered a derivative work. ✅
C.They must purchase a commercial license from the FSF to avoid releasing their own source code.
D.They are exempt from releasing any source code because dynamic linking is not considered a 'derivative work' by the GPL.
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: Dynamic linking with a GPL-licensed library creates a combined work that is, according to the FSF's interpretation, a derivative of the GPL code. Therefore, distributing the binary without offering the corresponding source code for the entire combined program violates the GPL. Option A is incorrect because the GPL covers the 'whole work'. Option C is false; the FSF does not sell exceptions for GPL libraries (though the copyright holder could). Option D is a long-standing legal gray area in some jurisdictions, but the strict HOTS interpretation is that it is a derivative work requiring the full source.

Q3. You find a bug in a Linux kernel module. You download the source code, fix the bug, and compile the module on your personal laptop. You never distribute the binary or the source code to anyone else. Which of the following is TRUE regarding your obligations under the GPL?

A.You must publish your modifications on a public website.
B.You must send your modifications to Linus Torvalds for review.
C.You have no obligation to share your modifications because you are not distributing the software. ✅
D.You must pay a fee to the FSF for the right to modify the kernel.
💡 Difficulty: easy | ✅ Correct: C

📖 Explanation: The GPL is a distribution-centric license. The rights and obligations (like providing source code) are triggered when you 'convey' or 'distribute' the software to others. Personal use, internal modifications within an organization, or modifications that are never shared with third parties do not trigger the source-distribution requirement. Option A and B are common mistakes; they confuse community norms with legal requirements. Option D is incorrect as modification is a fundamental right granted under the GPL without fee.

Q4. A commercial company distributes a hardware appliance that contains a Linux kernel modified by their engineers. They provide the modified kernel source code on a CD, but the CD is not included with the appliance; instead, a note in the manual says 'source available on request for a fee of $50 to cover shipping and handling'. Does this comply with the GPL?

A.Yes, absolutely, as the GPL allows a charge to cover the physical act of distribution. ✅
B.No, because the GPL explicitly forbids any charge for source code distribution.
C.No, because they must make the source code available for download for free.
D.Yes, but only if the $50 is refundable upon request.
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: The GPL explicitly permits charging a fee for the physical act of distribution (e.g., covering the cost of a CD or shipping). However, the source code must be made available to the recipient. The company is compliant by offering it on a CD for a reasonable fee. Option B is incorrect; the GPL does not forbid charging for source distribution, only that it must be available. Option C is a common misunderstanding; there is no requirement for free online access in the GPLv2. Option D is irrelevant.

Q5. Which of the following scenarios represents a clear violation of the GPL (v2) in the context of a desktop Linux distribution?

A.A user modifies the kernel to improve Wi-Fi performance on their personal computer.
B.A company distributes a Linux distro that includes proprietary NVIDIA graphics drivers alongside GPL code.
C.A company distributes binary-only patches for the Linux kernel without providing the source code to those patches. ✅
D.A developer creates a proprietary application that uses a system call to the Linux kernel.
💡 Difficulty: medium | ✅ Correct: C

📖 Explanation: Distributing a binary patch to a GPL-licensed component (the kernel) without the source code is a clear violation, as the patch itself is a derivative work. Option B, while frowned upon, is technically a 'mere aggregation' if the proprietary driver is a separate module, and many distributions do this. Option A is personal use, no distribution. Option D is generally accepted, as system calls are considered interface boundaries and do not necessarily create a derivative work, per the 'system call exception' argument (though legally debated, it's standard practice).

Q6. The Linux kernel is licensed under the GPL, but user-space applications are often licensed under proprietary licenses. How is it legally possible to run a proprietary program on top of Linux?

A.The GPL contains an explicit exception allowing any software running in user-space to be proprietary.
B.Distributing the kernel and the proprietary application together is considered 'mere aggregation', and the GPL's restrictions do not extend to the proprietary application. ✅
C.The proprietary developer must pay a 'runtime fee' to the FSF.
D.It is not legal; all software running on Linux must be open-source.
💡 Difficulty: hard | ✅ Correct: B

📖 Explanation: The GPL covers the kernel itself, but it has no jurisdiction over programs that run on top of it. This is the fundamental principle of 'mere aggregation'. The proprietary app, the kernel, and shared libraries are seen as separate works unless the proprietary app is specifically derived from the kernel code. There is no 'system call exception' in the GPL text, but the FSF's interpretation states that normal communication via system calls does not make an application a derivative work. Option A describes an exception that doesn't exist in the standard GPL. Option D is false.

Q7. You are analyzing the network activity of a Linux system. The graph below shows the number of active TCP connections over time. A.You cannot audit the kernel because it is proprietary.

C.You can only audit the proprietary application's source code.
D.You cannot audit the kernel because the memory management is closed-source.
💡 Difficulty: easy | ✅ Correct: B

📖 Explanation: The Linux kernel is under the GPL. This license explicitly grants you the freedom to access, study, and modify the source code. A claim about a memory leak can be verified by examining the source of the slab allocator or VM subsystems. The proprietary application cannot be audited if its license forbids it, but the kernel is entirely open. Option A and D are factually incorrect. Option C is incorrect for the kernel, though it is true for the proprietary app.

Q8. Consider a developer who writes a kernel module that is 'closed-source' and only distributed as a binary. They claim they are not violating the GPL because they use a 'proprietary shim' layer. This shim is also binary. This is a classic method to circumvent the GPL. What is the most accurate legal/community perspective on this practice?

A.This is perfectly legal and accepted by all Linux maintainers.
B.This is considered a 'GPL circumvention' and the FSF and kernel maintainers view it as a violation because the shim is designed to link the proprietary code with the kernel, creating a derivative work. ✅
C.This is legal because the shim acts as a barrier, preventing the proprietary code from being a derivative work.
D.This is legal, but the developer must still provide the source code for the shim.
💡 Difficulty: hard | ✅ Correct: B

📖 Explanation: This is a highly debated topic, but the kernel community strongly considers this a violation. They argue that the shim is a 'wrapper' specifically written to interface with the GPL kernel, making it a derivative work of the kernel. If the proprietary code and the shim are combined with the kernel, the whole work must be GPL. This is the basis for many legal threats (e.g., the 'GPL enforcement' cases). Option A is false, the community is very hostile to this. Option C is the legal argument of the circumvention, which is typically not successful. Option D is nonsensical; if it's a derivative, the entire code must be GPL, not just the shim.

Q9. A system administrator uses a tool to extract the source code of a running Linux kernel process from `/proc/kcore`. They find a section of code that has no corresponding source in the official kernel tree. They suspect this is a binary blob injected by a proprietary driver. Which of the following licensing statements is TRUE?

A.This is valid, as proprietary drivers are allowed to overwrite kernel memory.

C.This is valid if the binary blob is signed by the hardware manufacturer.
D.This is a violation only if the binary blob is larger than 4MB.
💡 Difficulty: hard | ✅ Correct: B

📖 Explanation: Dynamic linking, loading a module, or even injecting code into the kernel to create a combined work falls under the GPL's derivative work definition. The GPL covers the Linux kernel. Distributing a binary-only module that is specifically designed to run in the kernel constitutes a violation unless it is GPL-compatible. The 'signature' (Option C) is irrelevant to the GPL requirements. Option A is false; you cannot legally overwrite memory with proprietary code for distribution. Option D is a distractor with no basis in licensing.

Q10. Which of the following licenses is MOST compatible with the GPL for merging code into a single project?

A.MIT License
B.Apache License 2.0
C.BSD 3-Clause License (without the advertising clause)
D.All of the above ✅
💡 Difficulty: easy | ✅ Correct: D

📖 Explanation: The MIT, Apache 2.0, and BSD 3-Clause (without advertising) are all permissive licenses that are GPL-compatible. They do not restrict the GPL's ability to enforce its terms on the combined work. They can be relicensed into a GPL project. Option A, B, and C are all correct individually, making D the best answer. A common misconception is that all open-source licenses are compatible, but some (like the old BSD with advertising clause, or MPL 1.1) require careful examination or are considered incompatible.

Q11. A developer contributes a patch to the Linux kernel. The patch is accepted into the mainline. What is the licensing status of that patch?

A.The patch remains the intellectual property of the original author, who can relicense it later.
B.The patch becomes part of the kernel and is licensed under the GPLv2, but the author retains copyright. ✅
C.The patch becomes part of the public domain.
D.The patch becomes the property of the Linux Foundation.
💡 Difficulty: hard | ✅ Correct: B

📖 Explanation: When a patch is submitted and accepted to the kernel, it is merged into the GPL-licensed codebase. The 'inbound=outbound' principle applies: the patch is licensed under the GPLv2. However, the original author retains the copyright. This is important because if the license were to change, the author's consent would be required. Option A is incorrect; they cannot relicense the patch independently after it's part of a GPL collective work. Option C is false. Option D is false; the copyright remains with the author, not the Foundation.

Q12. A company has a fleet of 10,000 embedded systems running Linux. They modify the kernel for a specific custom hardware platform and distribute these systems to customers. According to the GPL, what is the company's obligation to provide source code to the customers?

A.They must provide the source code to the customers, but not to the general public, if the software is used in an embedded system. ✅

C.They only need to provide source code if they charged the customer for the system.
D.They do not need to provide source code because it is embedded hardware.
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: The GPL's trigger is distribution. They have distributed the software to customers. Therefore, they must offer the source code to those customers. There is no 'embedded exception' in the GPL. Option A is correct; they have to provide it to the recipients. Option B is incorrect; they only need to provide it to the people they distributed the binary to (the customers), not the general public unless they choose to. Option C is wrong; charging or not charging doesn't affect the obligation. Option D is a common myth; embedded systems are not exempt.

Q13. You are reading a bug report. The user says: 'I compiled the kernel with the proprietary NVIDIA driver module using a script that bypasses the GPL check. The module loads. This proves the GPL is not enforceable.' Evaluate this user's reasoning.

A.The reasoning is correct; if the kernel doesn't stop it, it's legal.
B.The reasoning is flawed. Technical circumvention does not imply legal compliance. Loading the module is a technical action, but distribution of the combined binary violates copyright law. ✅
C.The reasoning is partially correct, as the GPL is only a social contract, not a legal document.
D.The reasoning is correct because the Linux kernel does not check licenses.
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: The user is conflating technical capability with legal permission. The Linux kernel has a 'MODULE_LICENSE' macro, but it is not a security mechanism. You can technically load a proprietary module, but doing so and distributing it creates a derivative work that violates the GPL. The legal enforcement happens in court, not in code. Option A is a dangerous misconception. Option C is false; the GPL is a legally binding copyright license. Option D misses the point; the kernel's inability to check doesn't make it legal.

Q14. Which of the following is NOT a permissible distribution mechanism for GPL-licensed source code, assuming you have distributed the corresponding binary?

A.Including a printed copy of the source code with the product.
B.Offering the source code for download via an FTP server, with a URL listed in the documentation.
C.Offering to provide the source code on a physical medium (e.g., CD-ROM) for a fee that covers the cost.
D.Including only a text file that says 'Source code is available upon request' without specifying a reasonable timeframe or fee policy. ✅
💡 Difficulty: hard | ✅ Correct: D

📖 Explanation: The GPL requires that you make the source code accessible to the recipient. It allows various methods: physical media, network download, or a written offer. Option D is considered an invalid offer because it lacks concrete terms (timeframe and cost). The GPL requires a 'written offer, valid for at least three years, to give any third party' the source code. A vague 'upon request' is not sufficient. Options A, B, and C are all explicitly allowed by the GPL text.

Q15. A developer writes a library and releases it under the LGPL (Lesser General Public License). A second developer creates a proprietary closed-source application that links to this LGPL library (dynamically). What is the primary restriction on the proprietary developer?

A.They must release their entire proprietary application under the LGPL.
B.They must not charge money for their application.
C.They must allow the user to replace the LGPL library with a modified version and must provide the necessary object files or link information to do so. ✅
D.They must distribute the source code of their application if they use a dynamic link.
💡 Difficulty: medium | ✅ Correct: C

📖 Explanation: The LGPL provides a 'library exception'. It allows proprietary applications to link to LGPL code (unlike GPL), but it requires that the user be able to replace the library with a modified version. This is done by providing the object files or the ability to relink. Option A is wrong, that's the GPL. Option B is incorrect, LGPL allows commercial use. Option D is incorrect; dynamic linking is the exact scenario the LGPL was designed to permit, provided the re-linkability requirement is met.

Q16. A company distributes a derivative work of a GPL-licensed program. They include a 'click-wrap' license agreement that pops up during installation, which attempts to restrict the user's rights (e.g., prohibiting reverse engineering). Does this override the GPL?

A.Yes, the click-wrap agreement is a contract and supersedes the license.
B.No, the GPL is a copyright license. If the terms conflict, the GPL controls what rights you have to distribute, and the user can ignore the click-wrap's restrictions regarding GPL rights. ✅
C.Yes, but only if the user clicks 'I Agree'.
D.No, because the GPL is invalid in the user's jurisdiction.
💡 Difficulty: hard | ✅ Correct: B

📖 Explanation: This is a classic case of licensing conflicts. The GPL is a copyright license that grants rights. The distributor of GPL software cannot unilaterally revoke those rights through a separate contract. The extra restrictions are void. Option A is incorrect; the GPL's terms are paramount for the distribution of that specific work. Option C is misleading; clicking doesn't grant the company the right to impose extra restrictions. Option D is generally false; the GPL is valid in most jurisdictions.

Q17. You are comparing the MIT License and the GNU GPL. A developer states: 'The MIT license is better because it is shorter and simpler, and it allows us to keep our improvements proprietary, so it is more free for the developer.' Analyze this statement.

A.This statement is entirely correct; simplicity and proprietary use are the core of 'free' software.

📖 Explanation: The statement is correct in identifying that MIT allows proprietary improvements (making it 'free' for the developer). However, it is incorrect to say it is universally 'better' or 'more free'. The GPL is considered 'more free' for the end-user because it guarantees the source code of improvements will be available. Option A ignores the end-user rights. Option C is factually wrong. Option D is wrong; the MIT license is a canonical open-source license.

Q18. What is the significance of the 'System Library' exception in the GPL?

A.It allows the kernel to be loaded with proprietary code.
B.It allows you to distribute proprietary software that uses standard libraries like `libc` without being forced to open-source the proprietary software. ✅
C.It allows you to bypass all GPL restrictions if your code is compiled with `gcc`.
D.It only applies to Microsoft Windows system libraries.
💡 Difficulty: hard | ✅ Correct: B

📖 Explanation: The GPL's 'system library' exception (often cited in GPLv2 and more explicitly in v3) clarifies that linking to 'system libraries' (like the C standard library or other system components that are part of the OS) does not make your program a derivative work. This is why you can run proprietary software on Linux (using glibc) without any licensing concerns for your application. Option A is incorrect, that is a separate debate (proprietary modules). Option C is false. Option D is incorrect; it applies to any system, not just Windows.

Q19. A developer creates a program that is licensed under the GPL. A commercial vendor wants to distribute this program on a CD-ROM along with their own proprietary software. The CD-ROM boots into a menu that lets you choose the program. What must the vendor do?

A.They must make the source code of their proprietary software available.
B.They can only distribute the GPL software if they remove the GPL notice.
C.They must ensure the GPL software is clearly identified as separate, and they must provide the source code for the GPL software, but not for their proprietary software. ✅
D.They cannot distribute them on the same CD because it constitutes a combined work.
💡 Difficulty: medium | ✅ Correct: C

📖 Explanation: This is 'mere aggregation'. If the GPL program and the proprietary program are separate applications on the same medium, they are considered independent works. The vendor must comply with the GPL for the GPL part (provide source) but has no obligation for their own proprietary part. Option A is incorrect; the GPL doesn't extend to the proprietary software. Option B is a violation of the GPL's copyright notice requirement. Option D is false; aggregation is allowed.

Q20. Which scenario involving a GPL-licensed library and a proprietary application is MOST likely to be considered a copyright violation by the FSF?

D.The proprietary application uses a websocket to communicate with a GPL-licensed server.
💡 Difficulty: hard | ✅ Correct: B

📖 Explanation: Static linking to a GPL library creates a single combined binary that is considered a derivative work of the library. Therefore, the entire combined work must be distributed under the GPL. If the application is proprietary, this is a violation. Option A is standard process separation and is usually safe. Option C is allowed under LGPL. Option D is communication over a network boundary, which is generally not considered a derivative work (the 'network' distinction).

Q22. An employee uses a GPL-licensed text editor at work to write a new proprietary software product. The company later distributes the proprietary software. Does the GPL apply to the proprietary software?

📖 Explanation: This is a crucial distinction. The GPL covers the software itself, not the data or output it produces. The text files created by the text editor are not derivative works of the editor. They are just data. The GPL's 'viral' nature applies to modifications to the GPL code or linking to it, not to using it to write code. Option A is a common misconception (the 'GPL virus' myth). Q23. A user downloads a GPL-licensed software package from a website. They pay a $10 download fee to the website owner. The website owner claims this fee is for 'bandwidth and hosting'. The website owner does not provide the source code, only the binary. Is this legal?

📖 Explanation: The GPL grants you the right to charge a fee for distribution of binaries (as in Option A of a previous question), but it absolutely requires that the source code be made available. Q24. A company has a derivative work of a GPL-licensed program. They provide the source code on a CD-ROM with the product. The source code is obfuscated and minified to make it unreadable. Is this compliant with the GPL?

A.Yes, as long as they provide the exact text that compiles.
B.No, the GPL requires source code to be in a 'preferred form for making modifications', which means it must be readable and editable by humans. ✅
C.Yes, because obfuscation is a standard practice in commercial software.
D.No, because obfuscation is illegal under copyright law.
💡 Difficulty: hard | ✅ Correct: B

📖 Explanation: The GPL explicitly defines 'source code' as the 'preferred form of the work for making modifications to it'. A minified or obfuscated code, while technically textual, is not the 'preferred form' (the developer uses the clean, commented code). Providing only obfuscated code violates the GPL. Option A is a trap; while it might compile, it fails the 'preferred form' requirement. Option C is irrelevant and false for GPL software. Option D is incorrect; obfuscation isn't illegal, but it's forbidden for satisfying the GPL source requirement.

Q25. Consider two licenses: BSD 3-Clause and GPLv3. A developer combines code from both into a single program. The BSD code is licensed under the BSD license, and the GPL code is under GPLv3. What is the resulting license of the combined work?

💡 Difficulty: hard | ✅ Correct: B

📖 Explanation: The GPL's copyleft clause states that when you distribute a derivative work of GPL'd code, the entire work must be licensed under the GPL. Since the combined program is a derivative work of the GPL code, it must be GPLv3. The BSD code's permissive nature allows it to be included in a GPL project. Option A is wrong; the stricter license (GPL) takes precedence for the combined work. Option C is false; these licenses are compatible (you can combine them, resulting in GPL). Option D is false.

Q26. A developer contributes code to a project under the GPLv2 'or any later version' license. Three years later, the project maintainers decide to release the next version under GPLv3 only. Can they legally do this with the contributor's code?

💡 Difficulty: hard | ✅ Correct: B

📖 Explanation: The 'or any later version' clause is a forward-compatibility mechanism. It grants permission to the distributor to distribute the work under the terms of GPLv3 or any later version. Therefore, the maintainers can relicense the combined work to GPLv3. Option A is incorrect because the contributor explicitly granted permission for 'any later version'. Option C is false; the FSF encourages this. Option D is absurd.

Q27. You are the compliance officer for a company using a proprietary software product that has a dependency on a GPL-licensed library. The vendor provides the binary, but not the source code. The GPL does not have a 'system library' exception for arbitrary libraries; the exception is narrowly defined. Dynamic linking to a GPL library typically creates a derivative work, requiring the full source. The LGPL was specifically designed to allow dynamic linking without the viral effect. Option A is slightly too broad, but B is more precise as it distinguishes between GPL and LGPL. Option C is false. Option D is irrelevant; the GPL doesn't require an extra fee, the source must be available.

Q29. A developer wants to release their software under a license that allows others to use, modify, and redistribute the software, but requires that any modifications made to the original source code must be released under the same license when distributed. However, they want to allow proprietary software to link to it as a library. Which license should they choose?

A.GNU General Public License (GPL)
B.MIT License
C.GNU Lesser General Public License (LGPL) ✅
D.Apache License 2.0
💡 Difficulty: easy | ✅ Correct: C

📖 Explanation: The description perfectly matches the LGPL (Lesser General Public License). It provides a weak copyleft for the library itself: modifications to the library must be shared, but linking to it is allowed without making the entire proprietary application open-source. Option A (GPL) is too restrictive for linking. Option B (MIT) and D (Apache) are permissive and do not require sharing modifications at all.

Q30. Company X distributes a GPL-licensed software with a 'written offer' for the source code, valid for three years. After three years, they stop distributing the binary. A user who received the binary in year 1 requests the source code in year 5. Must Company X provide it?

A.Yes, because the GPL is perpetual.
B.No, because the three-year offer has expired and they are no longer distributing the binary. ✅
C.Yes, but they must charge a fee for it.
D.No, because the user waited too long.
💡 Difficulty: hard | ✅ Correct: B

📖 Explanation: The GPL (v2) states the written offer is valid for at least three years. Once that period expires, and if the distributor is no longer distributing the binary, they are under no further obligation to provide the source code to that specific request. The obligations are tied to the period of distribution. Option A is incorrect; the license grants rights perpetually, but the specific distribution trigger is time-limited for the 'written offer' method. If they provided it on a CD initially, that would be permanent. Option C is irrelevant.

Q31. When comparing the MIT license and the GPLv3, a developer argues: 'The MIT license is better because it has no restrictions, so it is a more pure form of open source.' Which statement accurately critiques this argument?

A.The MIT license is not open source because it lacks a patent grant.
B.The GPLv3 is more pure because it protects the user's freedoms from proprietary 'tivoization' (hardware restrictions). ✅
C.The MIT license is actually more restrictive than the GPL.
D.The developer is correct; fewer restrictions always equate to better open-source licensing.
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: The argument is flawed because it equates 'fewer restrictions' with 'better'. The GPL is a 'protective' or 'copyleft' license; it restricts the distributor to ensure the user's freedoms are preserved. GPLv3, in particular, addresses 'tivoization' by preventing hardware manufacturers from using GPL software in devices that prevent users from running modified versions. Option A is false; MIT has no patent grant, but the FSF considers it a 'weak' but valid open-source license. Option C is false; MIT is clearly less restrictive. Option D ignores the philosophical goals of the GPL.

Q32. A user compiles a GPL-licensed program from source and distributes the binary to a friend. The user does not include any source code or a written offer. The user claims this is 'personal use' and doesn't require source. Is this correct?

A.Yes, personal distribution to a friend is exempt from the GPL.
B.No, any distribution of a binary without corresponding source is a violation of the GPL, regardless of whether it is to a friend or a corporation. ✅
C.Yes, because the user compiled it themselves, they are the owner.
D.No, but only if the friend pays money for the binary.
💡 Difficulty: easy | ✅ Correct: B

📖 Explanation: The GPL's trigger is distribution, not the identity of the recipient. If you give a compiled binary to anyone (a friend, a colleague, a customer), you have distributed it. If you distribute the binary, you must also offer the source code. The 'personal use' exception only applies if the user never gives the binary to anyone else. Option A is a common and dangerous misconception. Option C is irrelevant. Option D is wrong; the payment doesn't affect the licensing obligation.

Q33. A proprietary software company wants to include a GPL-licensed parsing library in their application. They are concerned about 'licensing contamination'. Their lawyer suggests a strategy: 'Separate the library into a separate process and use inter-process communication (IPC) to communicate with it.' Is this a viable strategy to avoid the GPL's copyleft effect?

A.Yes, this is a valid 'mere aggregation' strategy, as the two programs are separate processes. ✅
B.No, IPC creates a stronger link than static linking.
C.Yes, but only if they rewrite the library from scratch in a different language.
D.No, because any communication with GPL code makes the whole program a derivative work.
💡 Difficulty: hard | ✅ Correct: A

📖 Explanation: Using separate processes with IPC is a well-established method for creating a barrier between GPL code and proprietary code. The GPL's scope generally covers the boundaries of a single program image. If they communicate via pipes, sockets, or files, they are considered distinct programs. This is the basis for many open-source business models (e.g., running a GPL server with a proprietary client). Option B is false; IPC is less linking than static linking. Option C is unnecessary. Option D is false; the GPL does not extend across process boundaries in this way.

Q34. Consider a scenario where a vendor distributes a hardware device containing Linux. The vendor provides the source code on a website, but the URL is broken and has been broken for 6 months. Several users have complained. Is the vendor compliant?

A.Yes, they offered it, and a broken URL is a technical issue, not a licensing one.
B.No, the GPL requires that the source code be effectively available. A non-functional URL for six months is a violation. ✅
C.Yes, but only if they respond to individual emails immediately.
D.No, because they must provide the source code on a CD-ROM for free.
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: Offering source code via a website means the site must be functional and accessible. If the URL is broken for a prolonged period, the offer is effectively invalid. The vendor is failing to fulfill their obligation to provide the source code. Option A is a common excuse but is not acceptable. Option C is a mitigation, but the primary obligation remains the online availability. Option D is false; they don't have to provide it for free, and they can choose the medium.

Q35. A developer creates a derivative work of a GPL-licensed program. They decide to not include the original copyright notices in the modified source files. Which of the following is TRUE?

A.This is allowed because the GPL only requires copyright notices in the binary.
B.This is a violation of the GPL, as it requires that copyright notices be preserved in all modified versions. ✅
C.This is allowed as long as they add their own copyright notice instead.
D.This is only a violation if the software is distributed for commercial purposes.
💡 Difficulty: easy | ✅ Correct: B

📖 Explanation: The GPL is a copyright license. A key requirement is to preserve the original copyright notices and disclaimers in all copies, including modified versions. Failing to do so violates the terms. It also violates the moral rights in some jurisdictions. Option A is false; notices must be in the source. Option C is false; you must preserve the original notices; you can add yours, but you cannot remove theirs. Option D is false; the requirement applies to all distributions.

Q36. What is the key difference between the GPLv2 and GPLv3 licenses regarding patents?

A.GPLv3 includes an explicit patent grant and protects users against patent litigation, whereas GPLv2 does not contain an explicit patent grant clause. ✅
B.GPLv2 includes a patent grant, but GPLv3 does not.
C.Both licenses have identical patent clauses.
D.GPLv3 allows patent trolling, while GPLv2 prohibits it.
💡 Difficulty: hard | ✅ Correct: A

📖 Explanation: One of the major updates in GPLv3 was the inclusion of an explicit patent grant to protect users and developers from patent infringement claims related to the software. It also includes a 'patent retaliation' clause. GPLv2 relies on implied patent grants and copyright law, which the FSF felt was insufficient. Option B is the reverse of the truth. Option C is false. Option D is the opposite of reality.

Q37. A developer wants to distribute a GPL-licensed software as a SaaS (Software as a Service). They do not distribute any binaries. Which of the following is true?

A.They must provide the source code to the public because SaaS counts as distribution.
B.They are not required to provide the source code because the AGPL (Affero GPL) is the license that covers network use, not the standard GPL. ✅
C.They must provide the source code only if they charge a fee.
D.They must provide the source code to the users, but not to the general public.
💡 Difficulty: hard | ✅ Correct: B

📖 Explanation: The standard GPL (v2 and v3) is triggered by 'distribution' or 'conveyance'. If you run the software on a server and only provide access via the network, you are not 'distributing' the software. This is the 'ASP loophole' (Application Service Provider). The AGPL (Affero GPL) was created specifically to close this loophole. Option A is false. Option C is false; charges do not change the requirement. Option D is false; no source is required at all if there is no distribution.

Q38. A developer writes a program that is a plugin for a GPL-licensed application. The plugin is loaded by the application via `dlopen()` and uses the application's API, which is documented. The plugin is proprietary. Is this a violation of the GPL?

A.Yes, `dlopen()` creates a derivative work.
B.No, if the plugin is a separate work and the API is a defined boundary (often considered a 'clear interface'), it may not be a derivative work, but this is a legal gray area. ✅
C.Yes, only if the plugin is statically linked.
D.No, because any plugin is always an independent work.
💡 Difficulty: hard | ✅ Correct: B

📖 Explanation: This is a complex area of copyright law. The GPL's scope depends on whether the plugin is a 'derivative work' of the application. `dlopen()` is a dynamic linking mechanism. If the API is generic and the plugin doesn't incorporate any GPL source code, it's often considered separate. However, if the API is specific to the GPL application and the plugin cannot work without it, courts might see it as a derivative. This is the classic 'GPL vs plugins' debate. Option A is a strong, but legally disputed stance. Option D is too absolute. The answer acknowledges the nuance (gray area).

Q39. The Linux kernel modules are a special case. While the kernel is GPL, modules are often considered separate works if they use only the 'public kernel API'. A company releases a binary-only module that uses only this public API. The module is a separate, independent software package. How is this usually treated?

A.This is treated as a clear violation.
B.This is often tolerated, but the module is still technically a derivative work according to the FSF. The legality is debated, but major vendors (like Nvidia) have done this for years. ✅
C.This is perfectly legal and officially supported by the Linux kernel maintainers.
D.This is only legal if the module is statically compiled into the kernel.
💡 Difficulty: hard | ✅ Correct: B

📖 Explanation: This is the heart of the proprietary module debate. The Linux kernel maintainers (and FSF) believe that even using the public API creates a derivative work and that binary modules are a violation. However, many hardware vendors (like Nvidia) distribute binary-only modules, arguing they are separate works. The legal situation is unresolved and often avoided. Option A is the FSF's view but not a universally accepted legal reality. Option C is false; the kernel maintainers (like Greg KH) are explicitly hostile to binary modules and will not support them. Option D is false; static linking would make it undeniably a derivative.
