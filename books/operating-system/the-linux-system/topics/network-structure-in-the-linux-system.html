What is Network Structure in The Linux System?

Definition:
Network Structure in The Linux System implements TCP/IP stack in kernel with socket API, netfilter hooks, and modular protocol families, supporting routing, firewalling, and virtualization through sk_buff packet buffers.

Example:
An HTTP request traverses socket → TCP → IP → netfilter PREROUTING → routing decision → eth0 driver, with skb−>data skb->data skb−>data pointing to payload throughout the pipeline.

Reason:
In-kernel networking achieves high throughput and low latency by avoiding user/kernel copies for packet processing, while modularity allows adding protocols (QUIC, VXLAN) without core changes.

📝 All Network Structure in The Linux System MCQs

Q1. What is the primary unit that the kernel uses when performing I/O on a block device?

A.A character interface
B.A unit of I/O ✅
C.A network socket
D.A process scheduler
💡 Difficulty: easy | ✅ Correct: B

📖 Explanation: The kernel works with blocks, which are fixed‑size chunks of data transferred to or from a device. A block represents the unit of I/O, meaning every read or write operation is expressed in terms of whole blocks. The other choices describe unrelated concepts: a character interface deals with streams, a network socket handles communication, and a process scheduler manages CPU time. Understanding blocks is essential for managing disk access efficiently.

Q2. Why is the C‑SCAN algorithm described as a unidirectional‑elevator algorithm?

A.Because it moves the disk head in one direction then jumps back to the start ✅
B.Because it processes requests in random order
C.Because it uses multiple queues for different priorities
D.Because it only reads data sequentially
💡 Difficulty: easy | ✅ Correct: A

📖 Explanation: C‑SCAN scans the request list from the lowest to the highest sector number, servicing requests as it moves in a single direction. When it reaches the highest sector, the head returns quickly to the lowest sector without servicing any requests, then resumes the same direction. This one‑way movement gives the algorithm its “unidirectional‑elevator” name. The other options mischaracterize its behavior.

Q3. A system with a heavy read workload needs higher throughput. Which I/O scheduler is most likely to improve performance?

A.CFQ ✅
B.C‑SCAN
C.FIFO
D.No scheduler (disable scheduling)
💡 Difficulty: easy | ✅ Correct: A

📖 Explanation: The Completely Fair Queueing (CFQ) scheduler gives each process a time slice of I/O, which often results in better throughput for read‑intensive workloads because it can keep the disk busy while fairly sharing access. C‑SCAN still follows a strict head‑movement pattern that may not exploit read locality as well. FIFO simply processes requests in arrival order, and disabling scheduling removes any intelligent ordering, both of which can degrade performance.

Q4. When a new I/O request arrives while the driver is processing a current request, when can the new request be merged with existing ones?

A.Immediately upon arrival
B.After the current request completes ✅
C.Never, merging is disabled
D.Only if the request targets the same sector
💡 Difficulty: easy | ✅ Correct: B

📖 Explanation: Merging is performed only after the active request finishes, because the driver cannot safely combine an in‑flight operation with pending ones. Once the current I/O completes, the scheduler examines the request list and merges adjacent or overlapping requests to reduce disk seeks. Immediate merging could corrupt data, and merging is not limited to identical sectors; it works on contiguous ranges.

Q5. What does the acronym CFQ stand for in Linux I/O scheduling?

A.Completely Fair Queueing ✅
B.Circular Fair Queue
C.Constant Frequency Queue
D.Core File Queue
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: CFQ is short for Completely Fair Queueing, a scheduler introduced in Linux 2.6 that aims to allocate I/O bandwidth fairly among processes. The other expansions are fabricated and do not correspond to any Linux component. Knowing the correct expansion helps students recognize the scheduler’s design goal of fairness, which distinguishes it from older elevator‑style algorithms.

Q6. How does CFQ differ fundamentally from traditional elevator‑based I/O algorithms?

A.It assigns time slices to processes rather than ordering by sector ✅
B.It sorts requests by starting sector only
C.It ignores request order completely
D.It selects requests randomly
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: CFQ gives each process a time slice of I/O, allowing multiple processes to share the device in a fair manner, whereas elevator algorithms like C‑SCAN simply order requests by their sector numbers. This per‑process fairness is the key distinction. The other choices misrepresent CFQ’s behavior; it still respects sector ordering within a slice but does not rely solely on it.

Q7. What is the main benefit of request merging in block‑device I/O?

A.It reduces the number of disk seeks ✅
B.It increases overall latency
C.It duplicates data on the disk
D.It disables the buffer cache
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: Merging combines adjacent or overlapping requests into a single larger operation, which means the disk head moves fewer times, reducing seek time and improving performance. The other options describe negative effects that merging does not cause; it does not increase latency, duplicate data, or interfere with caching. By decreasing seeks, merging directly contributes to faster I/O.

Q8. Why are request lists typically kept sorted by the starting‑sector number?

A.To facilitate sequential access and minimize seek time ✅
B.To randomize I/O patterns for security
C.To encrypt data on the fly
D.To confuse device drivers
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: Sorting by starting sector allows the scheduler to service requests in an order that moves the disk head smoothly across the platter, which minimizes the distance it must travel and thus reduces latency. Randomizing or encrypting the order would increase seek time, and confusing drivers is not a design goal. The sorted list is a core optimization for mechanical disks.

Q9. A server shows long latency spikes when many small write requests arrive simultaneously. Which scheduler change is most likely to smooth the latency?

A.Switch to CFQ ✅
B.Use C‑SCAN
C.Disable the scheduler entirely
D.Increase the block size of each request
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: CFQ assigns time slices to processes, which helps smooth out bursts of small writes by preventing any single process from monopolizing the disk. C‑SCAN still processes writes in strict head order, which can still experience spikes. Disabling scheduling removes any intelligent ordering, and simply increasing block size does not address the bursty nature of the workload.

Q10. In a database that performs sequential reads followed by occasional random writes, which scheduler best balances read throughput with write handling?

A.CFQ
B.C‑SCAN
C.Deadline ✅
D.Noop
💡 Difficulty: medium | ✅ Correct: C

📖 Explanation: The deadline scheduler maintains separate read and write queues and enforces timing constraints, allowing it to prioritize sequential reads while still servicing random writes promptly. CFQ provides fairness but may not give reads the priority they need for high throughput, and C‑SCAN treats all requests equally, potentially delaying writes. Noop does almost nothing, offering no advantage for mixed workloads.

Q11. If a block‑device driver reports that a request has completed but the request list still contains the entry, what is the most likely cause?

A.The driver failed to remove the entry from the list ✅
B.The request is still pending execution
C.The request list is immutable by design
D.The request was merged and will be removed later
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: When a driver signals completion, it is expected to also delete the corresponding entry from the request list. If the entry remains, the most common explanation is a programming oversight where the removal step was omitted. The request is not pending—completion indicates it finished. Request lists are mutable, and merging would have already removed the entry during the merge operation.

Q12. A system equipped with SSDs shows no performance gain when switching from FIFO to CFQ. Why is this expected?

A.SSD latency is already negligible, so scheduling adds little benefit ✅
B.CFQ is only designed for HDDs with high seek times
C.SSDs require the C‑SCAN algorithm for optimal performance
D.CFQ disables the SSD cache, reducing speed
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: SSDs have almost no mechanical seek latency, so the primary advantage of CFQ—fair distribution of seek time—is irrelevant. Consequently, CFQ offers little or no improvement over a simple FIFO queue. While CFQ was introduced to improve HDD performance, it does not harm SSDs, but the expected benefit simply does not materialize.

Q13. How does the concept of a “time slice” in CFQ affect I/O fairness among processes?

A.Each process receives an equal amount of service time ✅
B.Faster processes receive larger slices
C.Slices are assigned based on process priority
D.Slices are chosen randomly for each process
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: CFQ divides the disk’s bandwidth into equal time slices that are allocated to each active process in turn, ensuring that no single process can dominate I/O resources. This per‑process allocation creates fairness. Faster processes do not get larger slices, priority does not change the basic slice size (though priority can affect weighting), and the allocation is deterministic, not random.

Q14. What is the impact of maintaining separate request lists for each block‑device driver?

A.It isolates the workload per device, preventing interference ✅
B.It merges all device requests into a single global list
C.It causes deadlock between drivers
D.It reduces overall memory usage dramatically
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: Having an individual request list for each driver keeps the I/O streams of different devices independent, so a busy disk does not affect the scheduling of another device. This isolation improves performance and simplifies management. Merging all requests would create contention, deadlocks are unrelated, and the memory impact is modest rather than dramatically reduced.

Q15. A high‑performance web server uses multiple disks with different rotational speeds and currently runs C‑SCAN on all disks. Which scheduling strategy could maximize overall throughput while preventing slower disks from becoming bottlenecks?

A.Assign CFQ per disk and weight each by its speed ✅
B.Use a single global C‑SCAN queue for all disks
C.Disable scheduling on the fast disks
D.Randomize requests across all disks
💡 Difficulty: hard | ✅ Correct: A

📖 Explanation: Applying CFQ individually to each disk allows the scheduler to give faster disks more frequent service slices, matching their higher I/O capability, while still providing fairness. A single global C‑SCAN queue would force the slowest disk to dictate the overall head‑movement cadence, creating a bottleneck. Disabling scheduling on fast disks removes any intelligent ordering, and randomization would increase seek times.

Q16. During heavy load, the system’s I/O latency spikes every 30 seconds, correlating with the request manager’s merge attempts. Which modification could reduce these latency spikes?

A.Implement asynchronous merging of requests
B.Increase the merge window size dramatically
C.Disable request merging entirely
D.Prioritize read requests over writes ✅
💡 Difficulty: hard | ✅ Correct: D

📖 Explanation: Moving the merge operation to an asynchronous thread allows the main I/O path to continue processing without waiting for the potentially costly merge computation, smoothing latency spikes. Enlarging the merge window can actually increase merge time, disabling merging removes a performance benefit, and simply prioritizing reads does not address the merge‑related delay.

Q17. A kernel developer wants to test the effect of request ordering on SSD wear. Which algorithm should they replace CFQ with to produce the most sequential write pattern?

A.C‑SCAN
B.Deadline
C.Noop ✅
D.Anticipatory
💡 Difficulty: hard | ✅ Correct: C

📖 Explanation: The noop scheduler performs virtually no reordering; it passes requests to the device in the order they arrive, preserving sequentiality. This behavior yields the most straightforward write pattern, useful for evaluating wear. C‑SCAN still imposes a head‑movement order, deadline adds timing constraints, and anticipatory attempts to predict future reads, none of which guarantee a purely sequential write stream.

Q18. In a virtualization environment, guest VMs issue interleaved I/O requests. Which scheduler helps isolate each VM’s I/O while still allowing high throughput?

A.CFQ with per‑process queues ✅
B.C‑SCAN
C.Deadline
D.Proportional‑share scheduler
💡 Difficulty: hard | ✅ Correct: A

📖 Explanation: CFQ maintains separate queues for each process (or VM), providing isolation that prevents one VM’s heavy I/O from starving others, while still delivering high throughput through its time‑slice mechanism. C‑SCAN treats all requests as a single stream, losing isolation. Deadline focuses on meeting deadlines but does not inherently separate VMs, and a proportional‑share scheduler is not a standard Linux I/O scheduler.

Q19. A request manager merges adjacent sectors. If two requests for sectors 100‑199 and 200‑299 arrive, will they be merged?

A.Yes, because they are contiguous ✅
B.No, because they are separate requests
C.Yes, but only if they originate from the same process
D.No, because merging requires overlapping ranges
💡 Difficulty: hard | ✅ Correct: A

📖 Explanation: Adjacency is sufficient for merging; sectors 100‑199 and 200‑299 are directly contiguous, so the manager can combine them into a single request covering 100‑299, reducing the number of disk operations. The fact that they are separate requests does not prevent merging, and the process identity is irrelevant for pure sector adjacency. Overlap is not required; contiguous ranges are enough.

Q20. An embedded device with limited RAM cannot maintain large request lists. Which scheduler is most appropriate to minimize memory overhead?

A.Noop ✅
B.CFQ
C.Deadline
D.Anticipatory
💡 Difficulty: hard | ✅ Correct: A

📖 Explanation: The noop scheduler performs virtually no scheduling work and therefore keeps the request list very small, which is ideal for memory‑constrained environments. CFQ and deadline maintain more complex data structures to enforce fairness and timing, consuming additional RAM, while anticipatory adds extra bookkeeping for read‑ahead, also increasing memory usage.

Q21. A developer observes that after enabling CFQ, a low‑priority background backup job runs slower, while interactive tasks improve. Which property of CFQ explains this behavior?

A.CFQ gives higher priority to interactive processes ✅
B.CFQ delays all background jobs indiscriminately
C.CFQ treats all processes equally regardless of priority
D.CFQ disables caching for background jobs
💡 Difficulty: hard | ✅ Correct: A

📖 Explanation: CFQ assigns larger or more frequent time slices to processes that are deemed interactive, based on heuristics such as recent I/O activity. This design improves responsiveness for user‑focused tasks at the expense of background workloads like backups, which receive fewer slices and therefore run slower. The other options misrepresent CFQ’s behavior; it does not uniformly delay background jobs nor treat all processes identically.
