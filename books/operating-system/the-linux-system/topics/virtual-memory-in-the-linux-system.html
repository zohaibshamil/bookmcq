What is Virtual memory in The Linux System?

Definition:
Virtual memory in The Linux System provides each process with an isolated linear address space mapped to physical RAM via page tables, enabling demand paging, swapping, and memory protection through MMU translation.

Example:
Accessing unmapped virtual address triggers a page fault; the kernel loads the required page from swap or file backing store into physical RAM and updates entries.

Reason:
Virtual memory abstracts physical limitations, allows processes larger than RAM, enforces isolation for security, and enables efficient sharing of libraries and copy-on-write semantics.

Q1. A program calls clone() with only the CLONE_VM flag. Which resource is shared between the parent and child?

A.The memory address space ✅
B.The file‑system information
C.The set of open files
D.No resources are shared
💡 Difficulty: easy | ✅ Correct: A

📖 Explanation: The CLONE_VM flag tells the kernel to use the same virtual‑memory mappings for both tasks, so they read and write to the same pages. Consequently, changes made by one are visible to the other. File‑system info, open‑file tables, and signal handlers are not affected because those require their own flags. This sharing reduces the overhead of copying page tables, which is why the memory space is the only resource shared in this scenario.

Q2. Why does storing a process’s virtual‑memory context in a separate substructure allow Linux to treat threads and processes similarly?

A.Because the CPU registers are duplicated for each thread
B.Because each thread gets its own page table
C.Because the memory context can be shared or isolated independently of other resources ✅
D.Because Linux copies the entire process image for every thread
💡 Difficulty: medium | ✅ Correct: C

📖 Explanation: Linux keeps the virtual‑memory descriptor (e.g., page tables) in its own data structure separate from other parts like file descriptors or signal tables. When a thread is created, the kernel can point the new task to the same memory descriptor, sharing it, or allocate a new one for isolation. This modular design lets the same clone() system call create either a fully independent process (no sharing) or a lightweight thread (shared memory) simply by choosing which substructures to share.

Q3. Which clone() flag makes the set of open files shared between the parent and child?

D.CLONE_VM
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: The flag that controls sharing of the file‑descriptor table is CLONE_FILES. When this flag is present, both tasks refer to the same table, so a file opened by one is immediately visible to the other. CLONE_FS shares the current working directory, CLONE_SIGHAND shares signal handlers, and CLONE_VM shares the memory space. Knowing the exact purpose of each flag is essential for correctly configuring process‑level resource sharing.

Using both flags would cause memory to be shared, while using no flags would duplicate both memory and file tables, which is not the desired outcome.

📖 Explanation: To share the virtual memory area while keeping file descriptor tables separate, only the CLONE_VM flag is required. CLONE_SIGHAND shares signal handlers, and CLONE_FS shares file‑system information, neither of which affect descriptor independence. Therefore the correct choice is CLONE_VM alone.

Q39. A parent uses clone with CLONE_VM and CLONE_SIGHAND to run a function that increments a global counter. After the child exits, what is the value of the counter in the parent?

A.It remains unchanged
B.It reverts to its original value
C.It retains the increment made by the child ✅
D.It becomes undefined
💡 Difficulty: hard | ✅ Correct: C

📖 Explanation: Because CLONE_VM shares the same address space, any modification to a global variable performed by the child directly affects the parent's memory. CLONE_SIGHAND sharing does not alter this behavior. The child's exit does not roll back memory changes, so the increment persists. The variable does not revert or become undefined; it simply reflects the child's update.

Q40. A developer wants a lightweight task that shares everything except the file descriptor table. Which flag should be omitted from the clone call?

A.CLONE_VM
B.CLONE_FS
C.CLONE_SIGHAND ✅
D.CLONE_FILES
💡 Difficulty: easy | ✅ Correct: C

📖 Explanation: To share all resources except the file descriptor table, the clone call must include CLONE_VM, CLONE_FS, and CLONE_SIGHAND, but must leave out CLONE_FILES. Omitting CLONE_FILES ensures each task has its own descriptor table while still sharing memory, filesystem information, and signal handlers. Including CLONE_FILES would cause the descriptors to be shared, which the developer wants to avoid. Hence the correct answer is CLONE_FILES.
