What is Kernel Modules of Linux system?

Kernel modules are dynamically loadable object files that extend kernel functionality without recompilation, allowing features like drivers to be loaded on demand using \( insmod \) or \( modprobe \) commands to keep the base kernel memory footprint minimal.

📝 All Kernel Modules of Linux system MCQs

Q1. A system admin wants to add support for a new USB device without rebuilding the kernel. Which command should they use to load the corresponding module?

A. insmod
B. modprobe ✅
C. rmmod
D. lsmod

💡 Difficulty: easy | ✅ Correct: B

📖 Explanation:

The correct answer is B because modprobe not only inserts the module but also resolves any dependent modules automatically, which is essential for real hardware support. insmod (A) only loads a single file and would fail if dependencies are missing. rmmod (C) removes modules, and lsmod (D) only lists currently loaded modules, so they cannot add support. In practice, using modprobe streamlines driver deployment on a running system.

Q2. What is the main benefit of loadable kernel modules compared to compiling drivers directly into the kernel?

A. Reduces memory usage
B. Allows runtime loading and unloading ✅
C. Improves network speed
D. Eliminates need for root privileges

💡 Difficulty: easy | ✅ Correct: B

📖 Explanation:

Option B is correct because modules can be inserted or removed while the kernel is running, letting administrators add or update functionality without rebooting. Reducing memory usage (A) is a side effect, not the primary advantage. Network speed (C) is unrelated, and root privileges (D) are still required to load modules, so those options are incorrect. This flexibility is why many drivers are distributed as modules.

Q3. Under which license must a kernel module be released to be accepted into the mainline Linux kernel?

A. MIT ✅
B. GPL
C. Apache
D. BSD

💡 Difficulty: easy | ✅ Correct: A

📖 Explanation:

The Linux kernel only accepts modules that are released under the GPL (or compatible) license, making B the correct choice. The GPL ensures that source code remains available and that derivative works share the same freedoms. MIT (A), Apache (C), and BSD (D) are permissive licenses but are not sufficient for inclusion in the mainline kernel, so they would be rejected.

Q4. A developer compiled a module named netfilter.ko but receives an error about missing symbols when loading it with insmod. Which tool should they use to automatically resolve dependencies before loading?

A. depmod ✅
B. modinfo
C. ldd
D. grep

💡 Difficulty: medium | ✅ Correct: A

📖 Explanation:

Option A, depmod, is correct because it scans modules, builds a dependency map, and updates the modules.dep file, allowing the loader to resolve missing symbols. modinfo (B) only displays information about a module, ldd (C) works for user‑space libraries, and grep (D) is a generic text search tool; none of these handle kernel symbol dependencies. Using depmod prevents symbol errors in real deployments.

Q5. During testing, a kernel module crashes the system after being loaded. Which command can be used to unload it safely without rebooting?

A. rmmod
B. modprobe -r ✅
C. unloadmod
D. killmod

💡 Difficulty: medium | ✅ Correct: B

📖 Explanation:

The correct answer is B; modprobe -r removes a module and also unloads any modules that depend on it, ensuring a clean state. rmmod (A) can also remove a module but does not handle dependencies, so it may leave orphaned modules and cause instability. unloadmod (C) and killmod (D) are not real commands in Linux, making them incorrect choices.

Q6. A sysadmin wants to prevent a specific module from being loaded automatically at boot. Which file should they edit to blacklist the module?

A. /etc/modprobe.d/blacklist.conf ✅
B. /boot/grub.cfg
C. /etc/fstab
D. /etc/modules-load.d/modules.conf

💡 Difficulty: medium | ✅ Correct: A

📖 Explanation:

Option A is correct because blacklist.conf in /etc/modprobe.d is read by modprobe and can contain lines like 'blacklist <module>', preventing automatic loading. The GRUB configuration (B) controls bootloader options, not module loading. /etc/fstab (C) mounts filesystems, and /etc/modules-load.d/modules.conf (D) lists modules to load, not to block them. Editing the blacklist file directly stops the unwanted module at boot.

Q7. When building a custom kernel module, the makefile uses the variable KERNELDIR. Which directory should KERNELDIR point to to ensure proper compilation against the running kernel?

A. /usr/src/linux ✅
B. /lib/modules/$(uname -r)/build
C. /etc/kernel
D. /opt/kernel

💡 Difficulty: medium | ✅ Correct: A

📖 Explanation:

The correct path is B, /lib/modules/$(uname -r)/build, because it is a symlink to the headers and build environment that match the currently running kernel version. /usr/src/linux (A) may contain source for a different kernel version, leading to mismatched symbols. /etc/kernel (C) and /opt/kernel (D) are not standard locations for kernel build trees, so they would not provide the needed files.

Q8. Why does the Linux kernel require that external modules be licensed under GPL to be merged into the mainline tree?

A. To protect intellectual property
B. To ensure source availability ✅
C. To improve performance
D. To simplify debugging

💡 Difficulty: medium | ✅ Correct: B

📖 Explanation:

Option B is correct because the GPL license obligates developers to make source code available, aligning with the kernel's open‑source philosophy and allowing anyone to audit or modify the code. Protecting IP (A) is opposite to the GPL’s intent, and performance (C) or debugging simplicity (D) are not reasons for the licensing requirement. This policy maintains transparency and collaboration across the community.

Q9. A module uses a symbol that was exported with EXPORT_SYMBOL_GPL. What will happen if the module is compiled with a non‑GPL license and loaded?

A. It loads but with warnings
B. It fails to load due to symbol not found ✅
C. It loads but disables GPL features
D. It automatically changes its license to GPL

💡 Difficulty: hard | ✅ Correct: B

📖 Explanation:

The correct answer is B; the kernel will reject the module because symbols marked EXPORT_SYMBOL_GPL are only available to GPL‑licensed modules, resulting in an \unknown symbol\ error at load time. Loading with warnings (A) does not happen, and the kernel does not alter a module's license (D). Option C is incorrect because the module simply cannot load, preventing any partial functionality.

Q10. During runtime, a loaded module creates a /proc entry to expose statistics. Which kernel API function should be used to create this entry safely?

A. create_proc_entry
B. proc_create ✅
C. proc_mkdir
D. proc_register

💡 Difficulty: hard | ✅ Correct: B

📖 Explanation:

proc_create (B) is the modern and safe API for creating entries in the /proc filesystem; it handles reference counting and works with the newer procfs infrastructure. create_proc_entry (A) is deprecated and can lead to memory leaks. proc_mkdir (C) only creates directories, not files, and proc_register (D) does not exist in the kernel API. Using proc_create ensures stability in production environments.

Q11. How does using loadable kernel modules improve system security compared to having all drivers built into the kernel?

A. They run in user space
B. They can be signed and verified before loading
C. They reduce attack surface by only loading needed code ✅
D. They prevent any kernel bugs

💡 Difficulty: medium | ✅ Correct: C

📖 Explanation:

Option C is correct because loading only the necessary modules limits the amount of privileged code residing in memory, thereby shrinking the potential attack surface. Running in user space (A) is false; modules execute in kernel mode. While signing (B) adds verification, it does not inherently reduce exposure. Claiming that modules prevent kernel bugs (D) is unrealistic; bugs can still exist in loaded code.

Q12. What is the relationship between the 'modprobe' command and the '/etc/modprobe.d' configuration files?

A. modprobe reads those files to apply options and blacklists ✅
B. modprobe writes to those files
C. Those files are only used by insmod
D. They store compiled module binaries

💡 Difficulty: medium | ✅ Correct: A

📖 Explanation:

The correct answer is A; modprobe parses the files in /etc/modprobe.d to apply module parameters, aliases, and blacklist directives before loading a module. It does not write to these files (B), nor are they used by insmod (C) which ignores configuration files. The directory does not contain compiled binaries (D); it holds plain‑text configuration that influences module loading behavior.

Q13. Explain why a kernel module cannot safely use standard C library functions like printf without special handling.

A. Because the kernel lacks a userspace library ✅
B. Because printf is not thread‑safe
C. Because using libc would cause licensing issues
D. Because kernel code must avoid dynamic memory allocation

💡 Difficulty: hard | ✅ Correct: A

📖 Explanation:

Option A is correct because the kernel runs without the standard C library (libc) and therefore cannot call functions like printf that depend on user‑space facilities. The thread‑safety concern (B) is secondary, and licensing (C) is not the primary technical barrier. While dynamic allocation (D) is allowed in the kernel, it must use kernel‑specific APIs, not libc. Hence, kernel modules must use printk or related kernel logging facilities.
