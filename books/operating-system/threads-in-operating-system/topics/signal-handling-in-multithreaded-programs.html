📝 All Signal handling in multithreaded programs MCQs

Q1. What is a signal in UNIX systems?

🔹 A. A method to create new processes
🔹 B. A notification mechanism for events
🔹 C. A synchronization primitive
🔹 D. A memory allocation technique

💡 Difficulty: easy | ✅ Correct: B

📖 Explanation:

A signal is a notification mechanism used in UNIX systems to inform a process that a particular event has occurred. Signals provide a way for the kernel or other processes to communicate events and interrupt the normal execution flow of a process.

Q2. What are the three stages of signal handling?

🔹 A. Creation, execution, and termination
🔹 B. Generation, delivery, and handling
🔹 C. Initiation, processing, and completion
🔹 D. Detection, response, and cleanup

💡 Difficulty: easy | ✅ Correct: B

📖 Explanation:

Signal handling follows a consistent pattern: generation by an event occurrence, delivery to a process, and handling once delivered. This three-stage process applies to all signals regardless of whether they are synchronous or asynchronous.

Q3. What type of signal is generated by division by zero?

🔹 A. Asynchronous signal
🔹 B. Synchronous signal
🔹 C. Timer signal
🔹 D. External signal

💡 Difficulty: easy | ✅ Correct: B

📖 Explanation:

Division by zero generates a synchronous signal because it's caused by the executing program's operation. Synchronous signals are generated by the running program itself and are delivered to the same process that performed the operation causing the signal.

Q4. What type of signal is generated by a timer expiring?

🔹 A. Synchronous signal
🔹 B. Internal signal
🔹 C. Asynchronous signal
🔹 D. Program-specific signal

💡 Difficulty: easy | ✅ Correct: C

📖 Explanation:

A timer expiring generates an asynchronous signal because it is caused by an event external to the running process. Asynchronous signals originate from outside the process and are typically sent to another process rather than generated by the process itself.

Q5. What is the default signal handler?

🔹 A. A handler created by the programmer
🔹 B. A handler provided by the kernel
🔹 C. A handler that ignores all signals
🔹 D. A handler that terminates the program

💡 Difficulty: easy | ✅ Correct: B

📖 Explanation:

The default signal handler is provided by the kernel and runs when handling a signal. Every signal has a default handler defined by the operating system, which can be overridden by a user-defined signal handler if the programmer chooses to customize signal handling behavior.

Q6. How can a programmer override the default signal handler?

🔹 A. By modifying the kernel
🔹 B. By defining a user-defined signal handler
🔹 C. By disabling the signal
🔹 D. By using the kill() function

💡 Difficulty: easy | ✅ Correct: B

📖 Explanation:

A programmer can override the default signal handler by creating a user-defined signal handler. This custom handler is called to handle the signal instead of the kernel's default handler, allowing the program to respond to signals in a specific way.

Q7. What action is typically taken for a window size change signal?

🔹 A. The signal is ignored
🔹 B. The program terminates
🔹 C. The system crashes
🔹 D. The process is restarted

💡 Difficulty: easy | ✅ Correct: A

📖 Explanation:

Some signals, such as window size change notifications, are simply ignored. Signals can be handled in various ways depending on the signal type and the program's requirements. Not all signals require immediate action or termination of the program.

Q8. Why is signal delivery more complicated in multithreaded programs?

🔹 A. Signals cannot be used in multithreaded programs
🔹 B. There are multiple threads to receive the signal
🔹 C. The kernel cannot generate signals for threads
🔹 D. Threads cannot handle signals

💡 Difficulty: medium | ✅ Correct: B

📖 Explanation:

Signal delivery is more complicated in multithreaded programs because a process may have several threads, and the system must decide which thread should receive the signal. In single-threaded programs, signals are always delivered to the single process, but multithreaded environments offer multiple delivery options.

Q9. What is the behavior of synchronous signals in multithreaded programs?

🔹 A. They are delivered to all threads
🔹 B. They are ignored by all threads
🔹 C. They are delivered to the thread causing the signal
🔹 D. They are delivered to the main thread

💡 Difficulty: medium | ✅ Correct: C

📖 Explanation:

Synchronous signals need to be delivered to the thread causing the signal, not to other threads. Since the signal is generated by a specific thread's operation, delivering it to that thread ensures appropriate handling of the exceptional condition at its source.

Q10. What is the behavior of asynchronous signals that terminate a process (e.g., Ctrl+C)?

🔹 A. They are delivered to the main thread only
🔹 B. They are sent to all threads
🔹 C. They are ignored in multithreaded programs
🔹 D. They are delivered to the first available thread

💡 Difficulty: medium | ✅ Correct: B

📖 Explanation:

Asynchronous signals that terminate a process, such as Ctrl+C, should be sent to all threads. This ensures the entire process terminates properly, as terminating only one thread while others continue executing could lead to inconsistent program state and resource leaks.

Q11. What does the kill() function do in UNIX?

🔹 A. Terminates a process immediately
🔹 B. Delivers a signal to a specified process
🔹 C. Creates a new process
🔹 D. Kills all threads in a process

💡 Difficulty: medium | ✅ Correct: B

📖 Explanation:

The kill() function in UNIX delivers a signal to a specified process. It takes a process ID (pid) and signal number as parameters, allowing one process to send signals to another process. The name is somewhat misleading as it can be used to send any signal, not just termination signals.

Q12. What is the purpose of the pthread_kill() function?

🔹 A. To terminate a thread
🔹 B. To deliver a signal to a specified thread
🔹 C. To create a new thread
🔹 D. To kill the entire process

💡 Difficulty: medium | ✅ Correct: B

📖 Explanation:

The pthread_kill() function delivers a signal to a specified thread. This POSIX Pthreads function takes a thread ID (tid) and signal number as parameters, providing a way to send signals directly to individual threads within a multithreaded process.

Q13. How does Windows emulate UNIX signals?

🔹 A. Through process creation
🔹 B. Using thread synchronization
🔹 C. Using asynchronous procedure calls (APCs)
🔹 D. Through message passing

💡 Difficulty: medium | ✅ Correct: C

📖 Explanation:

Windows emulates UNIX signals using asynchronous procedure calls (APCs). The APC facility allows a user thread to specify a function to be called when the thread receives notification of a particular event, which serves as an equivalent to asynchronous signals in UNIX.

Q14. What determines which threads receive an asynchronous signal in some UNIX versions?

🔹 A. Thread priority
🔹 B. Thread creation time
🔹 C. Which threads are blocking the signal
🔹 D. Process ID

💡 Difficulty: hard | ✅ Correct: C

📖 Explanation:

In some UNIX multithreaded versions, asynchronous signals may be delivered only to threads that are not blocking the signal. A thread can specify which signals it will accept and which it will block, and the signal is typically delivered only to the first thread found that is not blocking it.

Q15. What happens when a signal needs to be handled only once in a multithreaded environment?

🔹 A. It is delivered to all threads
🔹 B. It is delivered to the first thread not blocking it
🔹 C. It is ignored
🔹 D. It is queued for later delivery

💡 Difficulty: hard | ✅ Correct: B

📖 Explanation:

When a signal needs to be handled only once, it is typically delivered only to the first thread found that is not blocking the signal. This prevents duplicate handling of the same signal event while ensuring that at least one thread in the process receives and processes the signal.

Q16. Why is the Windows APC facility more straightforward than UNIX signal handling for multithreaded programs?

🔹 A. APCs are delivered to a particular thread rather than a process
🔹 B. APCs are always synchronous
🔹 C. APCs are faster than signals
🔹 D. APCs can handle more events

💡 Difficulty: hard | ✅ Correct: A

📖 Explanation:

The Windows APC facility is more straightforward than UNIX signal handling because APCs are delivered to a particular thread rather than a process. This eliminates the complex decision-making process required in UNIX to determine which thread should receive a signal when multiple threads exist.

Q17. What is the correct order of signal handling stages?

🔹 A. Delivery, generation, handling
🔹 B. Generation, delivery, handling
🔹 C. Handling, generation, delivery
🔹 D. Generation, handling, delivery

💡 Difficulty: easy | ✅ Correct: B

📖 Explanation:

The correct order is generation (signal is created by event occurrence), delivery (signal is sent to a process), and handling (signal is processed). This sequence applies to all signals in UNIX systems, whether synchronous or asynchronous in nature.

Q18. Which of the following is an example of an asynchronous signal?

🔹 A. Illegal memory access
🔹 B. Division by zero
🔹 C. Ctrl+C keystroke
🔹 D. Null pointer dereference

💡 Difficulty: medium | ✅ Correct: C

📖 Explanation:

Ctrl+C keystroke is an example of an asynchronous signal because it is generated by an event external to the running process. Illegal memory access, division by zero, and null pointer dereference are all examples of synchronous signals generated by the process itself.

Q19. Which of the following is NOT a valid option for signal delivery in multithreaded programs?

🔹 A. Deliver to the thread to which the signal applies
🔹 B. Deliver to every thread in the process
🔹 C. Deliver to a randomly selected thread
🔹 D. Assign a specific thread to receive all signals

💡 Difficulty: medium | ✅ Correct: C

📖 Explanation:

Delivering to a randomly selected thread is not a valid option. The valid options include delivering to the applying thread, delivering to every thread, delivering to certain threads, or assigning a specific thread to receive all signals. The method depends on the signal type.

Q20. What is the role of a user-defined signal handler?

🔹 A. To provide default handling
🔹 B. To override the kernel's default handling
🔹 C. To generate new signals
🔹 D. To block all signals

💡 Difficulty: medium | ✅ Correct: B

📖 Explanation:

A user-defined signal handler overrides the kernel's default handling for a specific signal. By defining custom handlers, programmers can implement specific actions in response to signals, such as cleaning up resources, logging information, or gracefully recovering from exceptional conditions.

Q21. What action is typically taken for illegal memory access signals?

🔹 A. The signal is ignored
🔹 B. The program is terminated
🔹 C. The memory is reallocated
🔹 D. A warning is printed

💡 Difficulty: medium | ✅ Correct: B

📖 Explanation:

Illegal memory access signals typically result in program termination. This is handled either by the default kernel handler or by a user-defined handler. Termination prevents the program from continuing execution in an invalid state that could cause further errors or security vulnerabilities.

Q22. What is the relationship between signals and processes in single-threaded programs?

🔹 A. Signals are delivered to specific threads
🔹 B. Signals are always delivered to the process
🔹 C. Signals are never delivered
🔹 D. Signals are delivered to the kernel

💡 Difficulty: medium | ✅ Correct: B

📖 Explanation:

In single-threaded programs, signals are always delivered to the process. Since the process has only one thread, signal delivery is straightforward and unambiguous. The signal is received by the single thread, and the appropriate handler is invoked.

Q23. What is the significance of the pthread_kill() function in multithreaded programming?

🔹 A. It allows thread-specific signal handling
🔹 B. It terminates all threads in a process
🔹 C. It creates a new thread
🔹 D. It blocks signals for all threads

💡 Difficulty: medium | ✅ Correct: B

📖 Explanation:

The pthread_kill() function is significant because it allows thread-specific signal handling by enabling delivery of signals to individual threads. This gives programmers fine-grained control over which threads receive which signals in multithreaded applications.

Q24. How does a thread specify which signals it will accept?

🔹 A. By using the kill() function
🔹 B. By specifying signal acceptance rules in UNIX versions
🔹 C. By calling pthread_create()
🔹 D. By using the signal() function

💡 Difficulty: medium | ✅ Correct: D

📖 Explanation:

A thread specifies which signals it will accept and which it will block through signal mask manipulation. This is typically done using functions like pthread_sigmask(), allowing each thread to control its signal reception behavior independently.

Q25. What is the primary difference between synchronous and asynchronous signals?

🔹 A. Synchronous signals are faster
🔹 B. Synchronous signals are generated by the process itself
🔹 C. Asynchronous signals terminate the process
🔹 D. Synchronous signals are always ignored

💡 Difficulty: medium | ✅ Correct: B

📖 Explanation:

The primary difference is that synchronous signals are generated by the process itself (e.g., division by zero), while asynchronous signals are generated by external events (e.g., Ctrl+C). This affects where the signal originates and how it should be delivered in multithreaded programs.

Q26. What is the function of the kill() system call?

🔹 A. To deliver a signal to a process
🔹 B. To end a process immediately
🔹 C. To create a new process
🔹 D. To send a message to a thread

💡 Difficulty: easy | ✅ Correct: A

📖 Explanation:

The kill() system call delivers a signal to a specified process. Despite its name, it is not limited to terminating processes but can be used to send any signal to any process for which the caller has appropriate permissions.

Q27. In the context of signal handling, what does the term 'asynchronous' refer to?

🔹 A. The signal is generated by the program itself
🔹 B. The signal originates from an event external to the process
🔹 C. The signal is handled after the program completes
🔹 D. The signal is processed in parallel

💡 Difficulty: easy | ✅ Correct: B

📖 Explanation:

'Asynchronous' refers to signals that originate from events external to the running process. These signals can occur at any time and are not synchronized with the program's execution, requiring special handling to ensure proper delivery and processing.

Q28. What is the main advantage of using APCs in Windows for signal emulation?

🔹 A. APCs are faster than UNIX signals
🔹 B. APCs avoid the complexity of delivering signals to processes
🔹 C. APCs can handle more signal types
🔹 D. APCs provide automatic signal handling

💡 Difficulty: hard | ✅ Correct: B

📖 Explanation:

The main advantage of using APCs for signal emulation in Windows is that they avoid the complexity of delivering signals to processes in multithreaded environments. Since APCs are delivered to specific threads rather than processes, the ambiguity of signal delivery is resolved.

Q29. What happens if a user-defined signal handler is not provided for a signal?

🔹 A. The signal is ignored
🔹 B. The default signal handler is used
🔹 C. The process terminates immediately
🔹 D. An error is generated

💡 Difficulty: medium | ✅ Correct: B

📖 Explanation:

If a user-defined signal handler is not provided, the default signal handler is used. The kernel provides default handlers for all signals, ensuring that every signal can be handled even if the program doesn't define custom handling. The default behavior varies depending on the signal type.

Q30. Which of the following signals is typically generated synchronously?

🔹 A. Ctrl+C keystroke
🔹 B. Timer expiration
🔹 C. Window resize
🔹 D. Null pointer dereference

💡 Difficulty: hard | ✅ Correct: D

📖 Explanation:

Null pointer dereference is typically generated synchronously because it's caused by the program's own operation. Synchronous signals are generated when a program performs an invalid operation, and they are delivered to the thread that performed the operation causing the signal.

Q31. In multithreaded programs, how are synchronous signals delivered?

🔹 A. To the thread causing the signal
🔹 B. To all threads
🔹 C. To the main thread
🔹 D. To the first available thread

💡 Difficulty: medium | ✅ Correct: A

📖 Explanation:

Synchronous signals are delivered to the thread causing the signal. Since the signal is generated by a specific thread's operation, delivering it to that thread ensures the handler can access the appropriate context and state information to handle the exceptional condition.

Q32. What is the purpose of a thread specifying which signals it blocks?

🔹 A. To improve performance
🔹 B. To control signal delivery
🔹 C. To terminate threads
🔹 D. To create new signals

💡 Difficulty: medium | ✅ Correct: B

📖 Explanation:

A thread specifies which signals it blocks to control signal delivery. By blocking certain signals, a thread indicates it should not receive those signals, allowing other threads in the process to handle them instead. This provides a mechanism for managing signal reception in multithreaded programs.

Q33. Why does a signal need to be handled after delivery?

🔹 A. To prevent signal generation
🔹 B. To complete the signal lifecycle
🔹 C. To ensure the event is processed
🔹 D. To create new signals

💡 Difficulty: medium | ✅ Correct: C

📖 Explanation:

A signal needs to be handled after delivery to ensure the event that caused the signal is properly processed. The handling stage completes the signal lifecycle, allowing the program to respond to the event appropriately, whether by ignoring it, terminating, or taking custom action.

Q34. What is the primary challenge with asynchronous signals in multithreaded programs?

🔹 A. Determining which thread should receive the signal
🔹 B. Generating the signal
🔹 C. Handling the signal quickly
🔹 D. Blocking the signal

💡 Difficulty: hard | ✅ Correct: A

📖 Explanation:

The primary challenge with asynchronous signals is determining which thread should receive the signal. Unlike synchronous signals that are clearly associated with the causing thread, asynchronous signals lack such association, requiring explicit policies to decide delivery in multithreaded environments.

Q35. What distinguishes Windows APCs from UNIX signals?

🔹 A. APCs are delivered to threads, signals to processes
🔹 B. APCs are synchronous, signals are asynchronous
🔹 C. APCs cannot handle events
🔹 D. APCs are slower than signals

💡 Difficulty: hard | ✅ Correct: A

📖 Explanation:

Windows APCs are delivered to specific threads rather than processes, unlike UNIX signals which are delivered to processes. This distinction makes APCs more straightforward in multithreaded environments because there is no ambiguity about which thread should receive the notification.

Q36. What happens to asynchronous signals when a thread blocks them?

🔹 A. They are delivered to other non-blocking threads
🔹 B. They are ignored completely
🔹 C. They are queued until the thread unblocks
🔹 D. They cause the process to terminate

💡 Difficulty: hard | ✅ Correct: A

📖 Explanation:

When a thread blocks an asynchronous signal, the signal may be delivered to other threads in the process that are not blocking it. Since signals need to be handled only once, they are typically delivered to the first thread found that is not blocking the signal.

Q37. Which component provides default signal handlers in UNIX systems?

🔹 A. The application program
🔹 B. The kernel
🔹 C. The hardware
🔹 D. The compiler

💡 Difficulty: easy | ✅ Correct: B

📖 Explanation:

The kernel provides default signal handlers for every signal. These default handlers ensure that signals are handled even when the application program does not define custom handlers. The default behavior is appropriate for most signals in typical program execution.

Q38. What is the role of signal masks in multithreaded signal handling?

🔹 A. To identify signal types
🔹 B. To control signal acceptance per thread
🔹 C. To specify handler functions
🔹 D. To terminate signal delivery

💡 Difficulty: hard | ✅ Correct: B

📖 Explanation:

Signal masks in multithreaded environments control signal acceptance on a per-thread basis. Each thread can maintain its own signal mask indicating which signals are blocked, allowing fine-grained control over signal delivery in multithreaded programs.

Q39. How does the complexity of signal delivery differ between single-threaded and multithreaded programs?

🔹 A. Both have the same complexity
🔹 B. Multithreaded programs have more complexity
🔹 C. Single-threaded programs have more complexity
🔹 D. Complexity depends on signal type

💡 Difficulty: medium | ✅ Correct: B

📖 Explanation:

Multithreaded programs have more signal delivery complexity because signals could potentially be delivered to any of the multiple threads. Single-threaded programs are simpler because the single process receives all signals, making the delivery target unambiguous.

Q40. What does the kill() function require as parameters?

🔹 A. Process ID and thread ID
🔹 B. Process ID and signal number
🔹 C. Thread ID and signal number
🔹 D. Signal number and handler function

💡 Difficulty: medium | ✅ Correct: B

📖 Explanation:

The kill() function requires a process ID (pid) and a signal number (signal) as parameters. The process ID identifies which process should receive the signal, and the signal number identifies which signal to deliver to that process.

Q41. What is the equivalent of asynchronous signals in Windows?

🔹 A. Synchronous procedure calls
🔹 B. Asynchronous procedure calls
🔹 C. Event handlers
🔹 D. Thread notifications

💡 Difficulty: hard | ✅ Correct: B

📖 Explanation:

Asynchronous procedure calls (APCs) are the equivalent of asynchronous signals in Windows. The APC facility allows a user thread to specify a function that should be called when the thread receives notification of a particular event, which closely matches the functionality of asynchronous signals in UNIX.
