What is Pthreads in operating system?

Definition:
POSIX Threads (Pthreads) is a standardized C language thread library defined by IEEE POSIX.1c standard, widely used in UNIX and Linux systems. It provides comprehensive API for thread creation, synchronization, and management, supporting both user-level and kernel-level threading depending on implementation, making it the de facto standard for portable multithreaded programming on POSIX-compliant systems.

Working:
Pthreads API includes functions like `pthread_create()` for thread creation, `pthread_mutex_lock()` for synchronization, and `pthread_join()` for thread completion waiting. The library interacts with Linux kernel through clone() system call, creating kernel threads that the scheduler manages. Pthreads supports various synchronization mechanisms including mutexes, condition variables, and read-write locks.

Example:
```c
pthread_t thread;
pthread_create(&thread, NULL, worker_function, NULL);
pthread_join(thread, NULL);
```
This creates a thread executing worker_function and waits for completion. Solution: Thread runs concurrently with creator until join synchronizes their execution, ensuring proper cleanup and result retrieval.

Reason:
Pthreads provides standardized interface ensuring code portability across UNIX variants, offers rich synchronization primitives for complex concurrent algorithms, integrates seamlessly with Linux kernel threading, and benefits from extensive community support and documentation making it ideal for educational and production environments.

Common MisConceptions:
Students think Pthreads is only for Linux, but it works on any POSIX-compliant system including macOS and BSD. Another misconception is that Pthreads always creates kernel threads, when some implementations support user-level threading. Some believe error handling is optional, but checking return values is crucial for robust programs.

Exam Preparation Tips: How to prepare this topic
Practice writing complete Pthreads programs, memorize essential function signatures, understand return value conventions, study synchronization examples with mutexes and condition variables, and learn debugging techniques for Pthreads applications using tools like valgrind.

Key Terms:

  • POSIX - Portable Operating System Interface standard.
  • pthread_create - function to create new POSIX thread.
  • pthread_join - function to wait for thread termination.
  • pthread_mutex - mutual exclusion lock for synchronization.

📝 All Pthreads in operating system MCQs

Q1. A program needs to run a calculation in a worker thread and continue accepting user input in the main thread. Which Pthreads function is normally used to create the worker?

A.pthread_create() ✅
B.pthread_join()
C.pthread_mutex_unlock()
D.pthread_exit()
💡 Difficulty: easy | ✅ Correct: A

📖 Explanation: The function pthread_create() requests creation of a new thread that begins execution through a specified start routine. The main thread can continue other work while the worker is eligible to execute, although the exact execution order depends on scheduling.

Q2. A main thread must wait until a worker finishes and obtain its returned pointer value. Which operation is most appropriate for a joinable worker?

A.pthread_cancel()
B.pthread_detach()
C.pthread_join() ✅
D.pthread_mutex_init()
💡 Difficulty: easy | ✅ Correct: C

📖 Explanation: pthread_join() waits for the specified joinable thread to terminate and can collect the value returned by its start routine or passed to pthread_exit(). It is appropriate when the caller needs completion synchronization and access to the worker's result.

Q3. A worker returns the address of a local variable from its start routine. The main thread retrieves that pointer using pthread_join(). What is the principal error?

A.A thread cannot return any pointer value
B.The join operation always copies the entire stack
C.The main thread must have a larger stack than the worker
D.The local variable's lifetime ends, so the returned pointer may refer to invalid storage ✅
💡 Difficulty: medium | ✅ Correct: D

📖 Explanation: A local automatic variable generally ceases to exist when its function returns. Joining the thread does not extend that variable's lifetime, so dereferencing the returned pointer may cause undefined behavior. The result should use valid longer-lived storage or another safe ownership strategy.

Q4. A developer creates four workers with pthread_create() and immediately calls pthread_join() on each worker in a loop. The workers perform independent computations. What is the key observation?

A.The program is guaranteed to execute only one worker in the entire process
B.Joining the workers one after another necessarily prevents their concurrent execution
C.Workers may execute concurrently after creation even though the main thread joins them sequentially ✅
D.pthread_join() automatically merges all worker computations into one thread
💡 Difficulty: medium | ✅ Correct: C

📖 Explanation: The workers become eligible to run when created, so they may execute concurrently while the main thread later waits for their completion. Sequential join calls determine the order in which the main thread waits, but do not necessarily serialize the workers' computation.

Q5. A Pthreads program initializes a mutex, locks it, updates a shared structure, and then returns from the function without unlocking it. Other workers later wait forever for that mutex. What is the most likely cause?

A.pthread_mutex_lock() automatically destroys the mutex
B.The mutex remains locked, so other threads cannot acquire it ✅
C.The mutex forces all threads to terminate
D.pthread_create() converts the mutex into a condition variable
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: A mutex protects a critical section only when the locking and unlocking protocol is followed correctly. If a thread exits while holding a mutex, other threads may remain blocked indefinitely unless the design has a suitable recovery mechanism; cleanup should ensure the lock is released safely.

Q6. Which statement about pthread_create() is correct?

A.It guarantees the new thread completes before returning
B.It always creates a new operating-system process
C.It automatically joins the new thread when the creator exits
D.It creates a thread that begins execution through a supplied start routine when scheduled ✅
💡 Difficulty: easy | ✅ Correct: D

📖 Explanation: pthread_create() creates a new thread with a specified start routine and argument. The thread may begin executing before or after the creating thread continues, so applications should not depend on a particular ordering unless synchronization explicitly establishes it.

Q7. A worker receives a pointer to a shared counter through the argument passed to pthread_create(). What must the programmer ensure?

A.The counter remains valid for the worker's entire access period and shared updates are synchronized as needed ✅
B.The pointer must always refer to a global variable, regardless of lifetime
C.The argument must contain a separate operating system process identifier
D.The worker must never return from its start routine
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: The argument pointer must refer to valid storage for as long as the worker uses it. If multiple threads access the counter and at least one modifies it, the application must also use suitable synchronization or atomic operations to avoid data races.

Q8. A program has six workers, each processing 20 independent CPU-bound tasks requiring 2 ms each. With six effective processor cores and no overhead, what is the ideal completion time?

A.120 ms
B.40 ms ✅
C.20 ms
D.6 ms
💡 Difficulty: hard | ✅ Correct: B

📖 Explanation: Each worker processes 20×2=4020 \times 2 = 4020×2=40 ms of CPU work. Six workers can run concurrently on six effective cores, so all six worker workloads finish in 40 ms. This assumes equal work distribution, no dependencies, and zero thread-management or scheduling overhead.

Q9. A developer checks pthread_create() only for a nonzero return value and assumes that the returned value is an error number from errno. What correction is appropriate?

A.pthread_create() never reports errors
B.The return value always contains a valid thread identifier on failure
C.Errors must be detected by checking whether the worker immediately prints output
D.Check the function's return code directly; a nonzero return indicates an error code, and errno should not be assumed to hold it ✅
💡 Difficulty: medium | ✅ Correct: D

📖 Explanation: POSIX functions such as pthread_create() report errors through their return value, rather than generally using errno in the usual system-call style. The program should compare the returned code with zero and handle failures before assuming that a valid thread was created.

Q10. A program calls pthread_join() on a thread that has already been detached. Which design assumption is invalid?

A.Every created thread must be joined exactly once
B.The program assumes the target remains joinable when it has been detached ✅
C.A detached thread can still execute its start routine
D.Thread creation and thread joining are different operations
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: Detaching a thread changes how its termination resources are reclaimed and normally makes it unavailable for joining. A program should decide whether it needs join-based completion and result collection before detaching the thread, rather than treating the two lifecycle choices as interchangeable.

Q11. A Pthreads application experiences increasing response time as worker count rises from 4 to 32. CPU utilization is already near 100 percent at four workers. Which explanation is most plausible?

A.More workers can add scheduling and contention overhead without increasing available CPU capacity ✅
B.The application must have fewer tasks than workers
C.Pthreads requires a separate core for each created thread
D.Near-100% CPU utilization proves that all tasks are waiting for input
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: Once the processor is saturated, adding workers may not create more CPU capacity. More runnable threads can increase context switching, lock contention, and queueing, which can worsen response time without increasing useful throughput.

Q12. A worker returns a pointer to a heap-allocated result, and the main thread obtains it through pthread_join(). Which responsibility remains with the application?

A.Assume the join operation automatically frees all heap memory
B.Avoid reading the result after the worker terminates under every circumstance
C.Keep the result permanently allocated even after use
D.Ensure the memory is freed exactly once when no longer needed ✅
💡 Difficulty: medium | ✅ Correct: D

📖 Explanation: pthread_join() collects the returned pointer but does not automatically free the memory to which it points. The application must define ownership, ensure the result remains valid while used, and release the allocation exactly once to avoid leaks or double-free errors.

Q13. A worker must sleep until a producer adds an item to a shared queue. Which combination is generally suitable for coordinating this condition safely?

A.A busy loop that reads the queue without synchronization
B.A mutex protecting the queue and a condition variable used with a predicate-checking loop ✅
C.A detached thread and an unprotected global flag
D.A call to pthread_exit() from the producer before inserting the item
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: A mutex protects the queue and the predicate that determines whether it contains an item. A condition variable allows a consumer to wait efficiently and recheck the predicate after waking, handling spurious wake-ups or cases where another consumer takes the item first.

Q14. A program uses pthread_mutex_lock() to protect a shared counter, but one worker occasionally tries to lock the same non-recursive mutex twice without unlocking it. What may happen?

A.The second lock always creates a new independent mutex
B.The counter becomes thread-local automatically
C.The worker may block waiting for a mutex it already holds ✅
D.The mutex automatically releases itself after two lock calls
💡 Difficulty: medium | ✅ Correct: C

📖 Explanation: Locking an already-held normal non-recursive mutex by the same thread can cause the thread to block indefinitely, depending on the mutex type and implementation behavior. The program should avoid recursive acquisition unless a suitable recursive mutex is deliberately configured and appropriate.

Q15. A developer wants to pass an integer task identifier to a worker using pthread_create(). Which approach is safest and most portable?

A.Use storage with a well-defined lifetime and pass a pointer to it, then read the value with the correct type ✅
B.Pass the address of a loop variable that is immediately reused without coordination
C.Pass a pointer to a local variable whose function returns before the worker reads it
D.Cast any integer to a pointer and dereference it without considering portability
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: The argument supplied to pthread_create() is a void pointer, so passing a pointer to valid storage with a suitable lifetime and type is a robust approach. Reused or expired storage can lead to incorrect values or undefined behavior; integer-to-pointer conversions are not universally portable.

Q16. A developer creates a thread with pthread_create() but passes a function whose signature does not match the required start-routine type. Why is this unsafe?

A.Pthreads automatically converts every incompatible function into a valid callback
B.The thread is guaranteed to execute the function correctly on all platforms
C.A type mismatch may cause undefined behavior or compiler diagnostics and should be corrected ✅
D.The mismatch affects only the printed thread name
💡 Difficulty: hard | ✅ Correct: C

📖 Explanation: The start routine must have the required compatible function type, typically returning void pointer and accepting a void pointer argument. Passing an incompatible function pointer is not a safe substitute and can cause diagnostics or undefined behavior; a correctly typed wrapper can adapt other functions.

Q17. A worker updates a shared result and then calls pthread_mutex_unlock(). The main thread later locks the same mutex before reading the result. What is the main benefit of this pattern?

A.It guarantees that the worker uses a separate processor
B.It makes the result independent of all program logic
C.It eliminates the need to initialize the mutex
D.It provides synchronization so the protected update can be safely observed after lock acquisition ✅
💡 Difficulty: medium | ✅ Correct: D

📖 Explanation: Correct mutex usage establishes synchronization between the thread releasing the lock and another thread subsequently acquiring it. This helps make the protected update visible and prevents conflicting accesses within the critical section, provided all relevant accesses follow the same synchronization discipline.

Q18. A program creates a worker and then calls pthread_exit() in the main thread. What is the most accurate general description of the intended effect?

A.It always terminates the entire process immediately, regardless of other threads
B.It terminates the calling thread while allowing other process threads to continue, subject to process-lifetime conditions ✅
C.It joins every other thread automatically
D.It detaches every worker and collects all their results
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: pthread_exit() terminates the calling thread rather than directly acting as a join operation. Other threads may continue executing, but process termination and the program's overall lifecycle still depend on what the remaining threads do and whether the process exits through another mechanism.

Q19. A developer uses pthread_cancel() to stop a worker and assumes every resource held by that worker will automatically be released safely. What is the strongest correction?

A.Cancellation always rolls back all shared-memory writes
B.Cancellation is identical to pthread_join()
C.A cancelled thread always releases every application lock in every possible cancellation state
D.Cancellation behavior and cleanup must be designed so locks and resources are not left inconsistent ✅
💡 Difficulty: medium | ✅ Correct: D

📖 Explanation: Thread cancellation behavior depends on cancellation state, type, and cancellation points. If a worker is cancelled while holding a mutex or modifying shared data, cleanup may be necessary to release resources and preserve invariants. Applications should not assume cancellation automatically rolls back operations.

Q20. A programmer calls pthread_mutex_destroy() while another thread may still be using the mutex. What is the main concern?

A.Destroying a mutex always increases parallelism
B.Destroying a mutex that is locked or still in use can produce undefined behavior or other errors ✅
C.The mutex is converted into a condition variable
D.The other thread automatically acquires a new mutex with the same identity
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: A mutex should be destroyed only when it is no longer in use and is in an appropriate state. Destroying a locked mutex or one that another thread may access can lead to undefined behavior or implementation errors, so lifecycle coordination is essential.

Q21. A developer believes that using pthread_join() automatically protects every shared variable written by the worker from concurrent access by other threads. Which statement is most accurate?

A.Joining a worker does not replace synchronization needed for concurrent accesses while the worker is running ✅
B.Joining makes every global variable atomic permanently
C.Joining prevents any other worker from executing
D.Joining automatically creates a mutex around every global variable
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: pthread_join() provides a way to wait for a particular thread's termination and synchronize with its completion. It does not prevent data races among threads while they are running, so shared state still needs appropriate mutexes, atomics, or other synchronization.

Q22. A worker writes a result to shared memory and sets a plain Boolean flag to true. The main thread repeatedly reads the flag without synchronization and then reads the result. What is the primary concern in C?

A.The Boolean flag is automatically protected by pthread_create() forever
B.The main thread must always see the newest value because it is on the same process
C.Unsynchronized conflicting accesses can create a data race and undefined behavior ✅
D.Plain Boolean variables are always invalid in multithreaded programs
💡 Difficulty: hard | ✅ Correct: C

📖 Explanation: In C, unsynchronized concurrent access to an ordinary shared variable can create a data race when at least one access modifies it. The flag and result need a correct synchronization protocol, such as a mutex or suitable atomic operations with appropriate memory ordering.

Q23. A program creates a thread using an attribute object, then changes the object's stack-size attribute while the thread is already running. What should the programmer understand?

A.Changing an attribute object generally does not retroactively resize an already-created thread's stack ✅
B.The stack size always doubles whenever an attribute changes
C.Every running thread reads all attribute changes continuously
D.The change automatically terminates the thread
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: Thread attributes are generally used to configure a thread at creation time. Changing the attribute object afterward does not normally alter the resources already allocated to an existing thread, so stack-size requirements should be considered before creating the thread.

Q24. A programmer calls pthread_join() from a worker thread and passes that same thread's identifier as the target. What is the main issue?

A.Self-joining always creates a new thread
B.The operation can fail or deadlock because a thread cannot meaningfully wait for its own termination ✅
C.The operation automatically changes the worker to detached state
D.The operation returns the thread's start routine without waiting
💡 Difficulty: hard | ✅ Correct: B

📖 Explanation: A thread cannot complete while it is waiting for its own termination. Attempting to join oneself is an invalid design and may return an error such as EDEADLK, depending on the implementation. Thread dependencies should be structured so a thread waits only for another thread that can finish independently.

Q25. A worker pool uses four threads. One worker blocks while waiting for a slow file operation, while three other workers continue processing independent CPU tasks. What does this demonstrate?

A.All Pthreads workers must block whenever one thread performs file I/O
B.The file operation creates three additional processor cores
C.Independent workers can continue making progress while another worker is blocked ✅
D.A blocked worker automatically transfers its stack to every other worker
💡 Difficulty: medium | ✅ Correct: C

📖 Explanation: Blocking one thread does not inherently block every other thread in the same process. Other workers can continue running independent work if they remain runnable and processor resources are available. The overall benefit depends on the threading implementation and how blocking operations interact with execution resources.

Q26. A developer wants a worker to perform cleanup after each task but remain available for subsequent tasks. Which design is most appropriate?

A.Call pthread_exit() after every task and assume the same thread resumes
B.Use pthread_cancel() after every successful task
C.Detach the worker after every task without recreating it
D.Keep the worker in a loop that processes tasks and performs per-task cleanup before accepting the next task ✅
💡 Difficulty: medium | ✅ Correct: D

📖 Explanation: A reusable worker can run a task-processing loop, performing the necessary cleanup after each task and then returning to the queue. This avoids repeatedly creating and destroying threads, while allowing resources associated with each individual task to be released at the correct time.
