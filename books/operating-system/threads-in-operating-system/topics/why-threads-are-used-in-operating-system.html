What is Why threads are used in operating system?

Definition:
Threads are used to achieve concurrency and parallelism within applications, allowing multiple tasks to execute simultaneously. They enable efficient resource utilization, improved application responsiveness, and better performance on multicore processors by dividing work into smaller, manageable execution units that share common resources.

Working:
The OS creates threads within processes to handle different tasks concurrently. When one thread waits for I/O, another can use the CPU. This overlapping of computation and I/O operations maximizes CPU utilization and reduces overall execution time for complex applications requiring multiple simultaneous operations.

Example:
A word processor uses one thread for typing input, another for spell-checking, and a third for auto-saving. If spell-checking takes 222 seconds, typing continues uninterrupted. Solution: Thread 1 handles keystrokes immediately while Thread 2 processes background tasks.

Reason:
Threads provide faster context switching than processes, require less memory overhead, enable natural modeling of concurrent activities, and allow applications to take advantage of multicore architectures without complex inter-process communication mechanisms.

Common MisConceptions:
Many believe threads automatically speed up all programs. However, poorly designed threaded applications can suffer from race conditions and deadlocks. Also, students think threading is only useful for multicore systems, but it benefits single-core systems through better I/O overlap.

Exam Preparation Tips: How to prepare this topic
Create comparison tables for threads vs processes, understand real-world applications requiring threads, practice identifying scenarios where threads improve performance, and study the relationship between threads and CPU utilization metrics.

Key Terms:

  • Concurrency - managing multiple tasks simultaneously.
  • Parallelism - executing multiple tasks at the exact same time.
  • Responsiveness - ability to respond quickly to user input.
  • Resource Sharing - common memory access among threads.

📝 All Why threads are used in operating system MCQs

Q1. Which primary resource advantage do threads have over processes when creating concurrent execution units?

A.Threads require separate virtual memory spaces
B.Threads share the parent process address space and resources ✅
C.Threads have higher creation overhead than processes
D.Threads cannot share file descriptors
💡 Difficulty: easy | ✅ Correct: B

📖 Explanation: Threads share the code section, data section, and open files of the parent process, requiring only a small stack and register set for creation. This significantly reduces memory footprint and creation time compared to duplicating an entire process address space.

Q2. In a single-core processor system, what is the primary benefit of using multithreading for a web browser?

A.True parallel execution of all tasks
B.Improved responsiveness during I/O operations ✅
C.Reduced total CPU usage
D.Elimination of context switching
💡 Difficulty: easy | ✅ Correct: B

📖 Explanation: On a single core, threads provide concurrency through time-slicing. When one thread blocks on network I/O (loading a page), another thread can execute (handling user input), keeping the UI responsive despite the lack of true hardware parallelism.

Q3. Why is context switching between threads of the same process faster than between different processes?

A.Threads do not require CPU register saving
B.No need to flush TLB and change page tables ✅
C.Threads have smaller code sections
D.Kernel bypasses scheduler for threads
💡 Difficulty: easy | ✅ Correct: B

📖 Explanation: Thread context switches within the same process do not require changing the virtual memory mapping (page tables). This avoids expensive TLB (Translation Lookaside Buffer) flushes and cache invalidations associated with process switches, making them significantly faster.

Q4. What happens to the shared memory segment when a new thread is created within a process?

A.A complete copy is made for the thread
B.The thread gets read-only access
C.The thread shares the existing memory space ✅
D.Memory is duplicated until modified
💡 Difficulty: easy | ✅ Correct: C

📖 Explanation: New threads share the existing heap and global data segments of the process. They do not get copies of memory, which saves significant RAM and allows efficient communication through shared variables without complex IPC mechanisms like pipes or sockets.

Q5. Which scenario best demonstrates the 'responsiveness' advantage of threads?

A.A batch job processing millions of records
B.A GUI application updating progress bar while calculating ✅
C.A server handling static file requests
D.A compiler optimizing code
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: In a GUI application, a long calculation in a worker thread prevents the UI from freezing. The main thread continues to handle mouse clicks and repaint events, providing immediate feedback to the user, which is impossible in a single-threaded blocking model.

Q6. Why might a database server prefer multithreading over multiprocessing for handling concurrent queries?

A.Processes offer better security isolation
B.Threads allow easier sharing of buffer pools and caches ✅
C.Processes have lower context switch overhead
D.Threads prevent deadlock scenarios
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: Database servers rely heavily on shared buffer pools and cached query plans. Threads can access these shared memory structures directly without serialization overhead required for inter-process communication, leading to higher throughput for concurrent query processing.

Q7. How does multithreading improve resource utilization in a multi-core server environment?

A.By reducing the number of active cores
B.By enabling parallel execution across multiple cores ✅
C.By minimizing memory bandwidth usage
D.By eliminating the need for scheduling
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: Multithreading allows the operating system to schedule different threads on different physical cores simultaneously. This exploits hardware parallelism, increasing overall throughput by keeping all cores busy rather than leaving some idle while others are overloaded.

Q8. What is the primary risk associated with sharing memory among threads compared to isolated processes?

A.Increased memory consumption
B.Race conditions and data corruption ✅
C.Slower execution speed
D.Inability to use global variables
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: Since threads share the same address space, concurrent unsynchronized access to shared data can lead to race conditions where the final state depends on unpredictable timing. Processes are isolated by default, preventing such accidental data interference.

Q9. In a real-time control system, why are kernel-level threads preferred for meeting deadlines?

A.They have lower creation cost
B.They support priority-based preemptive scheduling ✅
C.They do not require synchronization
D.They run in user space for safety
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: Kernel-level threads integrate with the OS scheduler, allowing high-priority real-time threads to preempt lower-priority ones immediately. This deterministic scheduling is crucial for meeting hard deadlines, which user-level threads cannot guarantee due to potential blocking.

Q10. Why is the 'Many-to-One' threading model often unsuitable for modern multi-core applications?

A.It consumes too much memory
B.It cannot exploit true parallelism on multiple cores ✅
C.It is too complex to implement
D.It requires special hardware support
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: In the Many-to-One model, all user threads map to a single kernel thread. Since only one kernel thread can run at a time, the application cannot utilize multiple CPU cores for parallel execution, limiting performance to that of a single core regardless of thread count.

Q11. Consider a video transcoding application. Why is pipeline threading effective here?

A.It reduces the total amount of data processed
B.It overlaps decoding and encoding stages concurrently ✅
C.It eliminates the need for temporary storage
D.It simplifies the error handling logic
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: Pipeline threading allows the decoder to work on Frame N+1 while the encoder works on Frame N. This overlap keeps both CPU and I/O subsystems busy, increasing throughput compared to sequential processing where each stage waits for the previous one to complete entirely.

Q12. How does using a thread pool improve performance over creating a new thread for each request in a web server?

A.It increases the maximum number of connections
B.It amortizes thread creation and destruction overhead ✅
C.It allows threads to share stack memory
D.It eliminates the need for load balancing
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: Creating and destroying threads is expensive. A thread pool reuses existing threads for multiple requests, avoiding repeated allocation and initialization costs. This reduces latency for individual requests and prevents resource exhaustion during traffic spikes.

Q13. Why might a scientific simulation use one thread per data chunk rather than one thread per data element?

A.To minimize synchronization and scheduling overhead ✅
B.To maximize the number of context switches
C.To ensure each element has its own stack
D.To prevent any form of parallelism
💡 Difficulty: hard | ✅ Correct: A

📖 Explanation: Creating a thread for every data element creates massive overhead from context switching and management. Grouping elements into chunks balances the workload across available cores while keeping the number of threads manageable, optimizing the ratio of computation to overhead.

Q14. What is the 'False Sharing' problem in multithreaded programs running on multi-core systems?

A.Threads share incorrect data values
B.Multiple threads modify variables in the same cache line ✅
C.Threads access memory out of bounds
D.Shared memory is not synchronized properly
💡 Difficulty: hard | ✅ Correct: B

📖 Explanation: Even if threads access different variables, if those variables reside in the same CPU cache line, modifications by one thread invalidate the cache line for other cores. This causes unnecessary cache coherence traffic and performance degradation, known as false sharing.

Q15. Why is debugging multithreaded applications more difficult than single-threaded ones?

A.Threads do not produce log output
B.Non-deterministic execution order causes intermittent bugs ✅
C.Debuggers cannot attach to threads
D.Threads consume too much stack space
💡 Difficulty: hard | ✅ Correct: B

📖 Explanation: Race conditions and deadlocks depend on specific timing interleavings that may not occur during every run. This non-determinism makes bugs hard to reproduce and isolate, as adding debug prints or breakpoints can change the timing and mask the issue (Heisenbug).

Q16. In a producer-consumer pattern, what role does the bounded buffer play in thread coordination?

A.It increases memory usage unnecessarily
B.It decouples production rate from consumption rate ✅
C.It forces threads to run sequentially
D.It eliminates the need for synchronization
💡 Difficulty: hard | ✅ Correct: B

📖 Explanation: The bounded buffer allows producers to continue working even if consumers are temporarily slow, and vice versa. It absorbs bursts in production or consumption rates, smoothing out variability and preventing either side from blocking the other unnecessarily, improving overall throughput.

Q17. Why might a garbage-collected language runtime pause all threads during collection?

A.To simplify the implementation of the collector
B.To ensure memory consistency and prevent dangling pointers ✅
C.To reduce CPU usage during GC
D.Because threads cannot allocate memory concurrently
💡 Difficulty: hard | ✅ Correct: B

📖 Explanation: In stop-the-world garbage collection, pausing mutator threads prevents object references from changing while the collector traces reachability. This gives the collector a consistent view of the heap and helps prevent it from mistakenly reclaiming objects that are still reachable; it is not primarily about preventing dangling pointers.

Q18. What is the primary limitation of user-level threads when one thread performs a blocking system call?

A.The thread terminates immediately
B.The entire process blocks, stopping all threads ✅
C.The kernel kills the process
D.Other threads automatically gain higher priority
💡 Difficulty: hard | ✅ Correct: B

📖 Explanation: Since the kernel is unaware of user-level threads, it sees only the single underlying kernel thread. If that thread blocks on I/O, the kernel suspends the entire process, preventing other ready user-level threads from executing until the I/O completes.

Q19. How does Amdahl's Law limit the performance gain from adding more threads?

A.It states that threads increase memory usage linearly
B.It limits speedup based on the serial fraction of the program ✅
C.It prohibits more threads than CPU cores
D.It requires exponential growth in thread count
💡 Difficulty: hard | ✅ Correct: B

📖 Explanation: Amdahl's Law dictates that the maximum speedup is limited by the portion of the program that must run sequentially SSS. Even with infinite threads, speedup is capped at 1S\frac{1}{S}S1​. If 10% of code is serial, max speedup is 10x, regardless of thread count.

Q20. Design a strategy: For a high-frequency trading system, why might you pin threads to specific CPU cores?

A.To prevent the OS from scheduling them
B.To minimize cache misses and context switch latency ✅
C.To allow threads to sleep longer
D.To increase the number of available cores
💡 Difficulty: hard | ✅ Correct: B

📖 Explanation: Pinning threads (affinity) ensures they stay on the same core, preserving warm caches. In low-latency systems, avoiding cache cold starts and migration overhead is critical. It also reduces contention for scheduler locks, providing more predictable execution times.

Q21. Why is the 'One-to-One' threading model considered a good balance for general-purpose OSes?

A.It maps each user thread to a kernel thread, allowing true parallelism ✅
B.It requires no kernel support
C.It allows unlimited user threads per kernel thread
D.It eliminates all synchronization needs
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: The One-to-One model allows the OS scheduler to distribute threads across multiple cores for true parallelism. While it has higher overhead than Many-to-One, it avoids the blocking problem and provides a straightforward mapping that modern OSes handle efficiently.

Q22. What is the main advantage of asynchronous I/O combined with a small thread pool?

A.It eliminates the need for any threads
B.It allows a few threads to handle many I/O operations concurrently ✅
C.It increases the size of the thread stack
D.It requires more system calls per operation
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: Asynchronous I/O allows threads to initiate I/O and continue processing other tasks without blocking. A small pool of threads can manage thousands of concurrent connections by switching tasks when I/O is pending, maximizing resource efficiency without creating thousands of threads.

Q23. Why might a developer choose coroutines over OS threads for a high-concurrency network server?

A.Coroutines provide hardware-level parallelism
B.Coroutines have lower memory overhead and cooperative scheduling ✅
C.Coroutines are managed by the kernel
D.Coroutines eliminate the need for networking code
💡 Difficulty: hard | ✅ Correct: B

📖 Explanation: Coroutines are lightweight user-space constructs with minimal stack size (KB vs MB for threads). Cooperative scheduling means no preemption overhead, and thousands of coroutines can run in a single thread, reducing context switch costs significantly compared to OS threads.

Q24. In a multi-threaded web crawler, how should URL frontier management be handled to avoid race conditions?

A.Each thread should have its own private list
B.Use a thread-safe queue with synchronization primitives ✅
C.Disable threading for URL management
D.Store URLs in global variables without locks
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: A thread-safe queue ensures that only one thread can dequeue a URL at a time, preventing duplicate crawling. Private lists would require complex merging, and unsynchronized global access leads to data corruption. Synchronization ensures integrity of the shared work queue.

Q25. Why is thread-local storage useful in a multi-threaded web server handling user sessions?

A.It allows all threads to share session data
B.It provides each thread with private data without synchronization ✅
C.It reduces the total memory used by the server
D.It enables threads to communicate directly
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: Thread-local storage gives each thread its own instance of a variable (e.g., a random number generator seed or temporary buffer). This eliminates the need for locks when accessing these variables, improving performance by removing contention for frequently accessed per-thread data.

Q26. What is the 'Thundering Herd' problem in thread synchronization?

A.Too many threads wake up simultaneously to compete for a lock ✅
B.Threads die unexpectedly under load
C.All threads block permanently
D.Threads consume excessive CPU while idle
💡 Difficulty: hard | ✅ Correct: A

📖 Explanation: When a condition variable is signaled, all waiting threads may wake up and compete for the associated mutex, causing a spike in context switches and contention. Only one will succeed, while others go back to sleep, wasting CPU cycles. Solutions include using exclusive signals or queues.

Q27. Why might a real-time audio processing application use fixed-size thread pools?

A.To ensure predictable memory allocation and timing ✅
B.To allow dynamic scaling based on load
C.To minimize the number of CPU cores used
D.To simplify the audio codec implementation
💡 Difficulty: hard | ✅ Correct: A

📖 Explanation: Dynamic thread creation introduces unpredictable latency due to memory allocation and scheduler intervention. Fixed-size pools pre-allocate resources, ensuring that audio buffers are processed within strict deadlines without jitter caused by runtime resource management overhead.

Q28. How does hyperthreading (SMT) affect the performance of multi-threaded applications?

A.It doubles the number of physical cores
B.It allows two threads to share one physical core's execution units ✅
C.It eliminates the need for multithreading
D.It reduces the clock speed of the CPU
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: Simultaneous Multithreading (SMT) allows two logical threads to run on one physical core by utilizing unused execution units. While not as fast as two physical cores, it improves throughput for mixed workloads where one thread is stalled (e.g., waiting for memory) while the other executes.

Q29. Why is priority inversion a critical issue in real-time threaded systems?

A.It causes high-priority threads to wait for low-priority ones holding locks ✅
B.It increases the priority of all threads
C.It prevents threads from acquiring locks
D.It reduces the number of available priorities
💡 Difficulty: hard | ✅ Correct: A

📖 Explanation: If a low-priority thread holds a lock needed by a high-priority thread, and a medium-priority thread preempts the low-priority one, the high-priority thread is indirectly blocked by the medium one. This violates priority assumptions and can cause missed deadlines. Priority inheritance solves this.

Q30. What is the benefit of using read-write locks over mutual exclusion locks in a read-heavy application?

A.Read-write locks are simpler to implement
B.Multiple readers can access data simultaneously ✅
C.Read-write locks prevent all writes
D.They require less memory
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: Mutual exclusion locks allow only one thread (reader or writer) at a time. Read-write locks allow multiple readers to access data concurrently as long as no writer is active. In read-heavy scenarios, this significantly increases throughput by reducing unnecessary blocking among readers.

Q31. Why might a distributed system use threads for local request handling but processes for isolation between services?

A.Threads are slower than processes
B.Threads offer efficiency locally; processes offer fault isolation globally ✅
C.Processes cannot communicate over networks
D.Threads require more network bandwidth
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: Within a single service, threads provide efficient concurrency with shared memory. Between services, processes provide strong isolation so that a crash in one service doesn't bring down others. This hybrid approach balances performance and reliability in microservices architectures.

Q32. In a parallel matrix multiplication algorithm, why is blocking (tiling) used alongside threading?

A.To reduce the number of threads needed
B.To improve cache locality for each thread ✅
C.To simplify the mathematical formula
D.To prevent threads from accessing the matrix
💡 Difficulty: hard | ✅ Correct: B

📖 Explanation: Blocking divides the matrix into smaller sub-matrices that fit in the CPU cache. Each thread processes a block, reducing cache misses by reusing data while it's still in the cache. Without blocking, threads might thrash the cache by accessing large, scattered memory regions.

Q33. Why is it dangerous to call fork() in a multi-threaded program?

A.Fork() duplicates only the calling thread, potentially leaving locks in inconsistent states ✅
B.Fork() terminates all other threads
C.Fork() cannot be called from threads
D.Fork() creates a new process with no memory
💡 Difficulty: hard | ✅ Correct: A

📖 Explanation: After fork(), the child process has only the calling thread. If other threads held locks in the parent, those locks remain locked in the child but no thread exists to unlock them. This can lead to deadlocks if the child tries to acquire those locks or use shared libraries that expect consistent state.

Q34. How does the 'Work Stealing' scheduler improve load balancing in thread pools?

A.Idle threads steal tasks from busy threads' queues ✅
B.Threads steal CPU time from other processes
C.Threads steal memory from other threads
D.It prevents threads from finishing their tasks
💡 Difficulty: hard | ✅ Correct: A

📖 Explanation: In work stealing, each thread has its own deque of tasks. If a thread finishes its work, it steals tasks from the tail of another busy thread's deque. This dynamically balances load without central coordination, reducing contention and keeping all cores utilized efficiently.

Q35. Why might a game engine separate rendering and physics into different threads?

A.Rendering and physics have different timing and resource requirements ✅
B.They must share the same GPU memory
C.Physics calculations are always faster
D.Rendering cannot be done in parallel
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: Rendering is often GPU-bound and synchronized with display refresh rates, while physics is CPU-bound and may run at a fixed timestep. Separating them allows physics to calculate ahead or catch up without stuttering the visual frame rate, optimizing both subsystems independently.

Q36. What is the primary challenge of scaling threads to hundreds of cores?

A.Lack of programming languages
B.Increased contention for shared resources and locks ✅
C.Threads become too small to be useful
D.Operating systems do not support it
💡 Difficulty: hard | ✅ Correct: B

📖 Explanation: As core count increases, contention for shared data structures (like global allocators or locks) becomes a bottleneck. Cache coherence traffic also increases. Scaling requires lock-free algorithms, partitioned data structures, and careful design to avoid serial bottlenecks that limit scalability.

Q37. Why is determinism difficult to achieve in multithreaded systems?

A.Threads execute at unpredictable speeds and orders ✅
B.Threads always follow a fixed schedule
C.Hardware prevents deterministic execution
D.Operating systems forbid deterministic behavior
💡 Difficulty: hard | ✅ Correct: A

📖 Explanation: Thread scheduling depends on system load, interrupts, and other factors, making the exact interleaving of instructions non-deterministic. Achieving determinism requires explicit synchronization and controlled scheduling, which often sacrifices performance, making it challenging for testing and reproducibility.
