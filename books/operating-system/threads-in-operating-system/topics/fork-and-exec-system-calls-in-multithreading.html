What is Fork and exec system calls in multithreading?

Definition:
In multithreaded programs, \( \texttt{fork()} \) duplicates only the calling thread in the child process, requiring careful handling before \( \texttt{exec()} \) to avoid inheriting inconsistent mutex states or deadlocks from other threads.

Example:
A threaded server forks a child to handle a client, but must ensure no locks are held during fork to prevent deadlock in the child.

Reason:
Duplicating only one thread avoids copying potentially blocked or corrupted state, but demands discipline to maintain correctness when combining process creation with multithreading.

Q1. What does the fork() system call do in a program?

A.Creates a new thread within the same process
B.Creates a separate duplicate process ✅
C.Terminates the current process
D.Merges two processes into one

📖 Explanation: The fork() system call creates a separate duplicate process. This is a fundamental operating system concept where a new process is created as an exact copy of the calling process, with its own memory space and resources.

💡 Difficulty: easy | ✅ Correct: B

📖 Explanation: The primary question is whether fork() duplicates all threads in the process or creates a single-threaded process containing only the thread that invoked fork(). This behavior is ambiguous in multithreaded environments.

📖 Explanation: Some UNIX systems provide two versions of fork() to resolve the ambiguity: one that duplicates all threads and another that duplicates only the calling thread. This gives developers flexibility based on their specific needs.
