What is Grand Central Dispatch in operating system?

Definition:
Grand Central Dispatch (GCD) is Apple's technology for concurrent code execution on macOS and iOS, managing thread pools automatically through dispatch queues. GCD abstracts thread management completely, allowing developers to submit tasks as blocks or functions to serial or concurrent queues, with system dynamically adjusting thread count based on workload and available resources.

Working:
Developers create dispatch queues (serial or concurrent) and submit tasks using dispatch_async or dispatch_sync. GCD maintains global thread pools, automatically creating and destroying threads as needed. Serial queues execute tasks one-at-a-time maintaining order, while concurrent queues execute multiple tasks simultaneously. System prioritizes queues and manages thread allocation intelligently.

Example:
```swift
dispatch_async(dispatch_get_global_queue(DISPATCH_QUEUE_PRIORITY_DEFAULT, 0), {
// Background task
let result = heavyComputation()
dispatch_async(dispatch_get_main_queue(), {
// Update UI on main thread
updateUI(result)
})
})
```
Solution: Background computation runs on global queue while UI update safely executes on main queue.

Reason:
GCD eliminates manual thread management complexity, optimizes thread usage automatically preventing oversubscription, provides simple queue-based abstraction easier than raw threads, integrates with system power management for energy efficiency on mobile devices, and handles edge cases like queue cancellation and dependency management elegantly.

Common MisConceptions:
Students think GCD creates unlimited threads, but it intelligently limits thread count based on CPU cores. Another misconception is that all queues behave identically, when serial queues guarantee execution order while concurrent queues don't. Some believe GCD is only for Apple platforms, inspiring similar frameworks on other systems.

Exam Preparation Tips: How to prepare this topic
Understand queue types and behaviors, practice submitting tasks correctly, learn main queue significance for UI updates, study quality-of-service classes for priority management, and compare GCD with traditional threading approaches highlighting automation benefits.

Key Terms:

  • Dispatch Queue - GCD structure managing task execution.
  • Serial Queue - queue executing tasks sequentially.
  • Concurrent Queue - queue executing tasks in parallel.
  • Block - anonymous function submitted to queue.

📝 All Grand Central Dispatch in operating system MCQs

Q1. A developer needs to execute independent background tasks on Apple platforms without manually creating and managing a separate thread for every task. Which approach best fits this requirement?

A.Create a new operating-system process for every task
B.Use Grand Central Dispatch queues to submit work for runtime scheduling ✅
C.Execute every task inside a single critical section
D.Assign each task permanently to a physical CPU core
💡 Difficulty: easy | ✅ Correct: B

📖 Explanation: Grand Central Dispatch (GCD) allows applications to submit work to dispatch queues, while the system manages scheduling and execution resources. This reduces the need for manual thread creation and lifecycle management, although it does not guarantee that every task executes simultaneously.

Q2. A user interface becomes unresponsive because a developer performs a large image-processing operation synchronously on the main thread. Which change is most appropriate?

A.Move the expensive computation to a suitable background queue and return UI updates to the main queue ✅
B.Increase the number of statements executed on the main thread
C.Place the entire image-processing operation inside a synchronous main-queue dispatch
D.Replace the image-processing operation with repeated main-thread polling
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: Long-running computation on the main thread can prevent the application from processing input and refreshing its interface. Moving suitable work to a background queue can improve responsiveness, while UI changes should generally be performed on the main thread.

Q3. A developer dispatches a task asynchronously to a queue and immediately reads a result that the task has not yet produced. Occasionally, the application uses an old value. What is the most likely cause?

A.Asynchronous dispatch always executes tasks in reverse order
B.The queue permanently caches all previous return values
C.Background tasks cannot modify shared data
D.The caller assumes completion before the asynchronous task has finished ✅
💡 Difficulty: medium | ✅ Correct: D

📖 Explanation: Asynchronous submission allows the caller to continue without waiting for the submitted task to finish. Reading the result immediately can therefore access an uninitialized or outdated value. The program needs an appropriate completion mechanism, synchronization primitive, or dependent task.

Q4. A developer submits three independent calculations to a serial dispatch queue. The calculations take 2, 3, and 4 seconds, respectively. Ignoring overhead, what is the minimum total execution time if all must finish on that queue?

A.4 seconds
B.9 seconds ✅
C.6 seconds
D.2 seconds
💡 Difficulty: easy | ✅ Correct: B

📖 Explanation: A serial dispatch queue executes one submitted task at a time, so the three task durations add together. The total is 2+3+4=92+3+4=92+3+4=9 seconds, assuming no additional overhead and no time spent waiting for unrelated resources.

Q5. A developer calls a synchronous dispatch operation on the main queue from code already executing on that same queue. The application hangs. What is the best explanation?

A.The main queue automatically rejects every synchronous operation
B.Synchronous dispatch always creates a deadlock on every queue
C.The operation forces the application to create a new process
D.The current execution waits for work that cannot begin until the current execution returns ✅
💡 Difficulty: hard | ✅ Correct: D

📖 Explanation: Synchronous dispatch blocks the caller until the submitted block completes. When code running on the main queue synchronously targets that same serial queue, the new block cannot execute until the current block returns, while the current block is waiting, creating deadlock.

Q6. A developer needs to perform a background download and then update the interface only after the download succeeds. Which design best expresses the dependency without blocking the interface?

A.Perform the download synchronously on the main queue and update the UI afterward
B.Submit the download asynchronously, then schedule the UI update on the main queue from its completion path ✅
C.Submit the UI update before starting the download and assume it will wait
D.Use a serial main queue for both the download and every interface animation
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: An asynchronous download lets the main thread remain responsive. Once the download completes, its completion path can enqueue the required interface update on the main queue. This preserves the dependency while avoiding a long blocking operation on the UI thread.

Q7. A task group contains independent file-processing jobs with highly variable execution times. A developer wants to avoid manually assigning every job to a specific thread. Which GCD property is most relevant?

A.Every queue has a permanently assigned worker thread
B.Each submitted block must explicitly choose its physical CPU core
C.The dispatch system schedules queued work using available execution resources ✅
D.GCD requires all jobs to use the main queue
💡 Difficulty: medium | ✅ Correct: C

📖 Explanation: GCD separates task submission from low-level thread management. Dispatch queues describe how work should be organized, while the system schedules eligible work using available resources. This allows variable-duration tasks to be managed without requiring the programmer to assign each job to a dedicated thread.

Q8. A developer submits a long-running task to a global concurrent queue and expects the operating system to create one new thread for that task. Which correction is most accurate?

A.Global queues always create a dedicated thread per submitted block
B.Every global queue is actually a separate operating-system process
C.The task must execute on the main thread regardless of queue selection
D.GCD manages execution resources, and a submitted block is not guaranteed a dedicated thread ✅
💡 Difficulty: easy | ✅ Correct: D

📖 Explanation: Dispatch queues represent work scheduling rather than a promise of one dedicated thread per block. The runtime determines how queued work uses available execution resources. Developers should not rely on a particular thread identity unless the API explicitly provides that guarantee.

Q9. A developer puts CPU-intensive work on a concurrent queue and observes that the user interface remains responsive, but total processing time barely improves. What is the most reasonable interpretation?

A.Concurrent queues guarantee linear speedup only for CPU-intensive tasks
B.The workload may be limited by serial dependencies, hardware capacity, or contention ✅
C.The main thread must be executing every background task
D.The queue automatically converts CPU calculations into input/output operations
💡 Difficulty: hard | ✅ Correct: B

📖 Explanation: Moving CPU-intensive work away from the main thread can improve responsiveness without guaranteeing shorter total execution time. Performance depends on available cores, serial sections, memory behavior, synchronization, and scheduling overhead. Responsiveness and computational speedup are different outcomes.

Q10. A developer wants to execute one setup block before several dependent processing blocks on the same serial queue. Which property helps preserve the required sequence?

A.The queue randomly reorders tasks to maximize processor usage
B.Serial queue execution preserves submission order for its queued blocks ✅
C.The runtime automatically executes the setup block last
D.Each block must be converted into a separate process
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: A serial dispatch queue executes one block at a time in submission order. Submitting the setup block before dependent blocks on that same queue therefore preserves their sequence. This guarantee does not automatically extend to unrelated queues or work submitted through other scheduling paths.

Q11. A developer needs to execute several independent tasks concurrently but must protect a shared database cache from simultaneous modifications. Which design is generally reasonable?

A.Use a concurrent queue for independent work and serialize cache mutations through a suitable synchronization mechanism ✅
B.Place every operation on the main queue without considering responsiveness
C.Allow all cache writes to proceed simultaneously because GCD manages threads
D.Create a separate unsynchronized copy of the cache for every task and merge them randomly
💡 Difficulty: hard | ✅ Correct: A

📖 Explanation: Independent work can benefit from concurrent scheduling, while shared mutable state needs deliberate coordination. A dedicated serial queue, lock, or another suitable synchronization mechanism can protect cache mutations without unnecessarily serializing all unrelated computation.

Q12. A task is submitted with a low-priority quality-of-service setting, while another task has a higher-priority setting. Which expectation is most appropriate?

A.The lower-priority task is guaranteed never to execute
B.The higher-priority task must finish first regardless of dependencies
C.Quality-of-service settings permanently bind each task to a specific CPU
D.The system can use priority information when scheduling work, but exact execution order is not guaranteed ✅
💡 Difficulty: medium | ✅ Correct: D

📖 Explanation: Quality-of-service information communicates the relative importance and responsiveness needs of work. The system may use it to influence scheduling, but resource contention, dependencies, and implementation details mean that priority settings do not guarantee an exact start or completion order.

Q13. A developer dispatches a block asynchronously to a serial queue and immediately waits on a semaphore that the block signals. The application can no longer make progress. What should be checked first?

A.Whether the queue contains enough comments
B.Whether the waiting code prevents the queued block from executing ✅
C.Whether the block has too many local variables
D.Whether serial queues automatically discard semaphore signals
💡 Difficulty: hard | ✅ Correct: B

📖 Explanation: A semaphore wait can block the thread that needs to make progress. If that thread is also responsible for executing the queued block, or if the required execution resources are otherwise unavailable, the wait can deadlock. The blocking dependency must be examined.

Q14. A developer uses a dispatch group to coordinate several independent downloads and wants to run a final aggregation step after all downloads finish. Which approach best matches this requirement?

A.Run aggregation immediately after submitting the first download

C.Associate the downloads with a dispatch group and schedule aggregation for group completion ✅
D.Create a new process after every download without tracking completion
💡 Difficulty: medium | ✅ Correct: C

📖 Explanation: A dispatch group tracks completion across multiple asynchronous operations. A notification or appropriate group-wait mechanism can coordinate a final aggregation step after the associated tasks complete, avoiding the assumption that submitting work means the work has already finished.

Q15. A developer uses dispatch_apply for a collection of independent calculations and assumes each iteration executes on a newly created thread. Which statement is most accurate?

D.dispatch_apply always creates exactly as many threads as iterations
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: dispatch_apply schedules repeated work through dispatch mechanisms, but the system manages execution resources rather than guaranteeing a separate thread for each iteration. Actual concurrency depends on the queue, available resources, and the operation's execution characteristics.

Q16. A program submits three blocks to the same concurrent queue. The first block creates a value required by the third block, but the second and third blocks are submitted immediately afterward. What is the main correctness concern?

A.Concurrent queues always run blocks in reverse submission order
B.The second block must always finish before the first block begins
C.The third block automatically waits for every earlier block
D.The third block may run before the first finishes unless a dependency or synchronization mechanism is used ✅
💡 Difficulty: hard | ✅ Correct: D

📖 Explanation: A concurrent queue permits overlapping execution, so submission order alone does not guarantee that one block completes before another begins. If the third block requires a value produced by the first, the program must establish a dependency or another suitable synchronization relationship.

Q17. A developer wants a group of tasks to execute one after another in a fixed sequence, with each task seeing the previous task's completed changes. Which choice is most direct when all tasks can use the same queue?

A.Submit them to separate concurrent queues and assume global ordering

C.Submit the tasks in sequence to a serial dispatch queue ✅
D.Use independent concurrent tasks and compare their timestamps afterward
💡 Difficulty: medium | ✅ Correct: C

📖 Explanation: A serial queue executes submitted blocks one at a time in submission order, making it suitable for ordered state transitions. The guarantee applies to work submitted to that queue and does not automatically serialize operations that occur outside it.

Q18. A developer creates a custom serial dispatch queue and assumes it will always execute blocks on the same physical thread. Which assessment is correct?

A.A serial queue guarantees one-at-a-time execution, not a permanent dedicated thread identity ✅

💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: Serial queues guarantee that their blocks do not execute concurrently with one another, but the programmer should not infer permanent thread affinity from seriality alone. Queue execution resources may be managed by the system, subject to the API's documented guarantees.

Q19. A developer dispatches several short tasks to a concurrent queue. The measured total time is longer than running the same tasks sequentially. Which experiment is most useful?

A.Increase the number of queues indefinitely without measuring
B.Add synchronous waits after every task to force extra coordination
C.Duplicate each task to increase available work
D.Measure scheduling overhead and test batching small tasks into larger blocks ✅
💡 Difficulty: hard | ✅ Correct: D

📖 Explanation: For very short tasks, scheduling and coordination costs can exceed the work performed. Batching multiple small operations can reduce overhead, but the appropriate granularity should be determined experimentally because excessively large blocks can also reduce load balancing.

Q20. A program has two independent background operations and one final operation that requires both results. Which coordination pattern best represents this dependency?

A.Start the final operation immediately and let it guess when results are ready

C.Run the final operation repeatedly until the results appear
D.Place all three operations on unrelated queues without any completion coordination
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: The final operation depends on two results, so it must not run until both prerequisite operations have completed successfully. A dispatch group, explicit dependency tracking, or completion callbacks can represent this relationship without forcing the entire application to block.

Q21. A developer uses a dispatch source to monitor repeated events such as a timer firing or a file descriptor becoming ready. Which description best captures its role?

A.It creates a new process whenever an event occurs

D.It replaces the operating system's entire interrupt-handling system
💡 Difficulty: medium | ✅ Correct: C

📖 Explanation: Dispatch sources integrate event notifications with dispatch queues. They can deliver events such as timers or certain system-level conditions to a handler scheduled through a queue, helping applications organize event-driven work without manually polling continuously.

Q22. A developer submits a background operation that must update a shared progress indicator frequently. Updates arrive out of order and sometimes show an older percentage. Which design is most robust?

📖 Explanation: Background operations may finish or report progress at different times, so updates can arrive out of order. The application should protect shared progress state as needed and perform interface changes on the main queue, discarding stale updates when appropriate.

Q27. A developer has a serial queue that processes requests. One request performs a synchronous wait for another request submitted to the same queue. The application stops progressing. Which reasoning best explains the failure?

A.The queue has too many available worker threads
B.The active request blocks the only execution path that can process the queued dependency ✅
C.Serial queues always discard requests that depend on earlier work
D.Synchronous waits automatically make every task asynchronous
💡 Difficulty: hard | ✅ Correct: B

📖 Explanation: A serial queue executes only one block at a time. If the active block waits synchronously for another block queued behind it, that second block cannot start until the first returns. This dependency cycle causes deadlock and requires redesigning the wait or queue structure.

📖 Explanation: Independent iterations may complete in a different order from their indices or submission order. Writing each result to its own predetermined slot can avoid conflicting writes, while shared collection operations require suitable synchronization. Final processing should wait until all required results are ready.

📖 Explanation: Many concurrent tasks competing for one lock can spend substantial time waiting instead of doing useful work. Reducing the frequency of shared-state access, batching operations, or partitioning the state may improve throughput while preserving correctness.
