📝 One to One Multithreading Model in operating system (32 MCQs)

Individual Kernel Thread for Every User Thread

The one-to-one multithreading model establishes a separate kernel thread for every user-level thread created by an application. The kernel can schedule these threads independently, allowing multiple threads belonging to one process to execute simultaneously on different processor cores. This model provides stronger kernel-level concurrency than many-to-one mapping but increases the number of kernel-managed execution entities and their associated resource requirements.

Why Independent Kernel Scheduling Improves Thread Execution

In many-to-one mapping, a blocking operation affecting the single kernel thread can prevent every mapped user thread from progressing. One-to-one avoids this particular restriction because each user thread has its own kernel execution entity. It also enables multicore parallelism, although excessive kernel-thread creation can increase memory consumption and scheduling overhead.

Thread Creation and Independent Kernel Dispatching

When an application creates a user thread, the threading library requests corresponding kernel-thread support. The kernel maintains scheduling information and execution context for each thread. Its scheduler places runnable threads on available processor cores, while blocking one kernel thread does not automatically block other threads belonging to the same process.

Scheduling Four Threads Across Two Processor Cores

Suppose a process creates four user threads, T1 through T4, using one-to-one mapping. The kernel creates four corresponding kernel threads. On a machine with two available cores, two runnable threads may execute simultaneously, while the remaining threads wait for CPU allocation. If T1 blocks on disk I/O, another runnable thread can continue.

Multicore Utilisation and Kernel Management Costs

One-to-one supports responsive applications, independent blocking behaviour, and parallel execution on multicore processors. It is commonly associated with modern general-purpose threading implementations. However, each kernel thread requires management structures, scheduling attention, and stack resources. Creating extremely large numbers of threads can cause memory pressure and excessive context switching, making thread pools useful in many workloads.

Misconceptions About One-to-One Thread Mapping

'Every user thread executes simultaneously' is incorrect because simultaneous execution is limited by available cores. 'A blocked thread blocks its entire process' is incorrect because other kernel threads may continue. 'One-to-one has no thread-management overhead' is incorrect because kernel scheduling and per-thread resources still consume system capacity.

Exam Focus: Counting Kernel Threads and Available Cores

Given a number of user threads, determine the corresponding kernel-thread count and maximum simultaneous execution permitted by available cores. Compare one-to-one with many-to-one in terms of blocking and parallelism. Questions may assess scheduling, kernel resource overhead, context switching, and why a process can continue executing when one of its threads blocks.

Key Terms of One-to-One Threading

  • One-to-one mapping - One kernel thread per user thread.
  • Kernel scheduling - Kernel allocation of CPU execution.
  • Runnable thread - Thread eligible for CPU allocation.
  • Blocked thread - Thread waiting for an event.
  • Multicore - Processor containing multiple execution cores.
  • Thread overhead - Resources required to manage threads.

📝 All One to One Multithreading Model in operating system MCQs

Q1. A program creates 18 user threads under a one-to-one implementation. Assuming every creation succeeds, how many kernel threads correspond to them?

A.one
B.nine
C.eighteen ✅
D.thirty-six
💡 Difficulty: easy | ✅ Correct: C

📖 Explanation: In one-to-one mapping, every user thread has its own corresponding kernel thread. Therefore, 18 successfully created user threads require 18 kernel threads, although the operating system may impose limits on how many can be created.

Q2. Which mapping relationship defines the one-to-one threading model?

A.each user thread maps to one kernel thread ✅
B.all user threads share one kernel thread
C.many user threads share a smaller kernel-thread pool
D.one kernel thread maps to several separate processes
💡 Difficulty: easy | ✅ Correct: A

📖 Explanation: The defining property is a one-to-one correspondence between user threads and kernel threads. The operating system can therefore recognize and schedule each corresponding kernel thread as an independent execution entity.

Q3. A graph gives user-thread and kernel-thread counts as (1,1), (3,3), (5,5), (8,8), and (12,12). Which mapping does it represent?

A.many-to-one
B.many-to-many
C.two-level
D.one-to-one ✅
💡 Difficulty: easy | ✅ Correct: D

📖 Explanation: The plotted pairs show equal user-thread and kernel-thread counts at every point, so K=UK=UK=U. This indicates one kernel thread for each user thread, which is the defining relationship of one-to-one mapping.

Q4. A web service has 14 user threads, each mapped to its own kernel thread. What does the kernel receive for scheduling?

A.one shared schedulable entity for the entire process
B.14 independently schedulable kernel threads ✅
C.one kernel thread for every two user threads
D.a single thread only when a request blocks
💡 Difficulty: easy | ✅ Correct: B

📖 Explanation: In this model, each user thread has a corresponding kernel thread visible to the operating system. The kernel scheduler can manage those 14 kernel threads independently rather than treating the process as one execution path.

Q5. A file-conversion program has 10 one-to-one threads. Two are blocked on separate disk reads, while the remaining eight are runnable. How many threads may be selected to run, assuming sufficient cores?

A.two
B.ten
C.eight ✅
D.one
💡 Difficulty: easy | ✅ Correct: C

📖 Explanation: The two blocked threads cannot execute until their disk operations complete. The other eight have independent kernel threads and are runnable, so they may be selected for execution when sufficient processor cores are available.

Q6. A student claims that 20 one-to-one threads on a four-core processor can all execute at the same instant. What is the error?

A.one-to-one mapping creates independent scheduling entities, not 20 physical execution cores ✅
B.the operating system can schedule only one kernel thread per process
C.one-to-one mapping prevents threads from becoming runnable
D.each user thread must run on a different computer
💡 Difficulty: easy | ✅ Correct: A

📖 Explanation: One-to-one mapping provides a kernel thread for each user thread, but does not create hardware cores. With four cores, at most four ordinary CPU-bound threads can execute simultaneously under the stated assumptions.

Q7. A server thread blocks while waiting for a network response. Another thread has independent CPU work ready. What allows the second thread to progress in one-to-one mapping?

A.the blocked thread automatically releases every application lock
B.the runtime converts the second thread into a process
C.the network operation is cancelled when another thread becomes ready
D.the second thread has its own kernel thread that the scheduler can run ✅
💡 Difficulty: easy | ✅ Correct: D

📖 Explanation: The network wait blocks the kernel thread associated with the requesting user thread. The second thread has a separate kernel thread, so the scheduler can run it if it is ready and processor capacity is available.

Q8. A process has 24 runnable one-to-one threads on a six-core machine. If all six cores are busy executing this process, how many runnable threads are not executing at that instant?

A.six
B.eighteen ✅
C.twenty-four
D.zero
💡 Difficulty: easy | ✅ Correct: B

📖 Explanation: Six cores can execute six ordinary CPU threads simultaneously. The remaining runnable count is 24−6=1824-6=1824−6=18, so eighteen threads must wait for processor time despite each having its own kernel thread.

Q9. Which statement best describes the blocking behavior of one-to-one mapping?

A.a blocking call by one thread normally blocks every thread in the process
B.a blocking call is converted into a user-level yield automatically
C.the affected kernel thread can block while other runnable kernel threads remain eligible ✅
D.blocking calls cannot occur when kernel threads are used
💡 Difficulty: easy | ✅ Correct: C

📖 Explanation: Each user thread has a separate kernel thread, so a blocking operation normally suspends only its associated execution path. Other kernel threads can remain runnable, although application dependencies may still prevent useful progress.

Q10. A student says one-to-one mapping guarantees that every runnable thread receives a dedicated physical core. Which correction is accurate?

A.a kernel thread is a scheduling entity, not a reserved processor core ✅
B.a physical core is created whenever a user thread starts
C.only blocked threads receive dedicated cores
D.one-to-one mapping is available only on single-core systems
💡 Difficulty: easy | ✅ Correct: A

📖 Explanation: One-to-one mapping associates each user thread with a kernel scheduling entity, not a physical processor. The operating system schedules those entities onto the available cores, and multiple runnable threads may compete for limited hardware.

Q11. A service creates 500 short-lived one-to-one threads. Profiling shows rising memory use and scheduling activity. What best explains these observations?

A.each thread duplicates the entire process address space
B.the kernel ignores threads once they become runnable
C.all threads permanently occupy separate physical cores
D.each user thread requires a kernel-thread counterpart with associated state and management ✅
💡 Difficulty: easy | ✅ Correct: D

📖 Explanation: A one-to-one implementation maintains a kernel thread for every user thread. Each kernel thread requires resources and scheduling work, so a large population can increase memory use, management overhead, and context-switch activity.

Q12. A simulation creates 12 CPU-bound threads on a 12-core processor. Which statement is the most accurate expectation?

A.all threads must still execute one after another because they share a process
B.the threads can potentially run in parallel, subject to scheduling, affinity, and resource constraints ✅
C.each thread is guaranteed an exclusive core for its entire lifetime
D.one-to-one mapping automatically balances the workload perfectly
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: Separate kernel threads make multicore execution possible, but do not reserve cores or guarantee ideal scheduling. Actual parallelism depends on runnable state, processor availability, affinity, synchronization, and competition for shared resources.

Q13. A program has 16 user threads under one-to-one mapping on a single-core processor. All are CPU-bound and runnable. How many can execute simultaneously?

A.sixteen
B.eight
C.one ✅
D.zero
💡 Difficulty: medium | ✅ Correct: C

📖 Explanation: Each user thread has an independent kernel scheduling identity, but the machine has only one execution core. Therefore, only one ordinary CPU-bound thread can execute at an instant, while the others await scheduling.

Q14. Thread A blocks on file input while holding mutex M. Thread B has a separate kernel thread but needs M before updating a result. What is the likely outcome?

A.B may be scheduled but must wait for A to release M ✅
B.B automatically inherits M when A blocks
C.A's blocking call prevents the kernel from scheduling B at all
D.B proceeds because one-to-one mapping removes mutex dependencies
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: One-to-one mapping allows B to be scheduled independently, but it does not release locks held by A. Because B needs mutex M, it cannot perform the protected update until A releases that mutex.

Q15. A graph plots thread count and measured throughput: (1,40), (2,75), (4,130), (6,155), and (8,158) requests per second. What trend is shown?

A.throughput decreases whenever another thread is added
B.throughput increases at a constant rate
C.throughput is independent of thread count
D.throughput improves initially but approaches a plateau as thread count rises ✅
💡 Difficulty: medium | ✅ Correct: D

📖 Explanation: Throughput rises from 40 to 158 requests per second, but the gain between six and eight threads is only three. The measurements suggest saturation, where extra threads provide little additional useful throughput.

Q16. A developer argues that independent kernel threads eliminate all interference between threads. Which example disproves this claim?

A.each thread has its own program counter
B.two threads contend for the same mutex or memory bandwidth ✅
C.each thread has a separate kernel-thread identifier
D.the scheduler can place different threads on different cores
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: Separate kernel scheduling does not isolate shared application resources. Threads may still contend for locks, caches, memory bandwidth, or devices, so one thread can delay another even when each has its own kernel thread.

Q17. A CPU-bound application uses 80 runnable one-to-one threads on an eight-core processor. Throughput stops improving and context switches increase. Which response is most reasonable?

A.increase the thread count further because more kernel threads always improve speed
B.force every thread to use the same processor core
C.measure workload behavior and consider limiting the active worker count near available capacity ✅
D.disable kernel scheduling to avoid context switches
💡 Difficulty: medium | ✅ Correct: C

📖 Explanation: Once the eight cores are saturated, additional runnable threads may add scheduling and contention costs without increasing CPU capacity. Measuring the workload and limiting active workers can reduce overhead while retaining parallel execution.

Q18. A thread performs a blocking read, but another thread depends on a lock held by the reader. Which statement most accurately compares scheduling and application progress?

A.the second thread can be scheduled, yet remain unable to progress until the lock becomes available ✅
B.the second thread must block at the kernel level because the first thread blocked
C.the operating system automatically transfers the lock to the second thread
D.one-to-one mapping guarantees that the second thread completes first
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: Independent kernel scheduling means the second thread may receive CPU time, but its lock dependency remains. Scheduling eligibility does not guarantee useful application progress when another thread holds a required resource.

Q19. A developer expects linear speedup when increasing one-to-one threads from four to eight on a four-core machine. Why is this expectation flawed?

A.one-to-one mapping allows only four user threads to exist
B.the operating system changes to many-to-one when more than four threads are created
C.every added thread automatically reduces the clock frequency by half
D.the machine still has four execution cores, and extra threads can add overhead or contention rather than doubling CPU capacity ✅
💡 Difficulty: medium | ✅ Correct: D

📖 Explanation: Doubling runnable threads does not double hardware execution capacity. Four cores still provide at most four simultaneous ordinary CPU execution streams, while extra threads may increase scheduling, cache, and synchronization costs.

Q20. A one-to-one program has 30 threads on a six-core machine: 10 are blocked on I/O, 12 are runnable, and 8 are currently executing. Which part of this state description is inconsistent?

A.having ten blocked threads
B.having twelve runnable threads
C.having eight running CPU threads ✅
D.having thirty total threads
💡 Difficulty: medium | ✅ Correct: C

📖 Explanation: Six cores can execute at most six ordinary CPU threads simultaneously. Ten blocked and twelve runnable threads are possible, but eight simultaneously executing CPU threads exceed the six-core capacity, making that part inconsistent.

Q21. A program has 20 one-to-one threads on a five-core machine. Four threads are blocked, and the remaining 16 are CPU-bound and runnable. Assuming all cores are available, how many runnable threads cannot execute simultaneously?

A.eleven ✅
B.four
C.five
D.fifteen
💡 Difficulty: hard | ✅ Correct: A

📖 Explanation: Four blocked threads do not use the cores. Of the 16 runnable threads, five can execute simultaneously, leaving 16−5=1116-5=1116−5=11 runnable threads waiting for processor time, assuming no other scheduling restrictions apply.

Q22. An application has 100 independent tasks, each requiring 1 ms of CPU time. It creates one one-to-one thread per task on a 10-core machine. Ignoring overhead, what is the ideal CPU completion time?

A.10 ms ✅
B.1 ms
C.100 ms
D.90 ms
💡 Difficulty: hard | ✅ Correct: A

📖 Explanation: Ten cores can execute ten tasks in each 1 ms wave. One hundred tasks therefore require 100/10=10100/10=10100/10=10 waves, giving an ideal completion time of 10 ms, assuming balanced work and no overhead.

Q23. A student observes that one-to-one mapping permits other threads to run when a thread blocks and concludes that all application dependencies disappear. What is the error?

A.blocking system calls are impossible in one-to-one mapping
B.a blocked kernel thread automatically releases all locks
C.independent scheduling does not remove dependencies such as locks, shared data, or resource waits ✅
D.other threads are always suspended whenever one thread blocks
💡 Difficulty: hard | ✅ Correct: C

📖 Explanation: The flawed conclusion confuses independent scheduling with independence of application state. Other threads may run while one blocks, but locks, shared data dependencies, and resource constraints can still prevent them from completing useful work.

Q24. A workload creates 60 one-to-one threads for short CPU tasks on a six-core machine. Each task requires 0.2 ms of useful work, while measured creation and scheduling overhead averages 0.1 ms per task. What fraction of the combined per-task time is overhead?

A.one-sixth
B.one-third ✅
C.one-half
D.two-thirds
💡 Difficulty: hard | ✅ Correct: B

📖 Explanation: Each task consumes 0.2 ms of useful work plus 0.1 ms overhead, totaling 0.3 ms. The overhead fraction is 0.1/0.3=1/30.1/0.3=1/30.1/0.3=1/3, or one-third of the combined time per task. This estimate excludes further queueing or synchronization costs.

Q25. A system reaches a per-process limit of 4,096 one-to-one threads even though memory remains available. Which conclusion is valid?

A.the system must use many-to-one mapping
B.one-to-one mapping cannot enforce thread limits
C.the limit proves that the machine has exactly 4,096 cores
D.an implementation or administrative policy can restrict thread creation without changing the one-to-one mapping relationship ✅
💡 Difficulty: hard | ✅ Correct: D

📖 Explanation: One-to-one describes how successfully created user threads correspond to kernel threads; it does not require unlimited creation. Systems can enforce resource, security, or configuration limits while preserving the one-to-one relationship.

Q26. A server's one-to-one worker threads perform independent requests, but all update a shared cache protected by one global lock. Throughput stays low despite many cores. Which change could address the bottleneck?

A.remove all cache consistency checks
B.increase thread count without changing the lock
C.reduce contention by partitioning cache state or using finer-grained synchronization where safe ✅
D.force all requests to use the same thread
💡 Difficulty: hard | ✅ Correct: C

📖 Explanation: The global lock serializes access to the cache, limiting parallel progress even though kernel threads can run independently. Partitioning state or using finer-grained synchronization can reduce contention while preserving correctness.

Q27. A developer wants to evaluate whether a one-to-one design benefits a workload with frequent blocking calls. Which experiment provides the strongest evidence?

A.compare controlled runs while measuring response time, throughput, thread count, blocking time, and resource use ✅
B.measure only the maximum number of threads created
C.change the hardware and application code between every trial
D.assume each blocked thread always doubles throughput
💡 Difficulty: hard | ✅ Correct: A

📖 Explanation: A controlled evaluation should measure both performance and costs under the same workload. Response time, throughput, blocking, thread population, and resource consumption reveal whether independent scheduling outweighs kernel-thread management overhead.

Q28. A program has 32 one-to-one threads on an eight-core processor. Six threads are blocked, 18 are runnable, and eight are executing. Which statement is correct?

A.the state is impossible because blocked and runnable threads cannot coexist
B.the eight running threads match the core limit, while the 18 runnable threads await processor time ✅
C.all 32 threads must be running because each has a kernel thread
D.only six threads can execute because six are blocked
💡 Difficulty: hard | ✅ Correct: B

📖 Explanation: The six blocked threads wait for events, while eight cores can execute eight threads simultaneously. The remaining 18 runnable threads are eligible but not executing, so the described distribution is consistent with one-to-one mapping.

Q29. A student claims that one-to-one mapping necessarily has lower latency than many-to-one because every thread has its own kernel thread. Which factor invalidates that conclusion?

A.one-to-one mapping never allows parallel execution
B.many-to-one always uses more kernel resources
C.latency depends on contention, scheduling overhead, synchronization, workload, and resource availability as well as mapping ✅
D.kernel threads cannot block on input
💡 Difficulty: hard | ✅ Correct: C

📖 Explanation: Independent kernel scheduling can improve responsiveness, but it does not guarantee lower latency in every workload. Contention, scheduling costs, locks, and resource availability can dominate the effect of the mapping model.

Q30. A one-to-one application creates a thread for every arriving request. Request bursts cause thousands of simultaneous threads, but only 12 cores are available. Which architectural adjustment can control resource growth while preserving multicore execution?

A.map every request to the same single kernel thread
B.disable independent scheduling for all requests
C.create additional physical cores whenever arrivals increase
D.use a bounded set of worker threads and queue excess requests for available workers ✅
💡 Difficulty: hard | ✅ Correct: D

📖 Explanation: A bounded worker set limits kernel-thread growth while retaining multiple independent execution paths. Queuing excess requests prevents uncontrolled thread creation, and the worker count can be tuned for CPU capacity and request blocking behavior.

💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: The one-to-one relationship requires a corresponding kernel thread for each new user thread. Once created and made runnable, that kernel thread becomes eligible for operating-system scheduling, subject to available resources and policy.
