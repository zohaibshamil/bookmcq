Q1. What is the primary purpose of communication between the kernel and thread library in many-to-many models?

🔹 B. To dynamically adjust the number of kernel threads for performance
🔹 C. To create new processes
🔹 D. To allocate memory

💡 Difficulty: easy | ✅ Correct: B

📖 Explanation:

Communication between the kernel and thread library allows dynamic adjustment of kernel threads to ensure optimal performance in many-to-many and two-level models. This coordination helps balance system resources and application requirements.

Q2. What intermediate data structure is placed between user and kernel threads in many-to-many models?

🔹 A. Process control block
🔹 B. Lightweight process (LWP)
🔹 C. Thread control block
🔹 D. File descriptor table

💡 Difficulty: easy | ✅ Correct: B

📖 Explanation:

A lightweight process (LWP) serves as an intermediate data structure between user and kernel threads in many-to-many and two-level models. This structure provides a virtual processor abstraction for user-thread scheduling.

Q3. How does a lightweight process (LWP) appear to the user-thread library?

🔹 A. As a physical processor
🔹 B. As a virtual processor
🔹 C. As a kernel thread
🔹 D. As a user thread

💡 Difficulty: easy | ✅ Correct: B

📖 Explanation:

The LWP appears as a virtual processor to the user-thread library. This abstraction allows the application to schedule user threads to run on available virtual processors provided by the kernel through LWPs.

Q4. What is each lightweight process (LWP) attached to?

🔹 A. A user thread
🔹 B. A kernel thread
🔹 C. A physical processor
🔹 D. A process

💡 Difficulty: easy | ✅ Correct: B

📖 Explanation:

Each LWP is attached to a kernel thread. The kernel schedules these kernel threads to run on physical processors, while the LWP provides the interface for user thread scheduling.

Q5. What happens when a kernel thread blocks in a many-to-many model?

🔹 A. Only the kernel thread blocks
🔹 B. The LWP and attached user thread also block
🔹 C. The entire process blocks
🔹 D. Other threads are preempted

💡 Difficulty: medium | ✅ Correct: B

📖 Explanation:

When a kernel thread blocks, the LWP attached to it blocks as well, and up the chain, the user-level thread attached to the LWP also blocks. This propagation ensures consistency in the thread hierarchy.

Q6. What is the optimal LWP allocation for a CPU-bound application running on a single processor?

Additional LWPs would not improve performance as the processor can only execute one thread at a time. However, the correct answer is no LWPs needed as the application doesn't require the many-to-many model.

Q7. Why might an I/O-intensive application require multiple LWPs?

🔹 C. To reduce memory usage
🔹 D. To simplify threading

📖 Explanation:

An I/O-intensive application may require multiple LWPs to handle concurrent blocking system calls. Each concurrent I/O request needs its own LWP because all could be waiting for I/O completion in the kernel simultaneously.

Q8. How many LWPs are needed for five concurrent file-read requests?

📖 Explanation:

Five file-read requests occurring simultaneously require five LWPs because all could be waiting for I/O completion in the kernel. Each concurrent blocking system call needs its own LWP to avoid blocking other requests.

Q9. What happens if a process has fewer LWPs than concurrent blocking system calls?

🔹 C. The kernel creates more LWPs automatically
🔹 D. The process terminates

📖 Explanation:

If a process has fewer LWPs than concurrent blocking system calls, some requests must wait for an LWP to return from the kernel. The process cannot initiate all blocking operations simultaneously due to insufficient virtual processors.

Q10. What is scheduler activation?

🔹 C. A process scheduling algorithm
🔹 D. A memory management technique

💡 Difficulty: medium | ✅ Correct: B

📖 Explanation:

Scheduler activation is a communication scheme between the user-thread library and the kernel. It enables coordination where the kernel provides virtual processors to the application and informs it about important events through upcalls.

Q11. What is an upcall in the context of scheduler activations?

🔹 A. A thread creation request

🔹 C. A user thread requesting kernel service
🔹 D. A process termination signal

💡 Difficulty: medium | ✅ Correct: B

📖 Explanation:

An upcall is a procedure where the kernel informs an application about certain events. These events include threads about to block or becoming unblocked, and the upcalls are handled by the thread library's upcall handlers.

Q12. What handles upcalls in scheduler activation?

🔹 A. The kernel scheduler
🔹 B. The thread library with upcall handlers
🔹 C. The application main thread
🔹 D. The process scheduler

💡 Difficulty: medium | ✅ Correct: B

📖 Explanation:

Upcalls are handled by the thread library using upcall handlers. These handlers run on virtual processors and perform necessary actions such as saving thread states, scheduling new threads, and managing blocked threads.

Q13. What event triggers an upcall when a thread is about to block?

🔹 A. A thread completes execution
🔹 B. A thread is about to block
🔹 C. A thread is created
🔹 D. A thread is terminated

💡 Difficulty: medium | ✅ Correct: B

📖 Explanation:

When an application thread is about to block, the kernel makes an upcall to the application informing it of this event. The upcall identifies the specific thread that is about to block, allowing the thread library to handle the situation appropriately.

Q14. What does the kernel do when an application thread is about to block in scheduler activation?

🔹 A. Terminates the thread
🔹 B. Allocates a new virtual processor
🔹 C. Blocks all threads
🔹 D. Creates a new process

💡 Difficulty: hard | ✅ Correct: B

📖 Explanation:

When a thread is about to block, the kernel allocates a new virtual processor to the application. The application then runs an upcall handler on this new virtual processor to manage the blocking thread and schedule another eligible thread.

Q15. What does the upcall handler do on a new virtual processor when a thread blocks?

🔹 A. Terminates the blocking thread
🔹 B. Saves the state of the blocking thread and schedules another thread
🔹 C. Creates a new kernel thread
🔹 D. Increases thread priority

💡 Difficulty: hard | ✅ Correct: B

📖 Explanation:

The upcall handler saves the state of the blocking thread, relinquishes the virtual processor on which the blocking thread is running, and schedules another eligible thread on the new virtual processor. This ensures continued progress despite thread blocking.

Q16. What happens when the event that a blocking thread was waiting for occurs?

🔹 A. The thread is terminated

🔹 C. The thread continues automatically
🔹 D. The process restarts

💡 Difficulty: hard | ✅ Correct: B

📖 Explanation:

When the event that the blocking thread was waiting for occurs, the kernel makes another upcall to the thread library informing it that the previously blocked thread is now eligible to run. This allows the thread to be scheduled again.

An upcall handler requires a virtual processor to run. The kernel may allocate a new virtual processor for the upcall handler or preempt one of the user threads and run the upcall handler on its virtual processor.

Q18. How does the kernel handle resource allocation when a thread blocks in scheduler activation?

Q22. What is the effect of insufficient LWPs on I/O performance?

🔹 A. Improved I/O performance
🔹 B. Reduced I/O performance due to queuing
🔹 C. No effect on I/O performance
🔹 D. Better resource utilization

💡 Difficulty: hard | ✅ Correct: B

📖 Explanation:

Insufficient LWPs reduces I/O performance because requests must wait for an available LWP. When all LWPs are blocked waiting for I/O completion, new requests cannot be initiated until one of the LWPs returns from the kernel, causing queuing delays.

Scheduler activation improves upon other models by providing efficient communication between the kernel and thread library. It enables the kernel to inform the application about important events (upcalls) and allows dynamic virtual processor allocation for optimal performance.

Q34. What is the difference between upcalls and system calls?

📖 Explanation:

Upcalls are from the kernel to the application, informing it about events such as threads blocking or unblocking. System calls, in contrast, are from the application to the kernel, requesting services such as I/O operations or resource allocation.

When the attached kernel thread blocks, the LWP blocks as well. This is because the LWP depends on the kernel thread for execution on physical processors, and the kernel thread's blocking prevents the LWP from making progress.
