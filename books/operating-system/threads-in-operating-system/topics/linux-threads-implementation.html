📝 All Linux threads implementation MCQs

Q1. What system call does Linux provide for duplicating a process?

🔹 A. clone()
🔹 B. fork()
🔹 C. exec()
🔹 D. spawn()

💡 Difficulty: easy | ✅ Correct: B

📖 Explanation:

Linux provides the fork() system call with traditional functionality for duplicating a process. This creates a new process as a copy of the parent process, following the standard UNIX process creation model.

Q2. What system call does Linux provide for creating threads?

🔹 A. fork()
🔹 B. clone()
🔹 C. exec()
🔹 D. pthread_create()

💡 Difficulty: easy | ✅ Correct: B

📖 Explanation:

Linux provides the clone() system call for creating threads. Unlike fork(), clone() allows fine-grained control over resource sharing between the parent and child through flag parameters.

Q3. What term does Linux use to refer to a flow of control within a program?

🔹 A. Process
🔹 B. Thread
🔹 C. Task
🔹 D. Flow

💡 Difficulty: easy | ✅ Correct: C

📖 Explanation:

Linux uses the term task" rather than process or thread when referring to a flow of control within a program. This reflects Linux's unified approach where processes and threads are both represented as tasks."

Q4. How does Linux distinguish between processes and threads?

🔹 A. They are completely different data structures
🔹 B. Linux does not distinguish between them
🔹 C. Processes have higher priority
🔹 D. Threads are always user-level

💡 Difficulty: easy | ✅ Correct: B

📖 Explanation:

Linux does not distinguish between processes and threads. Both are represented as tasks in the kernel, and the difference lies in how much resources they share with other tasks, determined by the flags passed to clone().

Q5. What determines how much sharing occurs between parent and child when clone() is invoked?

🔹 A. The process priority
🔹 B. A set of flags passed to clone()
🔹 C. The memory size
🔹 D. The CPU speed

💡 Difficulty: medium | ✅ Correct: B

📖 Explanation:

When clone() is invoked, it is passed a set of flags that determine how much sharing is to take place between the parent and child tasks. These flags control which resources are shared or copied between the tasks.

Q6. What does the CLONE_FS flag indicate when passed to clone()?

🔹 A. The same memory space is shared
🔹 B. File-system information is shared
🔹 C. Signal handlers are shared
🔹 D. The set of open files is shared

💡 Difficulty: medium | ✅ Correct: B

📖 Explanation:

The CLONE_FS flag indicates that file-system information, such as the current working directory, is shared between the parent and child tasks. This allows both tasks to see the same file-system context.

Q7. What does the CLONE_VM flag indicate when passed to clone()?

🔹 A. File-system information is shared
🔹 B. Signal handlers are shared
🔹 C. The same memory space is shared
🔹 D. The set of open files is shared

💡 Difficulty: medium | ✅ Correct: C

📖 Explanation:

The CLONE_VM flag indicates that the same memory space is shared between the parent and child tasks. This is a key feature for thread creation, as threads within the same process share the same virtual memory address space.

Q8. What does the CLONE_SIGHAND flag indicate when passed to clone()?

🔹 A. File-system information is shared
🔹 B. The same memory space is shared
🔹 C. Signal handlers are shared
🔹 D. The set of open files is shared

💡 Difficulty: medium | ✅ Correct: C

📖 Explanation:

The CLONE_SIGHAND flag indicates that signal handlers are shared between the parent and child tasks. This allows both tasks to respond to signals in the same way, which is typical behavior for threads in a process.

Q9. What does the CLONE_FILES flag indicate when passed to clone()?

🔹 A. File-system information is shared
🔹 B. The same memory space is shared
🔹 C. Signal handlers are shared
🔹 D. The set of open files is shared

💡 Difficulty: medium | ✅ Correct: D

📖 Explanation:

The CLONE_FILES flag indicates that the set of open files is shared between the parent and child tasks. This allows both tasks to access the same file descriptors, which is common in thread implementations.

Q10. What happens when clone() is invoked with no flags set?

🔹 A. It creates a thread
🔹 B. It creates a process similar to fork()
🔹 C. It terminates the parent
🔹 D. It creates a new kernel thread

💡 Difficulty: medium | ✅ Correct: B

📖 Explanation:

When none of the sharing flags is set when clone() is invoked, no sharing takes place between parent and child. This results in functionality similar to that provided by the fork() system call, creating an independent process.

Q11. What happens when clone() is invoked with CLONE_FS, CLONE_VM, CLONE_SIGHAND, and CLONE_FILES flags set?

🔹 A. It creates a process similar to fork()
🔹 B. It creates a thread
🔹 C. It causes a compilation error
🔹 D. It creates a new kernel thread

💡 Difficulty: medium | ✅ Correct: B

📖 Explanation:

When clone() is invoked with these flags, the parent and child share file-system information, memory space, signal handlers, and open files. This is equivalent to creating a thread, as the parent shares most of its resources with the child.

Q12. What kernel data structure represents each task in Linux?

🔹 A. struct process
🔹 B. struct thread
🔹 C. struct task_struct
🔹 D. struct kernel_task

💡 Difficulty: medium | ✅ Correct: C

📖 Explanation:

A unique kernel data structure called struct task_struct exists for each task in the Linux system. This structure contains all the information needed by the kernel to manage and schedule the task.

Q13. What does struct task_struct contain?

🔹 A. The actual data for the task
🔹 B. Pointers to other data structures where data is stored
🔹 C. The task's executable code
🔹 D. The task's priority level

💡 Difficulty: medium | ✅ Correct: B

📖 Explanation:

Instead of storing data directly, struct task_struct contains pointers to other data structures where the task's data is stored. These include structures for open files, signal-handling information, and virtual memory.

Q14. What happens when fork() is invoked in Linux?

🔹 A. A new task is created pointing to parent's data
🔹 B. A new task is created with copies of all parent's data structures
🔹 C. The parent process is terminated
🔹 D. A new thread is created

💡 Difficulty: medium | ✅ Correct: B

📖 Explanation:

When fork() is invoked, a new task is created along with a copy of all the associated data structures of the parent process. This creates a completely independent process with its own resources.

Q15. What happens when clone() is invoked in Linux?

🔹 A. A new task is created with copies of all parent's data
🔹 B. A new task is created pointing to parent's data structures based on flags
🔹 C. The parent process is terminated
🔹 D. A new kernel thread is created

💡 Difficulty: medium | ✅ Correct: B

📖 Explanation:

When clone() is invoked, a new task is created, but rather than copying all data structures, the new task points to the data structures of the parent task depending on the set of flags passed. This allows selective sharing.

Q16. What is the key difference between fork() and clone() in Linux?

🔹 A. fork() creates threads, clone() creates processes
🔹 B. fork() copies data, clone() shares data based on flags
🔹 C. fork() is faster than clone()
🔹 D. There is no difference

💡 Difficulty: hard | ✅ Correct: B

📖 Explanation:

The key difference is that fork() creates a new task with copies of all parent data structures, while clone() creates a new task that points to the parent's data structures based on flags. clone() provides fine-grained control over resource sharing.

Q17. Which data structures does struct task_struct point to in Linux?

🔹 A. Only file system data
🔹 B. Open files, signal-handling information, and virtual memory structures
🔹 C. Only memory data
🔹 D. Only signal handlers

💡 Difficulty: medium | ✅ Correct: B

📖 Explanation:

Struct task_struct contains pointers to data structures that represent open files, signal-handling information, and virtual memory. These pointers allow the task to access its resources through shared or copied structures.

Q18. Why does Linux use a task rather than separate process and thread concepts?

🔹 A. To simplify the kernel
🔹 B. To provide a unified approach to control flows
🔹 C. To reduce memory usage
🔹 D. To improve security

💡 Difficulty: hard | ✅ Correct: B

📖 Explanation:

Linux uses a unified task concept to represent all flows of control. This allows flexibility where tasks can share resources to varying degrees, effectively supporting both processes and threads through the same underlying mechanism.

Q19. What is the significance of struct task_struct containing pointers instead of data?

🔹 A. It saves memory
🔹 B. It enables flexible sharing between tasks
🔹 C. It improves performance
🔹 D. It simplifies scheduling

💡 Difficulty: hard | ✅ Correct: B

📖 Explanation:

The pointer-based approach enables flexible sharing between tasks. By pointing to shared data structures, multiple tasks can share the same resources. When fork() is called, the data structures are copied, while clone() allows pointing to shared structures.

Q20. Which clone flags would create functionality equivalent to thread creation?

🔹 A. No flags set
🔹 B. CLONE_FS, CLONE_VM, CLONE_SIGHAND, and CLONE_FILES
🔹 C. Only CLONE_VM
🔹 D. Only CLONE_FILES

💡 Difficulty: hard | ✅ Correct: B

📖 Explanation:

Setting CLONE_FS, CLONE_VM, CLONE_SIGHAND, and CLONE_FILES makes the parent and child share file-system info, memory, signal handlers, and open files. This is equivalent to creating a thread since the parent shares most resources with the child.

Q21. Which clone flags would create functionality equivalent to fork()?

🔹 A. All flags set
🔹 B. No flags set
🔹 C. Only CLONE_FS set
🔹 D. Only CLONE_VM set

💡 Difficulty: medium | ✅ Correct: B

📖 Explanation:

When none of the flags are set, no sharing takes place between the parent and child, resulting in functionality similar to fork(). The child task gets its own independent resources, just like a process created by fork().

Q22. How does Linux represent multiple threads in the same process?

🔹 A. As separate processes
🔹 B. As tasks sharing the same memory space
🔹 C. As kernel threads only
🔹 D. As user threads only

💡 Difficulty: medium | ✅ Correct: B

📖 Explanation:

Multiple threads in the same process are represented as tasks sharing the same memory space (CLONE_VM flag) along with other shared resources. These tasks share the virtual memory address space while having their own execution context.

Q23. What resources are shared when CLONE_FS flag is set?

When CLONE_FS is set, the parent and child share file-system information such as the current working directory. This means changes to the file-system context by one task are visible to the other task.

Q24. What resources are shared when CLONE_FILES flag is set?

🔹 A. Memory space
🔹 B. File-system information
🔹 C. Signal handlers
🔹 D. Open file descriptors

💡 Difficulty: medium | ✅ Correct: D

📖 Explanation:

When CLONE_FILES is set, the parent and child share the same set of open file descriptors. This allows both tasks to read, write, and manipulate the same open files without needing to duplicate file handles.

Q25. What is the primary advantage of clone() over fork() in Linux?

🔹 A. Faster execution
🔹 B. Flexible resource sharing between tasks
🔹 C. Better memory management
🔹 D. Simpler interface

💡 Difficulty: hard | ✅ Correct: B

📖 Explanation:

The primary advantage of clone() is flexible resource sharing between tasks. It allows fine-grained control over which resources are shared or copied, enabling efficient thread creation where resources are shared instead of duplicated.

Q26. What is the relationship between CLONE_VM and thread creation?

CLONE_VM enables threads to share the same memory space, which is essential for thread creation. When tasks share memory, they can access the same global variables and data structures, allowing them to work together within the same process.

Q35. What is the relationship between the flags passed to clone() and the resulting task type?

🔹 B. Flags only affect performance

📖 Explanation:

The flags passed to clone() determine the type of task created. When all flags are set (sharing everything), the result is a thread. When no flags are set (sharing nothing), the result is a process. Intermediate flag combinations create tasks with varying degrees of sharing.

Not distinguishing between processes and threads simplifies the kernel design by providing a unified representation for all flows of control. The same task structures and scheduling mechanisms work for both, while sharing is controlled through clone() flags.

Q39. How does the pointer-based design of struct task_struct support both processes and threads?
