What is Multithreading models in operating system?

Definition:
Multithreading models define the relationship between user-level threads and kernel-supported threads, categorized as many-to-one, one-to-one, or many-to-many, affecting scheduling granularity and concurrency where mapping U:K U:K U:K determines performance characteristics.

Example:
Early Solaris used many-to-one; modern Linux uses one-to-one; some runtime systems use many-to-many.

Reason:
The model dictates whether blocking system calls stall all threads, how much parallelism is possible, and the trade-off between flexibility and overhead.

Q1. A system with a single CPU core implements the Many-to-One model. If a thread invokes a blocking system call, what is the immediate consequence for the other threads in the same process?

A.They are preempted and rescheduled on another core.
B.They continue to execute because the kernel schedules processes.
C.They are blocked from executing until the calling thread finishes. ✅
D.They are migrated to a different process context.
💡 Difficulty: easy | ✅ Correct: C

📖 Explanation: In the Many-to-One model, the entire process is managed by a single kernel thread. When one user-level thread makes a blocking system call, the kernel blocks the underlying kernel thread. Since all user-level threads are multiplexed onto this single kernel thread, the entire process is suspended, preventing any other user thread from running. Options A and D are incorrect because there is no other core or process context to migrate to. Option B is false as the kernel does not schedule individual user threads in this model.

Q2. Consider an application with 8 user-level threads running on a dual-core system using the One-to-One model. Which statement correctly describes the level of concurrency and parallelism achievable?

A.Maximum parallelism is 2 threads simultaneously, concurrency can be up to 8. ✅
B.Maximum parallelism is 8 threads simultaneously, concurrency is unlimited.
C.Both concurrency and parallelism are limited to 2 threads.
D.Concurrency is limited to 2 threads, but parallelism can be 8.
💡 Difficulty: hard | ✅ Correct: A

📖 Explanation: The One-to-One model maps each user thread to a distinct kernel thread. On a dual-core system, only 2 threads can execute in parallel at any given instant (one per core), so parallelism is capped at 2. However, the system can support many threads in a concurrent state (e.g., ready or waiting), and the scheduler can interleave their execution. Option B describes parallelism equal to the number of threads, which is impossible with only 2 cores. Options C and D incorrectly reverse the definitions of concurrency and parallelism.

Q3. A developer argues: 'The Many-to-One model is obsolete because it cannot utilize multiple cores, so it has no practical use.' Which statement best evaluates this criticism?

A.The criticism is entirely valid; the model offers no benefits.
B.The criticism is flawed because the model reduces overhead and is useful for specific applications. ✅
C.The criticism is valid only for systems with more than 4 cores.
D.The criticism is flawed because the model provides true kernel-level parallelism.
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: While the Many-to-One model cannot achieve parallel execution on multiple cores, it is not obsolete. Its primary advantage is extremely low overhead for thread creation and management since the kernel is not involved. It is highly suitable for applications where threads perform minimal blocking I/O and the primary goal is to simplify logic on a single-core system or within a lightweight runtime. Option A is incorrect due to these benefits. Option C is arbitrary and false. Option D is factually wrong because the model uses a single kernel thread, not multiple.

Q4. In the Many-to-Many model, which of the following scenarios would most likely cause a performance bottleneck despite having available CPU cores?

A.All user threads are CPU-bound and the number of kernel threads equals the number of CPU cores.
B.All user threads frequently perform blocking I/O operations.
C.The number of user threads is much smaller than the number of kernel threads.
D.The application uses a global interpreter lock (GIL) that serializes thread execution. ✅
💡 Difficulty: hard | ✅ Correct: D

📖 Explanation: The Many-to-Many model multiplexes user threads onto a smaller or equal number of kernel threads. A Global Interpreter Lock (GIL) is a mutual exclusion mechanism that prevents multiple threads from executing Python bytecode simultaneously, effectively serializing their execution. Even if the operating system provides multiple kernel threads and cores, the GIL forces threads to take turns, defeating the purpose of the model and creating a bottleneck. Option A is ideal performance. Option B is well-handled by the model using additional kernel threads to schedule other work. Option C is not a bottleneck.

Q5. A system uses a Two-Level model. What is the fundamental advantage it provides over a pure Many-to-Many model?

A.It allows a user thread to be bound to a specific kernel thread, ensuring it can run without being blocked by others. ✅
B.It reduces the total number of kernel threads needed to a fixed minimum.
C.It eliminates the need for kernel-level scheduling.
D.It automatically distributes threads evenly across all available CPUs.
💡 Difficulty: hard | ✅ Correct: A

📖 Explanation: The Two-Level model is an enhancement of the Many-to-Many model. It provides the flexibility to bind certain user-level threads to specific kernel threads, creating a 'real-time' or 'critical' thread that is guaranteed to run without being blocked by other user threads in the same process. This is crucial for priority threads. Option B is a feature of Many-to-One, not Two-Level. Option C is false as kernel scheduling is still the backbone. Option D describes a scheduler policy, not a core structural model.

Q6. Given the following thread state transition: Thread A is running, then it performs a long computation, and the time quantum expires. The scheduler selects Thread B to run. This is an example of:

A.Thread-level parallelism
B.Context switching ✅
C.Process migration
D.Inter-process communication
💡 Difficulty: easy | ✅ Correct: B

📖 Explanation: A context switch is the mechanism where the CPU switches from one thread or process to another. In this scenario, the operating system's scheduler interrupts Thread A after its time quantum expires, saves its state (registers, program counter), and loads the saved state of Thread B. This allows multiple threads to share a single CPU core over time. Option A is parallel execution, not time-sharing. Option C is moving a process between nodes. Option D is data exchange, not scheduling.

Q7. An operating system uses the One-to-One model. Which of the following is a direct and significant consequence of this design choice regarding resource utilization?

A.It limits the total number of threads that can be created due to kernel resource overhead. ✅
B.It ensures that all thread management can be done without system calls.
C.It completely prevents the use of multiple CPU cores.
D.It makes thread synchronization unnecessary for data integrity.
💡 Difficulty: easy | ✅ Correct: A

📖 Explanation: The One-to-One model creates a unique kernel thread for every user-level thread. This means each thread consumes kernel memory for its stack and thread control block, and management operations like creation and synchronization require system calls, which are expensive. This overhead directly limits the total number of threads an application can practically create. Option B describes the Many-to-One model. Option C is false; One-to-One enables parallel execution on multiple cores. Option D is false; synchronization is still critical.

Q8. Compare the Many-to-One and One-to-One models in terms of thread creation overhead and concurrent execution. Which statement is correct?

A.Many-to-One has low creation overhead but cannot execute threads on multiple cores. ✅
B.One-to-One has low creation overhead and can execute threads on multiple cores.
C.Many-to-One has high creation overhead but can execute threads on multiple cores.
D.Both models have similar overhead and provide the same level of parallelism.
💡 Difficulty: hard | ✅ Correct: A

📖 Explanation: The Many-to-One model manages thread creation entirely in user space without kernel intervention, resulting in very low overhead. However, it multiplexes all user threads onto a single kernel thread, preventing parallel execution on multiple cores. The One-to-One model allows for parallelism on multiple cores because each user thread maps to a kernel thread, but this involves significant overhead for each thread creation and management due to system calls. Option B is false because One-to-One has high overhead. Option C incorrectly describes Many-to-One. Option D is false.

Q9. In the Many-to-Many model, the operating system maintains a pool of kernel threads. How does this pool primarily help in managing an application with a large number of user-level threads?

A.It ensures that each user thread has a dedicated CPU core.
B.It allows the application to run without any user-level scheduling.
C.It acts as a buffer, allowing the scheduler to multiplex many user threads onto a smaller number of kernel threads, optimizing resource use. ✅
D.It prevents user threads from being blocked, regardless of their I/O operations.
💡 Difficulty: hard | ✅ Correct: C

📖 Explanation: The Many-to-Many model decouples user-level threads from kernel-level threads via a pool. The user-level scheduler maps a large number of user threads onto a smaller number of kernel threads in the pool. This avoids the massive overhead of creating a kernel thread for every user thread, while still allowing for some degree of parallelism. Option A is unrealistic; the number of cores limits that. Option B is false because user-level scheduling is a core component. Option D is false; blocking can still occur.

Q10. A programmer is writing a highly interactive GUI application that must remain responsive to user input while performing background calculations. The application is running on a multi-core system. Which threading model is most appropriate and why?

A.Many-to-One, because it offers the simplest and fastest thread management.
B.One-to-One, because it allows the GUI thread to run on one core while a background thread calculates on another, ensuring responsiveness. ✅
C.Many-to-Many, because it is the only model that supports real-time scheduling.
D.Two-Level, because it allows all threads to be bound to a single kernel thread.
💡 Difficulty: easy | ✅ Correct: B

📖 Explanation: A responsive GUI requires that the event-dispatching thread is never blocked. Background calculations must not interfere with it. On a multi-core system, the One-to-One model is ideal because it maps each thread to a distinct kernel thread, enabling true parallel execution. The GUI thread can be scheduled on one core while the calculation thread runs on another. Option A is poor as a blocking call in any thread would freeze the entire process. Option C is not exclusively for real-time. Option D is wrong because binding all to one kernel thread loses the benefit of multiple cores.

Q11. Consider a system with 4 CPU cores. An application creates 20 user-level threads and uses the Many-to-Many model with 4 kernel threads. If 3 of these user threads are CPU-bound and 17 are I/O-bound, what is the most likely consequence?

A.The 3 CPU-bound threads will run on 3 separate cores, while the 17 I/O threads are managed on the 4th kernel thread. ✅
B.All 20 threads will be blocked because there are not enough kernel threads for all.
C.The 17 I/O-bound threads will be blocked, causing a deadlock.
D.The system will panic because the number of user threads exceeds kernel threads.
💡 Difficulty: easy | ✅ Correct: A

📖 Explanation: In the Many-to-Many model, the scheduler can bind the 3 CPU-bound threads to 3 separate kernel threads, allowing them to run on 3 different cores in parallel. The remaining 1 kernel thread can handle the multiplexing and scheduling of the 17 I/O-bound threads, which spend most of their time blocked on I/O, so one kernel thread is often sufficient to manage their state. Option B is incorrect because the model doesn't require a 1:1 mapping. Options C and D are not standard consequences of this model.

Q12. Analyze the following statement: 'The Two-Level model is superior to all other models because it combines the efficiency of Many-to-One with the parallelism of One-to-One.' Is this statement accurate?

A.Yes, it provides the best of both worlds without any significant drawbacks.
B.No, it is not superior because it introduces complexity in scheduling and still requires careful management of bound threads. ✅
C.Yes, because it eliminates all contention for kernel resources.
D.No, because it cannot support more than one CPU core.
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: The Two-Level model indeed combines features: many user threads to few kernel threads, plus the ability to bind one user thread to a kernel thread. However, it is not 'superior' in a blanket sense. It introduces significant scheduling complexity. The OS and the user-space scheduler must coordinate to manage both unbound and bound threads effectively. Managing this mix and preventing priority inversion requires a complex scheduler. Option A ignores the complexity. Option C is false; resource contention still exists. Option D is false, as the Two-Level model supports multiple cores through its kernel threads.

Q13. What is the primary difference between a 'thread' in the Many-to-One model and a 'process' in a traditional single-threaded system, from the kernel's perspective?

A.There is no difference; the kernel treats them identically.
B.The kernel sees the thread as a process, while in Many-to-One, the kernel only sees a single process for the entire thread group. ✅
C.The kernel sees each thread as a separate process in Many-to-One.
D.The kernel can see and schedule individual threads in Many-to-One.
💡 Difficulty: hard | ✅ Correct: B

📖 Explanation: From the kernel's perspective in the Many-to-One model, the entire process with all its user-level threads is visible as a single entity. The kernel has no knowledge of the individual user-level threads; it only schedules the single process that contains them. In a traditional single-threaded process, this is also the case. The difference is that internally, the Many-to-One model has a user-space library managing the multiple threads, but the kernel remains unaware of them. Options A, C, and D are false because the kernel does not distinguish or schedule them at the thread level.

Q14. In an operating system using the One-to-One model, a single thread performs a blocking read operation on a disk. What happens to the process and its other threads?

A.The entire process is blocked from executing.
B.Only the calling thread is blocked; other threads in the same process continue to run. ✅
C.The process is terminated to prevent corruption.
D.All threads in the process are migrated to a different CPU.
💡 Difficulty: easy | ✅ Correct: B

📖 Explanation: In the One-to-One model, each user thread is mapped to a kernel thread. The kernel schedules these threads independently. Therefore, when a thread makes a blocking system call (like a disk read), only that particular kernel thread is placed into a waiting state. The other kernel threads belonging to the same process are unaffected and can still be scheduled by the kernel to execute. Option A describes the behavior of the Many-to-One model. Options C and D are incorrect.

Q15. Imagine a system that uses the Many-to-Many model and a scheduling algorithm that implements a 'scheduler activation' mechanism. What is the purpose of the 'upcall' from the kernel to the user-level scheduler?

A.To inform the user-level scheduler about a kernel event, such as a thread blocking, so it can adjust its scheduling. ✅
B.To perform a context switch from one user thread to another.
C.To allocate a new kernel thread for every user thread that is created.
D.To disable all user-level scheduling when the system is under heavy load.
💡 Difficulty: hard | ✅ Correct: A

📖 Explanation: Scheduler activations are a mechanism used in the Many-to-Many model. The kernel makes an 'upcall' to the user-level scheduler to notify it of kernel-level events. For example, when a user thread blocks in the kernel, the kernel sends an upcall so the user-level scheduler can schedule another user thread onto the freed kernel thread, maintaining high throughput. Option B describes context switching, which is performed by the CPU or scheduler. Option C describes the One-to-One model's behavior. Option D is the opposite of the purpose of this adaptive mechanism.

Q16. If an operating system supports the Many-to-Many model, and the number of kernel threads in the pool is significantly less than the number of user-level threads, what is the maximum level of true parallelism the application can achieve?

A.Equal to the number of user-level threads.
B.Equal to the number of kernel threads. ✅
C.Equal to the number of user-level threads divided by the kernel threads.
D.Equal to the number of CPU cores.
💡 Difficulty: easy | ✅ Correct: B

📖 Explanation: True parallelism is the ability to execute multiple instructions simultaneously on different cores. In the Many-to-Many model, even if there are many user threads, they are multiplexed onto a pool of kernel threads. The kernel schedules these kernel threads onto CPU cores. Therefore, the maximum number of threads that can be executed in parallel at any given moment is limited by the number of kernel threads available (or the number of CPU cores, whichever is smaller). Since the question states kernel threads are significantly less, that is the bottleneck.

Q17. A system is executing a CPU-intensive task. Which of the following best describes the impact of thread creation and management overhead on performance in the One-to-One model versus the Many-to-One model?

A.One-to-One has lower overhead because it doesn't use user-level scheduling.
B.Many-to-One has higher overhead because it requires kernel intervention for every thread operation.

D.Both have identical overhead because all thread operations eventually require a system call.
💡 Difficulty: easy | ✅ Correct: C

📖 Explanation: The One-to-One model involves the kernel for creation, synchronization, and management of each thread. Each of these actions requires a system call, which is a costly operation involving a context switch to kernel mode. The Many-to-One model performs nearly all thread management (creation, scheduling, synchronization) in user space without kernel intervention, making it much faster. However, this speed comes at the cost of being unable to run on multiple cores. Option A is false. Option B is the reverse. Option D is false because Many-to-One avoids many system calls.

Q18. Consider the following reasoning: 'A process with multiple threads using the Many-to-Many model is more efficient than a similar process using the Many-to-One model only when there are more CPU cores available.' Is this reasoning correct?

A.Yes, because the Many-to-Many model only provides a benefit when it can utilize multiple cores. ✅
B.No, the Many-to-Many model is always more efficient because it has better concurrency.
C.No, the Many-to-Many model is more efficient even on a single core because it reduces kernel overhead compared to Many-to-One.
D.Yes, because the Many-to-One model is unusable on multi-core systems.
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: The reasoning is correct in its core premise. The Many-to-One model maps all threads to a single kernel thread. On a single-core CPU, this doesn't matter because only one thread can run at a time anyway. The Many-to-Many model introduces the ability to use multiple kernel threads, which is only beneficial when there are multiple cores to achieve parallelism. On a single core, the Many-to-Many model simply adds more management overhead without providing a performance benefit in terms of throughput. Option B is false as efficiency is context-dependent. Option C is incorrect because Many-to-Many has more overhead than Many-to-One. Option D is false.

Q19. A specific user thread in a Many-to-Many system is designated as 'bound' to a kernel thread. What is the primary implication of this binding?

A.The thread can only execute when no other user threads are ready.
B.The thread is guaranteed to make progress even if other user threads in the process are blocked. ✅
C.The thread loses its ability to use CPU caches.
D.The thread cannot perform any I/O operations.
💡 Difficulty: hard | ✅ Correct: B

📖 Explanation: In the Many-to-Many (and especially Two-Level) model, a bound thread has a dedicated kernel thread. This means that even if other user-level threads in the same process are blocked (e.g., on I/O or a lock), the bound thread's kernel thread remains schedulable by the kernel. This ensures that the bound thread can make progress and is not blocked by the actions of its peers, making it ideal for time-critical or high-priority tasks. Option A is the opposite. Options C and D are not implications of binding.

Q20. Which of the following graphs would best represent the relationship between the number of threads (x-axis) and the execution time of a CPU-bound task (y-axis) for the Many-to-Many model on a system with 4 cores, assuming the number of kernel threads is fixed at 4?

A.A monotonically decreasing curve.

C.A linearly increasing curve.
D.A curve that is exactly constant regardless of the number of threads.
💡 Difficulty: hard | ✅ Correct: B

📖 Explanation: For a CPU-bound task, adding threads up to the number of available cores (4) will decrease execution time as parallelism increases. When thread count increases beyond 4, they must timeshare on the 4 cores, causing scheduling overhead (context switching) without increasing throughput. Thus, performance plateaus or even slightly degrades. Option A is incorrect because it suggests infinite scaling. Option C is wrong as more threads help up to a point. Option D is incorrect as initial scaling shows significant improvement. The correct graph shows an initial sharp decrease, a minimum at 4, and a slight increase/plateau after.

Q21. A student proposes that the 'Many-to-Many' model is essentially the same as the 'Two-Level' model. Which of the following correctly distinguishes them?

💡 Difficulty: hard | ✅ Correct: B

📖 Explanation: The Many-to-Many model is the general case where user threads are multiplexed onto a pool of kernel threads. The Two-Level model is a specific implementation of Many-to-Many. It operates similarly but adds the capability to 'bind' specific user-level threads to a specific kernel thread, guaranteeing a dedicated mapping. This is useful for handling priority or real-time threads. Option A is incorrect as there is a clear distinction. Option C is reversed. Option D is incorrect because Two-Level uses multiple kernel threads.

Q22. In a system running multiple applications, one using the One-to-One model and another using the Many-to-One model. Which application is likely to show better performance on a multi-core system for a heavily parallelizable task, and why?

A.The Many-to-One application, because it has lower thread management overhead.
B.The One-to-One application, because its threads can be scheduled on multiple cores simultaneously. ✅
C.The Many-to-One application, because it uses a single process, reducing memory footprint.
D.Both will show the same performance as they are limited by the CPU.
💡 Difficulty: easy | ✅ Correct: B

📖 Explanation: For a heavily parallelizable task, the ability to utilize multiple CPU cores is paramount. The One-to-One model maps each user thread to a kernel thread, so the OS can schedule them on different cores, achieving true parallelism. The Many-to-One model multiplexes all threads onto a single kernel thread, meaning only one can execute at a time, effectively wasting the multi-core capability. Option A is false because while the overhead is low, the lack of parallelism is a far greater bottleneck. Options C and D are incorrect.

Q23. A system administrator notices that a multi-threaded application is creating a very large number of threads (over 1000) and the system is becoming unresponsive. If the application is using the One-to-One model, what is the most likely primary cause of the system's poor performance?

A.The CPU cores are being overloaded by thread computation.
B.The system is running out of memory and kernel resources to manage the large number of kernel threads. ✅
C.The user-level scheduler is too slow to manage the threads.
D.The process is experiencing a deadlock.
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: The One-to-One model creates a 1:1 mapping. Creating over 1000 threads means creating over 1000 kernel threads. Each kernel thread requires a significant amount of memory for its kernel stack and task_struct, in addition to memory for the user stack. The kernel also has a limit on the total number of threads it can manage. This consumes a massive amount of system memory and can lead to system-wide thrashing or the inability to create new threads. Options A and D are possible, but the primary cause of the unresponsiveness in this scenario is the overwhelming resource consumption by the kernel threads themselves.

Q24. Consider the Many-to-Many model. A user-level thread has just been unblocked from an I/O operation. How does this event propagate through the system to get the thread scheduled on a CPU?

A.The kernel directly schedules the user-level thread on a CPU.
B.The user-level scheduler gets an upcall from the kernel, and then it queues the thread for execution on an available kernel thread. ✅
C.The kernel creates a new process for the unblocked thread.
D.The thread automatically gets executed as soon as it is unblocked.
💡 Difficulty: hard | ✅ Correct: B

📖 Explanation: In the Many-to-Many model, the kernel manages the pool of kernel threads. When a kernel thread is blocked (e.g., for I/O), the kernel does not know about user threads. When the I/O completes, the kernel cannot wake the user thread directly. Instead, it uses a scheduler activation (upcall) to notify the user-level scheduler. The user-level scheduler then decides which ready user thread to assign to the now-available kernel thread. Option A is wrong because the kernel doesn't schedule user threads directly. Option C is incorrect. Option D is false as scheduling is not instantaneous.

Q25. A developer is choosing a threading model for a high-performance web server that handles thousands of concurrent client connections with minimal CPU usage per connection. The server is running on a system with multiple cores. Which model is most suitable?

A.Many-to-One, for the lowest possible overhead.
B.One-to-One, for maximum parallelism.
C.Many-to-Many, to balance low overhead and resource utilization with some parallelism. ✅
D.Two-Level, but only if all threads are bound.
💡 Difficulty: easy | ✅ Correct: C

📖 Explanation: A high-performance web server needs to handle many connections. A Many-to-One model is too limited as it cannot use multiple cores. A pure One-to-One model is problematic because creating a kernel thread for each of thousands of connections would exhaust system resources. The Many-to-Many model is the best balance: it allows for a pool of kernel threads (say, equal to the number of cores) to achieve parallelism for active connections, while using low-overhead user-level threads to manage the potentially large number of idle or waiting connections. Option D is overkill and binding all would be inefficient.

Q26. Which of the following is a significant disadvantage of the Two-Level model compared to the Many-to-Many model?

A.It cannot provide any parallelism.
B.It has increased complexity in the scheduler to manage both bound and unbound threads. ✅
C.It requires a 1:1 mapping for all threads, increasing overhead.
D.It is not supported by any modern operating system.
💡 Difficulty: hard | ✅ Correct: B

📖 Explanation: The Two-Level model adds the feature of bound threads to the Many-to-Many model. This means the user-level scheduler must now manage two categories of threads: bound (which have a dedicated kernel thread) and unbound (which are multiplexed). The scheduler must coordinate with the kernel to ensure bound threads get their allocated resources without starving unbound threads, and to handle upcalls correctly. This significantly complicates the scheduler logic. Option A is false because it provides parallelism via the unbound threads on kernel threads. Option C describes the One-to-One model. Option D is false.

Q27. A process using the Many-to-One model is running on a single-core system. Which of the following scenarios would cause the entire process to halt, even though the CPU is idle?

A.One thread is performing a CPU-bound calculation.
B.The process is waiting for a signal from another process.
C.One thread calls a blocking I/O function. ✅
D.The user-level scheduler is performing a context switch.
💡 Difficulty: easy | ✅ Correct: C

📖 Explanation: In the Many-to-One model, the entire process is managed by a single kernel thread. If that thread makes a blocking system call, such as for I/O (e.g., read from a file), the kernel will block the kernel thread, which represents the entire process. As a result, no other user-level thread in that process can run, even though the CPU might be idle. Option A does not block; it uses CPU time. Option B is a process-level wait, but a blocking I/O call is the classic example that halts all threads in this model. Option D is a user-space operation and does not block the kernel thread.

Q28. What is the fundamental problem that all threading models attempt to solve, which arises from the difference between user-space and kernel-space entities?

A.How to synchronize threads using mutexes.
B.How to map user-level thread abstractions onto kernel-level scheduling entities to manage execution on CPUs. ✅
C.How to allocate memory to threads efficiently.
D.How to prevent threads from corrupting each other's data.
💡 Difficulty: hard | ✅ Correct: B

📖 Explanation: The central challenge in threading models is the mapping between the threads seen by the programmer (user-level threads) and the threads or processes that are actually scheduled by the operating system kernel (kernel-level threads or processes). The models (One-to-One, Many-to-One, Many-to-Many, Two-Level) are defined by this mapping and its impact on performance, concurrency, and parallelism. Option A is a separate synchronization problem. Option C and D are also important but are not the 'fundamental' problem these models were designed to solve.

Q29. In the context of the Many-to-Many model, what does the term 'virtual processor' refer to?

A.A physical CPU core.
B.A data structure representing a kernel thread. ✅
C.A hardware register used for threading.
D.A non-existent thread.
💡 Difficulty: hard | ✅ Correct: B

📖 Explanation: In the Many-to-Many model, a kernel thread acts as a 'virtual processor' from the perspective of the user-level threads scheduler. The user-level scheduler can map a user thread to a virtual processor (kernel thread) to run. When a user thread blocks, the user-level scheduler can map another user thread to this same virtual processor. This abstraction allows the user-level scheduler to control which user thread runs on which kernel-level scheduling entity. Options A, C, and D do not accurately describe this specific terminology within this context.

Q30. Assume you have a system with 2 physical cores and a multi-threaded application. The application uses the Many-to-Many model with 10 user-level threads and 2 kernel threads. If a user-level thread calls a blocking I/O operation, what is the maximum number of other user-level threads that can still execute in parallel on the CPU?

A.0
B.1 ✅
C.9
D.10
💡 Difficulty: easy | ✅ Correct: B

📖 Explanation: When one user-level thread makes a blocking I/O call, the kernel thread it is running on is blocked. With only 2 kernel threads total, 1 kernel thread is blocked. This leaves only 1 other kernel thread available to execute. This remaining kernel thread can be used by the user-level scheduler to execute one of the other 9 user-level threads. Therefore, the maximum number of threads that can run in parallel (on the 2 physical cores) is 1 (the thread on the unblocked kernel thread). The blocked kernel thread cannot execute any instructions. Options C and D are impossible because there is only one unblocked kernel thread. Option A is incorrect because one thread can run on the other core.
