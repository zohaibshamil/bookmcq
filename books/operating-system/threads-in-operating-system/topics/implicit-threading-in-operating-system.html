What is Implicit Threading in operating system?

Definition:
Implicit threading shifts thread creation and management responsibility from programmers to compilers and runtime libraries, automatically parallelizing code without explicit thread directives. This approach simplifies concurrent programming by hiding threading complexity, allowing developers to focus on algorithm logic while the system identifies parallelization opportunities and manages thread lifecycle automatically.

Working:
Compilers analyze code for parallelizable loops and sections, inserting thread creation and synchronization automatically. Runtime libraries manage thread pools, load balancing, and work distribution. Techniques include loop-level parallelism where iterations execute concurrently, task-based parallelism decomposing work into dependent tasks, and automatic vectorization converting sequential operations into parallel SIMD instructions.

Example:
OpenMP directive: `#pragma omp parallel for` before a loop automatically distributes iterations across threads. Compiler generates code creating threads, partitioning loop iterations, and joining threads afterward. Solution: Programmer writes sequential-looking code while compiler handles parallelization details transparently.

Reason:
Implicit threading reduces programming errors from manual thread management, enables automatic optimization based on target hardware, simplifies code maintenance by separating algorithm from parallelization strategy, and allows non-expert programmers to benefit from multicore processors without deep concurrency knowledge.

Common MisConceptions:
Students believe implicit threading always produces optimal parallelization, but compiler heuristics may miss opportunities or create inefficient thread distributions. Another misconception is that no programmer involvement is needed, when hints and pragmas often guide compiler decisions for better results.

Exam Preparation Tips: How to prepare this topic
Study OpenMP and Intel TBB examples, understand compiler parallelization limitations, practice identifying code suitable for implicit threading, compare with explicit threading approaches, and analyze performance differences between compiler-generated and hand-written parallel code.

Key Terms:

  • Compiler Directive - hint guiding automatic parallelization.
  • Auto-parallelization - compiler automatically creating parallel code.
  • Runtime Library - library managing threads at execution time.
  • Loop Parallelism - distributing loop iterations across threads.

📝 All Implicit Threading in operating system MCQs

Q1. Which statement best describes the central idea of implicit threading?

A.Programmers manually create and manage every worker thread
B.The system or programming framework manages thread creation and execution for parallel tasks ✅
C.Every application must execute on exactly one thread
D.The operating system eliminates synchronization requirements
💡 Difficulty: easy | ✅ Correct: B

📖 Explanation: Implicit threading shifts much of the responsibility for managing threads from application programmers to compilers, runtime systems, or libraries. Developers express parallel work, while the framework determines how that work is executed using available processing resources.

Q2. A developer submits 500 independent image-processing tasks without specifying which worker should execute each task. Which mechanism most directly supports this design?

A.A thread pool managed by a runtime system ✅
B.A separate manually created operating-system process for every pixel
C.A single permanently blocked thread
D.A mechanism that disables processor scheduling
💡 Difficulty: easy | ✅ Correct: A

📖 Explanation: A thread pool maintains reusable worker threads that execute submitted tasks. The developer does not need to create and assign a new thread for every operation, reducing management overhead while allowing the runtime to distribute work among available workers.

Q3. Why can implicit threading reduce the difficulty of writing parallel applications?

A.It guarantees that all tasks execute simultaneously
B.It removes the need to identify independent work
C.It allows a framework to manage worker threads and some scheduling decisions ✅
D.It guarantees that race conditions cannot occur
💡 Difficulty: easy | ✅ Correct: C

📖 Explanation: Implicit threading hides many low-level thread-management details behind higher-level abstractions. Programmers can focus on defining tasks and dependencies, although they must still identify shared-state hazards and ensure that concurrent operations produce correct results.

Q4. Which statement about a thread pool is correct?

A.Its worker threads must be destroyed after every task
B.It reuses worker threads to execute multiple submitted tasks ✅
C.It guarantees that every task receives a separate processor core
D.It prevents tasks from waiting in queues
💡 Difficulty: easy | ✅ Correct: B

📖 Explanation: A thread pool typically keeps a collection of worker threads available for repeated use. Tasks can wait in a queue until a worker becomes available, avoiding the repeated creation and destruction costs associated with short-lived threads.

Q5. What does a fork-join parallel execution model generally do?

A.It permanently divides a program into unrelated processes
B.It prevents the main computation from waiting for results
C.It executes all subtasks in a fixed order without concurrency
D.It divides work into parallel branches and later synchronizes their completion ✅
💡 Difficulty: easy | ✅ Correct: D

📖 Explanation: Fork-join execution divides a computation into concurrent subtasks at a fork point and synchronizes them at a join point. This model is useful when independent portions of a computation can run concurrently before their results are combined.

Q6. What is the primary purpose of a task queue in an implicit-threading runtime?

A.To hold work until an available worker can execute it ✅
B.To guarantee that tasks execute in the order they finish
C.To assign every task permanently to one processor
D.To eliminate all dependencies between tasks
💡 Difficulty: easy | ✅ Correct: A

📖 Explanation: A task queue stores pending units of work until workers can execute them. Depending on the runtime, scheduling policies may prioritize certain tasks or distribute work across workers, but queueing alone does not guarantee completion order.

Q7. A team processes a large dataset by dividing it into independent chunks. Why might this be easier with task-based parallelism than manually managed threads?

A.Each chunk automatically receives exclusive access to all memory
B.Every chunk is guaranteed to run simultaneously
C.The runtime can schedule chunks without requiring the programmer to assign individual worker threads ✅
D.Task-based parallelism guarantees zero scheduling overhead
💡 Difficulty: medium | ✅ Correct: C

📖 Explanation: Task-based parallelism lets the programmer express independent units of work while the runtime schedules them onto available workers. This separates the description of useful computation from the lower-level decisions about worker assignment and execution.

Q8. A program creates thousands of tiny tasks, but each task performs only a few arithmetic operations. What is the most likely performance problem?

A.The processor automatically converts all tasks into one instruction
B.Task creation, scheduling, and coordination overhead may exceed the useful computation ✅
C.The number of tasks guarantees linear speedup
D.Implicit threading prevents the processor from using caches
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: Very small tasks may require less time to compute than the runtime needs to schedule and coordinate them. Grouping several operations into larger tasks can reduce overhead and improve performance, although excessively large tasks may reduce available parallelism.

Q9. An application uses a framework that assigns tasks to a limited collection of reusable workers. The number of submitted tasks rises from 20 to 2,000. Which outcome is most reasonable?

A.The framework must create exactly 2,000 workers
B.All tasks will finish in the order they were submitted
C.The operating system will stop scheduling other applications
D.More tasks may wait in queues while the worker count remains limited ✅
💡 Difficulty: medium | ✅ Correct: D

📖 Explanation: A bounded worker pool can accept more tasks than it has workers. Excess tasks wait until workers become available, so a larger task backlog does not necessarily cause a proportional increase in thread count or simultaneous execution.

Q10. A parallel program divides work among eight workers, but one task takes ten times longer than the others. What is the most likely effect on completion time?

A.The long-running task may become a bottleneck that delays overall completion ✅
B.The short tasks automatically make the long task finish sooner
C.The join operation ignores the slow task
D.The runtime must terminate seven workers permanently
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: Parallel completion depends on the workload distribution as well as the number of workers. When one task takes much longer than the others, workers that finish early may become idle while the remaining task determines the completion time.

Q11. A developer uses a parallel framework but updates a shared counter from multiple tasks without synchronization. Which conclusion is correct?

A.Implicit threading automatically makes every shared variable atomic
B.The counter cannot be corrupted because tasks are managed by a runtime
C.A race condition can still occur despite automatic thread management ✅
D.The runtime necessarily executes all counter updates sequentially
💡 Difficulty: medium | ✅ Correct: C

📖 Explanation: Implicit threading manages execution but does not automatically make arbitrary shared-memory operations safe. Concurrent read-modify-write operations can interleave and lose updates unless the program uses suitable synchronization, atomic operations, or a safe reduction mechanism.

Q12. Which distinction between a task and a worker thread is most accurate in a task-based runtime?

A.A task must always have its own permanent operating-system thread
B.A worker thread represents only a data structure and never executes instructions
C.A task and a worker thread are always identical concepts
D.A task represents work to perform, while a worker thread is an execution resource that can perform multiple tasks ✅
💡 Difficulty: medium | ✅ Correct: D

📖 Explanation: A task describes a unit of computation, whereas a worker thread provides an execution context for running that computation. A runtime can execute many tasks over time using fewer reusable workers than there are tasks.

Q13. An application has four available worker threads and 100 independent tasks. If the tasks take similar amounts of time and scheduling overhead is small, which expectation is most reasonable?

A.Several tasks can execute concurrently, while the remaining tasks wait for workers ✅
B.All 100 tasks must execute at exactly the same instant
C.Only four tasks can ever be completed by the application
D.The runtime must create 96 additional processors
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: Four workers can execute up to four tasks concurrently when each worker runs one task at a time. The remaining tasks can wait in queues and execute as workers become available, allowing a large workload to be handled with a bounded number of threads.

Q14. Which condition most strongly supports useful parallel execution through an implicit-threading framework?

A.Every task modifies the same variable without synchronization
B.All tasks wait for the same external event before doing any work
C.Many tasks can make progress independently with limited coordination ✅
D.Every task requires the previous task to finish first
💡 Difficulty: medium | ✅ Correct: C

📖 Explanation: Parallel execution is most beneficial when tasks contain substantial independent work. Independence reduces synchronization and waiting, allowing multiple workers to make progress concurrently instead of spending much of their time coordinating access to shared resources.

Q15. A developer uses OpenMP to parallelize a loop whose iterations are independent. What does the OpenMP parallel-loop construct primarily communicate?

A.That the loop must run on a single worker
B.That eligible loop iterations can be distributed among a team of threads ✅
C.That every iteration must create a new process
D.That memory accesses no longer require correctness analysis
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: An OpenMP parallel-loop construct expresses that iterations may be executed by a team of threads according to the construct's scheduling rules. The programmer must still verify iteration independence and handle shared variables correctly to avoid data races.

Q16. A developer submits background tasks to Grand Central Dispatch without creating a dedicated thread for each task. What is the framework's principal role?

A.It converts every task into a separate process
B.It guarantees that tasks execute in submission order on every queue
C.It disables the operating system's thread scheduler
D.It manages queued work and arranges its execution using system-managed resources ✅
💡 Difficulty: medium | ✅ Correct: D

📖 Explanation: Grand Central Dispatch provides task queues and system-managed execution resources so developers can express work without manually managing every thread. Actual execution and ordering depend on queue semantics, dependencies, and available system resources.

Q17. A parallel application becomes slower when its worker count increases from 8 to 32. Which explanation is most plausible?

A.Additional workers may increase contention, scheduling costs, or memory-bandwidth pressure ✅
B.More workers always reduce the total work performed
C.A runtime cannot execute tasks when more than eight workers exist
D.Increasing workers necessarily converts every parallel task into a sequential task
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: Adding workers does not guarantee better performance. Contention for shared data, cache interference, scheduling overhead, and memory-bandwidth limits can outweigh the benefit of additional concurrency, especially when the workload is already near a hardware bottleneck.

Q18. A developer divides a computation into tasks but allows a task to read a result before the task producing that result has completed. What is the most appropriate correction?

A.Increase the number of workers until the result becomes available
B.Repeat the consumer task indefinitely
C.Represent the dependency and ensure the producer completes before the consumer reads the result ✅
D.Remove all synchronization from the application
💡 Difficulty: medium | ✅ Correct: C

📖 Explanation: Parallel tasks must respect data dependencies. A consumer that reads a result before its producer completes may observe missing or stale data. Expressing the dependency or using suitable synchronization ensures that the consumer proceeds only when the required result is ready.

Q19. A programmer claims that a framework using implicit threading guarantees deterministic output for every parallel algorithm. Which assessment is best?

A.Correct, because all runtime schedulers follow one universal task order
B.Incorrect, because execution order can vary and unsynchronized conflicting operations may produce different results ✅
C.Correct, because worker reuse eliminates all race conditions
D.Incorrect only when an application uses more than one processor
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: Implicit threading does not guarantee deterministic task ordering. Scheduling can vary across executions, and conflicting unsynchronized operations may produce nondeterministic results. Deterministic behavior requires suitable algorithm design, synchronization, and control over operations whose order affects results.

Q20. A runtime uses work stealing, and one worker finishes its local tasks while another worker has a large backlog. What is the purpose of work stealing?

A.To force all workers to execute identical tasks
B.To prevent tasks from moving between workers
C.To increase the number of unfinished tasks deliberately
D.To let an idle worker take available work from another worker's queue ✅
💡 Difficulty: medium | ✅ Correct: D

📖 Explanation: Work stealing can improve load balance by allowing an idle worker to obtain tasks from a busy worker's queue. It is particularly useful when task execution times vary, although stealing and coordination introduce some overhead.

Q21. A program launches a large number of asynchronous tasks, each of which waits synchronously for another task scheduled on the same fully occupied fixed-size pool. Why can this design deadlock?

A.The runtime always expands its pool without limit
B.Waiting automatically completes the awaited task
C.All workers may become blocked while the tasks needed to release them remain queued ✅
D.Asynchronous tasks cannot communicate with one another
💡 Difficulty: hard | ✅ Correct: C

📖 Explanation: If every worker blocks while waiting for another task that requires a worker from the same saturated pool, the awaited tasks cannot begin. This resource dependency can cause deadlock unless the design uses nonblocking coordination, suitable scheduling, or adequate execution resources.

Q22. A team compares two implementations. Implementation P uses many tiny tasks, while implementation Q combines the same work into moderately sized tasks. Q finishes sooner with identical results. Which explanation best fits the observation?

A.Q must have performed less mathematically necessary work because its tasks are larger
B.Q likely reduced per-task scheduling and coordination overhead ✅
C.P necessarily used fewer CPU instructions for every task
D.The runtime cannot schedule tiny tasks in parallel
💡 Difficulty: hard | ✅ Correct: B

📖 Explanation: Each task can carry fixed scheduling and coordination costs. If tasks are too small, these costs may dominate useful computation. Combining operations into moderately sized tasks can improve efficiency while retaining enough independent work for the available workers.

Q23. A developer parallelizes a loop in which iteration iii writes an array element later read by iteration i+1i+1i+1. What must be considered before parallelizing the loop?

A.Whether the machine has enough memory to store the loop variable only
B.Whether the runtime will assign the first iteration to worker zero
C.Whether all iterations have identical source-code length
D.Whether dependencies between iterations require ordering or a redesigned algorithm ✅
💡 Difficulty: hard | ✅ Correct: D

📖 Explanation: A loop with a write-to-read dependency between iterations may produce incorrect results if those iterations execute out of order. The programmer must preserve the required ordering, redesign the computation, or use a synchronization strategy that respects the dependency.

Q24. A developer parallelizes a computation with four independent tasks, but each task must wait for a common external service before continuing. Which design concern is most important?

A.Worker threads may spend substantial time blocked, so concurrency and resource use should be managed carefully ✅
B.The runtime automatically removes the external service dependency
C.All four tasks are guaranteed to finish simultaneously
D.Implicit threading prevents external I/O from blocking workers
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: Tasks waiting for an external service may occupy execution resources without doing useful computation, depending on the runtime and API. Nonblocking I/O, asynchronous continuations, or an appropriate pool configuration can improve resource utilization when many tasks spend time waiting.

Q25. A developer uses a reduction operation to calculate the total of independent numerical results. Why can a reduction be safer than having every task update one shared total?

A.A reduction guarantees the same floating-point result under every execution order
B.A reduction eliminates the need to calculate any partial results
C.The framework can combine partial results using a defined reduction mechanism instead of unsynchronized concurrent updates ✅
D.A reduction requires each task to run on a separate processor
💡 Difficulty: medium | ✅ Correct: C

📖 Explanation: A reduction lets workers compute partial results and combines them through a supported mechanism. This avoids many races associated with simultaneous updates to one shared accumulator, although floating-point addition may still produce slightly different rounding results under different combination orders.

Q26. A programmer says, 'Because my runtime uses a thread pool, I can safely launch a task that waits for another task in the same pool without considering deadlock.' What is the flaw in this reasoning?

A.Thread pools never execute waiting tasks
B.A pool can become saturated by blocked workers, preventing queued dependent tasks from running ✅
C.Every waiting task automatically receives a new processor
D.Deadlock is possible only when tasks use separate operating-system processes
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: A thread pool limits the execution resources available to submitted tasks. If workers block while waiting for tasks that cannot start without those same workers, the application can deadlock. The developer must consider dependencies and blocking behavior even when the runtime manages threads.

Q27. An application uses a task runtime to process independent files. Each task writes to a separate output file, but all tasks append to one shared log without coordination. What is the most accurate assessment?

A.Separate output files do not eliminate possible races in the shared log ✅
B.Independent file processing guarantees that all log writes are atomic
C.The runtime will always serialize writes to every shared resource
D.The shared log cannot be affected by scheduling
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: Independence of the main file-processing tasks does not make their shared logging operation safe. Concurrent appends can interleave or produce ordering problems depending on the logging mechanism. A thread-safe logger, synchronization, or a dedicated logging task can address this risk.

Q28. An OpenMP loop uses a shared accumulator and ordinary addition from multiple threads. The final total changes between executions. Which explanation is most likely?

A.OpenMP automatically converts every shared variable into a private variable
B.The loop iterations must be executing sequentially
C.Concurrent updates may form a data race, so a valid reduction or synchronization mechanism is needed ✅
D.The processor is changing the mathematical definition of addition
💡 Difficulty: hard | ✅ Correct: C

📖 Explanation: When several threads read and update a shared accumulator without appropriate synchronization, updates can overlap and be lost. An OpenMP reduction or another correct synchronization technique allows contributions to be combined safely, rather than relying on unsynchronized shared updates.

Q29. A framework allows a developer to specify that task B depends on task A. What is the main benefit of expressing this dependency explicitly?

A.It guarantees that both tasks execute on the same worker
B.It allows the runtime to respect correctness constraints while scheduling otherwise independent work flexibly ✅
C.It prevents task A from ever running concurrently with unrelated tasks
D.It eliminates all waiting throughout the application
💡 Difficulty: hard | ✅ Correct: B

📖 Explanation: Explicit dependency information tells the runtime which tasks must wait for earlier results. The runtime can preserve correctness while scheduling independent tasks when resources are available, improving flexibility without forcing the entire computation to run sequentially.

Q30. A computational pipeline contains three stages: stage A produces data, stage B transforms it, and stage C summarizes it. Each stage depends on the preceding stage's output, but many records can be processed independently. Which approach is most appropriate?

A.Force all records through one global sequential execution with no overlap
B.Let every stage process arbitrary data before its input exists
C.Create a separate operating-system process for every individual record regardless of cost
D.Express stage dependencies while allowing independent records or chunks to proceed concurrently ✅
💡 Difficulty: hard | ✅ Correct: D

📖 Explanation: The pipeline has dependencies between stages for each record, but separate records may be processed independently. A task runtime can preserve producer-consumer relationships while overlapping work across records, balancing correctness with useful concurrency.

Q31. A team finds that a parallel program achieves 3.5 times speedup on four workers, but only 3.6 times speedup on eight workers. Which decision is best justified by these measurements alone?

A.Always use eight workers because more workers must be faster
B.Conclude that the parallel algorithm contains no sequential work
C.Investigate overhead and resource limits before deciding whether eight workers are worth using ✅
D.Remove all task dependencies to force a larger speedup
💡 Difficulty: hard | ✅ Correct: C

📖 Explanation: The increase from 3.5 to 3.6 is small compared with the doubling of worker count. Additional workers may offer little benefit, but a decision should also consider resource costs, workload variability, latency requirements, and whether further tuning could improve scaling.

Q32. A developer creates one task per element in a dataset containing ten million elements. The runtime spends substantial time scheduling tasks. Which redesign is most likely to help?

A.Create two tasks per element to increase concurrency
B.Partition the dataset into appropriately sized chunks and process multiple elements per task ✅
C.Force every task to create a new worker thread
D.Insert a synchronization barrier after every element
💡 Difficulty: hard | ✅ Correct: B

📖 Explanation: Creating a task for every element can overwhelm a runtime with scheduling and bookkeeping overhead. Chunking multiple elements into each task reduces the number of scheduled units while retaining parallelism, provided the chunks are balanced and large enough to amortize their management costs.

Q33. A developer uses implicit threading for a workload that contains a long sequential phase followed by a short parallel phase. Why might adding many workers provide little overall improvement?

A.The runtime is required to slow down sequential code whenever workers exist
B.Parallel tasks cannot execute after a sequential phase
C.Every additional worker increases the number of sequential instructions
D.The sequential portion limits the maximum speedup achievable for the entire program ✅
💡 Difficulty: hard | ✅ Correct: D

📖 Explanation: Only the parallel portion can benefit directly from additional workers. If the sequential phase accounts for a substantial share of total execution time, it limits overall speedup, even when the parallel phase becomes much faster. This is a consequence of Amdahl's law.

Q34. A parallel task computes a local result and returns it to a parent task, which combines the results after all children finish. Which correctness property makes this design preferable to unsynchronized shared updates?

A.Each task can compute independently, and the parent combines completed results at a defined synchronization point ✅
B.The parent can combine results before any child begins
C.Local variables are automatically shared across all workers
D.Returning results removes every possible failure from the runtime
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: Local computation limits conflicting access to shared state, while a synchronization point ensures that child results are available before combination. This design reduces the risk of data races and makes dependencies clearer, although the combination operation itself must still be correct.

Q35. A developer selects implicit threading because the application must run efficiently on systems with different core counts. Which design choice best supports portability?

A.Hard-code one worker for every task and every machine
B.Assume that each task always receives a dedicated physical core
C.Express independent tasks and let the runtime adapt execution to available resources ✅
D.Use processor-specific thread identifiers to assign every task permanently
💡 Difficulty: hard | ✅ Correct: C

📖 Explanation: Describing parallel work independently of a fixed worker assignment helps a runtime adapt to machines with different processor counts and resource limits. Portability still depends on appropriate task granularity, synchronization, runtime support, and avoiding assumptions about execution order.

Q36. A team uses fork-join execution to sort a large collection by recursively sorting two halves in parallel and merging the results. Which issue must be addressed to preserve correctness?

A.Both halves must always use the same worker thread

💡 Difficulty: hard | ✅ Correct: D

📖 Explanation: Parallel recursive sorting can process independent halves concurrently, but merging requires both sorted results to be ready. Correct synchronization at the join point and safe handling of memory ensure that parallel execution preserves the sorting algorithm's required dependencies.

Q37. A runtime can schedule independent tasks dynamically, but a programmer manually inserts a global barrier after every small task. What is the likely consequence?

A.Unnecessary barriers can force workers to wait and reduce the benefit of dynamic scheduling ✅
B.The barriers guarantee perfect load balancing without overhead
C.The runtime will automatically ignore all barriers
D.The program becomes race-free regardless of its shared-memory operations
💡 Difficulty: hard | ✅ Correct: A

📖 Explanation: A barrier prevents participating workers from proceeding until the required group reaches the synchronization point. Frequent barriers can leave fast workers idle while slower tasks finish, reducing available concurrency. Barriers should be used where the algorithm genuinely requires coordinated progress.

Q38. A runtime has eight workers, but only two tasks are ready because the remaining tasks depend on results that have not yet been produced. What is the best conclusion?

A.The runtime must create six additional operating-system processes
B.The eight workers must execute the two tasks eight times each

D.The application can guarantee eight-way speedup by increasing the queue size
💡 Difficulty: hard | ✅ Correct: C

📖 Explanation: Worker capacity does not create independent work. If only two tasks are ready, at most two such tasks can execute concurrently under ordinary one-task-per-worker execution. Increasing the worker count or queue size cannot remove genuine data dependencies.

Q39. A developer wants to process independent requests using a bounded worker pool. Each request can take a variable amount of time, and the system must remain responsive under heavy load. Which strategy is most appropriate?

A.Create an unlimited number of permanent workers as soon as requests arrive

📖 Explanation: A bounded pool limits resource consumption, while queueing and backpressure policies help manage bursts of incoming work. Monitoring latency and queue length reveals overload. An unlimited worker count can exhaust memory and scheduling resources, while a single worker may limit throughput unnecessarily.

Q40. A team reports that its parallel program is slower than the sequential version, even though its tasks are independent. Which investigation is the best first step?

📖 Explanation: Independent tasks can still perform poorly when overhead exceeds the benefit of parallelism. Profiling helps identify whether tasks are too small, synchronization is excessive, workers are contending for resources, or the computation is limited by memory or another shared resource.
