What is System Calls in Operating System Structures?

Definition:
System calls are programmed interfaces that allow user-level processes to request privileged OS services, acting as a controlled gateway where a call syscall(id,args) \text{syscall}(id, args) syscall(id,args) transitions execution from user mode to kernel mode.

Example:
When a C program calls fork() \text{fork()} fork(), the CPU switches to kernel mode, executes the process creation routine, and returns a new PID to the caller.

Reason:
System calls enforce security and stability by preventing user programs from directly manipulating hardware or kernel data structures.

All I/O, process management, and communication require system calls to request services from the kernel.

Q47. What is the role of the `module_init()` and `module_exit()` macros in a Linux kernel module?

📖 Explanation: module_init() and module_exit() are essential macros that register the module's entry and exit points. When the kernel loads a module using `insmod`, it calls the function specified by module_init. When it removes the module using `rmmod`, it calls the module_exit function. This provides a standardized way for modules to initialize and clean up.

Q48. In the memory block method of parameter passing, if the address passed to the kernel is invalid, what occurs?

This will likely lead to the kernel killing the offending process (segmentation fault) or crashing if the fault occurs in kernel context.

Q50. What happens if a kernel module's exit function (module_exit) is not called before the module is removed?

C.The system will crash immediately
D.The module will be removed anyway
💡 Difficulty: hard | ✅ Correct: B

📖 Explanation: When a module is removed using `rmmod`, the kernel invokes its exit function. If the exit function is not properly implemented or is missing, the kernel will not be able to clean up resources like allocated memory, locks, or file descriptors. This leads to a memory leak and potential resource exhaustion. The module's code is unloaded, but the resources it allocated remain.

Q51. How can a system call result in a context switch?

While not a process-to-process context switch, it still changes the CPU's context (mode, stack pointer, etc.). This is a fundamental cost of using system calls.

Q53. When traversing a kernel linked list with `list_for_each_entry_safe`, why is the 'safe' version preferred when deleting nodes?

Q62. What is the risk of using `kmalloc()` without a corresponding `kfree()` in a kernel module?
