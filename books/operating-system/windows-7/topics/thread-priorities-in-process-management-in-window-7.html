What is Thread priorities in Process management in Window 7?

Definition:
Thread priorities range from 0-31 with base priority inherited from process class and dynamic adjustments where priority inheritance prevents priority inversion.

Example:
Real-time audio thread runs at priority 15 while background indexing operates at priority 4 to avoid audible glitches.

Reason:
Fine-grained priority control enables QoS guarantees for latency-sensitive applications while preventing starvation of lower-priority tasks through aging and boosting mechanisms.

📝 All Thread priorities in Process management in Window 7 MCQs

Q1. What does APC stand for in the Windows kernel?

A.Asynchronous Procedure Call ✅
B.Advanced Process Control
C.Application Process Component
D.Asynchronous Power Control
💡 Difficulty: easy | ✅ Correct: A

📖 Explanation: An APC is an Asynchronous Procedure Call, a mechanism that lets the system queue a routine to run in the context of a specific thread. Option A matches this definition. Options B, C, and D are unrelated terms; they describe unrelated concepts and thus are incorrect. Knowing the correct expansion helps identify the role of APCs in thread management and how they differ from other kernel objects.

Q2. Why are DPC routines executed at a priority higher than normal threads but lower than hardware interrupts?

A.Because DPCs must not preempt interrupt service routines but need to finish before regular threads resume ✅
B.Because DPCs are user‑mode code and must stay below kernel‑mode priorities
C.Because DPCs are only for I/O completion and therefore share the same priority as threads
D.Because DPCs run on a separate processor core dedicated to background tasks
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: DPCs run after the ISR finishes, so they need a priority above standard threads to ensure timely processing, yet they must stay below hardware interrupt levels to avoid delaying critical ISRs. Option A captures this balance. Options B, C, and D mischaracterize DPC priority relative to user‑mode code, thread priority, or core allocation, making them inaccurate.

Q3. A driver queues a DPC to handle a timer expiration while many threads are ready to run. What is the most likely effect on thread scheduling?

A.The DPC will run before the threads, temporarily delaying their execution ✅
B.The threads will preempt the DPC because threads have higher priority
C.Both DPC and threads will share the CPU time equally
D.The DPC will be ignored until all threads finish
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: When a DPC is queued, it is given a priority above normal threads, so the scheduler will run the DPC first, postponing thread execution until the DPC completes. This ensures timely handling of deferred work. Option A describes this behavior. Option B is wrong because DPCs outrank regular threads; Option C is incorrect because the scheduler does not split time equally; Option D is false since DPCs are not ignored.

Q4. In which condition can a user‑mode APC be delivered to a thread?

A.Only when the thread is in a non‑alertable wait state
B.Only when the thread is executing kernel code
C.Only when the thread is waiting in the kernel and marked alertable ✅
D.Only when the thread has highest priority in the system
💡 Difficulty: hard | ✅ Correct: C

📖 Explanation: User‑mode APCs are delivered only when a thread is waiting in the kernel and has been marked as alertable, allowing the system to invoke the APC safely. Option C states this precisely. Option A is incorrect because a non‑alertable wait blocks APC delivery. Option B is wrong because APCs run in user mode, not during kernel execution. Option D misstates priority requirements, which are unrelated to APC delivery.

Q5. If a system experiences a surge of queued DPCs, which outcome is most likely regarding thread quantum and overall responsiveness?

A.Thread quantum may be shortened, causing more frequent context switches and reduced responsiveness ✅
B.Thread quantum will increase, giving threads more CPU time and improving responsiveness
C.DPCs will be executed on separate cores, leaving thread scheduling unaffected
D.The system will automatically lower thread priorities to accommodate DPC processing
💡 Difficulty: hard | ✅ Correct: A

📖 Explanation: A large number of DPCs can consume CPU time, prompting the scheduler to shorten thread quanta to maintain system balance, which leads to more context switches and can degrade responsiveness. Option A reflects this effect. Option B is opposite of typical behavior; Option C is inaccurate because DPCs run on the same core unless multi‑core scheduling is explicitly used; Option D misrepresents priority adjustments, which are not automatically made for DPC load.

Q6. A developer wants to ensure that an APC delivering I/O completion runs promptly without being delayed by lower‑priority threads. Which action should they take?

A.Raise the target thread’s base priority above normal threads
B.Lower the system’s DPC priority so APCs run first
C.Mark the thread as alertable and queue the APC to that thread ✅
D.Disable all other APCs while the I/O completes
💡 Difficulty: medium | ✅ Correct: C

📖 Explanation: To guarantee timely APC execution, the thread must be in an alertable wait state, allowing the kernel to deliver the APC as soon as possible. Option C correctly describes this requirement. Raising the thread’s priority (Option A) does not affect APC delivery because APCs are independent of thread priority. Lowering DPC priority (Option B) does not influence APC scheduling. Disabling other APCs (Option D) is unnecessary and could interfere with system functionality.
