What is Access to kernel objects in Window 7?

Kernel object access requires valid handles obtained through creation/open APIs, validated by object manager checking caller token against object security descriptor, with handle tables per-process preventing direct pointer manipulation.

Q1. A high‑rate network card generates an interrupt, the ISR queues a DPC to finish packet processing. Which statement correctly describes the priority relationship that guarantees the DPC will not pre‑empt other device ISRs but will still run before normal threads?

A. DPC runs only after all ISRs complete, regardless of priority
B. DPC executes at a priority lower than any device ISR but higher than normal thread priority ✅
C. DPC runs at the same priority as APCs
D. DPC can be preempted by other DPCs of equal priority

💡 Difficulty: hard | ✅ Correct: B

📖 Explanation:

The DPC’s priority is deliberately set between the highest interrupt request level (IRQL) used by device ISRs and the IRQL for regular thread execution. This ensures that while the ISR finishes first, the DPC can run without being delayed by normal thread scheduling, preserving system responsiveness. Option B captures this design; A ignores the need for a middle priority, C misstates the relationship with APCs, and D suggests a pre‑emptive rule that does not exist.

Q2. When a driver needs to perform a lengthy file‑system cleanup after an I/O completion, it can queue the work to the system’s worker‑thread pool instead of using a DPC. Which advantage best explains why this approach is preferred?

A. Worker threads run at a higher IRQL, preventing context switches
B. Worker threads can block without affecting ISR latency ✅
C. Worker threads execute in user mode only
D. Worker threads guarantee immediate execution

💡 Difficulty: medium | ✅ Correct: B

📖 Explanation:

Worker threads operate at PASSIVE_LEVEL, allowing them to block, wait on synchronization objects, or perform page‑faultable operations without increasing interrupt latency. This contrasts with DPCs, which must execute quickly and cannot block. Option B correctly highlights the latency benefit; A is false because higher IRQL would worsen latency, C is inaccurate as worker threads may run in kernel mode, and D is wrong because scheduling is still subject to normal thread policies.

Q3. A thread is put into an alertable wait state and an APC is queued to it. What is the most likely outcome once the wait condition is satisfied?

A. The APC will execute before the thread returns to user mode ✅
B. The APC will be ignored and remain pending
C. The APC will execute only after the thread exits kernel mode
D. The APC will cause the thread to terminate immediately

💡 Difficulty: easy | ✅ Correct: A

📖 Explanation:

When a thread is in an alertable wait, the kernel checks for queued APCs each time the wait is satisfied. If an APC is present, it is delivered and runs in the context of that thread before the thread resumes normal execution. Therefore, option A is correct. Option B contradicts the alertable behavior, C misrepresents the timing, and D confuses APC delivery with termination semantics.

Q4. Why does the Windows dispatcher assign DPCs a priority that is lower than device‑interrupt IRQLs but higher than normal thread IRQLs?

A. To ensure DPCs can be pre‑empted by any thread
B. To allow DPCs to run concurrently with ISRs
C. To guarantee that time‑critical interrupt handling finishes first, while still enabling deferred work to run before regular scheduling ✅
D. To keep DPCs isolated from both ISRs and threads

💡 Difficulty: medium | ✅ Correct: C

📖 Explanation:

The dispatcher’s priority scheme is designed so that the most urgent work—the ISR—completes before any deferred processing begins, yet the deferred work still runs before ordinary thread scheduling to avoid unnecessary delays. Option C accurately reflects this intent. Option A is wrong because DPCs are not pre‑empted by threads, B suggests concurrency that does not occur, and D misstates the isolation purpose.

Q5. An operating system needs to terminate a specific thread from user mode. Which mechanism involving APCs makes this possible?

A. Queueing a kernel‑mode APC that calls the thread’s exit routine ✅
B. Using a user‑mode APC that directly frees the thread’s stack
C. Scheduling a DPC that forces the thread to crash
D. Posting an alertable I/O request that the thread must handle

💡 Difficulty: hard | ✅ Correct: A

📖 Explanation:

A kernel‑mode APC can be queued to the target thread; when the thread becomes alertable, the APC runs and can invoke functions such as ZwTerminateThread, safely ending the thread’s execution. This is the standard method for remote termination. Option A describes this process. Option B is invalid because user‑mode APCs cannot directly free kernel resources, C misuses DPCs for termination, and D conflates I/O completion with thread control.
