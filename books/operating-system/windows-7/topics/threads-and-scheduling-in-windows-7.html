📝 Threads and scheduling in Windows 7

📖 From Operating System • 19. Windows 7 • 13 questions available

What is Threads and scheduling in Windows 7?

Threads are the basic unit of CPU scheduling in Windows 7, using a preemptive priority-based algorithm with \(32\) priority levels where higher-priority threads preempt lower ones and time slices \(Q\) prevent starvation.

Q1. What is the main function of the Hardware Abstraction Layer (HAL) in Windows?

A. Provides a graphical user interface
B. Hides hardware differences from upper layers ✅
C. Manages network protocols
D. Implements the file system

💡 Difficulty: easy | ✅ Correct: B

📖 Explanation:

The HAL's purpose is to present a uniform virtual hardware interface, so upper‑level components do not need to know the exact chipset details. Option B states this directly. Options A, C, and D describe unrelated functions: a GUI, networking, and file‑system management, which are handled by other subsystems. By abstracting hardware, the HAL allows a single driver version per CPU architecture, simplifying development and improving portability.

Q2. Why does Windows employ an object‑oriented design for its kernel components?

A. To encapsulate data and associated operations in reusable types ✅
B. To enable direct assembly‑level manipulation of hardware
C. To enforce strict procedural programming rules
D. To eliminate the need for synchronization primitives

💡 Difficulty: easy | ✅ Correct: A

📖 Explanation:

Object‑oriented design groups related data (attributes) and functions (methods) into objects, making kernel code modular and easier to maintain. Option A captures this benefit. Option B is inaccurate because the kernel still uses assembly only where necessary. Option C mischaracterizes the design philosophy, and option D ignores the essential role of synchronization in a concurrent kernel environment.

Q3. How does thread scheduling interact with interrupt handling in the Windows kernel?

A. Interrupts are processed only after all threads finish execution
B. The scheduler can preempt a running thread to service a high‑priority interrupt
C. Interrupt handling always occurs in user mode, independent of scheduling ✅
D. The kernel disables scheduling while an interrupt is pending

💡 Difficulty: medium | ✅ Correct: C

📖 Explanation:

The kernel separates interrupt handling from thread scheduling; interrupts are serviced in kernel mode, but they do not depend on thread completion. Option C correctly notes that interrupt handling occurs in kernel mode, not user mode, and is independent of the scheduler’s decisions. Option A is false because threads rarely run to completion before an interrupt. Option B misstates that the scheduler directly preempts threads for interrupts; the interrupt handler runs immediately. Option D is incorrect because the kernel does not disable scheduling entirely during an interrupt.

Q4. A program creates Thread X with priority 8 and Thread Y with priority 4. Both become ready at the same time on a dual‑core system. Which statement best describes their execution?

A. Both run simultaneously on separate cores regardless of priority
B. Thread Y will always run before Thread X
C. Thread X will preempt Thread Y if they share a core
D. Thread X may run on one core while Thread Y runs on another, but if they compete for the same core, the higher‑priority thread is favored ✅

💡 Difficulty: medium | ✅ Correct: D

📖 Explanation:

Windows can schedule ready threads on any idle core, so Thread X and Thread Y may execute concurrently on different CPUs. However, if they contend for the same core, the scheduler prefers the higher‑priority thread, which is Thread X. Option D captures both possibilities. Option A ignores priority, Option B reverses the priority order, and Option C suggests mandatory preemption even when separate cores are available, which is not required.

Q5. In a priority‑inversion scenario where a low‑priority thread holds a mutex needed by a high‑priority thread, which kernel mechanism can prevent the high‑priority thread from being blocked indefinitely?

A. Priority inheritance ✅
B. Round‑robin scheduling
C. Time slicing
D. Thread termination

💡 Difficulty: medium | ✅ Correct: A

📖 Explanation:

Priority inheritance temporarily raises the low‑priority thread’s priority to match that of the waiting high‑priority thread, allowing it to release the mutex promptly. Option A describes this mechanism. Round‑robin scheduling (B) and time slicing (C) manage CPU allocation but do not resolve inversion. Thread termination (D) would abort the low‑priority thread but is not a normal solution and would cause data loss.

Q6. Which responsibility of the Windows kernel involves low‑level processor synchronization?

A. Managing user‑mode memory allocation
B. Coordinating access to shared resources using spin locks and interlocked operations ✅
C. Handling graphical user interface rendering
D. Providing network socket APIs

💡 Difficulty: medium | ✅ Correct: B

📖 Explanation:

Low‑level synchronization ensures that multiple processors or cores can safely access shared data structures, typically using spin locks, interlocked functions, or other atomic primitives. Option B correctly identifies this role. Memory allocation (A) is a higher‑level service, GUI rendering (C) belongs to the user‑mode subsystem, and network sockets (D) are provided by the networking stack, not by low‑level synchronization.

Q7. When a user‑mode application calls a system service, what happens during the transition to kernel mode?

A. The CPU switches to a lower frequency and continues executing user code
B. The kernel validates the request, saves the user context, and executes the service routine ✅
C. The application thread is terminated and a new kernel thread is created
D. All registers are cleared and the system reboots

💡 Difficulty: medium | ✅ Correct: B

📖 Explanation:

During a system call, the CPU performs a mode switch, saving the user‑mode context, validating parameters, and then executing the requested kernel routine. Option B describes this process. Changing CPU frequency (A) is unrelated, terminating the thread (C) is not the normal flow, and clearing registers leading to a reboot (D) is incorrect.

Q8. Why is only one version of each device driver required for a given CPU architecture in Windows?

A. Because the HAL abstracts chipset‑specific details, allowing drivers to rely on a consistent interface ✅
B. Because Windows does not support multiple hardware configurations
C. Because drivers are written in a universal high‑level language that compiles to any chipset
D. Because the kernel automatically rewrites driver code at runtime

💡 Difficulty: hard | ✅ Correct: A

📖 Explanation:

The HAL presents a uniform virtual hardware interface, so drivers can interact with devices without needing to know the exact chipset implementation. Option A explains this abstraction. Option B is false; Windows supports many hardware variations. Option C misstates that drivers are universal without HAL support. Option D suggests dynamic code rewriting, which does not occur.

Q9. A system uses preemptive multitasking with a time slice of 20 ms. If a CPU‑bound thread runs for 45 ms, how many times will the scheduler preempt it?

A. Zero times, because the thread finishes before the slice expires
B. One time, after the first 20 ms slice
C. Two times, after each 20 ms slice, with the remaining 5 ms completing the third slice ✅
D. Three times, because the scheduler always preempts after each slice regardless of remaining work

💡 Difficulty: hard | ✅ Correct: C

📖 Explanation:

The scheduler allocates 20 ms slices. After the first 20 ms, it preempts the thread (first preemption). After the second 20 ms, it preempts again (second preemption). The remaining 5 ms runs to completion without another preemption. Thus, two preemptions occur, making option C correct. Option A ignores slicing, option B counts only one preemption, and option D incorrectly adds an extra preemption.

Q10. A developer binds a high‑priority thread to CPU 0 using thread affinity. What is a likely consequence if CPU 0 becomes overloaded with low‑priority work?

A. The high‑priority thread will automatically migrate to another CPU
B. The high‑priority thread may experience increased latency despite its priority ✅
C. All threads on CPU 0 will inherit the high priority
D. The system will terminate the low‑priority tasks to free CPU 0

💡 Difficulty: hard | ✅ Correct: B

📖 Explanation:

Thread affinity restricts a thread to a specific processor, so the high‑priority thread cannot move even if the CPU is busy with lower‑priority work, leading to possible latency. Option B captures this effect. Option A is false because affinity prevents migration. Option C misinterprets priority inheritance, and option D describes behavior that the scheduler does not perform.

Q11. When the Windows API function SetThreadPriority is used to raise a thread's priority, which outcome is most likely?

A. The thread will instantly preempt all other threads regardless of their priorities
B. The thread will be scheduled more frequently, but only when higher‑priority threads are not runnable ✅
C. The thread's priority change is ignored unless the system is rebooted
D. The thread will gain exclusive access to the CPU core

💡 Difficulty: medium | ✅ Correct: B

📖 Explanation:

Increasing a thread's priority makes the scheduler favor it, but it will only run ahead of other threads if those threads have lower or equal priority and are not already running. Option B reflects this behavior. Option A overstates the effect, option C is incorrect because the change takes effect immediately, and option D misrepresents CPU allocation.

Q12. In Windows kernel terminology, what distinguishes an object type from an object instance?

A. An object type is a concrete memory block, while an instance is a pointer to it
B. An object type defines attributes and methods; an instance contains actual attribute values
C. Object types exist only in user mode, and instances exist only in kernel mode ✅
D. There is no distinction; the terms are interchangeable

💡 Difficulty: hard | ✅ Correct: C

📖 Explanation:

The kernel defines object types as templates describing attributes and methods; each created object (instance) holds specific values for those attributes. Option C correctly states this relationship. Option A reverses the concepts, option B is partially correct but mislabels where they exist, and option D denies the meaningful distinction that the kernel makes.

Q13. Why is the Windows kernel primarily written in C with only limited assembly code?

A. C allows direct hardware manipulation without any abstraction
B. C provides a balance between low‑level access and portability, while assembly is used only where unavoidable ✅
C. Assembly is obsolete and no longer supported in modern operating systems
D. C code executes faster than any assembly instructions

💡 Difficulty: medium | ✅ Correct: B

📖 Explanation:

C offers constructs for pointer arithmetic and system calls, giving sufficient control over hardware while remaining portable across CPU families. Assembly is reserved for tasks that require exact timing or privileged instructions. Option B captures this rationale. Option A overstates C's capabilities, option C is false because assembly is still used for critical sections, and option D incorrectly claims C is always faster than assembly.
