What is Process management in Window 7?

Definition:
Process management encompasses creation, termination, and monitoring of processes through Win32 API and native NT APIs where process lifetime follows Create→Execute→Terminate \text{Create} \rightarrow \text{Execute} \rightarrow \text{Terminate} Create→Execute→Terminate with exit code propagation.

Example:
CreateProcessAsUser launches process under different security context for service impersonation scenarios.

Reason:
Comprehensive process lifecycle management enables secure multi-user computing, service hosting, and application sandboxing with proper resource cleanup and audit trail generation.

Q1. What does APC stand for?

A.Asynchronous Procedure Call ✅
B.Deferred Procedure Call
C.Application Process Control
D.Automatic Process Cleanup
💡 Difficulty: easy | ✅ Correct: A

📖 Explanation: APC is an abbreviation for Asynchronous Procedure Call. This term describes a mechanism that lets the operating system queue a routine to run in the context of a specific thread. The other choices either describe a different concept (Deferred Procedure Call) or are unrelated terms. Knowing the exact meaning helps identify when APCs are appropriate, such as initiating new threads or handling I/O completion.

Q2. Why are APCs only delivered when a thread is in an alertable wait state?

A.Because the kernel must ensure the thread can safely execute user‑mode code
B.Because APCs require higher CPU priority than normal threads ✅
C.Because APCs are only used for hardware interrupt handling
D.Because the scheduler blocks APCs during normal execution
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: APCs are delivered only when a thread is in an alertable wait because this guarantees a safe point where user‑mode code can run without disrupting critical kernel operations. The other options are incorrect: APCs do not need higher priority than normal threads, they are not limited to hardware interrupt handling, and the scheduler does not block them arbitrarily. This rule prevents race conditions and maintains system stability.

Q3. A driver queues a DPC after handling a high‑priority interrupt. When will the DPC execute?

A.Immediately after the ISR finishes
B.Only after all other device interrupts are processed
C.When the CPU is at a priority lower than device interrupts but higher than normal threads
D.Only when the system is idle ✅
💡 Difficulty: medium | ✅ Correct: D

📖 Explanation: A DPC runs when the CPU priority drops below that of device interrupts yet stays above the priority used for regular thread scheduling. This ensures urgent interrupt work is handled first, then the deferred work runs without delaying other ISRs. The other choices are wrong: it does not run immediately after the ISR, nor does it wait for the system to be idle, and it certainly does not wait for all device interrupts to finish before any DPC can run.

Q4. How does using a pool of worker threads improve system responsiveness compared to executing DPC routines directly?

A.Worker threads run at a higher priority than DPCs
B.Worker threads allow DPCs to be short and prevent long blocking
C.Worker threads eliminate the need for APCs ✅
D.Worker threads increase interrupt latency
💡 Difficulty: hard | ✅ Correct: C

📖 Explanation: A pool of worker threads lets the system offload longer‑running work from DPCs, keeping DPC routines short. Short DPCs avoid delaying other device interrupts and maintain quick context switches, which improves overall responsiveness. Running heavy code directly in DPCs could block higher‑priority ISRs. The other statements are inaccurate: worker threads do not run at higher priority than DPCs, they do not replace APCs, and they do not increase interrupt latency.

Q5. A process needs a thread to be terminated right after an I/O operation completes. Which mechanism should be used to safely stop the thread?

A.Use a DPC routine
B.Use an APC ✅
C.Use a hardware ISR
D.Use a timer callback
💡 Difficulty: hard | ✅ Correct: B

📖 Explanation: The appropriate mechanism is an APC because APCs can be queued to a specific thread to perform actions such as termination, especially when the thread is in an alertable state after I/O completion. DPCs are intended for deferred interrupt processing and run at a different priority, making them unsuitable for safely stopping a thread. Hardware ISRs and timer callbacks operate at even lower levels and cannot target a particular thread for termination. Using an APC ensures the thread is stopped in a controlled, context‑aware manner.
