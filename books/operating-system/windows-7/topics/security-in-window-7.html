Q1. What does the 'V' bit indicate in a page-table entry?

🔹 A. The page is valid
🔹 B. The page is protected
🔹 C. The page is dirty
🔹 D. The page is swapped out

💡 Difficulty: easy | ✅ Correct: A

📖 Explanation:

The 'V' bit, short for Valid, tells the memory manager whether the entry points to a real page in physical memory. When the bit is set, the CPU can use the address directly; when it is clear, the entry is treated as invalid and a fault occurs. Options B, C, and D describe other status flags (protection, dirty, swapped) that are represented by different bits, not the V bit. Recognizing the V bit’s role is essential for understanding how page faults are generated.

Q2. Why does the VM manager increment the age of pages that have not been marked as referenced since the last pass?

🔹 A. To prioritize them for eviction
🔹 B. To increase their protection level
🔹 C. To move them to a higher priority queue
🔹 D. To reset their reference bits

💡 Difficulty: medium | ✅ Correct: A

📖 Explanation:

The VM manager ages pages that have not been referenced so it can identify pages that are idle and safe to evict. Incrementing the age creates a numeric priority: the larger the age, the more likely the page will be chosen when trimming is required. Option A captures this intent. Option B is incorrect because protection levels are unrelated to aging. Option C reverses the priority by moving pages to a higher‑priority queue, which would keep them longer. Option D merely resets bits without affecting eviction decisions. Understanding aging explains why least‑recently‑used pages are targeted first.

Q3. How does the per‑working‑set LRU replacement policy improve overall system responsiveness compared to a single global LRU scheme?

🔹 A. It evicts pages from the smallest process first
🔹 B. It keeps all pages in memory longer
🔹 C. It trims pages based on each process's recent usage, reducing interference
🔹 D. It randomizes page selection to avoid patterns

💡 Difficulty: medium | ✅ Correct: C

📖 Explanation:

A per‑working‑set LRU policy keeps each process’s page‑age information separate, so the manager removes pages that are old only within that process. This isolation prevents a large or busy process from monopolizing the eviction pool and hurting smaller processes, thereby keeping the system responsive. Option C describes this benefit. Option A is wrong because the policy does not specifically target the smallest process first. Option B is opposite of the intended effect, as pages stay longer. Option D suggests random selection, which ignores recent‑use information. The per‑process focus is why Windows can maintain responsiveness even under load.

Q4. What is the purpose of the 4 bits that select the paging file in a page‑file PTE?

🔹 A. They indicate whether the page is encrypted
🔹 B. They store the process identifier
🔹 C. They specify the page’s cache policy
🔹 D. They identify which of the multiple paging files contains the page's data

💡 Difficulty: hard | ✅ Correct: D

📖 Explanation:

The four bits that select the paging file tell the OS which paging file on disk stores the page’s contents. Windows can maintain several paging files, and these bits allow a single PTE to point to the correct file without extra structures. Therefore, option D is correct. Option A confuses these bits with encryption status, which is handled elsewhere. Option B incorrectly claims they store a process identifier; the process ID is not needed here. Option C mentions cache policy, which is controlled by separate flags. Knowing the purpose of these bits clarifies how the system locates swapped pages.

Q5. A process has a hard limit of 200 MB and is currently using 190 MB of physical memory while the system has plenty of free memory. Which action is the VM manager most likely to take?

🔹 A. Trim the process’s working set
🔹 B. Allocate additional memory to the process
🔹 C. Ignore the hard limit because memory is available
🔹 D. Swap out the entire process

💡 Difficulty: medium | ✅ Correct: A

📖 Explanation:

When a process hits its hard limit, the VM manager treats the limit as a strict cap regardless of overall system memory. The manager will therefore trim the process’s working set to stay under the limit, freeing pages that are least recently used. Option A reflects this behavior. Option B is impossible because the limit prevents additional allocation. Option C ignores the policy that enforces the hard cap, and option D is excessive; the manager only trims enough pages, not the whole process. This trimming keeps the process within its allocated quota.

Q6. During a memory‑pressure event the VM manager inspects three pages: Page X is marked referenced, Page Y is not referenced and has an age of 5, Page Z is not referenced and has an age of 2. Which page will be selected first for trimming?

🔹 A. Page X
🔹 B. Page Y
🔹 C. Page Z
🔹 D. Both Y and Z equally

💡 Difficulty: hard | ✅ Correct: B

📖 Explanation:

The VM manager selects pages for trimming based on two criteriwhether the reference bit is set and the age value. Pages not referenced are candidates, and among them the one with the highest age is considered the oldest. In the scenario, Page Y is not referenced and has an age of 5, which is greater than Page Z’s age of 2, making Y the prime candidate. Option B therefore is correct. Option A is still referenced, so it is not eligible. Option C, while also unreferenced, is younger. Option D incorrectly treats both as equal.

Q7. If a page‑file PTE’s protection bits allow read and execute but not write, what occurs when the process attempts to write to that page?

🔹 A. The write succeeds silently
🔹 B. The write triggers a page‑fault
🔹 C. The operating system silently changes the protection
🔹 D. The write is cached and applied later

💡 Difficulty: medium | ✅ Correct: B

📖 Explanation:

Protection bits in a page‑file PTE define the operations allowed on that page. If write permission is missing, any attempt to modify the page triggers a page‑fault so the OS can enforce protection, typically by copying the page or denying the write. Thus, option B is correct. Option A is false because the write would not succeed silently. Option C is incorrect; the OS does not automatically change protection without explicit action. Option D suggests caching, which does not apply to protection violations.

Q8. Three processes have working‑set sizes of 150 MB, 300 MB, and 450 MB respectively. The system has 1 GB of RAM with 200 MB free, and the VM manager must trim 100 MB total. Which process is most likely to lose the largest portion of its working set?

🔹 A. Process A (150 MB)
🔹 B. Process B (300 MB)
🔹 C. Process C (450 MB)
🔹 D. All processes will be trimmed equally

💡 Difficulty: hard | ✅ Correct: C

📖 Explanation:

The VM manager uses heuristics that consider both the size of each working set and the growth rate of processes. The largest working set (Process C at 450 MB) is the most likely to contain excess pages and often grows faster, so it will lose the biggest share when the manager must trim 100 MB. Option C reflects this reasoning. Option A, the smallest process, would be trimmed least to preserve its limited resources. Option B is intermediate but not the largest. Option D ignores the heuristic that prioritizes larger or rapidly growing sets, making it incorrect.
