What is Change journal in Window 7?

Definition:
The NTFS Change Journal ($UsnJrnl) records file and directory modifications with USN identifiers where journal entry rate reflects filesystem activity level with persistent sequential logging.

Example:
Backup software queries change journal to identify modified files since last backup instead of scanning entire volume.

Reason:
Change tracking enables efficient incremental backup, replication, and indexing by providing authoritative modification history without expensive full-volume enumeration.

Q1. How many bits are dedicated to page‑protection information in a Windows page‑file PTE?

B.5 ✅
C.6
D.8
💡 Difficulty: easy | ✅ Correct: B

Knowing the exact bit allocation helps when interpreting PTE structures or debugging memory‑related issues, linking the answer directly to the design of the page‑file entry.

Q2. Why does the Windows VM manager increment the age of a page only when its referenced bit is not set, rather than based on how long the page has resided in memory?

A.Because age is based on wall‑clock time, which better reflects usage patterns
B.Because unreferenced pages are considered older and more eligible for trimming
C.Because the referenced bit indicates recent use, making the page appear newer ✅
D.Because the age counter is randomized to avoid bias
💡 Difficulty: medium | ✅ Correct: C

📖 Explanation: The correct answer is C because the VM manager’s age counter reflects recent usage: a page that has not been referenced since the last sweep is considered older and a candidate for trimming. Option A suggests time‑based aging, which is not used; B mixes up reference and dirty bits; D claims age is random. Understanding that age depends on the referenced bit explains why LRU works effectively, ensuring frequently accessed pages stay in memory while idle pages are reclaimed.

Q3. A process has a working set of 200 pages, of which 30 pages have their referenced bits set. When the VM manager trims the set, which pages are most likely to be removed?

A.Pages with the referenced bit set
B.Pages without the referenced bit set ✅
C.A random 20‑page subset
D.The newest 20 pages added to the set
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: The correct answer is B. Pages whose referenced bits are not set indicate they have not been accessed recently, so the VM manager classifies them as the oldest and trims them first. Option A would keep the most used pages, which defeats the purpose of LRU. Option C (random selection) ignores usage patterns, and D (newest pages) would degrade performance. This scenario shows how the manager uses reference information to decide which pages to evict, protecting active data.

Recognizing the size of the offset field lets administrators predict the maximum page‑file size that can be indexed, which is crucial when configuring system memory or diagnosing paging failures.

Q5. How does a per‑working‑set LRU replacement policy improve system responsiveness compared to a global LRU approach?

A.It allows the VM manager to trim pages from any process only when total memory is low
B.It evicts pages strictly in FIFO order, simplifying management
C.It prevents any trimming, keeping all pages resident
D.It enables targeted trimming of rapidly growing processes even when memory is plentiful ✅
💡 Difficulty: hard | ✅ Correct: D

📖 Explanation: The correct answer is D because a per‑working‑set LRU policy tracks page ages separately for each process, allowing the VM manager to trim pages from a rapidly expanding process even when overall memory is abundant. Option A describes a global LRU, which cannot target a single process; B suggests FIFO, which does not consider recent use; C claims no impact on responsiveness. By isolating each process’s working set, the system can maintain responsiveness for other applications, illustrating why Windows 7 introduced this refinement.

Q6. A Windows 7 process has a hard limit of 150 MB physical memory and is currently using 120 MB. The system needs to trim memory. How much can be reclaimed without violating the hard limit?

A.0 MB
B.30 MB ✅
C.150 MB
D.120 MB
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: The correct answer is B. The process is allowed up to 150 MB, currently uses 120 MB, so the VM manager can safely reclaim up to without breaching the hard limit. Option A (0 MB) would ignore possible reclamation; C (150 MB) would exceed the limit; D (120 MB) would remove all current usage. This calculation shows how hard limits constrain trimming, ensuring a process never exceeds its allocated physical memory while still permitting the system to free resources.
