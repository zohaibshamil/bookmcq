📝 Redirectors and servers in Window 7

📖 From Operating System • 19. Windows 7 • 26 questions available

What is Redirectors and servers in Window 7?

Definition:
Redirectors (client-side) and servers (server-side) implement distributed filesystem protocols like SMB/CIFS where request-response latency \( L_{\text{SMB}} \) is minimized through signing, encryption, and multichannel support.

Example:
Accessing \\server\share invokes MUP redirector to route request through appropriate network provider based on UNC path.

Reason:
Transparent network filesystem access enables seamless resource sharing and centralized storage while maintaining local filesystem semantics for applications.

Q1. What does ALPC stand for?

A. Advanced Local Procedure Call ✅
B. Asynchronous Local Process Communication
C. Automatic Link Procedure Control
D. Application Layer Protocol Converter

💡 Difficulty: easy | ✅ Correct: A

📖 Explanation:

Advanced Local Procedure Call is the correct expansion. The other options describe unrelated concepts: Asynchronous Local Process Communication is not a Windows term, Automatic Link Procedure Control refers to networking hardware, and Application Layer Protocol Converter is a generic term unrelated to Windows internals. Knowing the exact name helps administrators recognize the mechanism used for early‑boot communication and for services that cannot rely on RPC.

Q2. Why is ALPC preferred over RPC during the early stages of system boot?

A. Because ALPC does not require the RPC runtime to be initialized
B. Because ALPC uses less memory than RPC ✅
C. Because ALPC provides faster network throughput
D. Because ALPC encrypts all messages by default

💡 Difficulty: easy | ✅ Correct: B

📖 Explanation:

ALPC is preferred because it can operate without the RPC runtime, which is not yet available during early boot. The other choices are inaccurate: ALPC does not inherently use less memory, it is not designed for network throughput (it works locally), and it does not automatically encrypt messages. Understanding this limitation explains why native services fall back to ALPC when RPC cannot be used.

Q3. Which of the following best describes the purpose of the three message‑passing techniques used when an ALPC channel is created?

A. To provide different security levels for messages
B. To support varying message sizes and performance trade‑offs
C. To enable communication across different network protocols
D. To allow messages to be sent without any copying at all ✅

💡 Difficulty: medium | ✅ Correct: D

📖 Explanation:

The three techniques exist to support varying message sizes and performance trade‑offs, allowing the system to choose the most efficient method. They are not about security levels, network protocols, or eliminating copying entirely—only the third technique minimizes copying, while the first two involve some copying. Recognizing this helps developers select the appropriate technique for a given workload, improving system responsiveness.

Q4. A client needs to send a 40 KB request to a server using ALPC. Which technique will the system most likely use?

A. Technique 2 with a shared‑memory section
B. Technique 3 that writes directly into the server’s address space
C. Technique 1 that copies data through the port’s queue ✅
D. Technique 4 that compresses the data first

💡 Difficulty: medium | ✅ Correct: C

📖 Explanation:

For a 40 KB request, which is below the \(63 \text{KB}\) threshold, the system normally chooses Technique 1, copying data via the port’s message queue. Technique 2 is reserved for larger messages, Technique 3 involves direct address‑space writes that are more complex, and there is no Technique 4. Selecting the correct technique ensures the request is delivered efficiently without unnecessary overhead.

Q5. A service must transfer a 200 KB file between processes. Which ALPC technique minimizes copying overhead?

A. Technique 2 with a shared‑memory section ✅
B. Technique 1 that uses the message queue
C. Technique 3 that writes directly into the target address space
D. Technique 4 that streams over TCP

💡 Difficulty: medium | ✅ Correct: A

📖 Explanation:

When the payload exceeds the \(63 \text{KB}\) limit, Technique 2 is used because it creates a shared‑memory section, allowing the receiver to read the data directly without copying. Technique 1 would involve copying large amounts of data, which is inefficient. Technique 3 is reserved for special cases and is more complex to implement. There is no Technique 4 in ALPC. Understanding this choice helps developers design high‑performance inter‑process communication.

Q6. In an ALPC channel, a client sends a request and then waits for a reply, but the server also needs to send an unsolicited notification. Which feature enables this behavior?

A. The use of a separate callback port
B. The channel’s built‑in timeout mechanism ✅
C. The client’s ability to poll the server continuously
D. The server’s priority boost feature

💡 Difficulty: medium | ✅ Correct: B

📖 Explanation:

The channel’s callback mechanism lets the client accept incoming requests while it is expecting a reply, enabling unsolicited notifications. A separate callback port is not part of the standard ALPC design, polling would waste CPU cycles, and priority boosting does not affect message flow. Recognizing the callback capability is essential for building responsive services that can both answer requests and push updates.

Q7. What is the primary trade‑off when choosing between copying messages (Technique 1) and using a shared‑memory section (Technique 2) in ALPC?

A. Copying is faster for small messages, while shared memory reduces overhead for large messages
B. Copying always uses less memory than shared memory
C. Shared memory provides stronger security than copying ✅
D. Copying eliminates the need for synchronization primitives

💡 Difficulty: hard | ✅ Correct: C

📖 Explanation:

The central trade‑off is that copying is faster for small messages because the overhead of creating a shared section outweighs the benefit, whereas shared memory reduces copy overhead for large messages. It is not true that copying always uses less memory; both methods allocate buffers. Shared memory does not inherently improve security, and copying still requires synchronization to ensure data integrity. Knowing this helps system architects decide which technique best fits their workload.

Since the message size of \(70 \text{KB}\) exceeds the \(63 \text{KB}\) threshold for Technique 1, the system will choose Technique 2, creating a shared‑memory section to avoid copying large data. Technique 3 is reserved for special scenarios and is more complex, while there is no Technique 4 in ALPC. Selecting the correct technique avoids unnecessary copying and improves performance in real‑world inter‑process communication.

Q9. When a Windows service starts before the RPC subsystem is available, which communication mechanism does it use to interact with other components?

💡 Difficulty: medium | ✅ Correct: A

📖 Explanation:

The service uses ALPC directly because RPC cannot be relied upon before the RPC subsystem is initialized. Named pipes and TCP/IP sockets are alternatives that involve network stacks, which are not yet ready. Waiting for RPC would delay service startup, potentially breaking dependencies. Understanding this fallback explains why early‑boot services can still communicate reliably.

Q10. How does the relationship between RPC and ALPC affect the design of Windows inter‑process communication?

A. ALPC replaces RPC for all remote calls

C. RPC and ALPC are unrelated and cannot be combined
D. RPC is only used for local calls while ALPC handles remote calls ✅

💡 Difficulty: medium | ✅ Correct: D

📖 Explanation:

ALPC is a lower‑level message‑passing mechanism that RPC may use as a transport, especially for local calls. It does not replace RPC for remote communication, nor are they unrelated; they complement each other. Recognizing this hierarchy helps developers choose the appropriate API based on locality and performance requirements.

Switching to TCP/IP would still require RPC for certain operations, and disabling the dependency would not make the service functional. This solution aligns with how early‑boot services communicate.

Q14. A Windows service needs to communicate with a subsystem during early boot before RPC is available. Which transport should it use?

A. TCP/IP ✅
B. ALPC
C. Named pipes
D. HTTP

💡 Difficulty: easy | ✅ Correct: A

📖 Explanation:

The correct answer is ALPC because it is the low‑level message‑passing mechanism that Windows services use when RPC cannot run during boot. TCP/IP and HTTP require the network stack, which is not fully initialized early in boot, so they cannot be relied on. Named pipes also depend on RPC services that are unavailable at that stage. Choosing ALPC lets the service open a connection‑port object and exchange messages directly, matching the real‑world need for early‑stage communication.

Q15. Why does ALPC provide three separate message‑passing techniques?

A. To support different network protocols
B. To optimize for different message sizes ✅
C. To enforce security levels
D. To enable multicast broadcasting

💡 Difficulty: medium | ✅ Correct: B

📖 Explanation:

ALPC offers three techniques so it can handle messages efficiently depending on their size. Small to medium messages (up to about 63 KB) use the queue‑copy method, while larger data uses a shared‑memory section to avoid copying, and the third technique allows direct address‑space access for specialized cases. The other options are incorrect: ALPC does not deal with network protocols or multicast, and security is handled by other mechanisms, not by choosing a technique. In practice, this size‑based design lets a distributed file system move data quickly without unnecessary overhead.

Q16. A developer must transfer a 100 KB file between a client and a server using ALPC. Which technique should be chosen?

A. First technique (queue copy)
B. Second technique (shared memory) ✅
C. Third technique (direct address access)
D. Use RPC instead

💡 Difficulty: medium | ✅ Correct: B

📖 Explanation:

The second technique is correct because it creates a shared‑memory section for large messages, allowing the 100 KB file to be placed once and read directly by the receiver, eliminating costly copies. The first technique is limited to messages up to 63 KB, so it would require splitting the file and add overhead. The third technique is intended for special cases where processes can map each other’s address space, which is more complex than needed. RPC is not used here because the scenario explicitly relies on ALPC. Selecting the shared‑memory method matches the real‑world need for efficient large‑data transfer.

D. It converts all messages to asynchronous events

💡 Difficulty: hard | ✅ Correct: A

📖 Explanation:

The callback mechanism lets both the client and the server issue new requests even when they are expecting a reply, enabling full‑duplex communication and reducing idle time. In a distributed file system, this capability means a client can request additional metadata while waiting for a file read, improving overall throughput.

Q20. Which Windows mechanism provides client-side caching for redirected folders?

A. Offline Files ✅
B. DFS Replication
C. NTFS Compression
D. BitLocker

💡 Difficulty: easy | ✅ Correct: A

📖 Explanation:

The correct answer is Offline Files because it stores copies of redirected folder contents on the local machine, allowing access when the network share is unavailable. DFS Replication moves files between servers but does not cache locally. NTFS Compression reduces file size on disk but does not provide offline access. BitLocker encrypts drives and is unrelated to caching. This caching lets users work with their files even if the network is down, matching real‑world expectations for reliability.

Q23. How does client-side caching interact with file locking semantics on a redirected folder?
