Q1. What does APC stand for in Windows operating systems?

🔹 A. Asynchronous Procedure Call
🔹 B. Alertable Process Control
🔹 C. Application Parallel Compute
🔹 D. Atomic Priority Channel

💡 Difficulty: easy | ✅ Correct: A

📖 Explanation:

The correct answer is Asynchronous Procedure Call because APCs are a mechanism for queuing procedures to execute in the context of a specific thread. Option B invents a term that does not exist in Windows. Option C and D describe unrelated concepts. Understanding the acronym helps identify the purpose of APCs, which is to allow deferred execution of code, often for I/O completion or thread management.

Q2. Why are user‑mode APCs only delivered when a thread is in an alertable wait state?

🔹 A. Because the kernel cannot interrupt user code
🔹 B. To ensure APCs run only when the thread can safely handle them
🔹 C. Because APCs require CPU idle time
🔹 D. To prioritize I/O operations

💡 Difficulty: medium | ✅ Correct: A

📖 Explanation:

User‑mode APCs are delivered only when a thread is alertable because this guarantees the thread is in a safe point to run additional code without corrupting its state. Option A is false; the kernel can interrupt user code but chooses not to for APCs. Option C misstates the timing requirement, and Option D confuses APC delivery with I/O priority. The alertable state provides a controlled environment for APC execution.

Q3. A driver queues a DPC that takes 30 ms to complete. The system's quantum is 15 ms. Which effect is most likely?

🔹 A. Thread scheduling will be unaffected
🔹 B. Other DPCs may be delayed, causing I/O latency
🔹 C. The DPC will preempt the thread and extend quantum
🔹 D. The ISR will be blocked

💡 Difficulty: medium | ✅ Correct: A

📖 Explanation:

The DPC runs at a priority lower than device ISR but higher than normal threads, so while it executes it prevents other threads from being scheduled on that processor. Because the DPC exceeds the quantum, it occupies the CPU longer than a thread would, delaying subsequent DPCs and increasing I/O latency. Option A ignores the scheduling impact, Option C mischaracterizes DPC behavior, and Option D incorrectly suggests ISR blockage.

Q4. How does the priority of a DPC compare to the priority of normal threads and device ISR?

🔹 A. Higher than ISR, lower than threads
🔹 B. Lower than ISR, higher than threads
🔹 C. Equal to ISR and threads
🔹 D. Independent of both

💡 Difficulty: hard | ✅ Correct: A

📖 Explanation:

DPCs are designed to run after the ISR has finished, so they have a lower priority than the ISR but a higher priority than normal thread execution. This ordering ensures critical interrupt handling occurs first, while DPCs handle less urgent work without preempting regular threads. Option A reverses the relationship, Option C incorrectly states equal priority, and Option D suggests no relationship, which is inaccurate for the Windows scheduling model.

Q5. A system experiences high CPU usage due to many DPCs. Which mitigation strategy is most appropriate?

🔹 A. Increase the number of worker threads
🔹 B. Raise thread quantum
🔹 C. Move time‑consuming work from DPC to worker threads
🔹 D. Disable APCs

💡 Difficulty: hard | ✅ Correct: A

📖 Explanation:

Moving lengthy operations out of DPCs into worker threads prevents DPCs from monopolizing the CPU, reducing latency and keeping interrupt handling responsive. Increasing worker threads (Option A) does not address the root cause, raising the quantum (Option B) affects thread scheduling but not DPC execution, and disabling APCs (Option D) removes a useful mechanism unrelated to DPC overload.

Q6. An application initiates an asynchronous I/O operation and then calls SleepEx(0, TRUE). What is the purpose of the TRUE flag?

🔹 A. To make the thread non‑alertable
🔹 B. To allow delivery of queued APCs while sleeping
🔹 C. To block all I/O
🔹 D. To terminate the thread after sleep

💡 Difficulty: easy | ✅ Correct: A

📖 Explanation:

The TRUE flag makes the sleep alertable, meaning the thread can receive and execute queued APCs during the wait. This is essential for handling completion of asynchronous I/O without busy‑waiting. Option A describes the opposite behavior, Option C incorrectly suggests I/O blocking, and Option D misinterprets the flag as a termination signal. Alertable sleeps enable efficient APC processing.

Q7. What is the main reason the dispatcher maintains a pool of worker threads for ISR and DPC work items?

🔹 A. To avoid priority inversion
🔹 B. To execute long‑running tasks without delaying interrupt handling
🔹 C. To increase ISR execution speed
🔹 D. To allow user‑mode code to run in kernel mode

💡 Difficulty: medium | ✅ Correct: A

📖 Explanation:

Worker threads give the dispatcher a place to run work items that are too time‑consuming for ISR or DPC contexts, ensuring that interrupt processing remains fast and responsive. Option A addresses a different synchronization issue, Option C is false because ISR speed is unchanged, and Option D misrepresents the separation between user and kernel modes.

Q8. A developer mistakenly queues a DPC that accesses pageable memory. What potential problem can arise?

🔹 A. The DPC will be executed faster
🔹 B. Page fault may occur, leading to system crash
🔹 C. The DPC will be ignored
🔹 D. The ISR will be delayed

💡 Difficulty: medium | ✅ Correct: A

📖 Explanation:

DPCs run at elevated IRQL where paging is not allowed; accessing pageable memory can cause a page fault, which the kernel cannot handle at that level, potentially resulting in a bug check (system crash). Option A is opposite of the likely slowdown, Option C incorrectly suggests the DPC is dropped, and Option D misattributes the delay to the ISR rather than the DPC's illegal memory access.
