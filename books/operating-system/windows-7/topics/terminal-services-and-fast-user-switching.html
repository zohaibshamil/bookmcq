Q1. How many bits are used for the byte offset within a page in IA-32 virtual address translation?

🔹 A. 12
🔹 B. 9
🔹 C. 2
🔹 D. 20

💡 Difficulty: easy | ✅ Correct: A

📖 Explanation:

The offset determines the exact byte inside a 4 KB page. IA‑32 uses a 12‑bit offset because 2^{12}=4096 bytes, matching the page size. Thus the lower twelve bits of any virtual address become the byte offset. The other choices (9, 2, 20) correspond to indices for PDEs or PTEs, not the offset. Recognizing the 12‑bit offset is crucial for forming the final physical address after the page number is obtained from the PTE.

Q2. What is the primary advantage of using a two‑level page‑directory structure instead of a single‑level page table in IA‑32 systems?

🔹 A. It increases the size of each page
🔹 B. It reduces the amount of memory needed to store page tables
🔹 C. It eliminates the need for a page offset
🔹 D. It allows virtual addresses to be larger than physical addresses

💡 Difficulty: easy | ✅ Correct: B

📖 Explanation:

A two‑level hierarchy dramatically cuts memory consumption because only the needed second‑level tables are allocated, not a full 2^{20} entry table. This saves RAM and improves cache efficiency. Options about page size, offsets, or address size are unrelated to the memory‑saving benefit. In practice, the reduced footprint speeds up address translation and allows larger address spaces without exhausting physical memory.

Q3. A process accesses virtual address 0xC1234567. Which bits represent the top‑level PDE index?

🔹 A. Bits 30‑29 (two bits)
🔹 B. Bits 30‑22 (nine bits)
🔹 C. Bits 31‑30 (the two most significant bits)
🔹 D. Bits 12‑0 (twelve bits)

💡 Difficulty: medium | ✅ Correct: C

📖 Explanation:

The top‑level PDE index occupies the two most significant bits of the 32‑bit address, bits 31‑30. For 0xC1234567, those bits are '01', selecting one of four PDEs. Options mentioning bits 30‑29 or the nine‑bit second‑level index are incorrect, as is the offset field. Knowing the correct bit field enables the OS to locate the appropriate top‑level entry before proceeding to lower‑level tables.

Q4. How does extending the PTE size from 32 bits to 64 bits affect the maximum physical memory addressable by IA‑32‑compatible servers?

🔹 A. It allows addressing up to 2^{24} bytes
🔹 B. It reduces the number of page‑directory entries
🔹 C. It has no impact on addressable memory
🔹 D. It increases the physical page number field, supporting larger physical addresses

💡 Difficulty: hard | ✅ Correct: D

📖 Explanation:

A 64‑bit PTE expands the field that holds the physical page number, so the hardware can reference pages beyond the original 20‑bit limit. This enables addressing of far more than the initial 4 GB, such as the 24‑bit (16 MB) or larger physical spaces used in modern servers. The other choices either misstate the effect or claim no change, which is inaccurate for contemporary architectures.

Q5. If a server uses a 24‑bit physical address space, how many distinct physical pages can be addressed, assuming a page size of 4 KB?

🔹 A. 2^{20} pages
🔹 B. 2^{12} pages
🔹 C. 2^{24} pages
🔹 D. 2^{14} pages

💡 Difficulty: medium | ✅ Correct: B

📖 Explanation:

A 24‑bit address provides 2^{24} total bytes. With a 4 KB page (2^{12} bytes), the number of unique pages equals 2^{24‑12}=2^{12}=4096 pages. Option B reflects this calculation. The other options either ignore the page‑size division or over‑estimate the count, leading to incorrect physical page counts. Understanding this relationship is vital for sizing page tables and ensuring the system can map all physical memory.

Q6. Why does the IA‑32 architecture limit the physical page number field in a 32‑bit PTE to 20 bits?

🔹 A. To match the 32‑bit virtual address space
🔹 B. To simplify the hardware decoder
🔹 C. Because the original design only needed to address 4 GB of physical memory
🔹 D. To reserve bits for protection flags

💡 Difficulty: medium | ✅ Correct: C

📖 Explanation:

When IA‑32 was first designed, typical machines held at most 4 GB of RAM, which requires 20 bits (2^{20} × 4 KB) to represent all physical pages. Consequently, the PTE allocated only 20 bits for the page number, leaving the remaining bits for flags. Options about matching virtual size, decoder simplicity, or flag reservation do not explain the historic memory‑size constraint.

Q7. A system has a virtual address where the second‑level PDE index bits are 0b101001011. Which decimal value does this index represent?

🔹 A. 667
🔹 B. 427
🔹 C. 811
🔹 D. 331

💡 Difficulty: medium | ✅ Correct: D

📖 Explanation:

The binary value 101001011 equals 1·2^{8}+0·2^{7}+1·2^{6}+0·2^{5}+0·2^{4}+1·2^{3}+0·2^{2}+1·2^{1}+1·2^{0}=256+64+8+2+1=331. Therefore the decimal index is 331. The other numbers result from mis‑reading the binary pattern or shifting bits incorrectly. Converting binary indices accurately is essential for locating the correct second‑level PDE during address translation.

Q8. In fast user switching, how does the separation of each user's session memory via distinct page tables improve system stability?

🔹 A. It prevents one user’s processes from overwriting another’s memory
🔹 B. It isolates each user’s page tables, ensuring memory protection across sessions
🔹 C. It increases CPU clock speed
🔹 D. It reduces the need for virtual memory

💡 Difficulty: medium | ✅ Correct: B

📖 Explanation:

Each logged‑in user receives a private set of page tables, so the OS can enforce protection bits that stop one session from accessing another's address space. This isolation prevents accidental or malicious memory corruption, enhancing overall stability. Options about CPU speed or virtual memory usage are unrelated to the security benefits provided by distinct page tables.

Q9. Given a 32‑bit virtual address 0x8F123ABC, determine the physical page number if the top‑level PDE points to a page‑directory page at physical frame 0x00123, the second‑level PDE points to a PTE page at frame 0x00456, and the selected PTE contains the physical page number 0x00ABC. What is the final physical address?

🔹 A. 11258556
🔹 B. 11258796
🔹 C. 11258795
🔹 D. 11258556

💡 Difficulty: hard | ✅ Correct: A

📖 Explanation:

The translation ends with the PTE providing physical page number 0x00ABC. The lower 12 bits of the virtual address (0xABC) become the offset, which is appended to the page number, yielding 0x00ABCABC. The other choices alter the offset or page number, producing incorrect addresses. This step demonstrates how the final physical address is assembled after navigating the page‑table hierarchy.

Q10. Explain why modern Windows servers, which run on AMD64 or IA‑64 architectures, can support physical address spaces far larger than the original IA‑32 limit.

🔹 A. Because they increase the number of CPU cores
🔹 B. Because they reduce the page size to 2 KB
🔹 C. Because they use 64‑bit PTEs that contain larger physical page number fields
🔹 D. Because they eliminate the need for page tables

💡 Difficulty: hard | ✅ Correct: C

📖 Explanation:

AMD64 and IA‑64 CPUs employ 64‑bit page‑table entries, expanding the field that stores the physical page number. This allows the OS to reference pages far beyond the 20‑bit limit of IA‑32, enabling terabytes of RAM on modern servers. Changing core count or page size does not directly increase addressable memory, and removing page tables would break virtual memory mechanisms.

Q11. A virtual address has the following bit fields: top‑level PDE index = 2 bits = 01, second‑level PDE index = 9 bits = 100110011, PTE index = 9 bits = 011001101, and offset = 12 bits = 101010101010. If the selected PTE holds the physical page number 0x1F2E3, what is the full 32‑bit physical address in hexadecimal?

🔹 A. 523123371
🔹 B. 523123369
🔹 C. 523123360
🔹 D. 523123370

💡 Difficulty: hard | ✅ Correct: D

📖 Explanation:

The offset bits 101010101010 equal hexadecimal 0xAAA. The PTE supplies the physical page number 0x1F2E3. Concatenating the page number with the offset yields 0x1F2E3AAA. Options that alter the low‑order nibble or change the page number are incorrect. This calculation shows how the final address is built from the page number and offset after successful table lookups.

Q12. What would be the impact on address translation latency if the second‑level page‑directory were removed, forcing a single‑level page table with 2^20 entries?

🔹 A. Latency would increase due to larger table lookups
🔹 B. Latency would decrease because fewer levels are traversed
🔹 C. Latency would stay the same because hardware caches compensate
🔹 D. Latency would become unpredictable

💡 Difficulty: hard | ✅ Correct: A

📖 Explanation:

A single large page table would require scanning up to 2^{20} entries for each translation, greatly increasing memory accesses and cache misses, thus raising latency. While fewer levels sounds simpler, the enormous table size outweighs the benefit. Options suggesting lower latency or unchanged performance ignore the cost of massive linear lookups, and unpredictability is not a direct consequence of the structural change.
