What is Fibers in Process management in Window 7?

Definition:
Fibers are user-mode cooperative threads with explicit scheduling where fiber switch cost due to avoiding kernel transition and register save/restore.

Example:
Game engine uses fibers for coroutine-style AI logic yielding control voluntarily during I/O waits.

Reason:
Lightweight cooperative multitasking enables high-frequency context switching for specialized workloads where preemptive scheduling overhead would be prohibitive.

Q1. What does APC stand for in Windows kernel terminology?

A.Asynchronous Process Call ✅
B.Active Procedure Completion
C.Asynchronous Procedure Call
D.Application Process Control
💡 Difficulty: easy | ✅ Correct: A

📖 Explanation: The correct answer is Asynchronous Procedure Call because APCs are kernel objects that allow code to run in the context of a specific thread. Option A misstates the word Process, Option B mixes unrelated terms, and Option D suggests an application‑level concept that does not exist in this context. Knowing the exact expansion helps identify the purpose of APCs when designing thread‑aware code.

Q2. Why does the system schedule a DPC at a priority lower than device ISR but higher than normal thread execution?

A.To ensure DPCs run before any user‑mode code ✅
B.Because DPCs must finish before the next ISR
C.To allow pending ISR work to complete while still preempting regular threads
D.To give threads a chance to run before DPCs
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: The correct answer is that DPCs run at a priority that lets them finish pending interrupt work without delaying normal thread scheduling. Option A is partly true but not the primary reason; Option B is inaccurate because DPCs are not required to finish before the next ISR; Option D reverses the priority order. Understanding this hierarchy explains how Windows balances responsiveness and throughput.

Q3. A driver’s ISR has completed the urgent hardware handling and now needs to perform additional processing that may take several milliseconds. Which mechanism should the driver use?

A.Deferred Procedure Call (DPC) ✅
B.Asynchronous Procedure Call (APC)
C.Create a new worker thread
D.Schedule a timer event
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: The correct answer is a DPC because it is designed to defer non‑urgent work after an ISR while still running at a high priority. APCs cannot be queued from an ISR and require an alertable thread, making them unsuitable. Creating a new thread would add unnecessary overhead, and a timer would introduce extra delay. Selecting DPC ensures timely processing without blocking critical interrupt handling.

Q4. In which situation will an APC be executed in user mode?

A.When the thread is in a non‑alertable wait state ✅
B.When the thread is running at normal priority
C.When the thread is waiting in the kernel and marked alertable
D.When the processor is idle
💡 Difficulty: hard | ✅ Correct: A

📖 Explanation: The correct answer is that APCs run only when a thread is waiting in the kernel and marked alertable, because this state allows the kernel to safely inject user‑mode code. Option A is wrong because a non‑alertable wait blocks APCs. Option B is incorrect because APCs are not delivered during normal execution. Option C misstates the condition. Recognizing this rule is crucial for correctly synchronizing asynchronous I/O notifications.

Q5. A system experiences heavy I/O traffic and must minimize latency for thread scheduling while still handling timer expirations. Which combination best meets these goals?

A.Use only worker threads for all deferred work ✅
B.Queue timer expirations to DPCs and defer lengthy processing to worker threads
C.Handle timer expirations directly in ISR and use APCs for all other work
D.Disable DPCs and rely on high‑priority threads
💡 Difficulty: hard | ✅ Correct: A

📖 Explanation: The correct answer pairs DPCs for quick timer handling with worker threads for longer tasks, preserving low latency for thread scheduling. Option A would overload worker threads and increase delay. Option C places too much work in the ISR, violating design rules. Option D eliminates DPCs, removing an efficient mechanism for timely processing. This combination reflects how Windows balances responsiveness and workload distribution.

Q6. When a periodic timer expires, why does Windows typically use a DPC to process the expiration rather than a regular thread?

A.Because DPCs can run at a higher priority than normal threads ✅
B.Because DPCs can preempt the ISR that set the timer
C.Because DPCs avoid the overhead of thread creation and can run before user‑mode scheduling
D.Because DPCs guarantee execution on the same processor as the timer
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: The correct answer is that DPCs avoid the overhead of creating or waking a full thread and execute before normal user‑mode scheduling, providing a fast response to timer events. Option A is partially true but not the main benefit; Option B is inaccurate because the ISR has already completed; Option D is false because DPCs are not bound to a specific processor. Understanding this choice shows why DPCs are preferred for time‑critical callbacks.
