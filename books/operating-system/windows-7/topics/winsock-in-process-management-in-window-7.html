Q1. What does APC stand for in Windows networking?

🔹 A. Asynchronous Procedure Call
🔹 B. Application Process Component
🔹 C. Advanced Protocol Control
🔹 D. Automatic Port Configuration

💡 Difficulty: easy | ✅ Correct: A

📖 Explanation:

The correct answer is Asynchronous Procedure Call because APCs are a core Windows mechanism for queuing procedures to run in the context of a specific thread. The other options are fabricated terms that do not exist in the Windows API. Understanding this definition helps identify how asynchronous I/O notifications are delivered, which is essential when working with Winsock functions that rely on APCs for completion signaling.

Q2. Why are Deferred Procedure Calls scheduled at a priority lower than hardware interrupts but higher than normal thread execution?

🔹 A. To ensure they never preempt any interrupt
🔹 B. To allow them to run after all urgent ISR work but before user threads
🔹 C. Because they run at the same priority as ISRs
🔹 D. Because they are processed only when the CPU is idle

💡 Difficulty: medium | ✅ Correct: A

📖 Explanation:

The correct answer states that DPCs run after urgent ISR work yet before normal threads, which balances prompt device handling with system stability. Option A is wrong because DPCs can preempt lower‑priority work. Option C is incorrect because DPCs have lower priority than ISRs. Option D is false; DPCs are not limited to idle CPU time. This ordering is crucial for Winsock drivers that need timely processing without blocking other system activities.

Q3. How does the dispatcher use a pool of worker threads to handle work items queued by ISR and DPC routines?

🔹 A. It executes them immediately in the ISR context
🔹 B. It schedules them as normal threads after the DPC finishes
🔹 C. It discards them if the pool is full
🔹 D. It runs them at interrupt priority level

💡 Difficulty: medium | ✅ Correct: A

📖 Explanation:

The dispatcher forwards queued work items to worker threads, which are scheduled like regular threads after the DPC completes, providing a safe environment for longer tasks. Option A is incorrect because executing in ISR context would block interrupts. Option C is false; items are not discarded merely due to pool size. Option D misstates priority levels—worker threads run at normal thread priority, not interrupt level. This mechanism lets Winsock drivers offload heavy processing without delaying critical interrupt handling.

Q4. What is the effect of marking a thread as alertable on the execution of user‑mode APCs?

🔹 A. APCs can run at any time regardless of thread state
🔹 B. APCs are blocked until the thread becomes non‑alertable
🔹 C. APCs are delivered only when the thread is waiting in an alertable state
🔹 D. APCs are ignored completely

💡 Difficulty: medium | ✅ Correct: A

📖 Explanation:

When a thread is marked alertable, the system permits queued APCs to execute while the thread is in a wait state, enabling asynchronous I/O completion. Option A is inaccurate because APCs cannot run while the thread is executing normal code. Option B reverses the condition; alertable state enables, not blocks, APCs. Option D is false—APCs are not ignored. Recognizing this behavior is key for Winsock applications that rely on APC callbacks for network operations.

Q5. A driver receives a high‑rate network packet interrupt. The ISR quickly schedules a DPC. Which action should the DPC perform to ensure efficient processing?

🔹 A. Process the entire packet queue in one go
🔹 B. Copy packet data to a user buffer directly
🔹 C. Defer the heavy parsing to a worker thread and only handle minimal bookkeeping
🔹 D. Ignore the interrupt and let the ISR handle everything

💡 Difficulty: hard | ✅ Correct: A

📖 Explanation:

The DPC should perform only minimal work such as updating counters or queuing a work item, then let a worker thread handle the heavy parsing. Option A would risk long DPC execution and block other interrupts. Option B violates the rule that DPCs cannot safely access user memory. Option D defeats the purpose of using a DPC. This design keeps the interrupt latency low, which is vital for high‑throughput Winsock networking.

Q6. An application initiates an asynchronous Winsock send. Upon completion, an APC is queued to the thread. Which condition must be satisfied for the APC to run and deliver the completion notification?

🔹 A. The thread must be in a non‑alertable wait state
🔹 B. The thread must be executing user code without any waits
🔹 C. The thread must be in an alertable wait state
🔹 D. The thread must be terminated

💡 Difficulty: hard | ✅ Correct: A

📖 Explanation:

For the APC to execute, the thread must be waiting in an alertable state, allowing the system to invoke the queued procedure. Option A is opposite; non‑alertable waits block APC delivery. Option B is incorrect because APCs cannot interrupt active execution. Option D is irrelevant—terminated threads cannot receive APCs. Knowing this requirement enables developers to correctly design Winsock applications that rely on APC callbacks for I/O completion.

Q7. A developer wants to defer a time‑consuming cleanup after a timer ISR. Should they use a DPC or queue a work item to a worker thread, and why?

🔹 A. Use a DPC because it runs at higher priority than the ISR
🔹 B. Use a DPC because it can run indefinitely without affecting threads
🔹 C. Queue a work item to a worker thread to avoid long DPC execution
🔹 D. Queue a work item to a worker thread because it runs at interrupt level

💡 Difficulty: medium | ✅ Correct: A

📖 Explanation:

The appropriate choice is to queue a work item to a worker thread, which prevents a long‑running DPC from monopolizing the processor and blocking other interrupts. Option A misstates priority; DPCs run after the ISR but still can delay other processing. Option B is false because DPCs are limited in execution time. Option D incorrectly describes the execution level. Using a worker thread aligns with best practices for Winsock drivers needing extensive post‑ISR processing.
