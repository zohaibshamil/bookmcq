What is Volume shadow copies in Window 7?

Definition:
Volume Shadow Copy Service (VSS) creates point-in-time snapshots using copy-on-write semantics where snapshot creation time \( T_{\text{snap}} \ll T_{\text{fullcopy}} \) through metadata-only operations.

Example:
Previous Versions tab shows file history from scheduled shadow copies, enabling recovery of accidentally deleted or modified files.

Reason:
Block-level snapshots enable rapid backup, application-consistent restores, and user self-service recovery without disrupting active workloads or requiring dedicated backup windows.

Q1. A process has 5 pages in its working set; three have been referenced since the last VM manager pass, and two have not. When memory pressure rises, what will the VM manager most likely do with the unreferenced pages?

A. Increase their protection bits
B. Trim (remove) the oldest unreferenced pages ✅
C. Swap them to the ready queue
D. Mark them as valid

💡 Difficulty: easy | ✅ Correct: B

📖 Explanation:

The VM manager tracks page references via the PTE. Pages that were not marked as referenced during the last scan are considered old. When memory becomes scarce, the manager removes these older, unreferenced pages to free physical memory. Increasing protection bits or marking pages as valid would keep them in memory, which contradicts the goal of freeing space. Swapping to a ready queue is not a VM manager operation; trimming is the correct response.

Q2. In a page‑file PTE, which bits are always set to zero?

A. The T, P, and V bits ✅
B. The protection bits
C. The offset bits
D. The reserved bits

💡 Difficulty: easy | ✅ Correct: A

📖 Explanation:

Page‑file PTEs are used for pages that have been moved to disk, so the valid (V), transition (T), and present (P) bits are all cleared to zero. This indicates that the page is not currently resident in physical memory. The protection bits store access rights, the offset bits point to the location in the page file, and the reserved bits are kept for bookkeeping, so they are not universally zero.

Q3. How many bits are allocated for the page‑file offset field in a page‑file PTE?

A. 24
B. 30
C. 32 ✅
D. 28

💡 Difficulty: medium | ✅ Correct: C

📖 Explanation:

The page‑file PTE structure includes a 32‑bit field that records the offset of the page within the page file. This offset tells the system where to find the page when it needs to be brought back into memory. The other fields (protection, paging‑file selector, and reserved bits) use different bit widths, but the offset is specifically 32 bits, enabling a large addressable range within the page file.

Q4. Why does Windows use a per‑working‑set LRU replacement policy rather than a system‑wide LRU?

A. To ensure fairness across processes ✅
B. To reduce CPU overhead
C. To prioritize high‑priority threads
D. To simplify paging file management

💡 Difficulty: medium | ✅ Correct: A

📖 Explanation:

A per‑working‑set LRU tracks the age of pages within each individual process, allowing the system to trim each process’s working set based on its own usage patterns. This prevents a single busy process from dominating the replacement decisions and ensures that every process gets a fair chance to retain its most recent pages. System‑wide LRU would ignore individual process needs and could lead to unfair memory distribution.

Q5. Process X has a hard limit of 200 MB on its working set. Even though the system has 2 GB free, its working set is being trimmed. Which mechanism explains this behavior?

A. VM manager’s age‑based trimming
B. Hard‑limit enforcement ✅
C. Random page eviction
D. Page‑file compression

💡 Difficulty: medium | ✅ Correct: B

📖 Explanation:

A hard limit is a configured maximum amount of physical memory that a process may use. When a process reaches this threshold, the VM manager will trim its working set regardless of overall system memory availability. This enforcement ensures that no single process can exceed its allocated quota, preserving system stability. Age‑based trimming is used under memory pressure, but the hard limit triggers trimming even when ample memory remains.

Q6. A system has two paging files. A page‑file PTE contains a 4‑bit field selecting the paging file. If the field value is binary 1010, which paging file does the page belong to?

A. Paging file 0
B. Paging file 5
C. Paging file 10
D. Invalid selection ✅

💡 Difficulty: hard | ✅ Correct: D

📖 Explanation:

The 4‑bit selector can represent values from 0 to 15. With only two paging files present, valid selectors are 0 and 1. Binary 1010 equals decimal 10, which exceeds the available paging‑file indices, making the selection invalid. Therefore, the PTE would be considered malformed or would cause an error. Options A, B, and C assume valid selections, which is not the case here.

Q7. When the VM manager increments the age of pages that have not been marked as referenced, what underlying assumption about page usefulness is it making?

A. Older pages are less likely to be needed soon ✅
B. Older pages contain more errors
C. Older pages use more power
D. Older pages are more secure

💡 Difficulty: hard | ✅ Correct: A

📖 Explanation:

The age‑based algorithm assumes that a page not referenced for a while is less likely to be accessed again in the near future. By incrementing its age, the manager flags it as a candidate for trimming, freeing physical memory for more active pages. This assumption does not relate to error rates, power consumption, or security; it purely reflects temporal locality of reference in typical workloads.

Q8. A newly launched application’s working set grows from 50 MB to 300 MB within a few seconds while the system has abundant memory. What does Windows 7’s VM manager do to maintain system responsiveness?

A. It disables trimming for that process
B. It aggressively trims the process’s working set ✅
C. It increases the system’s page‑file size
D. It moves pages to a dedicated high‑speed cache

💡 Difficulty: medium | ✅ Correct: B

📖 Explanation:

Windows 7 introduced a policy that monitors rapidly expanding working sets. Even when overall memory is plentiful, the VM manager will proactively trim the expanding process to prevent it from monopolizing resources and to keep the system responsive for other tasks. Disabling trimming would worsen performance, while changing page‑file size or moving pages to a special cache does not directly address the rapid growth scenario.
