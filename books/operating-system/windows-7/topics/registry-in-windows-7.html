📝 All Registry in Windows 7 MCQs

Q1. What is the primary purpose of the Windows Registry?

🔹 A. To store executable files
🔹 B. To provide a hierarchical database for configuration settings
🔹 C. To manage network connections
🔹 D. To handle user authentication

💡 Difficulty: easy | ✅ Correct: B

📖 Explanation:

The Registry is a central hierarchical database that stores system-wide and per‑user configuration settings, such as hardware parameters, software options, and user preferences. Option B correctly describes this role. Options A, C, and D describe unrelated functions: executable files are stored on disk, network connections are managed by networking components, and authentication is handled by security subsystems. Understanding the Registry’s purpose helps students see where Windows keeps critical configuration data.

Q2. How does the Registry support the Hardware Abstraction Layer (HAL) when configuring device drivers?

🔹 A. It supplies driver source code
🔹 B. It contains BIOS firmware
🔹 C. It stores driver configuration data that the HAL reads during initialization
🔹 D. It replaces the HAL functions

💡 Difficulty: medium | ✅ Correct: C

📖 Explanation:

The HAL relies on the Registry to obtain driver‑specific settings, such as IRQ numbers, memory ranges, and DMA channels, without hard‑coding them. Option C captures this relationship. Option A is incorrect because source code is not stored in the Registry; option B refers to BIOS, which is separate; option D suggests the Registry replaces HAL, which is false. This explanation links the Registry’s role to real driver configuration.

Q3. Why is storing driver configuration data in the Registry considered advantageous over hard‑coding values in the driver binary?

🔹 A. It allows administrators to modify settings without recompiling the driver
🔹 B. It speeds up driver loading time
🔹 C. It encrypts the driver code
🔹 D. It reduces memory usage

💡 Difficulty: medium | ✅ Correct: A

📖 Explanation:

Storing settings in the Registry lets administrators change parameters (e.g., timeout values) without rebuilding the driver, providing flexibility and easier maintenance. Option A reflects this benefit. Option B is inaccurate because reading from the Registry adds a small overhead; option C is unrelated to encryption; option D incorrectly suggests memory savings. This concept is vital for managing drivers across diverse hardware.

Q4. In Windows, object types are defined by the kernel. How are these object types typically represented in the Registry?

🔹 A. As values under HKCU\\Software
🔹 B. As files in the System32 folder
🔹 C. As entries in the Event Log
🔹 D. As keys and subkeys that describe object attributes

💡 Difficulty: medium | ✅ Correct: D

📖 Explanation:

The kernel’s object types (e.g., events, mutexes) have their attributes stored as Registry keys and subkeys, allowing system components to query or modify them. Option D correctly describes this representation. Options A and B refer to unrelated locations, and option C describes logging, not object definition. Recognizing this mapping helps students understand how the Registry reflects kernel‑level structures.

Q5. A system fails to start because a critical driver cannot locate its settings. Which built‑in utility should you use to repair the corrupted Registry key?

🔹 A. Disk Cleanup
🔹 B. Registry Editor (regedit) in safe mode
🔹 C. Task Manager
🔹 D. System Configuration (msconfig)

💡 Difficulty: medium | ✅ Correct: B

📖 Explanation:

When a driver cannot find its configuration, the Registry Editor (regedit) allows direct inspection and correction of the relevant keys, especially when launched in safe mode to avoid loading the problematic driver. Option B is correct. Disk Cleanup removes temporary files, Task Manager manages processes, and msconfig controls startup programs, none of which edit the Registry directly. This scenario illustrates practical Registry troubleshooting.

Q6. You must deploy a new network driver to 200 workstations. Which Registry change ensures the driver loads automatically at boot without manual driver installation on each machine?

🔹 A. Add a value under HKLM\\SYSTEM\\CurrentControlSet\\Services\\<DriverName>\\Start set to 0
🔹 B. Create a shortcut in the Startup folder
🔹 C. Modify HKCU\\Software\\Microsoft\\Windows\\CurrentVersion\\Run
🔹 D. Edit the boot.ini file

💡 Difficulty: hard | ✅ Correct: C

📖 Explanation:

Setting the driver’s Start value to 0 under the Services key tells the Service Control Manager to load the driver during boot, automating deployment across many machines. Option A is the correct method. A shortcut in the Startup folder applies only to user‑level programs, not kernel drivers; modifying the Run key affects user processes; editing boot.ini is obsolete on modern Windows versions. This answer connects Registry editing to large‑scale driver deployment.

Q7. Malware inserts a value into HKLM\\Software\\Microsoft\\Windows\\CurrentVersion\\Run. What is the most likely effect of this modification?

🔹 A. It disables the firewall
🔹 B. It encrypts user files
🔹 C. It changes the desktop background
🔹 D. It causes the malicious program to execute each time the system starts

💡 Difficulty: hard | ✅ Correct: D

📖 Explanation:

The Run key under HKLM is consulted at system startup to launch programs automatically. Adding a malicious entry causes that program to run each boot, providing persistence. Option D reflects this behavior. Disabling the firewall, encrypting files, or changing the background are unrelated to the Run key’s purpose. Understanding this helps students recognize a common technique used by malware to maintain access.

Q8. An administrator changes the Registry value \\MemoryManagement\\LargeSystemCache to 1 to improve caching. What impact does this have on system performance?

🔹 A. It disables all caching
🔹 B. It reduces CPU usage
🔹 C. It increases the amount of memory used for file system caching, potentially improving I/O performance but using more RAM
🔹 D. It forces the system to reboot

💡 Difficulty: hard | ✅ Correct: C

📖 Explanation:

Setting LargeSystemCache to 1 tells Windows to allocate more RAM for system file caching, which can speed up disk I/O at the cost of higher memory consumption. Option C correctly describes this trade‑off. Disabling caching (A) is the opposite effect; reducing CPU usage (B) is not a direct result; forcing a reboot (D) is unrelated. This explanation links a specific Registry tweak to real performance outcomes.

Q9. During the boot process, how does the kernel use the Registry to locate essential system components?

🔹 A. It reads the Registry to find the location of the boot loader only
🔹 B. It queries HKLM\\SYSTEM\\CurrentControlSet\\Control to load drivers and services needed for initialization
🔹 C. It ignores the Registry and uses hard‑coded paths
🔹 D. It stores boot logs in the Registry

💡 Difficulty: medium | ✅ Correct: B

📖 Explanation:

The kernel reads the HKLM\\SYSTEM\\CurrentControlSet\\Control subtree to determine which drivers and services must be started early, ensuring proper initialization of hardware and core services. Option B captures this mechanism. Option A is too narrow, option C is false because the Registry is essential for dynamic configuration, and option D misstates the purpose of boot logs. This ties Registry access to the critical boot sequence.

Q10. On a 64‑bit Windows system, a 32‑bit application writes to HKLM\\Software\\MyApp. Where does the system actually store this data?

🔹 A. In the same 64‑bit key
🔹 B. It is discarded
🔹 C. In HKCU\\Software\\MyApp
🔹 D. In HKLM\\Software\\Wow6432Node\\MyApp

💡 Difficulty: easy | ✅ Correct: D

📖 Explanation:

Windows uses registry redirection for 32‑bit applications on a 64‑bit OS, storing their data under the Wow6432Node subtree. Therefore, the write to HKLM\\Software\\MyApp is redirected to HKLM\\Software\\Wow6432Node\\MyApp, making option D correct. The other options are incorrect because the data is not kept in the 64‑bit location, not discarded, and not redirected to the current‑user hive. This concept is essential for understanding cross‑architecture registry behavior.
