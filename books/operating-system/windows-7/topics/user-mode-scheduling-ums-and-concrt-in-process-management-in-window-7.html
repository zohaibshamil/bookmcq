Q1. What does APC stand for in the Windows kernel?

🔹 A. Asynchronous Procedure Call
🔹 B. Application Process Control
🔹 C. Automatic Priority Change
🔹 D. Advanced Power Configuration

💡 Difficulty: easy | ✅ Correct: A

📖 Explanation:

The abbreviation APC stands for Asynchronous Procedure Call. This mechanism lets the kernel queue a routine to run in the context of a particular thread, enabling operations such as I/O completion notifications or thread creation. The other choices describe unrelated concepts: Application Process Control, Automatic Priority Change, and Advanced Power Configuration are not kernel terms. Recognizing the correct expansion is critical because APCs are the primary way asynchronous events are delivered to user‑mode code.

Q2. Why are APCs delivered only when a thread is in an alertable wait state?

🔹 A. Because alertable wait allows the kernel to interrupt user code safely
🔹 B. Because the scheduler only checks the APC queue during alertable waits
🔹 C. Because non‑alertable waits block all kernel callbacks
🔹 D. Because APCs require user‑mode code to be paused

💡 Difficulty: easy | ✅ Correct: B

📖 Explanation:

APCs are processed only when a thread explicitly enters an alertable wait because the kernel checks the thread’s APC queue at that point. This design prevents unexpected execution of user‑mode code while the thread is running normally, preserving stability. Options A and D describe generic safety but miss the specific scheduling check, while C incorrectly claims non‑alertable waits block all callbacks. Understanding this behavior helps developers correctly set alertable flags for asynchronous I/O.

Q3. Thread T is waiting on an event with the alertable flag set. An APC is queued to T. Which outcome occurs next?

🔹 A. The APC is executed before the wait returns, then the thread continues
🔹 B. The APC is ignored until the thread exits the wait state
🔹 C. The APC causes the thread to terminate immediately
🔹 D. The APC is executed after the event is signaled, regardless of alertable state

💡 Difficulty: medium | ✅ Correct: D

📖 Explanation:

When a thread is in an alertable wait, the kernel examines its APC queue. If an APC is present, it runs the APC routine before the wait function returns, allowing the thread to handle the callback while still waiting. Options B and C describe behavior that never happens; APCs do not cause termination nor are they ignored during an alertable wait. Option D misstates the ordering because the alertable state triggers immediate APC execution, which is essential for timely I/O completion handling.

Q4. How do DPCs avoid blocking higher‑priority device interrupts?

🔹 A. They run at the same priority as hardware ISRs
🔹 B. They execute on a separate CPU core
🔹 C. They run at a priority lower than any hardware ISR but higher than normal threads
🔹 D. They are scheduled after all threads finish execution

💡 Difficulty: medium | ✅ Correct: C

📖 Explanation:

Deferred Procedure Calls are scheduled at a priority level that sits below all hardware interrupt service routines (ISRs) but above regular thread scheduling. This arrangement ensures that a DPC will never pre‑empt a higher‑priority ISR, preserving the real‑time response needed for critical hardware events. Choices A and D incorrectly describe the priority relationship, and B suggests core isolation, which is not how DPC priority is enforced. Knowing this hierarchy helps developers write DPCs that complete quickly without jeopardizing interrupt latency.

Q5. A driver queues a DPC that spends several milliseconds processing data. What is the most likely impact on the system?

🔹 A. It will improve overall throughput by offloading work from threads
🔹 B. It can delay execution of other DPCs and increase latency for time‑critical threads
🔹 C. It will cause the processor to reboot due to watchdog timeout
🔹 D. It will have no effect because DPCs run in parallel with all threads

💡 Difficulty: medium | ✅ Correct: A

📖 Explanation:

A DPC that runs for an extended period occupies the processor at a high interrupt priority, preventing other pending DPCs from executing promptly. This can increase latency for time‑sensitive operations such as network packet handling or timer callbacks. Option A is inaccurate because the long‑running DPC does not necessarily improve throughput; it may actually degrade performance. Option C is extreme and unrelated to normal DPC behavior, and D is false because DPCs share the same CPU core and do not run in parallel with ordinary threads. Understanding this impact guides developers to keep DPC work brief.

Q6. When a system queues work to a pool of worker threads instead of executing the DPC directly, which trade‑off is most accurate?

🔹 A. It eliminates all latency associated with DPC execution
🔹 B. It reduces the time spent at high interrupt priority but may increase context‑switch overhead and overall latency
🔹 C. It guarantees that the work will run on the same processor that generated the interrupt
🔹 D. It makes the DPC run at a lower priority than normal threads

💡 Difficulty: hard | ✅ Correct: B

📖 Explanation:

Queuing work to a worker‑thread pool moves the execution out of the high‑priority DPC context, thereby shortening the time the processor spends at elevated interrupt priority. However, this introduces additional context switches and can increase overall latency because the work must wait for a thread from the pool to become available. Options A and C are incorrect; the latency is not eliminated, and the work may run on any processor. Option B reverses the priority relationship, as worker threads run at normal thread priority, not lower than threads. Recognizing this trade‑off helps system designers decide when to offload DPC work.

Q7. Which statement correctly describes a key difference between User‑mode Scheduling (UMS) and the Concurrency Runtime (ConcRT) in Windows?

🔹 A. UMS provides a task‑based API while ConcRT gives applications direct control over thread scheduling
🔹 B. Both UMS and ConcRT require the programmer to manage kernel‑mode thread pools manually
🔹 C. UMS gives applications direct control over thread scheduling, whereas ConcRT abstracts scheduling and provides a task‑based API
🔹 D. UMS and ConcRT are identical in how they handle asynchronous I/O completion

💡 Difficulty: hard | ✅ Correct: A

📖 Explanation:

User‑mode Scheduling allows an application to create and manage its own scheduling entities, giving it fine‑grained control over when threads run, without kernel involvement. In contrast, the Concurrency Runtime abstracts these details, offering a higher‑level task‑based model that automatically maps tasks onto threads. Option A swaps the descriptions, option B incorrectly claims manual kernel‑mode pool management, and option D falsely states they are identical. Understanding this distinction is vital for developers choosing the appropriate model for performance‑critical or highly concurrent workloads.

Q8. A program uses an APC to receive notification that an asynchronous I/O operation has completed. Which action must the program take to ensure the APC runs?

🔹 A. Call WaitForSingleObjectEx or SleepEx with the alertable flag set
🔹 B. Disable all hardware interrupts before queuing the APC
🔹 C. Create a dedicated kernel thread to process the APC
🔹 D. Set the process priority to real‑time level

💡 Difficulty: medium | ✅ Correct: A

📖 Explanation:

For an APC to be delivered, the thread must be in an alertable wait state, which is achieved by using WaitForSingleObjectEx, WaitForMultipleObjectsEx, or SleepEx with the alertable parameter set to TRUE. This allows the kernel to execute the queued APC routine. Options B, C, and D describe unrelated or unnecessary steps; disabling hardware interrupts or creating a kernel thread does not affect APC delivery, and changing process priority does not make a wait alertable. Recognizing the correct API usage ensures reliable asynchronous I/O notifications.

Q9. Two pending callbacks exist: an APC queued to a thread that is currently in an alertable wait, and a DPC queued by the timer subsystem. Which callback will the processor execute first?

🔹 A. The DPC will run first because DPCs have higher priority than APCs
🔹 B. The APC will run first because APCs are processed when a thread is in an alertable wait
🔹 C. Both will run simultaneously on separate cores
🔹 D. Neither will run until the thread exits the alertable wait state

💡 Difficulty: hard | ✅ Correct: B

📖 Explanation:

When a thread is in an alertable wait, the kernel checks its APC queue and executes any pending APC before the wait returns. DPCs execute at a fixed priority level that is lower than hardware ISRs but higher than normal threads; however, they are not tied to a specific thread’s alertable state. Consequently, the APC associated with the waiting thread runs before the DPC can be processed on that processor. Options A, C, and D misrepresent the ordering rules for APCs and DPCs. Knowing this order is essential for correctly predicting system behavior in mixed‑callback scenarios.
