Q1. A process with a 200 MB working set receives a hard limit of 150 MB. During a period of high CPU activity, the VM manager must trim pages. Which action best follows the manager’s policy for trimming?

🔹 A. Trim the newest pages first until the working set is exactly 150 MB.
🔹 B. Remove the oldest unreferenced pages first, even if the set falls below 150 MB.
🔹 C. Select pages randomly to meet the 150 MB target.
🔹 D. Trim pages only when physical memory is critically low.

💡 Difficulty: medium | ✅ Correct: B

📖 Explanation:

Option B is correct because the VM manager ages pages based on their last reference and removes the oldest unreferenced ones first, ensuring that only pages not recently used are trimmed while keeping the working set above the hard limit when possible. Option A is wrong; the policy does not target the newest pages. Option C is incorrect since trimming is not random. Option D is inaccurate because trimming can occur even when memory is not critically low if a hard limit is set. This reflects the manager’s goal to preserve active data while respecting limits.

Q2. A page-file PTE contains a 32‑bit offset field and a 4‑bit paging‑file selector. If the offset stored is 0x00A3F5C0 and the selector bits are 0110, what is the byte location on disk for this page assuming each paging file starts at byte 0?

🔹 A. Byte 0x00A3F5C0 in paging file 3.
🔹 B. Byte 0x00A3F5C0 in paging file 6.
🔹 C. Byte 0x00A3F5C0 in paging file 0.
🔹 D. Byte 0x00A3F5C0 in paging file 12.

💡 Difficulty: hard | ✅ Correct: B

📖 Explanation:

Option B is correct because the 32‑bit offset field directly gives the byte position within the selected paging file, and the selector bits 0110 represent the decimal value 6, indicating paging file 6. Thus the page resides at byte 0x00A3F5C0 in that file. Option A uses the wrong file number (3). Option C assumes a selector of 0, which is not the case. Option D suggests a file number 12, exceeding the 4‑bit range (max 15) but not matching the selector. Understanding the bit fields lets the system locate pages accurately, which is essential for fault recovery.

Q3. Why does Windows use a per‑working‑set least‑recently‑used (LRU) replacement policy instead of a global LRU?

🔹 A. Because per‑working‑set LRU reduces CPU overhead by limiting scans to each process.
🔹 B. Because a global LRU would require more disk space for page tables.
🔹 C. Because per‑working‑set LRU guarantees that all processes get equal memory.
🔹 D. Because a global LRU cannot track page references.

💡 Difficulty: easy | ✅ Correct: A

📖 Explanation:

Option A is correct because a per‑working‑set LRU only examines pages belonging to a single process, reducing the amount of data the VM manager must scan and thus lowering CPU overhead. Option B is wrong; paging file size does not depend on the replacement policy. Option C is inaccurate because equal memory distribution is not guaranteed by the policy. Option D is false because a global LRU can track references, but it is more costly. The per‑process approach balances performance with fairness, fitting Windows’ design goals.

Q4. How many bits are allocated for the page‑file offset in a page‑file PTE?

🔹 A. 32
🔹 B. 20
🔹 C. 5
🔹 D. 4

💡 Difficulty: easy | ✅ Correct: A

📖 Explanation:

The page‑file offset field stores the location of the page on disk, and the specification defines it as 32 bits wide. Therefore option A is correct. Options B, C, and D refer to other fields: 20 bits are reserved for bookkeeping, 5 bits hold protection flags, and 4 bits select the paging file. Knowing the bit allocation helps the OS locate pages efficiently during paging operations.

Q5. What does it indicate when the T, P, and V bits are all zero in a page‑file PTE?

🔹 A. The page is resident in physical memory
🔹 B. The page is not present and not dirty
🔹 C. The page is locked for exclusive access
🔹 D. The page is part of a RAID volume

💡 Difficulty: easy | ✅ Correct: B

📖 Explanation:

When T (transition), P (present), and V (valid) bits are zero, the entry describes a page that is not currently in physical memory and has not been modified, so it is not dirty. Option B captures this meaning. Option A is opposite (page would be present), option C describes a lock state not encoded by these bits, and option D is unrelated to paging structures. This interpretation guides the VM manager when deciding whether to read the page from disk.

Q6. Why does Windows prefer a per‑working‑set LRU replacement policy instead of a single global LRU for all processes?

🔹 A. It reduces contention by handling each process separately
🔹 B. It ensures equal memory distribution regardless of process activity
🔹 C. It allows the system to ignore page references
🔹 D. It simplifies the paging file structure

💡 Difficulty: medium | ✅ Correct: A

📖 Explanation:

A per‑working‑set LRU keeps age information local to each process, so the OS does not need to lock a global list each time a page is referenced, reducing contention and improving scalability. Option A states this benefit. Option B is false because memory is allocated based on demand, not equality. Option C misrepresents the policy’s purpose, and option D is unrelated to replacement strategy. Understanding this design explains why trimming can be done independently per process.

Q7. Process A has a hard working‑set limit of 200 MB while Process B has no limit. Both are running on a system with 4 GB RAM and 3 GB free. Which outcome is most likely when memory pressure increases?

🔹 A. Process A will be trimmed first, even though it uses less memory
🔹 B. Process B will be trimmed first because it has no limit
🔹 C. Both processes will be trimmed equally
🔹 D. No trimming will occur because enough free memory exists

💡 Difficulty: medium | ✅ Correct: A

📖 Explanation:

When memory becomes scarce, the VM manager first enforces hard limits; Process A cannot exceed 200 MB, so its pages are candidates for trimming regardless of overall free memory. Option A reflects this rule. Option B reverses the priority, option C suggests equal treatment which ignores hard limits, and option D is incorrect because the system will still trim to protect overall stability. This scenario shows how hard limits drive trimming decisions.

Q8. A process has 150 pages in its working set. The VM manager increments the age of pages not referenced in the last pass. If 30 pages have age 3, 50 pages have age 2, and the rest have age 1, and the system decides to trim pages with age ≥ 2, how many pages will be removed?

🔹 A. 30
🔹 B. 50
🔹 C. 80
🔹 D. 120

💡 Difficulty: medium | ✅ Correct: C

📖 Explanation:

Pages with age 3 and age 2 are eligible for trimming. Adding them gives \(30+50=80\) pages, so option C is correct. Option A counts only the age‑3 pages, option B counts only the age‑2 pages, and option D exceeds the total eligible pages. This calculation demonstrates how the VM manager uses age thresholds to decide which pages to evict under pressure.

Q9. How do the 5 bits reserved for page protection in a page‑file PTE affect the handling of a page that has been written to?

🔹 A. They indicate the page can be executed but not read
🔹 B. They store the original protection to restore after paging
🔹 C. They flag the page as dirty for write‑back
🔹 D. They are unused for written pages

💡 Difficulty: medium | ✅ Correct: B

📖 Explanation:

The protection bits remember the access rights (read, write, execute) that were in effect before the page was swapped out, allowing the OS to restore those rights when the page is read back. Hence option B is correct. Option A misstates the purpose, option C confuses protection with the dirty flag (which is separate), and option D incorrectly claims the bits are unused. Proper handling of these bits ensures security and correctness after paging.

Q10. Suppose a server runs two virtual machines, VM‑X and VM‑Y. VM‑X has a working‑set limit of 1 GB and currently uses 800 MB with 200 MB of pages aged 4. VM‑Y has no limit and uses 1.2 GB with all pages aged 1. If the system must free 300 MB, which set of pages will the VM manager likely select for trimming?

🔹 A. 200 MB from VM‑X (age 4) and 100 MB from VM‑Y (age 1)
🔹 B. 300 MB from VM‑X (age 4)
🔹 C. 300 MB from VM‑Y (age 1)
🔹 D. 200 MB from VM‑X (age 4) and 100 MB from VM‑X (age 2)

💡 Difficulty: hard | ✅ Correct: D

📖 Explanation:

Because VM‑X has a hard limit and contains the oldest pages (age 4), the manager will first trim those 200 MB. To reach the required 300 MB, it will continue trimming the next oldest pages from VM‑X, which are at age 2, adding another 100 MB. Option D matches this behavior. Option A mixes in VM‑Y pages despite younger age, option B cannot supply enough memory, and option C ignores the hard‑limit priority. This illustrates how age and limits guide trimming under severe pressure.

Q11. What is the primary reason the VM manager increments page ages only for pages that have not been marked as referenced since the last pass?

🔹 A. To ensure pages are never evicted
🔹 B. To prioritize pages that have been recently accessed for retention
🔹 C. To randomize page selection
🔹 D. To synchronize with RAID parity updates

💡 Difficulty: hard | ✅ Correct: B

📖 Explanation:

The VM manager uses the reference bit to detect recent activity; pages not referenced are considered unused and have their age increased, making them more likely to be evicted. This keeps frequently accessed pages in memory. Option B captures this logic. Option A is opposite, option C suggests randomness which is not used, and option D introduces an unrelated RAID concept. Recognizing this mechanism explains why recent usage protects pages from being trimmed.

Q12. What is the primary purpose of sector sparing in storage devices?

🔹 A. Increase the drive's read speed
🔹 B. Replace bad sectors with reserved spare sectors
🔹 C. Compress data to save space
🔹 D. Encrypt all stored data

💡 Difficulty: easy | ✅ Correct: B

📖 Explanation:

Sector sparing exists to keep a drive usable after a physical defect appears. When a sector becomes unreadable, the controller swaps it with a pre‑allocated spare sector, so the logical address still maps to a good location. This does not affect speed, compression, or encryption, so options A, C, and D are incorrect. In real systems, sparing lets users continue normal operation despite isolated defects.

Q13. Why does cluster remapping usually provide better data integrity than simple sector replacement?

🔹 A. It spreads data across multiple drives
🔹 B. It groups adjacent bad sectors into a single remapped cluster
🔹 C. It encrypts the data before writing
🔹 D. It reduces the number of write cycles on flash cells

💡 Difficulty: medium | ✅ Correct: C

📖 Explanation:

Cluster remapping groups a set of contiguous bad sectors into a larger logical unit that can be redirected to a healthy area, preserving the relationship among neighboring blocks. Simple sector replacement only fixes one location and may leave surrounding data vulnerable. Encryption (option D) is unrelated, and spreading data across drives (option A) describes RAID, not remapping. Grouping bad sectors (option B) is part of remapping, but the integrity gain comes from maintaining logical continuity, which is why C is correct.

Q14. How does sector sparing influence wear‑leveling strategies in solid‑state drives (SSDs)?

🔹 A. It forces wear‑leveling to ignore spare blocks
🔹 B. It reduces the need for wear‑leveling because bad blocks are removed
🔹 C. It adds additional spare blocks that wear‑leveling can use
🔹 D. It has no effect on wear‑leveling at all

💡 Difficulty: medium | ✅ Correct: A

📖 Explanation:

When a SSD marks a block as bad, sector sparing provides a spare block that can be written to later. Wear‑leveling algorithms can then include these spares in their rotation, spreading erase cycles more evenly across the device. Ignoring spares (A) would shorten lifespan, and claiming reduced wear‑leveling need (B) is false because the drive still requires balanced usage. Saying there is no effect (D) ignores the practical role spares play, making C the correct answer.

Q15. A hard drive reports three consecutive bad sectors. Which technique should the controller use to preserve usable capacity?

🔹 A. Sector sparing with a single spare per bad sector
🔹 B. Cluster remapping of the three sectors into one larger logical block
🔹 C. Reformat the drive and discard the bad region
🔹 D. Ignore the bad sectors and continue operation

💡 Difficulty: easy | ✅ Correct: B

📖 Explanation:

When bad sectors appear consecutively, the simplest method is to replace each with its own spare sector, a process known as sector sparing. Cluster remapping (option B) is more appropriate for larger groups or when spares are scarce, but using individual spares maintains the original logical layout. Reformatting (C) would erase all data, and ignoring the defects (D) would cause data loss, so option A is the correct, practical response.

Q16. After a firmware update, the logical‑to‑physical mapping of a drive changes. Which method ensures previously spared sectors remain correctly referenced?

🔹 A. Re‑initialize all spare sectors as new blocks
🔹 B. Perform a full surface scan and rebuild the mapping table
🔹 C. Apply a translation layer that maps old spare addresses to new physical locations
🔹 D. Delete the spare sectors and rely on error‑correction codes

💡 Difficulty: hard | ✅ Correct: C

📖 Explanation:

Firmware updates can alter how logical addresses map to physical locations, but the drive must still know where its reserved spares reside. A translation layer (option C) preserves the relationship by converting old spare identifiers to the new physical addresses. Re‑initializing spares (A) would lose the history of which sectors were bad. A full scan (B) is costly and unnecessary for just the spares, and deleting spares (D) would expose the system to unrecoverable errors. Therefore, option C correctly maintains continuity.

Q17. Which statement best describes the performance trade‑off when using sector sparing versus cluster remapping?

🔹 A. Sector sparing adds minimal latency, while cluster remapping can increase read/write latency due to larger remapped regions
🔹 B. Cluster remapping eliminates latency entirely, unlike sector sparing which slows the drive
🔹 C. Both techniques have identical performance impacts
🔹 D. Sector sparing always degrades performance more than cluster remapping

💡 Difficulty: medium | ✅ Correct: A

📖 Explanation:

Sector sparing swaps a single bad sector with a spare, so the access time change is negligible. Cluster remapping, however, redirects an entire group of sectors, potentially causing the controller to handle larger, less optimal regions, which can raise latency for reads and writes. Options B and D exaggerate the effects, and C ignores the differing overheads. Thus, option A accurately captures the real‑world performance implications.

Q18. In SMART reporting, how is a sector‑sparing event distinguished from a remapped‑cluster event, and what does each indicate about drive health?

🔹 A. Sparing events are logged as “Reallocated_Sector_Count”, clusters as “Current_Pending_Sector”
🔹 B. Sparing events raise “Offline_Uncorrectable”, clusters raise “Seek_Error_Rate”
🔹 C. Sparing events increment “Reallocated_Sector_Count”, clusters increment “Reallocated_Event_Count”
🔹 D. Both events use the same SMART attribute, so they cannot be distinguished

💡 Difficulty: hard | ✅ Correct: C

📖 Explanation:

SMART defines separate attributes: “Reallocated_Sector_Count” tracks individual sectors replaced via sparing, while “Reallocated_Event_Count” records larger remapping actions such as cluster remapping. Therefore, a rise in the former signals isolated defects, whereas an increase in the latter suggests more extensive damage. Options A and B mix unrelated attributes, and D is incorrect because SMART does differentiate the events. Understanding this distinction helps technicians assess whether a drive is experiencing minor wear or a systemic failure.

Q19. Design a storage system that must tolerate up to \(5\%\) sector failure without noticeable performance loss. Which combination of sector sparing and cluster remapping best meets this requirement?

🔹 A. Use sector sparing for the first \(2\%\) of failures and cluster remapping for the remaining \(3\%\)
🔹 B. Apply cluster remapping exclusively for all failures
🔹 C. Reserve \(10\%\) of total capacity as spares and never use cluster remapping
🔹 D. Mix sector sparing and cluster remapping, allocating spares for isolated defects and remapping clusters for contiguous failures

💡 Difficulty: hard | ✅ Correct: A

📖 Explanation:

To handle up to \(5\%\) faulty sectors while keeping performance steady, the system should employ both techniques: sector sparing quickly replaces isolated bad blocks, preserving normal access patterns, while cluster remapping efficiently deals with groups of adjacent failures, preventing large‑scale fragmentation. Option A arbitrarily splits the failure range, which may not match actual defect patterns. Exclusively using cluster remapping (B) could increase latency, and reserving a large spare pool (C) wastes capacity. Hence, option D offers the balanced, real‑world solution.
