Q1. What is the primary purpose of an Asynchronous Procedure Call (APC) in the Windows operating system?

🔹 A. To suspend, resume, or terminate threads and deliver I/O completion notifications
🔹 B. To handle hardware interrupts directly
🔹 C. To schedule timer expirations
🔹 D. To replace the dispatcher’s role in thread scheduling

💡 Difficulty: easy | ✅ Correct: A

📖 Explanation:

APCs are designed to run in the context of a specific thread and are used for operations such as suspending, resuming, or terminating that thread, as well as notifying the thread that an asynchronous I/O operation has finished. Options B, C, and D describe other mechanisms: hardware interrupts are handled by ISRs, timer expirations are processed by DPCs, and thread scheduling is managed by the dispatcher, not by APCs.

Q2. Why are user‑mode APCs executed only when a thread is in an alertable wait state?

🔹 A. Because the kernel must be idle
🔹 B. Because alertable waits indicate the thread can safely run asynchronous code without disrupting critical kernel operations
🔹 C. Because APCs need a dedicated CPU core
🔹 D. Because alertable waits increase thread priority

💡 Difficulty: medium | ✅ Correct: A

📖 Explanation:

An alertable wait tells the kernel that the thread is willing to run asynchronous code at a point where it is not holding critical resources. This prevents APCs from interrupting the thread while it is performing non‑reentrant operations, ensuring system stability. Option A is incorrect because the kernel can be busy; Option C is false because APCs share the CPU; Option D misinterprets priority effects.

Q3. How does the priority ordering between Deferred Procedure Calls (DPC) and normal threads influence overall system responsiveness?

🔹 A. DPCs run at lower priority than threads, ensuring threads always get CPU first
🔹 B. DPCs run at the same priority as threads, causing no impact on responsiveness
🔹 C. DPCs run at a higher priority than threads but lower than hardware interrupts, allowing quick completion of interrupt work while preventing long DPCs from starving threads
🔹 D. DPCs preempt threads at any time, which can lead to instability

💡 Difficulty: medium | ✅ Correct: A

📖 Explanation:

DPCs are scheduled after hardware interrupts but before normal thread execution, so they can finish urgent interrupt processing quickly while still yielding the CPU to regular threads. This balance keeps the system responsive. Option A reverses the priority relationship; Option B suggests equal priority, which is not true; Option D exaggerates DPC power, which could cause instability if DPCs preempt threads indiscriminately.

Q4. A developer needs to pause a running thread without risking deadlock. Which mechanism should be used to safely suspend the thread?

🔹 A. Terminate the thread directly
🔹 B. Use a critical section to block the thread
🔹 C. Queue an APC that calls NtSuspendThread on the target thread
🔹 D. Raise the thread’s priority to maximum

💡 Difficulty: medium | ✅ Correct: A

📖 Explanation:

Queuing an APC that invokes NtSuspendThread allows the target thread to be suspended at a safe point, typically when it enters an alertable state, avoiding deadlock. Terminating the thread (A) is abrupt and unsafe; using a critical section (B) can cause deadlock if the thread holds the lock; raising priority (D) does not pause execution. The APC approach leverages the OS’s built‑in mechanism for controlled suspension.

Q5. System logs show increased latency because DPC routines are taking too long. Which strategy best mitigates this problem while preserving timely interrupt handling?

🔹 A. Move the lengthy work from the DPC to a worker thread via a queued work item
🔹 B. Increase the DPC priority above all hardware interrupts
🔹 C. Disable DPC processing temporarily
🔹 D. Convert the DPC into a kernel‑mode APC

💡 Difficulty: hard | ✅ Correct: B

📖 Explanation:

Offloading the heavy computation to a worker thread frees the DPC to finish quickly, maintaining prompt interrupt response while preventing long DPC execution from delaying other tasks. Raising DPC priority (B) would interfere with hardware interrupts; disabling DPCs (C) would postpone essential processing; converting to a kernel‑mode APC (D) does not solve the latency issue because APCs still run in thread context and can be delayed. The queued work‑item solution follows best practice for handling lengthy DPC work.)
