📝 SCAN scheduling in Disk Scheduling

📖 From Operating System • 10. Mass Storage Structure • 9 questions available

What is SCAN scheduling in Disk Scheduling?

Definition:
SCAN scheduling moves the disk arm continuously in one direction servicing requests until reaching the end, then reverses direction like an elevator.

Example:
Starting at 53 moving toward higher cylinders with queue [98, 183, 37, 122], SCAN services 98→122→183 then reverses to service 37.

Reason:
SCAN prevents starvation and provides more uniform response times than SSTF while maintaining reasonable throughput through directional batching.

Q1. What is the primary characteristic of the SCAN disk‑scheduling algorithm?

A. It serves requests in the order they arrive, without reordering
B. It moves the disk arm back and forth across the cylinder range, servicing requests in one direction before reversing ✅
C. It always jumps to the furthest request then returns to the start
D. It selects the request with the shortest seek distance

💡 Difficulty: easy | ✅ Correct: B

📖 Explanation:

The SCAN algorithm, often called the elevator algorithm, moves the head in one direction, servicing all pending requests it encounters, then reverses at the outer or inner edge of the disk. This matches option B. Option A describes FCFS, which does not reorder requests. Option C describes C‑SCAN, which jumps back without servicing on the return. Option D describes SSTF, which chooses the nearest request. SCAN’s systematic sweep reduces overall seek time in typical hard‑disk workloads.

Q2. Why does the SCAN algorithm typically produce less variance in request waiting times than FCFS?

A. Because it always chooses the nearest request, leading to minimal movement
B. Because it groups requests by cylinder, reducing rotational latency only
C. Because it sweeps across the cylinder range in a predictable pattern, preventing long gaps between services ✅
D. Because it ignores request order, causing equal wait times for all requests

💡 Difficulty: medium | ✅ Correct: C

📖 Explanation:

SCAN creates a predictable head‑movement pattern: the arm travels from one end of the disk to the other, serving every request encountered. This regular motion prevents a request from waiting an unusually long time, which can happen under FCFS when a large request arrives early and blocks later ones. Option C captures this effect. Option A describes SSTF, not SCAN. Option B mentions rotational latency but does not explain variance. Option D is inaccurate because SCAN does not ignore order; it follows a defined sweep.

Q3. How does the reversal of direction in the SCAN algorithm affect the average seek time?

A. It adds travel to the disk’s outermost cylinder, increasing average seek but avoiding starvation ✅
B. It eliminates the need to travel to the innermost cylinder, thereby decreasing average seek
C. It reduces total distance by skipping cylinders that have no pending requests
D. It has no impact on average seek time

💡 Difficulty: medium | ✅ Correct: A

📖 Explanation:

When SCAN reaches the extreme cylinder, the head must travel back across the entire range before servicing requests on the opposite side. This extra travel to the end (often an empty region) raises the average distance the head moves per request, but it also ensures that no request is ignored indefinitely. Option A describes this trade‑off. Option B is false because the head still visits both extremes. Option C misstates the algorithm’s behavior; SCAN does not skip cylinders. Option D is incorrect because reversal clearly changes the distance traveled.

Q4. A disk has pending requests at cylinders 55, 58, 18, 90, 150, and 38. The head is currently at cylinder 50 and is moving outward. Assuming the maximum cylinder number is 200, what total head movement will SCAN produce?

A. 282 cylinders
B. 332 cylinders ✅
C. 294 cylinders
D. 310 cylinders

💡 Difficulty: medium | ✅ Correct: B

📖 Explanation:

First the head moves from 50 to 55 (+5), then to 58 (+3), 90 (+32), and 150 (+60). It continues to the outer limit at 200 (+50) before reversing. On the return it travels to 38 (+162) and finally to 18 (+20). Summing these distances gives \(5+3+32+60+50+162+20 = 332\) cylinders. Option B matches this total. The other options result from omitting one of the segments or mis‑ordering the requests, which would not follow SCAN’s outward‑then‑inward sweep.

Q5. Given an initial head position of 50 moving outward, and pending requests at cylinders 10, 22, 38, 43, 55, 73, 84, and 95, what is the average seek distance per request under SCAN (max cylinder 200)?

A. 42.5 cylinders ✅
B. 45.0 cylinders
C. 40.0 cylinders
D. 38.0 cylinders

💡 Difficulty: hard | ✅ Correct: A

📖 Explanation:

The SCAN order outward is 55, 73, 84, 95, then to 200, and back to 43, 38, 22, 10. Head movements are \(50\!\to\!55 =5\), \(55\!\to\!73 =18\), \(73\!\to\!84 =11\), \(84\!\to\!95 =11\), \(95\!\to\!200 =105\), \(200\!\to\!43 =157\), \(43\!\to\!38 =5\), \(38\!\to\!22 =16\), and \(22\!\to\!10 =12\). Adding them yields a total of \(340\) cylinders. Dividing by the eight requests gives an average of \(340/8 = 42.5\) cylinders. Option A reflects this calculation. The other choices arise from incorrect totals or dividing by the wrong number of requests.

Q6. A system currently uses SCAN for disk I/O. If it switches to C‑SCAN, which of the following is the most likely effect on overall throughput?

A. Throughput will increase because C‑SCAN provides more uniform head movement ✅
B. Throughput will decrease because C‑SCAN adds extra seek overhead
C. Throughput will remain unchanged because both algorithms move the head the same distance
D. Throughput becomes unpredictable due to random jumps

💡 Difficulty: medium | ✅ Correct: A

📖 Explanation:

C‑SCAN always returns the head to the beginning of the disk without servicing requests on the return trip, creating a consistent, one‑direction sweep. This eliminates the extra back‑track travel that SCAN performs, reducing unnecessary head movement and often raising the number of requests completed per unit time. Therefore throughput is expected to increase, matching option A. Option B is opposite of the typical effect. Option C ignores the reduction in back‑track distance, and option D mischaracterizes C‑SCAN as random, which it is not.

Q7. Which statement best describes the difference between SCAN and C‑SCAN regarding fairness and starvation?

A. SCAN can cause starvation of requests near the middle, while C‑SCAN eliminates starvation
B. C‑SCAN provides more uniform wait times, whereas SCAN may favor requests in one direction ✅
C. SCAN always yields lower average seek time than C‑SCAN
D. C‑SCAN cannot be implemented on modern disks

💡 Difficulty: hard | ✅ Correct: B

📖 Explanation:

C‑SCAN moves the head in one direction only, then jumps back instantly, giving every request an equal chance to be served on the next sweep, which leads to more uniform waiting periods. SCAN, by contrast, services requests while moving outward and then inward, so requests that lie just after the reversal point may wait longer than those encountered earlier, creating a potential fairness issue. Option B captures this nuance. Option A incorrectly claims SCAN causes starvation, which is rare. Option C is not guaranteed; average seek can be similar. Option D is false because C‑SCAN is widely used.

Q8. A disk queue contains the following pending requests: (30,R), (70,W), (20,R), (90,W), (50,R). The head is at cylinder 40 moving outward. If writes are given priority within each SCAN sweep, in which order will the requests be serviced?

A. 70W, 90W, 30R, 50R, 20R
B. 50R, 70W, 90W, 30R, 20R
C. 70W, 90W, 50R, 30R, 20R ✅
D. 70W, 90W, 30R, 20R, 50R

💡 Difficulty: medium | ✅ Correct: C

📖 Explanation:

Moving outward from 40, the head first encounters cylinders greater than 40: 50R, 70W, and 90W. Because writes have priority, the algorithm will serve 70W then 90W before the read at 50R. After reaching the outer limit, the head reverses and services the remaining reads in decreasing order: 30R then 20R. Thus the service sequence is 70W, 90W, 50R, 30R, 20R, which corresponds to option C. The other options either ignore write priority or misorder the reversal.

Q9. A database server frequently reads large sequential files from a hard‑disk. Which scheduling algorithm would most likely improve its performance?

A. SCAN ✅
B. FCFS
C. Random
D. Priority

💡 Difficulty: easy | ✅ Correct: A

📖 Explanation:

When large sequential reads dominate, an algorithm that minimizes head movement across the disk surface is advantageous. SCAN sweeps the head across the cylinder range, reducing the distance between consecutive requests and taking advantage of the sequential nature of the data. This typically yields faster access than FCFS, which follows arrival order, or Random, which adds unnecessary seeks. Priority scheduling would not address the underlying seek cost. Therefore SCAN is the best choice, as indicated by option A.
