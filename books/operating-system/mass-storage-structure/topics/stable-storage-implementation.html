📝 Stable Storage Implementation

📖 From Operating System • 10. Mass Storage Structure • 14 questions available

What is Stable Storage Implementation?

Definition:
Stable storage guarantees atomic persistence of critical data through redundant writes to independent non-volatile media with verification and recovery protocols.

Example:
A transaction log entry is written to two physically separate disks with checksum \( H(d) \), confirmed only after both acknowledgments succeed.

Reason:
This implementation survives single-point failures including power loss and media corruption, providing the durability foundation required for database ACID properties and crash recovery.

Q1. A disk scheduler receives the request queue {98, 183, 37, 122, 14, 124, 65, 67} and the head is currently at cylinder \(53\). Using the C‑LOOK algorithm, which cylinder will be serviced next?

A. 65 ✅
B. 67
C. 14
D. 98

💡 Difficulty: easy | ✅ Correct: A

📖 Explanation:

The C‑LOOK algorithm services requests in increasing cylinder order starting from the current head position, then jumps directly to the lowest pending request. Since the head is at \(53\), the next higher request in the queue is \(65\). Therefore option A is correct. Options B, C, and D refer to later or lower cylinders that are not the immediate next target.

Q2. A server experiences a high volume of random disk requests, causing frequent head starvation with SSTF. Which scheduling algorithm is most likely to prevent starvation while maintaining good throughput?

A. FCFS
B. SSTF
C. SCAN ✅
D. LOOK

💡 Difficulty: medium | ✅ Correct: C

📖 Explanation:

SCAN moves the disk arm in one direction servicing all pending requests before reversing, which prevents any request from being ignored indefinitely, unlike SSTF that may keep serving nearby requests. SCAN therefore reduces starvation risk while still providing reasonable throughput. FCFS processes in arrival order without optimizing movement, SSTF can cause starvation, and LOOK is similar to SCAN but stops at the last request, making SCAN the better answer for the described condition.

Q3. If a program reads a file stored contiguously from cylinder \(20\) to \(30\), while another program reads an indexed file with blocks at cylinders \(5\), \(45\), \(80\), and \(120\), which program will cause more total head movement on average?

A. The program reading the contiguous file
B. The program reading the indexed file ✅
C. Both will cause equal movement
D. It depends on the initial head position

💡 Difficulty: medium | ✅ Correct: B

📖 Explanation:

The indexed file accesses blocks that are widely scattered, forcing the head to travel large distances between each block, whereas the contiguous file keeps the head within a small range of cylinders. Hence the indexed file program generates more head movement on average. The initial head position could affect the first seek but does not change the overall larger distance traveled for the indexed file, making option B correct.

Q4. Given the request queue {98, 183, 37, 122, 14, 124, 65, 67} and a head starting at cylinder \(53\), what is the total number of cylinders the head moves under C‑LOOK (excluding the wrap‑around jump)?

A. 145
B. 150
C. 158
D. 153 ✅

💡 Difficulty: hard | ✅ Correct: D

📖 Explanation:

C‑LOOK services requests in increasing order from the current head position: \(65\) → \(67\) → \(98\) → \(122\) → \(124\) → \(183\); then it jumps to the lowest request \(14\) and continues to \(37\). The distances are \(12+2+31+24+2+59+23 = 153\) cylinders. Option D matches this sum. The other options are close but do not reflect the correct cumulative distance, so D is the right answer.

Q5. In a file system where directory entries reside on cylinder \(0\) and file data begins on the last cylinder \(199\), what is the minimum head movement required to open a file and read its first block?

A. 199 cylinders ✅
B. 100 cylinders
C. 0 cylinders
D. 199 minus current head position

💡 Difficulty: medium | ✅ Correct: A

📖 Explanation:

To open a file, the head must first read the directory at cylinder \(0\) and then move to the file’s data at cylinder \(199\). This requires traveling the full span of the disk, which is \(199\) cylinders. Option A states this exact distance. Option D depends on an unspecified current head position, while options B and C underestimate the required movement, making A the correct choice.

Q6. A disk receives 80% sequential requests (near each other) and 20% random requests scattered across the disk. Which algorithm best balances response time for random requests while exploiting sequential locality?

A. FCFS
B. SSTF
C. C‑SCAN
D. LOOK ✅

💡 Difficulty: hard | ✅ Correct: D

📖 Explanation:

LOOK behaves like SCAN but stops at the last request in each direction, reducing unnecessary travel. This property lets it quickly serve sequential clusters while still moving in one direction, which improves response for scattered random requests compared to pure SSTF. FCFS does not optimize movement, SSTF can cause starvation, and C‑SCAN always returns to the start, adding extra travel. Therefore LOOK is the most balanced choice.

Q7. When the request queue contains only a single pending request, how do all disk‑scheduling algorithms behave relative to each other?

A. FCFS is fastest
B. All behave identically ✅
C. SSTF outperforms others
D. SCAN moves head back and forth

💡 Difficulty: easy | ✅ Correct: B

📖 Explanation:

With only one request, every algorithm has no choice but to move the head directly to that cylinder, making their behavior identical to FCFS. There is no opportunity for optimization or direction changes, so the correct answer is that all algorithms behave the same. Options A, C, and D describe behaviors that require multiple pending requests, which are not applicable here.

Q8. Why does the SCAN algorithm reduce the likelihood of starvation compared to SSTF?

A. It services requests in a fixed direction ✅
B. It always chooses the closest request
C. It randomly selects a request
D. It ignores request order

💡 Difficulty: easy | ✅ Correct: A

📖 Explanation:

SCAN moves the head monotonically in one direction, servicing every request encountered before reversing. This guarantees that any request will eventually be reached, preventing indefinite postponement. SSTF, by always picking the nearest request, can repeatedly skip far‑away requests, leading to starvation. Hence option A correctly explains the reduction in starvation risk.

Q9. How does the file allocation method influence disk head movement patterns?

A. Contiguous allocation clusters blocks, reducing movement ✅
B. Indexed allocation always places blocks together
C. Linked allocation eliminates movement
D. Allocation method has no effect

💡 Difficulty: medium | ✅ Correct: A

📖 Explanation:

When a file is stored contiguously, its blocks occupy consecutive cylinders, so the head moves only a short distance while reading the file. In contrast, indexed or linked allocations may locate blocks far apart, causing larger seeks. Therefore the allocation method directly impacts head movement, making option A the accurate statement. The other options misrepresent how indexed and linked allocations work.

Q10. Explain why C‑LOOK can achieve lower average seek time than SCAN in a system where requests are clustered near the outer cylinders.

A. C‑LOOK eliminates unnecessary travel to the innermost cylinder ✅
B. C‑LOOK always services the farthest request first
C. SCAN skips outer cylinders
D. Both have identical travel

💡 Difficulty: hard | ✅ Correct: A

📖 Explanation:

C‑LOOK only moves as far as the highest pending request before jumping back to the lowest, avoiding the extra sweep to the extreme inner cylinder that SCAN performs regardless of request distribution. When most requests lie near the outer edge, this saved travel reduces the average seek time. Options B, C, and D describe behaviors that are not true for C‑LOOK, so A is correct.

Q11. What is the primary reason that heavy disk load can cause starvation in SSTF?

A. SSTF always selects the nearest request, causing far requests to wait ✅
B. SSTF skips requests randomly
C. SSTF moves head only outward
D. SSTF has fixed service order

💡 Difficulty: medium | ✅ Correct: A

📖 Explanation:

Under heavy load, many requests are constantly arriving near the current head position. SSTF's rule of picking the closest request means those nearby requests keep getting serviced, while those farther away may never become the nearest, leading to starvation. The other options describe mechanisms not used by SSTF, so option A correctly identifies the cause.

Q12. In a stable‑storage implementation, why must write‑ahead logging be coordinated with disk‑scheduling algorithms?

A. To ensure that log records are written before the corresponding data blocks, preserving consistency even if the head moves ✅
B. To allow logs to be written after data
C. Because scheduling algorithms ignore logs
D. Logs are unrelated to storage stability

💡 Difficulty: hard | ✅ Correct: A

📖 Explanation:

Write‑ahead logging requires that the log entry reach stable storage before the actual data modification is flushed. Disk‑scheduling decisions affect the order and timing of these writes; if a data block were written before its log, a crash could leave the system inconsistent. Coordinating the scheduler ensures logs are prioritized appropriately. The other statements either reverse the correct order or claim no relationship, which is inaccurate.

Q13. What does the acronym SSTF stand for in disk scheduling?

A. Shortest Seek Time First ✅
B. Sequential Scan Transfer Function
C. Simple Seek Transfer Format
D. Systematic Service Timing Factor

💡 Difficulty: easy | ✅ Correct: A

📖 Explanation:

SSTF is commonly defined as Shortest Seek Time First, describing the algorithm that selects the pending request requiring the smallest head movement. The other options are fabricated expansions that do not match the accepted meaning, making option A the correct definition.

Q14. Which disk‑scheduling algorithm moves the head only in one direction and then jumps back to the beginning without servicing requests on the return?

A. SCAN
B. C‑LOOK ✅
C. FCFS
D. SSTF

💡 Difficulty: medium | ✅ Correct: B

📖 Explanation:

C‑LOOK operates by moving the head in a single direction, servicing all pending requests, and then quickly returning to the lowest pending request without servicing any cylinders on the return trip. This behavior matches the description. SCAN also moves in one direction but services requests on the way back, while FCFS and SSTF do not perform a jump‑back operation. Hence option B is correct.
