What is Improvement in performance via parallelism?

Definition:
RAID enhances performance by distributing I/O operations across multiple disks simultaneously, increasing aggregate bandwidth and reducing effective access latency.

Example:
Striping across n n n disks achieves theoretical throughput Tn=n×T1 T_n = n \times T_1 Tn​=n×T1​ for large sequential reads spanning all stripes.

Reason:
Parallelism exploits concurrent disk access to overcome individual device bandwidth limitations, scaling performance linearly with disk count for suitable workload patterns.

Q1. What is the primary characteristic of the C‑SCAN disk‑scheduling algorithm?

A.It moves the arm only to the nearest request and then reverses direction. ✅
B.It treats cylinders as a circular list, moving in one direction until the end, then jumps to the beginning.
C.It services requests in the order they arrive, without reordering.
D.It moves the arm back and forth across the entire disk repeatedly.
💡 Difficulty: easy | ✅ Correct: A

📖 Explanation: C‑SCAN treats the cylinders as a circular list; the arm moves in one direction, services all requests, reaches the highest cylinder, then instantly returns to the lowest cylinder and continues. This distinguishes it from algorithms that reverse direction. The other options describe FCFS, LOOK, or traditional SCAN behavior, which do not include the wrap‑around feature. Understanding this characteristic helps explain why C‑SCAN can provide more uniform wait times in real disk systems.

Q2. Why does LOOK scheduling often result in lower average seek time than the original SCAN algorithm?

A.Because LOOK skips servicing any request beyond the furthest request in the current direction.
B.Because LOOK always moves the arm to the outermost cylinder before reversing. ✅
C.Because LOOK services requests in random order to avoid bias.
D.Because LOOK only services requests that are currently pending, ignoring future arrivals.
💡 Difficulty: easy | ✅ Correct: B

📖 Explanation: LOOK modifies SCAN by stopping the arm at the last request in the current direction instead of traveling to the disk’s extreme. By avoiding unnecessary movement to empty cylinders, the total distance the arm travels is reduced, which directly lowers average seek time. The other choices either misdescribe the algorithm’s behavior or suggest random servicing, which is not how LOOK operates.

Q3. Given a disk with cylinders 0‑199, head at 53, and request queue 98, 183, 37, 122, 14, 124, 65, 67, which algorithm yields the smaller total head movement?

A.SCAN
B.C‑SCAN
C.Both produce the same total movement ✅
D.Neither algorithm is suitable for this workload
💡 Difficulty: medium | ✅ Correct: C

📖 Explanation: Calculating movements shows SCAN travels 53→65→67→98→122→124→183→14→37 for a total of 299 cylinders, while C‑SCAN adds the wrap‑around from 199 back to 0, increasing travel to 382 cylinders. Therefore SCAN results in less head movement. The “Both” option is incorrect because the distances differ, and “Neither” is false since both algorithms can handle the queue, though SCAN is more efficient here. This demonstrates how algorithm choice impacts performance in real disk scheduling.

Q4. Which statement best describes the performance advantage of C‑LOOK over C‑SCAN?

A.C‑LOOK reduces the number of cylinder jumps by only moving to the last request before wrapping.
B.C‑LOOK always moves the arm faster than C‑SCAN due to higher spindle speeds.
C.C‑LOOK services requests in the order they arrive, unlike C‑SCAN.
D.C‑LOOK uses multiple heads to read data simultaneously. ✅
💡 Difficulty: medium | ✅ Correct: D

📖 Explanation: C‑LOOK improves performance by limiting movement to the furthest request in the current direction before performing the circular jump, thereby eliminating unnecessary travel to empty cylinders that C‑SCAN includes. This reduction in movement shortens seek time and increases throughput. The other options incorrectly attribute speed improvements to hardware or FIFO ordering, which are not characteristics of C‑LOOK.

Q5. A system uses two identical disks. Each disk can handle 100 I/O / s under FCFS. Switching to C‑SCAN improves each disk’s throughput by 30 %. If both disks operate in parallel, what is the combined throughput?

A.260 I/O / s
B.200 I/O / s ✅
C.130 I/O / s
D.300 I/O / s
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: Under FCFS, each disk handles 100 I/O / s. A 30 % improvement with C‑SCAN raises each disk’s capacity to 130 I/O / s. Running two disks in parallel doubles the capacity, giving 130 × 2 = 260 I/O / s. Option B reflects only the original FCFS total, C reflects a single disk’s C‑SCAN rate, and D mistakenly multiplies the improvement factor twice. This calculation shows how parallelism and an efficient algorithm together boost overall system performance.

Q6. Consider a disk with head at 50 and pending requests at 55, 58, 60, 10, 15. Which algorithm provides the lower average wait time for these requests?

A.SCAN
B.LOOK ✅
C.C‑LOOK
D.FCFS
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: LOOK (and C‑LOOK) reverse direction after servicing the highest pending request (60) without traveling to the disk’s end, resulting in wait times of 5, 8, 10, 55, and 60 ms respectively, averaging 27.6 ms. SCAN continues to the outermost cylinder before reversing, causing much longer waits (average ≈ 138.8 ms). FCFS would service in arrival order, yielding similar high waits. Therefore LOOK gives the lowest average wait time, illustrating how limiting unnecessary movement improves performance.

Q7. How does employing parallel disks with C‑LOOK scheduling improve overall system performance compared to a single disk using FCFS?

A.It reduces the average seek distance on each disk, and parallelism multiplies the reduced latency across disks.
B.It increases the rotational speed of each disk, making FCFS faster.
C.It allows disks to share the same request queue, eliminating the need for scheduling. ✅
D.It changes the hardware interface to a faster protocol, independent of scheduling.
💡 Difficulty: hard | ✅ Correct: C

📖 Explanation: Parallel disks each running C‑LOOK shorten the average seek distance because the arm only travels to the last request before wrapping, decreasing latency per I/O. When multiple disks operate concurrently, their reduced latencies combine, effectively multiplying the performance gain. The other options incorrectly attribute speed gains to hardware changes or queue sharing, which are not the primary mechanisms of improvement in this context.

Q8. A server farm has three disks, each handling 80 I/O / s with FCFS. Using C‑LOOK increases each disk’s throughput by 25 %. What is the overall throughput improvement factor compared to a single FCFS disk?

A.2.5‑fold
B.3‑fold
C.3.75‑fold ✅
D.4‑fold
💡 Difficulty: hard | ✅ Correct: C

📖 Explanation: FCFS on one disk yields 80 I/O / s. A 25 % boost with C‑LOOK raises each disk to 100 I/O / s. With three disks operating in parallel, total throughput becomes 300 I/O / s. The improvement factor relative to a single FCFS disk is 300 / 80 = 3.75, making option C correct. The other ratios miscalculate the multiplication of disks or the percentage increase.

Q9. Which concept explains why parallelism, combined with algorithms like C‑SCAN or C‑LOOK, leads to better disk‑access performance?

A.Parallelism allows multiple independent seek operations to occur simultaneously, reducing overall wait time. ✅
B.Parallelism forces the disk to spin faster, decreasing rotational latency.
C.Parallelism merges all requests into a single queue, eliminating the need for scheduling.
D.Parallelism replaces mechanical arms with solid‑state memory, making scheduling irrelevant.
💡 Difficulty: hard | ✅ Correct: A

📖 Explanation: When multiple disks operate in parallel, each can perform its own seek independently. Efficient algorithms such as C‑SCAN or C‑LOOK minimize individual seek distances, so the combined effect is a substantial reduction in total wait time for I/O requests. The other options incorrectly attribute performance gains to increased spin speed, queue merging, or hardware replacement, which are not the primary reasons parallelism improves scheduling efficiency.
