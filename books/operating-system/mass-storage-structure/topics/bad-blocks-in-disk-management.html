📝 All Bad blocks in Disk Management MCQs

Q1. A storage system receives logical block number 2500. The outer zone stores 140 sectors per track, the inner zone stores 100 sectors per track, and each cylinder contains 2 tracks. The first 2000 logical blocks are allocated to outer‑zone cylinders. Which cylinder number could contain block 2500?

🔹 A. 9
🔹 B. 10
🔹 C. 11
🔹 D. 12

💡 Difficulty: easy | ✅ Correct: B

📖 Explanation:

The outer zone provides 140 sectors × 2 tracks = 280 sectors per cylinder. The first 2000 blocks fill 2000 ÷ 280 ≈ 7.14 cylinders, so cylinders 0‑7 are used. Block 2500 lies 500 blocks beyond the outer zone (2500‑2000 = 500). The inner zone supplies 100 × 2 = 200 sectors per cylinder, so 500 ÷ 200 = 2.5, meaning the third inner cylinder (index 2) after the outer zone is used. Adding the 8 outer cylinders gives cylinder 10. Hence option B is correct, while the other numbers do not match the calculation.

Q2. A file of 500 sectors starts at logical block 4000, but sector 4025 is defective. How does the disk handle this situation?

🔹 A. The file is aborted and an error is returned
🔹 B. The defective sector is skipped and the file continues with a gap
🔹 C. The system remaps the defective sector to a spare sector and continues transparently
🔹 D. The file is rewritten to a new location

💡 Difficulty: easy | ✅ Correct: C

📖 Explanation:

When a sector is marked bad, modern disks keep a pool of spare sectors. During normal writes, the controller automatically substitutes the bad sector with a spare one, preserving the logical block sequence. Therefore the file continues without interruption, matching option C. Option A would halt operation, which is not typical for transparent remapping. Option B would create a visible gap, which is undesirable. Option D implies a full rewrite, which is unnecessary for a single bad block.

Q3. In a CLV drive, outer tracks hold 40 % more sectors than inner tracks. If an inner track has 120 sectors, how many sectors does an outer track have?

🔹 A. 140
🔹 B. 152
🔹 C. 168
🔹 D. 180

💡 Difficulty: easy | ✅ Correct: C

📖 Explanation:

A 40 % increase means multiply the inner count by 1.40: \(120 \times 1.40 = 168\). Thus the outer track contains 168 sectors, making option C correct. Option A (140) reflects a 16.7 % increase, option B (152) reflects a 26.7 % increase, and option D (180) reflects a 50 % increase, none of which satisfy the 40 % specification.

Q4. A hard disk uses CAV, keeping rotation speed constant. If the linear velocity at the inner track is 50 m/s and the radius is 25 mm, what is the approximate rotation speed in revolutions per second?

🔹 A. 250
🔹 B. 300
🔹 C. 318
🔹 D. 350

💡 Difficulty: easy | ✅ Correct: C

📖 Explanation:

The angular speed \(\omega\) equals linear speed divided by radius: \(\omega = 50 \text{m/s} ÷ 0.025 \text{m} = 2000 \text{rad/s}\). Converting to revolutions per second uses \(1 \text{rev} = 2\pi \text{rad}\): \(2000 ÷ (2\pi) ≈ 318 \text{rev/s}\). Hence option C is correct. Options A and B underestimate the speed, while option D overestimates it, making them inaccurate.

Q5. Why does a disk with variable sectors per track require more complex logical‑to‑physical address translation than a disk with constant sectors per track?

🔹 A. Because the mapping must account for differing sector counts per track and zone
🔹 B. Because variable sectors cause the disk to spin at varying speeds
🔹 C. Because the controller needs extra memory to store sector sizes
🔹 D. Because the operating system cannot cache any data

💡 Difficulty: medium | ✅ Correct: A

📖 Explanation:

When sectors per track vary, the translation from a logical block number to a physical address must consider how many sectors each preceding track contributed. This extra bookkeeping makes the algorithm more intricate, matching option A. Option B confuses speed control with mapping complexity. Option C suggests memory usage unrelated to translation, and option D incorrectly claims the OS cannot cache data, which is unrelated to sector count variation.

Q6. How does the presence of spare sectors affect the detection of bad blocks during normal operation?

🔹 A. Bad blocks are instantly reported to the user
🔹 B. Spare sectors hide bad blocks by remapping them silently
🔹 C. Spare sectors cause the disk to stop working when a bad block appears
🔹 D. Spare sectors double the usable capacity of the disk

💡 Difficulty: medium | ✅ Correct: B

📖 Explanation:

Spare sectors are reserved to replace defective ones without user intervention. When a write reaches a bad sector, the controller redirects the data to a spare sector, making the failure invisible to the operating system; this is described by option B. Option A would generate frequent errors, contrary to typical behavior. Option C suggests a catastrophic failure, which is not the purpose of spares. Option D incorrectly claims capacity doubling, which does not occur.

Q7. In what way does constant angular velocity (CAV) simplify the design of disk firmware relative to constant linear velocity (CLV)?

🔹 A. CAV eliminates the need to adjust rotation speed as the head moves
🔹 B. CAV requires complex speed‑control loops for each track
🔹 C. CAV forces the firmware to calculate varying sector densities
🔹 D. CAV makes zone bit recording impossible

💡 Difficulty: medium | ✅ Correct: A

📖 Explanation:

CAV keeps the spindle speed fixed, so the firmware does not have to compute or command speed changes when the head moves between tracks. This stability reduces algorithmic complexity, supporting option A. Option B reverses the truth, as speed changes are required for CLV, not CAV. Option C describes CLV's variable density issue, not CAV. Option D is false because ZBR can be implemented with CAV.

Q8. What is the primary advantage of using zone bit recording (ZBR) that results in outer tracks having more sectors than inner tracks?

🔹 A. It maximizes total disk capacity by exploiting longer outer tracks
🔹 B. It reduces power consumption of the spindle motor
🔹 C. It simplifies the logical‑to‑physical address mapping
🔹 D. It eliminates the need for spare sectors

💡 Difficulty: medium | ✅ Correct: A

📖 Explanation:

ZBR tailors the number of sectors to track length, allowing the outer, longer tracks to hold more data, thereby increasing overall capacity—option A. Option B is unrelated; power usage is not the main driver. Option C is opposite, as variable sector counts make mapping harder. Option D is unrelated to ZBR's purpose.

Q9. How does increasing the number of sectors per track over time impact the reliability of bad block management?

🔹 A. More sectors per track reduce the chance of encountering a bad block
🔹 B. More sectors per track increase the chance that a single bad block affects more user data
🔹 C. Increasing sectors per track has no effect on bad block management
🔹 D. It forces the system to use more spare sectors

💡 Difficulty: medium | ✅ Correct: C

📖 Explanation:

When sector density rises, the logical‑to‑physical mapping becomes more granular, but the probability of any single sector being defective does not change significantly; thus, the management strategy remains similar, aligning with option C. Option A incorrectly assumes fewer bad blocks. Option B suggests a larger impact per bad block, which is not generally true because bad blocks are isolated. Option D misstates the relationship between sector count and spare usage.

Q10. Why might a system choose to hide defective sectors by remapping them to spare sectors rather than reporting errors to the operating system?

🔹 A. To maintain uninterrupted I/O performance and avoid application crashes
🔹 B. To increase the total storage capacity of the disk
🔹 C. To simplify the firmware design
🔹 D. To reduce the power consumption of the drive

💡 Difficulty: medium | ✅ Correct: B

📖 Explanation:

Remapping defective sectors to spares preserves the logical continuity of data, preventing errors from propagating to the OS and keeping applications running smoothly—option B. Option A misstates the goal; the primary aim is data integrity, not just performance. Option C is false because firmware already handles remapping. Option D is unrelated to error handling.

Q11. How does the variation in sectors per track influence the calculation of disk capacity?

🔹 A. Capacity is simply the product of cylinders and tracks, independent of sector count
🔹 B. Capacity must sum the sectors of each zone, accounting for differing sectors per track
🔹 C. Capacity is determined solely by the outermost zone's sector count
🔹 D. Variation in sectors per track does not affect capacity calculations

💡 Difficulty: medium | ✅ Correct: B

📖 Explanation:

When sectors per track differ across zones, total capacity equals the sum of sectors contributed by each zone, requiring the firmware to add the varying counts—option B. Option A ignores sector variation. Option C over‑emphasizes the outer zone. Option D claims no effect, which contradicts the need to account for differing sector numbers.

Q12. What effect does rotating the disk faster when moving from outer to inner tracks (as in CLV) have on data transfer rate?

🔹 A. It keeps the linear data rate constant across the disk surface
🔹 B. It increases the data rate on inner tracks only
🔹 C. It decreases the data rate on outer tracks only
🔹 D. It has no impact on data transfer rate

💡 Difficulty: medium | ✅ Correct: A

📖 Explanation:

CLV adjusts rotational speed so that the linear velocity of the disk surface under the head remains constant, preserving a uniform data transfer rate regardless of radius—option A. Option B misrepresents the purpose of speed increase. Option C incorrectly suggests a reduction on outer tracks. Option D ignores the intentional speed modulation.

Q13. How does the mapping of logical blocks to physical locations help in load balancing across the disk surface?

🔹 A. It spreads sequential logical blocks across multiple tracks, reducing hotspot activity
🔹 B. It concentrates all logical blocks on the outermost tracks for faster access
🔹 C. It forces the head to stay on a single track for the duration of a file
🔹 D. It eliminates the need for caching in the operating system

💡 Difficulty: medium | ✅ Correct: C

📖 Explanation:

Logical‑to‑physical mapping often interleaves blocks so that consecutive logical blocks are placed on different tracks or cylinders, distributing I/O load and avoiding concentration—option C. Option A describes the opposite effect. Option B would create a hotspot, reducing performance. Option D incorrectly claims mapping replaces caching.

Q14. What does the acronym CAV stand for in disk technology?

🔹 A. Constant Angular Velocity
🔹 B. Constant Access Velocity
🔹 C. Circular Array Variation
🔹 D. Constant Audio Volume

💡 Difficulty: medium | ✅ Correct: A

📖 Explanation:

CAV is universally defined as Constant Angular Velocity, meaning the spindle rotates at a fixed speed regardless of head position. This matches option A. The other choices are unrelated terms that do not describe the disk rotation method.

Q15. In disk terminology, what is a \cylinder\?

🔹 A. A set of tracks that share the same radius on all platters
🔹 B. A group of sectors within a single track
🔹 C. A collection of platters stacked together
🔹 D. A type of bad block that cannot be remapped

💡 Difficulty: medium | ✅ Correct: A

📖 Explanation:

A cylinder comprises all tracks located at the same radial distance across every platter, forming a vertical stack. This definition aligns with option A. Options B and C describe different concepts (sectors and platters). Option D invents a nonexistent bad‑block type.

Q16. A system reports that logical block 12345 is unreadable. The disk has 200 cylinders, each cylinder contains 2 tracks, outer‑zone tracks hold 150 sectors, inner‑zone tracks hold 100 sectors. Assuming the outer zone occupies the first 100 cylinders, which physical sector number is being accessed?

🔹 A. 12400
🔹 B. 12500
🔹 C. 12600
🔹 D. 12700

💡 Difficulty: hard | ✅ Correct: B

📖 Explanation:

First, calculate outer‑zone capacity: 100 cylinders × 2 tracks × 150 sectors = 30 000 sectors. Logical block 12345 lies within this range, so it is in the outer zone. The sector offset within the outer zone is 12 345. Dividing by sectors per cylinder (300) gives cylinder 41 with remainder 45. The track number is floor(45 ÷ 150) = 0, and the sector index is 45. The physical sector number = (41 × 2 + 0) × 150 + 45 = 12 500, matching option B. The other numbers result from mis‑calculations of cylinder or track indices.

Q17. A disk uses CLV and outer tracks hold 40 % more sectors than inner tracks. If a file of 10 000 sectors starts at the beginning of an outer track with 168 sectors per track, and the file continues across tracks, how many tracks will the file occupy?

🔹 A. 58
🔹 B. 59
🔹 C. 60
🔹 D. 61

💡 Difficulty: hard | ✅ Correct: C

📖 Explanation:

The number of tracks required equals the ceiling of total sectors divided by sectors per track: \(\lceil 10 000 ÷ 168 \rceil = \lceil 59.52 \rceil = 60\). Therefore the file spans 60 tracks, making option C correct. Option A (58) and B (59) underestimate the count, while option D (61) overestimates it.

Q18. A diagnostic reports that 0.5 % of the total sectors are marked as bad and have been remapped. If the disk capacity is 500 GB and each sector stores 512 bytes, estimate the total amount of storage lost to unrecoverable bad sectors (assuming only the remapped sectors are usable).

🔹 A. 1 GB
🔹 B. 2.5 GB
🔹 C. 5 GB
🔹 D. 10 GB

💡 Difficulty: hard | ✅ Correct: B

📖 Explanation:

First, find total sectors: \(500 GB ÷ 512 B ≈ 976 562 500\) sectors. 0.5 % of these equals \(0.005 × 976 562 500 ≈ 4 882 813\) sectors. Multiplying by 512 B gives about \(2.5 GB\) of lost capacity, which matches option B. The other options represent either too little or too much loss based on mis‑applied percentages or arithmetic errors.

Q19. A RAID‑1 array mirrors a disk that uses ZBR. If the primary disk suffers a bad block in an inner‑zone track, how does the mirror handle the read request?

🔹 A. The mirror reads its own copy of the logical block using its own mapping
🔹 B. The mirror skips the block and returns an error
🔹 C. The mirror rebuilds the block from parity information
🔹 D. The mirror redirects the request to the spare sector pool

💡 Difficulty: hard | ✅ Correct: A

📖 Explanation:

RAID‑1 maintains an identical logical view on both drives. When a bad block is encountered, the controller accesses the mirrored copy of the same logical block, which is mapped to a corresponding physical location on the second drive, preserving data integrity—option A. Options B and C describe behaviors not applicable to RAID‑1 (error or parity reconstruction). Option D misstates the role of spare sectors, which are handled locally by each drive, not by the RAID layer.

Q20. An operating system schedules sequential reads to minimize head movement. Given a disk with three zones—outer (40 % more sectors), middle (standard), inner (20 % fewer sectors)—which zone should the OS prioritize for a large sequential read to achieve highest throughput?

🔹 A. Outer zone
🔹 B. Middle zone
🔹 C. Inner zone
🔹 D. Any zone, because zone does not affect throughput

💡 Difficulty: hard | ✅ Correct: A

📖 Explanation:

The outer zone contains the most sectors per track, so each rotation delivers more data, yielding the highest data rate for sequential operations. Prioritizing the outer zone therefore maximizes throughput—option A. The middle zone offers average performance, while the inner zone provides the lowest data per rotation due to fewer sectors. Option D ignores the impact of sector density on transfer speed.

Q21. A firmware update moves the spare sector pool from the outermost cylinder to the innermost cylinder. How might this affect the latency of remapping a bad block that occurs in the outer zone?

🔹 A. It increases latency because the spare sector is farther away
🔹 B. It decreases latency because inner cylinders spin faster
🔹 C. It has no effect on latency
🔹 D. It causes data loss during remapping

💡 Difficulty: hard | ✅ Correct: A

📖 Explanation:

When a bad block in the outer zone must be remapped to a spare located on the innermost cylinder, the head must travel a greater distance, adding seek time and thus increasing latency—option A. Option B incorrectly assumes inner cylinders spin faster, which does not reduce seek distance. Option C ignores the physical movement required, and option D mischaracterizes the outcome of remapping.
