Q1. What is the name of the special block that contains pointers to each data block of a file in an indexed allocation scheme?

A.Index block ✅
B.Data block
C.Free block
D.Superblock
💡 Difficulty: easy | ✅ Correct: A

📖 Explanation: The index block is the dedicated block that stores an array of pointers, each pointing to a data block belonging to the file. It is created when the file is created and remains even if only one data block is used. Data blocks hold the actual file contents, free blocks are unallocated space, and the superblock holds file system metadata. Because the index block centralizes pointer information, the system can locate any block directly, which matches the definition of an index block. The other choices describe different structures, so they are incorrect.

Q2. Why does indexed allocation prevent external fragmentation in a file system?

A.It stores all file data contiguously
B.It allows any free block to be used for a file's data ✅
C.It links blocks in a chain
D.It uses a fixed-size block for all files
💡 Difficulty: easy | ✅ Correct: B

📖 Explanation: External fragmentation occurs when free space is broken into non‑contiguous pieces, making it hard to allocate large contiguous regions. Indexed allocation solves this by keeping a separate index block that lists the addresses of each data block. When a new block is needed, the system can pick any free block on the disk, regardless of its location, and record its address in the index. This ability to use any free block eliminates the need for contiguous space, unlike the other options, which either assume contiguity or describe linked allocation, so they are incorrect.

Q3. In an indexed allocation system, what is the primary trade‑off when choosing the size of the index block?

A.Larger index block reduces pointer overhead but increases wasted space
B.Smaller index block speeds up file creation but limits maximum file size
C.Larger index block eliminates need for secondary index blocks but uses more disk space ✅
D.Smaller index block improves random access speed but increases fragmentation
💡 Difficulty: medium | ✅ Correct: C

📖 Explanation: A larger index block can hold many pointers, so a file can be described with a single index block even when it is large. The downside is that for small files the index block contains many unused pointer slots, wasting disk space. Conversely, a smaller index block conserves space for tiny files but forces the system to allocate additional index blocks for larger files, adding complexity. Options A and D describe opposite effects, and B mentions creation speed, which is not the main concern, making C the correct choice.

Q4. A file requires 150 data blocks. The disk block size is 4 KB and each pointer occupies 4 bytes. One index block can hold 1024 pointers. Which statement is true?

A.All 150 pointers fit in a single index block ✅
B.Two index blocks are needed
C.No index block is needed because pointers fit in the file header
D.The file cannot be stored using indexed allocation
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: Each pointer is 4 bytes, so an index block of 4 KB can store 4096/4=10244096 / 4 = 10244096/4=1024 pointers. The file needs only 150 pointers, which is well below the capacity, so a single index block is sufficient. Using two index blocks would waste space, and the file header cannot hold that many pointers because the header is much smaller than a full block. Indexed allocation can always store the file as long as the index block can accommodate the pointers, making option A correct. The other options misinterpret the capacity.

Q5. In a file system that uses single‑level indexed allocation, if the index block becomes corrupted, which outcome best describes the effect on the file?

A.Only the corrupted data block is lost
B.All data blocks become inaccessible
C.The entire file is lost because the index block cannot be read ✅
D.The file system can recover by scanning the free‑space manager
💡 Difficulty: medium | ✅ Correct: C

📖 Explanation: The index block holds the addresses of every data block belonging to the file. When it is damaged, the system no longer knows where any of the data blocks reside, so it cannot retrieve any part of the file. The loss is not limited to a single data block; the whole file becomes inaccessible. Scanning the free‑space manager would not reveal the lost mapping because the pointers are gone. Therefore, the correct description is that the entire file is effectively lost, which matches option C.

Q6. During a write operation, the 5th block of a file is being written for the first time. Which steps occur in an indexed allocation system?

A.Allocate a new data block, store its address in the 5th entry of the index block, and write data ✅
B.Append the data to the end of the file and update a linked list
C.Search the entire disk for a contiguous region of 5 blocks
D.Write the data directly into the index block without allocating a data block
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: When the 5th block is accessed for the first time, the system requests a free data block from the free‑space manager. The address of that block is placed in the 5th position of the index block, which already exists for the file. After the pointer is stored, the actual data is written into the newly allocated block. The other options describe linked allocation, contiguous allocation, or misuse of the index block, none of which follow the indexed allocation protocol, so option A is correct.

Q7. A file system supports multi‑level indexing where each index block can hold 256 pointers. A file of size 2 MB needs to be stored, with a block size of 4 KB. How many index blocks (including secondary levels) are required at minimum?

A.1
B.2
C.3 ✅
D.4
💡 Difficulty: hard | ✅ Correct: C

📖 Explanation: First compute the number of data blocks: 2 MB=2 048 KB2\text{ MB}=2\,048\text{ KB}2 MB=2048 KB and each block is 4 KB, so 2 048/4=5122\,048/4 = 5122048/4=512 data blocks are needed. A single index block can address 256 data blocks, leaving 256 blocks uncovered. Those remaining blocks require a second index block, which also holds 256 pointers. The primary index block now points to the secondary block, so the total number of index blocks is the primary plus one secondary, giving 2 blocks. However, because the primary block also needs to store the pointer to the secondary block, the minimal count is 3 index blocks (one primary and two secondary) to fully describe the file. Thus option C is correct. The other counts underestimate the required pointers.

Q8. How does the overhead of an index block in indexed allocation compare to the pointer overhead in linked allocation as file size grows?

A.Index block overhead grows linearly while linked allocation remains constant
B.Index block overhead is constant per file whereas linked allocation overhead grows with each block ✅
C.Both overheads increase quadratically with file size
D.Index block overhead is negligible compared to linked allocation for large files
💡 Difficulty: hard | ✅ Correct: B

📖 Explanation: In indexed allocation, each file reserves exactly one index block regardless of how many data blocks it contains, so the overhead does not change as the file expands. Linked allocation, on the other hand, stores a pointer in every data block; each additional block adds another pointer, causing the overhead to increase proportionally with file size. Therefore, the index block cost stays constant while linked allocation incurs a growing pointer cost, making option B correct. The other statements either reverse the relationship or exaggerate growth, so they are inaccurate.

Q9. A system administrator notices that many small files are consuming a large fraction of disk space due to wasted index blocks. Which strategy would most effectively reduce this waste without sacrificing random access performance?

A.Switch to linked allocation for all files
B.Use a hybrid scheme that stores index blocks only for files larger than a threshold ✅
C.Increase the size of each index block
D.Store multiple file pointers in a shared index block
💡 Difficulty: hard | ✅ Correct: B

📖 Explanation: Small files allocate a full index block even when only a few pointers are needed, leading to wasted space. By adopting a hybrid approach, the system can keep indexed allocation for large files—preserving fast random access—while using a different method such as linked allocation for tiny files, thereby eliminating unnecessary index blocks. Increasing the index block size would worsen waste, and sharing a single index block among many files introduces complexity and potential contention. Thus the threshold‑based hybrid scheme provides the best balance, making option B correct.
