What is The Network file systems Protocol?

Definition:
The NFS protocol defines RPC-based operations for remote file manipulation including READ, WRITE, LOOKUP, and GETATTR.

Example:
READ request specifies ⟨fh,offset,count⟩\langle fh, offset, count \rangle⟨fh,offset,count⟩; server responds with ⟨data,eof_flag⟩\langle data, eof\_flag \rangle⟨data,eof_flag⟩ or error code.

Reason:
Stateless design using unique file handles enables server crash recovery without session state, trading some performance for robustness in unreliable networks.

📝 All The Network file systems Protocol MCQs

Q1. Why does an index block contain pointers rather than the actual file data?

A.Because pointers are smaller than data blocks ✅
B.Because data blocks are stored elsewhere on disk
C.Because pointers allow direct access to any block
D.Because pointers reduce external fragmentation
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: The index block stores addresses that point to the real data blocks, so the file’s contents remain on separate data blocks. This design keeps the index block compact, enabling quick lookup of any block without moving large amounts of data. Option A is wrong because pointers are indeed smaller, but the reason is not about size alone. Option B is incorrect because data blocks are not kept inside the index block. Option D misstates the purpose; pointers are used for efficient location, not for fragmentation control.

Q2. What is the main reason indexed allocation avoids external fragmentation?

A.It places all file blocks contiguously
B.It allocates each block independently from any free space ✅
C.It uses a single large index block to map addresses
D.It links blocks in a chain
💡 Difficulty: easy | ✅ Correct: B

📖 Explanation: Indexed allocation assigns each file block to any free disk block, so blocks do not need to be adjacent. This freedom prevents gaps between allocated blocks, eliminating external fragmentation. Option B describes the method but does not explain why fragmentation is avoided. Option C is false because a single index block does not guarantee contiguity. Option D describes linked allocation, which can still suffer from fragmentation.

Q3. If a file requires 150 blocks and each index block can hold 100 pointers, how many index blocks are needed?

A.1 ✅
B.2
C.3
D.4
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: Dividing the total blocks by the capacity per index block gives 150/100=1.5150 / 100 = 1.5150/100=1.5. Since a partial index block cannot be used, the system must allocate the next whole index block, resulting in 2 index blocks. Option A would only cover the first 100 pointers, leaving 50 blocks unaddressed. Option C and D over‑estimate the requirement, allocating unnecessary index blocks.

Q4. A system uses linked index blocks, each holding 100 pointers. When a client accesses block 120 of a file, what sequence of reads occurs?

A.Read the first index block, then the 20th data block ✅
B.Read the second index block directly, then the data block
C.Read the first index block, follow its link to the second index block, then read the data block
D.Read only the data block because pointers are cached
💡 Difficulty: hard | ✅ Correct: A

📖 Explanation: To reach block 120, the client must first read the initial index block (which contains pointers 1‑100). Because block 120 lies beyond that range, the client follows the link stored in the first index block to the second index block, which holds pointers 101‑200, and finally reads the desired data block. Option A stops after the first index block, missing the needed pointer. Option B assumes direct access to the second block, which is not possible without the link. Option D ignores the need to locate the pointer.

Q5. How does the space overhead of indexed allocation compare to linked allocation for a file that occupies exactly two data blocks?

A.Indexed uses fewer bytes because it stores only two pointers
B.Linked uses fewer bytes because it stores only two pointers
C.Indexed uses more bytes because a whole index block is allocated ✅
D.Both use the same amount of overhead
💡 Difficulty: medium | ✅ Correct: C

📖 Explanation: Indexed allocation must reserve an entire index block even if only two pointers are needed, so the overhead includes the full block size plus the two pointers. Linked allocation, by contrast, adds a single pointer per data block, resulting in only two extra pointers. Therefore, option C correctly identifies the larger overhead for indexed allocation. Option A and B incorrectly assume pointer count alone determines overhead, ignoring the fixed‑size index block. Option D is false because the overhead sizes differ.

Q6. Each disk block is 4 KB and a pointer occupies 4 bytes. Approximately how many pointers fit in one index block?

A.256 ✅
B.512
C.1024
D.2048

📖 Explanation: A 4 KB block contains 409640964096 bytes. Dividing by the pointer size 444 bytes yields 4096/4=10244096 / 4 = 10244096/4=1024 pointers per block. Option A results from dividing by 16, which is incorrect. Option B would be correct for an 8‑byte pointer. Option C corresponds to a 16‑byte pointer. Thus, option D accurately reflects the calculation.

Q7. How does the size of the index block affect the scalability of NFS file sharing across many clients?

A.Larger index blocks reduce the number of network messages needed for large files
B.Smaller index blocks increase the chance of pointer overflow requiring additional metadata ✅
C.Larger index blocks cause more cache misses on client machines
D.Smaller index blocks improve security by limiting exposure of file layout
💡 Difficulty: hard | ✅ Correct: B

📖 Explanation: A larger index block can hold more pointers, so a client can retrieve many block addresses with a single read, decreasing network traffic and improving scalability for large files. Option B describes a problem that actually encourages smaller blocks, not larger ones. Option C misattributes cache behavior to block size. Option D confuses security concerns with index block sizing.

Q8. When an index block becomes full, which mechanism is commonly used to extend it in NFS implementations?

A.Allocate a new contiguous index block and copy data ✅
B.Link additional index blocks together forming a chain
C.Replace the index block with a double‑indirect structure
D.Use a bitmap to mark free pointer slots
💡 Difficulty: hard | ✅ Correct: A

📖 Explanation: Linking extra index blocks creates a chain where each block contains a header and additional pointers, allowing the file to grow beyond the capacity of a single block without relocating existing data. Option A would require moving all pointers, incurring high overhead. Option C describes a double‑indirect scheme, which is more complex and not the typical first‑step extension. Option D refers to free‑space management, not index block extension.

Q9. A client wants to read the 5th block of a file stored with indexed allocation. Which sequence best describes the steps performed by the NFS server?

A.Read the index block, locate pointer 5, then read data block 5 ✅
B.Read the data block directly because block numbers are global
C.Read the index block, send all pointers to client, client selects pointer 5
D.Read the entire file into memory then extract block 5
💡 Difficulty: hard | ✅ Correct: A

📖 Explanation: The server first reads the index block to obtain the full list of pointers, then transmits that list to the client. The client uses the fifth pointer to request the specific data block. Option A omits the client’s involvement after the pointer is found. Option B assumes direct block addressing, which indexed allocation does not provide. Option D unnecessarily loads the whole file, wasting resources.

Q10. What is the primary disadvantage of allocating a whole index block for very small files?

A.It increases the time to locate data blocks ✅
B.It wastes disk space because many pointer slots remain unused
C.It causes external fragmentation on the disk
D.It forces the use of double‑indirect pointers
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: When a file is tiny, most of the pointers in its index block remain null, leading to wasted space that could otherwise store useful data. This inefficiency is the main drawback. Option A is unrelated to space waste. Option B describes external fragmentation, which indexed allocation avoids. Option C is incorrect because external fragmentation is not caused by the index block size.

Q11. If an index block becomes corrupted, what recovery technique can NFS typically employ?

A.Rebuild the index block from a backup copy
B.Ignore the corruption and continue serving requests ✅
C.Replace the corrupted block with a zero‑filled block
D.Ask the client to resend the entire file
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: NFS servers often keep backup copies or snapshots of metadata, allowing them to reconstruct a damaged index block from a recent backup, restoring correct pointers. Option B would likely cause further errors. Option C would lose all pointer information, making the file inaccessible. Option D shifts the burden to the client, which cannot regenerate the index structure.

Q12. In NFS terminology, what does the acronym NFS stand for?

A.Network File Sharing ✅
B.Network File Service
C.Network File System
D.Node File System
💡 Difficulty: easy | ✅ Correct: A

📖 Explanation: NFS is short for Network File System, a protocol that lets clients access files over a network as if they were on local storage. Option A confuses sharing with the protocol name. Option B uses “Service” instead of “System.” Option D invents a non‑standard term. The correct expansion directly reflects the purpose of the protocol.
