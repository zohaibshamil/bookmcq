Q1. What does FAT stand for in file systems?

🔹 A. File Allocation Table
🔹 B. Fast Access Technique
🔹 C. File Access Tracker
🔹 D. Fragmented Allocation Table

💡 Difficulty: easy | ✅ Correct: B

📖 Explanation:

The correct answer is \File Allocation Table\ because FAT is the table that maps each file’s logical blocks to physical disk blocks. Option B invents a unrelated term, option C suggests a tracker that does not exist, and option D mixes fragmentation with allocation. Understanding the acronym helps students recognize why the table is central to file‑system operations and why it must sometimes be cached to speed up access.

Q2. Why does indexed allocation allow faster direct access than linked allocation?

🔹 A. All block addresses are stored together in an index block
🔹 B. It uses a hash table for block lookup
🔹 C. It stores blocks contiguously on disk
🔹 D. It eliminates the need for a directory

💡 Difficulty: medium | ✅ Correct: B

📖 Explanation:

Indexed allocation keeps an array of block pointers in a single index block, so the system can compute the location of any block directly. Option B describes a hash table which indexed allocation does not use. Option C refers to contiguous allocation, not indexed. Option D is incorrect because directories still exist. This design reduces seek time, which is crucial when restoring specific parts of a file.

Q3. If the FAT is not cached, how many disk‑head movements are required to read the three blocks 217, 618, and 339?

🔹 A. 3
🔹 B. 4
🔹 C. 6
🔹 D. 9

💡 Difficulty: medium | ✅ Correct: A

📖 Explanation:

For each block, the head must first move to the start of the volume to read the FAT entry, then move to the block itself, giving two movements per block. With three blocks this totals \(2 \times 3 = 6\) movements. Option A undercounts by assuming only one movement per block, B assumes one extra movement, and D overestimates by adding unnecessary trips. Knowing the worst‑case count helps estimate backup‑restore performance.

Q4. How does caching the FAT reduce the number of disk‑head seeks, and what trade‑off does this introduce?

🔹 A. Reduces seeks but increases CPU usage
🔹 B. Reduces seeks by keeping the FAT in memory, at the cost of using RAM
🔹 C. Eliminates seeks entirely, but requires SSD
🔹 D. Caches the data blocks, not the FAT

💡 Difficulty: hard | ✅ Correct: A

📖 Explanation:

Keeping the FAT in RAM means the head does not need to travel to the FAT area for each lookup, cutting seek operations dramatically. The trade‑off is that RAM space is consumed, which could limit memory for other processes. Option A mentions CPU instead of memory, C claims impossible elimination of seeks, and D misstates what is cached. This balance is key when planning backup strategies.

Q5. A system can cache only two FAT entries at a time. A file occupies blocks 100, 200, 300, and 400. Which blocks will still require a separate FAT read before the block can be accessed?

🔹 A. 100 and 200
🔹 B. 200 and 300
🔹 C. 300 and 400
🔹 D. All four blocks

💡 Difficulty: hard | ✅ Correct: A

📖 Explanation:

If only two entries can be cached, the system might keep the first two (100 and 200) while the remaining blocks (300 and 400) lack cached entries, forcing an extra FAT read for each. Option A assumes the cached ones need reads, which is opposite. Option B selects a middle pair, and D suggests no caching benefit. Recognizing which blocks stay uncached helps estimate additional latency during restores.

Q6. A backup program uses incremental backup. Which statement best describes what is saved each time?

🔹 A. Only the file names
🔹 B. All blocks of every file
🔹 C. Only the blocks that have changed since the last backup
🔹 D. A full copy of the disk

💡 Difficulty: easy | ✅ Correct: A

📖 Explanation:

Incremental backup records only the portions of files that have been modified since the previous backup, reducing storage and time. Option A ignores data content, B describes a full backup, and D suggests a complete disk image, which is not incremental. Knowing this behavior is essential for planning efficient restore procedures and storage management.

Q7. What is the main advantage of indexed allocation for restoring a file after a crash?

🔹 A. The index block provides a single location to locate all file blocks
🔹 B. It eliminates the need for a backup
🔹 C. It stores blocks in alphabetical order
🔹 D. It compresses the file data

💡 Difficulty: medium | ✅ Correct: A

📖 Explanation:

The index block contains pointers to every block of the file, so after a crash the system can quickly locate each piece without scanning the disk sequentially. Options B and D describe unrelated benefits, while C is irrelevant to allocation. This advantage speeds up restore operations because the system avoids the many seeks required by linked allocation.

Q8. During a restore, the system reads the index block first. If the index block is corrupted, which recovery method is most effective?

🔹 A. Re‑read the index block from the backup copy
🔹 B. Scan the entire disk for the file’s data blocks
🔹 C. Use linked allocation pointers to rebuild the index
🔹 D. Abort the restore

💡 Difficulty: medium | ✅ Correct: B

📖 Explanation:

Restoring the index block from a recent backup restores the map of block locations, allowing the remainder of the file to be retrieved efficiently. Scanning the whole disk (option B) would be extremely slow, option C assumes linked allocation which may not exist, and aborting (option D) prevents recovery altogether. Using the backup copy is the standard, reliable approach.

Q9. A file system uses linked allocation without a FAT. A user requests the 7th block of a large file. Which factor makes this request inefficient?

🔹 A. The need to read the directory entry
🔹 B. Sequential traversal of pointers from the first block
🔹 C. Random access to the index block
🔹 D. Caching of the entire file

💡 Difficulty: hard | ✅ Correct: A

📖 Explanation:

Linked allocation stores each block’s pointer inside the previous block, so to reach the 7th block the system must follow six pointers sequentially, causing many disk reads. Option A is unrelated to block access, C describes indexed allocation, and D would actually improve performance, not hinder it. This sequential dependency is a key limitation when designing backup‑restore mechanisms for large files.

Q10. How does external fragmentation differ between contiguous allocation and linked allocation?

🔹 A. Contiguous allocation has no external fragmentation
🔹 B. Linked allocation creates more external fragmentation
🔹 C. Both suffer equally from external fragmentation
🔹 D. Contiguous allocation can leave unused gaps between files, while linked allocation does not create such gaps

💡 Difficulty: medium | ✅ Correct: A

📖 Explanation:

With contiguous allocation, files must occupy consecutive space, so when files are created and deleted, small gaps (external fragments) can appear between them. Linked allocation places each block wherever free space exists, so it does not generate gaps between files. Option A incorrectly claims no fragmentation, B reverses the behavior, and C states they are identical. Recognizing this helps choose allocation methods for efficient backup storage.
