What is Bit vector Free Space Management?

Definition:
Bit vector free space management uses a bitmap where bit \( b_i = 0 \) indicates block \( i \) is free and \( b_i = 1 \) indicates allocated.

Example:
Finding first free block scans bits until encountering \( b_k = 0 \); allocating sets \( b_k \leftarrow 1 \) atomically.

Reason:
Enables fast contiguous allocation searches and compact representation (\( n \) bits for \( n \) blocks) but requires entire bitmap in memory for efficiency on large disks.

📝 All Bit vector Free Space Management MCQs

Q1. What term describes the condition where free disk space is divided into many small, non‑contiguous pieces?

A.Internal fragmentation ✅
B.External fragmentation
C.Sparse allocation
D.Block clustering
💡 Difficulty: easy | ✅ Correct: A

📖 Explanation: External fragmentation occurs when free space is broken into many separate pieces that are too small to satisfy a new allocation request. This condition does not involve the internal layout of allocated blocks, so option A is incorrect. Sparse allocation and block clustering refer to different storage concepts, not the specific fragmentation described. Therefore, option B correctly identifies the phenomenon.

Q2. Why is the first‑fit allocation strategy generally faster than best‑fit when searching for a free hole?

A.It scans from the end of the list, reducing comparisons.
B.It stops at the first hole large enough, avoiding full list traversal.
C.It sorts holes by size before each allocation.
D.It uses a binary search tree, which is slower. ✅
💡 Difficulty: easy | ✅ Correct: D

📖 Explanation: First‑fit examines the free‑hole list sequentially and stops as soon as it encounters a hole whose size meets the request, which usually requires fewer comparisons than scanning the entire list. Best‑fit must compare every hole to find the smallest sufficient one, increasing search time. Options A and C describe behaviors that are not characteristic of first‑fit, and option D misstates the data structure used, making B the correct choice.

Q3. A file system has free holes of sizes 5, 12, 7, and 20 blocks in that order. If a request for 8 blocks arrives, which hole will first‑fit allocate and which hole will best‑fit allocate?

A.First‑fit: 5; Best‑fit: 7 ✅
B.First‑fit: 12; Best‑fit: 7
C.First‑fit: 12; Best‑fit: 12
D.First‑fit: 20; Best‑fit: 12
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: First‑fit scans the list from the beginning and selects the first hole that can accommodate 8 blocks, which is the 12‑block hole (the 5‑block hole is too small). Best‑fit searches for the smallest hole that still fits the request, which is the 7‑block hole because it is the smallest size greater than or equal to 8. Option A incorrectly assigns the 5‑block hole to first‑fit, option C chooses the same hole for both strategies, and option D picks the last hole for first‑fit, all of which are inaccurate.

Q4. How does contiguous allocation enable direct access to the i‑th block of a file that starts at disk block b?

A.By storing a pointer to each block in a table. ✅
B.By computing the address as b + i at run time.
C.By using a linked list of block numbers.
D.By hashing the block index to a disk sector.
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: In contiguous allocation, all blocks of a file reside sequentially on disk. To reach the i‑th block, the system simply adds the offset i to the starting block number b, yielding the address b + i, which can be calculated instantly. This eliminates the need for intermediate pointers or tables, making option A incorrect. Linked lists (option C) and hashing schemes (option D) belong to other allocation methods, not contiguous allocation, so option B is the correct description.

Q5. In a bit‑vector representation, each bit indicates whether a disk block is free (0) or allocated (1). If external fragmentation leaves many isolated free blocks, how does this affect the length of the bit vector needed to represent the disk?

A.The bit vector must be shortened because free blocks are fewer. ✅
B.The bit vector length remains unchanged; it always equals total blocks.
C.The bit vector must be expanded to include extra bits for each fragment.
D.The bit vector is replaced by a linked list of free blocks.
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: A bit vector has one bit for every physical block on the disk, regardless of how those blocks are arranged. External fragmentation changes the distribution of free and allocated bits but does not alter the total number of blocks, so the vector’s length stays the same. Option A suggests shortening, which is false because the total block count does not change. Option C proposes adding extra bits for each fragment, which is unnecessary; the existing bits already represent each block. Option D replaces the bit vector entirely, which is not required. Therefore, option B correctly states that the length is unchanged.

Q6. A disk contains 100 blocks and its bit vector is initially all 0s (free). Three files are allocated contiguously with sizes 20, 30, and 10 blocks respectively. After these allocations, how many blocks remain free?

A.40 ✅
B.30
C.20
D.10
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: The total number of blocks allocated is 20 + 30 + 10 = 60. Subtracting this from the total of 100 blocks leaves 100 − 60 = 40 blocks still free. Option A reflects this calculation. Options B, C, and D underestimate the remaining free space by ignoring part of the allocated total, leading to incorrect numbers. Hence, the correct answer is 40 free blocks, represented by option A.

Q7. Over time, which allocation strategy tends to produce less external fragmentation, first‑fit or best‑fit, and why does the difference matter for storage utilization?

A.First‑fit produces less fragmentation because it leaves larger holes untouched. ✅
B.Best‑fit produces less fragmentation by always using the smallest sufficient hole.
C.Both produce equal fragmentation; the difference is only in allocation speed.
D.Best‑fit creates more fragmentation because it splits holes into tiny pieces.
💡 Difficulty: hard | ✅ Correct: A

📖 Explanation: Best‑fit consistently chooses the smallest hole that can satisfy a request, which reduces the size of leftover fragments and thus limits the creation of many tiny unusable pieces. First‑fit may leave larger holes partially used, potentially generating larger but fewer fragments, but it does not specifically aim to minimize leftover space. Option A reverses the effect, option C incorrectly claims equal fragmentation, and option D mischaracterizes best‑fit as causing more fragmentation. Therefore, option B correctly explains why best‑fit tends to yield lower external fragmentation, improving overall storage utilization.

Q8. A file of size 15 blocks must be placed. Current free holes are 8, 12, and 20 blocks. Which allocation strategy (first‑fit, best‑fit, worst‑fit) will leave the largest remaining contiguous free space after allocation?

A.First‑fit
B.Best‑fit
C.Worst‑fit ✅
D.All strategies leave the same amount of free space
💡 Difficulty: hard | ✅ Correct: C

📖 Explanation: Worst‑fit selects the largest available hole, which is the 20‑block hole, and places the 15‑block file there, leaving a contiguous free fragment of 5 blocks. First‑fit would choose the first hole that fits (the 12‑block hole is too small, so it would take the 20‑block hole as well, leaving 5 blocks, but the initial 8‑block hole remains unused, resulting in two separate free regions). Best‑fit would choose the 12‑block hole, leaving a 3‑block fragment and preserving the 20‑block hole untouched, which does not maximize a single large free region. Thus, worst‑fit yields the largest contiguous free space, making option C correct.

Q9. Using a bit vector, a system scans bits sequentially to find a free run of 5 consecutive 0s. If the disk has 200 blocks and free blocks are randomly scattered, approximately how many bits must be examined in the worst case to locate such a run?

A.5
B.10
C.25
D.200 ✅
💡 Difficulty: hard | ✅ Correct: D

📖 Explanation: In the worst‑case scenario, the system may have to examine every bit on the disk before encountering a suitable sequence of five consecutive 0s, especially when free blocks are sparsely and randomly distributed. Therefore, it could need to scan all 200 bits. Options A, B, and C underestimate the worst‑case effort by assuming a short scan, which is only possible under favorable distributions. Consequently, option D correctly reflects the maximum number of bits that might be examined.
