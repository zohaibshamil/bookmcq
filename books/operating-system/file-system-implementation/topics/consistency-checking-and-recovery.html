What is Consistency checking and Recovery?

Definition:
Consistency checking verifies structural integrity after crashes, and recovery repairs inconsistencies to restore valid file system state.

Example:
fsck detects orphaned inode with link count but referenced in directory, moving it to lost+found for manual review.

Reason:
Crashes leave partial updates causing metadata corruption; automated checking prevents data loss and ensures reliable operation despite power failures or bugs.

Q1. What does FAT stand for?

A.File Allocation Table ✅
B.Fixed Allocation Technique
C.File Access Tracker
D.Fast Allocation Token
💡 Difficulty: easy | ✅ Correct: A

📖 Explanation: The correct answer is File Allocation Table because the acronym FAT is universally used to denote the table that maps each disk block to its next block or to indicate end‑of‑file. Options B, C, and D are fabricated terms that are not used in operating‑system literature. Understanding the definition helps students recognize the structure that drives block location and seek calculations in FAT‑based file systems.

Q2. Why can the FAT allocation scheme cause a large number of disk‑head seeks?

A.Because the FAT must be read from the start of the volume for each block access ✅
B.Because the FAT stores data in compressed form
C.Because the FAT uses variable‑length entries
D.Because the FAT requires multiple passes over the directory
💡 Difficulty: easy | ✅ Correct: A

📖 Explanation: Option A is correct: each time a block is needed the system must first move to the beginning of the volume to read the FAT entry, then move to the actual data block, creating two seeks per block. The other options describe unrelated characteristics; the FAT is not compressed, does not use variable‑length entries, and does not involve directory passes. This explains why un‑cached FAT leads to many seeks.

Q3. How does indexed allocation improve random‑access time compared with linked allocation?

A.All block pointers are gathered in a single index block, allowing direct calculation of a block's address ✅
B.It stores pointers in a binary tree that reduces search depth
C.It compresses pointers to save space, making reads faster
D.It eliminates the need for a FAT entirely
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: Option A is correct because the index block holds an array of addresses, so the system can compute the location of any block directly without traversing a chain. Options B and C describe unrelated data structures, and D is inaccurate—linked allocation still requires a FAT or directory for metadata. The direct‑access benefit is vital for applications needing fast reads of arbitrary blocks.

Q4. What problem does linked allocation solve that contiguous allocation cannot handle efficiently?

A.External fragmentation and the need to declare file size in advance ✅
B.Increased read latency for sequential files
C.Inability to store files larger than a single block
D.Lack of support for file permissions
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: The correct answer is external fragmentation and size declaration because linked allocation allows each block to be placed anywhere on the disk, avoiding gaps left by contiguous allocation and eliminating the need to know the total size beforehand. Options B, C, and D describe issues unrelated to allocation strategy. Recognizing this advantage explains why linked allocation is chosen for flexible file growth despite its slower direct access.

Q5. Why might a system choose to cache the FAT in main memory?

A.To eliminate the extra seek required to read the FAT for each block access ✅
B.To reduce the size of the FAT on disk
C.To enable variable‑length block pointers
D.To allow multiple files to share the same FAT entry
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: Caching the FAT removes the need to reposition the disk head to the beginning of the volume for every block lookup, thereby cutting the number of seeks in half. Options B, C, and D are incorrect: caching does not change the FAT's on‑disk size, does not affect pointer length, and each file still has distinct entries. This practical benefit is why many operating systems keep the FAT resident in RAM.

Q7. If the FAT is cached, how many seeks are needed to read the same three‑block file?

B.2

Q11. What inconsistency could appear if a FAT entry erroneously points to the same block it describes?

A.The block would be considered both allocated and free, leading to a loop detection error ✅
B.The file size would double unexpectedly
C.The directory entry would become corrupted
D.The disk would report a checksum mismatch
💡 Difficulty: hard | ✅ Correct: A

📖 Explanation: When a FAT entry references itself, the allocation chain creates a self‑loop, causing the system to believe the block is both the start and the end of a file segment. This prevents proper traversal and may be flagged as a loop error. Options B, C, and D describe unrelated anomalies. Detecting such loops is a key part of consistency checking in file‑system utilities.
