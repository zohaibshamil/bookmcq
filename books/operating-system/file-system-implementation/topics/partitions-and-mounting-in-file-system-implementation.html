What is Partitions and mounting in File System Implementation?

Definition:
Partitions divide a physical disk into independent logical volumes, and mounting attaches a file system on a partition to a directory tree at a specified mount point.

Example:
The command \( mount /dev/sda2 /home \) links the ext4 file system on partition sda2 to the /home directory path.

Reason:
Partitioning isolates failures and allows different file systems per volume, while mounting provides a unified namespace for seamless access across storage devices.

Q1. A new hard drive is being added to a server. To allow the system to boot from this drive, where must the boot control block be placed on the volume?

A. At the very end of the volume
B. At the first block of the volume ✅
C. In the middle of the volume
D. At a random location

💡 Difficulty: easy | ✅ Correct: B

📖 Explanation:

The boot control block must occupy the first block of a volume because firmware and the operating system expect to find boot code at a known offset. Placing it elsewhere would prevent the system from locating the boot loader, causing a failure to start. The other positions are incorrect because they do not match the fixed-location requirement described in standard disk layouts.

Q2. A volume reports a total of 50,000 blocks and a free‑block count of 12,000. If each block is 4 KiB, what is the total free space in bytes?

A. 48,000,000 bytes
B. 49,152,000 bytes ✅
C. 51,200,000 bytes
D. 48,960,000 bytes

💡 Difficulty: medium | ✅ Correct: B

📖 Explanation:

Multiply the free‑block count (12,000) by the block size (4 KiB = 4,096 bytes). The calculation \(12,000 \times 4,096 = 49,152,000\) gives the total free bytes. Option B matches this result. Options A, C, and D use incorrect multiplications or block‑size values, leading to mismatched totals.

Q3. When converting a UFS file system to NTFS, which NTFS structure directly replaces the per‑file File Control Block (FCB) used in UFS?

A. A row in the Master File Table ✅
B. The boot block
C. The superblock
D. The directory entry

💡 Difficulty: hard | ✅ Correct: A

📖 Explanation:

In NTFS, each file's metadata is stored as a row in the Master File Table (MFT), which serves the same purpose as the per‑file FCB in UFS. This row contains identifiers, attributes, and pointers needed for file access. The boot block, superblock, and directory entry serve different roles such as booting, volume metadata, and name mapping, so they do not replace the FCB.

Q4. What is the primary purpose of a volume control block (VCB) on a storage partition?

A. Store user passwords
B. Manage network connections
C. Hold partition size, block size, and free‑space information ✅
D. Control CPU scheduling

💡 Difficulty: easy | ✅ Correct: C

📖 Explanation:

The volume control block, often called a superblock in many file systems, records essential details about the partition, including total blocks, block size, and counts of free blocks and free file control blocks. This information enables the OS to allocate space and manage files efficiently. The other options describe unrelated system functions that are not managed by the VCB.

Q5. How does the directory structure differ between UFS and NTFS?

A. UFS uses a flat list, NTFS uses a B‑tree
B. UFS stores file names with inode numbers, NTFS stores metadata in the Master File Table ✅
C. UFS stores metadata in the MFT, NTFS uses inode numbers
D. Both use identical structures

💡 Difficulty: medium | ✅ Correct: B

📖 Explanation:

UFS keeps a directory that maps each file name to an inode number, while NTFS stores all file metadata—including names, attributes, and pointers—in rows of the Master File Table. This fundamental difference influences how each system resolves file lookups. The other statements either reverse the roles or claim no difference, which is inaccurate.

Q6. Why is it important for the boot control block to reside at a fixed position on a volume?

A. It speeds up file reads
B. It allows the OS to locate the boot code without scanning the disk ✅
C. It reduces power consumption
D. It enables dynamic resizing

💡 Difficulty: medium | ✅ Correct: B

📖 Explanation:

The boot control block’s fixed location (typically the first block) lets firmware and the operating system quickly retrieve boot code without searching the entire disk, ensuring a reliable start-up sequence. Speeding up general file reads, reducing power, or permitting dynamic resizing are unrelated concerns; the primary benefit is deterministic access to boot information.

Q7. What is the term used for the boot control block in UFS?

A. Boot block ✅
B. Superblock
C. Inode
D. MFT entry

💡 Difficulty: easy | ✅ Correct: A

📖 Explanation:

In UFS, the initial block that may contain boot code is specifically called the boot block. The superblock holds volume metadata, an inode represents a file’s metadata, and an MFT entry is an NTFS concept. Therefore, only the boot block correctly names the UFS structure that can store boot information.

Q8. In NTFS, where are the file metadata (such as attributes and location pointers) stored?

A. In the boot sector
B. In the directory tree
C. In the Master File Table ✅
D. In the swap file

💡 Difficulty: medium | ✅ Correct: C

📖 Explanation:

NTFS keeps all file metadata inside the Master File Table (MFT), where each file occupies a distinct row containing its attributes, security information, and data pointers. The boot sector only holds boot code, the directory tree organizes names, and the swap file is used for paging, none of which store comprehensive file metadata.

Q9. A system cannot mount a volume because the superblock appears corrupted. Which component should be examined first to diagnose the problem?

A. The volume control block (superblock) ✅
B. The boot block
C. The directory structure
D. The per‑file FCB

💡 Difficulty: medium | ✅ Correct: A

📖 Explanation:

Since the error directly mentions the superblock, the logical first step is to inspect the volume control block that contains this critical metadata. Corruption here can prevent mounting. The boot block, directory structure, and per‑file FCB are unrelated to the mounting process and would not explain a superblock failure.

Q10. A file of size 10,240 bytes needs to be stored on a disk with a block size of 4,096 bytes. How many blocks are required to hold the file?

A. 1 block
B. 2 blocks
C. 3 blocks ✅
D. 4 blocks

💡 Difficulty: hard | ✅ Correct: C

📖 Explanation:

Divide the file size by the block size: \(10,240 ÷ 4,096 ≈ 2.5\). Since a block cannot be partially allocated, the file must occupy three whole blocks, rounding up to the next integer. Option C correctly reflects this. Options A and B underestimate the needed space, while D overestimates it.

Q11. What role does the free‑block pointer play in volume management?

A. Tracks used blocks
B. Points to a list of available blocks for allocation ✅
C. Stores file permissions
D. Manages network sockets

💡 Difficulty: medium | ✅ Correct: B

📖 Explanation:

The free‑block pointer maintains a reference to a list or bitmap of blocks that are currently unallocated, allowing the file system to quickly find space for new data. It does not track used blocks, store permissions, or handle networking, making the other options incorrect.

Q12. How does the handling of the free‑FCB count differ between UFS and NTFS?

A. Both store count in the boot block
B. UFS uses a linked list, NTFS uses a bitmap
C. UFS does not track free FCBs, NTFS tracks them in the MFT
D. UFS stores count in the superblock, NTFS stores count within the MFT ✅

💡 Difficulty: hard | ✅ Correct: D

📖 Explanation:

UFS records the number of free file control blocks in its superblock, while NTFS keeps this information inside the Master File Table as part of its metadata structures. The other statements misrepresent where each system stores the count or claim mechanisms that are not used.

Q13. When mounting several partitions, which component ensures that each file receives a unique identifier across the system?

A. The per‑file FCB (or MFT row) ✅
B. The boot block
C. The free‑block pointer
D. The directory name

💡 Difficulty: medium | ✅ Correct: A

📖 Explanation:

Each file’s unique identifier is stored in its per‑file control block (FCB) in UFS or as a row in the MFT for NTFS. This identifier distinguishes files even if they have identical names in different directories. The boot block, free‑block pointer, and directory name serve other purposes and do not guarantee uniqueness.

Q14. A user asks where the Master File Table (MFT) is located on an NTFS volume. Which statement is correct?

A. At the end of the volume
B. Immediately after the boot sector ✅
C. In the root directory
D. Scattered throughout the volume

💡 Difficulty: easy | ✅ Correct: B

📖 Explanation:

In NTFS, the MFT typically begins right after the boot sector, making it the second major structure on the volume. This placement allows the system to locate file metadata early during mounting. It is not placed at the end, within the root directory, or arbitrarily scattered, so those options are incorrect.

Q15. How does separating the boot control block from the volume control block affect system recovery after a crash?

A. It prevents any recovery
B. It forces re‑formatting
C. It allows the boot code to be loaded even if the volume metadata is damaged, enabling partial recovery ✅
D. It merges both blocks for faster boot

💡 Difficulty: hard | ✅ Correct: C

📖 Explanation:

Keeping the boot control block independent means the system can still read essential boot code even if the volume control block (superblock) becomes corrupted. This enables the OS to start a recovery process or boot from alternate media. The other options either exaggerate the impact or describe nonexistent behavior such as merging blocks.
