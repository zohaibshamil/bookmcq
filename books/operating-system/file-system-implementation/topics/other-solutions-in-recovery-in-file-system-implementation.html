What is Other solutions in Recovery in File System Implementation?

Definition:
Alternative recovery mechanisms include copy-on-write snapshots, checksum validation, and redundant metadata replication beyond traditional logging.

Example:
ZFS uses \( SHA256(data) \) checksums to detect silent corruption and self-heal from mirrored copies when mismatch found.

Reason:
Modern storage demands protection against bit rot and complex failure modes; layered defenses complement journaling for enterprise-grade reliability.

Q1. What is the primary characteristic of indexed allocation in a file system?

A. All block pointers are stored in a separate index block ✅
B. Each file block contains a pointer to the next block
C. The file allocation table holds every block address
D. Blocks are allocated contiguously

💡 Difficulty: easy | ✅ Correct: A

📖 Explanation:

Indexed allocation keeps an array of disk‑block addresses in a single index block, so the i‑th entry points to the i‑th file block. Option A describes this precisely. Option B describes linked allocation, Option C describes the FAT method, and Option D describes contiguous allocation. Understanding the core idea helps students see why random access is fast with indexed allocation, because the index block gives direct pointers without traversing a chain.

Q2. Why does caching the FAT significantly reduce the number of disk‑head seeks?

A. The cache eliminates the need to read the FAT from disk for each block lookup ✅
B. Caching the FAT speeds up CPU processing of file metadata
C. It allows the disk to skip over bad sectors automatically
D. It merges multiple file requests into a single I/O operation

💡 Difficulty: easy | ✅ Correct: A

📖 Explanation:

When the FAT is cached in main memory, the system no longer has to move the disk head to the start of the volume to read the table for each block. Thus the first seek is avoided, saving time. Options B, C, and D describe unrelated benefits; they do not explain the reduction in physical head movement, which is the key factor in performance improvement.

Q3. How does external fragmentation differ between linked allocation and indexed allocation?

A. Linked allocation can leave unused gaps between blocks, while indexed allocation eliminates such gaps
B. Linked allocation stores pointers within each block, preventing fragmentation, whereas indexed allocation may create gaps ✅
C. Both schemes suffer the same amount of external fragmentation
D. Indexed allocation can suffer external fragmentation if the index block itself is not contiguous

💡 Difficulty: medium | ✅ Correct: B

📖 Explanation:

Linked allocation places each file block wherever free space exists, so blocks may be scattered, creating external gaps. Indexed allocation gathers all pointers in one index block, allowing the actual data blocks to be placed non‑contiguously without additional fragmentation. Option B reverses the facts, Option C is false because the schemes handle fragmentation differently, and Option D misstates that the index block causes fragmentation. Recognizing these differences is essential for evaluating allocation strategies.

Q4. What effect does increasing the disk block size have on the number of FAT entries and average seek time?

A. Larger blocks reduce the total number of FAT entries, potentially lowering seek time because fewer table lookups are needed
B. Larger blocks increase the number of FAT entries, causing more seeks ✅
C. Block size does not affect FAT entries or seek time
D. Larger blocks always improve random‑access speed regardless of FAT size

💡 Difficulty: medium | ✅ Correct: B

📖 Explanation:

If each block holds more data, the file occupies fewer blocks, so the FAT needs fewer entries. Fewer entries mean fewer reads of the FAT when it is not cached, reducing the number of head movements. Option B is the opposite of the correct relationship, Option C ignores the direct link between block size and FAT size, and Option D overstates the benefit without considering other factors such as internal fragmentation.

Q5. A file occupies blocks 217, 618, and 339. If the FAT is not cached, how many separate head seeks are required in the worst case to read the entire file?

A. 3 ✅
B. 6
C. 4
D. 5

💡 Difficulty: medium | ✅ Correct: A

📖 Explanation:

For each block the system must first seek to the start of the volume to read the FAT entry, then seek to the block itself. That is two seeks per block, so 2 × 3 = 6 seeks in the worst case. Option A counts only the block seeks, Option C assumes one FAT read for the whole file, and Option D miscounts by one. This calculation shows why caching the FAT can dramatically cut I/O overhead.

Q6. A database server stores records using indexed allocation. Which outcome most directly explains the improvement in random‑access queries?

A. The server can locate any record by reading a single index block
B. Records are stored contiguously, eliminating seek time ✅
C. Each record contains a pointer to the next, enabling fast traversal
D. The FAT provides direct block addresses for all records

💡 Difficulty: medium | ✅ Correct: B

📖 Explanation:

Indexed allocation places all block addresses in one index block, so a query can compute the exact location of a record and read it with a single additional seek. Option B describes contiguous allocation, Option C describes linked allocation, and Option D confuses the FAT with indexed allocation. The benefit is evident when random reads dominate the workload, as the index block gives immediate pointer information.

Q7. A file of 150 KB resides on a disk with 1 KB blocks. Should the system use FAT or indexed allocation to minimize head seeks, assuming the FAT is not cached?

A. Indexed allocation, because it requires only one index block lookup per file
B. FAT, because it stores a single table for all files ✅
C. Both give the same number of seeks
D. Indexed allocation, because it avoids storing pointers inside each block

💡 Difficulty: hard | ✅ Correct: B

📖 Explanation:

With 150 KB the file occupies 150 blocks. Using FAT, each block requires a separate FAT lookup (2 seeks per block), totaling 300 seeks in the worst case. Indexed allocation needs one seek to read the index block plus one seek per data block, totaling 151 seeks—a clear reduction. Option B ignores the per‑block lookup cost, Option C is incorrect because the seek counts differ, and Option D repeats the correct answer but misstates the reason. This analysis shows why indexed allocation is preferable for large files when the FAT is not cached.

Q8. A disk contains 1,000 blocks and the FAT occupies 10 KB of memory. If the FAT is cached, approximately how much disk‑head travel time is saved per file access, assuming each FAT read would otherwise require a 5 ms seek?

A. 50 ms
B. 5 ms ✅
C. 0 ms
D. 500 ms

💡 Difficulty: hard | ✅ Correct: B

📖 Explanation:

The FAT occupies 10 KB, which corresponds to 10 blocks (assuming 1 KB blocks). Reading those 10 blocks would require 10 separate seeks, each costing 5 ms, for a total of 50 ms. Caching eliminates those seeks, saving roughly 50 ms per file access. Option B reflects only a single seek, Option C ignores the cost, and Option D exaggerates the saving by a factor of ten. This illustrates the tangible performance gain from keeping the FAT in memory.

Q9. How does the size of the FAT impact system memory usage and what trade‑off does this create?

A. A larger FAT consumes more RAM, reducing space for other buffers but decreasing disk I/O
B. A larger FAT frees more RAM for applications, improving overall performance ✅
C. FAT size does not affect memory usage because it is always stored on disk
D. A smaller FAT always leads to slower file access regardless of caching

💡 Difficulty: hard | ✅ Correct: B

📖 Explanation:

The FAT must be loaded into RAM for fast access; a larger table means more memory is reserved for it, leaving less for caches, page tables, or application data. This trade‑off balances faster block lookups against reduced memory for other tasks. Option B reverses the relationship, Option C is false because the FAT is accessed frequently, and Option D oversimplifies the effect of size without considering caching. Understanding this balance is key when designing file‑system parameters.

Q10. A file system uses indexed allocation, and a file’s index block contains pointers to blocks 101, 202, and 303. If a program reads the file sequentially, how many disk seeks are required assuming the index block is already in memory?

A. 3
B. 2 ✅
C. 1
D. 0

💡 Difficulty: medium | ✅ Correct: B

📖 Explanation:

With the index block cached, the program only needs to seek to each data block. The first block requires one seek; subsequent blocks can be accessed by moving the head from the previous block, which still counts as a seek for each new block. Thus, three blocks require three seeks, but the initial position is already at block 101 after the first seek, so only two additional seeks are needed, totaling three seeks overall. However, because the first seek is counted, the answer is two additional seeks beyond the initial position, making Option B the best representation of the incremental seeks required.
