Q1. What term describes the condition where free disk space is divided into many small non‑contiguous pieces making it difficult to allocate large files?

🔹 A. External fragmentation
🔹 B. Internal fragmentation
🔹 C. Disk latency
🔹 D. File locking

💡 Difficulty: easy | ✅ Correct: A

📖 Explanation:

External fragmentation occurs when free space is broken into many tiny, non‑adjacent pieces, so a large file cannot find a single contiguous region even though the total free space is enough. This matches the definition asked. Internal fragmentation deals with wasted space inside allocated blocks, not the distribution of free space. Disk latency and file locking are performance or concurrency issues, not storage layout problems. Recognizing external fragmentation guides the choice of allocation algorithms.

Q2. Why does contiguous allocation enable direct access to any block of a file without reading preceding blocks?

🔹 A. Because the file system stores the starting block number and calculates offset
🔹 B. Because blocks are linked with pointers
🔹 C. Because data is stored in a linked list
🔹 D. Because the OS caches all file blocks

💡 Difficulty: easy | ✅ Correct: C

📖 Explanation:

Contiguous allocation records the first block of the file; to reach block i the system adds i to that start address, giving the exact location instantly. This calculation provides direct access. Linked pointers are used in linked allocation, not contiguous. A linked list storage scheme still requires traversing pointers, so it cannot jump directly. OS caching may speed reads but does not explain the deterministic calculation. Hence the first option correctly describes the mechanism.

Q3. A disk has free holes of sizes 20 KB, 12 KB, and 8 KB. A new file of 10 KB needs to be stored. Which allocation strategy will place the file in the smallest possible hole that fits?

🔹 A. First fit
🔹 B. Best fit
🔹 C. Worst fit
🔹 D. Random fit

💡 Difficulty: medium | ✅ Correct: B

📖 Explanation:

Best‑fit scans all free holes and chooses the smallest one that can accommodate the request, which is the 12 KB hole in this scenario. First‑fit would also select the 20 KB hole because it is the first that fits, not the smallest. Worst‑fit chooses the largest hole, and random fit has no defined rule. Understanding best‑fit helps reduce wasted space while still satisfying the allocation request.

Q4. Which statement best captures the trade‑off between first‑fit and best‑fit allocation strategies?

🔹 A. First‑fit is always faster and uses less space than best‑fit
🔹 B. Best‑fit always produces less external fragmentation but can be slower
🔹 C. First‑fit and best‑fit have identical performance in all cases
🔹 D. Best‑fit never suffers from fragmentation

💡 Difficulty: medium | ✅ Correct: B

📖 Explanation:

Best‑fit tends to leave smaller leftover holes, reducing external fragmentation, but it must examine more holes to find the optimal spot, making it slower on average. First‑fit stops at the first suitable hole, which speeds allocation but can leave larger fragments. The other options are inaccurate: first‑fit is not always faster and does not guarantee less waste, and no algorithm completely eliminates fragmentation. Therefore the second choice correctly describes the trade‑off.

Q5. A file system uses linked allocation for files. When reading a file sequentially, which advantage does linked allocation have over contiguous allocation?

🔹 A. Direct access to any block is possible
🔹 B. No external fragmentation
🔹 C. Simpler file size expansion
🔹 D. Faster random reads

💡 Difficulty: medium | ✅ Correct: C

📖 Explanation:

Linked allocation stores each block with a pointer to the next, so adding new blocks simply involves updating a pointer, making file growth straightforward without relocating existing data. This flexibility is an advantage over contiguous allocation, which may require moving the entire file to create space. Direct access is easier with contiguous allocation, not linked. External fragmentation is eliminated in linked allocation but the question asks specifically about sequential reads. Random reads are slower because each block must be followed through pointers.

Q6. A disk has three free holes each of size 5 KB, 5 KB, and 5 KB. A single file of size 12 KB needs to be allocated using contiguous allocation. Which outcome demonstrates that external fragmentation prevents allocating the file even though total free space exceeds the request?

🔹 A. Allocation succeeds
🔹 B. Allocation fails because of insufficient total space
🔹 C. Allocation fails because no single hole is large enough
🔹 D. Allocation succeeds using linked allocation

💡 Difficulty: hard | ✅ Correct: C

📖 Explanation:

External fragmentation describes a situation where enough total free space exists (15 KB) but no single contiguous hole can satisfy a request larger than any individual hole (12 KB). Therefore the allocation fails, not because the overall space is lacking, but because the free space is split into pieces too small to hold the file. Options A and D are incorrect because they assume success, and B misidentifies the cause as insufficient total space.

Q7. In the worst case, what is the time complexity of locating a suitable free hole using the first‑fit algorithm on a disk with \(n\) free holes?

🔹 A. \(O(1)\)
🔹 B. \(O(\log n)\)
🔹 C. \(O(n)\)
🔹 D. \(O(n^2)\)

💡 Difficulty: hard | ✅ Correct: C

📖 Explanation:

First‑fit scans the list of free holes sequentially until it finds one large enough. In the worst case, the suitable hole may be the last one examined or none may exist, requiring the algorithm to inspect every hole. This linear scanning results in a time complexity of \(O(n)\). Constant time \(O(1)\) would imply immediate access, which is not the case. Logarithmic \(O(\log n)\) would require a sorted structure, and \(O(n^2)\) would imply nested loops, both inaccurate for first‑fit.

Q8. A file system has free holes of sizes 4 KB, 7 KB, 12 KB, and 20 KB. Two new files of sizes 6 KB and 15 KB must be stored. Which allocation sequence using first‑fit will successfully store both files?

🔹 A. Store 6 KB in 7 KB hole then 15 KB in 20 KB hole
🔹 B. Store 6 KB in 4 KB hole then 15 KB in 12 KB hole
🔹 C. Store 6 KB in 12 KB hole then 15 KB in 20 KB hole
🔹 D. Store 6 KB in 4 KB hole then 15 KB in 20 KB hole

💡 Difficulty: medium | ✅ Correct: A

📖 Explanation:

First‑fit examines holes in order. The 6 KB request cannot fit in the 4 KB hole, so it moves to the 7 KB hole and fits there. After that allocation, the remaining holes are 4 KB, 12 KB, and 20 KB. The 15 KB request cannot fit in 4 KB or 12 KB, but it fits in the 20 KB hole, completing both allocations. The other options either place files in holes that are too small or skip the correct order, leading to failure.

Q9. How does the size of the allocation unit (block size) influence the degree of external fragmentation in a contiguous allocation scheme?

🔹 A. Larger blocks increase fragmentation because more space is wasted per file
🔹 B. Smaller blocks reduce fragmentation by allowing finer granularity
🔹 C. Block size has no effect on fragmentation
🔹 D. Fragmentation is only affected by file size not block size

💡 Difficulty: medium | ✅ Correct: C

📖 Explanation:

When the allocation unit is smaller, the system can fit files into tighter spaces, leaving less unused space between allocated blocks and thus reducing external fragmentation. Larger blocks force files to occupy whole blocks even if they need only a fraction, creating larger gaps that cannot be used by smaller files. Therefore the second option correctly explains the relationship. The other statements either invert the effect or claim no influence, which contradicts how block granularity works.
