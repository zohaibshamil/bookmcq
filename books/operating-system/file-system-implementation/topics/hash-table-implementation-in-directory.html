What is Hash table Implementation in Directory?

Definition:
Hash table directory implementation uses a hash function h(name) h(name) h(name) to map filenames to bucket indices for average constant-time lookups.

Example:
Looking up myfile.txt myfile.txt myfile.txt computes h(myfile.txt)=42 h(\text{myfile.txt}) = 42 h(myfile.txt)=42 and directly accesses bucket 42 instead of scanning all entries.

Reason:
Reduces average lookup complexity from O(n) O(n) O(n) to O(1) O(1) O(1), significantly improving performance for directories with thousands of entries despite collision handling overhead.

📝 All Hash table Implementation in Directory MCQs

Q1. What is the primary purpose of a hash function in a hash table?

A.To sort keys
B.To compute an index for a key ✅
C.To encrypt data
D.To compress values
💡 Difficulty: easy | ✅ Correct: B

📖 Explanation: A hash function takes an input key and produces a numeric value that is used as an index into the table. This index determines where the associated record is stored, allowing near‑constant‑time lookup, insertion, and deletion. Options A, C, and D describe unrelated operations: sorting, encryption, and compression are not the role of a hash function in a hash table. By converting keys directly to positions, the function enables the core advantage of hash tables—fast access.

Q2. Why does a high load factor generally increase the average search time in a hash table?

A.It reduces the number of buckets
B.It causes more collisions
C.It expands the table automatically ✅
D.It improves cache locality
💡 Difficulty: easy | ✅ Correct: C

📖 Explanation: A high load factor means many keys share the same limited number of buckets, so collisions become more frequent. Each collision forces the algorithm to examine additional entries—either by following a chain or probing further—raising the average number of steps required to find or insert a key. Options A and D describe effects that are not directly tied to load factor, while option C is incorrect because a high load factor does not trigger automatic expansion without explicit resizing logic.

Q3. A hash table uses separate chaining with 10 buckets. If 30 keys are inserted, what is the expected average chain length?

A.3
B.2 ✅
C.5
D.1
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: The average chain length equals the load factor, calculated as the number of keys divided by the number of buckets. With 30 keys and 10 buckets, the load factor is 30/10=330/10 = 330/10=3, meaning each bucket will on average hold three keys in its linked list. Option B underestimates the length, option C overestimates it, and option D suggests an unrealistically short chain. Understanding this relationship helps predict memory usage and lookup cost in a chained hash table.

Q4. How does double hashing improve upon linear probing in open addressing?

A.It uses a larger table
B.It stores keys in sorted order
C.It reduces memory usage
D.It uses two hash functions to compute probe sequence, reducing primary clustering ✅
💡 Difficulty: medium | ✅ Correct: D

📖 Explanation: Double hashing generates a second hash value that determines the step size for each probe, so the sequence of examined slots depends on both hash results. This breaks up the contiguous clusters that linear probing often creates, leading to more uniform probe distribution and fewer repeated collisions. Options A, B, and C describe unrelated benefits; they do not address the core issue of probe pattern and clustering that double hashing specifically mitigates.

Q5. In a dynamic hash table that doubles its size when a threshold is crossed, which condition typically triggers the rehash operation?

A.When number of deletions exceeds 50% ✅
B.When load factor exceeds 0.75
C.When any collision occurs
D.When the table becomes empty
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: Most implementations monitor the load factor, defined as n/mn/mn/m where nnn is the number of stored keys and mmm is the bucket count. When this ratio grows beyond a preset limit—commonly 0.75—the table is resized (usually doubled) and all keys are re‑hashed to maintain efficient O(1) operations. Option A concerns deletions, option C would cause excessive rehashing, and option D is irrelevant because an empty table does not need resizing. Keeping the load factor below the threshold preserves performance.

Q8. Why might a hash table with open addressing degrade to O(n)O(n)O(n) performance even if the load factor is kept below 0.5?

B.Because the table size is too small
