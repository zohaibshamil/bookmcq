Q1. What value is initially stored in each entry of an index block when a new file is created?

🔹 A. 0
🔹 B. -1
🔹 C. null
🔹 D. empty string

💡 Difficulty: easy | ✅ Correct: A

📖 Explanation:

The correct answer is \null\ because a fresh index block must indicate that no disk blocks have been assigned yet. Option A (0) would suggest a valid block address, which is incorrect. Option B (-1) is sometimes used as a sentinel but the standard convention here is null. Option D (empty string) is not a valid pointer type. In practice, a null entry tells the file system that the corresponding block must be allocated before data can be written, ensuring correct allocation behavior.

Q2. Why does indexed allocation avoid external fragmentation compared to linked allocation?

🔹 A. It stores all pointers contiguously in memory
🔹 B. It allocates each file block separately
🔹 C. It allows any free disk block to satisfy a request
🔹 D. It uses a fixed-size index block

💡 Difficulty: easy | ✅ Correct: A

📖 Explanation:

Indexed allocation avoids external fragmentation because each file block can be placed in any free disk block, and the index block simply records those locations. Option A is wrong because the pointers are kept on disk, not necessarily in RAM. Option B describes linked allocation, which still suffers from fragmentation when blocks become scattered. Option D is incorrect because the size of the index block does not directly affect fragmentation. The correct choice explains that the flexibility of choosing any free block prevents gaps from forming.

Q3. How does the overhead of an index block compare to the pointer overhead of linked allocation for a two‑block file?

🔹 A. Index block overhead is lower
🔹 B. Index block overhead is higher
🔹 C. Both have equal overhead
🔹 D. Overhead depends on file size

💡 Difficulty: medium | ✅ Correct: A

📖 Explanation:

For a file consisting of only two blocks, indexed allocation requires an entire index block even though only two pointers are needed, so its overhead is higher than linked allocation, which adds just one pointer per block. Option A is wrong because the index block adds extra space regardless of the number of pointers. Option C is inaccurate; linked allocation uses fewer bytes for two pointers. Option D is misleading since the overhead difference is fixed for this case, not variable with file size. The higher overhead reflects the cost of reserving a full block for pointers.

Q4. A database stores a log file that initially occupies one block. After heavy activity, the file grows to 150 blocks. Which allocation strategy would minimize wasted space while still permitting direct access?

🔹 A. Single index block
🔹 B. Linked allocation with block‑level pointers
🔹 C. Multi‑level index blocks linked together
🔹 D. Hybrid of indexed and linked allocation

💡 Difficulty: medium | ✅ Correct: A

📖 Explanation:

Using multiple index blocks linked together (multi‑level indexing) allows the system to add new index blocks as the file expands, avoiding the waste of a single large index block for a small file while preserving direct access. Option A would waste space because a single index block must hold 150 pointers, many of which may be unused early on. Option B loses the advantage of direct access, requiring sequential traversal. Option D adds unnecessary complexity without solving the waste issue. The correct approach balances space efficiency and random‑access capability.

Q5. If a file system reserves one disk block for an index block that can hold 100 pointers, what is the maximum file size (in blocks) that can be addressed without adding another index block?

🔹 A. 100 blocks
🔹 B. 99 blocks
🔹 C. 101 blocks
🔹 D. 200 blocks

💡 Difficulty: medium | ✅ Correct: B

📖 Explanation:

An index block that holds 100 pointers can directly reference up to 100 data blocks, so the maximum file size addressable is 100 blocks. Option B (99) underestimates the capacity; each pointer can be used. Option C (101) exceeds the pointer count, requiring an additional index block. Option D (200) would need two index blocks. Understanding the pointer capacity of the index block is essential for planning storage limits and ensuring that the file system can allocate enough space for growing files.

Q6. A file system uses indexed allocation. When the third block of a file is written, what steps occur?

🔹 A. Allocate a new index block and store its address
🔹 B. Replace a null entry with the new block’s address
🔹 C. Append the block address to the end of the file
🔹 D. Delete the oldest block to free space

💡 Difficulty: medium | ✅ Correct: A

📖 Explanation:

When the third block is written, the system locates the third entry in the existing index block (which was initially null) and replaces that null with the address of the newly allocated disk block. Option A is unnecessary because the existing index block already has space for the pointer. Option C describes linked allocation, not indexed. Option D is unrelated to writing a new block. The correct step updates the index block, enabling direct access to the new block.

Q7. Which characteristic of indexed allocation most directly contributes to its ability to provide direct access to any block?

🔹 A. Storing pointers in a linked list
🔹 B. Using a single contiguous block for data
🔹 C. Having a separate index block with pointers
🔹 D. Allocating blocks in fixed‑size chunks

💡 Difficulty: hard | ✅ Correct: A

📖 Explanation:

Direct access is achieved because the index block contains a pointer for each logical block, allowing the system to jump directly to the required disk location. Option A (linked list) forces sequential traversal, eliminating direct access. Option B (contiguous data) would also allow direct access but is not typical for indexed allocation. Option D (fixed‑size chunks) does not explain the pointer mechanism. The separate index block is the key structure that maps logical positions to physical addresses instantly.

Q8. A video editing application stores a 2‑GB video file using indexed allocation with a block size of 4 KB. Approximately how many pointers must the index block contain?

🔹 A. \(2\,\text{GB} \div 4\,\text{KB} = 524{,}288\) pointers
🔹 B. \(2\,\text{GB} \div 4\,\text{KB} = 524{,}288\) blocks, each needing a pointer
🔹 C. \(2\,\text{GB} \times 4\,\text{KB}\) pointers
🔹 D. \(2\,\text{GB} \div 4\,\text{KB} = 2{,}048\) pointers

💡 Difficulty: hard | ✅ Correct: A

📖 Explanation:

The file size divided by the block size gives the number of blocks, and each block requires one pointer in the index block, so the correct calculation is \(2\,\text{GB} \div 4\,\text{KB} = 524{,}288\) pointers. Option A repeats the calculation but labels it incorrectly as pointers without context; however, it is essentially the same value, making it ambiguous. Option C multiplies instead of dividing, leading to an astronomically large number. Option D uses a far smaller result, miscalculating the division. Understanding the relationship between file size, block size, and pointer count is crucial for estimating index block overhead.

Q9. When an index block becomes full, which mechanism is typically employed to continue supporting larger files?

🔹 A. Replace the index block with a larger one
🔹 B. Link additional index blocks together
🔹 C. Compress existing pointers to free space
🔹 D. Delete the oldest pointers

💡 Difficulty: hard | ✅ Correct: A

📖 Explanation:

The standard method is to link additional index blocks, forming a chain that can be traversed to find pointers beyond the capacity of the first block. Option A would require moving all pointers, which is costly and error‑prone. Option C (compression) is not practical for pointer storage. Option D (deleting pointers) would lose data. Linking new index blocks preserves existing pointers and extends the file’s addressable range, ensuring scalability without data loss.

Q10. A system administrator notices that many small files are consuming a disproportionate amount of disk space due to indexed allocation. Which change would most effectively reduce this waste?

🔹 A. Increase the block size to 8 KB
🔹 B. Switch to linked allocation for small files
🔹 C. Use a multi‑level index scheme for all files
🔹 D. Store all files in a single large index block

💡 Difficulty: hard | ✅ Correct: A

📖 Explanation:

Switching to linked allocation for small files eliminates the need for a full index block when only one or two pointers are required, directly reducing wasted space. Option A (larger block size) would increase internal fragmentation. Option C adds complexity without addressing the specific waste caused by index blocks. Option D (single large index block) would dramatically increase waste. The correct solution matches the allocation method to file size, optimizing space usage.
