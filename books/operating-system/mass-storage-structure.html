📖 Mass Storage Structure

Chapter Overview:

Mass Storage Structure examines how operating systems organize, access, manage, and protect large volumes of persistent data. Building on file systems and basic I/O operations, this chapter explores magnetic disks, solid-state drives, magnetic tapes, and storage attachment architectures. It explains disk scheduling algorithms, disk initialization, boot blocks, bad-block management, and swap-space organization. It also examines RAID technologies, their reliability and performance benefits, design trade-offs, and stable storage implementation, connecting physical storage organization with efficient and dependable system operation.

Prerequisites:

Students should understand file systems, file operations, device management, I/O requests, and the role of secondary storage in an operating system. Familiarity with storage devices, input/output controllers, block-based data access, and interrupt-driven I/O will help explain disk organization and scheduling. Basic knowledge of data redundancy, parallel operations, and operating system memory management is useful for understanding RAID configurations and swap-space management.

Learning Objectives:

After studying this chapter, students should be able to explain the structure and operation of magnetic disks, solid-state disks, and magnetic tapes. They should distinguish host-attached storage, NAS, and SAN; calculate disk head movements using FCFS, SSTF, SCAN, C-SCAN, and LOOK; and evaluate disk scheduling choices. They should also explain formatting, boot blocks, bad blocks, swap-space management, RAID levels, redundancy, parallelism, storage reliability, RAID limitations, and stable storage implementation.

Topics Covered:

  • Mass Storage Devices and Disk Structure - examines magnetic disks, solid-state disks, magnetic tapes, and disk organization.
  • Storage Attachment Architectures - compares host-attached storage, network-attached storage, and storage area networks.
  • Disk Scheduling Algorithms - explains FCFS, SSTF, SCAN, C-SCAN, LOOK, and algorithm selection.
  • Disk Management and Swap Space - covers formatting, boot blocks, bad blocks, and swap-space management.
  • RAID Reliability and Performance - examines redundancy, parallelism, RAID levels, selection, extensions, and implementation problems.
  • RAID Design and Evaluation - evaluates storage configurations according to reliability, performance, capacity, and limitations.
  • Stable Storage Implementation - explains techniques for preserving data consistency and reliability despite storage failures.

Chapter Learning Path:

Begin with physical storage devices and disk organization to understand how persistent data is stored. Next, study host-attached storage, NAS, and SAN to understand how systems access storage resources. Learn disk scheduling algorithms and their head-movement calculations before examining formatting, boot blocks, and bad blocks. Then study swap-space requirements and management. Progress to RAID concepts, reliability, performance, and level selection. Finish with RAID limitations and stable storage implementation to understand dependable data preservation.

How the Topics Connect:

Storage-device structures establish how data is physically organized and accessed. Attachment architectures determine how computers communicate with storage systems. Disk scheduling improves access request handling, while formatting and bad-block management prepare and maintain usable storage. Swap space extends available memory resources using persistent storage. RAID combines multiple devices to improve reliability or performance, and stable storage addresses data preservation when failures occur.

End-to-End Flow:

Consider a server storing a 100 GB database on a RAID array containing four 1 TB disks. A host accesses the storage through a SAN connection. When several read requests arrive, the disk scheduler selects their execution order using an appropriate algorithm. RAID distributes or mirrors data according to its configuration, while redundancy helps protect against supported disk failures. The operating system also manages swap space separately. During storage preparation, formatting establishes usable structures, and bad-block handling prevents unreliable sectors from being used.

Why This Chapter Matters:

Without organized mass storage, operating systems could not efficiently retain large datasets or manage persistent information. Poor disk scheduling increases access delays, while inadequate redundancy risks data loss. Swap-space management supports memory operations, and stable storage helps preserve critical information. These mechanisms underpin databases, file systems, servers, backups, and reliable storage infrastructure.

Common Confusions Across Topics:

Students sometimes believe 'NAS and SAN provide storage in the same way.' NAS typically provides file-level access, whereas SAN provides block-level storage access. Another misconception is 'RAID always guarantees complete data protection.' RAID reliability depends on its level and failure assumptions, and it does not replace backups. Finally, 'all disk scheduling algorithms minimize movement equally' is incorrect because each policy uses different request-selection and head-movement strategies.

Exam Focus Areas:

Examinations commonly require calculating total head movement using FCFS, SSTF, SCAN, C-SCAN, and LOOK scheduling. Students should compare storage attachment architectures, identify disk-management operations, and explain swap-space organization. RAID questions frequently involve level characteristics, capacity, redundancy, performance, and fault tolerance. Other important areas include bad-block handling, algorithm selection, RAID limitations, and stable storage reliability.

Chapter Summary:

This chapter explains how operating systems manage persistent storage across different physical devices and attachment architectures. Disk scheduling organizes access requests, while formatting and maintenance prepare storage for reliable use. Swap space supports memory management, and RAID combines storage devices to improve availability or performance. Stable storage completes the discussion by addressing how important information can remain dependable despite hardware failures.

Key Terms:

  • Magnetic Disk - a secondary storage device that stores data magnetically on rotating platters.
  • Solid-State Disk (SSD) - a storage device that uses flash memory rather than rotating magnetic platters.
  • Disk Scheduling - the process of determining the order in which pending disk requests are serviced.
  • Network-Attached Storage (NAS) - a storage system that provides file-level access over a network.
  • Storage Area Network (SAN) - a dedicated storage network that provides block-level access to storage devices.
  • Swap Space - disk or other backing storage reserved for supporting virtual memory operations.
  • RAID - a technique that combines multiple storage devices to provide performance, redundancy, or both.
  • Stable Storage - a storage abstraction designed to preserve information reliably despite specified failure conditions.

Further Reading:

  • Linux Kernel Documentation - Multi-Queue Block I/O Queueing Mechanism (blk-mq) - explains block-device request handling and the Linux storage I/O scheduling infrastructure.
  • Linux Kernel Documentation - Multiple Devices (MD) RAID - describes software RAID configuration, supported levels, device management, and array recovery.
  • Linux Man-pages - swapon(8) and mkswap(8) - provides practical information about preparing and enabling swap areas.
  • A Case for Redundant Arrays of Inexpensive Disks - David Patterson, Garth Gibson, and Randy Katz; introduces RAID concepts, reliability, parallelism, and RAID levels.
  • SNIA Dictionary - provides technical definitions and explanations of storage networking, NAS, SAN, RAID, and storage technologies.
  • Storage Networking Industry Association Technical Resources - explores storage architectures, data reliability, storage management, and enterprise storage technologies.
