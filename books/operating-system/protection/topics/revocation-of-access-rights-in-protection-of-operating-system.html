Q1. What is the confinement problem in computer security?

🔹 A. The inability to prevent a program from accessing the network.
🔹 B. The difficulty of ensuring that information cannot leave its original execution environment.
🔹 C. The challenge of encrypting all stored data.
🔹 D. The problem of authenticating users across domains.

💡 Difficulty: easy | ✅ Correct: B

📖 Explanation:

The confinement problem refers to the difficulty of guaranteeing that information initially stored in an object cannot migrate outside of its execution environment. Option B captures this definition. Option A describes network access, not confinement. Option C concerns encryption, which is a separate technique. Option D deals with authentication, which is unrelated. Understanding confinement is essential because it highlights why copy and owner rights alone cannot stop data leakage, linking directly to real‑world security policies.

Q2. Which of the following operations is NOT a primitive operation defined in the basic access‑matrix model?

🔹 A. Create domain
🔹 B. Delete object
🔹 C. Read right
🔹 D. Transfer rights

💡 Difficulty: easy | ✅ Correct: D

📖 Explanation:

In the basic access‑matrix model, operations such as creating a domain, deleting an object, and granting or checking a read right are defined primitives. Option D, Transfer rights, is not a primitive operation; it represents a higher‑level action that would require additional mechanisms. Options A, B, and C correctly describe basic matrix actions. Recognizing non‑primitive operations helps developers understand the limits of the model and when extensions are needed.

Q3. Why are copy and owner rights insufficient to prevent the propagation of information?

🔹 A. They completely block any data movement
🔹 B. They only limit who can initially obtain rights, not how rights can be further transferred or used
🔹 C. They encrypt all copied data automatically
🔹 D. They enforce network firewalls

💡 Difficulty: easy | ✅ Correct: C

📖 Explanation:

Copy and owner rights control who may initially receive a right, but they do not control subsequent actions once a right is granted. Option C correctly states that these rights do not prevent further propagation or usage. Options A and B describe capabilities that do not exist in the model, and D refers to network devices unrelated to rights. Understanding this limitation explains why additional mechanisms, such as confinement, are required in practice.

When a new domain is created, the access matrix must accommodate an additional row representing that domain’s permissions. Option A accurately describes this dynamic update. Option B suggests removal of columns, which concerns objects, not domains. Option C implies immutability, contradicting the ability to add domains. Option D describes merging, which is a separate policy decision. Recognizing the need for runtime updates is crucial for designing systems that can adapt to changing security requirements.

Q5. What does the sparsity of an access matrix imply for choosing an implementation method?

🔹 A. It makes the matrix dense and easy to store
🔹 B. It suggests using structures that store only non‑empty entries
🔹 C. It requires storing every possible right for every domain‑object pair
🔹 D. It eliminates the need for rights sets

💡 Difficulty: medium | ✅ Correct: B

📖 Explanation:

A sparse matrix contains many empty cells, so storing the full two‑dimensional array would waste space. Option B correctly indicates that implementations should keep only the non‑empty triples, reducing memory usage. Option A is opposite of sparsity, Option C describes a worst‑case approach, and Option D is inaccurate because rights sets are still needed. This insight guides developers toward efficient data structures like global tables.

Q6. Why is the confinement problem generally considered unsolvable?

🔹 A. Because hardware cannot enforce it
🔹 B. Because networks are insecure
🔹 C. Because users forget passwords
🔹 D. Because it would require solving undecidable problems

💡 Difficulty: medium | ✅ Correct: D

📖 Explanation:

The confinement problem asks whether a program can be guaranteed never to leak data, which would entail predicting all possible program behaviors. This task is equivalent to solving the halting problem, an undecidable issue, making a general solution impossible. Option D captures this reasoning. Options A, B, and C refer to unrelated practical obstacles, not the fundamental theoretical limitation. Recognizing this unsolvability helps set realistic expectations for security mechanisms.

Q7. How does revoking an access right manifest within the access matrix?

🔹 A. Revocation removes a right from a specific entry
🔹 B. Revocation adds new rights to all entries
🔹 C. Revocation changes user passwords
🔹 D. Revocation duplicates existing rights

💡 Difficulty: medium | ✅ Correct: A

📖 Explanation:

Revocation directly modifies the matrix by deleting the specified right from the <domain, object> cell, thereby preventing future use of that permission. Option A accurately describes this process. Options B and D incorrectly suggest adding or copying rights, while C pertains to authentication rather than matrix entries. Understanding this direct relationship is vital for implementing effective security policies that can adapt to changing trust levels.

🔹 D. To record audit logs of access attempts

A global table records every non‑empty <domain, object, rights‑set> triple, enabling efficient searches and updates without allocating space for empty cells. Option C correctly identifies this purpose. Options A and B describe unrelated structures, and D refers to logging rather than permission storage. This design choice directly supports dynamic and sparse permission management in real systems.
