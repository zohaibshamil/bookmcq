What is Cambridge CAP System is an example of Capability Based Systems?

Definition:
The Cambridge CAP computer featured hardware-enforced capabilities with tagged memory, ensuring that only valid capability tokens could reference objects and preventing pointer forgery.

Example:
Memory words included tag bit; tag=1 \text{tag}=1 tag=1 indicated capability, checked automatically on every load/store instruction.

Reason:
Hardware tagging eliminated software overhead for capability validation, demonstrating that architectural support makes capability systems practical and secure.

Q1. In the lock–key protection mechanism, what is the name of the list that contains the unique bit patterns assigned to each domain?

A.Locks
B.Keys ✅
C.Capabilities
D.Access lists
💡 Difficulty: easy | ✅ Correct: B

📖 Explanation: The list of unique bit patterns attached to a domain is called a key list, and each individual pattern is a key. Therefore the correct answer is Keys. Locks are associated with objects, not domains. Capabilities belong to capability‑based systems, and access lists describe which domains may use an object. Understanding this terminology helps when configuring domain permissions in a real system.

Q2. Why does the lock–key mechanism represent a compromise between access lists and capability lists?

A.It eliminates the need for OS management
B.It allows domains to generate their own keys
C.It combines centralized control with localized verification ✅
D.It uses encryption to hide permissions
💡 Difficulty: easy | ✅ Correct: C

📖 Explanation: The lock–key approach keeps a central authority (the OS) that assigns and checks keys, like access lists, while allowing a process to present a matching key locally, similar to capabilities. This blend gives both control and efficiency. The other options describe features that are not part of the lock–key design: the OS still manages keys, domains cannot create keys independently, and encryption is not the primary mechanism.

Q3. Which characteristic of capability lists makes revocation potentially inefficient compared to the lock–key mechanism?

A.Capabilities are stored with processes ✅
B.Capabilities require cryptographic signatures
C.Capabilities cannot be duplicated
D.Capability lists are global
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: When capabilities are attached to a process, revoking a right often requires scanning every process to remove or invalidate the relevant capability, which is costly. In contrast, the lock–key scheme can change the object's lock list centrally. Cryptographic signatures, duplication rules, and global scope are not the main reasons for revocation difficulty, making option A the correct choice.

Q4. How does the operating system protect the integrity of a domain's key list in the lock–key scheme?

A.By encrypting each key
B.By storing keys in read‑only memory
C.By disallowing user processes from examining or modifying the list ✅
D.By requiring passwords for each access
💡 Difficulty: medium | ✅ Correct: C

📖 Explanation: The OS ensures that only privileged code can view or alter a domain's keys; normal processes cannot inspect or change the list, preventing tampering. Encryption or read‑only memory are implementation details, not the fundamental protection policy. Requiring passwords for every access would defeat the purpose of a fast key check. Thus option C accurately describes the OS's role.

Q5. When a process attempts to access an object, what condition must be satisfied for the lock–key mechanism to grant access?

A.The object's lock must be identical to one of the domain's keys
B.The domain must possess a key that matches any lock of the object ✅
C.The object's lock must be a superset of the domain's keys
D.The domain must have more keys than the object has locks
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: Access is granted if at least one of the domain's keys matches one of the object's locks; this single match is sufficient. The other statements impose unnecessary or incorrect constraints: exact identity is too strict, a superset relationship is irrelevant, and having more keys does not guarantee a match. Hence the correct condition is described in option B.

Q6. A file server uses the lock–key mechanism. Object X has locks 0x1A and 0x2B. Domain D currently holds keys 0x3C and 0x4D. Which action must the operating system take to allow Domain D to read Object X?

A.Add a new lock to Object X
B.Remove a lock from Object X
C.Change the existing locks
D.Insert a matching key into Domain D's key list ✅
💡 Difficulty: medium | ✅ Correct: D

📖 Explanation: Since Domain D lacks a key that matches any of Object X's locks, the OS must add a suitable key (e.g., 0x1A or 0x2B) to D's key list. Changing the object's locks would affect other domains, and removing locks could unintentionally grant access to unauthorized domains. Adding a lock alone does not help D without a matching key. Therefore, inserting a matching key is the appropriate step.

Q7. A process in Domain P attempts to write to Object Y, which has locks 0x55 and 0xAA. Domain P currently has keys 0x55 and 0xFF. Which outcome occurs?

A.Write is permitted because Domain P possesses a matching key ✅
B.Write is denied because Domain P lacks a key for lock 0xAA
C.OS must revoke one of Domain P's keys
D.Object Y must be recreated with different locks
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: Domain P holds key 0x55, which matches one of Object Y's locks, so the lock–key check succeeds and the write operation is allowed. The absence of a matching key for the second lock does not block access; only one match is needed. Revoking keys or recreating the object are unnecessary actions.

Q8. In a system using lock–key protection, an administrator wants to prevent all domains from accessing a confidential object except for a privileged domain. Which operation achieves this most directly?

A.Remove all locks from the object
B.Add a new key to every other domain
C.Replace the object's lock list with a single lock known only to the privileged domain ✅
D.Delete the privileged domain's keys
💡 Difficulty: medium | ✅ Correct: C

📖 Explanation: By setting the object's lock list to a single lock that only the privileged domain possesses, the system ensures that no other domain can satisfy the lock–key check. Removing locks would make the object universally accessible, and adding keys to other domains would defeat the purpose. Deleting the privileged domain's keys would lock out the intended user. Hence option C is the most direct solution.

Q9. What is a primary security advantage of the lock–key mechanism over pure capability lists regarding key distribution?

A.Keys can be publicly disclosed without risk
B.Keys are managed by the OS, preventing processes from forging or copying them ✅
C.Keys are shorter than capabilities
D.Keys automatically expire after use
💡 Difficulty: hard | ✅ Correct: B

📖 Explanation: The OS centrally controls key creation and assignment, so ordinary processes cannot fabricate or duplicate keys, reducing the risk of unauthorized access. This contrasts with pure capability systems where processes may hold capabilities that can be transferred or forged. Public disclosure, length, and automatic expiration are not inherent properties of lock–key keys, making option B the correct advantage.

Q10. A multi‑tenant cloud service implements lock–key protection. Tenant A's domain has keys {K1, K2}. Tenant B's domain has keys {K3}. Object Z has locks {K2, K3}. If Tenant A tries to delete Object Z, which of the following must the system verify?

A.That Tenant A holds K3
B.That Tenant B holds K2
C.That both tenants have the same keys
D.That Tenant A possesses at least one key matching a lock of Object Z and has delete permission ✅
💡 Difficulty: hard | ✅ Correct: D

📖 Explanation: The system must confirm that Tenant A has a key (K2) that matches one of Object Z's locks and that Tenant A's access rights include the delete operation. The presence of K3 in Tenant B is irrelevant for Tenant A's request. Therefore, option D captures the essential verification step.

Q11. During a security audit, it is discovered that a domain's key list includes a key that does not correspond to any object's lock. What is the most appropriate response?

A.Remove the extraneous key to reduce attack surface ✅
B.Add a new lock to every object
C.Convert the system to a capability list
D.Ignore the finding because unused keys are harmless
💡 Difficulty: hard | ✅ Correct: A

📖 Explanation: An unused key expands the potential attack surface because a future object could be assigned that lock, inadvertently granting access. Removing it eliminates this risk. Adding locks to all objects is unnecessary, converting to a different protection model is excessive, and ignoring the issue leaves a latent vulnerability. Hence the prudent action is option A.

Q12. Suppose a system administrator mistakenly assigns the same lock pattern to two distinct objects, Object M and Object N. A domain with a single matching key can now access both objects. Which of the following best describes the resulting security issue?

A.Privilege escalation
B.Denial of service
C.Loss of confidentiality due to unintended sharing ✅
D.Increased system performance
💡 Difficulty: hard | ✅ Correct: C

📖 Explanation: When two objects share a lock, any domain that possesses the matching key can access both, potentially exposing confidential information that should have been isolated. This is a classic confidentiality breach caused by unintended sharing. It does not elevate privileges beyond what the key already permits, nor does it cause denial of service or performance changes. Therefore, option C correctly identifies the problem.
