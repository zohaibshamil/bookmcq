What is Domain of Protection in Operating System?

A domain of protection is defined as a set of access rights \( D = \{ (object, rights\_set) \} \) that specifies exactly which operations a process can perform on specific system objects while executing within that protected environment.

Q1. What is the principle of least privilege?

A. Grant all users admin rights
B. Users receive only the minimum rights needed ✅
C. Users share a single account
D. No privileges are ever granted

💡 Difficulty: easy | ✅ Correct: B

📖 Explanation:

The principle of least privilege means that each user is given only the permissions required to perform their job functions and nothing more. Option B captures this idea. Option A is opposite, granting excessive rights. Option C suggests a shared account, which violates accountability. Option D denies any privileges, which would prevent legitimate work. By limiting rights, organizations reduce the chance that compromised accounts can cause widespread damage.

Q2. Why are audit trails important in a protected domain?

A. They speed up processing
B. They provide a record of privileged actions ✅
C. They replace authentication
D. They eliminate need for passwords

💡 Difficulty: easy | ✅ Correct: B

📖 Explanation:

Audit trails keep a detailed record of every privileged operation, allowing administrators to review who did what and when. Option B correctly states this benefit. Option A is incorrect because logging does not speed up processing. Option C is wrong; authentication is separate from auditing. Option D is false; audit trails complement, not replace, passwords. In real environments, the ability to trace privileged actions is essential for detecting misuse and supporting forensic investigations.

Q3. An operator needs to mount tapes and back up files. Which access control method best ensures the principle of least privilege?

A. Give the operator full admin rights
B. Create a role that includes only tape and backup commands ✅
C. Allow the operator to use any account
D. Disable all privileges

💡 Difficulty: medium | ✅ Correct: B

📖 Explanation:

The scenario calls for granting the operator only the commands needed to mount tapes and back up files, which aligns with the principle of least privilege. Option B describes creating a role that includes just those specific commands, providing the required access without excess rights. Option A would give full admin rights, exposing the system to unnecessary risk. Option C allows any account use, breaking accountability. Option D disables all privileges, preventing the operator from performing the needed tasks. Role‑based limits are the safest choice.

Q4. How does increasing the number of services in an operating system typically affect its security posture?

A. Improves security because more features
B. No impact
C. Increases attack surface ✅
D. Guarantees no vulnerabilities

💡 Difficulty: medium | ✅ Correct: C

📖 Explanation:

Adding more services to an operating system typically enlarges its attack surface, meaning there are more entry points an attacker can exploit. Option C correctly identifies this effect. Option A is misleading; more features do not automatically improve security. Option B claims no impact, which is false because each service introduces potential vulnerabilities. Option D suggests guarantees of no vulnerabilities, which is unrealistic. In practice, limiting services is a core strategy for strengthening system security.

Q5. A company uses RBAC and defines three roles: Analyst, Developer, and Auditor. Which assignment correctly follows least‑privilege practice?

A. Give Analyst rights to modify source code
B. Give Developer rights to view audit logs
C. Give Auditor rights to change system configurations
D. Give Analyst rights to read reports only ✅

💡 Difficulty: medium | ✅ Correct: D

📖 Explanation:

In RBAC, each role should contain only the permissions necessary for its job function, embodying least‑privilege. Option D assigns the Analyst role the ability to read reports, which is appropriate and does not grant unnecessary rights. Option A gives the Analyst the ability to modify source code, a task for Developers. Option B lets the Developer view audit logs, typically reserved for Auditors. Option C permits the Auditor to change system configurations, exceeding the Auditor’s usual read‑only responsibilities. Therefore, D best follows the principle.

Q6. After a breach, investigators find that privileged function calls were not logged because the audit subsystem was disabled. Which immediate remediation would most effectively reduce future risk?

A. Re‑enable audit logging for all privileged functions ✅
B. Increase password length
C. Install more RAM
D. Change user interface theme

💡 Difficulty: hard | ✅ Correct: A

📖 Explanation:

When privileged function calls are not logged, investigators lose vital evidence needed to trace malicious activity. The most effective immediate step is to re‑enable audit logging for all privileged operations, as stated in option A. This restores visibility and deters future abuse. Option B (increasing password length) improves authentication but does not address the missing logs. Option C (adding RAM) is unrelated to security. Option D (changing UI theme) has no impact on audit capability. Restoring comprehensive logging directly mitigates the identified weakness.

Q7. Comparing Windows 2000 and Solaris, which factor most likely explains Solaris’s relatively higher security despite both being UNIX‑derived?

A. Solaris has fewer lines of code and services ✅
B. Windows 2000 uses a different kernel language
C. Solaris lacks any protection mechanisms
D. Windows 2000 has built‑in encryption

💡 Difficulty: hard | ✅ Correct: A

📖 Explanation:

Solaris is often viewed as more secure than Windows 2000 despite both originating from UNIX concepts. The primary reason is that Solaris typically has fewer lines of code and runs fewer services, which reduces the potential attack surface, as captured in option A. Option B incorrectly attributes security to kernel language differences. Option C is false because Solaris does implement protection mechanisms. Option D misstates that Windows 2000 has built‑in encryption as the key factor, which does not explain overall security posture.

Q8. A server is configured to allow remote database access only between 02:00‑04:00 UTC. Which mechanism enforces this restriction?

A. Role‑based access control
B. Time‑based access control list ✅
C. Password complexity rule
D. File encryption

💡 Difficulty: medium | ✅ Correct: B

📖 Explanation:

Time‑based access control lists restrict network or service access to specified periods, matching the described scenario. Option B correctly identifies this mechanism. Option A (RBAC) controls access based on roles, not time. Option C (password complexity) deals with credential strength, unrelated to scheduling. Option D (file encryption) protects data confidentiality but does not limit when a service can be used. Therefore, a time‑based ACL is the appropriate tool to enforce the 02:00‑04:00 UTC window.

Q9. An organization wants to grant temporary elevated privileges to a user for a specific maintenance task, then automatically revoke them. Which mechanism best accomplishes this?

A. Permanent admin account
B. Capability‑based token that expires after task ✅
C. Disable all audit logs
D. Share root password among staff

💡 Difficulty: hard | ✅ Correct: B

📖 Explanation:

Granting temporary elevated privileges that automatically expire is a classic use case for capability‑based tokens or time‑limited sudo‑like mechanisms. Option B describes a capability token that expires after the maintenance task, directly implementing the principle of least privilege and reducing lingering risk. Option A gives a permanent admin account, which violates least‑privilege. Option C disables audit logs, removing accountability. Option D shares the root password, creating a major security hole. Therefore, a revocable capability token is the best solution.
