What is Type 0 hypervisor in virtualization?

Definition:
A Type 0 (firmware-level) hypervisor is embedded directly into system firmware or specialized hardware below the traditional OS layer, providing virtualization services before any general-purpose operating system loads.

Example:
Oracle SPARC servers use Logical Domains (LDoms) where the hypervisor runs in OpenBoot firmware, partitioning physical resources into \( N \) independent domains before Solaris boots in any domain.

Reason:
This architecture minimizes attack surface and boot-time latency since no host OS exists to compromise, offering higher security and reliability for mission-critical enterprise workloads requiring strict isolation guarantees.

📝 All Type 0 hypervisor in virtualization MCQs

Q1. What is a Type 0 hypervisor?

A.A hypervisor that runs directly on hardware without a host operating system
B.A hypervisor that runs as an application on top of an operating system ✅
C.A hypervisor that only supports paravirtualization
D.A hypervisor used only for container virtualization
💡 Difficulty: easy | ✅ Correct: B

📖 Explanation: A Type 0 hypervisor, also called a bare‑metal hypervisor, executes directly on the physical CPU and manages guests without any intervening host OS. This direct placement gives it full control over privileged resources. Option B describes a hosted hypervisor, which is a Type 2 design. Option C is inaccurate because a Type 0 hypervisor can support full virtualization, not just paravirtualization. Option D confuses hypervisors with container technologies, which do not emulate hardware. The correct answer reflects the defining characteristic of a Type 0 hypervisor.

Q2. Why must a VMM trap privileged instructions from a guest kernel when using a Type 0 hypervisor?

A.Because the guest kernel runs in user mode on the physical CPU and any privileged instruction would cause a trap that the VMM can handle
B.Because the VMM wants to log all privileged instructions for auditing ✅
C.Because privileged instructions are illegal in virtual environments
D.Because trapping improves guest performance
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: When a Type 0 hypervisor schedules a guest, it runs the guest entirely in the physical CPU’s user mode. Consequently, any attempt by the guest kernel to execute a privileged instruction (e.g., changing control registers) triggers a hardware trap. The VMM intercepts this trap, emulates the intended effect, and maintains isolation. Option B is a secondary benefit, not the primary reason. Option C is false; privileged instructions are not inherently illegal, they are simply disallowed in user mode. Option D misstates the effect of trapping, which actually adds overhead, not improves performance.

Q3. How does the virtual CPU (VCPU) state relate to the physical CPU registers during a context switch?

A.The VCPU stores a snapshot of the guest’s registers, which the VMM loads into the physical CPU when the guest is scheduled
B.The VCPU directly manipulates the physical CPU registers at all times ✅
C.The VCPU is only a software abstraction and never interacts with real registers
D.The VCPU replaces the physical CPU entirely
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: The VCPU acts as a data structure that holds the guest’s architectural state—general‑purpose registers, program counter, flags, etc. When the VMM switches a guest onto the real CPU, it copies the saved values from the VCPU into the physical registers, and on exit it saves them back. This mirrors how an operating system saves a process’s PCB. Option B is incorrect because the VCPU does not constantly control the hardware; it is consulted only during switches. Option C misrepresents the VCPU’s purpose, and Option D is impossible because the physical CPU must execute instructions.

Q4. What is the main limitation of trap-and-emulate without hardware virtualization extensions for a Type 0 hypervisor?

A.High overhead due to frequent VM exits
B.Inability to virtualize the memory management unit ✅
C.Inability to intercept privileged instructions
D.Lack of support for multiple guests
💡 Difficulty: hard | ✅ Correct: B

📖 Explanation: Without extensions like Intel VT‑x or AMD‑V, every privileged instruction executed by a guest causes a trap to the VMM, which must emulate the effect before returning control. This frequent trapping introduces considerable performance overhead, especially for workloads with many system calls or I/O operations. Option B is partially true but modern binary‑translation techniques can still handle MMU virtualization. Option C is false because traps do intercept privileged instructions; the issue is the cost, not the ability. Option D is unrelated; multiple guests can still be managed, albeit with reduced efficiency.

Q5. A guest kernel attempts to execute a privileged instruction on a Type 0 hypervisor. Which mechanism does the VMM employ to handle this event?

A.Trap-and-emulate ✅
B.Binary translation
C.Hardware‑assisted virtualization
D.None of the above
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: When the guest kernel issues a privileged operation while running in user mode, the CPU generates a trap that transfers control to the VMM. The VMM then emulates the requested operation, preserving isolation and correctness. Binary translation rewrites code ahead of time, which is not triggered by a single instruction trap. Hardware‑assisted virtualization would require CPU extensions that are not present in this scenario. “None of the above” is incorrect because trap‑and‑emulate is the standard response.

Q6. A system lacks VT‑x/AMD‑V hardware support. Which technique must a Type 0 hypervisor rely on to provide full virtualization?

A.Hardware assistance
B.Binary translation
C.Trap-and-emulate ✅
D.Paravirtualization
💡 Difficulty: medium | ✅ Correct: C

📖 Explanation: Without hardware extensions, the hypervisor cannot delegate privileged instruction handling to the CPU. It therefore must rewrite guest code dynamically, replacing privileged instructions with safe sequences—a process known as binary translation. This approach enables full virtualization despite missing hardware support. Trap-and-emulate (option C) can also be used, but it incurs higher overhead and is typically combined with binary translation. Paravirtualization (option D) requires guest modifications, which defeats the goal of full virtualization. Hardware assistance (option A) is unavailable.

Q7. Guest A tries to modify its page‑table entries directly. How does the Type 0 hypervisor prevent this from corrupting host memory?

A.Trap the instruction and emulate a safe update
B.Allow the modification because guests have full privileges ✅
C.Translate the page tables at load time
D.Ignore the change and continue execution
💡 Difficulty: hard | ✅ Correct: B

📖 Explanation: Direct modification of page tables is a privileged operation. The VMM intercepts the offending instruction via a trap, then emulates the change in a shadow page‑table that maps guest virtual addresses to host physical memory safely. This ensures isolation and prevents accidental host memory corruption. Allowing the change (option B) would break isolation. Translating at load time (option C) cannot handle runtime updates. Ignoring the change (option D) would lead to undefined behavior and possible crashes.

Q8. A guest OS issues an I/O‑port instruction. Which method ensures the hypervisor maintains isolation between guests?

A.Trap-and-emulate the I/O operation
B.Pass the instruction directly to the hardware ✅
C.Emulate the I/O device entirely in the VMM
D.Ignore the I/O request
💡 Difficulty: hard | ✅ Correct: B

📖 Explanation: I/O‑port instructions are privileged; the hypervisor traps them, emulates the intended effect, and optionally forwards the request to a virtual device. This preserves isolation, as each guest sees only its own virtualized I/O space. Direct pass‑through (option B) would expose the hardware to multiple guests, breaking isolation. Full device emulation (option C) is often combined with trapping but the initial step is still the trap. Ignoring the request (option D) would cause the guest to malfunction.

Q9. To benchmark the overhead of trap‑and‑emulate, which metric should a developer primarily measure?

A.Number of VM exits per second
B.CPU clock frequency ✅
C.Disk I/O throughput
D.Network latency
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: Trap‑and‑emulate overhead is directly tied to how often the guest causes traps that force the VMM to intervene. Counting VM exits per second quantifies this frequency and reveals the performance cost of each exit. CPU clock frequency (option B) is unrelated to virtualization overhead. Disk I/O (option C) and network latency (option D) may be affected indirectly but are not the primary indicators of trap‑and‑emulate cost.

Q10. What distinguishes virtual user mode from virtual kernel mode in a Type 0 hypervisor?

A.Both run in physical user mode
B.Virtual kernel mode runs in physical kernel mode ✅
C.Virtual user mode runs in kernel mode
D.There is no distinction between the two
💡 Difficulty: easy | ✅ Correct: B

📖 Explanation: In a Type 0 hypervisor, the guest’s user and kernel modes are both executed while the physical CPU remains in user mode. This design keeps the hypervisor in control of privileged operations, allowing it to trap and emulate kernel actions safely. Option B incorrectly suggests the physical CPU switches to kernel mode, which would violate isolation. Option C reverses the relationship, and option D ignores the essential virtualization concept of separate virtual modes.
