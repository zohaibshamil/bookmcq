Q1. What does the abbreviation VCPU stand for in virtualization contexts?

🔹 A. Virtual CPU
🔹 B. Virtual Control Processor
🔹 C. Virtual Core Processing Unit
🔹 D. Virtual Central Processing Unit

💡 Difficulty: easy | ✅ Correct: A

📖 Explanation:

The term VCPU means Virtual CPU, representing the guest’s view of a processor. It stores registers, flags, and control state but does not run instructions itself. The other choices mix similar words but do not match the standard definition; they are invented terms. Understanding that a VCPU is a software construct helps students see why the VMM must switch its state during context changes, preserving isolation between guests.

Q2. Why must a virtual machine guest's privileged instructions cause a trap to the VMM rather than being executed directly?

🔹 A. Because the host CPU cannot decode them
🔹 B. To maintain isolation and enforce that all privileged actions are mediated
🔹 C. To improve performance
🔹 D. Because the guest OS lacks the necessary hardware

💡 Difficulty: easy | ✅ Correct: A

📖 Explanation:

Privileged instructions require kernel‑mode authority, which a guest does not have in a virtualized environment. By trapping them to the VMM, the hypervisor can emulate the effect safely, preserving the host’s security boundaries. Option A is false because modern CPUs can decode such instructions. Option C misstates the purpose—traps add overhead, not speed. Option D is irrelevant because hardware availability is not the issue; isolation is.

Q3. A cloud provider wants to run a legacy OS that executes privileged instructions. Which virtualization technique should they use to ensure those instructions are safely handled without hardware support for full virtualization?

🔹 A. Binary translation
🔹 B. Trap-and-emulate
🔹 C. Direct execution
🔹 D. Paravirtualization

💡 Difficulty: medium | ✅ Correct: A

📖 Explanation:

Trap-and-emulate intercepts privileged instructions, causing a VM exit that the VMM handles, which works even when the CPU lacks full virtualization extensions. Binary translation (A) rewrites code ahead of time, but it is more complex and not required for simple privileged instruction handling. Direct execution (C) would run the code without mediation, breaking isolation. Paravirtualization (D) requires the guest to be modified, which the legacy OS cannot provide.

Q4. How does the virtual CPU (VCPU) differ from a physical CPU in terms of execution?

🔹 A. VCPU runs code directly on hardware
🔹 B. VCPU only stores state, not execute code
🔹 C. VCPU executes privileged instructions
🔹 D. VCPU is a separate physical core

💡 Difficulty: medium | ✅ Correct: A

📖 Explanation:

A VCPU is a software abstraction that holds the architectural state of a guest CPU—registers, flags, and control fields—but it never executes instructions itself. The actual execution occurs on the physical CPU under the VMM’s control. Option A incorrectly suggests direct execution, which would bypass isolation. Option C mischaracterizes the VCPU’s role; privileged instructions are trapped, not executed by the VCPU. Option D describes a hardware core, not a virtual construct.

Q5. During a VM context switch, the VMM must load the guest's state. Which structure is analogous to a traditional OS's PCB for this purpose?

🔹 A. VCPU
🔹 B. Page Table
🔹 C. Interrupt Descriptor Table
🔹 D. TLB

💡 Difficulty: medium | ✅ Correct: A

📖 Explanation:

The VCPU acts like a process control block (PCB) by encapsulating the guest’s CPU registers, program counter, and status flags that the VMM saves and restores on each switch. Page tables map virtual to physical memory but do not store execution state. The interrupt descriptor table defines handlers, unrelated to context. The translation lookaside buffer (TLB) caches address translations and is not a state container. Recognizing the VCPU as the PCB analogue clarifies how virtualization mimics OS scheduling.

Q6. What hardware feature most directly enables efficient trap-and-emulate mechanisms in modern CPUs?

🔹 A. Cache coherence protocol
🔹 B. Hardware virtualization extensions (e.g., Intel VT‑x)
🔹 C. Hyper‑Threading
🔹 D. Branch prediction

💡 Difficulty: medium | ✅ Correct: B

📖 Explanation:

Hardware virtualization extensions add new CPU modes and instructions that detect privileged operations and automatically generate VM exits, allowing the VMM to emulate them with minimal overhead. Cache coherence, hyper‑threading, and branch prediction improve performance but do not provide the trap capability needed for virtualization. Knowing that VT‑x (or AMD‑V) is the key feature helps students understand why modern processors are better suited for virtualization.

Q7. A developer notices that a guest VM frequently triggers VM exits when executing a specific privileged instruction. Which optimization could reduce the exit frequency?

🔹 A. Enable binary translation for that instruction
🔹 B. Rewrite the guest to use a hypercall
🔹 C. Add a shadow page table
🔹 D. Increase the VM's allocated memory

💡 Difficulty: medium | ✅ Correct: A

📖 Explanation:

Replacing the privileged instruction with a hypercall (a paravirtualized interface) lets the guest request the operation directly from the VMM, avoiding the trap and exit. Binary translation (A) could also help but is more heavyweight and not targeted at a single instruction. A shadow page table (C) assists memory translation, not instruction handling. Adding memory (D) does not affect exit frequency. The hypercall approach directly addresses the root cause.

Q8. Assume a VMM uses trap-and-emulate and the host CPU lacks a dedicated VMX root mode. A guest attempts to modify the CR3 register. Describe the sequence of events the VMM must perform to correctly emulate this change while preserving isolation.

🔹 A. VMM saves host state, updates CR3, resumes guest
🔹 B. VMM intercepts trap, updates a shadow CR3, emulates effect
🔹 C. VMM ignores the change, letting guest continue
🔹 D. VMM reboots the guest

💡 Difficulty: hard | ✅ Correct: A

📖 Explanation:

When the guest writes CR3, the CPU traps to the VMM because the operation is privileged. The VMM then updates a shadow copy of CR3 that represents the guest’s page‑table base, ensuring the host’s real CR3 remains unchanged. It then emulates the side effects, such as flushing the TLB, before returning control. Option A would expose the host’s paging structures, breaking isolation. Option C is unsafe, and option D is an extreme overreaction.

Q9. In a multi-tenant environment, two VMs share the same physical CPU. VM1 runs a compute‑intensive task, while VM2 runs a latency‑sensitive database. Which scheduling policy implemented by the VMM best ensures VM2 meets its latency requirements?

🔹 A. Round‑robin
🔹 B. Priority‑based preemptive scheduling
🔹 C. First‑come‑first‑served
🔹 D. Fair share with equal time slices

💡 Difficulty: hard | ✅ Correct: A

📖 Explanation:

Priority‑based preemptive scheduling lets the VMM assign a higher priority to the latency‑sensitive VM, preempting the compute‑heavy VM when needed, thus reducing response time. Round‑robin (A) gives each VM equal slices, which may delay the database. First‑come‑first‑served (C) ignores urgency. Fair share (D) also divides time equally, not guaranteeing latency. Understanding scheduling choices shows how VMMs manage performance isolation.

Q10. Why does a VMM need to maintain a separate VCPU state for each guest rather than reusing a single physical CPU context?

🔹 A. To allow simultaneous execution of multiple guests
🔹 B. To preserve each guest's architectural state across switches
🔹 C. Because the hardware cannot save registers
🔹 D. To reduce power consumption

💡 Difficulty: hard | ✅ Correct: A

📖 Explanation:

Each guest has its own set of registers, flags, and control information that must be restored whenever it is scheduled. Keeping a distinct VCPU ensures that when the VMM switches between guests, the correct state is loaded, preventing cross‑contamination of execution contexts. Option A is incorrect because physical CPUs cannot run multiple guests at the same instant without time slicing. Option C misstates hardware capabilities, and option D is unrelated to isolation. Maintaining per‑guest VCPU state is essential for correct virtualization.
