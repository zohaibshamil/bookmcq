Q1. What does the term VCPU represent in a paravirtualized system?

🔹 A. A physical processor core assigned to a guest
🔹 B. A software structure that holds the guest's CPU state
🔹 C. A dedicated hardware thread for virtualization
🔹 D. An emulated peripheral device

💡 Difficulty: easy | ✅ Correct: B

📖 Explanation:

The VCPU is a software construct maintained by the hypervisor that records the register contents, program counter, and other CPU state as the guest believes it to be. It does not execute instructions itself; instead, the VMM uses it to load and save context when switching guests. This distinction lets the VMM control execution while keeping the guest's view consistent, which is essential for isolation and correct operation.

Q2. Why must a virtual kernel mode execute in the physical machine's user mode?

🔹 A. Because the hypervisor cannot run in kernel mode
🔹 B. To prevent the guest from accessing privileged hardware directly
🔹 C. To allow the guest to run faster than native code
🔹 D. Because user mode has higher priority

💡 Difficulty: easy | ✅ Correct: B

📖 Explanation:

Running the guest's kernel in physical user mode ensures that any attempt to execute privileged instructions triggers a trap to the hypervisor. The trap allows the VMM to intercept and emulate the operation, preserving isolation and preventing the guest from directly manipulating hardware resources. This design keeps the host safe while giving the guest the illusion of its own kernel mode.

Q3. A guest OS issues a privileged instruction while running in its virtual user mode. Which action should the VMM take to correctly handle this event?

🔹 A. Ignore the instruction and continue execution
🔹 B. Execute the instruction directly on the hardware
🔹 C. Translate the instruction to a safe user-mode operation
🔹 D. Trap the instruction, emulate its effect, and update the VCPU state

💡 Difficulty: medium | ✅ Correct: D

📖 Explanation:

When a privileged instruction is encountered in virtual user mode, the CPU raises a trap that transfers control to the hypervisor. The VMM then emulates the intended effect of the instruction, updates the stored VCPU registers, and resumes the guest. Ignoring or directly executing the instruction would violate isolation, while simple translation would not preserve the exact semantics required by the guest OS.

Q4. How do CPU hardware virtualization extensions simplify the implementation of a VMM?

🔹 A. They provide direct support for trapping privileged instructions
🔹 B. They eliminate the need for virtual memory
🔹 C. They enable multiple VMs to share a single physical CPU without context switches
🔹 D. They automatically translate binary code to a portable format

💡 Difficulty: medium | ✅ Correct: A

📖 Explanation:

Modern CPUs include extensions such as VT-x or AMD-V that add a new execution mode and instructions for trapping privileged operations. These extensions allow the hypervisor to run the guest directly on the hardware while automatically intercepting sensitive instructions, reducing the amount of software emulation required. Consequently, the VMM can be simpler, faster, and more reliable than a pure software solution.

Q5. When choosing between trap-and-emulate and binary translation, which advantage does binary translation offer?

🔹 A. It requires no CPU support
🔹 B. It reduces the number of VM exits
🔹 C. It allows the guest to run in kernel mode safely
🔹 D. It eliminates the need for a VCPU structure

💡 Difficulty: medium | ✅ Correct: B

📖 Explanation:

Binary translation rewrites guest code at runtime, replacing privileged instructions with safe sequences that run in user mode. By doing so, it avoids the frequent transitions (VM exits) that trap-and-emulate would cause each time a privileged operation occurs. Fewer exits mean lower overhead and better performance, while the VCPU structure is still needed to store the guest's state during context switches.

Q6. Why must both virtual user mode and virtual kernel mode be executed in the physical machine's user mode in a paravirtualized environment?

🔹 A. To improve overall system performance
🔹 B. To ensure that any privileged operation by the guest is intercepted by the VMM
🔹 C. Because the hardware only supports one mode at a time
🔹 D. To allow the guest OS to bypass security checks

💡 Difficulty: hard | ✅ Correct: B

📖 Explanation:

Executing both virtual modes in physical user mode guarantees that any attempt by the guest to perform a privileged action causes a trap to the hypervisor. This interception is essential for maintaining isolation and preventing the guest from directly accessing hardware or kernel resources. Without this design, the VMM could not enforce security boundaries, and the host system would be vulnerable to guest misbehavior.

Q7. A VMM is being built for a processor that lacks hardware virtualization support. Which technique must the VMM rely on to provide isolation for guest OSes?

🔹 A. Binary translation
🔹 B. Direct execution of guest code
🔹 C. Hardware-assisted paging
🔹 D. Nested virtualization

💡 Difficulty: hard | ✅ Correct: A

📖 Explanation:

When hardware assistance is unavailable, the hypervisor cannot rely on native traps for privileged instructions. Instead, it must use binary translation to rewrite guest code on the fly, inserting safe sequences and emulating privileged operations. This software-only approach preserves isolation but incurs higher overhead than hardware‑assisted methods. Direct execution would give the guest unrestricted access, while the other options require hardware features the processor does not provide.

Q8. In a multi-guest system, what data structure does the VMM typically use to store each guest's VCPU state during a context switch?

🔹 A. Interrupt Descriptor Table
🔹 B. Page Table Entry
🔹 C. Scheduler Queue
🔹 D. Virtual Processor Control Block

💡 Difficulty: hard | ✅ Correct: D

📖 Explanation:

The VMM keeps a Virtual Processor Control Block for each guest, which contains the saved register set, program counter, and other CPU state needed to resume execution later. During a context switch, the hypervisor writes the current VCPU information into this block and restores the next guest's state from its block. This structure mirrors the role of a PCB in a conventional OS but is specific to virtual CPUs.

Q9. How does a VCPU differ from a traditional Process Control Block (PCB) in an operating system?

🔹 A. A VCPU stores only memory state, while a PCB stores CPU registers
🔹 B. A VCPU is used by the hypervisor to represent a guest's CPU, whereas a PCB represents a host process
🔹 C. A VCPU contains network configuration, while a PCB contains file descriptors
🔹 D. A VCPU is hardware, while a PCB is software

💡 Difficulty: medium | ✅ Correct: B

📖 Explanation:

A VCPU is a hypervisor‑maintained structure that captures the complete CPU context of a virtual machine, allowing the VMM to pause and resume the guest. In contrast, a PCB belongs to the host OS and describes a single process running on that OS. While both store register state, the VCPU represents an entire virtual CPU for isolation, whereas the PCB is part of normal process scheduling within the host.

Q10. A cloud provider wants to reduce VM exit overhead when guests frequently invoke system calls. Which optimization technique should they implement?

🔹 A. Use a fast‑path system call handler that batches multiple calls
🔹 B. Disable all system calls in the guest
🔹 C. Force the guest to run in kernel mode
🔹 D. Replace the VMM with a bare‑metal hypervisor

💡 Difficulty: medium | ✅ Correct: A

📖 Explanation:

A fast‑path system call handler intercepts common calls and processes them with minimal VMM intervention, often by batching or caching results. This reduces the number of full VM exits, lowering latency and CPU usage. Disabling system calls would break functionality, and forcing kernel mode would violate isolation. Switching to a bare‑metal hypervisor does not directly address the exit cost of frequent calls.
