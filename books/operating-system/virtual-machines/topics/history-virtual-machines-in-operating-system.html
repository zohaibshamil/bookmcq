Q1. In which year did IBM first commercialize virtual machines on its mainframes?

🔹 A. 1970
🔹 B. 1972
🔹 C. 1974
🔹 D. 1976

💡 Difficulty: easy | ✅ Correct: B

📖 Explanation:

The correct answer is 1972 because IBM introduced the VM operating system on its System/370 mainframes that year, marking the first commercial use of virtual machines. 1970 and 1974 are close but incorrect dates, and 1976 is later than the actual introduction. Knowing the historical timeline helps understand how virtualization evolved from early mainframes to modern cloud infrastructures.

Q2. Which statement correctly distinguishes a type 1 hypervisor from a type 2 hypervisor?

🔹 A. Type 1 runs directly on hardware, while type 2 runs as an application on a host OS.
🔹 B. Type 1 requires a host OS, type 2 does not.
🔹 C. Both types run directly on hardware.
🔹 D. Type 2 provides VMM functions only for guest OSes.

💡 Difficulty: easy | ✅ Correct: A

📖 Explanation:

Option A is correct because a type 1 hypervisor (bare‑metal) installs on the physical server and controls hardware directly, whereas a type 2 hypervisor runs atop an existing operating system as a regular program. Option B reverses the relationship, option C incorrectly claims both run directly on hardware, and option D misstates the scope of type 2. This distinction is fundamental for selecting appropriate virtualization solutions.

Q3. What is the primary advantage of paravirtualization compared to full virtualization?

🔹 A. It eliminates the need for a hypervisor.
🔹 B. Guest OS is modified to cooperate with the VMM, reducing overhead.
🔹 C. It allows running unmodified guest OSes on any hardware.
🔹 D. It provides hardware emulation for legacy applications.

💡 Difficulty: medium | ✅ Correct: B

📖 Explanation:

Paravirtualization works by altering the guest operating system so it can communicate directly with the virtual machine monitor, which cuts down on the extra processing that full virtualization requires. Therefore, option B is correct. Option A is false because a hypervisor is still needed, option C describes full virtualization, and option D refers to emulation, not paravirtualization. Understanding this benefit guides performance‑critical deployment decisions.

Q4. Programming‑environment virtualization, as used by Java and .NET, differs from hardware virtualization because it...

🔹 A. Creates a virtual CPU that mimics the physical processor.
🔹 B. Provides an abstract runtime that isolates programs without simulating hardware.
🔹 C. Requires modified guest operating systems.
🔹 D. Runs only on type 1 hypervisors.

💡 Difficulty: medium | ✅ Correct: B

📖 Explanation:

The correct answer is B: Java’s JVM and .NET’s CLR create a software runtime that abstracts the underlying hardware, allowing programs to run in a controlled environment without emulating a full machine. Option A describes hardware virtualization, option C incorrectly implies guest OS modification, and option D limits the technique to type 1 hypervisors, which is not true. This concept explains why developers can write portable code across diverse platforms.

Q5. How does application containment (e.g., Solaris Zones, BSD Jails) differ from full virtualization?

🔹 A. Containment isolates the entire hardware stack, while virtualization isolates only the OS.
🔹 B. Containment shares the host kernel, whereas virtualization runs separate kernels.
🔹 C. Containment requires emulating a different CPU architecture.
🔹 D. Containment provides better performance than any hypervisor.

💡 Difficulty: hard | ✅ Correct: B

📖 Explanation:

Option B is correct because containment technologies run multiple isolated user spaces on a single shared kernel, so they do not need separate kernel instances as full virtual machines do. Option A reverses the isolation scope, option C incorrectly suggests CPU emulation is required, and option D overstates performance benefits—while containment can be faster, it is not universally superior. Recognizing this distinction helps architects choose lightweight isolation versus full VM isolation.

Q6. A company needs to host dozens of Linux servers with minimal overhead. Which hypervisor type should they deploy and why?

🔹 A. Type 2, because it is easier to install on existing Windows workstations.
🔹 B. Type 1, because it runs directly on hardware and reduces resource overhead.
🔹 C. Paravirtualization, because it modifies the guest OS for better performance.
🔹 D. Application containment, because it provides full hardware isolation.

💡 Difficulty: medium | ✅ Correct: A

📖 Explanation:

The best choice is a type 1 (bare‑metal) hypervisor, as it eliminates the extra host operating system layer, giving each Linux guest direct access to hardware resources and lower CPU and memory consumption. Option A adds unnecessary overhead on Windows, option C requires guest OS changes which may not be feasible for many servers, and option D does not provide true hardware isolation. This decision aligns with efficiency goals in data‑center deployments.

Q7. To run a Windows application on an ARM‑based laptop, which virtualization technique is most appropriate?

🔹 A. Type 1 hypervisor.
🔹 B. Paravirtualization.
🔹 C. Emulation.
🔹 D. Programming‑environment virtualization.

💡 Difficulty: medium | ✅ Correct: B

📖 Explanation:

Emulation is the correct answer because it translates instructions from one CPU architecture (x86) to another (ARM), allowing the Windows program to execute on hardware it was not originally designed for. Type 1 hypervisors require compatible hardware, paravirtualization needs a modified guest OS, and programming‑environment virtualization only abstracts software runtimes, not CPU instruction sets. Selecting emulation solves the cross‑architecture compatibility problem.

Q8. When security isolation is the top priority, how does a Solaris Zone compare to a virtual machine?

🔹 A. Zones provide stronger isolation because they run separate kernels.
🔹 B. VMs provide stronger isolation because they emulate hardware and have separate kernels.
🔹 C. Both provide identical isolation levels.
🔹 D. Zones cannot isolate network traffic.

💡 Difficulty: hard | ✅ Correct: A

📖 Explanation:

Virtual machines give stronger isolation since each VM runs its own kernel and virtualized hardware, creating a more robust barrier against attacks. Solaris Zones share the host kernel, so a kernel vulnerability could affect all zones. Option A incorrectly claims zones have separate kernels, option C ignores the fundamental architectural differences, and option D is false because zones can be configured with network isolation. This insight guides security‑focused architecture choices.

Q9. If a system adds three successive layers of indirection to simplify code, what is the most likely performance impact?

🔹 A. Linear improvement in speed.
🔹 B. No change, because indirection does not affect performance.
🔹 C. Potential slowdown due to added call overhead and cache misses.
🔹 D. Exponential increase in memory usage.

💡 Difficulty: hard | ✅ Correct: C

📖 Explanation:

Adding multiple layers of indirection typically introduces extra function calls and pointer dereferences, which can increase CPU cycles and cause cache inefficiencies, leading to slower execution. Therefore, option C is correct. Option A is unrealistic—indirection rarely speeds up code, option B ignores measurable overhead, and option D exaggerates memory impact. Understanding this trade‑off helps developers balance code readability with runtime efficiency.

Q10. A developer wants to test Java code that relies on the JVM’s sandbox. Which virtualization approach should they use?

🔹 A. Full hardware virtualization.
🔹 B. Programming‑environment virtualization.
🔹 C. Paravirtualization.
🔹 D. Application containment.

💡 Difficulty: medium | ✅ Correct: B

📖 Explanation:

Programming‑environment virtualization is appropriate because the JVM itself provides a sandboxed runtime that abstracts the underlying hardware, allowing the developer to test Java code without needing full machine emulation. Full hardware virtualization would be unnecessary overhead, paravirtualization requires guest OS changes, and application containment does not provide the specific runtime isolation the JVM offers. This choice streamlines testing while preserving the intended security model.

Q11. During software testing, a team uses a type 2 hypervisor on their laptops to spin up multiple OS instances. What is a key benefit of this setup?

🔹 A. It eliminates the need for any host operating system.
🔹 B. It allows testing on different OS versions without altering the host.
🔹 C. It provides the highest possible performance for production workloads.
🔹 D. It removes all security risks associated with the host.

💡 Difficulty: medium | ✅ Correct: A

📖 Explanation:

The primary advantage is the ability to run various operating systems side‑by‑side on a single workstation, enabling testers to verify software compatibility across versions without re‑installing or reconfiguring the host machine. Option A is false because a host OS is required for a type 2 hypervisor, option C misstates performance characteristics (type 2 adds overhead), and option D overstates security benefits. This flexibility accelerates development cycles.

Q12. A high‑traffic web server runs on a virtualized environment. Which scenario would most likely justify switching from full virtualization to paravirtualization?

🔹 A. The guest OS cannot be modified.
🔹 B. The workload is CPU‑intensive and suffers from virtualization overhead.
🔹 C. The hardware does not support virtualization extensions.
🔹 D. The server requires complete hardware emulation for legacy drivers.

💡 Difficulty: hard | ✅ Correct: A

📖 Explanation:

When a CPU‑bound workload experiences noticeable slowdown due to the extra translation layer of full virtualization, moving to paravirtualization—where the guest OS cooperates directly with the hypervisor—can reduce overhead and improve throughput. Option A is incorrect because paravirtualization requires guest modifications, option C would prevent any virtualization, and option D describes a need for full hardware emulation, not paravirtualization. This decision targets performance optimization.
