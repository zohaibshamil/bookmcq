📝 All CPU scheduling and Virtualization MCQs

Q1. What is the primary purpose of CPU scheduling in an operating system?

🔹 A. To allocate memory
🔹 B. To determine order of process execution
🔹 C. To manage disk I/O
🔹 D. To provide network routing

💡 Difficulty: easy | ✅ Correct: B

📖 Explanation:

The correct answer is B because CPU scheduling decides which process receives the CPU at any given moment, directly influencing system throughput and responsiveness. Option A describes memory management, C describes disk I/O management, and D describes networking tasks, none of which are the scheduler’s role. Recognizing this helps students understand why effective scheduling is essential for multitasking and overall system performance.

Q2. Which statement best describes a preemptive CPU scheduling algorithm?

🔹 A. It allows a running process to continue until it blocks or finishes
🔹 B. It can forcibly remove a running process to give CPU to another
🔹 C. It schedules only I/O‑bound processes
🔹 D. It requires manual intervention

💡 Difficulty: easy | ✅ Correct: B

📖 Explanation:

Answer B is correct because preemptive algorithms can interrupt a running process, allowing higher‑priority or time‑critical tasks to run immediately. Option A describes non‑preemptive behavior, C limits scheduling to a specific class of processes, and D suggests human control, which is not how OS schedulers operate. Knowing this distinction clarifies why preemptive scheduling improves responsiveness in interactive environments.

Q3. Three processes have CPU bursts of 10 ms, 4 ms, and 6 ms respectively. Using Round‑Robin with a 4 ms quantum, what is the average waiting time?

🔹 A. 6 ms
🔹 B. 7.33 ms
🔹 C. 8.67 ms
🔹 D. 10 ms

💡 Difficulty: medium | ✅ Correct: C

📖 Explanation:

The correct answer is C. By simulating Round‑Robin, the waiting times are 10 ms for the first process, 4 ms for the second, and 12 ms for the third, giving an average of (10+4+12)/3 ≈ 8.67 ms. Options A, B, and D result from incorrect calculations or ignoring the quantum effect. This example shows how quantum size impacts waiting time, a key concept for designing efficient schedulers.

Q4. Why can priority inversion cause performance problems in a preemptive system?

🔹 A. Higher‑priority tasks are blocked by lower‑priority ones holding needed resources
🔹 B. All tasks run at the same priority level
🔹 C. The scheduler ignores task priorities
🔹 D. Priority inversion only occurs in non‑preemptive systems

💡 Difficulty: medium | ✅ Correct: A

📖 Explanation:

Answer A is correct because when a low‑priority task holds a resource needed by a high‑priority task, the high‑priority task must wait, reducing responsiveness. Options B and C misrepresent how priorities affect scheduling, and D is false because inversion can happen in preemptive environments. Understanding this helps students anticipate and mitigate such issues, for example by using priority inheritance protocols.

Q5. In a type 0 hypervisor with four partitions each assigned a dedicated CPU core, a new high‑priority VM must run on core 2 currently occupied by a low‑priority VM. Which scheduling approach should the hypervisor use to minimize latency?

🔹 A. Non‑preemptive FIFO
🔹 B. Preemptive priority scheduling
🔹 C. Round‑Robin with large quantum
🔹 D. First‑come‑first‑served

💡 Difficulty: medium | ✅ Correct: B

📖 Explanation:

The correct answer is B because preemptive priority scheduling allows the hypervisor to interrupt the low‑priority VM and allocate the core to the high‑priority VM immediately, reducing wait time. Options A and D would not allow interruption, and C would add unnecessary context switches without addressing priority. This scenario illustrates why preemptive priority mechanisms are vital for meeting real‑time requirements in virtualized environments.

Q6. A system receives an average of 5 processes per second, each requiring 0.1 seconds of CPU time. What is the CPU utilization?

🔹 A. 0.3
🔹 B. 0.5
🔹 C. 0.7
🔹 D. 0.9

💡 Difficulty: hard | ✅ Correct: B

📖 Explanation:

Answer B is correct because utilization \(U\) equals arrival rate \(\lambda\) times average service time \(S\): \(U = \lambda \times S = 5 \times 0.1 = 0.5\), or 50 %. Options A, C, and D result from misapplying the formula or using incorrect values. This calculation demonstrates how workload characteristics directly affect CPU load, a fundamental concept for capacity planning.

Q7. How does a multi‑level feedback queue (MLFQ) adapt to both interactive and CPU‑bound processes?

🔹 A. It permanently assigns each process to a fixed priority level
🔹 B. It demotes processes that use a lot of CPU time and promotes those that frequently yield
🔹 C. It uses a single round‑robin queue for all processes
🔹 D. It schedules only the shortest jobs first

💡 Difficulty: hard | ✅ Correct: B

📖 Explanation:

The correct answer is B because MLFQ lowers the priority of CPU‑intensive processes while raising the priority of I/O‑bound or interactive ones, allowing quick response for interactive tasks. Option A describes a static priority system, C ignores priority differentiation, and D describes Shortest Job First, not MLFQ. Recognizing this dynamic behavior helps students design schedulers that balance throughput and responsiveness.

Q8. Using Shortest Remaining Time First (SRTF), processes arrive as follows: at time 0, P A with burst 8 ms; at time 2 ms, P B with burst 4 ms; at time 4 ms, P C with burst 2 ms. What is the CPU allocation order from time 0 to 8 ms?

🔹 A. A, B, C
🔹 B. A, C, B
🔹 C. B, A, C
🔹 D. C, B, A

💡 Difficulty: hard | ✅ Correct: A

📖 Explanation:

Answer A is correct. At 0–2 ms, A runs (remaining 6 ms). At 2 ms, B arrives with a shorter remaining time, preempting A, so B runs from 2–6 ms (remaining 0 ms). At 6 ms, C (remaining 2 ms) runs until 8 ms. Options B, C, and D misorder the preemptions or ignore the SRTF rule. This scenario highlights how SRTF continuously selects the process with the smallest remaining CPU burst, improving average waiting time.

Q9. Which algorithm guarantees the minimum average waiting time for a given set of processes?

🔹 A. First‑Come‑First‑Served
🔹 B. Shortest Job First
🔹 C. Round‑Robin
🔹 D. Priority scheduling

💡 Difficulty: medium | ✅ Correct: B

📖 Explanation:

The correct answer is B because Shortest Job First (SJF) always selects the shortest available CPU burst, minimizing total waiting time across all processes. FCFS (A) follows arrival order regardless of burst length, Round‑Robin (C) adds context‑switch overhead, and Priority (D) may not consider burst length. Understanding why SJF is optimal helps students appreciate trade‑offs between fairness and efficiency.

Q10. A host with 8 physical cores runs 12 virtual machines under a fair scheduler that equally shares CPU time. What fraction of a core does each VM receive?

🔹 A. 01-Feb
🔹 B. 02-Mar
🔹 C. 03-Apr
🔹 D. 1

💡 Difficulty: medium | ✅ Correct: B

📖 Explanation:

Answer B is correct because each VM receives \(8/12 = 2/3\) of a core when CPU time is divided equally. Option A (1/2) would require 16 VMs, C (3/4) would need fewer VMs, and D (1) would imply each VM gets a full core. This calculation shows how over‑commitment works in virtualized environments, affecting performance expectations.

Q11. What does the term “virtual machine sprawl” refer to?

🔹 A. A rapid increase in physical server count
🔹 B. The uncontrolled growth of many VMs on a host, making management difficult
🔹 C. A technique for cloning VMs quickly
🔹 D. A method for allocating memory to VMs

💡 Difficulty: easy | ✅ Correct: B

📖 Explanation:

The correct answer is B because virtual machine sprawl describes a situation where numerous VMs are created without proper tracking, leading to complexity in monitoring, security, and resource allocation. Option A describes hardware expansion, C describes cloning, and D describes memory allocation. Recognizing sprawl helps administrators implement policies to maintain control and efficiency.

Q12. In a type 0 hypervisor, three VMs share a single network card using time‑division multiplexing with a 5 ms quantum. Each VM generates a packet every 15 ms. Will any VM experience packet loss due to scheduling?

🔹 A. Yes, because the quantum is too short
🔹 B. No, because each VM gets a slot every 15 ms
🔹 C. Yes, because 3 × 5 ms = 15 ms equals the packet interval causing collision
🔹 D. Cannot determine without knowing bandwidth

💡 Difficulty: hard | ✅ Correct: B

📖 Explanation:

Answer B is correct: each VM receives a 5 ms slot every 15 ms, matching its packet generation interval, so packets can be transmitted without overlap, preventing loss. Option A misinterprets quantum length, C incorrectly assumes simultaneous transmission leads to collision, and D ignores the timing relationship. This illustrates how careful time‑division scheduling can avoid network contention.

Q13. How does preemptive scheduling improve system responsiveness compared to non‑preemptive scheduling?

🔹 A. It allows the scheduler to interrupt a running CPU‑bound process to run a higher‑priority or interactive process
🔹 B. It guarantees that all processes finish at the same time
🔹 C. It eliminates the need for context switches
🔹 D. It forces all processes to run in a fixed order

💡 Difficulty: medium | ✅ Correct: A

📖 Explanation:

The correct answer is A because preemptive scheduling can pause a CPU‑intensive task to give immediate CPU access to a higher‑priority or interactive task, reducing latency. Options B and D misrepresent scheduling goals, and C is false because preemptive scheduling actually introduces context switches. Understanding this benefit explains why many modern OSes prefer preemptive algorithms for interactive workloads.
