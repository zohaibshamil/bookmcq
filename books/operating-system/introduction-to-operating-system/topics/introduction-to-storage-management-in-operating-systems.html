What is Introduction to Storage Management in Operating Systems?

Definition:
Storage management handles persistent data on secondary devices, organizing blocks and files where seek time and rotational latency significantly impact overall I/O performance .

Example:
A file system like ext4 managing inodes and block groups to map hierarchical directory structures to physical disk sectors while caching frequently accessed metadata in RAM.

Reason:
Efficient storage management ensures data integrity, optimizes access patterns for slow mechanical media, and provides a uniform naming convention that hides complex device-specific geometry from applications.

Q13. Why do Solid State Drives (SSDs) require a 'Garbage Collection' process, unlike magnetic hard drives?

This background process is garbage collection.

Q22. Why is the 'Write-Back' caching policy generally faster than 'Write-Through', and what is the risk?

Q23. How does 'prefetching' differ from standard demand paging/caching?

Q25. What is 'cache pollution', and how can streaming large files cause it?

A.Cache pollution occurs when useful data is evicted from the cache to make room for data that is unlikely to be reused. Streaming a large file sequentially can fill the cache with file data that is read once and discarded, pushing out frequently used code or data structures. ✅

💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: Standard replacement policies like LRU assume that recently used data will be used again. Sequential streaming violates this. The stream data pushes out 'hot' data (like OS kernel code or active application variables) from the cache, degrading overall system performance even though the stream itself is fast.

A.Metadata journaling only logs structural changes (inodes, directories), which are small. Full data journaling logs the actual file content changes as well, which involves writing twice (once to journal, once to final location), doubling write I/O for data. ✅
B.It skips data.
C.It compresses metadata.
D.It uses RAM.
💡 Difficulty: easy | ✅ Correct: A

📖 Explanation: Writing data to the journal and then to the file is slow. Metadata is tiny (KBs). Journaling only metadata ensures structural consistency quickly. Data consistency is left to the application or write-back cache.

Q87. What is 'Bit Rot' or 'Data Degradation' in long-term storage?

A.The gradual decay of magnetic charges or flash electron traps over time, leading to bit flips. File systems like ZFS use checksums to detect this and RAID/replication to heal it by reading from a good copy. ✅
B.Rotting fruit.
C.Disk corrosion.
D.Virus infection.
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: Bits aren't permanent. Electrons leak. Magnetic domains weaken. Without checksums, the OS reads corrupted data silently. Checksums detect the error; redundancy fixes it.

Q88. How does 'Interrupt Affinity' tuning improve I/O performance?

Q89. What is 'Lease-Based Caching' in distributed systems?

D.It buys cache.
💡 Difficulty: hard | ✅ Correct: A

📖 Explanation: Simple caching leads to staleness. Leases provide a contract: 'You can cache this for 10 seconds.' After 10s, you must check back. If the server changes the file, it breaks the lease. This balances consistency and performance.

Q90. What is the 'Extent Tree' in ext4?

Q91. Why is 'Write Caching' on the drive itself risky without power protection?

Q92. What is 'Scatter-Gather List' (SGL) in NVMe?

Q100. Why is 'Allocation Groups' used in XFS?

Q101. What is 'Read Lookahead' in disk controllers?

Q102. How does 'Memory-Mapped I/O' affect cache coherence?

Q103. What is the 'Writeback Throttling' mechanism?

A.It limits the rate at which dirty pages are generated by processes, forcing them to wait if the amount of dirty data in memory exceeds a threshold. This prevents the system from running out of clean pages and stalling due to massive synchronous flushes later. ✅

Q104. Why is 'Error Correction Code' (ECC) essential in NAND Flash?

Q105. What is 'Completion Queue' in NVMe?
