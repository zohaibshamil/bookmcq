What is Introduction to Process Management in Operating Systems?

Definition:
Process management involves creating, scheduling, and terminating processes, where CPU utilization aims to maximize U=TbusyTtotal U = \frac{T_{busy}}{T_{total}} U=Ttotal​Tbusy​​ through algorithms like round-robin or priority scheduling.

Example:
The OS maintaining a Process Control Block (PCB) for each active program containing state, registers, and memory pointers to facilitate rapid context switching between running tasks.

Reason:
Effective process management enables multiprogramming and time-sharing, giving users the illusion of dedicated processors while optimizing throughput and response time across competing workloads.

📝 All Introduction to Process Management in Operating Systems MCQs

Q1. Why is a process considered an 'active' entity while a program is considered 'passive'?

A.A program contains executable instructions stored on disk, whereas a process includes the current activity represented by the program counter and register values. ✅
B.A program is written in high-level language, whereas a process is machine code.
C.A program can be executed by multiple users, whereas a process is single-user.
D.A program resides in secondary storage, whereas a process resides only in registers.
💡 Difficulty: easy | ✅ Correct: A

📖 Explanation: A program is a static file containing code. A process is the dynamic instance of that code in execution, possessing state such as the program counter, stack, and data section.

Q2. In a multiprogramming environment, what is the primary objective of keeping multiple processes in memory simultaneously?

A.To ensure that every user gets an equal time slice immediately.
B.To maximize CPU utilization by ensuring the CPU always has a process to execute when another waits for I/O. ✅
C.To reduce the total amount of physical memory required by the system.
D.To prevent any single process from monopolizing the disk drive.
💡 Difficulty: easy | ✅ Correct: B

📖 Explanation: Multiprogramming aims to keep the CPU busy. When one process waits for I/O, the OS switches to another ready process, thereby increasing overall CPU utilization.

Q3. Which component of the Process Control Block (PCB) is critical for resuming a process after a context switch?

A.The process ID (PID).
B.The program counter and CPU registers. ✅
C.The list of open files.
D.The accounting information.
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: The program counter indicates the next instruction to execute, and the registers hold the current computational state. Without saving and restoring these, the process cannot resume correctly where it left off.

Q4. What distinguishes a 'zombie' process from an 'orphan' process in UNIX-like systems?

A.A zombie process has terminated but its parent has not yet called wait(), whereas an orphan process's parent has terminated. ✅
B.A zombie process is waiting for I/O, whereas an orphan process is waiting for CPU.
C.A zombie process has no PID, whereas an orphan process has a PID of 0.
D.A zombie process is running in kernel mode, whereas an orphan is in user mode.
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: A zombie retains its entry in the process table so the parent can read its exit status. An orphan is adopted by the init process (PID 1) because its original parent died.

Q5. Why does the fork() system call typically return twice?

A.It returns once to the parent with the child's PID and once to the child with 0. ✅
B.It returns once to the operating system and once to the hardware.
C.It returns once for the text segment and once for the data segment.
D.It returns once if successful and once if it fails.
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: fork() creates a duplicate process. Both processes continue execution from the point of the fork. The return value differentiates them: 0 for the child, and the child's PID for the parent.

Q6. If a process executes exec() immediately after fork(), why is copy-on-write optimization particularly beneficial?

A.It prevents the child process from accessing the parent's memory.
B.It avoids the unnecessary overhead of copying the parent's address space since it will be replaced by the new program. ✅
C.It allows the parent and child to share the same stack permanently.
D.It ensures that the new program inherits all the parent's open file descriptors securely.
💡 Difficulty: hard | ✅ Correct: B

📖 Explanation: Standard fork copies the address space. If exec follows immediately, that copy is wasted. Copy-on-write delays physical copying until a write occurs; since exec replaces the memory image, no copying of the old image is ever needed.

Q7. What is the primary disadvantage of using threads instead of processes for concurrent tasks?

A.Threads cannot share memory.
B.Threads are more expensive to create than processes.
C.A bug in one thread can crash the entire process because they share the same address space. ✅
D.Threads cannot utilize multiple CPU cores.
💡 Difficulty: medium | ✅ Correct: C

📖 Explanation: Threads share the same heap and global variables. If one thread corrupts memory or enters an infinite loop holding a lock, it affects all other threads in the same process, unlike isolated processes.

Q8. In the many-to-one multithreading model, what happens if one user-level thread makes a blocking system call?

A.Only that specific thread blocks, and others continue running.
B.The entire process blocks because the kernel sees only one thread. ✅
C.The operating system automatically creates a new kernel thread to handle the call.
D.The thread is swapped out to disk while others run.
💡 Difficulty: hard | ✅ Correct: B

📖 Explanation: In the many-to-one model, the kernel is unaware of user-level threads. It sees only one kernel thread associated with the process. If that kernel thread blocks on a system call, the whole process stops.

Q9. Why is the 'init' process (PID 1) significant in UNIX process management?

A.It is the first process created by the kernel and adopts orphaned processes. ✅
B.It manages all I/O devices directly.
C.It is the only process allowed to run in kernel mode.
D.It schedules all other processes on the CPU.
💡 Difficulty: easy | ✅ Correct: A

📖 Explanation: Init is the ancestor of all user processes. If a parent terminates before its child, the child becomes an orphan and is reparented to init, which periodically calls wait() to clean up zombie children.

Q10. Which state transition is NOT directly possible in a standard five-state process model?

A.Ready to Running.
B.Running to Waiting.
C.Waiting to Running. ✅
D.Waiting to Ready.
💡 Difficulty: medium | ✅ Correct: C

📖 Explanation: A process in the Waiting (Blocked) state must first move to the Ready state when the event it is waiting for occurs. It cannot go directly to Running; the scheduler must select it from the Ready queue first.

Q11. What is the role of the 'short-term scheduler' (CPU scheduler)?

A.To select which process from the ready queue should be allocated the CPU. ✅
B.To decide which jobs are admitted into the system from the job pool.
C.To swap processes in and out of main memory.
D.To create new processes when resources are available.
💡 Difficulty: easy | ✅ Correct: A

📖 Explanation: The short-term scheduler operates frequently (milliseconds) to select the next process from the ready queue for execution on the CPU. The long-term scheduler handles admission, and the medium-term handles swapping.

Q12. How does the 'long-term scheduler' influence the degree of multiprogramming?

A.By selecting processes from the job pool and loading them into memory, it controls how many processes reside in memory concurrently. ✅
B.By rapidly switching between processes, it increases the number of active threads.
C.By swapping out idle processes, it reduces the memory footprint.
D.By terminating processes that exceed their time limits.
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: The degree of multiprogramming is the number of processes in memory. The long-term scheduler controls this by admitting new processes only when there is space and balancing the mix of I/O-bound and CPU-bound jobs.

Q13. Why might an operating system use a 'medium-term scheduler'?

A.To improve performance by removing memory-intensive processes from memory temporarily (swapping) to free up frames. ✅
B.To prioritize real-time processes over batch processes.
C.To manage the creation of new threads within a process.
D.To handle interrupt requests from I/O devices.
💡 Difficulty: hard | ✅ Correct: A

📖 Explanation: Swapping allows the OS to reduce the degree of multiprogramming when memory is scarce. The medium-term scheduler swaps out processes to free memory and swaps them back in later, facilitating load balancing and memory management.

Q14. In the context of process creation, what does 'cascading termination' refer to?

A.When a parent process terminates, all its child processes are also terminated by the OS. ✅
B.When a child process terminates, the parent is forced to restart.
C.When a process crashes, it causes the kernel to reboot.
D.When multiple processes terminate simultaneously due to a power failure.
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: Some systems do not allow children to exist without parents. If a parent exits, the OS recursively terminates all descendants to prevent orphaned processes from consuming resources indefinitely.

Q15. What is the primary purpose of interprocess communication (IPC) via shared memory?

A.To allow processes to exchange data by reading and writing to a common region of memory without kernel intervention for each access. ✅
B.To send messages through the operating system's message queue.
C.To duplicate files between two different hard drives.
D.To synchronize CPU clocks across multiple processors.
💡 Difficulty: easy | ✅ Correct: A

📖 Explanation: Shared memory establishes a region accessible by multiple processes. Once set up, data exchange is as fast as local memory access, avoiding the overhead of system calls required in message passing.

Q16. Why is message passing often preferred over shared memory in distributed systems?

A.Message passing does not require shared physical memory and handles synchronization implicitly through send/receive operations. ✅
B.Message passing is faster than shared memory on a single machine.
C.Shared memory cannot be used between threads.
D.Message passing requires less coding effort.
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: In distributed systems, nodes do not share physical memory. Message passing abstracts the network communication, making it the natural choice for IPC across machines, whereas shared memory is limited to a single address space.

Q17. What is a 'race condition' in the context of cooperating processes?

A.When the outcome of execution depends on the particular order in which instructions of concurrent processes are interleaved. ✅
B.When two processes try to access the CPU at the exact same nanosecond.
C.When a process runs faster than the operating system can schedule it.
D.When a deadlock occurs due to resource starvation.
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: Race conditions occur when multiple processes access shared data concurrently, and the final result depends on the timing of their execution. Proper synchronization is required to prevent this.

Q18. Which of the following best describes the 'producer-consumer' problem?

A.A synchronization issue where a producer generates data and a consumer uses it, requiring coordination to prevent buffer overflow or underflow. ✅
B.A scheduling problem where the CPU produces results and the memory consumes them.
C.A memory allocation problem where processes produce fragments and consume free space.
D.A networking problem where packets are produced by the sender and consumed by the receiver.
💡 Difficulty: easy | ✅ Correct: A

📖 Explanation: This is a classic synchronization paradigm. The producer adds items to a bounded buffer, and the consumer removes them. They must synchronize to ensure the producer doesn't write to a full buffer and the consumer doesn't read from an empty one.

Q19. Why is the 'bounded-buffer' solution more complex than the 'unbounded-buffer' solution?

A.The bounded buffer requires synchronization mechanisms to handle cases where the buffer is full or empty, whereas the unbounded buffer never fills up. ✅
B.The bounded buffer uses less memory, making it harder to allocate.
C.The unbounded buffer requires complex pointer arithmetic.
D.The bounded buffer cannot be implemented using semaphores.
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: An unbounded buffer theoretically has infinite size, so the producer never blocks. A bounded buffer has a fixed size, requiring the producer to wait if full and the consumer to wait if empty, necessitating synchronization primitives like semaphores or mutexes.

Q20. What is the significance of the 'context switch' overhead in system performance?

A.It represents pure overhead where no useful work is done, so frequent context switches can degrade throughput. ✅
B.It improves security by isolating processes.
C.It increases the clock speed of the CPU.
D.It reduces the amount of memory required for each process.
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: During a context switch, the OS saves the state of the old process and loads the state of the new one. The CPU performs no user-level work during this time. Excessive switching wastes CPU cycles.

Q21. How does the 'many-to-many' multithreading model overcome the limitations of the 'many-to-one' and 'one-to-one' models?

A.It allows many user threads to be mapped to a smaller or equal number of kernel threads, enabling true concurrency without the high overhead of creating a kernel thread for every user thread. ✅
B.It maps every user thread to a unique kernel thread, maximizing parallelism.
C.It maps all user threads to a single kernel thread, minimizing overhead.
D.It eliminates the need for kernel threads entirely.
💡 Difficulty: hard | ✅ Correct: A

📖 Explanation: Many-to-one lacks true concurrency (blocking one blocks all). One-to-one has high overhead for many threads. Many-to-many balances this by allowing concurrency (multiple kernel threads) while managing the number of kernel threads efficiently.

Q22. In Linux, how are threads fundamentally different from processes in terms of kernel data structures?

A.Linux does not strictly distinguish between them; both are treated as 'tasks' that may share resources like memory and file descriptors based on flags passed to clone(). ✅
B.Threads have their own separate page tables, while processes share them.
C.Processes are scheduled by the kernel, but threads are scheduled by the user library.
D.Threads cannot receive signals, but processes can.
💡 Difficulty: hard | ✅ Correct: A

📖 Explanation: Linux uses the clone() system call. By specifying flags like CLONE_VM and CLONE_FILES, a new task can share the parent's memory and files, effectively creating a thread. Without these flags, it acts like a traditional forked process.

Q23. What is the primary risk associated with asynchronous cancellation of a thread?

A.Resources allocated to the thread (like locks or memory) may not be properly released, leading to deadlocks or memory leaks. ✅
B.The thread may take too long to terminate.
C.The operating system may crash due to invalid pointers.
D.The parent process will be terminated along with the thread.
💡 Difficulty: hard | ✅ Correct: A

📖 Explanation: Asynchronous cancellation terminates the thread immediately. If the thread was holding a mutex or had allocated memory that needs freeing, these actions are skipped, potentially leaving the system in an inconsistent state. Deferred cancellation is safer.

Q24. Why is thread-local storage (TLS) necessary in multithreaded applications?

A.Because threads share the same global variables, TLS provides each thread with its own private copy of specific data to avoid race conditions on those variables. ✅
B.Because threads cannot access the heap.
C.Because TLS increases the speed of context switching.
D.Because TLS allows threads to communicate with each other securely.
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: Since threads share the process's data segment, global variables are shared. TLS allows a variable to be declared such that each thread gets its own instance, preventing conflicts when threads need to maintain separate state for the same logical variable.

Q25. What determines whether a process is 'I/O-bound' or 'CPU-bound'?

A.An I/O-bound process spends more time waiting for I/O operations than executing CPU instructions, while a CPU-bound process spends most of its time computing. ✅
B.An I/O-bound process uses more memory than a CPU-bound process.
C.A CPU-bound process interacts frequently with the keyboard and mouse.
D.An I/O-bound process has a higher priority than a CPU-bound process.
💡 Difficulty: easy | ✅ Correct: A

📖 Explanation: This classification is based on behavior. I/O-bound processes have short CPU bursts and long I/O waits. CPU-bound processes have long CPU bursts and infrequent I/O. This distinction is crucial for scheduling algorithms.

Q26. Why is the 'fork-exec' pattern commonly used in UNIX shells to run commands?

A.Fork creates a duplicate of the shell, and exec replaces the child's memory image with the command's program, allowing the shell to continue running independently. ✅
B.Fork executes the command directly, and exec creates a new process for the shell.
C.Fork and exec are combined into a single system call for efficiency.
D.Exec creates a child process, and fork loads the program into it.
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: This separation allows the shell (parent) to remain intact while the child runs the new program. Fork provides the new process context, and exec loads the new binary. This modularity simplifies process management and error handling.

Q27. What is the effect of 'priority inversion' in real-time scheduling?

A.A low-priority process holds a resource needed by a high-priority process, causing the high-priority process to wait indirectly behind medium-priority processes. ✅
B.A high-priority process is mistakenly assigned a low priority by the scheduler.
C.A process changes its own priority to gain CPU access.
D.The operating system inverts the priority queue, serving the last process first.
💡 Difficulty: hard | ✅ Correct: A

📖 Explanation: Priority inversion violates the priority principle. It occurs when a high-priority task is blocked by a low-priority task holding a lock, and a medium-priority task preempts the low-priority task, preventing it from releasing the lock. Priority inheritance protocols solve this.

Q28. In the context of process synchronization, what is a 'critical section'?

A.A segment of code where a process accesses shared resources, and only one process should be allowed to execute in this section at a time to prevent race conditions. ✅
B.The part of the CPU where interrupts are handled.
C.The memory area reserved for the operating system kernel.
D.The section of the PCB that stores the process priority.
💡 Difficulty: easy | ✅ Correct: A

📖 Explanation: The critical section is the code region that manipulates shared data. To ensure data consistency, mutual exclusion must be enforced so that no two processes are in their critical sections simultaneously.

Q29. Why might a system choose 'preemptive' scheduling over 'non-preemptive' scheduling?

A.Preemptive scheduling allows the OS to interrupt a running process to give the CPU to a higher-priority or ready process, improving responsiveness and fairness. ✅
B.Non-preemptive scheduling is too complex to implement.
C.Preemptive scheduling requires less memory.
D.Non-preemptive scheduling causes more context switches.
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: Non-preemptive scheduling lets a process run until it voluntarily yields or terminates. This can lead to poor response times for interactive users if a long CPU-bound process runs. Preemption ensures the OS maintains control and can service urgent tasks.

Q30. What is the relationship between a 'process' and a 'thread' regarding resource ownership?

A.A process is the unit of resource ownership (memory, files), while a thread is the unit of CPU execution within that process. ✅
B.A thread owns the memory, and the process executes the instructions.
C.Both processes and threads own separate memory spaces.
D.A process is a type of thread that runs in kernel mode.
💡 Difficulty: easy | ✅ Correct: A

📖 Explanation: The process provides the environment (address space, resources). Threads are lightweight entities within that environment that share the resources but have their own execution state (stack, registers, PC).
