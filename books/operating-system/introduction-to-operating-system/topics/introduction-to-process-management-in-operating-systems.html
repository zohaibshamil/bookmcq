📝 Introduction to Process Management in Operating Systems (27 MCQs)

Definition of Process Management:

Process management is the operating system function responsible for creating, scheduling, executing, synchronizing, and terminating processes. It distinguishes an active program from a passive program file. Without process management, multiple applications could compete unpredictably for processor time, causing execution conflicts and preventing effective multitasking.

How Process Management Works:

The operating system creates a process and assigns it resources and a process control block. It places the process in an appropriate scheduling queue. The scheduler selects a ready process, while the dispatcher transfers processor control. Processes may block, resume, communicate, or terminate.

Process Management Example:

Consider Process A and Process B. A executes for 4 milliseconds before its time slice expires. The operating system saves A's execution context and schedules B. After another 4 milliseconds, B is interrupted, allowing A to resume from its saved state.

Why Process Management Matters:

Process management provides controlled multitasking instead of allowing one application to monopolize the processor. Without scheduling and context switching, other ready processes may experience unnecessary delays. However, frequent switching introduces overhead because execution state must be saved and restored.

Common Misconceptions About Process Management:

'A program and process are identical.' Correction: A program is passive code, whereas a process is an executing instance. 'Blocked processes are ready to execute.' Correction: They await an event. 'Context switching performs useful application work.' Correction: It primarily changes execution context.

Exam Tips for Process Management:

Learn process states and draw their transition diagram. Explain process creation, termination, scheduling, and context switching. Practice identifying ready, running, and blocked processes in scenarios. Exams commonly test process control blocks and scheduling sequences.

Key Terms in Process Management:

  • Process - An executing instance of a program.
  • PCB - Stores information required to manage a process.
  • Scheduler - Selects processes for processor execution.
  • Context Switching - Saving one process state and restoring another.

📝 All Introduction to Process Management in Operating Systems MCQs

Q1. A developer launches a text editor, a music player, and a web browser simultaneously. The operating system assigns each running program the resources needed for execution. What operating system entity represents each running instance of these programs?

A.Thread
B.Process ✅
C.Program file
D.System call
💡 Difficulty: easy | ✅ Correct: B

📖 Explanation: A process is an instance of a program that is currently executing, with its own execution state and allocated resources. A program file is passive code stored on disk, whereas a process is active. Remember that a program becomes a process when it is loaded and executed.

Q2. A process P1 is executing when its time quantum expires. The scheduler selects P2, saves P1's register values, and restores P2's saved values. What operation has occurred?

A.Process synchronization
B.Process creation
C.Context switching ✅
D.Memory compaction
💡 Difficulty: easy | ✅ Correct: C

📖 Explanation: Context switching occurs when the CPU changes from executing one process to another. The OS saves the current process state and restores the selected process state. Process creation would introduce a new process rather than simply change CPU ownership. Remember that saving and restoring CPU context identifies a context switch.

Q3. A student examines a process control block and finds its process ID, state, program counter, and CPU register values. Why does the operating system maintain this information?

A.To preserve process execution information during scheduling and switching. ✅
B.To store the complete source code of every running program.
C.To maintain permanent copies of all files accessed by the process.
D.To replace the processor's hardware registers during normal execution.
💡 Difficulty: easy | ✅ Correct: A

📖 Explanation: A Process Control Block stores essential information about a process, including its state, identification, program counter, and registers. The scheduler uses this information to manage execution and restore processes after context switches. A PCB does not contain the complete source code. Remember that the PCB represents the OS-managed process record.

Q4. A web server creates a new worker process whenever a client request arrives. The parent process continues accepting additional requests while the worker handles its assigned task. What benefit does this design provide?

A.It guarantees that every worker uses the same memory address space.
B.It eliminates the need for CPU scheduling.
C.It prevents workers from performing I/O operations.
D.It allows multiple requests to be handled independently. ✅
💡 Difficulty: medium | ✅ Correct: D

📖 Explanation: Creating separate worker processes allows the server to handle multiple requests independently. The operating system schedules their CPU execution and manages their resources. Separate processes do not automatically share the same address space. Remember that process-based concurrency improves workload separation and responsiveness.

Q5. A process is currently waiting for data from a keyboard. The keyboard event occurs, and the required input becomes available. Which state transition normally follows?

A.Waiting to terminated
B.Waiting to ready ✅
C.Running to new
D.Ready to waiting
💡 Difficulty: easy | ✅ Correct: B

📖 Explanation: When the required I/O event completes, a waiting process becomes ready because it can continue execution when the CPU is assigned. It does not immediately become running because another process may currently occupy the CPU. Remember that I/O completion generally moves a process from waiting to ready.

Q6. A process is created successfully, but the scheduler has not yet selected it for CPU execution. What is its most likely state?

A.Running
B.Waiting
C.Ready ✅
D.Terminated
💡 Difficulty: easy | ✅ Correct: C

📖 Explanation: A newly admitted process typically enters the ready state after initialization and resource preparation. It is eligible for CPU execution but must wait until the scheduler selects it. Running means the CPU is currently executing it. Remember that ready processes are waiting for CPU time, not I/O completion.

Q7. During a context switch, the operating system saves the program counter of process P1 before loading process P2. What does the saved program counter allow P1 to do later?

A.Resume execution from the instruction where it was interrupted. ✅
B.Restart execution from the beginning of its program.
C.Recover deleted files from secondary storage.
D.Continue execution without restoring its registers.
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: The program counter identifies the next instruction to execute. Saving it in the process context allows P1 to resume from the correct location when scheduled again. Restarting from the beginning would discard progress. Remember that restoring the program counter and registers is essential for correct process resumption.

Q8. A system has four ready processes, but only one CPU is available. The scheduler selects P3 while P1, P2, and P4 remain in the ready queue. What happens to the selected process?

A.It enters the waiting state until I/O completes.
B.It enters the terminated state after selection.
C.It remains in the new state until memory is allocated.
D.It transitions from ready to running. ✅
💡 Difficulty: easy | ✅ Correct: D

📖 Explanation: The scheduler dispatches a selected ready process to the CPU, causing a transition from ready to running. The other ready processes remain eligible for execution. Waiting indicates that a process cannot continue until an event occurs. Remember the standard dispatch transition: ready to running.

Q9. A process creates a child process using a process-creation system call. The parent and child both become eligible for execution. What relationship exists between them?

A.They must share the same process ID.
B.They are separate processes with distinct process identifiers. ✅
C.The child automatically replaces the parent in the ready queue.
D.The parent loses its process control block permanently.
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: A child process receives its own process identifier and is managed as a separate process by the operating system. The parent may continue executing or wait for the child, depending on the program's behaviour. Remember that process creation establishes a parent-child relationship without merging their identities.

Q10. A CPU executes process P1, which requests a disk read. The operating system blocks P1 until the disk operation completes and dispatches P2. What state does P1 enter immediately after requesting the disk read?

A.Ready
B.Running
C.Waiting ✅
D.New
💡 Difficulty: medium | ✅ Correct: C

📖 Explanation: A process that requests an I/O operation cannot continue until the requested event completes, so it enters the waiting or blocked state. P2 may then be dispatched if it is ready. The ready state means a process is eligible for CPU execution. Remember that blocking I/O typically moves running to waiting.

Q11. A process has been selected by the scheduler, but the CPU has not yet started executing its first instruction because the dispatcher is still restoring its context. What operation is taking place?

A.Process dispatching ✅
B.Process termination
C.Process synchronization
D.Process suspension
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: Dispatching transfers CPU control to the process selected by the short-term scheduler. This includes restoring its context and switching to the appropriate execution mode. Scheduling selects the process, while dispatching actually gives it the CPU. Remember the distinction: scheduler selects, dispatcher executes the switch.

Q12. A system contains processes P1, P2, and P3. P1 is running, P2 is ready, and P3 is waiting for disk input. The disk operation for P3 finishes, and a preemptive scheduler selects P2. What is the resulting state of P1, P2, and P3, respectively?

A.Waiting, running, ready
B.Ready, waiting, running
C.Terminated, running, ready
D.Ready, running, ready ✅
💡 Difficulty: hard | ✅ Correct: D

📖 Explanation: P1 is preempted and returns to ready, P2 is dispatched and becomes running, and P3 moves from waiting to ready after disk completion. The key is that disk completion does not guarantee immediate CPU execution. Remember to evaluate each process transition independently when analysing scheduling traces.

Q13. A process is currently executing an infinite loop. A timer interrupt occurs, and the OS gives the CPU to another ready process. What feature of the operating system makes this possible?

A.Cooperative file management
B.Preemptive multitasking ✅
C.Static memory allocation
D.Sequential process execution
💡 Difficulty: easy | ✅ Correct: B

📖 Explanation: Preemptive multitasking allows the operating system to interrupt a running process and reassign the CPU. A timer interrupt provides an opportunity for the scheduler to regain control. Cooperative scheduling would depend on the running process voluntarily yielding the CPU. Remember that timer interrupts support preemption.

Q14. A process enters the ready queue after completing an I/O operation. However, the CPU is currently executing another process. What resource is the process waiting to obtain?

A.Secondary storage space
B.A device interrupt
C.CPU time ✅
D.A new process identifier
💡 Difficulty: easy | ✅ Correct: C

📖 Explanation: A ready process has all the conditions required to execute except access to the CPU. It waits in the ready queue until the scheduler selects it. A waiting process, in contrast, is waiting for an event such as I/O completion. Remember that ready means waiting for CPU allocation.

Q15. A program uses two threads to process separate sections of a large dataset. Both threads belong to the same process. Which resource is generally shared between these threads?

A.The process's address space and open files ✅
B.Each thread's program counter
C.Each thread's CPU register set
D.Each thread's execution stack
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: Threads belonging to the same process generally share its address space, code, data, and open files. However, each thread maintains its own program counter, registers, and stack to support independent execution. Remember that threads share process resources but maintain separate execution contexts.

Q16. An operating system uses a process table containing 200 entries. Each process has a unique PID. After process 45 terminates, the OS creates another process. What can happen to PID 45?

A.It must remain permanently unused.
B.It must be assigned to the parent process.
C.It must become the new process's memory address.
D.It may be reused according to the OS's PID allocation policy. ✅
💡 Difficulty: medium | ✅ Correct: D

📖 Explanation: Process identifiers uniquely distinguish active processes, but operating systems may reuse identifiers after processes terminate. Reuse depends on the PID allocation policy and must avoid conflicts with active processes. A PID is not a memory address. Remember that uniqueness is required among active processes, not necessarily throughout system lifetime.

Q17. A process P1 executes for 4 milliseconds, blocks for disk I/O, and later resumes for another 3 milliseconds. During the I/O interval, P2 uses the CPU. What is the total CPU execution time consumed by P1?

A.4 milliseconds
B.7 milliseconds ✅
C.11 milliseconds
D.3 milliseconds
💡 Difficulty: easy | ✅ Correct: B

📖 Explanation: CPU execution time includes only the periods during which the processor executes P1. Adding its two execution intervals gives \(4+3=7\) milliseconds. The time spent waiting for disk I/O is not CPU burst time. Remember to exclude blocked intervals when calculating a process's CPU execution time.

Q18. A system has 10 processes, each requiring 2 milliseconds of context-switch overhead whenever the CPU changes from one process to another. If the CPU switches between processes 9 times, how much total time is spent on context switching?

A.9 milliseconds
B.11 milliseconds
C.18 milliseconds ✅
D.20 milliseconds
💡 Difficulty: medium | ✅ Correct: C

📖 Explanation: Each context switch consumes 2 milliseconds, so nine switches require \(9\\times2=18\) milliseconds. This time is overhead rather than useful process execution. A common error is counting processes instead of actual switches. Remember to multiply the number of switches by the overhead per switch.

Q19. A process is executing when its parent requests that it terminate. The operating system releases its allocated resources and removes its active execution information. What state does the process enter?

A.Terminated ✅
B.Ready
C.Waiting
D.New
💡 Difficulty: easy | ✅ Correct: A

📖 Explanation: A process enters the terminated state after its execution ends and the operating system performs the required cleanup. Its resources are released, and its active process information is eventually removed. Ready and waiting describe processes that have not completed execution. Remember that termination is the final process lifecycle state.

Q20. A system has five processes in the ready queue. A newly created high-priority process arrives, and the scheduling policy is preemptive priority scheduling. The new process has a higher priority than the running process. What is the expected action?

A.The new process waits until the running process terminates.
B.The running process moves to the waiting state.
C.The OS terminates the running process.
D.The running process is preempted and the new process is dispatched. ✅
💡 Difficulty: medium | ✅ Correct: D

📖 Explanation: In preemptive priority scheduling, a newly ready process with a higher priority can interrupt the currently running process. The interrupted process normally returns to the ready queue rather than being terminated or blocked. Remember that preemptive priority scheduling permits higher-priority arrivals to take the CPU.

Q21. A process P1 creates child P2 and then waits for P2 to finish. P2 completes its execution while P1 remains blocked. What happens to P1 after the child terminates?

A.P1 automatically terminates with P2.
B.P1 becomes ready to resume execution. ✅
C.P1 returns to the new state.
D.P1 permanently remains in the waiting state.
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: When P2 terminates, the event awaited by P1 has occurred. The operating system can move P1 from waiting to ready so it can be scheduled again. P1 does not automatically terminate with its child. Remember that waiting for a child is an event-dependent blocked state.

Q22. A system has a single CPU and three processes with the following CPU burst requirements: P1 = 8 ms, P2 = 5 ms, and P3 = 3 ms. Using non-preemptive Shortest Job First scheduling, all processes arrive at time zero. What is the average waiting time?

A.5 ms
B.6 ms
C.3.67 ms ✅
D.3 ms
💡 Difficulty: hard | ✅ Correct: C

📖 Explanation: Shortest Job First executes P3, P2, then P1. Their waiting times are 0, 3, and 8 milliseconds, respectively. The average is \((0+3+8)/3=3.67\) ms, approximately 3.67 ms. Remember that waiting time is the time before execution begins, not the total turnaround time.

Q23. A process is removed temporarily from main memory because the OS needs to free memory for other processes. Its execution cannot continue until it is brought back. What is this operation commonly called?

A.Context restoration
B.Process dispatching
C.Thread synchronization
D.Process swapping ✅
💡 Difficulty: medium | ✅ Correct: D

📖 Explanation: Swapping temporarily transfers a process between main memory and secondary storage to manage memory pressure. A swapped-out process cannot execute until it is brought back into memory. Context restoration only restores CPU execution information. Remember that swapping concerns process memory residency, not simply CPU scheduling.

Q24. A process P1 is waiting for a disk operation. Another process P2 completes its execution, and the scheduler finds no ready processes. What will the CPU most likely do?

A.Execute P1 even though its disk operation is incomplete.
B.Remain idle or execute an idle task until an event occurs. ✅
C.Restart P2 from its first instruction.
D.Move P1 directly to the terminated state.
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: If no process is ready, the CPU cannot execute a blocked process whose required event has not occurred. The operating system may execute an idle task or place the processor in an idle state until an interrupt arrives. Remember that waiting processes are not eligible for CPU scheduling.

Q25. A process has a PID of 120, a program counter of 5000, and a state of running. After a context switch, its PCB records a program counter of 5000 and a state of ready. What does this information indicate?

A.The process was preempted and can resume from its saved execution point. ✅
B.The process has completed all instructions and is waiting for deletion.
C.The process has restarted from its original entry point.
D.The process has lost its allocated memory permanently.
💡 Difficulty: hard | ✅ Correct: A

📖 Explanation: The saved program counter indicates where the process should resume, while the ready state indicates that it is eligible for CPU execution. This is consistent with preemption during a context switch. A completed process would be terminated, not ready. Remember that PCB fields together describe the process's current execution status.

Q26. A system has two processes sharing a single CPU. P1 executes for 6 ms, followed by P2 for 4 ms, and then P1 executes again for 3 ms. How many context switches occur if the CPU starts with P1 and no other switching overhead is counted?

A.1
B.2 ✅
C.3
D.4
💡 Difficulty: hard | ✅ Correct: B

📖 Explanation: The CPU starts with P1, switches from P1 to P2 after 6 milliseconds, and switches from P2 back to P1 after 4 milliseconds. Therefore, there are two context switches. The final execution of P1 does not require another switch unless another process is selected. Remember to count transitions between different running processes.

Q27. A process executes a system call that creates a child process. The operating system allocates a new PID and PCB for the child. Which additional action is necessary before the child can compete for CPU time?

A.The child must be terminated once its PCB is created.
B.The parent must release its entire address space.
C.The child must immediately replace the parent in the CPU.
D.The child must be initialized and placed in an appropriate schedulable state. ✅
💡 Difficulty: medium | ✅ Correct: D

📖 Explanation: Creating a process requires more than allocating a PID and PCB. The OS must initialize its execution context and required resources before making it eligible for scheduling. A newly created process may initially enter the new state before admission to the ready queue. Remember that process creation includes initialization and scheduling preparation.
