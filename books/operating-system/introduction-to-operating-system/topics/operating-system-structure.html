Q1. Why is the separation of mechanism and policy considered a fundamental design principle in operating systems?

🔹 A. To ensure that the hardware can be replaced without changing the software.
🔹 B. To allow policy decisions to change over time or between installations without requiring changes to the underlying implementation mechanisms.
🔹 C. To reduce the total amount of code required for the kernel.
🔹 D. To make the operating system run faster by hardcoding policies into the hardware.

💡 Difficulty: easy | ✅ Correct: B

📖 Explanation:

Mechanisms determine how something is done, while policies determine what will be done. Separating them allows flexibility; for example, changing the CPU scheduling algorithm (policy) doesn't require rewriting the context switch code (mechanism).

Q2. Which of the following best describes the primary disadvantage of a monolithic kernel structure compared to a microkernel?

🔹 A. It provides less performance due to excessive context switching.
🔹 B. It lacks modularity, making it difficult to extend or debug because all services run in kernel mode with no clear boundaries.
🔹 C. It cannot support multiprocessing.
🔹 D. It requires more memory than a microkernel because it uses virtual memory inefficiently.

💡 Difficulty: medium | ✅ Correct: B

📖 Explanation:

In a monolithic kernel, all OS services run in the same address space. A bug in any service can crash the entire system, and the lack of clear interfaces makes extension and debugging difficult.

Q3. How does a microkernel architecture primarily facilitate the addition of new services?

🔹 A. By recompiling the entire kernel source code with the new service included.
🔹 B. By loading new device drivers directly into the physical memory reserved for the kernel.
🔹 C. By implementing new services as user-level processes that communicate with the kernel via message passing.
🔹 D. By using dynamic linking to attach shared libraries to the kernel's address space.

💡 Difficulty: medium | ✅ Correct: C

📖 Explanation:

Microkernels keep the kernel small by moving non-essential services (like file systems and network stacks) to user space. New services are added as user processes, avoiding kernel modification.

Q4. What is the specific role of the Hardware Abstraction Layer (HAL) in modern operating system designs like Windows?

🔹 A. To provide a graphical user interface that works across different hardware vendors.
🔹 B. To translate high-level application calls into machine code.
🔹 C. To hide hardware-specific details from the rest of the operating system, allowing the OS to be portable across different hardware platforms.
🔹 D. To manage the virtual memory page tables directly.

💡 Difficulty: easy | ✅ Correct: C

📖 Explanation:

The HAL isolates platform-dependent code (like interrupt controllers and multiprocessor synchronization) from the rest of the kernel, enabling the OS to run on different hardware architectures with minimal changes.

Q5. In a layered operating system design, why must Layer N only invoke operations provided by Layer N-1?

🔹 A. To ensure that higher layers do not consume too much CPU time.
🔹 B. To enforce information hiding and simplify debugging by ensuring each layer depends only on lower-level abstractions.
🔹 C. To allow Layer N to access hardware registers directly for performance.
🔹 D. To prevent deadlocks between layers.

💡 Difficulty: medium | ✅ Correct: B

📖 Explanation:

Layering relies on strict hierarchy. If Layer N could call Layer N-2, it would bypass the abstraction of Layer N-1, breaking encapsulation and making the system harder to verify and maintain.

Q6. Which statement accurately reflects the trade-off between layered structures and monolithic kernels regarding performance?

🔹 A. Layered structures generally offer better performance because they use less memory.
🔹 B. Monolithic kernels are typically faster because they avoid the overhead of function calls and parameter passing across layer boundaries.
🔹 C. Layered structures are faster because they allow parallel execution of layers.
🔹 D. There is no significant performance difference between the two architectures.

💡 Difficulty: hard | ✅ Correct: B

📖 Explanation:

Each layer transition involves checking parameters and potentially copying data. In a deeply layered system, a single system call may traverse many layers, adding cumulative overhead compared to the direct function calls in a monolithic kernel.

Q7. What is the defining characteristic of a hybrid kernel, such as those found in macOS (XNU) or Windows NT?

🔹 A. It uses a microkernel for all I/O operations but a monolithic kernel for memory management.
🔹 B. It combines aspects of both monolithic and microkernel designs, often running some critical services in kernel space for performance while keeping others modular.
🔹 C. It runs entirely in user space but simulates kernel mode using hardware virtualization.
🔹 D. It is a monolithic kernel that dynamically loads all modules at boot time only.

💡 Difficulty: medium | ✅ Correct: B

📖 Explanation:

Hybrid kernels aim to balance the performance of monolithic kernels (by keeping key services like networking or file systems in kernel space) with the modularity and stability benefits of microkernels.

Q8. Why might an operating system designer choose a modular approach (loadable kernel modules) over a strictly layered approach?

🔹 A. Modules allow for dynamic addition and removal of functionality without rebooting, offering greater flexibility than static layers.
🔹 B. Layers are easier to implement because they do not require inter-process communication.
🔹 C. Modules provide better security because they run in user space.
🔹 D. Layers consume less disk space than modules.

💡 Difficulty: medium | ✅ Correct: A

📖 Explanation:

Modular kernels allow drivers and file systems to be loaded on demand. This supports hardware diversity and reduces the memory footprint of the base kernel, unlike static layered designs which are fixed at compile/link time.

Q9. In the context of operating system structures, what is the primary function of the 'System Call Interface'?

🔹 B. To serve as the boundary between user mode and kernel mode, providing a controlled entry point for applications to request kernel services.
🔹 C. To manage the physical allocation of RAM to processes.
🔹 D. To schedule threads across multiple CPU cores.

💡 Difficulty: easy | ✅ Correct: B

📖 Explanation:

The system call interface is the API through which user applications interact with the OS. It traps into kernel mode, validates arguments, and invokes the appropriate kernel routine, ensuring protection.

Q10. Which of the following scenarios best illustrates the concept of 'policy vs. mechanism' in CPU scheduling?

🔹 A. The hardware timer interrupt is the mechanism; the decision of how long a time quantum should be is the policy.
🔹 B. The context switch code is the policy; the selection of the next process is the mechanism.
🔹 C. The scheduler algorithm is the mechanism; the hardware clock speed is the policy.
🔹 D. The process control block is the policy; the CPU register set is the mechanism.

💡 Difficulty: medium | ✅ Correct: A

📖 Explanation:

The mechanism is the timer interrupt that forces a context switch. The policy is the rule determining the length of the quantum (e.g., 10ms for interactive, 100ms for batch). Changing the policy doesn't require changing the interrupt handler.

Q11. What is a significant security risk associated with monolithic kernel designs where device drivers run in kernel mode?

🔹 A. Device drivers can easily be updated without restarting the system.
🔹 B. A bug or vulnerability in a third-party device driver can compromise the entire system's integrity and stability.
🔹 C. Device drivers cannot access physical memory directly.
🔹 D. Monolithic kernels do not support access control lists.

💡 Difficulty: hard | ✅ Correct: B

📖 Explanation:

Since drivers share the kernel's address space and privilege level, a flaw in a driver (e.g., buffer overflow) can allow an attacker to execute arbitrary code with full kernel privileges, leading to a rootkit or system crash.

Q12. How does the 'Exokernel' architecture differ fundamentally from traditional monolithic or microkernel designs?

💡 Difficulty: hard | ✅ Correct: B

📖 Explanation:

Exokernels minimize OS intervention by exposing hardware details (like disk blocks or memory pages) to applications. Applications then link with library OSes to implement custom policies, aiming for higher performance and flexibility.

Q13. In a client-server model within an operating system (such as windowing systems), what is the primary advantage of running the server in a separate process?

🔹 A. It allows the server to crash without necessarily bringing down the client applications, enhancing fault isolation.
🔹 B. It reduces the latency of graphics rendering significantly.
🔹 C. It eliminates the need for inter-process communication.
🔹 D. It allows the server to access hardware ports directly without permissions.

💡 Difficulty: medium | ✅ Correct: A

📖 Explanation:

By separating the window server from applications, a bug in an application won't crash the GUI subsystem, and vice versa. This modularity improves overall system reliability.

Q14. Why is the 'bootstrap program' typically stored in ROM or EEPROM rather than on the hard disk?

🔹 A. ROM is faster than hard disks.
🔹 B. ROM is non-volatile and contains the initial instructions needed to load the OS from secondary storage, which is necessary because RAM is empty at power-on.
🔹 C. ROM has larger storage capacity than hard disks.
🔹 D. Hard disks cannot store executable code.

💡 Difficulty: easy | ✅ Correct: B

📖 Explanation:

At power-up, the CPU needs a known starting address with valid instructions. RAM is volatile and uninitialized. ROM/EEPROM retains the bootstrap loader, which initializes hardware and loads the OS kernel from disk into RAM.

Q15. What is the main challenge in implementing a pure microkernel regarding inter-process communication (IPC)?

🔹 A. IPC in microkernels is too fast, causing race conditions.
🔹 B. The frequent context switches and message copying required for IPC between user-space servers and the kernel can lead to significant performance overhead.
🔹 C. Microkernels do not support IPC.
🔹 D. IPC requires direct hardware access which microkernels forbid.

💡 Difficulty: hard | ✅ Correct: B

📖 Explanation:

Since services like file I/O or networking run in user space in a microkernel, every operation requires message passing across the user/kernel boundary. This involves context switches and data copying, which is slower than direct function calls in monolithic kernels.

Q16. Which feature distinguishes a 'Virtual Machine Monitor' (Hypervisor) from a standard operating system kernel?

🔹 A. A hypervisor manages physical hardware to create isolated virtual environments for multiple guest operating systems, whereas a standard kernel manages hardware for a single OS instance.
🔹 B. A hypervisor only runs in user mode.
🔹 C. A hypervisor does not manage memory.
🔹 D. A hypervisor is strictly a type of microkernel.

💡 Difficulty: medium | ✅ Correct: A

📖 Explanation:

A hypervisor (VMM) abstracts the physical hardware to allow multiple OS instances (guests) to run concurrently. It handles resource virtualization and isolation, which is distinct from a standard OS managing resources for its own processes.

Q17. In the context of system generation (SYSGEN), why is table-driven configuration often preferred over recompiling the source code for every hardware change?

🔹 A. Recompiling is error-prone.
🔹 B. Table-driven approaches allow the system to adapt to hardware configurations at boot time or runtime without the time-consuming process of recompilation and relinking.
🔹 C. Table-driven systems are smaller in size.
🔹 D. Recompiling requires a different compiler for each hardware vendor.

💡 Difficulty: medium | ✅ Correct: B

📖 Explanation:

SYSGEN via tables allows the OS to probe hardware or read configuration files to set up data structures dynamically. Recompiling is slow and rigid, making it unsuitable for systems with diverse or changing hardware.

Q18. What is the primary purpose of 'interrupt vectors' in the operating system structure?

🔹 A. To store the data being transferred during an I/O operation.
🔹 B. To provide a mapping from interrupt numbers to the memory addresses of specific interrupt service routines (ISRs), enabling efficient dispatch.
🔹 C. To prioritize interrupts based on their severity.
🔹 D. To buffer input from the keyboard.

💡 Difficulty: medium | ✅ Correct: B

📖 Explanation:

When an interrupt occurs, the CPU uses the interrupt number as an index into the interrupt vector table. This table contains pointers to the specific ISR code, allowing the OS to quickly jump to the correct handler without polling devices.

Q19. Why do modern operating systems like Linux and Solaris use a 'hybrid' or 'modular' structure rather than a pure microkernel?

🔹 A. Pure microkernels were proven to be insecure.
🔹 B. Hybrid/modular structures offer a pragmatic balance, retaining the performance benefits of having key services in kernel space while maintaining the extensibility and modularity of loadable modules.
🔹 C. Hardware manufacturers refused to support pure microkernels.
🔹 D. Modular structures are easier to write in assembly language.

💡 Difficulty: hard | ✅ Correct: B

📖 Explanation:

Pure microkernels suffered from performance penalties due to IPC. Hybrid designs keep performance-critical paths in the kernel (like networking stacks) but allow drivers and file systems to be loaded as modules, achieving a practical balance.

Q20. How does the concept of 'dual-mode operation' (user mode vs. kernel mode) support the structural integrity of an operating system?

🔹 A. It allows the OS to run faster in user mode.

🔹 D. It allows users to modify the kernel code directly.

💡 Difficulty: easy | ✅ Correct: B

📖 Explanation:

Dual-mode operation is a hardware-enforced protection mechanism. User programs run in restricted mode. If they try to perform privileged actions (like I/O or modifying page tables), the hardware traps to the kernel, preventing unauthorized access.

Q21. In a distributed operating system structure, what is the key difference from a network operating system?

🔹 A. A distributed OS makes the collection of independent computers appear to the user as a single coherent system, whereas a network OS makes the network visible and requires explicit remote access commands.
🔹 B. A distributed OS does not use networks.
🔹 C. A network OS shares memory physically between machines.
🔹 D. A distributed OS is always slower.

💡 Difficulty: medium | ✅ Correct: A

📖 Explanation:

Transparency is the key. In a distributed OS, file location and process migration are hidden. In a network OS, users explicitly mount remote shares or use commands like `ssh` or `ftp`, aware of the machine boundaries.

Q22. What is the role of the 'Command Interpreter' (Shell) in the OS structure?

🔹 A. It is part of the kernel responsible for memory allocation.
🔹 B. It is a system program that reads user commands and translates them into system calls, acting as the primary interface between the user and the OS kernel.
🔹 C. It compiles high-level languages into machine code.
🔹 D. It manages the hardware interrupt controller.

💡 Difficulty: easy | ✅ Correct: B

📖 Explanation:

The shell is a user-level process. It parses input, expands wildcards, handles pipes, and invokes the appropriate binaries or system calls. It is not part of the kernel, allowing users to replace it with different shells (bash, zsh, etc.).

Q23. Why is 'spooling' considered a structural component of the I/O subsystem?

🔹 A. It allows multiple processes to send output to a single device (like a printer) by buffering data on disk, decoupling the process execution from the slow device speed.
🔹 B. It increases the resolution of printed documents.
🔹 C. It encrypts data before sending it to the device.
🔹 D. It allows direct memory access for all I/O devices.

💡 Difficulty: medium | ✅ Correct: A

📖 Explanation:

Spooling acts as a buffer between fast producers (applications) and slow consumers (devices). By writing to a disk spool file, the application can continue execution immediately, while the OS manages the actual device transfer asynchronously.

Q24. Which structural approach is most susceptible to the 'domino effect' where a failure in one component crashes the entire system?

🔹 A. Microkernel
🔹 B. Monolithic Kernel
🔹 C. Layered System
🔹 D. Virtual Machine

💡 Difficulty: hard | ✅ Correct: B

📖 Explanation:

In a monolithic kernel, all components share the same address space and privilege level. There is no protection between subsystems (e.g., between the network stack and the file system). A bug in any part can corrupt kernel memory, crashing the whole OS.

Q25. What is the primary benefit of using 'loadable kernel modules' in Linux?

🔹 A. It allows the kernel to be smaller at boot and enables dynamic addition of drivers or file systems without rebooting.
🔹 B. It makes the kernel code open source.
🔹 C. It increases the clock speed of the CPU.
🔹 D. It prevents user programs from accessing the kernel.

💡 Difficulty: medium | ✅ Correct: A

📖 Explanation:

LKMs allow the base kernel to remain lean. Drivers for rare hardware or experimental file systems can be loaded only when needed, saving memory and allowing updates to drivers without a full system restart.

Q26. In the Mach microkernel design, what mechanism replaces traditional system calls for many operations?

🔹 A. Direct memory access.
🔹 B. Message passing.
🔹 C. Shared memory pointers.
🔹 D. Interrupts.

💡 Difficulty: hard | ✅ Correct: B

📖 Explanation:

Mach relies heavily on message passing for communication between tasks and servers. Even basic operations often involve sending messages to user-space servers, which was a radical departure from traditional UNIX system calls.

Q27. Why is the 'file system' often implemented as a separate module or server rather than being tightly integrated into the core scheduler?

🔹 A. To allow different file system types (NTFS, ext4, FAT) to coexist and be swapped without altering the core kernel logic.

🔹 C. To make the file system run faster than the CPU.
🔹 D. Because schedulers cannot understand file names.

💡 Difficulty: medium | ✅ Correct: A

📖 Explanation:

Modularity allows the OS to support multiple file system formats. The VFS (Virtual File System) layer provides a common interface, while specific file system modules handle the on-disk structures. This separation simplifies maintenance and extension.

Q28. What is the significance of the 'Process Control Block' (PCB) in the OS structure?

🔹 A. It is the data structure used by the kernel to store all information about a specific process, enabling context switching and management.
🔹 B. It is a user-level data structure for storing variables.
🔹 C. It is the hardware register set of the CPU.
🔹 D. It is the file descriptor table.

💡 Difficulty: easy | ✅ Correct: A

📖 Explanation:

The PCB is the kernel's representation of a process. It holds state (registers, PC), scheduling info, memory maps, and I/O status. Without the PCB, the OS cannot suspend and resume processes effectively.

Q29. How does 'symmetric multiprocessing' (SMP) influence OS structure?

🔹 A. It requires the OS kernel to be reentrant and thread-safe, as multiple CPUs may execute kernel code simultaneously.
🔹 B. It requires a separate OS instance for each CPU.
🔹 C. It eliminates the need for interrupts.
🔹 D. It forces the OS to use a microkernel design.

💡 Difficulty: medium | ✅ Correct: A

📖 Explanation:

In SMP, any CPU can run any thread, including kernel threads. The kernel data structures must be protected by locks (spinlocks/mutexes) to prevent race conditions when multiple CPUs access them concurrently.

Q30. What is the main disadvantage of the 'simple structure' seen in early MS-DOS?

🔹 A. It lacked protection between applications and the OS, allowing any program to crash the system or overwrite memory.
🔹 B. It was too complex for users to understand.
🔹 C. It did not support floppy disks.
🔹 D. It required a graphical interface.

💡 Difficulty: medium | ✅ Correct: A

📖 Explanation:

MS-DOS ran in a single mode with no memory protection. Applications had direct access to hardware and memory. A buggy program could overwrite the OS code or other applications, leading to system instability.

Q31. In the context of OS structure, what is a 'daemon'?

🔹 C. A type of kernel panic.
🔹 D. A user interface shell.

💡 Difficulty: easy | ✅ Correct: B

📖 Explanation:

Daemons (or services) are long-running processes that start at boot and wait for requests. They are structural elements that extend OS functionality (e.g., cron, sshd) without being part of the kernel itself.

Q32. Why do some operating systems use a 'Virtual File System' (VFS) layer?

🔹 C. To encrypt all file data.

💡 Difficulty: medium | ✅ Correct: A

📖 Explanation:

VFS abstracts the differences between local file systems (ext4, NTFS) and network file systems (NFS). It provides a uniform interface to applications, so they don't need to know the specific details of the storage backend.

Q33. What is the primary reason for moving the 'Graphics Subsystem' out of the kernel in modern OS designs like Windows Vista/7 and macOS?

🔹 A. To improve system stability by ensuring that a graphics driver crash does not take down the entire kernel.

💡 Difficulty: hard | ✅ Correct: A

📖 Explanation:

Historically, graphics drivers ran in kernel mode. Because they are complex and frequently updated, they were a major source of blue screens. Moving them to user mode (or a separate protected server) isolates faults.

Q34. Which of the following best describes the 'Client-Server' model in the context of the X Window System?

In X11, the 'server' is the entity controlling the screen/keyboard/mouse. Applications are 'clients' that send requests to draw windows. This allows apps to run on one machine and display on another, demonstrating a flexible structural split.

Q35. What is the role of the 'Scheduler' in the OS structure?

🔹 C. To manage network packets.

💡 Difficulty: easy | ✅ Correct: A

📖 Explanation:

The scheduler is a core kernel component responsible for deciding which ready process gets the CPU next. It implements the CPU scheduling policy (e.g., Round Robin, Priority).

Q36. Why is 'context switching' considered a structural overhead in multitasking systems?

🔹 A. It requires saving and restoring processor state and updating kernel data structures, consuming CPU cycles that do not perform useful work for the application.

🔹 C. It increases the network bandwidth.
🔹 D. It requires the user to log in again.

💡 Difficulty: medium | ✅ Correct: A

📖 Explanation:

Context switching involves flushing caches, saving registers to the PCB, and loading new ones. This is pure overhead. Efficient OS structures aim to minimize unnecessary context switches.

Q37. In a microkernel, where does the 'File System' typically reside?

🔹 A. In the kernel core.
🔹 B. In user space as a server process.
🔹 C. In the BIOS.
🔹 D. In the hardware controller.

💡 Difficulty: medium | ✅ Correct: B

📖 Explanation:

To keep the microkernel small, non-essential services like the file system are moved to user space. The kernel only provides basic IPC and memory management. The file system server communicates with the kernel and apps via messages.

Q38. What is the primary function of the 'Memory Manager' within the OS structure?

🔹 A. To track which parts of memory are currently being used and allocate/deallocate memory for processes.
🔹 B. To clean the physical memory chips.
🔹 C. To increase the speed of the CPU cache.
🔹 D. To convert AC power to DC.

💡 Difficulty: easy | ✅ Correct: A

📖 Explanation:

The memory manager maintains data structures (page tables, free lists) to map virtual addresses to physical frames, handle paging/swapping, and protect processes from accessing each other's memory.

Q39. How does the 'Layered Approach' facilitate formal verification of an operating system?

🔹 A. By allowing each layer to be proven correct independently, assuming the lower layers are correct, thus simplifying the mathematical proof of the entire system.
🔹 B. By making the code shorter.
🔹 C. By using only assembly language.
🔹 D. By eliminating the need for testing.

💡 Difficulty: hard | ✅ Correct: A

📖 Explanation:

Formal verification is extremely difficult for large systems. Layering breaks the problem down. If Layer 0 is correct, and Layer 1 is proven correct using only Layer 0's interface, then Layer 1 is correct relative to the hardware. This compositional reasoning is key.

Q40. What is a 'System Daemon' in UNIX-like systems?

🔹 C. A type of virus.
🔹 D. A hardware driver.

💡 Difficulty: easy | ✅ Correct: B

📖 Explanation:

Daemons like `syslogd` or `httpd` run in the background. They are standard user processes but are structured to detach from the controlling terminal and run continuously, providing essential OS-adjacent services.

Q41. Why is the 'Network Stack' often implemented as a set of layered protocols (TCP/IP) within the OS?

🔹 A. To allow different applications to use the same network hardware without interfering with each other, and to modularize handling of addressing, routing, and reliability.

🔹 C. To prevent the OS from using Wi-Fi.
🔹 D. To reduce the size of the network card.

💡 Difficulty: medium | ✅ Correct: A

📖 Explanation:

The network stack mirrors the OSI/TCP-IP model. Each layer (Link, IP, TCP, Socket) adds specific functionality. This structure allows swapping components (e.g., Ethernet for Wi-Fi at the link layer) without breaking the upper layers.

Q42. What is the main structural difference between 'Batch Systems' and 'Time-Sharing Systems'?

📖 Explanation:

Structure-wise, time-sharing requires a sophisticated scheduler and memory protection to isolate concurrent interactive users. Batch systems are simpler, focusing on throughput and job sequencing without immediate feedback.

Q43. In the Windows NT architecture, what is the 'Executive'?

Windows NT uses a modified microkernel. The 'Kernel' handles low-level tasks (threading, interrupts). The 'Executive' runs in kernel mode but provides higher-level services (I/O, Security, PnP). This split allows some modularity within kernel mode.

Q44. Why is 'Protection' considered a structural requirement rather than just a feature?

📖 Explanation:

Protection is built into the structure via dual-mode operation, memory segmentation/paging, and access control lists. It is not an add-on; it is intrinsic to the design of any modern multi-tasking OS to ensure isolation.

Q45. What is the role of the 'Device Driver' in the OS structure?

🔹 A. To act as a translator between the generic I/O subsystem commands and the specific hardware commands of a device.

📖 Explanation:

Drivers abstract hardware differences. The OS calls `read()` on a generic interface. The driver translates this into specific register writes for a specific SCSI or USB controller. This allows the OS to support new hardware without rewriting the core I/O code.

Q46. Which structural component is responsible for 'Deadlock Detection'?

🔹 D. The Network Stack.

📖 Explanation:

Deadlocks occur when processes hold resources while waiting for others. The OS structure must include mechanisms (graphs, timers) in the resource allocation subsystem to detect or prevent these circular waits.

Q47. Why do modern OSs use 'Asynchronous I/O' structures?

🔹 A. To allow a process to initiate an I/O operation and continue executing other tasks while the I/O completes in the background, improving CPU utilization.
🔹 B. To make the disk spin slower.
🔹 C. To prevent the use of buffers.
🔹 D. To force the CPU to wait for every byte.

💡 Difficulty: medium | ✅ Correct: A

📖 Explanation:

Synchronous I/O blocks the process. Asynchronous I/O requires the OS to maintain state (callbacks, completion queues) to notify the process later. This structural complexity yields better performance for high-latency devices.

Q48. What is the significance of the 'Init' process (PID 1) in UNIX-like OS structures?

💡 Difficulty: medium | ✅ Correct: A

📖 Explanation:

Init is the ancestor of all user processes. Its structural role is crucial for system startup and shutdown. If a child process dies, Init adopts it to ensure its resources are cleaned up, preventing resource leaks.

Q49. How does 'Virtualization' change the traditional OS structure?

🔹 A. It introduces a Hypervisor layer between the hardware and the OS, allowing multiple OS instances to share physical resources while believing they have exclusive access.

Virtualization adds a layer of indirection. The Hypervisor traps privileged instructions from Guest OSs and emulates hardware. This changes the OS structure by requiring paravirtualized drivers or hardware-assisted virtualization extensions.

Q50. What is the primary purpose of the 'Boot Loader'?

The BIOS/UEFI performs hardware checks. The Boot Loader (GRUB, NTLDR) then finds the OS kernel on disk, loads it into RAM, sets up initial parameters, and jumps to the kernel's entry point.

Q51. In a 'Microkernel', why is 'Message Passing' critical?

🔹 A. Because all services (drivers, FS) are in user space, they must communicate with each other and the kernel through structured messages, as they cannot share memory or call functions directly.

🔹 C. Because it uses less CPU.
🔹 D. Because it is required by law.

💡 Difficulty: hard | ✅ Correct: A

📖 Explanation:

Isolation is the goal of microkernels. Since services are in separate address spaces, they cannot use global variables or direct pointers. Message passing is the only safe way to exchange data and requests, enforcing strict boundaries.

Q52. What is the main advantage of the 'Module-Based' structure in Linux?
