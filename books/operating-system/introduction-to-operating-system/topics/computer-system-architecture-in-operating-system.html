What is Computer System Architecture in Operating System?

Definition:
Architecture encompasses the instruction set design and hardware-software interface visible to programmers, defining operations like \( ADD \ R1, \ R2, \ R3 \) that the OS must manage during context switches.

Example:
x86-64 architecture providing specific privilege levels (rings 0-3) that enforce separation between kernel mode and user mode to prevent unauthorized hardware access.

Reason:
The OS relies on architectural features like memory management units and protection rings to implement security, virtualization, and multitasking safely and efficiently at the hardware level.

Q1. What fundamentally distinguishes a clustered system from a tightly coupled multiprocessor system?

A.Clustered systems consist of loosely coupled nodes connected via a network, each with its own OS instance and memory. ✅
B.Clustered systems share a single unified memory address space across all nodes.
C.Clustered systems use a single monolithic kernel for all nodes.
D.Clustered systems cannot scale beyond four nodes.
💡 Difficulty: easy | ✅ Correct: A

📖 Explanation: Clusters are collections of independent computers (nodes) linked by LAN/WAN. They communicate via message passing, unlike SMP which shares memory and buses. Each node runs its own OS.

Q2. Why is high availability (HA) a primary motivation for deploying clustered systems?

A.To increase the raw computational speed of single-threaded applications.
B.To provide redundancy so that if one node fails, others can take over services with minimal downtime. ✅
C.To reduce the cost of hardware components.
D.To simplify software development by distributing code.
💡 Difficulty: easy | ✅ Correct: B

📖 Explanation: HA clusters monitor node health. Upon failure, resources (IPs, storage, apps) migrate to surviving nodes. This ensures continuous service availability, distinct from pure performance scaling.

Q3. In a cluster environment, what role does a distributed lock manager (DLM) play?

A.It manages keyboard input across multiple terminals.
B.It coordinates access to shared storage or resources across nodes to prevent data corruption in concurrent access scenarios. ✅
C.It encrypts network traffic between nodes.
D.It balances the electrical load across the cluster power supply.
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: Since nodes don't share memory, they can't use standard mutexes. DLM provides a network-based locking protocol to serialize access to shared disks/files, ensuring consistency in shared-storage clusters.

Q4. How does 'single-system image' (SSI) differ from standard clustering?

A.SSI makes the cluster appear as one unified computer to users/apps, hiding node boundaries; standard clusters expose individual nodes. ✅

C.SSI is only possible on mainframes; standard clusters use PCs.
D.SSI eliminates the need for networking between nodes.
💡 Difficulty: hard | ✅ Correct: A

📖 Explanation: SSI abstracts the underlying topology. Processes, files, and devices look global. Standard clusters require apps to be cluster-aware or use middleware to distribute work explicitly.

Q5. What is the primary communication overhead difference between shared-memory multiprocessors and message-passing clusters?

A.Message passing involves explicit data copying and network serialization, whereas shared memory allows implicit communication via load/store instructions. ✅

D.Message passing is always faster than shared memory.
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: In clusters, data must be packaged, sent over network stack, received, and unpacked. In SMP, writing to a shared variable is a simple store instruction (though cache coherence adds hidden cost). Explicit messaging is generally higher latency.

Q6. Why is 'quorum' essential in preventing split-brain scenarios in storage clusters?

B.It counts the number of active users logged in.

D.It allocates IP addresses dynamically.
💡 Difficulty: hard | ✅ Correct: A

📖 Explanation: If a network partition occurs, two subsets of nodes might both try to write to shared disk, corrupting data. Quorum rules dictate that only the subset with >50% membership (or configured quorum device) stays active, fencing off the minority.

Q7. In the context of cluster load balancing, what is the trade-off between centralized and distributed dispatching?

💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: A central dispatcher has perfect global view but scales poorly and is a SPOF. Distributed dispatchers (e.g., DNS round-robin, client-side) scale well but may unevenly distribute load due to lack of real-time global knowledge.

Q8. How does 'fencing' contribute to data integrity in a high-availability cluster?

💡 Difficulty: hard | ✅ Correct: A

📖 Explanation: If a node hangs but still has bus/storage access, simply starting services elsewhere causes corruption. Fencing guarantees the rogue node is dead/unreachable before recovery proceeds, preserving data safety.

Q13. Why is 'data locality' more challenging to optimize in clusters than in SMP systems?

💡 Difficulty: hard | ✅ Correct: A

📖 Explanation: The latency gap between local and remote access is 10^3-10^6x larger in clusters. Algorithms must minimize communication or tolerate latency aggressively, whereas SMP optimizations focus on cache lines and NUMA distances.

Q16. What is the fundamental limitation of 'shared-disk' cluster architectures compared to 'shared-nothing'?

💡 Difficulty: hard | ✅ Correct: A

📖 Explanation: Every node accessing shared disk needs coordination (locking/cache coherency). This coordination overhead grows with node count. Shared-nothing partitions data, so adding nodes adds independent capacity without increasing coordination for existing data.

📖 Explanation: Local HA protects against hardware failure. Geographic diversity protects against catastrophic site events. Trade-off is increased latency and complexity in synchronous replication, but essential for true DR.

Q18. What distinguishes symmetric multiprocessing (SMP) from asymmetric multiprocessing (AMP)?

A.In SMP, all processors run identical copies of the OS and share workload dynamically; in AMP, specific tasks are assigned to specific processors. ✅
B.SMP uses separate memory for each CPU; AMP uses shared memory.
C.SMP is only used in embedded systems; AMP is used in servers.
D.AMP allows dynamic load balancing; SMP requires static assignment.
💡 Difficulty: easy | ✅ Correct: A

📖 Explanation: SMP treats all CPUs as peers capable of running any task or OS function. AMP designates a master processor for OS/scheduling and slaves for specific tasks, creating a rigid hierarchy.

Q19. Why is cache coherence a critical issue in multiprocessor systems with private caches but not in single-processor systems?

A.Because multiple processors may hold stale copies of the same memory location in their private caches, leading to inconsistent views of shared data. ✅
B.Because single processors do not use caches.
C.Because multiprocessors always use write-through caching.
D.Because cache coherence is handled entirely by the compiler.
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: In uniprocessors, there is only one cache view. In multiprocessors, if CPU A writes to X and CPU B reads X from its own cache before A's write propagates, B sees old data. Protocols like MESI are needed to maintain consistency.

Q20. In a Non-Uniform Memory Access (NUMA) architecture, what is the primary performance implication for a process accessing remote memory?

A.Access latency is uniform regardless of memory location.
B.Remote memory access is significantly slower than local memory access due to interconnect overhead. ✅
C.Remote memory access is faster due to specialized hardware accelerators.
D.Processes cannot access remote memory without OS intervention.
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: NUMA optimizes for locality. Each CPU has fast local memory. Accessing memory attached to another CPU requires traversing an interconnect, adding latency. OS schedulers must be NUMA-aware to place threads near their data.

Q21. What is the 'thundering herd' problem in multiprocessor synchronization?

A.When too many processors attempt to acquire the same lock simultaneously, causing excessive bus traffic and cache invalidations. ✅
B.When a single processor fails and others take over its load.
C.When the power supply cannot handle peak current draw.
D.When the scheduler assigns all threads to one core.
💡 Difficulty: hard | ✅ Correct: A

📖 Explanation: If thousands of threads spin-wait or wake up on the same lock, the resulting bus transactions (cache line bouncing) can saturate the interconnect, making the lock acquisition much slower than expected.

Q22. How does Amdahl's Law limit the theoretical speedup of a multiprocessor system?

A.Speedup is limited by the serial fraction of the program that cannot be parallelized. ✅
B.Speedup is limited by the total amount of RAM installed.

D.Speedup is unlimited as long as enough processors are added.
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: Even with infinite processors, the sequential portion of code dictates the minimum execution time. If 10% of a program is serial, max speedup is 10x, regardless of adding 1000 cores.

Q23. Why might an operating system use per-CPU run queues instead of a single global run queue in an SMP system?

A.To reduce lock contention on the scheduler data structure and improve cache locality for scheduled threads. ✅
B.To ensure strict global fairness among all processes.
C.To simplify the scheduler implementation.
D.To prevent processes from migrating between CPUs.
💡 Difficulty: hard | ✅ Correct: A

📖 Explanation: A global queue requires a lock acquired by every CPU for every schedule event, becoming a bottleneck. Per-CPU queues allow independent scheduling decisions, reducing contention, though they require load-balancing mechanisms to prevent imbalance.

Q24. What is the primary advantage of multicore processors over traditional multi-chip SMP systems?

A.Reduced communication latency between cores due to on-die interconnects and shared lower-level caches. ✅
B.Increased physical distance between processing units.

D.Elimination of the need for an operating system.
💡 Difficulty: easy | ✅ Correct: A

📖 Explanation: Cores on the same die share L2/L3 caches and interconnects physically located on the silicon. This makes communication orders of magnitude faster and cheaper than off-chip buses used in discrete multi-chip SMP.

Q25. In the context of multiprocessor scheduling, what is 'processor affinity' and why is it desirable?

A.The tendency of a process to prefer certain types of instructions.
B.Keeping a process on the same CPU to maximize cache hit rates and minimize migration overhead. ✅
C.Assigning high-priority processes to the fastest CPU only.
D.Binding processes to specific memory banks.
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: Migrating a process invalidates its cached state in the source CPU's private cache and populates the destination's cache (cold start). Affinity keeps processes local to preserve warm caches, improving performance.

Q26. How does the memory consistency model affect programming in multiprocessor systems?

A.It defines the order in which memory operations appear to execute, impacting how locks and atomic primitives must be implemented. ✅
B.It determines the maximum size of the address space.
C.It specifies the voltage levels for memory modules.
D.It dictates the file system format used for shared storage.
💡 Difficulty: hard | ✅ Correct: A

📖 Explanation: Weak consistency models allow reordering of loads/stores for performance. Programmers must use explicit barriers or atomics to enforce ordering. Assuming sequential consistency on weak hardware leads to subtle concurrency bugs.

Q27. What is a key challenge in scaling SMP systems beyond a certain number of processors?

A.Bus contention and memory bandwidth saturation limit further performance gains. ✅
B.The operating system kernel becomes too small to manage many CPUs.
C.Cooling requirements decrease exponentially.
D.Compiler optimization becomes impossible.
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: Traditional SMP relies on a shared bus or crossbar. As N increases, contention for shared resources (bus, memory controller) grows superlinearly, leading to diminishing returns and eventual saturation.

Q28. What is 'false sharing' in multiprocessor cache coherence?

A.When two threads on different cores modify unrelated variables that happen to reside on the same cache line, causing unnecessary invalidation traffic. ✅
B.When a thread accesses memory belonging to another process.
C.When the cache controller reports an error incorrectly.
D.When two cores share the same ALU.
💡 Difficulty: hard | ✅ Correct: A

📖 Explanation: Cache coherence operates at the cache-line granularity (e.g., 64 bytes). Modifying byte 0 invalidates the line for core holding byte 60, even if unrelated. This causes ping-pong traffic and severe performance degradation.

Q29. How does hyperthreading (SMT) differ from adding physical cores in a multiprocessor system?

A.SMT shares execution resources and caches between logical processors, offering less than linear performance gain; physical cores have dedicated resources. ✅
B.SMT doubles the clock speed; physical cores do not.
C.SMT eliminates the need for an OS scheduler.
D.Physical cores cannot run multiple threads.
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: SMT fills pipeline bubbles by interleaving instructions from two threads. It improves throughput but doesn't double compute capacity since functional units are shared. Physical cores add full independent capacity.

Q30. In an SMP system, why is atomic test-and-set or compare-and-swap instruction necessary?

A.To implement spinlocks and synchronization primitives safely without race conditions on the lock variable itself. ✅
B.To perform floating-point addition.
C.To read data from the hard drive atomically.
D.To switch between user and kernel mode.
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: Without hardware atomicity, checking and setting a lock is two separate steps. Another CPU could interleave between check and set, leading to both thinking they acquired the lock. Atomic instructions guarantee indivisibility.

Q31. What is the scalability advantage of message-passing multicomputers over shared-memory multiprocessors for very large systems?

A.Message-passing scales better because it avoids the global bottleneck of cache coherence and shared memory bandwidth. ✅
B.Message-passing is easier to program.
C.Shared memory cannot exceed 4 CPUs.
D.Message-passing systems do not require an operating system.
💡 Difficulty: hard | ✅ Correct: A

📖 Explanation: Coherence traffic grows quadratically or worse with core count. Message-passing only communicates when explicitly programmed, avoiding implicit global state synchronization, enabling scaling to millions of cores (e.g., supercomputers).

Q32. Why might an OS disable interrupts on a specific CPU in an SMP system during critical section entry?

A.To prevent preemption on that CPU while holding a spinlock, avoiding deadlock if the interrupt handler tries to acquire the same lock. ✅
B.To save power on that CPU.
C.To force other CPUs to stop executing.
D.To reset the local APIC timer.
💡 Difficulty: hard | ✅ Correct: A

📖 Explanation: If CPU holds a spinlock and gets interrupted, and the ISR tries to grab the same lock, it will spin forever (deadlock) since the interrupted thread can't release it. Disabling interrupts locally prevents this scenario.

Q33. What is the primary reason for using a crossbar switch instead of a bus in high-end multiprocessors?

A.Crossbars provide non-blocking, simultaneous point-to-point connections between multiple CPUs and memory banks, eliminating bus contention. ✅
B.Crossbars are cheaper to manufacture.
C.Crossbars use less power than buses.
D.Crossbars simplify cache coherence protocols.
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: Buses are broadcast/shared media. Crossbars allow N inputs to connect to M outputs simultaneously (if no output conflict), providing bandwidth proportional to N*M, essential for scaling beyond ~8-16 processors.

Q34. What is the 'fork-join' parallelism model's primary synchronization point in multiprocessor execution?

A.The join barrier where the parent thread waits for all spawned child threads to complete before proceeding. ✅
B.The fork system call creation point.
C.The memory allocation routine.
D.The context switch boundary.
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: Fork spawns parallel tasks. Join is the convergence point. Correctness depends on all children finishing. Efficient join implementation (barriers, counters) is critical to avoid serializing the parallel phase unnecessarily.

Q35. Why do modern multiprocessor OS kernels use Read-Copy-Update (RCU) instead of reader-writer locks for frequently read data?

A.RCU allows readers to proceed without locks or atomic ops, eliminating contention on hot paths; writers defer reclamation until grace periods elapse. ✅
B.RCU is simpler to implement than rwlocks.
C.Readers are rare in OS kernels.
D.RCU prevents writers from ever updating data.
💡 Difficulty: hard | ✅ Correct: A

📖 Explanation: Reader-writer locks still require atomic updates to reader counts, causing cache line bouncing. RCU makes reads completely wait-free and cache-friendly, ideal for routing tables/process lists where reads vastly outnumber writes.

Q36. In a single-processor system, how does the operating system achieve the illusion of concurrent execution for multiple processes?

💡 Difficulty: easy | ✅ Correct: B

📖 Explanation: Single-processor systems have only one execution unit. Concurrency is simulated by saving and restoring process states (context switching) fast enough that users perceive simultaneous execution.

Q37. What is the primary bottleneck in a single-processor system when running I/O-bound and CPU-bound processes concurrently?

Q38. Why is interrupt handling particularly critical in single-processor architectures compared to multiprocessor ones?

💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: In a uniprocessor system, the sole CPU must service all interrupts. If it is busy with a long computation without preemption, system responsiveness degrades significantly compared to systems where another core can handle interrupts.

Q39. Which scheduling challenge is unique to single-processor systems that does not exist in true parallel systems?

💡 Difficulty: medium | ✅ Correct: C

📖 Explanation: True parallelism is impossible on a single processor. Scheduling must focus entirely on fair time-slicing and minimizing context-switch overhead, whereas multiprocessors must also manage spatial distribution of work.

Q40. How does the presence of a single shared bus in many legacy single-processor systems affect scalability?

Q41. In the context of single-processor protection, why is the distinction between user mode and kernel mode enforced by hardware rather than software?

Q42. What role does the timer interrupt play specifically in maintaining fairness in a single-processor time-sharing system?

📖 Explanation: Without a timer, a cooperative multitasking system relies on processes yielding. A timer enables preemptive multitasking, ensuring that even non-cooperative or buggy processes cannot starve others on the single CPU.

Q43. Why might a single-processor system use Direct Memory Access (DMA) despite having only one CPU?

💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: Even with one CPU, DMA is crucial for efficiency. It offloads byte-by-byte copying from the CPU, allowing overlap of computation and I/O, which maximizes the utilization of the single processing unit.

Q44. Which of the following best describes the 'von Neumann bottleneck' in single-processor architecture?

D.The maximum clock speed achievable by silicon.
💡 Difficulty: hard | ✅ Correct: A

📖 Explanation: The von Neumann architecture uses a single bus/pathway for both instructions and data. The CPU is often stalled waiting for memory because it cannot fetch an instruction and read/write data simultaneously through the same channel.

Q45. How does context switching overhead impact the effective throughput of a single-processor system as the number of processes increases?

💡 Difficulty: medium | ✅ Correct: C

📖 Explanation: Each switch consumes CPU cycles saving/restoring state. As processes increase, switches become more frequent. Beyond a saturation point, the CPU spends more time managing processes than running them, reducing useful work.

Q46. Which factor most directly limits the maximum number of processes a single-processor system can effectively support?

📖 Explanation: While memory limits absolute count, effectiveness is bound by scheduling overhead. If switching takes 1ms and quantum is 10ms, supporting 1000 runnable processes means most time is wasted switching, not computing.

Q47. In a single-processor system with virtual memory, what happens during a page fault that differs from a multiprocessor system?

Q48. Why were early single-processor systems often batch-oriented rather than interactive?

📖 Explanation: In uniprocessor, the scheduler runs frequently on the only CPU. Complex queue ops waste cycles. In MP, per-CPU queues or lock-free structures mitigate this. Single queue contention is the dominant factor in UP scheduling overhead.
