📝 Introduction to Memory Management in Operating Systems (21 MCQs)

Definition:

Memory management is the operating system function that tracks, allocates, protects, and releases main memory for executing processes. It distinguishes controlled memory allocation from unrestricted address access. Without memory management, one process could overwrite another process's instructions or data, resulting in corruption and unpredictable execution.

Working:

The operating system tracks available and occupied memory regions. When a process starts, it arranges suitable memory allocation and establishes address translations where required. Hardware memory-management support helps enforce access permissions. When a process terminates, its allocated memory is released for reuse by other processes.

Example:

Suppose a system has 1,024 MB of available memory. Process A receives 256 MB, and Process B receives 384 MB. The remaining available memory is 1024−256−384=3841024 - 256 - 384 = 3841024−256−384=384 MB. When A terminates, its 256 MB becomes available again.

Reason:

Memory management provides protection and efficient allocation compared with allowing applications to select arbitrary physical addresses. Unrestricted allocation can cause overlapping memory usage and corruption. Virtual memory also allows processes to use address spaces independently of available physical memory, subject to system limits.

Common Misconceptions:

'Virtual memory is always faster than RAM.' Correction: Accessing secondary storage is generally slower. 'Memory allocation permanently reserves memory.' Correction: Allocations are released when appropriate. 'Every process shares identical addresses.' Correction: Processes can have separate virtual address spaces.

Exam Preparation Tips: How to prepare this topic

Practice memory-allocation calculations and address translation problems. Understand physical and virtual addresses, paging, segmentation, and protection. Explain what happens when a process terminates. Exams commonly test fragmentation, allocation methods, and virtual memory concepts.

Key Terms:

  • Physical Memory - Actual main memory installed in a computer.
  • Virtual Memory - An abstraction providing processes with virtual address spaces.
  • Paging - Dividing memory into fixed-size blocks.
  • Fragmentation - Memory wastage caused by allocation patterns.

📝 All Introduction to Memory Management in Operating Systems MCQs

Q1. An operating system is running three processes that require 120 MB, 180 MB, and 200 MB of memory. The system has 600 MB of available memory. How much memory remains after all three processes are loaded?

A.80 MB
B.100 MB ✅
C.120 MB
D.140 MB
💡 Difficulty: easy | ✅ Correct: B

📖 Explanation: The processes require 120+180+200=500120 + 180 + 200 = 500120+180+200=500 MB. Subtracting this from the available 600 MB leaves 100 MB. Choosing 120 MB may result from incorrectly adding the allocation sizes. This tests basic memory allocation and capacity calculation. Always calculate total demand before subtracting from available memory.

Q2. A computer has 8 GB of RAM, of which 2 GB is reserved for the operating system and hardware. If applications currently use 3.5 GB, how much memory remains available for additional applications?

A.2 GB
B.2.5 GB ✅
C.3 GB
D.3.5 GB
💡 Difficulty: easy | ✅ Correct: B

📖 Explanation: Usable memory is 8−2=68 - 2 = 68−2=6 GB because the operating system and hardware reserve 2 GB. Applications consume 3.5 GB, leaving 6−3.5=2.56 - 3.5 = 2.56−3.5=2.5 GB. The common mistake is subtracting application usage directly from total RAM. Always exclude reserved memory first.

Q3. A programmer observes that a process uses virtual addresses starting at 0 while its physical memory begins at address 8000. What mechanism allows the operating system to translate the process addresses into physical addresses?

A.Address binding ✅
B.Process scheduling
C.Disk scheduling
D.Interrupt handling
💡 Difficulty: easy | ✅ Correct: A

📖 Explanation: Address binding establishes the relationship between a program's logical addresses and physical memory locations. The memory management unit can perform this translation during execution. Process scheduling determines CPU allocation, not address translation. Remember that address binding may occur at compile time, load time, or execution time.

Q4. A system uses a contiguous memory allocation scheme with a base register of 4000 and a limit register of 1200. A process generates logical address 850. What physical address is produced?

A.850
B.3150
C.4850 ✅
D.5200
💡 Difficulty: medium | ✅ Correct: C

📖 Explanation: The logical address 850 is within the process limit of 1200, so translation is valid. The physical address is 4000+850=48504000 + 850 = 48504000+850=4850. Selecting 850 confuses logical and physical addresses. This tests base-and-limit address translation. Add the base register value only after verifying that the logical address is within the limit.

Q5. A process has a base register of 6000 and a limit register of 1000. During execution, it generates logical address 1100. What should the memory management hardware do?

A.Translate it to physical address 7100
B.Translate it to physical address 6000
C.Allow access because the base is valid
D.Generate an address protection exception ✅
💡 Difficulty: medium | ✅ Correct: D

📖 Explanation: The limit register permits logical addresses from 0 through 999. Since 1100 exceeds the process limit, the access must be rejected, generating a protection exception. Adding the base to produce 7100 would incorrectly permit an out-of-range access. Always check the limit before performing address translation.

Q6. A computer uses fixed partition memory allocation. Four partitions have sizes of 100 MB, 200 MB, 300 MB, and 400 MB. A process requiring 180 MB is assigned to the 200 MB partition. How much internal fragmentation results?

A.10 MB
B.20 MB ✅
C.80 MB
D.180 MB
💡 Difficulty: easy | ✅ Correct: B

📖 Explanation: Internal fragmentation is the unused space inside an allocated partition. The process occupies 180 MB of a 200 MB partition, leaving 200−180=20200 - 180 = 20200−180=20 MB unused. The 80 MB option confuses the difference with another partition size. For fixed partitions, subtract process size from allocated partition size.

Q7. A system has 500 MB of free memory distributed across several non-contiguous holes. A process requests 350 MB, but the largest available hole is only 300 MB. What prevents the allocation under contiguous memory allocation?

A.Internal fragmentation
B.Memory protection
C.External fragmentation ✅
D.Address binding
💡 Difficulty: medium | ✅ Correct: C

📖 Explanation: The total free memory is 500 MB, but no single contiguous hole can accommodate the 350 MB request. This is external fragmentation because free memory is divided into separate blocks. Internal fragmentation occurs inside allocated partitions. When evaluating allocation failures, compare the request with the largest contiguous free block, not just total free memory.

Q8. A process requires 240 MB of memory. The operating system uses variable-sized partitions and selects the smallest available hole that can accommodate the process. Available holes are 100 MB, 260 MB, 400 MB, and 300 MB. Which hole will be selected?

A.260 MB ✅
B.300 MB
C.400 MB
D.100 MB
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: Best-fit allocation selects the smallest hole large enough for the request. The 100 MB hole is insufficient, while 260 MB is the smallest suitable block. Choosing 300 MB reflects a larger-fit decision. This tests contiguous memory allocation strategies. Sort suitable holes by size and select the smallest one that satisfies the request.

Q9. A memory manager uses first-fit allocation. Free holes appear in this order: 120 MB, 350 MB, 200 MB, and 500 MB. A process requests 180 MB. Which hole receives the process?

A.120 MB
B.350 MB ✅
C.200 MB
D.500 MB
💡 Difficulty: easy | ✅ Correct: B

📖 Explanation: First-fit scans memory from the beginning and selects the first hole large enough for the process. The 120 MB hole is too small, so the 350 MB hole is selected immediately. Choosing 200 MB would correspond to a later suitable hole. Remember that first-fit depends on search order, not smallest block size.

Q10. A system has free memory blocks of 150 MB, 450 MB, 250 MB, and 350 MB. Using worst-fit allocation, a process requesting 200 MB is assigned to which block?

A.150 MB
B.250 MB
C.350 MB
D.450 MB ✅
💡 Difficulty: easy | ✅ Correct: D

📖 Explanation: Worst-fit selects the largest available hole that can satisfy the request. Among the suitable blocks, 450 MB is the largest. Selecting 250 MB would resemble best-fit, while 150 MB cannot accommodate the process. For allocation strategy questions, identify whether the algorithm prefers the first, smallest, or largest suitable hole.

Q11. A system uses dynamic relocation with a relocation register containing 12,000. A process generates logical address 2,500. Assuming the address is valid, what physical address is accessed?

A.9500
B.12000
C.14000
D.14500 ✅
💡 Difficulty: medium | ✅ Correct: D

📖 Explanation: Dynamic relocation adds the relocation register value to the logical address. Therefore, the physical address is 12,000+2,500=14,50012,000 + 2,500 = 14,50012,000+2,500=14,500. The 14,000 option results from an arithmetic error. This tests run-time address relocation. Remember that relocation translates an address by adding the process's starting physical location.

Q12. An operating system moves a process from one physical memory region to another while the process continues to use the same logical addresses. What feature makes this possible?

A.Dynamic relocation ✅
B.Static linking
C.Disk partitioning
D.CPU time slicing
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: Dynamic relocation allows logical addresses to be translated into physical addresses during execution. Consequently, the operating system can change a process's physical location without modifying its logical address references. Static linking combines program components, while time slicing controls CPU sharing. Remember that execution-time address translation supports flexible process movement.

Q13. A computer has 16 GB of RAM. The operating system reserves 3 GB, and the remaining memory is divided into four equal fixed partitions. What is the size of each partition?

A.2.75 GB
B.3 GB
C.3.25 GB ✅
D.4 GB
💡 Difficulty: medium | ✅ Correct: C

📖 Explanation: Memory available for partitions is 16−3=1316 - 3 = 1316−3=13 GB. Dividing this equally among four partitions gives 13/4=3.2513 / 4 = 3.2513/4=3.25 GB per partition. Choosing 4 GB incorrectly divides total RAM without excluding the operating system reservation. Calculate usable memory before dividing it into partitions.

Q14. A memory allocation system has four free holes of 100 MB, 250 MB, 400 MB, and 600 MB. Three processes request 90 MB, 230 MB, and 380 MB in that order. Using first-fit allocation and scanning from the beginning each time, how much total free memory remains after allocation?

A.550 MB
B.620 MB
C.650 MB ✅
D.700 MB
💡 Difficulty: hard | ✅ Correct: C

📖 Explanation: First-fit allocates 90 MB from 100 MB, leaving 10 MB; 230 MB from 250 MB, leaving 20 MB; and 380 MB from 400 MB, leaving 20 MB. Including the untouched 600 MB hole gives 10+20+20+600=65010 + 20 + 20 + 600 = 65010+20+20+600=650 MB. A common error is subtracting requests without accounting for the original holes. Track each hole after every allocation.

Q15. A computer uses a memory management scheme in which each process receives its own logical address space. Process P generates logical address 500, and process Q also generates logical address 500. Why can both processes use this address safely?

A.Both processes must occupy identical physical locations
B.The operating system disables memory protection
C.Each process has an independent address translation context ✅
D.Logical addresses are automatically stored on disk
💡 Difficulty: medium | ✅ Correct: C

📖 Explanation: Each process has its own address space and address translation context, allowing the same logical address to map to different physical locations. Identical logical addresses do not imply identical physical addresses. This tests process isolation and address translation. Remember that separate address spaces support protection and prevent unintended interference between processes.

Q16. A program is compiled with absolute physical memory addresses. The operating system later attempts to load it at a different memory location without modifying its address references. What is the likely result?

A.The program automatically relocates itself
B.The program may access incorrect physical locations ✅
C.The program eliminates external fragmentation
D.The program receives a larger logical address space
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: Absolute addresses refer to specific physical locations established during compilation. Loading the program elsewhere without adjusting those references can cause incorrect memory accesses. Automatic relocation requires appropriate relocation information or hardware support. This tests address binding. Remember that absolute addressing restricts where a program can be loaded unless relocation is performed.

Q17. A system uses a 32-bit logical address space and byte-addressable memory. What is the maximum number of distinct logical byte addresses available to a process?

A.2 GB
B.1 GB
C.4 GB ✅
D.8 GB
💡 Difficulty: easy | ✅ Correct: C

📖 Explanation: A 32-bit address provides 2322^{32}232 distinct address combinations. With byte-addressable memory, each address identifies one byte, giving 4,294,967,2964,294,967,2964,294,967,296 bytes or 4 GB. The 2 GB option incorrectly assumes a 31-bit address space. For address-space questions, calculate 2n2^n2n for an n-bit address.

Q18. A process requires 700 MB of contiguous memory. The operating system has free holes of 250 MB, 200 MB, and 300 MB. After compacting memory, the operating system can combine the holes. Assuming no memory is occupied by other processes during compaction, what is the result?

A.The request still fails because no original hole was large enough
B.The request succeeds with 50 MB remaining free ✅
C.The request succeeds with 100 MB remaining free
D.The request fails because compaction creates internal fragmentation
💡 Difficulty: hard | ✅ Correct: B

📖 Explanation: Compaction combines the three free regions into 250+200+300=750250 + 200 + 300 = 750250+200+300=750 MB of contiguous memory. Allocating 700 MB leaves 50 MB free. The original largest hole was only 300 MB, but compaction removes the separation between holes. This tests external fragmentation and compaction. Compare total reclaimable free space with the request after consolidation.

Q19. A memory manager uses variable-sized partitions. Initially, free memory consists of one 1,000 MB block. It allocates 300 MB, 250 MB, and 200 MB to three processes consecutively from the beginning of the block. How much contiguous free memory remains at the end?

A.150 MB
B.200 MB
C.250 MB ✅
D.300 MB
💡 Difficulty: hard | ✅ Correct: C

📖 Explanation: The allocations consume 300+250+200=750300 + 250 + 200 = 750300+250+200=750 MB from the original 1,000 MB block. The remaining contiguous region is 1,000−750=2501,000 - 750 = 2501,000−750=250 MB. Selecting 300 MB may result from overlooking one allocation. This tests sequential variable-partition allocation. Maintain a running total of allocated memory to avoid arithmetic mistakes.

Q20. A process is allocated a memory region with a base address of 20,000 and a limit of 5,000. Another process attempts to access physical address 23,000 directly without going through its own address translation mechanism. What protection principle prevents unauthorized access?

A.Memory compaction
B.Process isolation ✅
C.First-fit allocation
D.Internal fragmentation
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: Process isolation prevents one process from accessing another process's protected memory region. A process must use addresses permitted by its own address translation and protection context. First-fit and compaction concern memory allocation, not access authorization. This tests memory protection. Remember that address translation and access validation work together to isolate processes.

Q21. A system uses fixed-size partitions of 256 MB each. A process requires 190 MB, while another requires 270 MB. Assuming each process must occupy one partition, what happens?

A.Both processes fit, leaving 52 MB unused
B.Only the first process fits, leaving 66 MB unused ✅
C.Only the second process fits, leaving 14 MB unused
D.Neither process fits because partitions must be fully occupied
💡 Difficulty: hard | ✅ Correct: B

📖 Explanation: The 190 MB process fits within a 256 MB partition, leaving 256−190=66256 - 190 = 66256−190=66 MB of internal fragmentation. The 270 MB process exceeds the partition size and cannot fit. This tests fixed partition allocation and internal fragmentation. Compare every process requirement with the partition capacity before calculating unused space.
