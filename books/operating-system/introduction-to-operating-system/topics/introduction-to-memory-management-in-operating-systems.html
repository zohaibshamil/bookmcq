What is Introduction to Memory Management in Operating Systems?

Definition:
Memory management tracks allocation and deallocation of main memory, using techniques like paging where logical address \( LA \) maps to physical address \( PA \) via page tables to support virtual memory.

Example:
Demand paging loading pages only when referenced, allowing a process with 4GB virtual address space to run on a machine with only 8GB RAM by swapping inactive pages to disk.

Reason:
It provides memory abstraction and isolation between processes, prevents fragmentation, and allows execution of programs larger than physical memory through efficient secondary storage integration.

📝 All Introduction to Memory Management in Operating Systems MCQs

Q1. Why is the separation of logical and physical address spaces fundamental to modern memory management?

A.It allows the compiler to generate absolute addresses that never change.
B.It enables the operating system to relocate processes in physical memory without modifying the program code. ✅
C.It reduces the size of the instruction set required by the CPU.
D.It eliminates the need for a Memory Management Unit (MMU).
💡 Difficulty: easy | ✅ Correct: B

📖 Explanation: Logical addresses are generated by the CPU, while physical addresses refer to actual memory locations. This separation allows the OS to move processes around in physical memory (relocation) or use virtual memory techniques, as the MMU translates logical to physical addresses dynamically.

Q2. In a system using base and limit registers for memory protection, what happens if a process attempts to access an address outside its limit?

A.The hardware automatically expands the limit register to accommodate the access.
B.The access is granted but logged for later review by the administrator.
C.A trap occurs, transferring control to the operating system to handle the violation. ✅
D.The operating system silently ignores the request and returns a null value.
💡 Difficulty: easy | ✅ Correct: C

📖 Explanation: Base and limit registers define the legal range of physical addresses for a process. Any attempt to access an address less than the base or greater than the base + limit results in a hardware trap, allowing the OS to terminate the offending process or handle the error.

Q3. What is the primary disadvantage of static binding (compile-time or load-time) compared to dynamic run-time binding?

A.It requires more complex hardware support.
B.It prevents the process from being moved in memory after execution begins. ✅
C.It significantly increases the context-switching overhead.
D.It makes it impossible to share code segments between processes.
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: Static binding fixes the physical address at compile or load time. If the process needs to be swapped out and back in, or if memory compaction is performed, the process cannot be relocated because its instructions contain hardcoded physical addresses. Dynamic binding via an MMU allows relocation at runtime.

Q4. How does the concept of 'locality of reference' justify the effectiveness of caching and paging?

A.Programs tend to access the same set of pages repeatedly over a short period. ✅
B.Hardware caches are large enough to hold entire programs.
C.Operating systems prefetch all data from disk before execution begins.
D.Random access patterns are more common than sequential ones in most applications.
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: Locality of reference (temporal and spatial) implies that if a page is accessed, it is likely to be accessed again soon (temporal) or nearby pages will be accessed (spatial). This behavior ensures that keeping a subset of pages in fast memory (cache/RAM) yields a high hit rate, making hierarchical memory structures efficient.

Q5. Why do page sizes in modern architectures tend to be powers of 2?

A.It simplifies the calculation of page numbers and offsets using bit masking and shifting rather than division and modulo. ✅
B.It aligns with the physical geometry of magnetic disk platters.
C.It reduces the internal fragmentation inherent in fixed-size allocation.
D.It allows the operating system to use variable-length page tables efficiently.
💡 Difficulty: easy | ✅ Correct: A

📖 Explanation: If page size is $2^n$, the lower $n$ bits of the logical address represent the offset, and the upper bits represent the page number. This allows the hardware to extract these fields using simple bitwise operations, which are much faster than arithmetic division.

Q6. In a paging system, what is the specific role of the Translation Look-aside Buffer (TLB)?

A.To store the entire page table for quick access.
B.To cache recent virtual-to-physical address translations. ✅
C.To manage the free frame list for page replacement.
D.To encrypt the data stored in memory pages.
💡 Difficulty: easy | ✅ Correct: B

📖 Explanation: Accessing the page table in main memory for every memory reference would double the memory access time. The TLB is a small, fast associative memory that caches recently used page table entries, allowing the hardware to bypass the page table lookup for frequent accesses.

Q7. What is the consequence of a TLB miss when the page is actually present in physical memory?

A.A page fault occurs, requiring disk I/O.
B.The CPU halts until the TLB is manually refreshed by the user.
C.The hardware must access the page table in main memory to retrieve the frame number. ✅
D.The operating system swaps out another process to free up TLB space.
💡 Difficulty: medium | ✅ Correct: C

📖 Explanation: A TLB miss means the translation is not in the cache. However, if the valid bit in the page table indicates the page is in memory, the hardware (or OS) walks the page table to find the frame number, updates the TLB, and resumes execution. No disk I/O is required unless the page itself is missing (a page fault).

Q8. Why is inverted paging often preferred over conventional paging for systems with very large virtual address spaces (e.g., 64-bit)?

A.It eliminates the need for a page table entirely.
B.It reduces the physical memory required to store page tables by having one entry per physical frame rather than per virtual page. ✅
C.It allows multiple processes to share the same virtual address space without isolation.
D.It speeds up context switching by avoiding TLB flushes.
💡 Difficulty: hard | ✅ Correct: B

📖 Explanation: In a 64-bit system, a conventional page table would be astronomically large because it has an entry for every possible virtual page. An inverted page table has only one entry for each physical frame, significantly reducing the memory overhead for storing mapping structures, though it complicates address translation.

Q9. In the context of address translation, what is the function of the 'valid-invalid' bit in a page table entry?

A.It indicates whether the page has been modified since it was loaded.
B.It distinguishes between pages that are currently in physical memory and those that are not. ✅
C.It specifies the protection level (read/write/execute) for the page.
D.It marks the page as shared among multiple processes.
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: The valid-invalid bit tells the MMU if the page described by this entry is currently resident in a physical frame. If invalid, accessing this page triggers a page fault, prompting the OS to bring the page into memory. If valid, the translation proceeds.

Q10. How does copy-on-write (COW) optimize the fork() system call in UNIX-like systems?

A.It immediately copies all parent pages to new physical frames for the child.
B.It delays physical copying of pages until either process attempts to modify a shared page. ✅
C.It shares all pages permanently between parent and child to save memory.
D.It compresses the memory pages to reduce the amount of data copied.
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: Fork() creates a child process that is initially identical to the parent. Instead of copying all pages immediately (which is expensive), COW maps both processes to the same physical pages marked as read-only. Only when a write occurs does the OS allocate a new frame and copy the data, ensuring efficiency when the child immediately execs a new program.

Q11. What is the primary cause of internal fragmentation in a paging system?

A.Allocating memory in fixed-size blocks when the process's memory requirement is not an exact multiple of the page size. ✅
B.Leaving gaps between allocated partitions due to varying process sizes.
C.Using a page size that is too small for the application's data structures.
D.Mapping multiple virtual pages to the same physical frame.
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: Paging divides memory into fixed-size frames. If a process needs 10.5 KB and the page size is 4 KB, it gets 3 pages (12 KB). The remaining 1.5 KB in the last page is unused and cannot be allocated to another process, resulting in internal fragmentation.

Q12. Why might an operating system support multiple page sizes (e.g., 4KB and 4MB)?

A.To allow users to choose their preferred memory granularity.
B.To reduce TLB misses for large data segments while maintaining fine-grained allocation for small objects. ✅
C.To simplify the hardware design of the Memory Management Unit.
D.To ensure compatibility with older 16-bit applications.
💡 Difficulty: hard | ✅ Correct: B

📖 Explanation: Large pages (huge pages) cover more memory with a single TLB entry, reducing TLB misses for large contiguous arrays or code segments. Small pages allow finer-grained memory management and less waste for small allocations. Supporting both allows the OS to optimize for different workload characteristics.

Q13. In a system using segmentation, how is a logical address structured?

A.As a single linear offset from the start of memory.
B.As a pair consisting of a segment selector and an offset within that segment. ✅
C.As a page number and a page offset.
D.As a base register value and a limit register value.
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: Segmentation reflects the programmer's view of memory (code, stack, heap, etc.). A logical address is therefore a tuple <segment-number, offset>. The segment number indexes the segment table to find the base address, and the offset is added to the base to get the physical address.

Q14. What is a key advantage of segmentation over pure paging regarding protection and sharing?

A.It allows different permissions (e.g., read-only for code, read-write for data) to be applied naturally to logical units. ✅
B.It eliminates external fragmentation completely.
C.It requires less hardware support for address translation.
D.It ensures that all segments are of equal size, simplifying allocation.
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: Segments correspond to logical entities like functions or data structures. It is natural to assign specific protection bits (read, write, execute) to an entire segment. In paging, a single page might contain mixed code and data, making fine-grained logical protection harder to enforce without complex software management.

Q15. Why is compaction generally not possible in systems that use static relocation (binding at load time)?

A.Because the hardware does not support base registers.
B.Because moving a process would invalidate all absolute physical addresses embedded in its instructions. ✅
C.Because compaction requires too much CPU time.
D.Because the operating system cannot track free holes accurately.
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: If addresses are bound at load time, the machine code contains specific physical addresses. If the OS moves the process to a different location in memory during compaction, those hardcoded addresses become incorrect. Dynamic relocation via an MMU is required to update address translations on the fly during movement.

Q16. In a demand-paging system, what defines a 'pure' demand paging approach?

A.Pages are loaded into memory only when they are referenced for the first time. ✅
B.All pages of a process are loaded into memory before execution begins.
C.Pages are pre-loaded based on a prediction algorithm before they are needed.
D.The operating system swaps entire processes in and out of memory.
💡 Difficulty: easy | ✅ Correct: A

📖 Explanation: Pure demand paging brings no pages into memory until they are actually demanded by a memory reference. This minimizes initial I/O and memory usage but can lead to a high number of page faults at the start of execution.

Q17. What is the 'working set' of a process?

A.The total number of pages allocated to the process by the operating system.
B.The set of pages that a process has referenced in the past $\Delta$ time units. ✅
C.The set of pages currently residing in the TLB.
D.The maximum number of pages the process can ever use.
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: The working set model assumes that processes execute in localities. The working set is the collection of pages actively used by the process within a recent time window. Keeping the working set in physical memory minimizes page faults; if the working set exceeds available frames, thrashing occurs.

Q18. Why does the Least Recently Used (LRU) page replacement algorithm suffer from high implementation overhead?

A.It requires maintaining a timestamp or stack order for every memory reference. ✅
B.It frequently causes Belady's anomaly.
C.It requires looking ahead into the future reference string.
D.It performs poorly on random reference patterns.
💡 Difficulty: hard | ✅ Correct: A

📖 Explanation: True LRU requires knowing exactly which page was used least recently. Implementing this requires updating a counter or moving a page to the top of a stack on *every* memory access. This hardware/software overhead is significant, leading to approximations like the Clock algorithm.

Q19. What is Belady's Anomaly, and which algorithm exhibits it?

A.An increase in page faults when more frames are allocated; exhibited by FIFO. ✅
B.A decrease in throughput when CPU speed increases; exhibited by LRU.
C.An increase in memory usage due to fragmentation; exhibited by Best-Fit.
D.A situation where the optimal algorithm fails; exhibited by Optimal.
💡 Difficulty: hard | ✅ Correct: A

📖 Explanation: Belady's Anomaly is the counter-intuitive result where adding more page frames leads to *more* page faults. This happens with FIFO because FIFO does not satisfy the stack property (the set of pages in memory with N frames is not a subset of pages in memory with N+1 frames). LRU and Optimal do not exhibit this.

Q20. In the Clock (Second-Chance) page replacement algorithm, what is the purpose of the 'use' bit?

A.To indicate if the page has been modified and needs to be written to disk.
B.To give a page a second chance before replacement if it was recently referenced. ✅
C.To lock the page in memory so it cannot be swapped out.
D.To mark the page as belonging to the kernel rather than a user process.
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: The Clock algorithm approximates LRU. Each page has a use bit. When the clock hand points to a page with the use bit set (1), it clears the bit to 0 and moves on (giving it a 'second chance'). If the bit is already 0, the page is selected for replacement. This prioritizes keeping recently used pages.

Q21. Why is global page replacement generally considered more efficient than local page replacement in terms of overall system throughput?

A.It allows a process with a low page-fault rate to donate frames to a process with a high page-fault rate. ✅
B.It prevents any single process from monopolizing memory.
C.It simplifies the accounting of free frames.
D.It ensures that every process gets an equal number of frames.
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: Global replacement treats all frames as a single pool. If Process A is idle or has good locality, its frames can be stolen by Process B which is actively faulting. This dynamic reallocation tends to keep the most active working sets in memory, improving overall CPU utilization compared to rigid local partitions.

Q22. What is the primary trade-off involved in increasing the page size in a virtual memory system?

A.Reduced page table size vs. increased internal fragmentation. ✅
B.Faster disk transfer rates vs. slower TLB lookups.
C.Increased external fragmentation vs. reduced internal fragmentation.
D.Simpler address translation vs. higher context-switch overhead.
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: Larger pages mean fewer entries in the page table (saving memory) and potentially better I/O throughput (transferring larger chunks). However, if a process uses only a small part of a large page, the rest of that page is wasted (internal fragmentation). Smaller pages reduce waste but increase page table size and management overhead.

Q23. How does prepaging differ from standard demand paging?

A.It loads pages into memory before they are referenced, based on predicted access patterns. ✅
B.It swaps out pages that have not been used for a long time.
C.It loads all pages of a process at startup.
D.It uses a compressed format for pages on disk.
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: Standard demand paging waits for a fault. Prepaging attempts to anticipate future references (e.g., loading the next sequential page when a page fault occurs) to reduce the latency of subsequent accesses. It trades off potential wasted I/O (if the page isn't used) for reduced stall time.

Q24. In a system with limited physical memory, why might the Operating System choose to kill a process rather than swap it out?

A.The process is thrashing severely and consuming excessive CPU cycles handling page faults. ✅
B.The process has exceeded its maximum allowed virtual memory size.
C.The process is running in kernel mode.
D.The process has open file descriptors that cannot be serialized.
💡 Difficulty: hard | ✅ Correct: A

📖 Explanation: Thrashing occurs when a process spends more time paging than executing. If the system is overloaded and swapping doesn't resolve the contention (because the working sets of all processes exceed physical memory), killing a process is the only way to free up enough frames for the remaining processes to run efficiently.

Q25. What is the role of the 'dirty' (modify) bit in a page table entry?

A.It indicates that the page has been executed recently.
B.It indicates that the page content has been changed since it was loaded from disk. ✅
C.It marks the page as part of the shared library.
D.It prevents the page from being swapped out.
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: When a page is selected for replacement, the OS checks the dirty bit. If set, the page must be written back to the backing store (disk) because the copy in memory is newer. If clear, the page can simply be discarded, saving a costly disk write operation.

Q26. Why do some operating systems implement a 'free frame buffer' or 'pool of free frames'?

A.To ensure that there is always a physical frame available immediately when a page fault occurs. ✅
B.To reserve memory exclusively for kernel operations.
C.To prevent user processes from allocating too much memory.
D.To store the page table entries for faster access.
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: Handling a page fault involves finding a free frame, reading from disk, and updating tables. If no free frames exist, the system must first select a victim and write it out, delaying the faulting process. Maintaining a buffer of pre-cleared free frames allows the OS to assign a frame to the faulting process immediately, overlapping the victim's write-back with the new page's read-in.

Q27. What is the significance of 'swap space' being located on a raw partition versus a regular file?

A.Raw partitions typically offer faster I/O performance because they bypass file system metadata overhead. ✅
B.Regular files are more secure because they are encrypted by default.
C.Raw partitions allow for dynamic resizing of swap space.
D.Regular files support compression natively.
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: Writing to a raw partition allows the OS to write directly to specific disk blocks without consulting the file system's inode structure, directory trees, or allocation maps. This reduces seek time and processing overhead, which is critical for swap performance where latency directly impacts system responsiveness.

Q28. In the context of memory-mapped files, how does the OS handle a write to a memory-mapped region?

A.It immediately writes the data to the disk synchronously.
B.It marks the corresponding page as dirty and defers the write to the disk until necessary. ✅
C.It copies the data to a separate buffer and discards the memory-mapped page.
D.It sends a network packet to the file server.
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: Memory-mapped I/O treats file data as memory pages. Writes modify the page in RAM. The OS marks the page as dirty. The actual disk write is deferred and handled by the page replacement daemon or sync mechanisms, allowing the application to continue execution without waiting for slow disk I/O.

Q29. Why is the 'Optimal' page replacement algorithm not implementable in a real operating system?

A.It requires knowledge of future page references. ✅
B.It requires too much computational power to calculate.
C.It violates the principle of locality.
D.It requires hardware support that does not exist.
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: The Optimal algorithm replaces the page that will not be used for the longest period of time. To know this, the OS would need to see the future reference string of the process. Since future behavior is unknown, Optimal serves only as a theoretical benchmark for evaluating other algorithms.

Q30. How does 'thrashing' manifest in system performance metrics?

A.High CPU utilization with low throughput.
B.Low CPU utilization with high disk I/O activity. ✅
C.High network bandwidth usage with low memory usage.
D.Low context-switching rate with high page fault rate.
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: When thrashing, processes are constantly faulting. The CPU spends most of its time waiting for disk I/O to swap pages in and out, or servicing the interrupts associated with paging. Consequently, useful work (throughput) drops, CPU utilization (for user code) drops, but disk activity skyrockets.
