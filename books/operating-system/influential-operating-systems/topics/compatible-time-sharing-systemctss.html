What is Compatible Time Sharing System(CTSS)?

Definition:
CTSS was the first operational time-sharing system providing interactive computing to multiple users simultaneously, introducing concepts like per-user file systems and command-line interfaces with response time .

Example:
Running on IBM 7094 at MIT, CTSS allowed 30+ users to edit files and run programs interactively, pioneering the RUNCOM command script ancestor to shell scripts.

Reason:
It proved that interactive computing was technically feasible and desirable, shifting paradigm from batch processing to human-computer dialogue and directly inspiring MULTICS and Unix development.

Q1. In which year was the Compatible Time-Sharing System first introduced?

A.1961 ✅
B.1965
C.1970
D.1972
💡 Difficulty: easy | ✅ Correct: A

📖 Explanation: The correct answer is 1961 because CTSS was created at MIT and debuted in that year, marking a pioneering moment for time‑sharing operating systems. The option 1965 refers to later developments such as IBM OS/360, while 1970 and 1972 are dates when CTSS was still in use but not its introduction. Knowing the launch year helps place CTSS in the historical timeline of early computing, illustrating its role as a forerunner to later systems.

Q2. Why was the initial priority level of a program in CTSS determined by its size?

A.To minimize memory fragmentation
B.To ensure the time quantum is at least as long as the swap time ✅
C.To give larger programs more CPU time
D.To prioritize I/O‑bound jobs
💡 Difficulty: easy | ✅ Correct: B

📖 Explanation: The correct answer is that the initial level was chosen so the quantum would be at least as long as the swap time, guaranteeing that a program could complete a swap before being pre‑empted. Options suggesting memory fragmentation, extra CPU for large jobs, or I/O prioritization do not reflect the scheduling design described for CTSS. This rule linked program size to the scheduler, ensuring efficient use of the limited drum‑swap mechanism.

Q3. How does a multilevel‑feedback‑queue scheduler, like the one used in CTSS, improve overall system responsiveness compared with a single‑level round‑robin scheduler?

A.It gives each job a fixed time slice regardless of behavior
B.It dynamically adjusts priorities based on CPU bursts
C.It always runs the longest‑waiting job first ✅
D.It prevents any job from ever being preempted
💡 Difficulty: medium | ✅ Correct: C

📖 Explanation: The correct answer is that the scheduler dynamically adjusts priorities based on how much CPU a job consumes, moving jobs that exceed their quantum to lower‑priority queues with larger quanta. This contrasts with a simple round‑robin approach that treats all jobs equally, often causing short jobs to wait behind long‑running ones. The other options describe static or unrealistic behaviors that would not enhance responsiveness. By adapting priorities, CTSS kept interactive tasks fast while still handling longer jobs efficiently.

Q4. What was the most significant influence of CTSS on the design of later operating systems such as MULTICS?

A.It introduced graphical user interfaces
B.It pioneered virtual memory paging
C.It implemented multilevel feedback scheduling
D.It supported distributed computing ✅
💡 Difficulty: hard | ✅ Correct: D

📖 Explanation: The correct answer is that CTSS demonstrated the practicality of time‑sharing concepts, directly inspiring the architecture of MULTICS, which expanded on those ideas with more sophisticated security and multitasking features. While CTSS did not create GUIs, virtual memory, or distributed computing, its success proved that multiple users could share a single computer effectively. This influence shaped the evolution of modern operating systems that prioritize interactive use and resource isolation.

Q5. A program requires 8 KB of memory and its swap operation takes 4 time units. Which initial level i should be assigned so that the quantum is at least as long as the swap time?

A.Level 1
B.Level 2 ✅
C.Level 3
D.Level 4
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: The correct answer is Level 2 because the quantum formula yields 4 time units when i = 2, matching the swap duration. Level 1 would give only 2 time units, insufficient for the swap, while Levels 3 and 4 provide more time than necessary, wasting resources. Selecting the smallest level that satisfies the swap constraint balances efficiency and responsiveness, reflecting CTSS’s strategy of matching program size to an appropriate time slice.

Q6. A program runs at level 3 with a quantum of time units but needs 10 time units to finish. What does the scheduler do next?

A.It is moved down to the next lower‑priority level, receiving a larger quantum ✅
B.It terminates the program immediately
C.It keeps the program at the same level
D.It moves the program up to a higher‑priority level
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: The correct answer is that the scheduler demotes the program to the next lower‑priority queue, which provides twice the previous quantum, allowing longer jobs more CPU time. Termination is not part of CTSS’s feedback policy, and keeping the program at the same level would cause repeated pre‑emptions. Moving it to a higher‑priority level would contradict the rule that shorter quanta are given to higher‑priority queues. This behavior illustrates how CTSS adapts to varied CPU demands.

Q8. A modern emulator provides 64 KB of memory for CTSS, preserving the original 5 KB monitor and 27 KB user space per user. Assuming no other overhead, what is the maximum number of simultaneous users it could support?

A.1 user
B.2 users ✅
C.3 users
D.4 users
💡 Difficulty: hard | ✅ Correct: B

📖 Explanation: The correct answer is 2 users. After reserving 5 KB for the monitor, 59 KB remains for user memory. Dividing 59 KB by the 27 KB required per user yields about 2.18, so only two full user partitions fit. One user would leave unused memory, while three or four users would exceed the available space. This calculation shows how CTSS’s fixed memory allocation limits scalability, even when modern hardware offers more total memory.
