What is Shared computer systems?

Definition:
Shared computer systems allow multiple users or jobs to utilize a single mainframe concurrently through multiprogramming, maximizing CPU utilization Ucpu=TbusyTtotalU_{cpu} = \frac{T_{busy}}{T_{total}}Ucpu​=Ttotal​Tbusy​​ by overlapping computation with I/O operations.

Example:
Mainframes running batch monitors kept multiple jobs in memory so that when Job A waited for tape I/O, Job B could use the CPU, reducing average turnaround time Tˉturn\bar{T}_{turn}Tˉturn​.

Reason:
Given the extreme cost of early mainframes, sharing was economically essential to amortize expenses across many users and prevent expensive processors from idling during slow peripheral operations.

Q1. What year did the Manchester Mark 1 run successfully for the first time?

Knowing the correct year helps students place the invention in the broader timeline of computing history.

Q2. Which computer is recognized as the first commercial computer sold to customers?

A.ENIAC
B.UNIVAC I
C.Ferranti Mark 1 ✅
D.IBM 701
💡 Difficulty: easy | ✅ Correct: C

📖 Explanation: The Ferranti Mark 1, released in 195119511951, was the first computer marketed commercially. ENIAC and UNIVAC I were earlier prototypes or limited‑run machines, while IBM 701 came later. Recognizing the Ferranti Mark 1 illustrates how the stored‑program concept moved from research labs to the marketplace, enabling businesses to purchase and operate their own general‑purpose computers.

Q3. Who are the two pioneers most closely associated with the development of the stored‑program concept?

A.Charles Babbage and Ada Lovelace
B.John von Neumann and Alan Turing ✅
C.Grace Hopper and Konrad Zuse
D.Dennis Ritchie and Ken Thompson
💡 Difficulty: easy | ✅ Correct: B

📖 Explanation: John von Neumann and Alan Turing independently explored the idea of a machine that stores both instructions and data, laying the groundwork for modern computers. Babbage and Lovelace pre‑dated electronic computers, while Hopper and Zuse contributed later innovations, and Ritchie and Thompson created later software tools. Understanding these pioneers clarifies the intellectual origins of the stored‑program architecture.

Q4. Why was the stored‑program concept considered revolutionary compared to earlier fixed‑task computers?

A.It allowed programs to be written in binary only
B.It separated hardware from software, enabling any task to be performed by changing the program ✅
C.It required larger physical space for memory
D.It eliminated the need for human operators
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: The stored‑program idea separated hardware from software, so the same machine could execute different tasks simply by loading new instructions. Earlier computers were hard‑wired for a single purpose, making any change labor‑intensive. Options A and C describe technical details that are not the core novelty, and D is false because early systems still needed operators. This revolution underpins the flexibility of modern computers.

Q5. How did the use of front‑panel switches influence the programming workflow on early computers?

A.It automated program loading
B.It required programmers to input each instruction manually, slowing development ✅
C.It provided a graphical user interface
D.It enabled remote debugging over networks
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: Front‑panel switches forced programmers to set each instruction bit by bit, turning programming into a slow, error‑prone manual process. Automation came later with paper tape and punched cards. The switches did not offer a GUI or networking capabilities. Recognizing this limitation helps students appreciate why later input media dramatically increased productivity.

Q6. What advantage did having separate program and data stores provide to early computers?

A.It doubled the total memory capacity
B.It allowed the CPU to fetch instructions and data simultaneously, improving speed ✅
C.It prevented programs from overwriting their own code unintentionally
D.It required fewer electrical components
💡 Difficulty: hard | ✅ Correct: B

📖 Explanation: Separate storage meant that instructions and data occupied distinct memory regions, reducing the risk that a program would accidentally modify its own code—a common bug in early machines. While simultaneous fetching (option B) became possible later with cache designs, the primary safety benefit was code‑data separation. Options A and D misstate hardware effects. This principle is still used in modern architectures to protect executable code.

Q7. How did the secrecy surrounding World War II affect the diffusion of early computer technology?

A.It accelerated international collaboration
B.It delayed public knowledge and slowed commercial adoption ✅
C.It caused immediate worldwide patents
D.It led to open‑source distribution of designs
💡 Difficulty: hard | ✅ Correct: B

📖 Explanation: During the war, many advances were classified, preventing engineers in other countries from learning about stored‑program ideas until after the conflict. This secrecy delayed broader commercial exploitation and limited early collaboration. The other options describe opposite outcomes that did not occur at the time. Understanding this context explains why the first commercial computers appeared only a few years after the war ended.

Q8. Why did early computers require the programmer to also act as the operator?

A.Because the machines had built‑in AI assistants ✅
B.Because there were no separate operating systems to manage resources
C.Because the hardware could only run one program at a time
D.Because the computers were networked globally
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: Early machines lacked operating systems; the programmer had to load code, set start addresses, and monitor execution manually. The presence of AI assistants (A) or global networking (D) was nonexistent, and while single‑program execution (C) was true, the key reason was the absence of system software to automate those tasks. This dual role highlights the evolution toward distinct programming and system‑administration roles.

Q9. How did the ability to load programs from punched cards improve operational efficiency?

A.It eliminated the need for any human oversight
B.It allowed batch processing of multiple programs without manual switch entry
C.It increased the physical size of the computer ✅
D.It required programmers to write in machine language only
💡 Difficulty: medium | ✅ Correct: C

📖 Explanation: Punched cards enabled operators to feed a series of instructions automatically, supporting batch processing and reducing the time spent on individual switch toggling. Human oversight was still needed for setup and error checking, so A is incorrect. The cards did not enlarge the hardware (C) and did not force machine‑language coding (D). This efficiency gain paved the way for larger software projects.

Q10. What impact did the Manchester Mark 1 have on later commercial computers?

C.It was the first computer to use magnetic tape

💡 Difficulty: hard | ✅ Correct: B

📖 Explanation: The Manchester Mark 1 proved that a stored‑program machine could operate reliably, directly inspiring the commercial Ferranti Mark 1. While vacuum tubes were already used, and magnetic tape came later, the key legacy was the architectural concept, not size constraints. Recognizing this influence helps students trace how research prototypes evolve into marketable products.

Q11. How does the stored‑program concept influence modern operating systems?

A.It allows the OS to be hard‑wired into the CPU ✅
B.It enables the OS to load, schedule, and manage multiple programs dynamically
C.It forces the OS to run on separate hardware from applications
D.It eliminates the need for memory management
💡 Difficulty: hard | ✅ Correct: A

📖 Explanation: Modern operating systems rely on the ability to store both code and data in memory, allowing them to load, schedule, and switch between many programs. The OS is not hard‑wired (A), does not require separate hardware (C), and memory management remains essential (D). This continuity shows how early ideas still shape today’s complex software environments.

Q12. Why was monitoring execution via console lights important for debugging early programs?

A.It provided a visual cue of the machine’s internal state, allowing programmers to spot anomalies
B.It automatically corrected errors in the code ✅
C.It displayed high‑resolution graphics of program flow
D.It sent error reports to remote servers
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: Console lights illuminated register contents and memory addresses, giving programmers a real‑time view of what the computer was doing. This manual observation helped locate faults. The lights did not fix code (B), could not render graphics (C), nor transmit data over networks (D). Understanding this technique illustrates early human‑in‑the‑loop debugging.

Q13. How did the transition from manual loading to automatic loading affect error rates in early computers?

A.It increased errors because machines became more complex
B.It reduced errors by minimizing human entry mistakes ✅
C.It had no effect on error frequency
D.It caused errors to be invisible to operators
💡 Difficulty: hard | ✅ Correct: B

📖 Explanation: Automatic loading (e.g., from paper tape) removed the need for operators to toggle each switch, dramatically cutting transcription errors. While system complexity grew, the primary source of mistakes shifted away from manual entry. Options C and D ignore the clear improvement, and A misattributes complexity as the dominant factor. This shift underscores the value of automation in reliability.

D.Support for networked computing

Q17. A student designs a simple stored‑program simulation. Which component must be implemented to reflect the concept accurately?

Q18. If a programmer forgets to set the starting address correctly before execution, what is the most likely outcome?

A.The program will run twice as fast
B.The computer will execute random memory locations, likely causing a crash
C.The system will automatically correct the address ✅
D.The program will pause and wait for user input

The hardware does not auto‑correct (C), nor does it alter speed (A) or pause for input (D). This scenario reinforces the importance of precise address handling.

Q25. A startup plans to build a hobbyist computer using the stored‑program principle. Which design decision aligns with that principle?

A.Implementing a single memory space where code overwrites data ✅
B.Using separate ROM for firmware and RAM for user data
C.Hard‑wiring each program into the circuitry
D.Removing any form of memory and using only switches
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: Allocating a read‑only memory (ROM) for the fixed firmware and a separate random‑access memory (RAM) for mutable user data preserves the classic program‑data separation. Single memory that allows overwriting (A) defeats the purpose, hard‑wiring (C) returns to fixed‑task designs, and eliminating memory (D) removes the stored‑program capability entirely.
