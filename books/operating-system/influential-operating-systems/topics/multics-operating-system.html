What is MULTICS operating system?

Definition:
MULTICS was an ambitious time-sharing OS emphasizing security, reliability, and hierarchical file systems with ring-based protection levels \( Ring_0 \dots Ring_7 \) and dynamic linking.

Example:
Developed for GE-645, it featured segmented virtual memory, ACL-based security, and PL/I implementation, though complexity led to performance issues where system call overhead \( O_{syscall} \) exceeded targets.

Reason:
Despite commercial challenges, it established enduring concepts like hierarchical namespaces, capability-based security, and high-level language OS implementation that profoundly influenced Unix, Windows NT, and modern secure systems.

📝 All MULTICS operating system MCQs

Q1. In what year did the design of the MULTICS operating system begin?

A.1963 ✅
B.1965
C.1967
D.1970
💡 Difficulty: easy | ✅ Correct: A

📖 Explanation: The correct answer is 1965 because the MULTICS project started its design work in that year, marking the beginning of the collaborative effort among MIT, GE, and Bell Labs. Option A (1963) is too early, and option C (1967) and D (1970) refer to later stages of development. Knowing the start year helps place MULTICS in the historical timeline of time‑sharing systems, showing its pioneering role in the mid‑1960s.

Q2. Why were protection rings introduced in MULTICS?

A.To simplify file naming
B.To provide hierarchical security levels for processes ✅
C.To increase CPU speed
D.To reduce memory usage
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: Protection rings give each executing process a level of privilege, creating a hierarchy that isolates critical system code from user programs. This design prevents a low‑level process from inadvertently modifying high‑level resources. Options A, C, and D describe unrelated goals: file naming, CPU performance, and memory consumption, none of which address security. The rings therefore enhance system robustness in real‑world multi‑user environments.

Q3. How did merging the segmented virtual address space with the file system affect program organization in MULTICS?

A.It required separate storage for code and data
B.It allowed each segment to be treated as a regular file ✅
C.It eliminated need for directories
D.It forced use of fixed‑size memory blocks
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: By treating each segment as a file, MULTICS unified memory management and persistent storage, letting programs load and save code or data using familiar file operations. This integration simplifies user interaction and supports hierarchical directories. Options A and D describe opposite constraints, while C suggests removing directories, which contradicts MULTICS's multilevel tree structure. The file‑segment model thus streamlines development and maintenance.

Q4. What was the main advantage of using the second‑chance page‑replacement algorithm in MULTICS?

A.It guaranteed FIFO ordering ✅
B.It gave pages a chance to stay if recently referenced
C.It required no hardware support
D.It minimized disk I/O to zero
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: The second‑chance algorithm scans pages and, if a page has been referenced recently, gives it another chance before eviction, improving overall hit rates compared to pure FIFO. Option A misstates the algorithm’s behavior, option C is false because hardware assistance (reference bits) is needed, and option D exaggerates its effect. In practice, this approach balances performance and simplicity for a time‑sharing OS.

Q5. Given an 18‑bit segment number, how many unique segments can be addressed in MULTICS?

A.\(2^{16}\) ✅
B.\(2^{18}\)
C.\(2^{32}\)
D.\(2^{8}\)
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: An 18‑bit field can represent \(2^{18}\) distinct values, so the system can address that many separate segments. Option A uses the wrong bit count, option C vastly overestimates the range, and option D is far too small. Understanding this capacity helps engineers plan the segmentation scheme and allocate identifiers without collisions in real deployments.

Q6. A 64‑KB file is to be stored in MULTICS where each page holds 1‑KB. How many pages are required?

A.32 ✅
B.64
C.128
D.16
💡 Difficulty: easy | ✅ Correct: A

📖 Explanation: A 64‑KB file divided by a 1‑KB page size yields \(64\) pages (\(64\text{KB} ÷ 1\text{KB} = 64\)). Option A (32) would correspond to 2‑KB pages, option C (128) assumes 0.5‑KB pages, and option D (16) would be for 4‑KB pages. Calculating page count is essential for memory allocation and disk usage planning in real systems.

Q7. If a process attempts to access memory beyond its allocated segment, which MULTICS mechanism prevents it from reading other segments?

A.Multilevel feedback queue ✅
B.Second‑chance algorithm
C.Protection rings
D.Paged‑segmentation hardware
💡 Difficulty: hard | ✅ Correct: A

📖 Explanation: Protection rings enforce access rights based on a process’s privilege level, stopping it from crossing segment boundaries. The multilevel feedback queue (A) schedules CPU time, not memory protection. The second‑chance algorithm (B) deals with page replacement, and paged‑segmentation hardware (D) provides the address translation but does not enforce security policies. Hence, rings are the correct safeguard in a real operating environment.

Q8. When a CPU in a MULTICS multiprocessor system is taken offline for maintenance, how does the OS continue to provide service?

A.It shuts down all processes ✅
B.It migrates tasks to remaining CPUs using load balancing
C.It pauses the entire system until the CPU returns
D.It duplicates the CPU in software
💡 Difficulty: hard | ✅ Correct: A

📖 Explanation: The operating system redistributes runnable tasks among the still‑active CPUs, using load‑balancing techniques to keep performance stable. Option A would cause a complete outage, option C would halt user work, and option D describes an unrealistic software emulation. Dynamic task migration ensures continuity of service, a critical requirement for high‑availability environments.
