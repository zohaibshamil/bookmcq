📝 All TOPS-20 Operating System MCQs

Q1. In what year did DEC stop work on its line of 36‑bit PDP‑10 computers?

A.1980
B.1982
C.1984 ✅
D.1986
💡 Difficulty: easy | ✅ Correct: C

📖 Explanation: The correct answer is 1984 because DEC announced the termination of its 36‑bit PDP‑10 product line that year to concentrate on the newer 32‑bit VAX architecture. 1980 is too early, 1982 precedes the actual decision, and 1986 is after the shift had already occurred. Knowing this date clarifies the historical context in which TOPS‑20 lost its hardware platform, showing how corporate strategy can end an operating‑system’s evolution.

Q2. What was the primary purpose of adding a hardware memory‑paging system to the PDP‑10 when BBN created TENEX?

A.Increase clock speed
B.Implement virtual memory ✅
C.Reduce power consumption
D.Add graphics capability
💡 Difficulty: easy | ✅ Correct: B

📖 Explanation: Implementing virtual memory is the correct purpose because the hardware pager allowed the system to present programs with the illusion of more memory than physically existed, a key innovation for timesharing. Increasing clock speed, reducing power use, and adding graphics were not goals of TENEX. Recognizing the role of paging helps students understand why TENEX—and later TOPS‑20—offered robust multitasking and why virtual memory became a cornerstone of modern OS design.

Q3. A company needs a multi‑user environment for research labs. Which feature of TOPS‑20 would most influence its selection?

A.Advanced command‑line interpreter with built‑in help ✅
B.Built‑in hardware pager for virtual memory
C.Support for only 64 KB memory
D.Ability to run only one program at a time
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: The advanced command‑line interpreter with on‑demand help is the correct choice because it reduces training time and aids users in a shared environment. The hardware pager is valuable but many modern systems already provide virtual memory. Limiting memory to 64 KB or single‑program execution would be detrimental. This explanation shows how user‑friendly interfaces can be a decisive factor when deploying legacy‑style time‑sharing systems.

Q4. How did DEC's acquisition of TENEX influence the development of the DECSYSTEM‑20?

A.DEC integrated TENEX without hardware changes
B.DEC used TENEX as a software base for new hardware with a pager ✅
C.DEC abandoned TENEX entirely
D.DEC merged TOPS‑10 with VMS
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: DEC used TENEX as the software foundation while designing the DECSYSTEM‑20 with a built‑in hardware pager, making TOPS‑20 possible. The other options are inaccurate: DEC did not keep the old hardware unchanged, it certainly did not discard TENEX, and TOPS‑10 was not merged with VMS. Understanding this relationship illustrates how a purchased OS can be adapted to new hardware, shaping the capabilities of the resulting system.

Q5. A university plans to run a multi‑user research environment on a legacy system. Which characteristic of TOPS‑20 makes it suitable for such a scenario?

A.Single‑tasking operation
B.Lack of command help
C.Built‑in hardware pager for virtual memory ✅
D.Limited networking
💡 Difficulty: medium | ✅ Correct: C

📖 Explanation: The built‑in hardware pager that provides virtual memory is the correct characteristic because it allows many users to run programs concurrently without exhausting physical memory. Single‑tasking would prevent sharing, lack of command help would hinder usability, and limited networking would restrict collaboration. Recognizing the importance of virtual memory helps students see why TOPS‑20 remained attractive for time‑sharing workloads even as newer systems emerged.

Q6. Why was TOPS‑20 considered more popular than its predecessor TOPS‑10 despite both running on PDP‑10 hardware?

A.Because TOPS‑20 had better graphics
B.Because TOPS‑20 added virtual memory and a user‑friendly command interpreter ✅
C.Because TOPS‑20 was cheaper
D.Because TOPS‑20 supported 64‑bit addressing
💡 Difficulty: hard | ✅ Correct: B

📖 Explanation: TOPS‑20’s popularity stemmed from its virtual memory capability and the intuitive command interpreter that offered on‑the‑fly assistance, which greatly improved user productivity. Graphics improvements, lower cost, and 64‑bit addressing were not factors; TOPS‑10 lacked these advanced usability features. This explanation connects the technical enhancements to real‑world adoption, showing how usability and memory management drive system success.

Q7. Suppose a modern cloud service wants to emulate historical time‑sharing behavior. Which design decision from TOPS‑20 should be replicated to improve user assistance?

A.Embed a help‑on‑demand command interpreter ✅
B.Remove paging entirely
C.Enforce single‑user sessions
D.Limit memory to 64 KB
💡 Difficulty: hard | ✅ Correct: A

📖 Explanation: Embedding a help‑on‑demand command interpreter mirrors TOPS‑20’s approach of providing immediate assistance, which reduces training overhead and improves user confidence. Removing paging would eliminate virtual memory, single‑user enforcement contradicts time‑sharing goals, and limiting memory would cripple modern workloads. This rationale demonstrates how a specific historical feature can be adapted to enhance contemporary cloud services that aim to recreate classic interactive experiences.

Q8. Which factor from TOPS‑20 history suggests a potential challenge when migrating users to VMS?

A.Hardware pager incompatibility
B.User familiarity with TOPS‑20 command interpreter
C.Lack of networking support
D.Single‑tasking limitation ✅
💡 Difficulty: medium | ✅ Correct: D

📖 Explanation: User familiarity with the TOPS‑20 command interpreter is the correct challenge because users accustomed to its help‑driven interface may resist the different command syntax of VMS. Hardware pager incompatibility, networking gaps, and single‑tasking are not primary migration issues. Recognizing this human‑factor obstacle helps students appreciate that successful OS transitions often require attention to user experience, not just technical compatibility.
