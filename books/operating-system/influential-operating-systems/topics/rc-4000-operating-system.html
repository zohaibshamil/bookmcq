What is RC 4000 operating system?

Definition:
The RC 4000 operating system pioneered the concept of a minimal kernel or nucleus, separating policy from mechanism where the microkernel provides only IPC and basic scheduling, leaving higher-level services to user-space servers with communication cost .

Example:
Per Brinch Hansen's design moved file systems and device drivers out of the kernel, communicating via message passing so that OS functionality could be customized without modifying privileged code.

Reason:
This separation improved extensibility and reliability by minimizing trusted computing base size, allowing different policies to coexist and reducing the impact of bugs in non-critical components.

📝 All RC 4000 operating system MCQs

Q1. What was the size of the drum backing store used by the THE operating system?

A.256‑KB word drum
B.512‑KB word drum ✅
C.1‑MB word drum
D.128‑KB word drum
💡 Difficulty: easy | ✅ Correct: B

📖 Explanation: The THE system stored swapped pages on a magnetic drum that could hold 512 KB‑words. This size was chosen because it matched the paging unit of 512‑word pages, allowing a whole page to be transferred in one drum rotation. The other options describe drums that are either too small or too large for the system’s design, making them incorrect. Recognizing the correct drum size helps understand the hardware constraints the OS had to work with.

Q2. Why did the THE system assign higher priority to I/O‑bound processes?

A.Because they used less recent CPU time
B.Because they required more memory ✅
C.Because they were newer
D.Because they had larger pages
💡 Difficulty: easy | ✅ Correct: B

📖 Explanation: The priority algorithm recomputed every 2 seconds and set priority inversely proportional to recent CPU usage. I/O‑bound processes typically spend little time on the CPU, so their recent CPU usage is low, giving them a high inverse value and thus higher priority. The other choices misinterpret the algorithm: memory use and page size do not affect priority, and being newer only influences initial priority, not the ongoing calculation.

Q3. A program experiences frequent page faults on the THE system. Which change would most likely reduce the fault rate?

A.Increase page size to 1024 words ✅
B.Switch to a FIFO replacement policy
C.Use the existing LRU policy
D.Disable paging entirely
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: Increasing the page size from 512 to 1024 words reduces the total number of pages needed to represent a program, so fewer pages must be swapped in and out, lowering the fault frequency. The system already uses LRU, which is optimal for locality, so changing the replacement policy would not help. Disabling paging would exceed the limited 32 KB memory, causing failures. Thus, a larger page size is the most effective adjustment.

Q4. How does the banker’s algorithm help the THE system avoid deadlock?

A.By guaranteeing that every resource request is satisfied immediately
B.By ensuring the system never enters an unsafe state
C.By limiting the number of processes that can run concurrently ✅
D.By allocating resources in a round‑robin fashion
💡 Difficulty: medium | ✅ Correct: C

📖 Explanation: The banker’s algorithm checks each resource request against a safety condition: after granting the request, the system must still be able to allocate resources to all processes in some order that lets each finish. This prevents the system from reaching an unsafe state where deadlock could occur. Immediate satisfaction without safety checks could create deadlock, and limiting concurrency or using round‑robin does not address resource safety, making those options incorrect.

Q6. The system has 3 instances of resource R. Allocation: P1‑1, P2‑1, P3‑0. Maximum needs: P1‑2, P2‑2, P3‑1. Available = 1. P3 now requests 1 instance of R. Which decision keeps the system in a safe state?

A.Grant the request
B.Den​y the request ✅
C.Grant but monitor later
D.Grant after swapping resources
💡 Difficulty: hard | ✅ Correct: B

📖 Explanation: If the request is granted, the new allocation becomes P3‑1 and available drops to 0. The remaining needs are P1‑1, P2‑1, P3‑0. With no available resources, neither P1 nor P2 can finish, so the system cannot reach a state where all processes complete—this is unsafe. Denying the request preserves safety because the current state (available = 1) allows either P1 or P2 to finish first, releasing resources. The other options either assume monitoring or swapping, which are not part of the banker’s safety check.

Q7. What performance advantage did the Venus system gain by implementing its lower layers in microcode compared to the THE system?

A.It allowed dynamic process creation
B.It reduced the need for semaphores
C.It provided faster execution of low‑level operations ✅
D.It increased the size of the drum backing store
💡 Difficulty: hard | ✅ Correct: C

📖 Explanation: Microcode executes directly on the hardware, bypassing the higher‑level operating‑system code that the THE system used for its lower layers. This hardware‑level implementation speeds up critical operations such as context switches and I/O handling, giving the Venus system a noticeable performance edge. Dynamic process creation and semaphore usage are software concerns, and drum size is unrelated to execution speed, so those choices are incorrect.

Q9. Why did the THE system use a static set of processes rather than creating processes dynamically?

A.To simplify synchronization and reduce overhead
B.To limit the number of users ✅
C.To enable hardware paging
D.To avoid using semaphores
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: A static process set means the operating system knows all processes in advance, allowing it to design fixed semaphore relationships and avoid the runtime cost of creating and destroying process control blocks. This design choice reduces synchronization complexity and overhead. Limiting users or enabling hardware paging are unrelated to process creation strategy, and the system already employed semaphores, so those options do not explain the static design.
