What is CP/M and MS/DOS?

Definition:
CP/M and MS-DOS were single-user disk operating systems for microcomputers providing BIOS abstraction and FAT filesystems where portability achieved through hardware abstraction layer .

Example:
CP/M's BDOS/BIOS separation allowed easy porting across Z80 systems, while MS-DOS adopted similar structure for IBM PC, using INT 21h API calls for file and console operations.

Reason:
They enabled the personal computer revolution by providing affordable, portable OS platforms that standardized software distribution and created ecosystems independent of specific hardware vendors.

📝 All CP/M and MS/DOS MCQs

Q1. Who is credited with writing the original CP/M operating system?

A.Gary Kildall ✅
B.Bill Gates
C.Steve Jobs
D.Linus Torvalds
💡 Difficulty: easy | ✅ Correct: A

📖 Explanation: Gary Kildall created CP/M while working at Digital Research. The other individuals are known for founding Microsoft, Apple, and Linux respectively, which are unrelated to CP/M’s origin. Recognizing Kildall’s role helps students understand the early software ecosystem that enabled personal computers. This knowledge is essential when studying how operating‑system ideas spread, even though the question simply asks for a name.

Q2. Why was CP/M considered a pivotal step toward widespread personal computing?

A.It introduced multitasking on 8‑bit machines
B.It provided a uniform API for disk I/O ✅
C.It required specialized hardware that only large corporations owned
D.It eliminated the need for any software development
💡 Difficulty: easy | ✅ Correct: B

📖 Explanation: CP M offered a standard set of system calls for disk operations, allowing software to run on many different hardware platforms without rewriting code. The other options describe features CP M did not have: it was single‑tasking, ran on common hardware, and still required programmers. Understanding this reason shows how standardization lowered barriers for developers, accelerating personal‑computer adoption.

Q3. How did the design of CP/M influence the later development of MS‑DOS?

A.MS‑DOS copied CP/M’s file‑system layout and command syntax
B.MS‑DOS abandoned CP/M concepts entirely
C.MS‑DOS used CP/M’s graphical user interface ✅
D.MS‑DOS was built on a different hardware architecture unrelated to CP/M
💡 Difficulty: medium | ✅ Correct: C

📖 Explanation: MS‑DOS retained CP/M’s file‑system structure (e.g., FAT) and adopted similar command‑line conventions, making it easier for users to transition. It did not copy CP M’s GUI because CP M lacked one, nor did it ignore CP M entirely. Recognizing this continuity explains why early DOS programs could be ported with minimal changes, illustrating the practical impact of design inheritance.

Q4. A developer must port a program written for CP/M to run under MS‑DOS. Which step is most critical to ensure correct file handling?

A.Changing all assembly language instructions to Intel syntax
B.Rewriting the user interface to use DOS commands
C.Mapping CP/M BDOS calls to DOS interrupt services ✅
D.Converting the program’s source code from Pascal to C
💡 Difficulty: medium | ✅ Correct: C

📖 Explanation: The core of a CP/M application communicates with the OS via BDOS calls; mapping these to DOS interrupt services (e.g., INT 21h) preserves file‑access behavior. Simply altering syntax or UI does not guarantee functional compatibility, and language conversion is unnecessary if the code remains in the same language. This focus on system‑call translation reflects real‑world porting tasks where low‑level OS interfaces are the primary obstacle.

Q5. A computer with 16 KB of RAM runs CP/M. What is the maximum size of a single program that can be loaded into memory, assuming the operating system occupies 4 KB?

A.12 KB
B.8 KB ✅
C.16 KB
D.4 KB
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: CP M reserves part of RAM for its own kernel; if the system uses 4 KB, the remaining 12 KB is available. However, CP M loads programs in 2 KB pages, and the largest contiguous block without fragmentation is 8 KB (four pages). Therefore, the maximum program size is 8 KB. The other choices either ignore OS overhead or exceed the paging limitation, illustrating how memory constraints affect program size.

Q6. A legacy application uses CP/M BDOS calls for file management. To emulate this on a modern operating system, which software layer must be created?

A.A compatibility translation layer that intercepts BDOS calls ✅
B.A new hardware device driver for floppy disks
C.A graphical front‑end that mimics CP/M menus
D.A network protocol that forwards file requests to a remote server
💡 Difficulty: hard | ✅ Correct: A

📖 Explanation: Emulating CP/M requires a translation layer that captures BDOS calls and maps them to the host OS’s file‑system API. Hardware drivers are unnecessary because modern OSes already support storage devices, and a GUI or network protocol does not address the low‑level system‑call translation. Building such a layer mirrors real‑world emulators like DOSBox, showing how software abstraction enables legacy code to run on current platforms.

Q7. How does the command‑line interpreter of TOPS‑20 differ from that of early MS‑DOS regarding user assistance?

A.TOPS‑20 offers context‑sensitive help after each command ✅
B.MS‑DOS provides built‑in tutorials for every command
C.Both require users to read external manuals
D.TOPS‑20 does not support any help features
💡 Difficulty: hard | ✅ Correct: A

📖 Explanation: TOPS‑20’s interpreter includes a built‑in help system that can be invoked with a question mark, giving immediate guidance on command syntax. Early MS‑DOS lacked such interactive assistance, relying on printed manuals or external documentation. The other statements are inaccurate: MS‑DOS did not embed tutorials, and both systems did not completely lack help. Understanding this contrast highlights how user‑friendly design can reduce learning curves, a key factor in system adoption.

Q8. An engineer is designing a small embedded device that must run a single application and store data on a floppy disk. Which legacy operating system would be most suitable as a starting point, and why?

A.MS‑DOS, because it supports multitasking
B.CP/M, because it has a minimal footprint and simple disk I/O ✅
C.TOPS‑20, because it offers advanced virtual memory
D.Linux, because it can be stripped down to a tiny kernel
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: CP M was designed for 8‑bit machines with limited memory, providing a tiny kernel and straightforward disk‑I/O routines, making it ideal for constrained embedded devices. MS‑DOS expects more RAM and includes features unnecessary for a single‑application environment. TOPS‑20’s virtual memory and Linux’s larger footprint would add unwanted complexity. Selecting CP M mirrors real‑world scenarios where developers choose lightweight legacy OSes to meet strict resource limits.
