📝 Atlas operating system

What is Atlas operating system?

The Atlas operating system was a pioneering research system that introduced virtual memory and paging, allowing programs to use an address space larger than physical memory by automatically swapping pages between \( \text{RAM} \) and secondary storage while also implementing supervisor calls for secure user-kernel interaction.

📝 All Atlas operating system MCQs

Q1. Which component of the resident monitor reads and executes the control cards at the point of execution?

A. Control‑card interpreter ✅
B. Loader
C. Device driver
D. Scheduler

💡 Difficulty: easy | ✅ Correct: A

📖 Explanation:

The control‑card interpreter is the part that parses each control card and carries out its instructions, so it is the correct choice. The loader only brings programs into memory, device drivers handle I/O, and the scheduler decides which process runs next; none of these perform the card‑reading function. In a real batch system, the interpreter directly determines which program to start, making this distinction crucial for system designers.

Q2. Why does linking both system and application programs to the same device drivers reduce memory usage in a batch environment?

A. It allows sharing of driver code
B. It speeds up CPU execution
C. It eliminates the need for I/O
D. All of the above ✅

💡 Difficulty: medium | ✅ Correct: D

📖 Explanation:

Sharing driver code means the same routine is stored once and referenced by many programs, cutting duplicate copies and freeing memory. While sharing does not directly speed the CPU or remove I/O, it does provide continuity and saves space, so option D (all of the above) best captures the overall benefit. Options A and B describe only part of the effect, and C is inaccurate because I/O is still required. In practice, this sharing lets larger applications run on limited main‑memory machines.

Q3. How does automatic job sequencing improve overall system throughput in a batch system?

A. It reduces human setup time ✅
B. It allows overlapping I/O
C. It increases CPU clock speed
D. It decreases memory usage

💡 Difficulty: medium | ✅ Correct: A

📖 Explanation:

Automatic sequencing removes the manual step of loading each job, so the CPU can start the next program as soon as the previous one finishes, raising the number of jobs processed per hour. Overlapping I/O is not guaranteed; the CPU clock speed is a hardware attribute, and memory usage is unchanged by sequencing alone. Therefore the primary benefit is the reduction of human‑operator delay, making option A correct. Real‑world batch farms measure throughput gains directly from this automation.

Q4. What is the primary hardware limitation that causes the CPU to remain idle even after implementing automatic job sequencing?

A. Slow mechanical I/O devices ✅
B. Insufficient memory
C. Lack of multitasking
D. Poor compiler optimization

💡 Difficulty: hard | ✅ Correct: A

📖 Explanation:

Mechanical devices such as card readers and tape drives operate in milliseconds, far slower than the microsecond‑scale CPU, so the processor often waits for I/O completion, creating idle cycles. While limited memory or missing multitasking can also affect performance, the text emphasizes I/O speed as the dominant factor. Poor compiler optimization influences program execution time but not the wait caused by external hardware. Consequently, option A accurately identifies the root cause of CPU idle periods in early batch systems.

Q5. In the described batch system, what specific action does the loader perform after the control‑card interpreter reads a $RUN card?

A. It loads the program into memory ✅
B. It compiles the program
C. It writes output to tape
D. It manages device drivers

💡 Difficulty: medium | ✅ Correct: A

📖 Explanation:

When a $RUN card appears, the interpreter signals the loader to locate the program's object code and place it in an executable region of memory, ready for execution. Compiling is a separate step performed earlier, output writing is handled by I/O routines, and device‑driver management is a continuous background function. Therefore only option A correctly describes the loader's role. In practical batch operations, this loading step determines whether the program can start promptly after the $RUN card.

Q6. How does using the same device drivers for both system and application programs affect program portability across different hardware platforms?

A. It increases portability ✅
B. It decreases portability
C. It has no effect
D. It depends on the hardware

💡 Difficulty: medium | ✅ Correct: A

📖 Explanation:

When programs rely on a common driver layer, only the driver needs to be rewritten for a new platform; the higher‑level programs remain unchanged, enhancing portability. Saying it decreases portability contradicts this benefit, and claiming no effect ignores the abstraction that drivers provide. While the underlying hardware still matters, the driver abstraction generally makes migration easier, so option A is the most accurate. Companies historically reused applications on new machines by updating drivers rather than rewriting entire code bases.

Q7. A batch system shows 30 % CPU idle time because I/O devices are slow. Which upgrade would most directly reduce the idle time?

A. Replace mechanical disks with faster solid‑state storage ✅
B. Increase CPU clock speed
C. Add more RAM
D. Optimize the compiler

💡 Difficulty: medium | ✅ Correct: A

📖 Explanation:

CPU idle time stems from waiting for I/O; swapping slower mechanical disks for solid‑state drives shortens data transfer latency, letting the CPU resume work sooner. Raising the CPU clock speed does not address the I/O bottleneck, extra RAM only helps with memory pressure, and compiler optimization affects program size or speed but not device latency. Hence the most effective change is option A, which aligns with real‑world upgrades that dramatically cut batch‑system idle periods.

Q8. A resident monitor has 300 KB of free memory. Program X requires 200 KB and Program Y requires 150 KB. Which technique allows both programs to be loaded without swapping?

A. Load X then Y
B. Load Y then X
C. Load X partially
D. Use overlay loading ✅

💡 Difficulty: hard | ✅ Correct: D

📖 Explanation:

Overlay loading divides each program into smaller modules that fit into the available memory, swapping modules as needed while keeping the total resident footprint below 300 KB. Loading either whole program first would exceed memory, and loading a program partially without a defined overlay strategy is not feasible. Therefore option D correctly describes the method used in early batch systems to run large applications on limited memory, illustrating practical memory‑management techniques.

Q9. If a control card mistakenly uses $END instead of $RUN, what will the resident monitor most likely do?

A. The program will not start ✅
B. The monitor will skip to the next control card
C. The system will crash
D. The loader will abort

💡 Difficulty: easy | ✅ Correct: A

📖 Explanation:

The $END card signals the end of a program, so the monitor treats it as a completion marker and proceeds to read the following card. It does not attempt to start a program, so option A is inaccurate; a crash or loader abort is unlikely because the monitor simply continues processing. Skipping to the next card matches typical batch behavior, making option B the correct choice. This mirrors real batch operations where a mis‑typed control card can cause a job to be bypassed.

Q10. An organization wants to eliminate human operator involvement in job setup. Which batch‑system feature should they emphasize?

A. Automatic job sequencing ✅
B. Device‑driver sharing
C. Memory paging
D. Real‑time scheduling

💡 Difficulty: easy | ✅ Correct: A

📖 Explanation:

Automatic job sequencing removes the need for a person to manually load and start each job, allowing the system to run jobs back‑to‑back without intervention. Device‑driver sharing aids memory efficiency, paging manages virtual memory, and real‑time scheduling addresses time‑critical tasks, none of which directly replace human setup. Therefore option A directly addresses the goal of minimizing operator work, reflecting how early batch environments achieved hands‑free operation.

Q11. One I/O operation takes 5 ms and a CPU instruction takes 0.5 µs. What is the ratio of I/O time to CPU time for a single instruction?

A. 10
B. 100
C. 1 000
D. 10 000 ✅

💡 Difficulty: hard | ✅ Correct: D

📖 Explanation:

Convert 5 ms to microseconds: \(5\,\text{ms}=5,000\,\mu\text{s}\). Divide by the CPU instruction time \(0.5\,\mu\text{s}\): \(5,000 / 0.5 = 10,000\). Therefore the I/O operation is ten thousand times slower than a single CPU instruction, making option D correct. The other options underestimate the disparity. Understanding this ratio helps engineers appreciate why CPUs often idle while waiting for slow mechanical I/O in batch processing.

Q12. A new job requires a program that uses a device driver not previously linked. What must the resident monitor do before executing the program?

A. Load the required driver into memory ✅
B. Skip the job
C. Use a default driver
D. Halt the system

💡 Difficulty: hard | ✅ Correct: A

📖 Explanation:

The monitor must ensure that all device drivers referenced by the program are present; loading the missing driver satisfies this requirement. Skipping the job would waste resources, using a default driver could cause incorrect I/O behavior, and halting the system is unnecessary. Hence option A reflects proper batch operation, where the monitor dynamically loads needed drivers to maintain continuity and correctness.

Q13. After a program finishes and control returns to the monitor, the next control card is $FTN. What action should the monitor take next?

A. Load the Fortran compiler ✅
B. Execute the previous program again
C. Skip to the next $RUN card
D. Write output to tape

💡 Difficulty: medium | ✅ Correct: A

📖 Explanation:

The $FTN card indicates that a Fortran source file follows and needs to be compiled. The monitor therefore invokes the Fortran compiler, loading it into memory. Re‑executing the previous program is unnecessary, skipping to $RUN would ignore the compilation step, and writing output is unrelated to compilation. Option A correctly describes the batch system's response, mirroring real workflows where source compilation follows job sequencing.
