📖 Main Memory

Main Memory Management: Address Binding, Paging, and Segmentation

Main Memory examines how an operating system organizes, allocates, protects, and translates access to physical memory while multiple processes execute. Building on process address spaces and basic computer architecture, this chapter follows memory management from hardware and address binding through loading, linking, swapping, and contiguous allocation. It then compares segmentation and paging, including page-table organizations, protection, and shared pages. Architecture examples demonstrate how these mechanisms are implemented in SPARC Solaris, Intel 32-bit, x86-64, and ARM systems.

Prerequisites for Understanding Main-Memory Management

Students should understand process address spaces, program execution, CPU registers, memory addresses, and the relationship between the processor and main memory. Knowledge of binary and hexadecimal number systems is particularly important for understanding address translation. Familiarity with process creation, shared libraries, and basic hardware protection mechanisms will help explain memory allocation, paging, segmentation, and architecture-specific memory-management implementations.

Learning Objectives: Address Translation and Memory Allocation

After studying this chapter, students should be able to explain basic memory hardware, address binding, and the distinction between logical and physical addresses. They should understand dynamic loading, dynamic linking, shared libraries, swapping, and contiguous memory allocation. They should identify internal and external fragmentation, explain segmentation and paging hardware, analyze page protection and shared pages, and compare hierarchical, hashed, and inverted page tables. They should also understand memory-management examples from SPARC Solaris, Intel 32-bit, x86-64, and ARM architectures.

Learning Path: From Memory Hardware to Page-Table Structures

Begin with memory hardware and address binding to understand how programs obtain memory addresses and how processors access physical memory. Next, study dynamic loading, linking, and swapping to understand how programs and memory contents are managed. Examine contiguous allocation and fragmentation before progressing to segmentation and paging. Learn paging hardware, protection, and shared pages before comparing different page-table organizations. Finish with architecture-specific examples to understand how these concepts appear in real processor and operating-system environments.

How Logical Addresses Are Translated into Physical Memory

Memory hardware establishes the foundation for address binding and logical-to-physical address translation. Dynamic loading, linking, and swapping explain how programs and their contents enter or leave memory. Contiguous allocation introduces placement strategies and fragmentation, motivating more flexible segmentation and paging techniques. Paging then requires hardware translation and protection mechanisms, while shared pages enable controlled memory sharing. Hierarchical, hashed, and inverted page tables organize translation information differently, and architecture examples demonstrate their practical implementation.

How an Operating System Allocates and Protects Main Memory

Assume a process accesses logical address 0x00401234 on a system using 4 KiB pages. Address binding and paging hardware translate the address through its page table. The page number is 0x401 and the offset is 0x234. If page 0x401 maps to physical frame 0x2A, the resulting physical address is 0x2A234. Hardware protection checks whether the requested access is permitted. A shared-library page may also be mapped into another process when appropriate permissions allow it.

Why Main-Memory Management Is Essential for Program Execution

Without effective memory management, processes could overwrite one another's data, access unauthorized memory, or waste available RAM through inefficient allocation. Paging and segmentation provide organized memory access, while protection and sharing support isolation and cooperation. These mechanisms are essential for virtual memory, process isolation, application execution, and efficient utilization of modern computer systems.

Common Misconceptions About Paging, Segmentation, and Fragmentation

Students sometimes believe 'logical addresses and physical addresses refer to the same location.' Logical addresses belong to a process address space, whereas physical addresses identify locations in main memory. Another misconception is 'paging and segmentation divide memory in the same way.' Paging uses fixed-size blocks, while segmentation uses logically meaningful variable-sized units. Finally, 'all fragmentation is external fragmentation' is incorrect because fixed-size paging can produce internal fragmentation, whereas variable-sized allocation can produce external fragmentation.

Paging, Segmentation, and Address Translation: Key Exam Areas

Examinations commonly test address binding, logical-to-physical address calculations, and distinctions between dynamic loading and dynamic linking. Students should calculate contiguous memory allocation outcomes, identify fragmentation types, and trace segmentation and paging address translations. Other important questions compare page-table structures, explain memory protection and shared pages, and identify differences among Intel, ARM, and SPARC memory-management approaches.

Summary of Main-Memory Allocation and Management

This chapter explains how operating systems manage physical memory while providing processes with organized and protected address spaces. Address binding and loading mechanisms connect programs to memory, while allocation techniques determine how memory is assigned. Segmentation and paging provide alternative memory-management approaches, supported by translation hardware and page tables. Architecture examples demonstrate how these principles are adapted to different processor designs and operating-system environments.

Essential Main-Memory and Address-Translation Terminology

  • Address Binding - the process of associating program instructions and data references with memory addresses.
  • Logical Address - an address generated by the CPU within a process address space.
  • Physical Address - the actual address of a location in main memory.
  • Memory Management Unit (MMU) - hardware responsible for translating addresses and enforcing memory access permissions.
  • Fragmentation - wasted memory space caused by inefficient allocation or unused portions of allocated blocks.
  • Segmentation - a memory-management technique that divides a process address space into logical variable-sized segments.
  • Page - a fixed-size block into which a process's logical address space is divided.
  • Page Table - a data structure that maps virtual pages to physical memory frames.
