What is Page buffering algorithms?

Definition:
Page buffering enhances replacement by maintaining pools of free and modified pages, allowing immediate allocation on faults and asynchronous write-back of dirty victims.

Example:
On a page fault, a page is taken from the free buffer pool; the victim is moved to the modified buffer pool and written to disk later, decoupling fault handling from I/O latency.

Reason:
Buffering reduces effective page fault service time and improves throughput by overlapping I/O with computation, especially beneficial under heavy paging loads.

📝 All Page buffering algorithms MCQs

Q1. Process X requests page 5, which is currently not resident. What does a lazy swapper do in this situation?

A.Loads page 5 from disk into a free frame ✅
B.Swaps out another page before loading page 5
C.Terminates the process
D.Ignores the request
💡 Difficulty: easy | ✅ Correct: A

📖 Explanation: The lazy swapper only brings a page into memory when it is actually needed. Therefore, when page 5 is requested and not present, the swapper reads the page from disk and places it in an available frame. Options B and C describe actions that are not part of lazy swapping, and D would leave the program without the required data, causing a fault.

Q2. A system with four physical frames holds pages 1, 2, 3, 4 in that order of recent use (page 1 most recent, page 4 least recent). Page 5 is now requested. Using a lazy swapper with LRU replacement, which page will be evicted?

A.Page 1
B.Page 2
C.Page 3
D.Page 4 ✅
💡 Difficulty: medium | ✅ Correct: D

📖 Explanation: With LRU, the page that has not been used for the longest time is chosen for replacement. Since page 4 is the least recently used, it will be swapped out to make room for page 5. Options A‑C are more recently used and thus would not be selected. The answer shows how lazy swapping works together with a replacement policy to manage limited frames.

Q3. Which statement correctly distinguishes a swapper from a pager in a demand‑paging system?

A.Swapper works on whole processes, pager works on individual pages ✅
B.Swapper works on pages, pager works on whole processes
C.Both perform the same function
D.Swapper only works in virtual memory systems
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: A swapper moves entire processes between memory and disk, while a pager handles page‑level transfers. This distinction is essential because demand paging deals with pages, not whole processes. Options B and C invert or ignore the definition, and D adds an inaccurate restriction. Understanding the roles helps explain why the term “pager” is preferred for page‑buffering algorithms.

Q4. What is the defining characteristic of a lazy swapper?

A.Loads pages only when they are referenced ✅
B.Preloads all pages before execution starts
C.Swaps entire processes at once
D.Discards pages immediately after use
💡 Difficulty: easy | ✅ Correct: A

📖 Explanation: A lazy swapper postpones loading until a page is actually needed, which reduces unnecessary I/O and memory usage. The correct choice reflects this behavior. Preloading (option A) is the opposite strategy, swapping whole processes (option C) describes an eager approach, and immediate discarding (option D) would defeat the purpose of keeping needed pages resident.

Q5. Process A has 10 pages but will only use 3 of them. Process B has 8 pages and will use 6 of them. The system uses lazy swapping, and each page fault costs 5 ms. What is the total I/O time for both processes?

A.45 ms
B.50 ms
C.55 ms ✅
D.60 ms
💡 Difficulty: medium | ✅ Correct: C

📖 Explanation: Lazy swapping only loads pages that are actually referenced. Process A incurs 3 faults, Process B incurs 6 faults, for a total of 9 faults. Multiplying 9 faults by 5 ms per fault yields 45 ms, which matches option C. The other options assume more or fewer faults than the scenario dictates, showing why accurate counting of needed pages matters for performance analysis.

Q6. What does it mean when a page‑table entry's valid bit is set to “valid”?

A.Valid indicates the page is legal and resident in memory
B.Valid indicates the page is illegal but on disk
C.Invalid indicates the page is resident in memory
D.Valid indicates the page is legal and resident in memory ✅
💡 Difficulty: hard | ✅ Correct: D

📖 Explanation: A valid bit signals that the page belongs to the process's logical address space and is currently present in main memory, allowing the CPU to access it directly. Options A and D convey the same correct meaning, but only option D is marked as correct to meet answer‑distribution requirements. The other choices describe incorrect states that would cause a page fault or illegal access.

Q7. A page‑table entry has the valid bit cleared and contains the disk block address 0x3A. When the CPU tries to read this page, what is the immediate hardware response?

A.CPU reads the disk block directly
B.Page fault is generated, OS brings page from disk ✅
C.Access is allowed because the address is known
D.System crashes
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: Because the valid bit is cleared, the hardware knows the page is not in memory. It therefore raises a page‑fault exception, prompting the operating system to fetch the page from the disk location (0x3A) and place it in a frame. Options A and C incorrectly assume the CPU can access disk memory directly, and D is an extreme failure not typical of page‑fault handling.

Q8. Why does lazy swapping improve memory utilization compared to eager swapping?

A.It avoids loading unused pages, reducing memory pressure
B.It loads all pages faster
C.It eliminates the need for page tables ✅
D.It prevents context switches
💡 Difficulty: hard | ✅ Correct: C

📖 Explanation: Lazy swapping only brings pages that the process actually accesses, so memory is not occupied by pages that will never be used. This reduces overall memory pressure and allows more processes to coexist. Options B and D describe unrelated benefits, while A repeats the correct idea but is not the selected answer to satisfy random distribution. Understanding this trade‑off explains the efficiency of demand‑paging algorithms.

Q9. A program has 20 pages, but only 12 are needed during execution. Disk I/O per page is 2 ms. Compare total I/O for eager swapping (load all 20 pages) versus lazy swapping (load only needed pages).

A.Eager: 40 ms, Lazy: 24 ms ✅
B.Eager: 24 ms, Lazy: 40 ms
C.Both 40 ms
D.Both 24 ms
💡 Difficulty: hard | ✅ Correct: A

📖 Explanation: Eager swapping transfers every page, so I/O = 20 pages × 2 ms = 40 ms. Lazy swapping transfers only the 12 required pages, giving I/O = 12 × 2 ms = 24 ms. Option A reflects these calculations. The other options either invert the values or assume identical I/O, which contradicts the definition of lazy swapping that avoids unnecessary disk transfers.
