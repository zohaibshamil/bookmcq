What is Page size in Virtual Memory?

Definition:
Page size determines the granularity of virtual-to-physical mapping, affecting TLB reach, internal fragmentation, and page fault overhead.

Example:
4 KB pages yield fine-grained protection but limit TLB coverage; 2 MB huge pages increase reach to but waste memory for small allocations.

Reason:
Page size choice balances conflicting goals: smaller pages reduce waste and improve flexibility, larger pages boost TLB effectiveness and reduce page table size.

📝 All Page size in Virtual Memory MCQs

Q1. What is the definition of page size in a virtual memory system?

A.Amount of physical memory allocated to the kernel ✅
B.Fixed length of a block of virtual memory that maps to a physical frame
C.Size of the swap file on disk
D.Number of processes that can run simultaneously
💡 Difficulty: easy | ✅ Correct: A

📖 Explanation: The correct answer is the fixed‑length block of virtual memory that corresponds to a physical frame because page size determines how memory is divided into equal chunks for paging. Option A describes kernel memory, not paging. Option C confuses page size with swap space size. Option D refers to multitasking capacity, which is unrelated. Understanding this definition helps students see why page size matters when designing memory‑management policies.

Q2. Why does over‑allocation of memory often lead to the need for page replacement?

A.It increases the number of free frames, reducing page faults ✅
B.It forces the operating system to terminate user processes immediately
C.It fills the free‑frame list, causing page faults that must be resolved by replacing existing pages
D.It eliminates the need for I/O buffers, simplifying memory management
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: When all frames are occupied, a new page fault cannot be satisfied by a free frame, so the OS must choose a resident page to evict. Option A is opposite; more free frames would lower fault rates. Option B is a possible but undesirable response, not the typical mechanism. Option D misstates the effect of over‑allocation. Recognizing this chain clarifies why page replacement is essential for maintaining system responsiveness.

Q3. How does a larger page size affect internal fragmentation within a process?

A.It reduces internal fragmentation because fewer pages are needed
B.It increases internal fragmentation because the last page may be only partially used ✅
C.It eliminates fragmentation entirely
D.It has no impact on fragmentation
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: A larger page size means each allocated page can hold more data, so the leftover space at the end of a process’s address space is typically smaller, reducing wasted memory. Option B incorrectly claims the opposite; while the final page may be partially filled, the overall waste tends to drop as page size grows. Option C is false because fragmentation still exists, and Option D ignores the relationship. This concept helps students balance page‑size choices against memory efficiency.

Q4. A process requires 10 KB of memory and the system uses a 4 KB page size. How many pages must be allocated for the process?

A.2 ✅
B.3
C.4
D.5
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: The process needs enough pages to cover 10 KB, so two full 4 KB pages (8 KB) plus a third page for the remaining 2 KB, totaling three pages. Option A would only provide 8 KB, insufficient. Option C would allocate 12 KB, more than necessary, and Option D even more. Calculating the number of pages is a routine step when mapping a process’s memory requirements to the paging architecture.

Q5. If the page size is doubled while the working set size of a program remains unchanged, what is the most likely impact on the number of page faults?

A.The number of page faults will increase ✅
B.The number of page faults will decrease
C.The number of page faults will stay the same
D.The impact cannot be predicted without more information
💡 Difficulty: hard | ✅ Correct: A

📖 Explanation: Doubling the page size reduces the total number of pages needed to represent the same working set, so the system has fewer pages to replace, leading to fewer page faults. Option A suggests the opposite trend, which contradicts the relationship between page count and fault frequency. Option C ignores the effect of page size on page count. Option D is unnecessary because the working set size is given. Understanding this effect guides designers when selecting an optimal page size.

Q6. A computer has 8 GB of total memory, and the operating system reserves 20 % of it for I/O buffers. How much memory is allocated to I/O buffers?

A.2 GB ✅
B.1 GB
C.1.6 GB
D.2.4 GB
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: Twenty percent of 8 GB equals  GB, so the I/O subsystem receives 1.6 GB. Option A (2 GB) corresponds to 25 %, not 20 %. Option B (1 GB) reflects 12.5 %. Option D (2.4 GB) would be 30 %. Converting percentages to actual memory sizes is a common task when configuring system resources.

Q7. Which page‑replacement algorithm is most effective at reducing thrashing in a heavily loaded system?

A.First‑In‑First‑Out (FIFO) ✅
B.Random replacement
C.Second‑chance (clock) algorithm
D.Least‑Recently‑Used (LRU) algorithm
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: LRU replaces the page that has not been used for the longest time, which tends to keep frequently accessed pages in memory and thus cuts down on repeated page faults that cause thrashing. FIFO (Option A) can evict pages still in use, leading to higher fault rates. Random replacement (Option B) lacks any strategy, and the clock algorithm (Option C) approximates LRU but can still suffer more thrashing than true LRU. Knowing the strengths of each algorithm helps administrators choose the best fit for high‑load environments.

Q8. Why is demand paging expected to be transparent to the user?

A.Because it improves utilization and operates without requiring user intervention
B.Because it slows down the system noticeably ✅
C.Because users must manually manage page tables
D.Because it only works on real‑time operating systems
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: Demand paging aims to keep the CPU busy by loading pages only when needed, so users experience smoother performance without noticing the underlying swaps. Option B contradicts the goal of hiding latency. Option C incorrectly assigns responsibility to the user. Option D limits the technique to a niche class of OSes. Recognizing transparency explains why modern OSes can run large applications on limited physical memory.

Q9. Two systems run the same workload: System X reserves a fixed 10 % of memory for I/O buffers, while System Y lets user processes and I/O compete for all memory. Which system is more likely to achieve higher throughput under heavy I/O demand?

A.System X with fixed allocation
B.System Y with shared allocation
C.Both will achieve identical throughput ✅
D.Throughput depends only on CPU speed, not memory allocation
💡 Difficulty: hard | ✅ Correct: C

📖 Explanation: When I/O demand is high, allowing the I/O subsystem to draw from the entire memory pool (System Y) gives it more flexibility to allocate larger buffers, reducing wait times and increasing data transfer rates. Fixed allocation (System X) may starve I/O if the preset 10 % is insufficient. Option C ignores the impact of allocation strategy, and Option D misattributes throughput solely to CPU performance. This scenario illustrates trade‑offs in memory‑allocation policies.

Q10. Which page‑replacement algorithm explicitly replaces the page that has not been used for the longest period of time?

A.Clock algorithm
B.First‑In‑First‑Out (FIFO)
C.Least‑Recently‑Used (LRU) algorithm ✅
D.Not Recently Used (NRU) algorithm
💡 Difficulty: easy | ✅ Correct: C

📖 Explanation: The LRU algorithm tracks usage history and evicts the page whose last reference occurred furthest in the past, matching the description. The Clock algorithm approximates LRU but uses a reference bit, not the exact longest‑unused criterion. FIFO removes pages in arrival order regardless of recent use. NRU groups pages by recent reference but does not guarantee the longest‑unused page is chosen. Understanding LRU helps students grasp why it often yields fewer page faults.
