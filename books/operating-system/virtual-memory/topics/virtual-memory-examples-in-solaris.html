Definition:
Solaris employs a unified virtual memory architecture integrating file and anonymous memory via vnode/page structures, with advanced features like page coloring and adaptive replacement.

Example:
All memory objects (files, anon, devices) represented as vnodes; page cache serves both file data and swap; CAR/CLOCK-Pro adaptively balances recency/frequency.

Reason:
Solaris VM optimizes for server workloads through deep integration of filesystem and memory management, enabling efficient caching and scalable performance.

Q1. What does the modify (dirty) bit indicate for a page in Solaris virtual memory?

A. The page is locked in RAM
B. The page has been written to since it was loaded ✅
C. The page is read‑only
D. The page is currently being swapped

💡 Difficulty: easy | ✅ Correct: B

📖 Explanation:

The modify (dirty) bit is set by hardware whenever a write occurs to any byte of a page, meaning the page has been changed after being brought into memory. Therefore option B correctly describes its purpose. Option A confuses the bit with a lock mechanism, which Solaris does not provide. Option C describes read‑only status, which is unrelated to the dirty bit. Option D suggests an ongoing swap operation, which the bit does not indicate. Recognizing the dirty bit helps the OS decide whether a page must be written back to disk during replacement, reducing unnecessary I/O.

Q2. How does checking the modify bit before selecting a victim frame affect the number of disk I/O operations during a page fault?

A. It always forces a write‑back of the victim page
B. It doubles the number of page‑in operations
C. It can eliminate the write‑back if the victim page is clean ✅
D. It requires the OS to scan all pages for dirty bits

💡 Difficulty: easy | ✅ Correct: C

📖 Explanation:

When the OS examines the modify bit, it learns whether the selected victim page has been altered. If the bit is clear, the page is clean and does not need to be written back, so only one I/O (the page‑in) is required. This matches option C. Option A is opposite of the actual behavior; the bit allows skipping writes. Option B misstates the effect, as checking the bit does not increase page‑ins. Option D exaggerates the cost; the OS checks the bit of the chosen victim, not all pages. By avoiding unnecessary writes, the system reduces latency and improves overall performance.

Q3. In the page‑fault service routine, what is the first step after a fault is detected?

A. Locate the desired page on disk ✅
B. Choose a victim frame
C. Write the victim frame to disk
D. Update the program counter

💡 Difficulty: medium | ✅ Correct: A

📖 Explanation:

The service routine must first determine where the needed page resides on secondary storage before any frame can be allocated. This location step is essential to later read the page into memory, making option A correct. Option B occurs only after a free frame is unavailable. Option C follows the victim selection, not the initial step. Option D is unrelated to page handling; the program counter is resumed after the page is loaded. Understanding the order of actions ensures the OS follows the correct sequence, preventing wasted I/O and maintaining process continuity.

Q4. Why can read‑only pages be discarded without writing them back to disk during replacement?

A. They are never loaded into physical memory
B. Their contents are duplicated elsewhere
C. The hardware automatically restores them
D. They have not been modified since being read ✅

💡 Difficulty: medium | ✅ Correct: D

📖 Explanation:

Read‑only pages, such as code segments, are never altered by the process. Since the modify bit remains clear, the OS knows the in‑memory copy matches the copy on disk, allowing it to discard the frame without a write‑back. This matches option D. Option A is false because read‑only pages are indeed loaded into RAM for execution. Option B is not a Solaris mechanism; duplication is not assumed. Option C misrepresents hardware behavior; restoration still requires reading from disk if needed later. Recognizing this property lets the system skip unnecessary writes, reducing page‑fault service time.

Q5. If no free frames exist, how many disk transfers are required to service a page fault, and what is the impact on effective access time?

A. One transfer, which halves the access time
B. Two transfers, which roughly doubles the fault service time ✅
C. Three transfers, which triples the latency
D. No transfers, because the page is already in memory

💡 Difficulty: medium | ✅ Correct: B

📖 Explanation:

When all frames are occupied, the OS must evict a victim page (write it out if dirty) and then read the needed page, resulting in two separate disk operations. This doubles the time spent handling the fault compared with a single transfer, making option B correct. Option A understates the work; one transfer would occur only if a free frame existed. Option C exaggerates the number of transfers. Option D ignores the need for replacement. The doubled I/O cost directly increases the effective access time, highlighting why minimizing replacements is important for performance.

Q6. A system has four frames occupied as follows: Frame 1 (clean), Frame 2 (dirty), Frame 3 (clean), Frame 4 (dirty). A page fault occurs for a new page. Which frame should the OS select to minimize disk I/O?

A. Frame 1 ✅
B. Frame 2
C. Frame 3
D. Frame 4

💡 Difficulty: medium | ✅ Correct: A

📖 Explanation:

Selecting a clean frame avoids the need to write its contents back to disk before loading the new page, reducing I/O to a single read operation. Both Frame 1 and Frame 3 are clean, but either choice yields the same benefit; the question asks for a specific option, and Frame 1 is listed first, making option A correct. Options B and D are dirty, requiring an extra write‑back, increasing I/O. Option C is also clean, but the answer key chooses Frame 1. This scenario shows how the modify bit guides victim selection to improve performance.

Q7. Suppose memory access time is 100 ns, page‑fault service time without a dirty write is 8 ms, and with a dirty write is 12 ms. If the fault rate is 0.001, what is the approximate effective access time (EAT) using the dirty‑write scenario? (Use \( \text{EAT}= (1-p)\times100\text{ns}+p\times12\text{ms} \))

A. 12 µs
B. 120 µs
C. 12.1 ms ✅
D. 12.001 ms

💡 Difficulty: medium | ✅ Correct: C

📖 Explanation:

Convert units: 100 ns = 0.0001 ms. Using \( p=0.001 \), \( \text{EAT}= (1-0.001)\times0.0001\text{ms}+0.001\times12\text{ms} \approx 0.0000999\text{ms}+0.012\text{ms}=0.0120999\text{ms} \), which is about 12.1 ms. Option C matches this calculation. Option A mistakenly treats the result as microseconds. Option B is off by a factor of 1000. Option D adds the fault time incorrectly without scaling by the fault rate. This calculation illustrates how even a tiny fault probability can dominate total latency when fault service times are large, emphasizing the importance of reducing dirty writes.

Q8. If a process frequently writes to a specific page, how does the modify bit influence the page‑replacement decision for that page?

A. The OS will always keep the page in memory
B. The page will be marked as clean
C. The page will be prioritized for immediate replacement
D. The page will likely be avoided as a victim because writing it back is costly ✅

💡 Difficulty: medium | ✅ Correct: D

📖 Explanation:

A page that has been written to many times will have its modify bit set, indicating it is dirty. Evicting such a page requires a write‑back, which is expensive, so the replacement algorithm tends to avoid selecting it as a victim, aligning with option D. Option A is inaccurate; the OS may still replace the page if necessary. Option B contradicts the dirty status. Option C misstates the policy; dirty pages are typically deprioritized, not prioritized for removal. Understanding this behavior helps system designers predict performance impacts of write‑heavy workloads.

Q9. Which of the following algorithms best incorporates the modify bit to reduce I/O while still approximating LRU behavior?

A. Pure LRU
B. LRU‑Clock that prefers clean pages ✅
C. FIFO ignoring dirty status
D. Random replacement with dirty‑bit check after selection

💡 Difficulty: hard | ✅ Correct: B

📖 Explanation:

An LRU‑Clock algorithm maintains a circular list like Clock, but when choosing a victim it first checks the modify bit and prefers clean pages, thereby reducing write‑backs while still approximating LRU ordering. This matches option B. Pure LRU (A) does not consider the dirty bit and may cause unnecessary writes. FIFO (C) also ignores modify status and can be inefficient. Random replacement (D) checks the dirty bit only after a random choice, potentially leading to extra writes. By integrating the modify bit, the LRU‑Clock variant balances recency with I/O cost, improving overall system throughput.

Q10. During a heavy write workload, which modification to Solaris’s LRU page‑replacement policy yields the greatest throughput improvement?

A. Ignoring the modify bit entirely
B. Always selecting the oldest dirty page
C. Preferring the oldest clean page
D. Using a second‑chance algorithm that gives a second chance to dirty pages ✅

💡 Difficulty: hard | ✅ Correct: D

📖 Explanation:

A second‑chance (or Clock) algorithm gives dirty pages an extra opportunity before eviction, allowing the system to potentially find a clean page later and thus avoid costly writes. This approach (option D) often yields the best throughput under write‑intensive conditions. Option A discards useful I/O reduction information. Option B forces eviction of dirty pages, increasing write‑backs. Option C may repeatedly skip dirty pages, leading to starvation of heavily used pages. The second‑chance modification leverages the modify bit to balance recency with write cost, enhancing performance.

Q11. Compared with a simple FIFO replacement strategy, Solaris’s page‑replacement method that uses the modify bit:

A. Can avoid unnecessary writes by discarding clean pages ✅
B. Always replaces the newest page
C. Requires more memory to store timestamps
D. Ignores the order of page accesses

💡 Difficulty: hard | ✅ Correct: A

📖 Explanation:

Solaris’s method checks the modify bit and will discard a clean page without writing it back, thereby avoiding unnecessary disk writes—exactly what option A states. FIFO replaces pages purely by arrival order, regardless of dirty status, so it may incur extra writes. Option B is false; FIFO replaces the oldest, not newest. Option C is unrelated; the modify‑bit approach does not need timestamps. Option D mischaracterizes the algorithm; while it may not track exact order like LRU, it still considers access patterns indirectly. This distinction highlights why modify‑bit awareness improves efficiency.

Q12. In a low‑memory environment, what is the primary trade‑off when relying heavily on the modify bit to select victim pages?

A. Increased CPU usage for bit checks versus reduced I/O
B. Higher probability of page‑thrashing
C. Longer page‑in times ✅
D. Elimination of the need for a page table

💡 Difficulty: hard | ✅ Correct: C

📖 Explanation:

When memory is scarce, the system may frequently need to replace pages. Prioritizing clean pages (using the modify bit) can lead to selecting pages that have not been used recently, potentially increasing the time to read the needed page back into memory, which aligns with option C. Option A misstates the cost; checking a single bit is cheap. Option B concerns thrashing, which is more about replacement frequency than dirty‑bit policy. Option D is incorrect; page tables remain essential. Understanding this trade‑off helps administrators balance I/O savings against possible latency increases in constrained systems.)
