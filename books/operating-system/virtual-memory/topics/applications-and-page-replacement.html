📝 Applications and page replacement (8 MCQs)

Definition:

Applications and page replacement describe how virtual memory algorithms manage the pages used by running programs. Different applications exhibit different access patterns, so selecting suitable replacement policies matters. Without effective replacement, frequently needed pages may repeatedly leave memory, increasing page faults and slowing applications.

Working:

An application generates a sequence of virtual page references as instructions execute. The operating system observes or estimates this behavior and applies a replacement policy when frames are exhausted. Locality, working-set size, and access frequency influence which pages should remain resident.

Example:

A text editor repeatedly accesses code pages 1 and 2 while occasionally opening page 8. With three available frames, a locality-aware policy can retain frequently used pages 1 and 2 while replacing less useful pages.

Reason:

Understanding application behavior helps select policies that reduce unnecessary page faults. Unlike using one blindly applied replacement strategy, workload-aware memory management considers locality and working sets, improving responsiveness across applications with different access patterns.

Common Misconceptions:

'Every application accesses pages in the same pattern' is incorrect because workloads differ. 'A page used once should always remain resident' is incorrect because later demand matters. 'One replacement algorithm always performs best' is incorrect because access patterns vary.

Exam Preparation Tips: How to prepare this topic

Study locality and working-set behavior. Trace application reference strings. Compare replacement policies under different workloads. Exams commonly ask how access patterns affect page faults and why frequently used pages should remain available.

Key Terms:

  • Application workload - the memory-access behavior of a program.
  • Locality - the tendency to reuse nearby or recent data.
  • Reference string - an ordered sequence of page accesses.
  • Working set - pages actively needed during a reference window.
  • Replacement policy - the rule used to select victim pages.

📝 All Applications and page replacement MCQs

Q1. A process currently has only page 2 resident in memory. The next CPU reference is to page 2. What does the lazy swapper do?

A.It issues a page fault and loads page 2 from disk.
B.It finds page 2 already valid and continues execution. ✅
C.It swaps out another page to make room for page 2.
D.It terminates the process due to invalid reference.
💡 Difficulty: easy | ✅ Correct: B

📖 Explanation: The lazy swapper checks the valid‑invalid bit before accessing a page. Since page 2 is already resident, the bit is marked valid, so the CPU proceeds without a fault. Option B correctly describes this behavior. Option A is wrong because a page fault occurs only when the page is not in memory. Option C is incorrect; no replacement is needed when the page is already present. Option D is false because an invalid reference would trigger a fault, not terminate the process. This illustrates how lazy swapping avoids unnecessary disk I/O.

Q2. Why is a lazy swapper preferred over swapping the entire process when using demand paging?

A.It reduces disk I/O by loading only needed pages. ✅
B.It guarantees that all pages are always in memory.
C.It eliminates the need for a page table.
D.It increases the size of the swap file.
💡 Difficulty: easy | ✅ Correct: A

📖 Explanation: A lazy swapper brings in pages only when they are referenced, which cuts down on the amount of data transferred between disk and memory. This reduction in I/O speeds up program start‑up and saves physical memory. Option A captures this advantage. Option B is opposite to the lazy approach, which does not keep all pages resident. Option C is inaccurate because a page table is still required to track page locations. Option D is unrelated; lazy swapping does not affect swap‑file size.

Q3. What does the “valid” setting of the valid–invalid bit indicate in a page‑table entry?

A.The page is illegal and cannot be accessed.
B.The page is currently stored on disk.
C.The page is legal and present in physical memory. ✅
D.The page is reserved for future use.
💡 Difficulty: medium | ✅ Correct: C

📖 Explanation: When the valid bit is set, the operating system knows the page is part of the process’s address space and that a physical frame holds its contents, so memory can be accessed directly. Option C states this precisely. Option A describes an illegal page, which would be marked invalid. Option B corresponds to an invalid bit that may point to a disk location, not a valid bit. Option D is not a standard meaning of the valid bit. Understanding this distinction is key for correct handling of page faults.

Q4. Given a reference string 1,2,3,2,4,1,2,3,4 and three frames, which page‑replacement algorithm will incur the fewest page faults under a lazy swapping policy?

A.FIFO
B.LRU ✅
C.Random
D.Optimal (theoretical)
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: LRU replaces the page that has not been used for the longest time, which matches the pattern of the reference string and results in fewer faults than FIFO, which discards pages in arrival order. Option B is correct. FIFO (Option A) would replace pages too early, causing extra faults. Random (Option C) is generally less efficient. The optimal algorithm (Option D) is theoretical and not implementable; it would give the minimum possible faults but is not a practical policy. This scenario shows how lazy swapping works with different replacement strategies.

Q5. How does the pager decide which pages to bring into memory when a process is swapped in?

A.It loads all pages whose valid–invalid bit is set to invalid.
B.It predicts future references and loads pages likely to be used soon. ✅
C.It randomly selects pages from the process’s address space.
D.It loads pages in alphabetical order of their identifiers.
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: The pager uses heuristics such as locality of reference to guess which pages will be needed next, loading those ahead of time to reduce page faults. This predictive behavior is described in option B. Option A would load every invalid page, defeating the purpose of lazy swapping. Option C suggests randomness, which provides no performance benefit. Option D is nonsensical because page identifiers have no alphabetical order. Predictive loading is the core idea behind efficient demand paging.

Q6. If memory access time is 0.1 ms, page‑fault service time is 10 ms, and the page‑fault rate is \(p\), what is the effective access time (EAT) using lazy swapping?

A.\(EAT = 0.1 + p \times 10\)
B.\(EAT = 0.1 \times (1-p) + 10 \times p\)
C.\(EAT = 0.1 \times (1-p) + (0.1 + 10) \times p\) ✅
D.\(EAT = 10 \times (1-p) + 0.1 \times p\)
💡 Difficulty: hard | ✅ Correct: C

📖 Explanation: The effective access time combines the time for a normal memory reference and the extra cost when a fault occurs: \((1-p) \times 0.1\) for hits plus \(p \times (0.1+10)\) for faults, giving option C. Option A omits the hit probability factor. Option B uses the wrong fault cost, missing the memory access that still occurs during a fault. Option D swaps the coefficients, implying faults happen on hits. This formula is essential for evaluating the impact of lazy swapping on overall system performance.

Q7. Compare lazy swapping with pre‑paging. Which statement best describes their trade‑off?

A.Lazy swapping always yields fewer page faults than pre‑paging.
B.Pre‑paging may load unnecessary pages, increasing I/O, while lazy swapping avoids that at the risk of more faults. ✅
C.Lazy swapping requires more RAM than pre‑paging.
D.Pre‑paging eliminates the need for a valid‑invalid bit.
💡 Difficulty: hard | ✅ Correct: B

📖 Explanation: Pre‑paging brings in a block of pages before they are referenced, which can cause extra disk reads if some pages are never used; lazy swapping loads pages only on demand, reducing unnecessary I/O but potentially incurring more page faults. Option B captures this balance. Option A is false because pre‑paging can sometimes reduce faults. Option C is incorrect; lazy swapping does not need more RAM. Option D is wrong because both techniques still rely on the valid‑invalid bit to track page residency. Understanding this trade‑off helps designers choose the appropriate strategy.

Q8. A program’s working set requires 12 pages, but the system has only 10 frames. What is the most likely effect, and how does lazy swapping influence it?

A.The system will run faster because lazy swapping caches extra pages.
B.The system will experience thrashing; lazy swapping may increase fault frequency because pages are loaded only when needed. ✅
C.The system will never swap pages because lazy swapping keeps all pages in memory.
D.The system will swap out the entire process each time a new page is needed.
💡 Difficulty: hard | ✅ Correct: B

📖 Explanation: When the working set exceeds available frames, the system repeatedly evicts and reloads pages, causing thrashing. Lazy swapping exacerbates this by loading pages only on demand, which can lead to a high page‑fault rate as each new reference triggers a swap. Option B correctly describes the outcome. Option A is opposite to the expected slowdown. Option C misrepresents lazy swapping, which does not keep all pages resident. Option D describes a full‑process swap, not the page‑level behavior of lazy swapping. This scenario highlights the importance of matching working‑set size to physical memory.
