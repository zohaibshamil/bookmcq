📝 All TLB reach in Virtual Memory MCQs

Q1. A process triggers a page fault while all frames are occupied. Which action is most commonly taken by the operating system to resolve the fault?

A.Terminate the process immediately
B.Swap out a process to free its frames ✅
C.Allocate additional frames beyond physical memory
D.Ignore the fault and continue execution
💡 Difficulty: easy | ✅ Correct: B

📖 Explanation: Swapping out a process is the standard response when no free frames exist. The OS selects a victim process, writes its pages to swap, and releases those frames for the faulting page. Terminating the process would waste work, allocating extra frames is impossible without virtual memory tricks, and ignoring the fault would crash the program. This mirrors real systems where swapping maintains progress while preserving user work.

Q2. Given the reference string 7,0,1,2,0,3,0,4,2,3,0,3,2 and three physical frames, which replacement policy results in the fewest page faults?

A.First-In‑First‑Out (FIFO)
B.Optimal (OPT)
C.Least‑Recently‑Used (LRU) ✅
D.Random (RAND)
💡 Difficulty: medium | ✅ Correct: C

📖 Explanation: LRU replaces the page that has not been used for the longest time, which matches the pattern of the reference string and yields fewer faults than FIFO, which evicts pages in arrival order regardless of recent use. OPT would be ideal but is not implementable; RAND is unpredictable. In practice, LRU‑like heuristics are chosen because they minimize faults, improving system performance.

Q4. A TLB contains 128 entries. Which page size gives the greatest TLB reach: 2 KB, 4 KB, 8 KB, or 16 KB?

A.256 KB
B.512 KB
C.1 MB
D.2 MB ✅
💡 Difficulty: hard | ✅ Correct: D

📖 Explanation: TLB reach is calculated as entries × page size. For 128 entries: 2 KB → 256 KB, 4 KB → 512 KB, 8 KB → 1 MB, 16 KB → 2 MB. The largest reach comes from the 16 KB page size, providing 2 MB of address space covered by the TLB. Smaller pages give proportionally smaller reaches, limiting the fraction of memory that benefits from fast translation.

Q6. Why does increasing the number of TLB entries generally improve effective memory access time?

A.It reduces the number of page faults ✅
B.It increases the likelihood of TLB hits
C.It lowers the CPU clock speed
D.It expands physical memory capacity
💡 Difficulty: easy | ✅ Correct: A

📖 Explanation: More TLB entries mean a higher probability that a virtual‑to‑physical translation is already cached, so the CPU can fetch data without a costly page‑table walk. This directly reduces average memory access time. Increasing entries does not affect page‑fault frequency, CPU frequency, or physical memory size; those are unrelated system attributes.

Q7. How does the choice of page‑replacement algorithm influence the TLB reach of a system?

A.It changes the number of TLB entries
B.It alters the page size ✅
C.It does not directly affect TLB reach
D.It expands physical memory
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: Page‑replacement algorithms decide which resident page to evict when memory is full, but they do not modify the TLB’s structure or the size of pages. Consequently, the TLB reach—defined by entries × page size—remains unchanged regardless of whether FIFO, LRU, or another policy is used. The algorithm impacts overall performance, not the static coverage of the TLB.

Q8. In a demand‑paging environment, what is the primary effect of a high TLB miss rate on system throughput?

A.Higher cache coherence
B.Reduced throughput due to extra page‑table walks and possible faults
C.Increased disk I/O bandwidth ✅
D.Lower CPU temperature
💡 Difficulty: hard | ✅ Correct: C

📖 Explanation: Each TLB miss forces the processor to walk the page table, which consumes cycles and may trigger a page fault if the needed page is not in memory. These extra delays lower the number of instructions completed per unit time, thus decreasing overall throughput. The other options describe unrelated phenomena: cache coherence, disk bandwidth, and temperature are not direct consequences of TLB misses.
