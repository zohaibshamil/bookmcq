📝 Frames Allocation algorithms

📖 From Operating System • 9. Virtual Memory • 9 questions available

What is Frames Allocation algorithms?

Definition:
Frame allocation algorithms determine how available physical frames are distributed among competing processes, either equally or proportionally based on size or priority.

Example:
Equal allocation gives each of \( n \) processes \( m/n \) frames; proportional allocation assigns \( (size_i / \sum size_j) \times m \) frames to process \( i \) based on virtual memory size.

Reason:
Fair and efficient allocation balances multiprogramming degree with individual process needs, preventing starvation while maximizing overall system utilization.

Q1. What does the valid‑invalid bit in a page‑table entry indicate?

A. Whether the page is currently loaded in physical memory ✅
B. The protection level of the page
C. The physical frame number assigned to the page
D. The size of the page

💡 Difficulty: easy | ✅ Correct: A

📖 Explanation:

The valid‑invalid (or present) bit tells the operating system if the page is resident in a frame. When the bit is set to 1, a memory reference can be satisfied directly; when it is 0, the CPU raises a page‑fault trap, causing the OS to bring the page in. Options B, C, and D describe unrelated attributes, so they are incorrect.

Q2. A process accesses pages 0,2,4,2,0,5 sequentially. The system has 3 free frames and uses demand paging. How many page faults will occur?

A. Exactly 2 page faults
B. Exactly 4 page faults ✅
C. Exactly 6 page faults
D. Exactly 3 page faults

💡 Difficulty: medium | ✅ Correct: B

📖 Explanation:

The first three distinct pages (0,2,4) each cause a fault and fill the three frames. The next accesses to 2 and 0 hit those frames, incurring no faults. The final reference to page 5 requires a replacement, producing a fourth fault. Thus the total is four faults. Options A, C, and D miscount either hits or replacements, making them wrong.

Q3. Why does marking a page invalid have no effect if the process never accesses that page?

A. Because the OS will automatically load the page ✅
B. Because the CPU ignores invalid bits
C. Because the page will never be referenced, so no fault occurs
D. Because the page is already in cache

💡 Difficulty: medium | ✅ Correct: A

📖 Explanation:

If a page is never referenced, the CPU never checks its valid‑invalid status, so no page‑fault trap is generated and the marking does nothing. Option A is false because loading occurs only on a fault. Option B is incorrect; the CPU does examine the bit when a reference occurs. Option D is unrelated to virtual memory mechanisms.

Q4. In a demand‑paging system, which algorithm chooses the page with the longest future reference interval?

A. FIFO
B. LRU
C. Optimal ✅
D. Second‑chance

💡 Difficulty: medium | ✅ Correct: C

📖 Explanation:

The Optimal algorithm (also called Bélády’s algorithm) evicts the page that will not be used for the longest period in the future, minimizing faults. FIFO removes the oldest loaded page regardless of future use, LRU removes the least recently used, and Second‑chance is a practical approximation of FIFO. Therefore only option C correctly describes the optimal strategy.

Q5. Consider a system with 8 frames and a reference string \\( \\langle 1,2,3,4,1,2,5,1,2,3,4,5 \\rangle \\). Using the Clock algorithm with reference bits initially 0, how many page faults occur?

A. 8
B. 9 ✅
C. 10
D. 11

💡 Difficulty: hard | ✅ Correct: B

📖 Explanation:

Starting with empty frames, the first eight distinct references (1‑4, then 5) generate faults, filling all frames. The Clock pointer cycles, giving each page a second chance; when 1 and 2 are referenced again, their bits are set, preventing immediate eviction. The final references cause two more faults as pages 3,4,5 replace previously cleared pages, totaling nine faults. Options A, C, and D either underestimate or overestimate the replacements.

Q6. How does the valid‑invalid bit interact with a page‑replacement algorithm when a page is evicted from a frame?

A. The bit is set to valid and the frame number is cleared
B. The bit remains unchanged and the frame number is updated
C. The bit is cleared to invalid and the frame is marked free ✅
D. The bit toggles between valid and invalid each time

💡 Difficulty: hard | ✅ Correct: C

📖 Explanation:

When a page is removed from physical memory, the OS must indicate that it is no longer present, so the valid‑invalid bit is cleared (set to 0). The frame becomes available for another page, and the page‑table entry retains the frame number until it is reused. Options A and D describe impossible behaviors, and B fails to mark the page as absent.

Q7. What is the main advantage of demand paging over pre‑paging regarding memory utilization?

A. It reduces disk I/O by loading all pages at once ✅
B. It ensures every page is loaded before execution
C. It loads only pages that are actually needed, saving memory
D. It eliminates the need for a page table

💡 Difficulty: medium | ✅ Correct: A

📖 Explanation:

Demand paging brings a page into memory only when a process actually references it, which conserves RAM and reduces unnecessary I/O. Pre‑paging loads a fixed set of pages regardless of need, potentially wasting space. Option A is opposite; pre‑paging increases I/O. Option B is inaccurate, and option D is unrelated to paging strategy.

Q8. A program attempts to write to a page that is marked invalid. What immediate action does the operating system take?

A. Terminate the program
B. Ignore the write
C. Generate a page‑fault trap to load the page ✅
D. Swap out another page

💡 Difficulty: easy | ✅ Correct: C

📖 Explanation:

When a reference hits an invalid page, the hardware raises a page‑fault trap, prompting the OS to locate the needed page in backing store and load it into a free frame. Only after the page is valid can the write proceed. Termination occurs only after repeated faults or illegal access, not immediately. Ignoring the write would corrupt data, and swapping out another page is part of the replacement process, not the initial response.

Q9. If a system's page‑fault rate is 0.02 and it makes 500 memory references per second, how many page faults occur per second?

A. 5 ✅
B. 10
C. 20
D. 100

💡 Difficulty: medium | ✅ Correct: A

📖 Explanation:

The number of faults per second equals the fault rate multiplied by total references: \\(0.02 \\times 500 = 10\\). Therefore ten faults occur each second. Option A underestimates by a factor of two, option C overestimates by double, and option D is far too high. This calculation directly applies the definition of fault rate to quantify system performance.
