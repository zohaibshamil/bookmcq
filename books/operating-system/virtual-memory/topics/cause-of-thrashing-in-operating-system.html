What is Cause of thrashing in Operating System?

Definition:
Thrashing occurs when a system spends more time paging than executing useful work due to insufficient frames relative to the aggregate working set size of active processes.

Example:
If total working sets require 100 frames but only 60 are available, processes constantly fault and evict each other’s pages, causing CPU utilization to plummet despite high page fault rates.

Reason:
Thrashing degrades performance catastrophically; recognizing its causes enables preventive measures like admission control or working set monitoring.

Q1. What is the name of the fault that occurs when a process accesses a page with the invalid bit set?

A.Page fault ✅
B.Segmentation fault
C.Bus error
D.General protection fault
💡 Difficulty: easy | ✅ Correct: A

📖 Explanation: A page fault is generated whenever the paging hardware finds the invalid bit set for a referenced page. The other choices describe different error conditions unrelated to virtual‑memory paging. Understanding that the invalid‑bit check triggers a trap helps students recognise why the OS must intervene. This directly matches the mechanism that starts the fault‑handling sequence described in the operating‑system model.

Q2. Why does the operating system terminate a process when an invalid page reference is detected?

A.Because the process attempted to read protected kernel memory
B.Because the reference cannot be satisfied by any existing page frame
C.Because the fault indicates a programming error that cannot be corrected by paging ✅
D.Because the OS wants to free memory for other processes
💡 Difficulty: easy | ✅ Correct: C

📖 Explanation: When the internal table shows the reference is truly invalid, no amount of paging can make the page available, so the only safe response is termination. Options A and B describe unrelated protection mechanisms, while D is a policy choice not mandated by the fault semantics. Termination prevents undefined behavior and keeps the system stable.

Q3. How does the internal table kept with the process control block help the OS distinguish between valid and invalid page references?

A.It stores the physical address of every page
B.It records the invalid‑bit status for each virtual page ✅
C.It lists the free frames in the system
D.It contains the program’s instruction pointer
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: The internal table mirrors the page‑table’s invalid bits, allowing the OS to quickly decide if a fault can be remedied by loading a page or must abort the process. The other options either describe unrelated data (free frames, instruction pointer) or misstate the table’s purpose (physical addresses). This distinction is crucial for correctly handling page faults without unnecessary termination.

Q4. Explain why pure demand paging can cause thrashing when the working set exceeds the number of available frames.

A.Because the OS will pre‑load all pages at start‑up ✅
B.Because each page fault forces a disk read, repeatedly evicting pages still needed
C.Because the CPU slows down due to context switches
D.Because the invalid bit is never cleared
💡 Difficulty: hard | ✅ Correct: A

📖 Explanation: When the working set is larger than physical frames, every fault brings in a needed page but must evict another needed page, causing a rapid cycle of faults—thrashing. Pre‑loading (A) does not happen in pure demand paging, and context‑switch overhead (C) is a symptom, not the cause. The invalid bit (D) is unrelated to the repeated replacement behavior.

Q5. What role does the free‑frame list play during page‑fault handling?

A.It determines which process will be scheduled next
B.It provides a pool of unused frames from which the OS can allocate a new page ✅
C.It stores the timestamps of recent page accesses
D.It records the priority of each process
💡 Difficulty: easy | ✅ Correct: B

📖 Explanation: When a fault occurs, the OS must find a physical frame to hold the incoming page. The free‑frame list supplies such a frame without needing to replace an existing one, simplifying the allocation step. The other choices describe scheduling, tracking access history, or priority management—functions handled elsewhere in the OS.

Q6. How does restarting the interrupted instruction after a page fault preserve program correctness?

A.It re‑executes the instruction with the newly loaded page now present
B.It skips the faulty instruction and continues with the next one ✅
C.It rewrites the instruction to avoid the faulting address
D.It changes the program’s control flow to a safe routine
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: After the page is loaded and the page table updated, the original instruction can be executed again because its operands are now resident in memory. Skipping (B) would change program semantics, while rewriting (C) or altering control flow (D) would corrupt the intended computation. This restart mechanism ensures the program behaves as if the page had always been present.

Q7. A process with 4 allocated frames repeatedly references pages 1‑5 in a round‑robin pattern. Which outcome is most likely?

A.The process will experience zero page faults after the first five references
B.The process will quickly enter a thrashing state with many page faults
C.The operating system will allocate additional frames automatically ✅
D.The page‑fault handler will terminate the process after the first invalid reference
💡 Difficulty: medium | ✅ Correct: C

📖 Explanation: With only four frames but five distinct pages, each reference to the missing page forces a replacement, causing a fault on almost every access—classic thrashing. The first option is impossible because the working set exceeds available frames. Automatic frame allocation (C) does not occur without explicit policy, and termination (D) only happens for truly invalid accesses, not for normal demand paging.

Q8. If the OS begins pre‑fetching the next likely page after a fault, what effect does this have on the overall page‑fault rate?

A.It increases the fault rate because more pages are read unnecessarily ✅
B.It decreases the fault rate by having pages ready before they are referenced
C.It has no effect because pre‑fetching is ignored by the hardware
D.It causes the system to run out of memory instantly
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: Pre‑fetching aims to anticipate future references, so the required page is already in memory when the CPU accesses it, reducing faults. An increase (A) would only happen if the prediction is terrible, which the question does not imply. Hardware does not ignore pre‑fetch requests (C), and memory exhaustion (D) would require extreme over‑fetching, not typical in a modest pre‑fetch scheme.

Q9. During page‑fault handling, which step is missing if the OS fails to update the page table after the disk read completes?

A.Finding a free frame ✅
B.Scheduling the disk operation
C.Modifying the internal table and page table to mark the page as resident
D.Restarting the interrupted instruction
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: If the page table is not updated, the CPU will continue to see the page as invalid, causing another fault on the next access. Finding a free frame (A) and scheduling the disk I/O (B) occur earlier, while restarting the instruction (D) happens after the table update. The missing update directly leads to repeated faults, undermining the whole handling process.

Q10. Given the reference string 7, 0, 1, 2, 0, 3, 0, 4 and three frames using FIFO replacement, how many page faults occur?

A.6
B.7 ✅
C.8
D.9
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: Step‑by‑step: fault on 7 (1), 0 (2), 1 (3), 2 replaces 7 (4), 0 already present, 3 replaces 0 (5), 0 replaces 1 (6), 4 replaces 2 (7). Thus seven faults. Options A, C, and D are off by one or two, showing common counting errors. Knowing the replacement order is essential for correct fault calculation.

Q11. A system with 4 frames uses LRU replacement. For the reference string 1,2,3,4,1,2,5,1,2,3,4,5, which reference most directly triggers thrashing?

A.Reference to page 5 at position 7
B.Reference to page 1 at position 5 ✅
C.Reference to page 3 at position 10
D.Reference to page 4 at position 12
💡 Difficulty: hard | ✅ Correct: B

📖 Explanation: When page 5 is first requested, the frames contain 1,2,3,4; LRU evicts the least recently used page (4), causing a fault. Subsequent accesses to 1,2,3,4 again each cause a fault, creating a rapid fault cycle—thrashing. The earlier references (B) do not cause eviction, and later references (C, D) occur after the thrashing has already begun.

Q13. If the OS mistakenly sets the invalid bit for a valid page, what symptom is most likely to appear?

A.The process will run faster because fewer pages are loaded
B.The process will be terminated immediately on first access to that page ✅
C.The system will ignore the fault and continue execution
D.The page will be swapped out repeatedly without faulting
💡 Difficulty: hard | ✅ Correct: B

📖 Explanation: Marking a valid page as invalid causes the hardware to raise a page fault each time the page is accessed. Because the OS believes the reference is illegal, it will terminate the process rather than load the page. The other options describe opposite behaviors or no‑fault scenarios, which do not match the described error.
