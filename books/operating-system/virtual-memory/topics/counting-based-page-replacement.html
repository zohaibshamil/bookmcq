📝 Counting based page replacement

📖 From Operating System • 9. Virtual Memory • 8 questions available

What is Counting based page replacement?

Definition:
Counting-based algorithms maintain a counter for each page that tracks reference frequency or recency, using these counts to guide replacement decisions beyond simple timestamps.

Example:
LFU (Least Frequently Used) evicts the page with smallest count, while MFU evicts the highest; counters may be aged periodically to prevent stale high counts from blocking replacement.

Reason:
These methods capture usage patterns better than pure recency, though they require careful tuning to avoid pitfalls like permanently retaining rarely-used-but-once-accessed pages.

Q1. What type of page-replacement algorithm selects the page with the smallest reference count for eviction?

A. Least Recently Used
B. First-In First-Out
C. Least Frequently Used ✅
D. Clock

💡 Difficulty: easy | ✅ Correct: C

📖 Explanation:

The algorithm that evicts the page with the smallest reference count is called Least Frequently Used (LFU). Option C correctly names LFU. Option A describes LRU, which bases decisions on recency, not frequency, so it would not necessarily pick the smallest count. Option B is FIFO, which removes the oldest loaded page regardless of count. Option D, the Clock algorithm, approximates LRU using a use bit, not a count. LFU directly matches the definition, making C the correct choice.

Q2. Why does a counting-based replacement algorithm typically generate fewer page faults than a pure FIFO scheme?

A. It removes the most frequently used pages
B. It removes the least frequently used pages ✅
C. It removes the newest pages
D. It removes pages at random

💡 Difficulty: easy | ✅ Correct: B

📖 Explanation:

Counting-based algorithms keep a counter for each page and evict the one with the lowest count, i.e., the least frequently used page. This tends to keep pages that are accessed often, reducing the chance of a future fault. Option B states this behavior. Option A is opposite, removing heavily used pages, which would increase faults. Options C and D describe unrelated strategies, so they are incorrect.

Q3. A system tracks page reference counts over the last 1,000 accesses. Page X has count 5, Page Y count 20, and Page Z count 2. A new page must be loaded. Which page should be evicted under a counting-based algorithm?

A. Page X
B. Page Y
C. Page Z ✅
D. No eviction needed

💡 Difficulty: medium | ✅ Correct: C

📖 Explanation:

Counting-based replacement chooses the page with the smallest reference count because it is the least frequently used. Among the three pages, Z has the lowest count (2), so it is the best candidate for eviction. Option C correctly identifies Page Z. Option A (Page X) and B (Page Y) have higher counts and would be kept longer. Option D is impossible because a new page requires a free frame, so eviction is mandatory.

Q4. Compared to LRU, what hardware overhead does a counting-based page-replacement algorithm primarily require?

A. A timer for each page
B. A simple counter per page ✅
C. No extra hardware
D. A stack of page identifiers

💡 Difficulty: medium | ✅ Correct: B

📖 Explanation:

A counting-based scheme needs to maintain a numeric counter for each page to record how often it is accessed. This is a modest hardware addition: a small register per page. Option B captures this requirement. LRU typically needs timestamps or a stack to track order, which can be more complex than a single counter. Option A describes a timer, which is not necessary for simple counting. Options C and D describe either no overhead or a data structure unrelated to counting, making them incorrect.

Q5. Three pages A, B, and C reside in memory with reference counters A=7, B=3, and C=5. A fourth page D needs to be loaded. Which page will be replaced by the counting-based algorithm?

A. Page A
B. Page B ✅
C. Page C
D. No replacement needed

💡 Difficulty: medium | ✅ Correct: B

📖 Explanation:

The counting-based algorithm evicts the page with the lowest reference count because it is the least frequently used. Here, page B has the smallest count (3), so it will be selected for replacement. Option B correctly identifies page B. Pages A and C have higher counts (7 and 5) and are therefore more valuable to keep. Option D is impossible because a new page must occupy a frame, requiring eviction of an existing page.

Q6. How can a counting-based replacement algorithm cause cache pollution when a page receives many accesses in a short burst and then becomes idle?

A. Counters retain high values after the burst ✅
B. Counters are reset too frequently
C. It treats all accesses equally
D. It only tracks recency

💡 Difficulty: hard | ✅ Correct: A

📖 Explanation:

When a page is accessed heavily in a brief period, its counter climbs to a high value. If the algorithm does not decay or reset counters, that high value persists even after the page becomes idle, preventing its eviction and causing other useful pages to be displaced—a phenomenon known as cache pollution. Option A describes this exact situation. Option B would actually mitigate pollution, not cause it. Option C is unrelated, and option D describes LRU, not counting‑based behavior.

Q7. In a system using 8‑bit saturating counters (max = 255) for page frequencies, many pages eventually reach the maximum value. Which strategy best restores discrimination among pages?

A. Periodically reset all counters ✅
B. Replace counters with larger bit‑width
C. Switch to a pure LRU policy
D. Ignore the counters entirely

💡 Difficulty: hard | ✅ Correct: A

📖 Explanation:

When counters saturate at 255, they can no longer distinguish between frequently used pages, so all appear equally popular. Periodically resetting the counters restores their ability to differentiate recent usage patterns, making option A the most effective fix. Option B would also work but requires hardware changes; the question asks for the best immediate strategy. Options C and D abandon counting altogether, which defeats the purpose of a counting‑based scheme.

Q8. A web server caches 4 pages. Their hit counts after a day are: P1=120, P2=45, P3=78, P4=30. A new page P5 is requested. Which page will the counting-based replacement algorithm evict?

A. P1
B. P2
C. P3
D. P4 ✅

💡 Difficulty: medium | ✅ Correct: D

📖 Explanation:

The counting-based algorithm evicts the cached page with the lowest hit count because it is the least frequently accessed. Among the cached pages, P4 has the smallest count (30), making it the prime candidate for eviction to make room for P5. Option D correctly identifies P4. Options A, B, and C have higher counts and would be retained longer under the algorithm.
