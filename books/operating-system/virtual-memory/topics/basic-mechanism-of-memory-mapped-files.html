What is Basic mechanism of Memory Mapped Files?

Definition:
Memory-mapped files allow file contents to be accessed as if they were part of a process’s virtual address space, with the OS handling transparent loading and flushing.

Example:
Mapping file to virtual addresses means reading triggers page fault if unmapped, fetching corresponding file block into RAM automatically.

Reason:
This eliminates explicit read/write syscalls and enables efficient random access, sharing, and caching through the virtual memory subsystem.

📝 All Basic mechanism of Memory Mapped Files MCQs

Q1. What does the copy-on-write (COW) technique primarily aim to reduce when a process forks?

A.Memory usage ✅
B.CPU cycles
C.Disk I/O
D.Network latency
💡 Difficulty: easy | ✅ Correct: A

📖 Explanation: Copy‑on‑write creates a shared physical page until one process writes to it, at which point a separate copy is made. This sharing avoids allocating a full set of duplicate pages, directly reducing the amount of memory consumed. Options B, C, and D describe unrelated performance aspects; they are not the primary goal of COW. By saving memory, COW lets more processes run concurrently on the same hardware.

Q2. Which term describes pages that are cleared to zero before being handed to a process?

A.Zero-fill-on-demand ✅
B.Lazy allocation
C.Dirty page
D.Copy-on-write
💡 Difficulty: easy | ✅ Correct: A

📖 Explanation: Zero-fill-on-demand pages are pre‑cleared to all zeros before allocation, ensuring no leftover data from previous owners remains. This protects security and provides a clean starting state. The other terms refer to different mechanisms: lazy allocation delays mapping, dirty pages have been modified, and copy‑on‑write deals with sharing until a write occurs. Hence, zero‑fill-on-demand is the correct description.

Q3. Why are pages that contain executable code typically not marked as copy‑on‑write?

A.Because they are read‑only and never need a private copy ✅
B.Because they are too large to copy
C.Because the OS cannot track execution
D.Because they cause page faults
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: Executable code pages are loaded as read‑only, so neither parent nor child will attempt to modify them. Since no write occurs, there is no need to create a private copy, and the pages can remain shared safely. The other options are inaccurate: size does not prevent copying, the OS can track execution, and page faults happen only on writes, not reads.

Q4. When a child process writes to a stack page that was marked copy‑on‑write, what happens to the original parent page?

A.It remains unchanged and shared ✅
B.It is immediately deleted
C.It is swapped to disk
D.It becomes read‑only
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: The parent’s page stays intact because the child’s write triggers a copy operation, leaving the original page untouched for the parent. Deletion would break the parent’s execution, swapping is unrelated to the write event, and the original page is already read‑only, so no change is needed. This behavior preserves isolation while still allowing sharing of unmodified pages.

Q5. A system has a pool of 5 free pages. Process 1 forks, and the child immediately writes to two distinct pages marked copy‑on‑write. How many free pages are consumed for the child’s copies?

A.2 ✅
B.3
C.5
D.0
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: Each write to a copy‑on‑write page forces the OS to allocate a new physical page for the child’s private copy. With two writes, two free pages are taken from the pool, leaving three still available. No additional pages are needed for the parent, and no pages are freed during the operation, so the correct count is two.

Q6. If a process modifies three pages after a fork, and the system initially shared all pages, how many total physical pages exist for those three after the modifications?

A.Six ✅
B.Three
C.Four
D.Five
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: Initially, parent and child share three pages. When the child modifies each page, a separate copy is allocated for each, adding three new pages. The parent still holds the original three, so the total becomes six physical pages representing those three logical pages across both processes.

Q7. How does copy‑on‑write interact with a page‑replacement algorithm like LRU?

A.COW pages are less likely to be evicted because they are shared
B.COW pages are always kept in memory
C.COW does not affect replacement decisions directly ✅
D.COW forces immediate replacement
💡 Difficulty: medium | ✅ Correct: C

📖 Explanation: Copy‑on‑write itself does not change the criteria used by LRU; pages are still evicted based on recent use. However, because shared pages can serve two processes, they might be accessed more frequently, indirectly influencing LRU decisions. The other statements overstate the effect or claim actions that do not occur.

Q8. When the free‑page pool is exhausted and a copy‑on‑write fault occurs, what is the OS most likely to do?

A.Delay the fault until a page is freed ✅
B.Terminate the process
C.Allocate a page from swap space
D.Ignore the fault
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: If no free pages are immediately available, the OS typically triggers a page‑replacement operation to free a page, then fulfills the copy‑on‑write request. Delaying the fault until a page becomes free allows the process to continue without termination. Allocating from swap or ignoring the fault would either be unnecessary or break memory consistency.

Q9. In a system that uses both zero‑fill‑on‑demand and copy‑on‑write, what order of operations occurs when a child process receives a new page after a fork?

A.Zero‑fill first, then mark as COW if needed ✅
B.Mark as COW first, then zero‑fill
C.Allocate without zero‑fill
D.Allocate without marking COW
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: When a new page is needed for the child, the OS first obtains a zero‑filled page to ensure no residual data remains. After the page is assigned, if the page can be written, it is marked copy‑on‑write so future writes trigger a private copy. This sequence guarantees both security (zero‑fill) and efficient sharing (COW).

Q10. Why are executable code pages typically shared between parent and child after a fork?

A.They are read‑only and never need a private copy ✅
B.They are small enough to fit in cache
C.They contain no useful data
D.They are always swapped out
💡 Difficulty: hard | ✅ Correct: A

📖 Explanation: Executable sections are loaded as read‑only, meaning neither process will attempt to modify them. Because no write occurs, the OS can keep a single physical copy and map it into both address spaces, saving memory. The other options either mischaracterize the nature of code pages or describe unrelated behaviors.

Q11. A diagram shows process 1 with pages A, B, C and process 2 with a copy of page C after a fork. If the child modifies page C, which pages will now exist in physical memory?

A.Pages A, B, original C, and a new copy of C
B.Pages A, B, and only one C
C.Pages A, B, and two copies of C ✅
D.Only page C
💡 Difficulty: hard | ✅ Correct: C

📖 Explanation: When the child writes to its copy of page C, the OS allocates a new physical page for the child’s version, leaving the original page C for the parent. Consequently, physical memory contains pages A, B, the original C, and the newly created copy of C, totaling four distinct pages.

Q12. During a copy‑on‑write page fault, which sequence correctly describes the OS actions?

A.Allocate a free page, copy contents, update mappings, clear COW flag ✅
B.Swap out the page, then allocate a new one
C.Mark the page as read‑only, then pause the process
D.Immediately terminate the process
💡 Difficulty: hard | ✅ Correct: A

📖 Explanation: The OS first obtains a free physical page, copies the contents of the original shared page into it, updates the faulting process’s page table to point to the new page, and finally clears the copy‑on‑write attribute because the page is now private. Swapping is unnecessary, and termination would be incorrect.

Q13. How does vfork() differ from fork() with copy‑on‑write regarding memory usage?

A.vfork() shares the address space without copying until exec or exit ✅
B.vfork() always copies all pages immediately
C.vfork() uses zero‑fill‑on‑demand exclusively
D.vfork() does not create a child process
💡 Difficulty: hard | ✅ Correct: A

📖 Explanation: vfork() creates a child that runs in the parent’s address space, postponing any copying until the child calls exec() or exits. This contrasts with fork() + COW, where pages are shared but may be copied on first write. Therefore, vfork() can use even less memory initially, while still providing a separate execution context.

Q14. If the parent writes to a page that the child has already copied via copy‑on‑write, what is the state of that page in physical memory?

A.Two distinct private copies exist ✅
B.The child’s copy is overwritten
C.Both processes share a single page again
D.The page is freed
💡 Difficulty: hard | ✅ Correct: A

📖 Explanation: After the child’s copy is created, the parent’s subsequent write triggers another allocation, producing a second private page. Thus, both processes now have separate physical pages for the same logical page. The child’s copy is not overwritten, sharing does not resume, and the original page remains allocated.

Q15. What security benefit does zero‑fill‑on‑demand provide when allocating a new page?

A.It erases any leftover data from previous owners ✅
B.It encrypts the page contents
C.It compresses the page to save space
D.It speeds up allocation
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: Zero‑fill‑on‑demand writes zeros to every byte of a newly allocated page, guaranteeing that no residual information from a prior process can be read by the new owner. This prevents accidental data leakage. Encryption and compression are separate techniques, and speed is not the primary security advantage.

Q16. A process forks and then writes to three distinct pages marked copy‑on‑write. How many total page copies will exist for those three pages after the writes?

A.Six ✅
B.Three
C.Four
D.Five
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: Each write forces the OS to allocate a new private page for the child, resulting in three new pages. The parent still retains the original three pages, so the total number of physical pages representing those three logical pages becomes six.

Q17. Which operating systems are known to implement copy‑on‑write?

A.Windows XP, Linux, and Solaris
B.Mac OS X only
C.Android only
D.iOS only ✅
💡 Difficulty: easy | ✅ Correct: D

📖 Explanation: All of the listed systems—Windows XP, Linux, and Solaris—use copy‑on‑write as part of their memory‑management strategy. The other choices name platforms that either do not use COW in the same way or were not mentioned as examples.

Q18. Why is it important for the OS to allocate free pages for copy‑on‑write from a dedicated pool?

A.It ensures quick access and avoids fragmentation ✅
B.It reduces CPU usage
C.It prevents page‑table corruption
D.It speeds up network I/O
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: A dedicated pool of pre‑zeroed pages allows the OS to satisfy copy‑on‑write requests promptly, minimizing latency and preventing the need to search the entire memory, which could cause fragmentation. CPU usage and network I/O are unrelated, and page‑table integrity is maintained regardless of the source pool.

Q19. A system has four free pages. After a fork, the child modifies three pages that were copy‑on‑write. Can the OS satisfy the request without additional allocation?

A.Yes, because three pages are needed ✅
B.No, because four pages are insufficient
C.Only if one page is shared
D.It depends on the page‑replacement policy
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: The child needs a new physical page for each of the three modified pages, consuming three of the four free pages. Since enough free pages remain, the OS can allocate them directly without invoking page replacement or additional memory. Hence, the request is satisfied.

Q20. How does copy‑on‑write influence the behavior of a classic LRU page‑replacement algorithm?

A.It may increase the reference count of shared pages, affecting their recency ✅
B.It forces LRU to ignore shared pages
C.It replaces only private pages
D.It disables LRU entirely
💡 Difficulty: hard | ✅ Correct: A

📖 Explanation: When pages are shared via COW, each access by either process updates the page’s last‑used timestamp, potentially keeping the shared page higher in the LRU order. This indirect effect can change which pages are evicted, but LRU still considers all pages; it does not ignore shared pages nor is it disabled.

Q21. Design a simple algorithm to handle a copy‑on‑write fault using zero‑fill‑on‑demand. Which step is performed first?

A.Allocate a zero‑filled page from the free pool ✅
B.Copy the original page contents
C.Update the page‑table entry
D.Clear the COW flag
💡 Difficulty: hard | ✅ Correct: A

📖 Explanation: The algorithm begins by pulling a zero‑filled page from the pre‑allocated pool, guaranteeing that no residual data is present. After allocation, the original contents are copied, the page‑table is updated, and finally the copy‑on‑write attribute is cleared. Starting with allocation ensures security and availability before any further actions.
