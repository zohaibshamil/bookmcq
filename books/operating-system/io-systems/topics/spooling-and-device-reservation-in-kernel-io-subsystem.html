📝 Spooling and device reservation in Kernel I/O Subsystem

📖 From Operating System • 13. I/O Systems • 7 questions available

What is Spooling and device reservation in Kernel I/O Subsystem?

Definition:
Spooling queues output jobs for sequential processing on shared devices, while reservation grants exclusive access to prevent conflicts during critical operations.

Example:
Print jobs are spooled to disk queue \( Q \); tape drives require \( \text{reserve}(dev) \) before backup begins.

Reason:
These mechanisms serialize access to non-sharable resources, preventing race conditions and ensuring orderly device usage in multiuser environments.

Q1. A printer controller raises a maskable interrupt while the CPU is executing a low‑priority I/O routine. Which outcome correctly describes the interrupt handling according to priority levels?

A. The CPU finishes the low‑priority routine before servicing the interrupt.
B. The interrupt preempt​s the low‑priority routine immediately. ✅
C. The interrupt is ignored until the routine disables interrupts.
D. The CPU switches to a non‑maskable interrupt handler.

💡 Difficulty: easy | ✅ Correct: B

📖 Explanation:

The correct answer is B because maskable interrupts are designed to preempt the current execution when they have higher priority than the running task. The low‑priority I/O routine can be interrupted immediately, allowing the CPU to service the device promptly. Option A is wrong because the CPU does not wait for the routine to finish; that would defeat the purpose of interrupts. Option C is incorrect since maskable interrupts can be enabled or disabled, not ignored entirely. Option D describes non‑maskable interrupts, which are not relevant here.

Q2. In a spooling system, when a printer’s buffer‑empty interrupt occurs, the OS should ...

A. Immediately write the next job to the printer without checking priority.
B. Queue the interrupt and wait for the current job to finish.
C. Service the interrupt, then schedule the highest‑priority pending print job. ✅
D. Ignore the interrupt and poll the printer status later.

💡 Difficulty: medium | ✅ Correct: C

📖 Explanation:

The correct answer is C because a buffer‑empty interrupt signals that the printer is ready for more data, so the OS should handle the interrupt and then schedule the highest‑priority pending print job. Option A ignores priority and could starve more urgent jobs. Option B defers service unnecessarily, increasing latency. Option D discards the interrupt, which would cause the printer to remain idle. By servicing the interrupt promptly and selecting the highest‑priority job, the system maintains efficient spooling and responsive I/O.

Q3. An OS designer wants to reserve vector 45 for a new network card. Which step is essential to ensure the interrupt can be masked by the CPU when lower‑priority tasks run?

A. Place the handler in the non‑maskable range 0‑31.
B. Register the handler in the IDT and set its descriptor’s privilege level to 0.
C. Install the handler at vector 45 and mark the interrupt as maskable in the PIC. ✅
D. Disable all maskable interrupts during handler installation.

💡 Difficulty: hard | ✅ Correct: C

📖 Explanation:

The correct answer is C because vector 45 is inside the maskable range (32‑255), so the OS registers the handler there and configures the PIC to treat it as maskable. Option A incorrectly puts the handler in the non‑maskable range, which is reserved for critical faults. Option B changes privilege level but does not affect maskability. Option D disables all maskable interrupts, preventing the device from ever generating an interrupt. Therefore, installing the handler at vector 45 and marking it maskable is required.

Q4. If a double‑fault exception occurs while handling a page‑fault interrupt, what is the most likely result given the CPU’s priority scheme?

A. The double‑fault is serviced before the page‑fault, and the system continues normally.
B. Both faults are merged into a single interrupt and processed together.
C. The page‑fault handler masks the double‑fault and retries the operation.
D. The CPU invokes the double‑fault handler which cannot be pre‑empted, often leading to a system crash. ✅

💡 Difficulty: hard | ✅ Correct: D

📖 Explanation:

The correct answer is D because a double‑fault exception has the highest priority and its handler cannot be pre‑empted by other interrupts; when it occurs during a page‑fault handler, the CPU immediately invokes the double‑fault routine, which usually leads to a system crash if not properly handled. Option A is wrong because the double‑fault does not allow normal continuation. Option B is incorrect; the two faults are not merged. Option C is false because the page‑fault handler cannot mask a double‑fault. Thus the system typically halts after the double‑fault.

Q5. Why does an operating system implement interrupt priority levels?

A. To allow every interrupt to be handled simultaneously.
B. To enable low‑priority interrupts to be deferred while high‑priority ones preempt the CPU. ✅
C. To prevent any interrupt from ever being masked.
D. To assign each device a unique non‑maskable vector.

💡 Difficulty: easy | ✅ Correct: B

📖 Explanation:

The correct answer is B because interrupt priority levels let the OS defer low‑priority interrupts while allowing high‑priority ones to pre‑empt the CPU, ensuring critical events are handled promptly. Option A is wrong; simultaneous handling is not possible. Option C is incorrect because masking is still possible for maskable interrupts. Option D misstates the purpose of priority levels, which do not assign unique non‑maskable vectors. By using priority levels, the system balances responsiveness and stability in real‑world I/O scenarios.

Q6. What distinguishes maskable interrupts (vectors 32‑255) from non‑maskable interrupts (vectors 0‑31) in an Intel Pentium system?

A. Maskable interrupts can be ignored by the CPU, while non‑maskable ones always trigger a handler.
B. Non‑maskable interrupts have higher priority and cannot be disabled by software. ✅
C. Maskable interrupts are only used for debugging, whereas non‑maskable are for I/O.
D. Both types are treated identically by the interrupt controller.

💡 Difficulty: medium | ✅ Correct: B

📖 Explanation:

The correct answer is B because non‑maskable interrupts have higher priority and cannot be disabled by software, ensuring that critical faults are always serviced. Option A is false; maskable interrupts can be ignored if disabled. Option C mischaracterizes the usage: maskable interrupts serve general I/O, while non‑maskable are for severe exceptions. Option D is wrong because the interrupt controller distinguishes the two types, not treats them identically. Understanding this distinction helps developers decide which interrupt type to use for reliable device drivers.
