📝 Nonblocking and asynchronous I/O (12 MCQs)

Definition:

Nonblocking and asynchronous I/O are approaches that let a program avoid waiting in the calling thread for an I/O operation to finish. Nonblocking calls return promptly when progress cannot be made, while asynchronous I/O reports completion later. Without these approaches, applications may waste time waiting and respond poorly to concurrent work.

Working:

With nonblocking I/O, the application attempts an operation and receives available data or a result indicating that it must try again. With asynchronous I/O, the application submits a request and continues other work. A completion event or notification later reports the result.

Example:

A server checks a nonblocking socket and finds no incoming bytes, so it continues serving another client. Separately, it submits an asynchronous file read for 4096 bytes. A completion notification later indicates how many bytes were read.

Reason:

These approaches improve responsiveness and concurrency compared with a thread that blocks during every operation. Nonblocking I/O may require repeated readiness checks, while asynchronous I/O needs completion management. Neither approach guarantees faster hardware transfers; they mainly change how the application waits.

Common Misconceptions:

'Nonblocking means the operation always succeeds immediately' is incorrect because it may return no data. 'Asynchronous means no waiting anywhere' ignores eventual completion handling. 'Both approaches are identical' overlooks their different result-notification models.

Exam Preparation Tips: How to prepare this topic

Trace when each call returns and when data becomes available. Compare readiness notification with completion notification. Practise identifying partial results and retry conditions. Exams commonly test concurrency, responsiveness, and differences between blocking, nonblocking, and asynchronous behavior.

Key Terms:

  • Blocking I/O - Call waits for the requested operation.
  • Nonblocking I/O - Call returns without waiting for progress.
  • Asynchronous I/O - Completion is reported after submission.
  • Readiness - Indication that an operation can proceed.

📝 All Nonblocking and asynchronous I/O MCQs

Q1. What is the CPU instruction commonly used to resume execution after handling an interrupt?

A.RET
B.JMP
C.IRET
D.CALL ✅
💡 Difficulty: easy | ✅ Correct: D

📖 Explanation: The instruction that restores processor state after an interrupt is called IRET. It pops the saved flags, segment selector, and instruction pointer, returning execution to the point where the interrupt occurred. Options A (RET) and B (JMP) are generic return or jump instructions that do not handle saved interrupt context. Option D (CALL) initiates a subroutine, not a return. IRET is defined by the CPU architecture for interrupt return, making it the correct choice.

Q2. Why does an interrupt controller dispatch the interrupt to the correct handler without the CPU polling all devices?

A.It uses a priority encoder ✅
B.It relies on DMA
C.It timestamps each request
D.It broadcasts to all handlers
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: The controller contains a priority encoder that examines the interrupt request lines and determines which device raised the signal, then directly forwards the interrupt vector to the CPU. This eliminates the need for the CPU to sequentially check each device, saving cycles. Options B and C describe mechanisms unrelated to interrupt selection, and D would cause unnecessary processing for every device. The priority encoder provides efficient, deterministic dispatch.

Q3. How does multilevel interrupt priority improve system responsiveness in a multitasking OS?

A.Higher‑priority interrupts can pre‑empt lower‑priority ones
B.All interrupts are handled in FIFO order ✅
C.It reduces need for context switches
D.It merges multiple interrupts into one
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: When the OS assigns priority levels, a high‑priority interrupt can interrupt a lower‑priority handler, allowing urgent tasks to be serviced promptly. This pre‑emption reduces latency for critical events. Option B describes a simple queue that would delay urgent interrupts. Option C is incorrect because priority handling does not eliminate context switches; it may even increase them. Option D suggests combining interrupts, which is not how priority schemes work.

Q4. In nonblocking I/O, what is the primary advantage of using asynchronous notification over polling?

A.Reduces CPU idle cycles
B.Eliminates need for buffers ✅
C.Guarantees ordering of events
D.Simplifies device driver code
💡 Difficulty: hard | ✅ Correct: B

📖 Explanation: Asynchronous notification lets the OS inform a process when data is ready, so the CPU does not waste cycles repeatedly checking the device state. This contrasts with polling, which consumes CPU time while waiting. Option B is false because buffers are still required to hold data. Option C is unrelated; ordering is handled by other mechanisms. Option D may be partially true but is not the principal benefit. Reducing idle cycles directly improves efficiency.

Q5. Which feature allows a CPU to temporarily defer handling an interrupt during a critical section?

A.Interrupt masking ✅
B.DMA
C.Cache coherency
D.Context switching
💡 Difficulty: hard | ✅ Correct: A

📖 Explanation: Interrupt masking lets the processor ignore certain interrupt lines while executing code that must not be interrupted, such as updating shared data structures. This deferral protects critical sections from unexpected pre‑emption. DMA (Direct Memory Access) moves data without CPU involvement but does not control interrupt acceptance. Cache coherency ensures memory consistency across cores, not interrupt handling. Context switching changes execution contexts but does not prevent an interrupt from occurring. Therefore, masking is the mechanism for temporary deferral.

Q6. A server process uses nonblocking read on a socket. If recv returns -1 with EAGAIN, what should the process do next?

A.Terminate the connection ✅
B.Retry immediately
C.Block until data arrives
D.Register for asynchronous notification
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: When recv reports EAGAIN, it indicates no data is available and the operation would block. The correct response is to arrange for the OS to notify the process when the socket becomes readable, typically by registering a callback or using select/poll mechanisms. Terminating the connection (A) is unnecessary, retrying immediately (B) would just repeat the error, and blocking (C) defeats the purpose of nonblocking I/O.

Q7. Device A raises a high‑priority interrupt while Device B is processing a low‑priority interrupt. What must the OS ensure?

A.Device B's handler completes before A's ✅
B.A's handler pre‑empts B's
C.Both handlers run concurrently
D.Interrupts are ignored until B finishes
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: The OS must allow the high‑priority interrupt to pre‑empt the lower‑priority handler so that urgent work is addressed promptly. This pre‑emption is a core part of multilevel interrupt handling. Letting B finish first (A) would increase latency for critical events. Running both concurrently (C) would require separate CPUs and is not typical for a single processor. Ignoring interrupts (D) would cause missed deadlines.

Q8. A real‑time application requires data from a sensor every 5 ms. Using asynchronous I/O, which design ensures the deadline is met?

A.Block on each read ✅
B.Use a busy‑wait loop
C.Register a callback that processes data and re‑issues the read
D.Queue reads and process after 50 ms
💡 Difficulty: hard | ✅ Correct: A

📖 Explanation: A callback that runs when the sensor data arrives lets the application handle the data immediately and then start the next asynchronous read, maintaining the 5 ms cadence without blocking. Blocking (A) would stall the thread, a busy‑wait (B) consumes CPU needlessly, and delayed queuing (D) violates the deadline. The callback approach aligns with nonblocking, event‑driven design.

Q9. A programmer mistakenly uses blocking I/O in a GUI thread. What symptom is most likely observed?

A.Increased network throughput ✅
B.UI freezes while waiting for I/O
C.CPU usage drops to zero
D.Multiple threads are spawned automatically
💡 Difficulty: hard | ✅ Correct: A

📖 Explanation: When a GUI thread performs a blocking call, it cannot process user events until the operation completes, causing the interface to appear frozen or unresponsive. Network throughput (A) is unrelated to UI responsiveness. CPU usage dropping (C) would indicate idleness, not blocking. Automatic thread creation (D) does not occur unless the programmer explicitly spawns them. Hence, UI freeze is the expected outcome.

Q10. A programmer implementing a nonblocking file copy checks for EOF after each read. Which mistake could cause data loss?

A.Treating zero bytes read as EOF
B.Ignoring partial reads ✅
C.Calling write before read
D.Closing file before all writes
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: If the code interprets a return value of zero as end‑of‑file, it may stop copying before the final block is transferred, especially when the file size is a multiple of the buffer size. Partial reads (B) must be handled, but treating zero as EOF is the specific error leading to loss. Writing before reading (C) disrupts order, and closing early (D) would truncate data, but the described symptom matches mistake A.

Q11. An embedded system uses an interrupt line to signal when a UART transmission is complete. Which action should the ISR perform?

A.Start next transmission immediately ✅
B.Clear the interrupt flag and update a status variable
C.Reset the CPU
D.Enter low‑power mode
💡 Difficulty: easy | ✅ Correct: A

📖 Explanation: The interrupt service routine should acknowledge the interrupt by clearing its flag, preventing re‑triggering, and set a status variable so the main code knows the transmission finished. Starting another transmission (A) may be appropriate later but not within the ISR without proper coordination. Resetting the CPU (C) is drastic and unnecessary. Entering low‑power mode (D) would halt further processing, which is not the ISR’s purpose.

Q12. What term describes I/O where the request returns immediately and the program is later notified of completion?

A.Polling ✅
B.Synchronous I/O
C.Asynchronous I/O
D.Blocking I/O
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: Asynchronous I/O initiates an operation that returns at once, allowing the program to continue execution while the OS notifies it upon completion, typically via a callback or event. Polling (A) actively checks status, notifies later. Synchronous I/O (B) waits for the operation to finish before returning. Blocking I/O (D) also waits, making the call non‑returning until done. Therefore, asynchronous I/O matches the described behavior.)
