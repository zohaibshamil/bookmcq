What is Application I/O Interface?

Definition:
The Application I/O Interface provides standardized system calls and APIs that abstract hardware details, allowing programs to interact with diverse devices uniformly.

Example:
The function \( \text{read}(fd, buf, count) \) works identically whether \( fd \) refers to a file, socket, or pipe.

Reason:
This abstraction decouples application logic from specific hardware implementations, ensuring portability and simplifying software development.

📝 All Application I/O Interface MCQs

Q1. When an interrupt is detected, what is the first action the CPU performs?

A. Save the current execution state ✅
B. Disable all interrupts
C. Jump directly to the handler address
D. Send an acknowledgment to the device

💡 Difficulty: easy | ✅ Correct: A

📖 Explanation:

The CPU must preserve the program's registers, program counter, and status flags before changing flow. Saving this state allows the processor to restore everything exactly as it was after the handler finishes. Disabling interrupts or acknowledging the device are later steps, and jumping without saving would corrupt the original context, preventing correct resumption.

Q2. A kernel needs to postpone a low‑priority network interrupt while a critical section runs. Which technique enables this behavior?

A. Polling the network device
B. Masking the interrupt line ✅
C. Using DMA for the transfer
D. Performing a context switch

💡 Difficulty: medium | ✅ Correct: B

📖 Explanation:

Masking the interrupt line tells the CPU to ignore requests from that source until the mask is cleared. This lets the critical code finish without interruption. Polling would still require checking the device, DMA moves data but does not control interrupt timing, and a context switch would change the running thread, not the interrupt handling policy.

Q3. Why are multilevel interrupt priorities important in modern operating systems?

A. They reduce overall power consumption
B. They simplify device driver code
C. They allow the system to treat high‑priority events more urgently ✅
D. They increase required memory for interrupt tables

💡 Difficulty: easy | ✅ Correct: C

📖 Explanation:

Priority levels let the OS decide which interrupt deserves immediate attention and which can wait. High‑priority devices such as timers or emergency signals are serviced quickly, while lower‑priority devices are delayed, improving responsiveness and ensuring critical tasks are not missed. The other options do not describe the main benefit.

Q4. What is the fixed location called where the CPU jumps to begin executing an interrupt service routine?

A. Interrupt vector ✅
B. Interrupt table
C. Handler address
D. Service routine entry point

💡 Difficulty: easy | ✅ Correct: A

📖 Explanation:

The interrupt vector is a predefined memory address that holds the entry point for the ISR. When the CPU detects an interrupt request, it uses this vector to locate the handler code. The other terms describe related structures but do not refer to the specific fixed address used for the jump.

Q5. Three devices generate interrupts: a keyboard (high priority), a mouse (low priority), and a timer (medium priority). Which device will be serviced first when an interrupt occurs?

A. Keyboard ✅
B. Timer
C. Mouse
D. None of them; the CPU will poll first

💡 Difficulty: medium | ✅ Correct: A

📖 Explanation:

Interrupt controllers assign higher priority to the keyboard, so its request is recognized before the timer or mouse. The controller automatically selects the highest‑priority pending interrupt, eliminating the need for the CPU to examine each device. The other choices would be selected only if the keyboard line were not asserted.

Q6. Which method most directly improves efficiency compared with polling every device for service?

A. Increasing the CPU clock speed
B. Using more memory for buffers
C. Requiring less hardware support
D. Avoiding a scan of each device until an interrupt arrives ✅

💡 Difficulty: medium | ✅ Correct: D

📖 Explanation:

Avoiding a scan means the CPU does not waste cycles checking devices that are idle. The interrupt controller notifies the CPU only when a device signals readiness, so the processor can perform other work. Raising the clock or adding memory does not address the root cause, and requiring less hardware would actually reduce the ability to handle interrupts efficiently.

Q7. A processor executes one million instructions per second and checks the interrupt line after each instruction. If an interrupt occurs every 2,000 instructions, how many interrupts does the CPU see each second?

A. 200
B. 2000
C. 500 ✅
D. 5000

💡 Difficulty: hard | ✅ Correct: C

📖 Explanation:

One million instructions divided by 2,000 instructions per interrupt yields 500 interrupts per second (1,000,000 ÷ 2,000 = 500). The other numbers result from incorrect division or multiplication and do not match the given rates.

Q8. Why does the return‑from‑interrupt instruction restore the previously saved state?

A. To speed up execution of the next program
B. To re‑establish the registers, program counter, and flags of the interrupted task ✅
C. To clear the device’s interrupt flag automatically
D. To start a new process immediately after handling the interrupt

💡 Difficulty: hard | ✅ Correct: B

📖 Explanation:

The return instruction (often called IRET) reloads the saved registers, program counter, and status flags so the original program can continue exactly where it left off. It does not clear the device flag (the handler does that) nor does it start a new process; its purpose is precise restoration of the pre‑interrupt context.

Q9. What is the purpose of the special instruction used to return from an interrupt service routine?

A. It terminates the program
B. It restores the saved CPU registers and program counter ✅
C. It clears the system memory
D. It halts the processor until the next interrupt

💡 Difficulty: medium | ✅ Correct: B

📖 Explanation:

The return‑from‑interrupt instruction (commonly IRET) reloads the saved execution context, allowing the CPU to resume the interrupted code. It does not end the program, clear memory, or halt the processor; those actions are performed by different instructions.

Q10. If an interrupt handler fails to clear the device’s interrupt flag, what is the most likely outcome?

A. The same interrupt will be generated repeatedly ✅
B. The CPU will crash immediately
C. The device will become idle and stop sending data
D. No effect; the system continues normally

💡 Difficulty: medium | ✅ Correct: A

📖 Explanation:

Leaving the flag set causes the interrupt controller to believe the device still needs service, so the CPU receives another interrupt as soon as it returns, leading to a loop of repeated interrupts. A crash or idle device requires additional faults, and ignoring the flag would not leave the system unaffected.

Q11. How does deferring interrupt handling during a critical section influence overall system responsiveness?

A. It increases latency for all subsequent I/O
B. It decreases overall throughput but protects data integrity
C. It has no impact on performance
D. It balances safety of the critical code with timely servicing of other devices ✅

💡 Difficulty: medium | ✅ Correct: D

📖 Explanation:

Deferring interrupts protects the critical region from unexpected changes, preserving correctness, while the system still services other pending interrupts as soon as the mask is cleared. This approach does not eliminate latency entirely, nor does it leave performance unchanged; it offers a trade‑off between safety and responsiveness.

Q12. In a system that supports nested interrupts, what happens when a high‑priority interrupt arrives while a low‑priority handler is executing?

A. The low‑priority handler completes before the high‑priority one starts
B. The high‑priority interrupt is ignored until the low‑priority handler finishes
C. Both handlers run at the same time on the same CPU core
D. The high‑priority handler pre‑empts the low‑priority handler, which is resumed later ✅

💡 Difficulty: hard | ✅ Correct: D

📖 Explanation:

Nested interrupt capability lets the CPU suspend the current low‑priority ISR, save its state, and immediately jump to the high‑priority ISR. After the high‑priority work finishes, the CPU restores the low‑priority context and continues where it left off. Ignoring or concurrent execution would break priority guarantees.

Q13. What is the relationship between DMA transfers and the number of interrupts generated by a device?

A. Interrupt lines replace the need for DMA completely
B. DMA can reduce the number of interrupts because data movement occurs without CPU involvement ✅
C. DMA speeds up the interrupt signaling process
D. There is no relation; DMA and interrupts operate independently

💡 Difficulty: hard | ✅ Correct: B

📖 Explanation:

When DMA handles bulk data movement, the device often signals only once (e.g., transfer complete) instead of generating an interrupt for each data word. This reduces interrupt overhead, allowing the CPU to focus on other tasks. The other statements mischaracterize the interaction between DMA and interrupt signaling.

Q14. Which hardware component sits between the CPU and peripheral devices to manage interrupt signals?

A. Interrupt controller ✅
B. DMA controller
C. Memory management unit
D. System clock

💡 Difficulty: medium | ✅ Correct: A

📖 Explanation:

The interrupt controller collects interrupt requests from devices, prioritizes them, and forwards the highest‑priority signal to the CPU. While DMA controllers move data and the MMU handles address translation, the clock generates timing signals; none of these directly manage interrupt signaling.

Q15. During an interrupt, the CPU must save its state before jumping to the handler. Which registers are typically saved?

A. Program counter only
B. Stack pointer only
C. Status register only
D. Program counter, stack pointer, and status register ✅

💡 Difficulty: medium | ✅ Correct: D

📖 Explanation:

A complete context save includes the program counter (where execution resumes), the stack pointer (to preserve call stack), and the status register (flags such as zero or carry). Saving only one of these would leave the other parts of the context undefined, preventing correct restoration after the handler finishes.

Q16. Why is continuous polling of devices considered inefficient compared with interrupt‑driven I/O?

A. Polling uses less power than interrupts
B. Polling speeds up data transfer rates
C. Polling wastes CPU cycles checking devices that are idle ✅
D. Polling improves overall system latency

💡 Difficulty: hard | ✅ Correct: C

📖 Explanation:

When the CPU repeatedly checks each device, it spends valuable cycles on devices that have no data, reducing time available for other tasks. Interrupts allow the CPU to remain idle or perform other work until a device signals that it needs attention, making better use of processing resources. The other options incorrectly describe the impact of polling.

Q17. A real‑time system requires high‑priority interrupts to be serviced within 2 ms. If the CPU handles 250 interrupts per second, does the system meet the requirement?

A. Yes, it meets the timing constraint
B. No, the average interval between interrupts is too long ✅
C. It depends on the priority of each interrupt
D. Cannot be determined without more information

💡 Difficulty: medium | ✅ Correct: B

📖 Explanation:

At 250 interrupts per second, the average time between successive interrupts is 1 ÷ 250 = 4 ms, which exceeds the 2 ms deadline for high‑priority handling. Therefore the system cannot guarantee the required response time. Priority distribution or other factors might improve specific cases, but the average interval alone shows the requirement is not met.
