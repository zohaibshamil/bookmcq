What is Error handling in Kernel I/O Subsystem?

Error handling in the kernel I/O subsystem detects, reports, and recovers from hardware failures and transient faults through retry mechanisms with exponential backoff after \( n \) failed attempts, checksum validation to detect data corruption, and graceful degradation strategies that isolate faulty devices while maintaining service availability for unaffected components.

Q1. Which interrupt vector numbers are reserved for nonmaskable exceptions?

A. 0–31 ✅
B. 32–255
C. 0–15
D. 16–31

💡 Difficulty: easy | ✅ Correct: A

📖 Explanation:

The correct answer is A because nonmaskable exceptions occupy vectors 0 through 31, allowing the CPU to handle critical errors that cannot be ignored. Option B describes maskable interrupts, which are optional and can be disabled. Option C limits the range incorrectly to 0–15, missing many nonmaskable vectors. Option D starts at 16, omitting the lower half of the nonmaskable range. Understanding these ranges helps OS designers map handlers to the proper vectors, ensuring reliable error processing.

Q2. Why does the CPU implement interrupt priority levels?

A. To allow low‑priority interrupts to be deferred while high‑priority ones can pre‑empt execution ✅
B. To increase the clock speed of the processor
C. To reduce power consumption during idle periods
D. To enable simultaneous execution of multiple interrupts

💡 Difficulty: medium | ✅ Correct: A

📖 Explanation:

Option A is correct because priority levels let the CPU postpone less urgent interrupts without disabling all interrupts, and let urgent ones interrupt current handling. Option B is unrelated to priority; clock speed is hardware‑controlled. Option C concerns power management, not interrupt handling. Option D suggests parallel execution, which the CPU does not support for interrupts. Recognizing this mechanism is key for OS scheduling and responsiveness.

Q3. How does a maskable interrupt differ from a nonmaskable interrupt when handling critical errors?

A. Maskable interrupts can be disabled by software, while nonmaskable cannot be disabled
B. Maskable interrupts always have higher priority than nonmaskable ones ✅
C. Maskable interrupts are only used for I/O devices, nonmaskable only for CPU exceptions
D. Maskable interrupts never cause a context switch, nonmaskable always do

💡 Difficulty: medium | ✅ Correct: B

📖 Explanation:

The correct choice is A: maskable interrupts (vectors 32–255) can be turned off by setting appropriate flags, whereas nonmaskable exceptions (vectors 0–31) are always processed. Option B is false; priority is independent of maskability. Option C oversimplifies; maskable interrupts can also signal errors, not just I/O. Option D is inaccurate because both types may trigger context switches. This distinction guides OS developers in protecting critical sections.

Q4. A disk controller signals that a write operation has completed. Which type of interrupt is most likely generated?

A. Nonmaskable exception
B. Maskable interrupt ✅
C. Software interrupt
D. Trap exception

💡 Difficulty: medium | ✅ Correct: B

📖 Explanation:

Option B is correct because device‑generated events like I/O completion use maskable interrupts (vectors 32–255), allowing the OS to enable or disable them as needed. Nonmaskable exceptions are reserved for CPU‑internal faults, not peripheral signals. Software interrupts are invoked by the CPU itself, not external hardware. Trap exceptions are a subclass of nonmaskable exceptions used for debugging. Recognizing the correct category ensures the OS installs the appropriate handler for device readiness.

Q5. When a user‑mode program attempts to execute a privileged instruction, which interrupt vector number is invoked?

A. Vector 0 (Divide Error)
B. Vector 13 (General Protection Fault) ✅
C. Vector 6 (Invalid Opcode)
D. Vector 14 (Page Fault)

💡 Difficulty: medium | ✅ Correct: B

📖 Explanation:

The correct answer is B because executing a privileged instruction from user mode triggers a General Protection Fault, which resides at vector 13. Vector 0 handles divide‑by‑zero errors, not privilege violations. Vector 6 signals an invalid opcode, unrelated to privilege levels. Vector 14 deals with page faults caused by memory access errors. Knowing the specific vector helps the OS pinpoint the cause of a protection violation and respond appropriately.

Q6. The CPU is servicing a low‑priority interrupt from vector 45 when a high‑priority interrupt from vector 14 arrives. What will the CPU do?

A. Complete the low‑priority handler before handling the high‑priority one
B. Immediately pre‑empt the low‑priority handler and service the high‑priority interrupt ✅
C. Ignore the high‑priority interrupt until the low‑priority one finishes
D. Merge both handlers into a single routine

💡 Difficulty: hard | ✅ Correct: B

📖 Explanation:

Option B is correct: the CPU’s priority scheme forces the high‑priority interrupt (vector 14) to pre‑empt the ongoing low‑priority service routine, ensuring urgent conditions are addressed first. Option A would violate priority rules, potentially delaying critical response. Option C incorrectly suggests the CPU cannot pre‑empt, which defeats the purpose of priority levels. Option D is impossible because interrupt handlers are distinct. This behavior is essential for maintaining system stability under concurrent interrupt loads.

Q7. Why is the page‑fault vector (14) classified as maskable even though it signals a memory‑management error?

A. Because the OS can temporarily disable page‑fault handling during critical sections
B. Because page faults are less severe than divide‑by‑zero errors
C. Because masking allows the CPU to postpone handling until after other higher‑priority interrupts ✅
D. Because page faults are generated by software, not hardware

💡 Difficulty: hard | ✅ Correct: C

📖 Explanation:

The correct answer is C: marking the page‑fault vector as maskable lets the CPU defer its handling when higher‑priority interrupts demand immediate attention, while still guaranteeing eventual service. Option A is incorrect; OSs generally keep page‑fault handling enabled. Option B mischaracterizes severity; page faults can be critical. Option D confuses the source; page faults arise from hardware memory‑access violations. Understanding this classification helps OS designers balance responsiveness with correct memory management.

Q8. During system boot, the OS installs an interrupt handler for vector 8 (double fault). Which action is essential to ensure proper handling of a double fault?

A. Setting the descriptor privilege level to user mode
B. Providing a dedicated stack pointer for the double‑fault handler
C. Disabling all maskable interrupts globally ✅
D. Mapping vector 8 to the same handler as vector 0

💡 Difficulty: hard | ✅ Correct: C

📖 Explanation:

Option C is correct: a double fault occurs when an exception happens while trying to invoke another exception handler, so the OS must disable all maskable interrupts to prevent recursive faults and ensure a controlled response. Option A would allow user‑mode code to invoke the handler, which is unsafe. Option B is unnecessary because the double‑fault handler uses a known stack. Option D would obscure the distinct nature of a double fault. Properly disabling interrupts during this critical condition is vital for system reliability.
