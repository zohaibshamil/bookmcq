Q1. Which instruction restores the CPU state after handling an interrupt?

🔹 A. return from interrupt
🔹 B. jump to handler
🔹 C. save state
🔹 D. disable interrupts

💡 Difficulty: easy | ✅ Correct: A

📖 Explanation:

The correct answer is A because the return‑from‑interrupt instruction tells the CPU to restore the registers and program counter saved when the interrupt occurred, allowing execution to continue where it left off. Option B describes the initial jump to the handler, not the restoration step. Option C is part of the entry sequence, not the exit. Option D merely disables further interrupts and does not recover the saved context. Restoring state ensures the interrupted program resumes correctly, which is essential for reliable I/O processing.

Q2. Why are multilevel interrupts important in modern operating systems?

🔹 A. They reduce power consumption
🔹 B. They allow devices to share the same IRQ line
🔹 C. They enable prioritization of urgent tasks
🔹 D. They simplify hardware design

💡 Difficulty: easy | ✅ Correct: A

📖 Explanation:

Multilevel interrupts let the system assign different priority levels to interrupt sources, so urgent events like timer ticks can pre‑empt less critical ones such as background network traffic. Option A is unrelated to priority handling. Option B describes IRQ sharing, which is a separate concept. Option D might be a side effect but does not capture the main benefit. Prioritization improves responsiveness and ensures time‑critical tasks are serviced promptly.

Q3. A kernel critical section must defer interrupts from a network card until it finishes updating a shared buffer. Which mechanism should the OS use?

🔹 A. Disable all interrupts globally
🔹 B. Mask only the network card’s interrupt line
🔹 C. Raise processor priority level to block lower‑priority interrupts
🔹 D. Poll the device continuously

💡 Difficulty: medium | ✅ Correct: B

📖 Explanation:

Masking only the network card’s interrupt line (option B) isolates the critical section from that specific device while allowing other interrupts to be processed, preserving overall system responsiveness. Option A would halt all interrupt activity, unnecessarily degrading performance. Option C raises the CPU priority but does not specifically block the network card’s line, potentially still allowing its interrupt. Option D replaces interrupt handling with inefficient polling, contradicting the goal of deferral during a critical region.

Q4. When an interrupt occurs, which hardware component allows the CPU to quickly determine which device raised it without scanning all devices?

🔹 A. DMA controller
🔹 B. Interrupt vector table
🔹 C. Programmable interrupt controller (PIC)
🔹 D. Memory management unit

💡 Difficulty: medium | ✅ Correct: A

📖 Explanation:

The programmable interrupt controller (PIC) consolidates interrupt signals and provides the CPU with a vector that identifies the originating device, eliminating the need for exhaustive polling. Option A, the DMA controller, moves data but does not identify interrupt sources. Option B, the interrupt vector table, stores handler addresses but relies on the PIC to supply the correct index. Option D, the MMU, manages virtual memory and is unrelated to interrupt identification. Hence, the PIC is the key component for rapid source determination.

Q5. How does the CPU detect an interrupt request?

🔹 A. By checking a status register only at the start of each program
🔹 B. By continuously monitoring the interrupt‑request line after every instruction
🔹 C. By receiving a hardware interrupt only when the device is idle
🔹 D. By polling devices in a round‑robin order

💡 Difficulty: medium | ✅ Correct: B

📖 Explanation:

The CPU’s control unit samples the interrupt‑request line after each instruction, so any pending request is noticed immediately (option B). Option A limits detection to program start, missing asynchronous events. Option C mischaracterizes the hardware behavior; interrupts can occur regardless of device idle state. Option D describes a software polling technique, not the hardware‑level detection mechanism. Continuous monitoring ensures timely response to asynchronous device signals.

Q6. A server receives both a high‑priority timer interrupt and a low‑priority network packet interrupt simultaneously. Which handling order maximizes system responsiveness?

🔹 A. Handle the network packet first, then the timer
🔹 B. Delay both until the CPU is idle
🔹 C. Service the timer interrupt first, then the network interrupt
🔹 D. Service both in parallel using two CPUs

💡 Difficulty: hard | ✅ Correct: C

📖 Explanation:

Serving the high‑priority timer interrupt first (option C) guarantees that time‑critical tasks are not delayed, preserving system timing guarantees. Option A would postpone the timer, potentially causing missed deadlines. Option B unnecessarily stalls all processing, reducing throughput. Option D assumes parallel CPUs, which may not be available and adds synchronization complexity. Prioritizing the timer aligns with multilevel interrupt design, delivering the most responsive behavior.

Q7. Given 200,000 interrupts per second and a handler execution time of 0.3 µs, what percentage of CPU time is consumed by interrupt handling?

🔹 A. 0.03
🔹 B. 0.06
🔹 C. 0.12
🔹 D. 0.3

💡 Difficulty: hard | ✅ Correct: B

📖 Explanation:

Each interrupt consumes 0.3 µs, so total time per second is 200,000 × 0.3 µs = 60 ms, which is 0.06 s. Dividing 0.06 s by the 1‑second interval yields 0.06 = 6 % of CPU time (option B). Option A underestimates the cost, option C doubles it, and option D vastly overestimates. Knowing the CPU overhead helps designers decide whether additional interrupt coalescing or faster handlers are needed to keep the system efficient.

Q8. What is the primary purpose of saving the CPU state at the start of an interrupt?

🔹 A. To increase cache performance
🔹 B. To allow the interrupt handler to execute without losing the interrupted program’s context
🔹 C. To reset the CPU registers
🔹 D. To enable the device to send data

💡 Difficulty: medium | ✅ Correct: B

📖 Explanation:

Saving the CPU state preserves the registers, program counter, and flags of the currently running task, so the interrupt handler can run and later restore the original context (option B). Option A is unrelated to state saving. Option C describes a reset, which would discard the current task. Option D concerns device operation, not CPU context. Maintaining the saved state ensures the interrupted program resumes correctly after the handler finishes.
