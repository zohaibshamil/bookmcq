📝 Caching in Kernel I/O Subsystem

📖 From Operating System • 13. I/O Systems • 8 questions available

What is Caching in Kernel I/O Subsystem?

Definition:
Caching retains copies of frequently accessed data in faster memory to avoid redundant slow device accesses, exploiting temporal and spatial locality.

Example:
The page cache stores recently read file blocks in RAM; subsequent reads hit cache with latency \( t_{\text{RAM}} \ll t_{\text{disk}} \).

Reason:
Caching exploits access patterns to achieve orders-of-magnitude performance gains, forming the backbone of modern storage hierarchies.

Q1. A device driver receives an interrupt with vector number 45. Which of the following statements is true about this interrupt?

A. It is a maskable interrupt. ✅
B. It is a non‑maskable interrupt.
C. It signals a divide‑by‑zero exception.
D. It is reserved for double‑fault handling.

💡 Difficulty: easy | ✅ Correct: A

📖 Explanation:

Vector numbers 32–255 are defined as maskable, meaning the CPU can temporarily ignore them if a higher‑priority condition is being serviced. Vector 45 falls in this range, so the interrupt can be masked by software and will not trigger an immediate non‑maskable exception. Option A correctly states this property. Option B is wrong because non‑maskable vectors are limited to 0–31. Option C describes a divide‑by‑zero exception, which uses vector 0. Option D refers to double‑fault (vector 8), which is unrelated to vector 45.

Q2. What is the primary purpose of having interrupt priority levels in a CPU?

A. To allow low‑priority interrupts to pre‑empt high‑priority ones.
B. To mask all interrupts during critical sections.
C. To let high‑priority interrupts pre‑empt low‑priority ones. ✅
D. To ensure every interrupt receives equal processing time.

💡 Difficulty: easy | ✅ Correct: C

📖 Explanation:

Interrupt priority levels let the CPU decide which interrupt to handle first when several arrive simultaneously. A high‑priority interrupt can interrupt the service routine of a lower‑priority one, ensuring that urgent events are processed quickly. Therefore option C is correct. Option A reverses the relationship and is false. Option B describes a global mask, which is a different mechanism. Option D suggests equal treatment, which contradicts the purpose of priority levels. In practice, this hierarchy reduces response time for critical hardware events.

Q3. During system boot the OS installs interrupt handlers. If a new network card is added after boot without updating the interrupt vector, what is the most likely outcome?

A. The device will operate normally because the OS uses dynamic allocation.
B. The system may crash or freeze due to an unhandled interrupt. ✅
C. The interrupt will be ignored and the device will simply poll.
D. The OS will automatically assign a free vector at runtime.

💡 Difficulty: medium | ✅ Correct: B

📖 Explanation:

When a new network card appears after the OS has already installed its interrupt vector table, the hardware will generate an interrupt on a vector that currently has no valid handler. The CPU will then jump to an undefined address, often causing a crash or a freeze. Option B captures this result. Option A is incorrect because the OS does not automatically allocate vectors without explicit registration. Option C is wrong; ignored interrupts would leave the device non‑functional. Option D is false because dynamic assignment does not happen without driver code.

Q4. Why are the first 32 interrupt vectors (0‑31) designated as non‑maskable on an Intel Pentium processor?

A. They correspond to low‑priority background tasks.
B. They represent critical processor exceptions that must be handled immediately. ✅
C. They are reserved for user‑defined software interrupts.
D. They are used for future extensions and can be masked.

💡 Difficulty: medium | ✅ Correct: B

📖 Explanation:

The first thirty‑two vectors are reserved for processor‑generated exceptions such as divide‑by‑zero, invalid opcode, and protection faults. These conditions are critical and must be handled immediately, so they are defined as non‑maskable to prevent software from accidentally disabling them. Option B correctly identifies this reason. Option A is incorrect because low‑priority tasks are not placed in this range. Option C misstates the purpose; user‑defined interrupts are typically placed in the maskable range. Option D is false because future extensions still respect the non‑maskable designation for these vectors.

Q5. Which interrupt vector number is assigned to the page‑fault exception?

A. 14 ✅
B. 13
C. 12
D. 15

💡 Difficulty: medium | ✅ Correct: A

📖 Explanation:

The page‑fault exception is assigned vector number 14 in the Intel Pentium interrupt table. This vector is invoked whenever a program accesses a page that is not currently resident in physical memory, prompting the OS to load the needed page. Option A correctly names the vector. Options B, C, and D list neighboring vectors: 13 corresponds to a general‑protection fault, 12 to a stack‑fault, and 15 to a floating‑point error. Knowing the exact mapping is essential for low‑level debugging and for writing correct exception handlers.

Q6. A real‑time embedded system must guarantee that a timer interrupt (vector 32) is serviced within 5 µs. Which design choice best ensures this timing guarantee?

A. Assign the timer interrupt the highest priority level. ✅
B. Enable global interrupts after every instruction.
C. Replace the interrupt with a polling loop.
D. Place the interrupt‑service routine in non‑cacheable memory.

💡 Difficulty: hard | ✅ Correct: A

📖 Explanation:

In a hard‑real‑time environment, meeting a strict latency bound requires that the timer interrupt be serviced before any lower‑priority work can delay it. Assigning the timer the highest priority ensures the CPU will always pre‑empt other ISRs to handle the timer within the 5 µs window. Option A therefore satisfies the requirement. Option B, enabling global interrupts after every instruction, does not affect priority. Option C replaces the interrupt with polling, which typically adds overhead and cannot guarantee the deadline. Option D would slow the handler by preventing cache use, worsening latency.

Q7. How does the ability of a high‑priority interrupt to pre‑empt a low‑priority ISR affect overall system latency and throughput?

A. It increases latency for low‑priority tasks but can improve overall throughput.
B. It decreases latency for low‑priority tasks while reducing throughput.
C. It improves throughput but may cause starvation of low‑priority interrupts. ✅
D. It has no measurable impact on latency or throughput.

💡 Difficulty: hard | ✅ Correct: C

📖 Explanation:

When a high‑priority interrupt can pre‑empt a low‑priority ISR, the low‑priority task may have to wait longer, increasing its latency, while the system can quickly respond to urgent events, improving overall throughput. However, if low‑priority interrupts are constantly pre‑empted, they may suffer starvation. Option C accurately reflects this trade‑off. Option A is partially true but omits the throughput benefit. Option B reverses the effect on latency. Option D claims no impact, which contradicts observed behavior in priority‑based interrupt systems.

Q8. If a programmer mistakenly registers a handler for vector 7 (reserved for coprocessor segment overrun) to service a user‑defined I/O device, what consequence is most likely?

A. The handler will never be invoked.
B. The system will treat the interrupt as a double‑fault and halt.
C. The device will work but the OS may misinterpret the interrupt.
D. Undefined behavior may occur, potentially leading to a system crash. ✅

💡 Difficulty: medium | ✅ Correct: D

📖 Explanation:

Vector 7 is reserved for the coprocessor segment overrun exception, a condition that the CPU uses for a specific error state. Registering a user‑defined handler for this vector overwrites the expected exception handling, leading to undefined behavior when the CPU triggers the real exception or when the device generates its interrupt. Option D correctly predicts a possible system crash. Option A is false because the handler will be called, but for the wrong reason. Option B mischaracterizes the fault as a double‑fault. Option C is unrealistic; the OS will not simply misinterpret the interrupt without adverse effects.)
