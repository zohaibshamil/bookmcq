What is Interrupts in I/O Hardware?

Definition:
An interrupt is an asynchronous signal sent by hardware to the CPU indicating that an event requires immediate attention, causing a context switch to an interrupt handler.

Example:
Upon finishing a disk read, the controller raises IRQ line kkk, pausing the current process to execute the service routine.

Reason:
Interrupts enable efficient multitasking by freeing the CPU to perform other computations while waiting for I/O completion rather than spinning idly.

📝 All Interrupts in I/O Hardware MCQs

Q1. What is the primary purpose of an interrupt in a computer system?

A.To temporarily halt the CPU to service a device ✅
B.To increase memory bandwidth
C.To synchronize clocks
D.To encrypt data
💡 Difficulty: easy | ✅ Correct: A

📖 Explanation: An interrupt signals the CPU to stop its current execution and run a special routine for the device that generated the signal. This enables rapid response without the CPU constantly checking the device. Options B, C, and D refer to unrelated mechanisms such as memory throughput, clock synchronization, and encryption, none of which describe the core function of an interrupt.

Q2. Which hardware component typically contains the interrupt vector table?

A.CPU
B.Interrupt controller ✅
C.DMA controller
D.Power supply
💡 Difficulty: easy | ✅ Correct: B

📖 Explanation: The interrupt vector table resides in the interrupt controller, which maps each interrupt request to the address of its service routine. The CPU fetches this address when an interrupt occurs, but it does not store the table itself. DMA controllers handle data transfers, power supplies provide electricity, and the CPU executes instructions, so those choices are incorrect.

Q3. What is the name of the hardware that prioritizes multiple interrupt requests?

A.Timer
B.Interrupt controller
C.Scheduler ✅
D.Decoder
💡 Difficulty: easy | ✅ Correct: C

📖 Explanation: The interrupt controller evaluates simultaneous interrupt requests and decides which one receives service first based on priority rules. A timer generates periodic signals, a scheduler manages task order in software, and a decoder translates binary codes, none of which perform priority arbitration for interrupts. Hence the interrupt controller is the correct answer.

Q4. Why does using interrupts generally improve CPU efficiency compared to polling?

A.Interrupts let the CPU perform other work until a device signals, while polling wastes cycles checking idle devices ✅
B.Polling reduces latency more than interrupts
C.Interrupts increase memory usage
D.Polling allows simultaneous device handling
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: Interrupt-driven designs allow the CPU to execute useful instructions and only switch to the service routine when the device actually needs attention, avoiding wasted cycles spent repeatedly checking device status. Polling continuously reads device registers regardless of activity, consuming time that could be used elsewhere. Options B, C, and D describe unrelated effects, making A the accurate choice.

Q5. How does an interrupt enable asynchronous communication between I/O devices and the CPU?

A.By forcing the CPU to wait for a clock tick
B.By allowing the device to signal the CPU at any time, independent of the CPU’s current execution
C.By synchronizing both to a shared bus clock ✅
D.By requiring the CPU to constantly query the device
💡 Difficulty: medium | ✅ Correct: C

📖 Explanation: An interrupt lets a peripheral raise a request whenever it needs service, breaking the strict timing of the CPU’s instruction stream. The CPU can continue its current tasks until the interrupt arrives, at which point it saves state and executes the handler. Options A and D describe synchronous or polling behavior, while B misstates the role of the clock. Therefore the correct answer is C.

Q6. What is the effect of nesting interrupts on system latency?

A.It guarantees zero latency for all interrupts
B.It can increase latency for lower‑priority interrupts because higher‑priority handlers may pre‑empt them
C.It eliminates the need for an interrupt vector table ✅
D.It forces the CPU into a low‑power state
💡 Difficulty: medium | ✅ Correct: C

📖 Explanation: When interrupts are nested, a higher‑priority interrupt can interrupt an already‑running lower‑priority handler, causing the lower‑priority request to wait longer before completion. This increases its effective latency. Nesting does not remove the vector table (option C) nor does it put the CPU into low power (option D). Option A is impossible because some delay always exists. Thus option B correctly describes the latency impact.

Q7. Why must interrupt service routines be short and non‑blocking?

A.Because long routines improve system throughput
B.Because short routines prevent the CPU from missing other interrupts and avoid deadlock ✅
C.Because they need to perform complex calculations
D.Because they must allocate large memory buffers
💡 Difficulty: hard | ✅ Correct: B

📖 Explanation: An ISR should finish quickly to return control to the interrupted task and allow the CPU to respond to other pending interrupts. If an ISR blocks or runs for a long time, higher‑priority interrupts may be missed, and the system can deadlock if the ISR waits for resources held by the interrupted code. Options A, C, and D describe undesirable behaviors, making B the correct choice.

Q8. How does priority inversion occur in interrupt handling, and what mechanism prevents it?

A.When a low‑priority interrupt disables higher‑priority ones, solved by using a priority encoder
B.When a high‑priority interrupt is ignored, solved by disabling all interrupts
C.When a medium‑priority interrupt pre‑empts a low‑priority one, solved by masking ✅
D.When a low‑priority interrupt holds a shared resource needed by a high‑priority interrupt, solved by priority inheritance
💡 Difficulty: hard | ✅ Correct: C

📖 Explanation: Priority inversion happens when a lower‑priority task holds a resource that a higher‑priority interrupt needs, causing the high‑priority interrupt to wait. Priority inheritance temporarily raises the lower‑priority task’s priority, allowing it to finish and release the resource. Options A and B mischaracterize the inversion, and D describes a different technique. Therefore option C correctly identifies the scenario and the preventive mechanism.

Q9. What role does the end‑of‑interrupt (EOI) signal play in the interrupt controller?

A.It resets the CPU clock ✅
B.It tells the controller that the current interrupt has been serviced and the line can be cleared
C.It initiates a new interrupt request
D.It powers down the I/O device
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: The EOI signal informs the interrupt controller that the CPU has finished handling the current interrupt, allowing the controller to clear the request and make the line available for future interrupts. It does not affect the CPU clock, start new requests, or control device power, so options B, C, and D are incorrect.

Q10. Explain how vectored interrupts differ from non‑vectored interrupts in terms of address handling.

A.Vectored interrupts provide the ISR address automatically, while non‑vectored require the CPU to fetch it from a fixed location
B.Both types use the same address mechanism
C.Non‑vectored interrupts supply the address, vectored do not
D.Vectored interrupts always use DMA ✅
💡 Difficulty: hard | ✅ Correct: D

📖 Explanation: In a vectored interrupt system, the interrupting device supplies a vector that the controller maps to the exact address of its service routine, allowing the CPU to jump directly. Non‑vectored interrupts only signal the CPU that an interrupt occurred; the CPU must then read a predetermined location to find the ISR address. Options A, B, and C mix up these definitions, making D the correct description.

Q11. In a daisy‑chained bus, how does an interrupt propagate to the CPU?

A.The first device in the chain always sends the interrupt directly to the CPU
B.Each device passes the interrupt request down the chain until the CPU acknowledges it
C.Interrupts are broadcast simultaneously to all devices ✅
D.The CPU polls each device sequentially
💡 Difficulty: medium | ✅ Correct: C

📖 Explanation: A daisy‑chained bus connects devices in series, and when an interrupt occurs, the request travels along the shared lines until the CPU detects it. The CPU does not need to poll each device; instead, the interrupt signal is broadcast along the chain, and the controller determines which device originated it. Options A and B misstate the propagation method, and D describes polling, not interrupt handling. Therefore option C is correct.

Q12. When a device raises an interrupt, which sequence of actions does the CPU typically perform?

A.Immediately execute the device’s code, then resume previous task
B.Save current context, locate the ISR via the vector table, execute the ISR, then restore context ✅
C.Ignore the interrupt until the next timer tick
D.Reset the entire system
💡 Difficulty: easy | ✅ Correct: B

📖 Explanation: Upon receiving an interrupt, the CPU first saves the state of the currently running program, then uses the interrupt vector table to find the address of the appropriate service routine. It executes that routine and finally restores the saved state to continue the original task. Options A, C, and D describe behaviors that would either corrupt program state or cause unnecessary delays, so B is the accurate description.

Q13. If a keyboard and a network card raise interrupts simultaneously, which device is serviced first if the keyboard has higher priority?

A.The network card ✅
B.The keyboard
C.Both are serviced at the same time
D.The CPU chooses randomly
💡 Difficulty: easy | ✅ Correct: A

📖 Explanation: Interrupt controllers assign priority levels to each source; when two requests occur together, the controller selects the higher‑priority one—in this case the keyboard—and forwards its vector to the CPU first. The network card’s request will be held until the keyboard’s ISR finishes. Options B, C, and D contradict the defined priority mechanism, making A the correct answer.

Q15. When deciding between interrupt‑driven I/O and polling for a high‑throughput sensor, which factor most strongly favors using interrupts?

A.The sensor produces data at a constant rate
B.The CPU has many idle cycles available
C.The sensor’s data rate is unpredictable and bursts are rare ✅
D.The system requires deterministic timing for every sample
💡 Difficulty: medium | ✅ Correct: C

📖 Explanation: Interrupt‑driven I/O shines when the device generates data irregularly; the CPU can remain idle until the device signals that data is ready, avoiding wasted cycles. If the sensor’s rate is constant, polling may be simpler. Options A and D describe scenarios where polling or deterministic timing might be preferred, while B does not address the sensor’s behavior. Hence option C correctly identifies the advantage of interrupts.

Q16. Which hardware feature helps a real‑time operating system keep interrupt latency below 10 µs?

A.Large cache memory
B.Dedicated interrupt controller with fast arbitration ✅
C.Multiple cores for parallel processing
D.High‑speed SSD storage
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: A dedicated interrupt controller designed for rapid arbitration can quickly identify and forward the highest‑priority request, minimizing the time the CPU spends determining which ISR to run. This directly reduces latency. While caches and multiple cores improve overall performance, they do not specifically target the interrupt‑handling path. SSD storage is unrelated to interrupt timing, making option B the appropriate choice.

Q17. In a noisy environment, which type of interrupt triggering is generally more reliable?

A.Edge‑triggered
B.Level‑triggered ✅
C.Software‑triggered
D.Timer‑triggered
💡 Difficulty: hard | ✅ Correct: B

📖 Explanation: Level‑triggered interrupts remain active as long as the signal stays asserted, which can cause false triggers in noisy conditions. Edge‑triggered interrupts respond only to transitions, reducing susceptibility to sustained noise. However, a well‑designed edge‑triggered circuit with proper debouncing is typically more reliable than level‑triggered in such environments. Options C and D describe unrelated mechanisms. Therefore option B is the correct answer.

Q19. Which mitigation technique is most effective against an interrupt storm that overwhelms the CPU?

A.Increasing CPU clock speed
B.Disabling all interrupts
C.Implementing interrupt rate limiting in the controller ✅
D.Adding more RAM
💡 Difficulty: hard | ✅ Correct: C

📖 Explanation: An interrupt storm floods the CPU with excessive requests, causing performance collapse. Rate limiting in the interrupt controller throttles how frequently a device can generate interrupts, preventing overload while still allowing necessary signaling. Raising clock speed (A) does not address the root cause, disabling all interrupts (B) stops essential communication, and adding RAM (D) does not affect interrupt handling. Hence option C is the correct mitigation.

Q20. In systems with both hardware and software interrupts, which type typically has higher priority?

A.Hardware interrupts ✅
B.Software interrupts
C.Both have equal priority
D.Priority is assigned randomly
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: Hardware interrupts originate from external devices and are usually given higher priority because they often represent time‑critical events that the CPU must address promptly. Software interrupts are generated by programs and can be scheduled at lower priority levels. Options B, C, and D contradict typical operating‑system designs, making option A the accurate statement.

Q21. A device requires a 4‑byte aligned ISR address. Which vector entry ensures correct execution?

A.4099
B.4100 ✅
C.4101
D.4102
💡 Difficulty: hard | ✅ Correct: B

📖 Explanation: Alignment to a 4‑byte boundary means the address must be divisible by 4. Hexadecimal 0x1004 ends with a 4, which is a multiple of 4, satisfying the alignment requirement. Addresses 0x1003 and 0x1005 are not divisible by 4, and 0x1006, while divisible by 2, is not a multiple of 4. Therefore the correct aligned vector is 0x1004, option B.

Q22. What advantage does interrupt‑driven keyboard input have over polling?

A.It reduces power consumption by keeping the CPU idle until a key is pressed ✅
B.It guarantees that every keystroke is captured without loss
C.It allows the keyboard to operate at higher voltage
D.It eliminates the need for a device driver
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: Interrupt‑driven input lets the CPU remain in other tasks or low‑power states until the keyboard signals a key press, saving energy and processing time. While both methods can capture keystrokes, polling continuously checks the device, wasting cycles. Options B, C, and D describe unrelated benefits. Hence option A correctly identifies the primary advantage.

Q23. What is the difference between maskable and non‑maskable interrupts?

A.Maskable interrupts can be ignored by the CPU, non‑maskable cannot ✅
B.Maskable interrupts are slower than non‑maskable
C.Non‑maskable interrupts are generated only by software
D.Maskable interrupts always have higher priority
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: Maskable interrupts can be disabled (masked) by the CPU when it is executing critical code, allowing the system to postpone handling them. Non‑maskable interrupts (NMIs) cannot be turned off and are used for urgent events like hardware failures. Options B, C, and D mischaracterize speed, source, or priority, making option A the correct distinction.

Q24. How does the interrupt priority scheme affect real‑time guarantees in embedded systems?

A.Higher priority levels increase overall system latency
B.Priority schemes have no impact on timing guarantees
C.Proper priority assignment ensures time‑critical tasks meet deadlines while less critical tasks may be delayed ✅
D.All interrupts are treated equally regardless of priority
💡 Difficulty: hard | ✅ Correct: C

📖 Explanation: In real‑time embedded designs, assigning higher priority to time‑critical interrupts guarantees they are serviced promptly, helping meet strict deadlines. Lower‑priority interrupts may be deferred, which is acceptable for non‑critical functions. Options A and B incorrectly state that priority either worsens latency or is irrelevant, and D contradicts the purpose of priority. Therefore option C accurately describes the effect.

Q25. Why is it important for an ISR to preserve the processor state?

A.So the CPU can power down after the ISR
B.To allow the ISR to modify global variables freely
C.To ensure the interrupted task can resume correctly after the ISR finishes ✅
D.Because the ISR needs to change the CPU clock speed
💡 Difficulty: medium | ✅ Correct: C

📖 Explanation: An ISR must save registers, flags, and other context before altering them, so that when it returns, the original program continues exactly where it left off. Failing to preserve state can corrupt data, cause crashes, or produce incorrect results. Q26. Explain the role of the Interrupt Descriptor Table (IDT) in modern x86 architectures.

A.It stores the binary code for all ISRs
B.It maps interrupt vectors to the addresses of their handlers and defines attributes such as privilege level ✅
C.It controls the power management of I/O devices
D.It provides a lookup table for memory addresses
💡 Difficulty: hard | ✅ Correct: B

📖 Explanation: The IDT is a data structure used by x86 CPUs to translate an interrupt vector into the linear address of its handler and to specify attributes like gate type and required privilege. It does not contain executable code itself, nor does it manage power or general memory mapping. Therefore option B correctly captures the IDT’s purpose.
