What is Kernel I/O subsystem summary?

Definition:
This summary integrates scheduling, buffering, caching, spooling, error handling, protection, and data structures into a cohesive framework governing kernel-level I/O management.

Example:
A write request traverses cache check →\rightarrow→ buffer allocation →\rightarrow→ scheduler queue →\rightarrow→ driver dispatch →\rightarrow→ completion callback.

Reason:
Holistic understanding reveals how individual optimizations interact to deliver reliable, secure, and high-performance I/O services to applications.

📝 All Kernel I/O subsystem summary MCQs

Q1. Which range of interrupt vector numbers is reserved for non‑maskable events?

A.0‑31 ✅
B.32‑255
C.64‑127
D.128‑255
💡 Difficulty: easy | ✅ Correct: A

📖 Explanation: The correct answer is A because vectors 0 through 31 are defined by the Intel architecture as non‑maskable, meaning they cannot be disabled by software and are used for critical exceptions such as divide‑error or machine‑check. Vectors 32‑255 are maskable and are typically assigned to external device interrupts. Options B, C, and D either describe maskable ranges or overlap incorrectly, so they are wrong. Understanding these ranges helps the OS map handlers correctly.

Q2. What is the primary purpose of having interrupt priority levels in a CPU?

A.Allow low‑priority interrupts to be ignored completely
B.Enable high‑priority interrupts to pre‑empt lower‑priority ones ✅
C.Reduce power consumption by disabling clocks
D.Simplify memory management
💡 Difficulty: easy | ✅ Correct: B

📖 Explanation: The correct answer is B. Interrupt priority levels let the CPU decide which interrupt can run while another is in progress. A high‑priority interrupt can pre‑empt a lower‑priority service routine, ensuring urgent events are handled promptly without disabling all interrupts. Option A is wrong because low‑priority interrupts are not ignored; they can be deferred. Options C and D describe unrelated effects, so they are incorrect.

Q3. A device generates an interrupt at vector 45 while the CPU is already handling an interrupt at vector 10. Which statement correctly describes the CPU’s behavior?

A.The CPU will finish the vector‑10 service routine before attending vector‑45
B.The vector‑45 interrupt will pre‑empt the vector‑10 routine because it has higher priority ✅
C.Both interrupts will be serviced simultaneously using separate cores
D.The CPU will mask the vector‑45 interrupt until the vector‑10 routine completes
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: The correct answer is B. Vector numbers 32‑255 are maskable, but priority is determined by the specific vector assigned; typically higher numbers indicate higher priority, and the CPU will suspend the current lower‑priority ISR to service the higher‑priority interrupt. Option A would delay the urgent device, which defeats the purpose of priority. Option C is impossible on a single‑core CPU without special hardware. Option D incorrectly suggests masking, which the CPU does not do for higher‑priority interrupts.

Q4. During I/O, a driver receives an interrupt indicating that a write operation has completed. What should the driver do first?

A.Immediately schedule a user‑space process to handle the data
B.Reset the device to its initial state
C.Read the device’s status register to confirm successful completion ✅
D.Ignore the interrupt and continue polling
💡 Difficulty: medium | ✅ Correct: C

📖 Explanation: The correct answer is C. After receiving a completion interrupt, the driver must read the device’s status register to verify that the write succeeded and to clear the interrupt condition. Immediately scheduling a user process (A) may be premature, resetting the device (B) could disrupt normal operation, and ignoring the interrupt (D) would waste the signal. Therefore, checking the status ensures correct I/O handling.

Q5. An operating system discovers that two devices share the same IRQ line. Which strategy must the OS employ to correctly handle interrupts from both devices?

A.Assign a unique vector to each device and ignore the shared line
B.Use interrupt sharing mechanisms that allow multiple handlers to be invoked for the same vector ✅
C.Disable maskable interrupts while the devices operate
D.Convert the shared IRQ to a non‑maskable interrupt
💡 Difficulty: hard | ✅ Correct: B

📖 Explanation: The correct answer is B. When two devices share an IRQ line, the OS must allow multiple interrupt handlers to be linked to the same vector and invoke each in turn, often by checking device‑specific status registers. Assigning unique vectors (A) is not possible without hardware changes. Disabling maskable interrupts (C) would halt all normal I/O, and converting to a non‑maskable interrupt (D) is not supported and would jeopardize system stability. Shared‑interrupt handling preserves correct operation.

Q6. How does the interrupt mechanism distinguish between processor exceptions such as divide‑by‑zero and regular device‑generated interrupts?

A.Exceptions use vector numbers 0‑31 and are non‑maskable, while device interrupts use vectors 32‑255 and are maskable ✅
B.Exceptions are always maskable, while device interrupts are non‑maskable
C.Both use the same vector range but are identified by a flag bit
D.The CPU treats all interrupts identically regardless of source
💡 Difficulty: hard | ✅ Correct: A

📖 Explanation: The correct answer is A. Processor exceptions occupy vectors 0‑31 and are non‑maskable, meaning they cannot be turned off and are reserved for critical faults like divide‑by‑zero. Device‑generated interrupts use vectors 32‑255, which are maskable and can be enabled or disabled by software. Option B reverses the maskability, option C suggests a flag that does not exist in the Intel design, and option D ignores the distinct handling, making them incorrect.

Q7. Why does the operating system install interrupt handlers into the interrupt vector during boot time?

A.To allow the CPU to execute user programs without interruption
B.To enable the system to respond quickly to hardware events as they occur ✅
C.To prevent any interrupts from ever occurring
D.To increase the clock speed of the processor
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: The correct answer is B. During boot, the OS probes hardware, determines which devices are present, and registers appropriate handlers at specific vector entries so that when a device raises an interrupt, the CPU can quickly jump to the correct routine. Option A is unrelated to interrupt handling, option C is false because interrupts are necessary for I/O, and option D misstates the effect of installing handlers. Prompt handler installation is essential for responsive I/O.

Q8. If a high‑priority interrupt arrives while a low‑priority interrupt service routine (ISR) is executing, what happens to the low‑priority ISR?

A.It continues to run to completion before the high‑priority ISR starts
B.It is paused, the high‑priority ISR runs, then the low‑priority ISR resumes ✅
C.It is terminated and must be restarted later
D.It is converted into a kernel thread
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: The correct answer is B. When a higher‑priority interrupt arrives, the CPU saves the state of the currently running low‑priority ISR, services the high‑priority one, and then restores the saved state to resume the low‑priority ISR. Option A would ignore priority, option C would lose work and require restarting, and option D describes a different mechanism not used for simple ISR pre‑emption. This behavior ensures urgent tasks are addressed promptly while preserving the original ISR work.
