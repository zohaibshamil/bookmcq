What is I/O protection in Kernel I/O Subsystem?

Definition:
I/O protection restricts direct hardware access to privileged kernel mode, validating all user I/O requests against permission bits and resource quotas.

Example:
User process cannot execute ; must use syscall checked against ACLs and capability tokens.

Reason:
Preventing unauthorized hardware manipulation safeguards system security, prevents crashes, and enforces fair resource sharing among processes.

Q1. Why are vectors 0–31 designated as non‑maskable in the Intel interrupt architecture?

A.They are reserved for critical processor exceptions ✅
B.They are for user‑level software interrupts
C.They are for legacy BIOS calls
D.They are for DMA channels
💡 Difficulty: easy | ✅ Correct: A

📖 Explanation: The first 32 vectors correspond to events such as divide error, page fault, and machine check, which indicate conditions that the CPU must handle immediately to maintain correct operation. Because masking them could allow a serious fault to go unnoticed, the architecture makes them non‑maskable. This ensures the operating system is forced to service these critical errors right away, whereas lower‑priority or device‑generated interrupts can be masked or delayed.

Q2. How do interrupt priority levels improve system responsiveness compared to simply masking all interrupts?

A.They let higher‑priority interrupts pre‑empt lower‑priority ones ✅
B.They increase the size of the interrupt vector table
C.They reduce the number of required IRQ lines
D.They eliminate the need for device drivers
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: Priority levels assign a rank to each interrupt source, so when a low‑priority handler is executing, a higher‑priority interrupt can interrupt it and be serviced immediately. If the system only used a global mask, every interrupt would be delayed until the mask is cleared, degrading responsiveness. By using priorities, the OS can defer only less important work while still reacting quickly to urgent events, keeping the system interactive and reliable.

Q3. A driver installs an interrupt handler for vector 45. While this handler runs, a higher‑priority interrupt with vector 20 occurs. What does the CPU do?

A.It pre‑empts the current handler and jumps to vector 20 ✅
B.It queues vector 20 until the handler finishes
C.It ignores vector 20 until the mask is cleared
D.It resets the processor
💡 Difficulty: hard | ✅ Correct: A

📖 Explanation: Vector 20 falls in the non‑maskable range (0‑31) and has a higher priority than vector 45, which is maskable. The CPU’s priority scheme allows the higher‑priority interrupt to pre‑empt the lower‑priority routine, saving the current context and branching to the handler for vector 20. This behavior prevents critical errors from being delayed, while the lower‑priority handler resumes once the high‑priority work completes.

Q4. During operation a device raises an interrupt with vector 70. How does the operating system decide which routine to run?

A.It looks up vector 70 in the interrupt‑vector table ✅
B.It scans the device’s PCI ID for a match
C.It checks the DMA channel assigned to the device
D.It asks the BIOS for the handler address
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: The interrupt‑vector table is a data structure that maps each possible vector number to a specific handler address. When the CPU receives vector 70, the OS indexes this table, retrieves the stored address, and transfers control to that routine. This direct mapping is fast and deterministic, unlike searching device IDs or consulting the BIOS, which would add unnecessary latency and complexity to interrupt handling.

Q5. A page‑fault exception (vector 14) occurs while a process accesses an unmapped page. Why is this interrupt maskable, and what steps should the OS take?

A.The OS saves the faulting address, loads the required page into memory, and then resumes the process ✅
B.The OS ignores the fault and continues execution
C.The CPU treats the fault as a non‑maskable error and halts
D.The OS resets the processor
💡 Difficulty: hard | ✅ Correct: A

📖 Explanation: Page faults are caused by normal memory accesses and can be handled without stopping the entire system, so they are maskable. The OS records the faulting virtual address, allocates a physical page, updates the page table, and then restarts the instruction that caused the fault. By handling the event in software, the OS maintains program continuity while protecting memory integrity, illustrating how maskable exceptions enable graceful recovery.

Q6. After boot, a new peripheral is added to the system. What must the operating system do to ensure its interrupts are serviced correctly?

A.Update the interrupt‑vector table with a handler for the device’s vector ✅
B.Reboot the machine to reload the BIOS defaults
C.Disable all other interrupts while the device is active
D.Reuse an existing vector already assigned to another device
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: When a new device appears, the OS assigns it a free vector number and records the address of its handler in the interrupt‑vector table. This dynamic update allows the CPU to route future interrupts from the device to the correct routine without requiring a full system restart. Ignoring the new device or reusing a vector would cause conflicts or missed interrupts, leading to unreliable I/O behavior.

Q7. What is the primary distinction between a double‑fault (vector 8) and a general‑protection fault (vector 13)?

A.A double‑fault occurs while handling another fault, making it more severe ✅
B.A general‑protection fault is always maskable, while a double‑fault is not
C.A double‑fault only happens on legacy hardware
D.Both faults invoke the same handler routine
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: A double‑fault signals that an exception occurred while the CPU was already processing a different exception, indicating a failure in the exception‑handling mechanism itself. This makes it a higher‑severity condition than a general‑protection fault, which simply indicates an illegal memory or privilege access and can be handled normally. Understanding this difference helps OS designers prioritize recovery actions and maintain system stability.

Q8. Which vector number is assigned to the divide‑error exception?

A.0 ✅
B.1
C.2
D.3
💡 Difficulty: easy | ✅ Correct: A

📖 Explanation: The Intel interrupt architecture defines vector 0 for the divide‑error exception, which is raised when a program attempts to divide by zero or when the quotient is too large to fit in the destination register. Recognizing this mapping allows developers to install a specific handler at vector 0 to catch arithmetic errors early, preventing undefined behavior and ensuring the operating system can safely terminate or correct the offending process.
