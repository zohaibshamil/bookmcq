What is Process creation and termination in operating system?

Definition:
Process creation involves generating a new process by duplicating or replacing the parent process's address space, assigning unique identifiers, and initializing PCB structures. Process termination occurs when a process completes execution or is forcibly stopped, releasing all allocated resources back to the operating system for reallocation to other waiting processes in the system efficiently.

Working:
Creation uses system calls like fork() creating child process as copy of parent, or exec() replacing current process image with new program. The OS allocates memory, creates PCB, assigns PID, and adds to ready queue. Termination uses exit() system call, OS deallocates memory, closes files, releases resources, removes PCB, and notifies parent process through wait() call for proper cleanup handling.

Example:
In Unix, parent process calls fork() creating child with new PID. Child executes exec() loading different program. When child finishes, it calls exit(status). Parent calls wait(&status) to collect exit status and release child's resources. If parent terminates before child, init process adopts orphaned children ensuring proper resource cleanup and preventing zombie processes in the system.

Reason:
Process creation enables multitasking by spawning new tasks dynamically, supports hierarchical process organization through parent-child relationships, and facilitates modular program design. Termination ensures resource leak prevention, maintains system stability by cleaning up after processes, and allows proper error handling through exit status codes for debugging and process coordination purposes effectively.

Common MisConceptions:
Students confuse fork() and exec(); fork() duplicates process while exec() replaces it. Many think terminated processes immediately disappear; actually, they become zombies until parent collects status via wait(). Another misconception is that only parent can terminate child; actually, OS can kill any process. People also believe all resources free instantly, but some may persist until explicitly released.

Exam Preparation Tips: How to prepare this topic
Understand fork-exec-wait-exit sequence thoroughly. Practice tracing parent-child process relationships. Learn about orphan and zombie processes with solutions. Study process tree structures. Memorize system calls and their purposes. Solve problems on resource allocation during creation and deallocation during termination with proper synchronization mechanisms.

Key Terms:

  • fork() - System call creating child process as duplicate of parent.
  • exec() - System call replacing current process image with new program.
  • Zombie Process - Terminated process whose entry still exists in process table waiting for parent to read exit status.
  • Orphan Process - Process whose parent has terminated, adopted by init process.
  • wait() - System call making parent wait for child termination and collect status.

📝 All Process creation and termination in operating system MCQs

Q1. Which system call creates a new process by duplicating the calling process?

A.exec
B.fork ✅
C.wait
D.exit
💡 Difficulty: easy | ✅ Correct: B

📖 Explanation: The fork system call creates a child process that is a near copy of the parent, including its program and open resources. Both processes then continue from the instruction after the call, and the return value tells each one whether it is the parent or the child.

Q2. Which system call replaces the memory image of the current process with a new program?

A.fork
B.exec ✅
C.wait
D.exit
💡 Difficulty: easy | ✅ Correct: B

📖 Explanation: The exec system call loads a new program into the existing process, discarding the old program's code, data and stack. The process keeps its identifier, so exec changes what the process runs rather than creating a new process, which is a key distinction when reasoning about process creation.

Q3. Which system call allows a parent process to wait for a child to finish and retrieve its exit status?

A.wait ✅
B.exec
C.fork
D.getpid
💡 Difficulty: easy | ✅ Correct: A

📖 Explanation: The wait call suspends the parent until one of its children terminates and returns the child's exit status. Collecting this status also releases the resources kept for the terminated child, so calling wait is the normal way for a parent to synchronise with and clean up after its children.

Q4. What is a process called when it has terminated but its exit status has not yet been collected by its parent?

A.Orphan
B.Zombie ✅
C.Daemon
D.Idle process
💡 Difficulty: easy | ✅ Correct: B

📖 Explanation: A zombie retains only a small entry in the process table so that the parent can read the exit status later. It uses no CPU or memory for execution, but its entry remains until the parent calls wait. Many zombies usually indicate a parent that fails to collect its children.

Q5. What is a child process called when its parent terminates before the child does?

A.Orphan ✅
B.Zombie
C.Foreground process
D.Sibling
💡 Difficulty: easy | ✅ Correct: A

📖 Explanation: An orphan is a child whose parent has ended. Operating systems typically reassign orphans to a system process such as init, which becomes their new parent. This adoption ensures that someone remains responsible for collecting the orphan's exit status when it finally terminates.

Q6. A student believes that exec creates a new process with a new process identifier. Which correction is most accurate?

A.exec creates a new process with a new identifier, so the student is correct.
B.exec keeps the same process identifier and replaces the program the process runs, so it does not create a new process. ✅
C.exec deletes all processes in the system.
D.exec is only used to print messages.
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: When a process calls exec, its identifier and parent relationship remain the same, but the code, data and stack are replaced by the new program. Creating a new process is the job of fork. Confusing the two calls leads to mistaken assumptions about process trees and identifiers.

Q7. Why does fork return different values to the parent and the child?

A.So that each process can tell whether it is the original parent or the newly created child and act accordingly. ✅
B.So the operating system can count the number of printers.
C.So the child becomes a zombie immediately.
D.So both processes have identical memory.
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: After fork, both processes run the same code, so the return value is the only way to distinguish them. The parent receives the child's identifier, while the child receives zero. Programs branch on this value so that each process performs its own role after creation.

Q8. Why must a parent normally call wait for its children?

A.To release the exit information kept for each child and prevent it from remaining as a zombie. ✅
B.To make the child run faster.
C.To change the child's program file on disk.
D.To delete the parent's memory.
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: When a child terminates, its exit status is kept until the parent collects it. Calling wait frees that entry and reports the result. Without this call, terminated children accumulate as zombies, consuming process table slots, which is why well-behaved programs always collect their children.

Q9. Why does the operating system adopt an orphan process under the init process, rather than leaving it without a parent?

A.So that some process always remains responsible for collecting the orphan's exit status when it terminates. ✅
B.So that orphans can run without any operating system at all.
C.So that the orphan can change its own identifier.
D.So that the orphan is immediately deleted.
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: Every process needs a parent to eventually collect its exit information and keep the process tree consistent. Reassigning orphans to init provides that responsibility, so terminated orphans do not accumulate as unmanaged zombies, which would otherwise waste process table space.

Q10. Why does copy-on-write make fork efficient?

A.Because the parent and child initially share memory pages, and a page is copied only when one of them writes to it. ✅
B.Because fork copies the entire memory of the system at once.
C.Because fork deletes all pages before copying.
D.Because copy-on-write removes the need for a child process.
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: Copying all memory at fork time would be slow and wasteful, especially when the child immediately calls exec. With copy-on-write, pages are shared until modified, so the cost of duplicating data is paid only for pages that actually change. This makes fork practical even for large processes.

Q11. After a fork, why does a change to a variable in the child not affect the parent's copy of that variable?

A.Because each process has its own separate address space, even though pages may be shared until written. ✅
B.Because variables exist only in the operating system.
C.Because the child cannot write to any memory.
D.Because the parent deletes the variable.
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: Although copy-on-write shares pages initially, a write causes the affected page to be copied so that each process has its own version. The address spaces are logically separate, so changes made by one process are invisible to the other, which is essential for correct isolation.

Q12. Why does termination of a parent not necessarily terminate its children on many systems?

A.Because children are independent processes unless the operating system enforces cascading termination. ✅
B.Because children are stored in the printer.
C.Because the parent cannot end at all.
D.Because children always end before parents.
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: A child is a separate process, and most systems let it continue after the parent exits, leading to orphan status. Some systems enforce cascading termination, which ends all descendants along with the parent. The behaviour is therefore a policy decision, not an automatic consequence of process creation.

Q13. A process has terminated and its exit status is recorded in the process table. Why does the operating system keep this entry until the parent collects it?

A.Because the parent needs the exit status to know whether the child succeeded or failed. ✅
B.Because the entry is needed to restart the computer.
C.Because the entry stores the child's keyboard layout.
D.Because processes cannot terminate without leaving an entry.
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: The exit status tells the parent how the child finished, which may affect the parent's next actions. Keeping the minimal entry until it is read preserves this information. Once collected, the entry is released so that the table space can be reused for new processes.

Q14. A program calls fork unconditionally three times in sequence in the same process. How many processes exist after these calls, including the original?

A.4
B.6
C.8 ✅
D.16
💡 Difficulty: hard | ✅ Correct: C

📖 Explanation: Each fork doubles the number of processes because every existing process creates one new copy. After three forks, the count is 23=82^3 = 823=8, including the original. Recognising this exponential growth is important when reasoning about loops that create processes, since they can quickly exhaust system resources.

Q15. A program executes the statement fork followed by fork, unconditionally, and every process then prints one line. How many lines are printed?

A.2
B.3
C.4 ✅
D.8
💡 Difficulty: hard | ✅ Correct: C

📖 Explanation: The first fork produces two processes, and the second fork doubles them to four, so four lines are printed. Each process executes the same code after fork, so the count follows the doubling pattern. Careful tracing of each call is essential for this kind of multi-step reasoning.

Q16. A shell creates a child to run a command. Which sequence of system calls is typically used?

A.fork in the shell, then exec in the child, with the shell calling wait ✅
B.exec in the shell first, then fork, then wait
C.wait first, then fork, then exec in the parent
D.exit first, then fork
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: The shell calls fork to create a child, the child calls exec to load the command's program, and the shell calls wait to pause until the command finishes. This standard sequence lets the shell launch commands while retaining control, and it explains why fork and exec are usually used together.

Q17. After a fork, the parent sets a variable x to 5 and the child then sets its own copy of x to 10. What value does the parent see for x afterward?

A.5 ✅
B.10
C.0
D.The value is undefined.
💡 Difficulty: hard | ✅ Correct: A

📖 Explanation: The child's assignment changes only the child's copy, so the parent still holds 5. Each process has its own address space, and writes are not shared even though memory pages may initially be shared. This isolation is a key property that makes process-based concurrency predictable.

Q18. A child process exits with status 3 and the parent calls wait. What value does wait report for the child's exit status?

A.0
B.3 ✅
C.Negative one
D.The child's process identifier
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: When the child terminates with status 3, the parent receives this value through wait, which lets it interpret the outcome. By convention a status of zero indicates success, while nonzero values signal specific failures. The exit status is the information carried from the child to the parent.

Q19. A process tree has P1 with children P2 and P3, and P2 has child P4. Under a cascading termination policy, P2 is terminated by the operating system. Which processes terminate as a result?

A.Only P2
B.P2 and P4 ✅
C.P1, P2 and P3
D.P3 and P4
💡 Difficulty: hard | ✅ Correct: B

📖 Explanation: Cascading termination ends a process together with all of its descendants, so terminating P2 also ends its child P4. P1 and P3 are not descendants of P2, so they continue. Identifying the subtree correctly is the key step in deciding which processes are affected by the termination.

Q20. Which value does fork return to the child process when it succeeds?

A.The child's own process identifier
B.Zero ✅
C.The parent's process identifier
D.Negative one
💡 Difficulty: easy | ✅ Correct: B

📖 Explanation: On success, fork returns zero to the child and the child's identifier to the parent. The zero return value lets the child recognise that it is the new process. Checking this return value is the standard way that programs decide which branch of code each process should follow.

Q21. A student says that a zombie process is still executing and consuming CPU time. What is the error in this reasoning?

A.There is no error, because zombies are active processes.
B.A zombie has already terminated and does not execute; it only retains a small process table entry until its parent collects the exit status. ✅
C.Zombies are programs stored on the printer.
D.Zombies only occur in the bootloader.
💡 Difficulty: hard | ✅ Correct: B

📖 Explanation: A zombie has finished executing and holds no CPU time. Its entry remains only to store the exit status for the parent. The student confuses the terminated state with an active one, which misreads what the presence of zombies indicates about the system.

Q22. A student says that when a parent calls exec, the parent is replaced by a new process with a different identifier. What is wrong with this claim?

A.Nothing is wrong, since exec always creates a new process.
B.exec replaces the program within the same process, which keeps the same identifier, so no new process is created. ✅
C.exec only works on printers.
D.Parents cannot call exec at all.
💡 Difficulty: hard | ✅ Correct: B

📖 Explanation: The exec call changes the code and data of the calling process while keeping its identifier and relationships. Creating a new process is done by fork. The student merges these two distinct operations, which leads to wrong conclusions about identifiers and process trees.

Q23. A student says that after fork, parent and child share the same memory, so writes by either process are visible to both. Which correction is most accurate?

A.The claim is correct because fork shares all data permanently.
B.Parent and child have separate address spaces; pages may be shared only until one process writes, so writes are not visible to the other. ✅
C.Fork never creates memory.
D.Processes never have memory.
💡 Difficulty: hard | ✅ Correct: B

📖 Explanation: Copy-on-write shares pages initially for efficiency, but a write triggers a private copy for the writing process. The address spaces are logically separate, so the student's conclusion about permanent visibility of writes is incorrect and would lead to serious errors in program reasoning.

Q24. A student says that a parent need not call wait because the operating system always cleans up terminated children automatically. What is the error?

A.There is no error, since cleanup is always automatic.
B.On many systems the child's entry remains as a zombie until the parent calls wait, so ignoring wait can leave zombies in place. ✅
C.Children never terminate.
D.Wait is only used in printers.
💡 Difficulty: hard | ✅ Correct: B

📖 Explanation: The operating system keeps the exit information until a parent reads it, so cleanup depends on the parent's wait call. Programs that never call wait accumulate zombies, consuming process table entries. The student's claim ignores this responsibility that the parent has in the termination protocol.

Q25. A student says that when a parent terminates, its orphan children are deleted immediately. Which evaluation is most accurate?

A.The claim is correct because orphans cannot survive.
B.The claim is flawed because orphans are typically adopted by a system process such as init and continue running. ✅
C.The claim is correct because orphans always become zombies.
D.The claim is flawed because orphans do not exist on any system.
💡 Difficulty: hard | ✅ Correct: B

📖 Explanation: Operating systems normally reassign orphans to init or an equivalent system process, which then becomes their parent. The orphans continue executing normally. Assuming they are deleted misunderstands the adoption mechanism that preserves the process tree's integrity.

Q26. A process tree shows the shell (PID 100) with three descendants: editor (PID 200), compiler (PID 201) and linker (PID 202), where the linker is a child of the compiler. How many descendants does the shell have in total?

A.1
B.2
C.3 ✅
D.4
💡 Difficulty: medium | ✅ Correct: C

📖 Explanation: The descendants of the shell include every process created beneath it, namely the editor, the compiler and the linker. The linker is a child of the compiler but still counts as a descendant of the shell. Counting all levels of the tree rather than only direct children is the key point.

Q27. A table records a child process with status Z from time 5 to time 20 while its parent remains sleeping and never calls wait. What does this record most likely indicate?

A.The child is a zombie waiting for its parent to collect its exit status. ✅
B.The child is running normally and using the CPU.
C.The child has been adopted and is now the root of the tree.
D.The child is a daemon that runs in the background forever.
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: Status Z denotes a zombie, a terminated process whose entry remains until the parent calls wait. Since the parent is sleeping and never collects the status, the entry persists for the entire interval. The record is therefore best explained by a zombie rather than normal execution.

Q28. A bar chart shows the number of processes after 1, 2, 3 and 4 fork iterations as 2, 4, 8 and 16. What is the best inference?

A.Process count grows exponentially with the number of fork iterations, so unbounded forking can exhaust system resources. ✅
B.Process count grows linearly and is always small.
C.Fork has no effect on the number of processes.
D.Process count falls as more forks are executed.
💡 Difficulty: hard | ✅ Correct: A

📖 Explanation: The bars double with each iteration, which is the signature of exponential growth. Unbounded forking inside loops can therefore consume process table entries and memory rapidly, which is why programs must control how many processes they create.

Q29. A line graph shows the memory used by a newly forked child over time. It stays near zero for a long period, then rises in steps as the child writes to its variables. What does this pattern suggest?

A.Copy-on-write is delaying the copying of pages until they are actually modified. ✅
B.The child copies the entire parent memory immediately at fork time.
C.The child never uses any memory at all.
D.The memory use is caused by the printer.
💡 Difficulty: hard | ✅ Correct: A

📖 Explanation: The flat start indicates that pages are shared rather than copied at fork time. The steps occur when the child writes to variables and private copies of the affected pages are created. The graph therefore matches the copy-on-write strategy, which defers copying until necessary.

Q30. A graph compares the time to create a process using a full copy of memory against copy-on-write, across different memory sizes. Copy-on-write stays nearly constant while full copying grows with memory size. What is the best inference?

A.Copy-on-write makes process creation cost largely independent of memory size, while full copying scales with it. ✅
B.Full copying is always faster than copy-on-write.
C.Memory size has no effect on creation time.
D.Copy-on-write requires the entire memory to be copied first.
💡 Difficulty: hard | ✅ Correct: A

📖 Explanation: The flat line for copy-on-write shows that the immediate cost does not grow with memory size, while full copying rises steadily. The inference is supported because the data compares the two methods across sizes, illustrating why modern systems favour copy-on-write for fork.

Q31. Which combination correctly describes how a new program is run in a new process on a typical system?

A.fork creates a child, and the child calls exec to load the new program. ✅
B.exec creates a new process, and the parent then calls fork.
C.wait creates a child and loads the program into it.
D.exit loads the program and creates a new process.
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: Running a new program in a new process combines two steps: fork creates the child, and the child uses exec to replace its image with the desired program. The other sequences reverse or misassign the roles of these calls, so they fail to create a separate process running the new program.

Q32. Which pairing correctly links a parent's call with its effect on the child's exit status?

A.The parent's wait retrieves the child's exit status and releases its process table entry. ✅
B.The parent's exec returns the child's exit status to the operating system.
C.The parent's fork deletes the child's exit status.
D.The parent's exit prints the child's memory contents.
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: The wait call is the mechanism by which a parent collects the child's exit status and allows the entry to be released. The other pairings assign the wrong effect to exec, fork or exit, so they do not describe how the exit status is transferred from child to parent.

Q33. Which situation leaves a zombie process in the system?

A.A child terminates and its parent never calls wait to collect its exit status. ✅
B.A child calls exec successfully and continues running.
C.A parent calls wait for a child that is still running.
D.A process is adopted by init after its parent exits.
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: A zombie arises when a child has ended but its parent has not yet collected the exit status, so the entry persists. The other situations involve normal execution, waiting for an active child, or adoption by init, none of which leave a terminated entry uncollected.

Q34. A program calls fork in a loop so that every existing process forks once per iteration, for 5 iterations, starting from one original process. Including the original, how many processes exist at the end?

A.6
B.10
C.16
D.32 ✅
💡 Difficulty: hard | ✅ Correct: D

📖 Explanation: Each iteration doubles the number of processes, so after 5 iterations the count is 25=322^5 = 3225=32, counting the original. The pattern shows that loops of fork calls grow exponentially. Forgetting that every process participates in each iteration, or counting only the newly created ones, leads to the smaller incorrect totals.

Q35. Process P (PID 300) forks child C (PID 301), and C forks grandchild G (PID 302). P exits, and then C exits before G finishes. What is the parent of G after C exits?

A.300
B.301
C.1 ✅
D.0
💡 Difficulty: hard | ✅ Correct: C

📖 Explanation: When C exits, G is orphaned, and the operating system reassigns it to init, which has PID 1 in typical systems. P's identifier 300 and C's identifier 301 are no longer valid parents of G at that point. Following the adoption rule step by step is the key to answering this multi-step scenario.
