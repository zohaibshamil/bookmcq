What is IPC systems examples shared memory message passing?

Definition:
Shared memory IPC establishes a common memory region mapped into multiple address spaces allowing direct data access with latency , whereas message passing uses kernel-mediated send/receive primitives with overhead proportional to message size .

Example:
In shared memory, two video processing threads directly read/write pixel arrays in a mapped segment avoiding copies, while in message passing, a web server sends HTTP request data via to a backend worker process through the kernel buffer.

Reason:
Choosing between these models depends on performance versus safety trade-offs; shared memory offers speed for tightly coupled processes on the same machine, while message passing provides location transparency and built-in synchronization suitable for distributed or loosely coupled architectures.

Q3. A system administrator observes that a POSIX shared memory segment is consuming disk space even after all processes that use it have terminated. Which of the following is the most probable cause?

Q4. A developer is trying to debug a POSIX shared memory program. The `shm_open()` call returns a valid file descriptor, but the subsequent `mmap()` call fails with the error `EACCES`. What is the most likely cause?

A.The shared memory object was created with read-only permissions (e.g., `O_RDONLY`), but `mmap` is trying to map it with `PROT_WRITE`. ✅
B.The size of the shared memory object, as set by `ftruncate()`, is 0 bytes.
C.The `MAP_SHARED` flag was omitted from the `mmap()` call.
D.The `shm_unlink()` function was called before `mmap()`.
💡 Difficulty: hard | ✅ Correct: A

📖 Explanation: The `EACCES` error in `mmap()` indicates a permission problem. The permissions are determined by the flags used to open the file descriptor and the protection flags passed to `mmap()`. If the shared memory object was opened with `O_RDONLY`, the file descriptor only allows read access. An `mmap()` call with `PROT_WRITE` would then be trying to write to a read-only file descriptor, resulting in `EACCES`. A size of 0 would cause a different error (e.g., `EINVAL` or the mapping being empty). Omitting `MAP_SHARED` would default to `MAP_PRIVATE`, which is allowed but not desired for IPC. If `shm_unlink()` were called, the file descriptor would likely be invalid, leading to a different error like `EBADF`.

Q5. In a system using POSIX shared memory, two processes, A and B, access a shared integer. Process A increments the integer, and Process B reads it. If no synchronization is used, which of the following scenarios is a likely outcome?

A.Process B will always read the updated value because shared memory writes are atomic.
B.The value read by Process B will be unpredictable, as the read and write operations are not atomic. ✅
C.The operating system will prevent concurrent access, causing Process B to block until Process A finishes.
D.The shared memory will become corrupted, causing a segmentation fault.
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: Without synchronization mechanisms like mutexes or semaphores, concurrent access to shared memory leads to race conditions. The read and write operations on a shared integer are not guaranteed to be atomic. Process A's increment (read-modify-write) can be interrupted by Process B's read, leading to Process B reading a stale or intermediate value. The outcome is unpredictable and depends on the scheduling of the processes. The OS does not automatically synchronize shared memory access; it's the programmer's responsibility. Corruption leading to a segfault is unlikely for a simple integer; the memory remains valid, just its contents are subject to race conditions.

C.POSIX shared memory is slower than Mach message passing because it requires system calls for every access.
D.Mach message passing is always faster than POSIX shared memory because it uses ports.
💡 Difficulty: hard | ✅ Correct: B

📖 Explanation: POSIX shared memory establishes a shared region by memory-mapping a file. After this setup, access to the shared memory is just normal memory access, requiring no system calls. Mach's message passing, to address the performance issue of double-copying (sender to kernel, kernel to receiver), employs virtual memory mapping techniques to map the sender's memory into the receiver's address space, effectively avoiding the second copy. POSIX shared memory does not require system calls for every access, making it generally faster than message passing for large data transfers. The use of ports in Mach is an addressing mechanism, not a direct factor in data copying speed.

Q8. Consider the POSIX shared memory producer-consumer solution. The bounded buffer uses a circular array with `in` and `out` pointers. If `BUFFER_SIZE` is 5, and the producer has just filled the buffer (i.e., `((in + 1) % BUFFER_SIZE) == out`), what does this condition indicate?

C.The buffer is full and the producer must wait. ✅
D.An overflow error has occurred.
💡 Difficulty: medium | ✅ Correct: C

📖 Explanation: The condition `((in + 1) % BUFFER_SIZE) == out` is the standard way to detect a full buffer in a circular queue implementation that uses one slot to distinguish between empty and full states. When this condition is true, it means that the producer has caught up to the consumer and there is no empty slot to write into. The producer must therefore block or wait until the consumer consumes an item and moves the `out` pointer. The buffer is not empty; it's full. Q9. In the POSIX shared memory example, what is the role of the `shm_unlink()` function?

A.It detaches the shared memory from the calling process's address space.
B.It immediately deallocates the shared memory object and frees its resources.
C.It marks the shared memory object for removal, and it is destroyed when all references to it are closed. ✅
D.It reduces the size of the shared memory object.
💡 Difficulty: medium | ✅ Correct: C

📖 Explanation: `shm_unlink()` is analogous to `unlink()` for files. It removes the name of the shared memory object from the system. The actual memory and resources associated with the object are not freed until the last process that has the object mapped (via `mmap()`) unmaps it and closes its file descriptor. This is a crucial design point for persistence and safety, allowing processes to continue using the object while preventing new processes from opening it by name. `shm_unlink()` does not detach the memory; `munmap()` does that. It doesn't immediately free resources, and it doesn't change the object's size.

Q16. In the POSIX shared memory program, the producer writes to shared memory using `sprintf()`. Why is it generally recommended to use `sprintf()` or `memcpy()` instead of direct assignment for complex data structures?

A.Direct assignment is slower than `sprintf()` and `memcpy()`.

💡 Difficulty: medium | ✅ Correct: C

📖 Explanation: The primary concern when writing to shared memory is concurrency. Q20. Consider the producer-consumer problem using POSIX shared memory. If `BUFFER_SIZE` is 10, and the producer has produced 9 items, what is the value of `in` relative to `out` assuming the buffer is empty initially (`in = out = 0`)?

A.in = 9, out = 0 ✅
B.in = 10, out = 0
C.in = 0, out = 9
D.in = 9, out = 9
💡 Difficulty: easy | ✅ Correct: A

📖 Explanation: The producer increments `in` after placing an item in the buffer. With an initially empty buffer, after producing 9 items, the `in` pointer will have been incremented 9 times, so `in = 9`. The consumer hasn't consumed anything, so `out` remains 0. The condition for a full buffer is `((in + 1) % BUFFER_SIZE) == out`, which would be `((10) % 10) == 0`, which is true. However, with a buffer size of 10, this implementation only allows 9 items to be stored before the producer is blocked (to distinguish empty from full). So after 9 items, the buffer is effectively full, and `in=9, out=0`.

Q24. In a POSIX shared memory system, the producer and consumer are separate processes. The producer writes a large image to the shared memory. The consumer reads it and displays it. A.A segmentation fault due to accessing invalid memory.

💡 Difficulty: medium | ✅ Correct: B

Q26. In the POSIX shared memory example, what happens if the `shm_fd` returned by `shm_open()` is not closed after the `mmap()` is successful?

A.It will cause a memory leak.

C.It will prevent other processes from mapping the shared memory object.
D.It is harmless; the file descriptor is automatically closed when the process exits. ✅
💡 Difficulty: medium | ✅ Correct: D

📖 Explanation: The file descriptor obtained from `shm_open()` is a system resource. If `shm_unlink()` is called, the shared memory object is marked for removal. It will actually be destroyed when all references to it are closed, which includes both the memory mappings and the open file descriptors. If the `shm_fd` is not closed, the reference count for the object will not drop to zero, so `shm_unlink()` will not cause the object to be fully destroyed. This can lead to resource leaks. It's not a 'memory leak' in the traditional sense of leaking heap memory, but a leak of a kernel resource. It doesn't prevent other processes from mapping the object, as they open it independently. If the process exits, the file descriptor is closed automatically, but it's good practice to close it explicitly.

Q27. A system uses Mach message passing. A client sends a message to a server's port and then immediately sends another message to the same port. Mach guarantees FIFO ordering for messages from the same sender. What does this guarantee imply?

A.Messages from the client will be processed in the order they were sent, but messages from other senders may be interleaved. ✅
B.The server will process all messages from all senders in the order they arrive in the mailbox.
C.The kernel will always deliver the messages in the order they were sent, regardless of the receiver.
D.The client will receive the replies in the same order as its requests.
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: Mach guarantees FIFO ordering for messages from the same sender to a given mailbox. This means if client A sends message 1 then message 2 to a port, message 1 will be queued before message 2. However, if client B sends a message in between, the order between messages from different senders is not guaranteed. The mailbox could contain [A1, B1, A2] or [B1, A1, A2]. The guarantee is about the relative order of a single sender's messages. It doesn't guarantee that all messages in the mailbox are in global FIFO order. Replies are a separate mechanism and their order isn't implied by this queue ordering.

Q28. A programmer is debugging a POSIX shared memory program. The `mmap()` call returns a valid pointer, but accessing the pointer causes a segmentation fault. Which of the following is the most likely cause?

D.The `ftruncate()` call set the size to 0.
💡 Difficulty: hard | ✅ Correct: A

📖 Explanation: A segmentation fault on accessing a mapped pointer indicates that the memory is not accessible. `mmap()` takes a `prot` argument that specifies the protection. If `PROT_NONE` is used, the memory is reserved but has no permissions (read, write, or execute), and any access will cause a segmentation fault. Using `MAP_PRIVATE` (instead of `MAP_SHARED`) would allow access; it just wouldn't be shared. If `shm_unlink()` were called before `mmap()`, `mmap()` would likely fail, not return a valid pointer. A size of 0 would not cause a segfault on access; it would just map an empty region.

Q29. The Mach operating system uses ports for communication. Which of the following statements about ports in Mach is correct?

📖 Explanation: A key feature of Mach ports is that rights (including receive rights) are themselves data that can be sent in messages. A task that owns a port can send the receive right for that port to another task, effectively delegating the ability to receive messages to that new task. This enables flexible communication patterns. A port is owned by a task, not the kernel. A task can receive from a port it doesn't own if the owner has delegated the receive right to it. Q30. In the Windows ALPC facility, what is the purpose of the 'callback mechanism' supported by communication channels?

📖 Explanation: The callback mechanism in ALPC enhances the flexibility of communication. Normally, in a client-server RPC, the client sends a request and waits for a reply. Q31. A developer is trying to use the POSIX shared memory example. The `shm_open()` call returns `-1` and sets `errno` to `EINVAL`. What is the most likely cause of this error?

Q32. When comparing the synchronization requirements of POSIX shared memory and Mach message passing, what is a key distinction?

A.Shared memory requires explicit synchronization, while message passing provides implicit synchronization through blocking sends and receives. ✅
B.Message passing requires explicit synchronization, while shared memory provides implicit synchronization.
C.Both require explicit synchronization mechanisms like mutexes and semaphores.
D.Neither requires any synchronization, as the kernel handles all concurrency issues.
💡 Difficulty: hard | ✅ Correct: A

📖 Explanation: This is a fundamental distinction. In POSIX shared memory, the processes share a memory region. They must coordinate their access using synchronization primitives (e.g., POSIX semaphores, mutexes) to avoid race conditions. This is explicit synchronization coded by the programmer. In Mach message passing, the `msg_send` and `msg_receive` operations can be blocking. A blocking `msg_receive` will wait until a message is available, and a blocking `msg_send` can wait until the message is delivered. This provides a form of implicit synchronization; the sending or receiving process will block, coordinating the flow of data without the need for separate mutexes or semaphores for the data transfer itself.

Q33. A process in a Mach system wants to send a message but is unsure if the target mailbox is full. It wants to avoid any situation where it is blocked indefinitely. Which Mach send option is the most appropriate?

B.Wait at most n milliseconds.
C.Do not wait at all and return immediately. ✅
D.Temporarily cache the message.
💡 Difficulty: easy | ✅ Correct: C

📖 Explanation: The process explicitly wants to avoid being blocked. The 'do not wait at all' option is the most straightforward for this. The sender will attempt to send the message. If the mailbox has room, the message is sent and the sender continues. If the mailbox is full, the `msg_send()` call returns immediately with an error (or a status indicating the message wasn't sent). The sender can then take appropriate action, such as retrying later or processing the data differently. Caching might still involve the kernel holding the message, and the sender's behavior depends on the specific implementation of caching. The 'wait at most n ms' could still block for n milliseconds.

📖 Explanation: Mach message passing, with its variable-size messages, is inherently designed for mixed workloads. POSIX shared memory is simpler for large data but requires complex synchronization and buffer management for small, frequent messages, making it less suitable for a control-message intensive workload. Windows ALPC is a valid answer, but the question specifically asks to choose between POSIX and Mach. Mach's message-passing paradigm is more naturally suited to a mix of control and data than a pure shared-memory model.

Q36. In the POSIX shared memory producer-consumer example, if the buffer is empty (`in == out`), and the consumer calls `read()` on the shared memory, what will happen?

C.The consumer will read 0 bytes, indicating an end-of-file.
D.The consumer will read and then the producer must handle the empty condition.
💡 Difficulty: hard | ✅ Correct: B

📖 Explanation: In the provided POSIX shared memory example, there is no built-in synchronization or blocking mechanism. If the consumer is scheduled and `in == out` (buffer empty), it will proceed to read from the shared memory region. It will read whatever data is currently in the buffer, which may be old, uninitialized, or garbage. This is a classic race condition. The consumer doesn't block; it will just read whatever is there.
