What is Interprocess Communication in process implementation?

Definition:
Interprocess Communication (IPC) refers to mechanisms allowing processes to exchange data and synchronize actions, mathematically ensuring mutual exclusion where only one process enters critical section \( CS_i \) at time \( t \) such that \( \sum_{i=1}^{n} \mathbb{I}(P_i \in CS) \leq 1 \).

Example:
A producer process writes data to a bounded buffer of size \( N \) only when the count \( c < N \), while a consumer reads only when \( c > 0 \), using semaphores to prevent race conditions during simultaneous access to the shared counter variable.

Reason:
IPC is essential for coordinating independent processes that must collaborate on complex tasks, preventing data corruption and deadlocks while enabling modular software design where components communicate through well-defined interfaces rather than shared global state.

Q1. A researcher is designing a multi-core system where processes frequently exchange small control messages. Which IPC model would generally provide better performance and why?

A. Shared memory, because it avoids system call overhead after setup
B. Message passing, because it avoids cache coherency issues on multi-core systems ✅
C. Shared memory, because it scales better with the number of cores
D. Message passing, because it requires less memory management overhead

💡 Difficulty: hard | ✅ Correct: B

📖 Explanation:

Recent research on multi-core systems shows that message passing can provide better performance than shared memory due to cache coherency issues. On multi-core systems, shared data migrates among multiple caches, causing cache coherency protocol overhead. Message passing avoids this by not sharing memory, making it more efficient for small, frequent communications despite the system call overhead.

Q2. In a producer-consumer system using shared memory with a bounded buffer of size N, the producer and consumer use pointers 'in' and 'out' with the condition that the buffer is full when ((in + 1) % N) == out, allowing at most N-1 items. What is the primary reason for not allowing N items, and how would the condition need to change to allow N items?

A. To prevent buffer overflow; change to (in == out) for full
B. To avoid ambiguity between empty and full states; use a separate counter or flag ✅
C. To improve memory alignment; use (in % N == out) condition
D. To prevent race conditions; implement locking around buffer access

💡 Difficulty: hard | ✅ Correct: B

📖 Explanation:

The condition ((in + 1) % N) == out artificially reduces capacity to N-1 to distinguish between empty (in == out) and full states. Without this, both states would look identical with the simple pointer-based approach. To allow N items, you need additional state information - either a counter variable tracking the number of items, or a boolean flag indicating whether the buffer is full. This is a classic synchronization challenge where simple pointer arithmetic alone cannot distinguish between empty and full.

Q3. Two processes communicate using message passing. Process A sends a message with a blocking send, and Process B uses a non-blocking receive. The message queue has bounded capacity and is initially empty. Describe what happens immediately after Process A invokes the send operation.

A. Process A blocks until Process B explicitly receives the message
B. Process A continues execution, and the message is placed in the queue ✅
C. Process A blocks until space is available in the message queue
D. The operation fails because both processes must use the same synchronization mode

💡 Difficulty: easy | ✅ Correct: B

📖 Explanation:

With a bounded-capacity queue that is initially empty, a non-blocking send would immediately place the message in the queue. However, the question specifies a blocking send. A blocking send blocks until the message is received by the receiving process OR placed in the mailbox, depending on the implementation. In most message-passing systems, blocking send waits until the message is delivered to the mailbox (if buffering is used) or until the receiver gets it (if no buffering). Since the queue is empty, the message is immediately queued and the sender continues.

Q4. Consider a system using a message-passing IPC mechanism with both blocking send and blocking receive. Under what condition would a rendezvous occur, and what are the implications for the producer-consumer problem?

A. When the message queue is full; producer blocks until consumer empties a slot
B. When the sender sends and receiver simultaneously executes receive; simplifies synchronization ✅
C. When a timeout is specified; prevents deadlock
D. When using non-blocking operations; improves throughput

💡 Difficulty: medium | ✅ Correct: B

📖 Explanation:

A rendezvous occurs when both send and receive operations are blocking - the sender blocks until the receiver accepts the message, and the receiver blocks until a message is available. In the producer-consumer problem, this is ideal because the producer automatically waits when there are no consumers ready, and the consumer automatically waits when no messages are available. This makes the producer-consumer synchronization nearly trivial, as the IPC mechanism handles all the coordination without requiring explicit semaphores or condition variables.

Q5. A developer implements shared memory communication between two processes. The producer writes data to a shared region, and the consumer reads from it. The system occasionally crashes due to memory corruption. Which of the following is the most likely cause and what solution would you propose?

A. Memory mapping error; check the mmap() return value
B. Cache coherency issue; add memory barriers
C. Race condition in accessing shared memory; implement proper synchronization ✅
D. Insufficient memory permissions; check file permissions

💡 Difficulty: hard | ✅ Correct: C

📖 Explanation:

The most likely cause is a race condition where both processes attempt to access the same memory location simultaneously without synchronization. When the producer and consumer both access shared memory without proper coordination, they can corrupt data or read inconsistent states. The solution requires implementing synchronization primitives like mutexes, semaphores, or condition variables to ensure mutual exclusion when accessing shared data. Unlike the other options, race conditions directly explain data corruption in concurrent shared-memory scenarios.

Q6. A system uses POSIX shared memory with memory-mapped files. A producer creates a shared memory object, writes to it, and exits. The consumer then tries to access this memory. Which of the following scenarios would cause the consumer to fail, and how would you fix it?

A. The producer didn't set proper permissions; use umask() before shm_open()
B. The producer called shm_unlink() before the consumer accessed it; remove shm_unlink() ✅
C. The consumer used the wrong name; check the name parameter
D. The mmap() size parameter was incorrect; verify size matches

💡 Difficulty: easy | ✅ Correct: B

📖 Explanation:

The producer calling shm_unlink() before the consumer accesses the shared memory would cause the consumer to fail, as the shared memory object is removed. shm_unlink() should only be called after all processes that need access have finished using the shared memory. The correct approach is to have the consumer call shm_unlink() after it has finished accessing the shared memory, or to ensure proper coordination between processes regarding when to unlink. The unlink operation removes the name from the system but the actual memory object persists until all references are closed.

Q7. Compare the approaches to IPC in Mach and Windows ALPC. Which statement correctly identifies a key difference in how they handle message transmission?

A. Both use only simple message copying without optimization
B. Mach uses virtual memory mapping to avoid double copying; Windows uses different techniques based on message size ✅
C. Windows uses network protocols for local communication
D. Both implement exactly the same optimization strategy

💡 Difficulty: medium | ✅ Correct: B

📖 Explanation:

Mach and Windows take different approaches to message transmission. Mach uses virtual memory management techniques to map the sender's address space containing the message into the receiver's address space, avoiding the double-copy overhead. Windows ALPC (Advanced Local Procedure Call) takes a size-based approach: small messages (≤256 bytes) use the port's message queue with copying; medium messages use a shared memory section object; and large messages allow direct address space access. The key difference is Mach's single elegant solution versus Windows' tiered approach based on message size.

Q8. A system implements message passing with three buffering strategies: zero capacity, bounded capacity (n messages), and unbounded capacity. For each strategy, determine whether the following statement is true or false: "The sender can never be blocked in any of these strategies."

A. True for all three strategies
B. False; zero capacity always blocks sender, bounded and unbounded may block
C. False; bounded capacity may block when full, unbounded never blocks
D. False; zero capacity blocks sender and bounded may block when full ✅

💡 Difficulty: hard | ✅ Correct: D

📖 Explanation:

The correct analysis: In zero-capacity buffering, the sender always blocks until the receiver receives the message because there is no buffer. In bounded capacity with size n, the sender blocks only when the buffer is full. In unbounded capacity, the sender never blocks because the buffer can grow infinitely. Thus the statement is false for zero capacity (always blocks) and bounded capacity (may block), while it's true only for unbounded capacity. This demonstrates the trade-off between buffering strategy and process blocking behavior.

Q9. A server process uses a mailbox for indirect communication. Multiple clients send messages to this mailbox. The server receives messages using a blocking receive. If two clients send messages simultaneously while the server is busy processing a previous request, what happens to the messages?

A. One message is lost due to race condition
B. Both messages are queued in the mailbox FIFO order ✅
C. The server's receive fails and returns an error
D. The clients are blocked until the server is ready

💡 Difficulty: easy | ✅ Correct: B

📖 Explanation:

When multiple messages are sent to a mailbox while the server is busy, the messages are placed in the mailbox's message queue. The mailbox serves as a buffer that holds messages for the receiver. In this scenario, both messages would be queued, typically in FIFO order (though the order between different senders may not be guaranteed). When the server completes its current request and invokes receive(), it will get the first queued message. This is a fundamental advantage of indirect communication - it provides natural buffering and decouples senders from receivers.

Q10. Consider a shared memory implementation of a bounded buffer. The code for the producer and consumer is given, but without any explicit synchronization. Which of the following is a potential issue that could lead to incorrect behavior?

B. The consumer may read the same item multiple times

📖 Explanation:

Without synchronization, all of the listed issues can occur. The producer might overwrite unread data if it writes before the consumer has read the previous item. The consumer might read the same item multiple times if the producer writes slowly and the consumer doesn't properly track what it has consumed. The producer might be blocked if the buffer is full and there's no proper condition for when space becomes available. These are classic race conditions in the producer-consumer problem that require careful synchronization to prevent.

Q11. A system uses message passing for communication. Which of the following scenarios most likely indicates that the system is using zero-capacity buffering?

A. The sender completes immediately after sending
B. The sender is blocked until the receiver calls receive ✅
C. The receiver can receive messages that were sent before it was ready
D. Both sender and receiver can execute concurrently without blocking

💡 Difficulty: medium | ✅ Correct: B

📖 Explanation:

Zero-capacity buffering means there is no queue to store messages. Therefore, the sender must block until the receiver actually receives the message. This is known as a rendezvous - both sender and receiver must be ready for the communication to complete. In contrast, bounded and unbounded buffering allow the sender to continue if there is space in the buffer, regardless of whether the receiver is ready. Option B correctly identifies this distinguishing characteristic of zero-capacity buffering.

Q12. A developer incorrectly assumes that using shared memory automatically handles synchronization. What would be the most likely consequence of this error, and why?

D. The shared memory will be automatically deallocated

💡 Difficulty: hard | ✅ Correct: C

📖 Explanation:

The most likely consequence is inconsistent or corrupted data due to race conditions. Shared memory only provides a communication channel - it does not provide any synchronization mechanisms. When multiple processes access shared memory concurrently without synchronization, they can interfere with each other's operations. For example, one process might read a data structure while another is in the middle of updating it, leading to corrupted or inconsistent data. This is a common misconception among developers new to concurrent programming, as they assume the operating system handles coordination automatically.

Chrome's multiprocess architecture uses process isolation, where each renderer process runs in its own separate address space. If a tab's renderer process crashes due to a JavaScript bug or memory issue, the crash is contained within that process because it doesn't share memory with other renderer processes. Other tabs continue unaffected. This demonstrates the importance of process isolation for fault tolerance, where processes serve as protection boundaries. Q14. Consider the following scenario: Process P1 and P2 both have access to mailbox M. P1 sends a message to M, then both P2 and P3 (who also has access to M) attempt to receive from M. Which process receives the message and what is the underlying principle?

📖 Explanation:

When multiple processes are waiting to receive from the same mailbox, the receiver selection depends on the implementation. The system could: (1) allow at most one process at a time to execute receive (ensuring one receiver gets the message), (2) arbitrarily select one receiver, (3) use a round-robin or other scheduling algorithm, or (4) notify the sender about which receiver got the message. Different operating systems implement different policies. This illustrates the design trade-offs in indirect communication - there's no single correct answer, as different systems may choose different approaches based on their requirements.

Q15. A system implements message passing with automatic buffering. Compare this to explicit buffering. Which statement correctly differentiates them?

A. Automatic buffering requires the programmer to manage buffer size
B. Explicit buffering allows better control over memory usage ✅
C. Automatic buffering always uses unbounded queues
D. Explicit buffering cannot handle variable-sized messages

💡 Difficulty: medium | ✅ Correct: B

📖 Explanation:

The key distinction is that automatic buffering means the operating system manages the buffer space (bounded or unbounded capacity) without programmer intervention, while explicit buffering requires the programmer to specify and manage buffer sizes and policies. Explicit buffering gives the programmer more control over memory usage and performance characteristics but places more responsibility on the application. The operating system doesn't always use unbounded queues for automatic buffering - it may use bounded queues, and the programmer may not be able to choose the size. Variable-sized messages are supported by both approaches.

Q16. Two processes communicate using a mailbox. Process A owns the mailbox. If Process A terminates without deleting the mailbox, what happens to any messages still in the queue and to processes that try to send to it?

A. Messages are preserved; sender continues normally
B. Mailbox is deleted with its owner; sender must be notified ✅
C. Messages are redirected to the kernel mailbox
D. Sender can take ownership of the mailbox

💡 Difficulty: medium | ✅ Correct: B

📖 Explanation:

If a process owns a mailbox and terminates, the mailbox disappears (is deleted) along with the owner. This is a fundamental aspect of mailbox ownership in many systems - the mailbox is part of the owner's address space. Any processes that subsequently try to send messages to this mailbox must be notified that the mailbox no longer exists. This prevents orphaned mailboxes and ensures that processes cannot send to nonexistent communication endpoints. The messages in the queue are also lost when the mailbox is deleted, emphasizing the importance of proper lifecycle management.

Q17. Compare the complexity of implementing IPC using shared memory versus message passing. Which statement is correct?

A. Shared memory requires more operating system support
B. Message passing is simpler for distributed systems ✅
C. Shared memory is easier to implement without synchronization
D. Message passing requires less programmer effort for large data

💡 Difficulty: medium | ✅ Correct: B

📖 Explanation:

Message passing is indeed simpler for distributed systems because it naturally handles network communication and doesn't require shared memory across machines. However, for large data transfers, shared memory is more efficient. Shared memory actually requires more programmer effort for synchronization, not less. It's also more complex to set up initially (requiring mmap calls, etc.) but is more efficient once set up. Message passing typically requires more operating system support (system calls for every send/receive), while shared memory only needs OS support for setup, after which normal memory operations are used.

Q18. A process creates a shared memory segment of 4096 bytes using shm_open() and mmap(), writes data to it, but then the consumer process cannot read the data. What is the most likely reason?

The most likely reason is that the consumer didn't use the same name parameter when calling shm_open(). The name parameter is the key that allows different processes to identify and access the same shared memory object. If the producer uses name "OS" and the consumer uses "OS1", they would create/access different shared memory objects. Q19. In a message-passing system, consider the following: The sender uses non-blocking send, and the receiver uses blocking receive. The message queue has bounded capacity and is full. What happens?

A. The sender returns immediately with an error ✅
B. The sender is blocked until space is available
C. The receiver receives the oldest message
D. Both sender and receiver are blocked

💡 Difficulty: easy | ✅ Correct: A

📖 Explanation:

When the sender uses non-blocking send and the message queue is full, the send operation cannot complete because there's no space. In a non-blocking send, the operation returns immediately, typically with an error or a status indicating that the message could not be sent. The sender does not block. The receiver, using blocking receive, will block until a message is available in the queue. This combination of non-blocking send and blocking receive allows the sender to continue processing while the receiver waits, but the sender must handle the error condition when the queue is full.

Q20. The Windows ALPC facility uses three different message-passing techniques based on message size. What is the primary benefit of this approach compared to a single unified method?

A. Simpler implementation and less code
B. Better performance optimization and resource utilization ✅
C. Easier to debug and maintain
D. Compatible with more hardware architectures

💡 Difficulty: medium | ✅ Correct: B

📖 Explanation:

The tiered approach allows Windows to optimize performance and resource usage based on message characteristics. Small messages (≤256 bytes) use the port's message queue with copying - simple and fast. Medium messages use a section object (shared memory) to avoid copying. Large messages allow direct address space access to handle big data efficiently. This provides better performance across the full range of message sizes compared to a single approach that would either be inefficient for small messages (shared memory overhead) or limited for large messages (copying constraints). It's a practical engineering solution to handle varying communication needs.

A. The message is lost

C. The operating system temporarily stores the message and delivers it when possible ✅

💡 Difficulty: medium | ✅ Correct: C

📖 Explanation:

When Mach's sender specifies to "cache the message," the operating system takes temporary custody of the message even though the mailbox is full. This is a specialized option meant for server tasks that need to send one-time replies but must continue processing. The OS will deliver the cached message when space becomes available and send an acknowledgment back to the sender. Only one message per sending thread can be pending this way at a time. This demonstrates Mach's flexible message passing designed for server-client communication where servers need to be responsive even when clients are slow.

Q22. Two processes communicate using POSIX shared memory. The producer writes data and then increments a counter. The consumer reads the counter and then the data. Which of the following is a correct synchronization approach using only the available IPC mechanisms?

A. Use the counter as a synchronization flag without additional mechanisms
B. Implement busy-waiting and memory barriers
C. Implement a semaphore using shared memory
D. Use an atomic compare-and-swap operation on the counter ✅

💡 Difficulty: easy | ✅ Correct: D

📖 Explanation:

In POSIX shared memory, the only IPC mechanism provided is shared memory itself. To properly synchronize, processes need to implement their own synchronization using atomic operations. An atomic compare-and-swap (CAS) operation on a shared counter is a standard approach - it can be used to implement spinlocks or other synchronization primitives without requiring external OS support. Simply using the counter as a flag without atomicity leads to race conditions. Busy-waiting with memory barriers can work but is less efficient. The key insight is that processes must implement their own synchronization using atomic operations on shared memory, as the OS doesn't provide built-in synchronization for shared memory communication.

Q23. Consider a system where process A needs to communicate with process B, but they are on different machines connected by a network. Which IPC mechanism would be most appropriate and why?

A. Shared memory, because it's faster
B. Message passing, because it supports distributed communication ✅
C. Pipes, because they're simple
D. Mailboxes, because they're flexible

💡 Difficulty: easy | ✅ Correct: B

📖 Explanation:

Message passing is the most appropriate because it naturally supports communication across networks. In message-passing systems, messages can be sent over network connections (using protocols like TCP/IP), allowing processes on different machines to communicate. Shared memory requires a shared address space, which is difficult to implement across machines (though distributed shared memory exists, it's complex). Pipes are typically limited to processes on the same machine. Mailboxes, while useful, are just one implementation of message passing. This highlights the key advantage of message passing over shared memory - it naturally works in distributed environments.

Q24. In the producer-consumer problem using message passing, the producer code is shown with send(next_produced) and the consumer with receive(next_consumed). What would happen if both used non-blocking operations and the queue was empty?

A. The producer would be blocked
B. The consumer would receive a null message ✅

💡 Difficulty: easy | ✅ Correct: B

📖 Explanation:

With non-blocking receive, the consumer would receive either a valid message or a null message (or error indicator) if no message is available. The consumer would not block. The producer would continue execution regardless. This is different from blocking receive, where the consumer would wait until a message arrives. Non-blocking operations provide more flexibility but require the application to handle cases where no message is available (by checking for null or handling errors). The producer-consumer problem becomes more complex with non-blocking operations because the consumer must handle the case of no messages being available gracefully.

In indirect communication using mailboxes, there is no automatic prevention of a process receiving its own messages unless explicitly implemented. This is a design consideration - some systems may choose to prevent this (by checking sender ID), while others may not. Q26. Compare the use of connection-oriented (TCP) sockets versus datagram (UDP) sockets for IPC. Which statement correctly identifies a difference relevant to reliability?

A. TCP provides reliable ordered delivery; UDP does not guarantee delivery ✅
B. UDP is more reliable than TCP
C. Both provide the same reliability guarantees
D. Neither provides any reliability guarantees

💡 Difficulty: medium | ✅ Correct: A

📖 Explanation:

Connection-oriented TCP sockets provide reliable, ordered delivery of data. If a packet is lost in transmission, TCP ensures retransmission until it's successfully delivered. Data is delivered in the same order it was sent. UDP (datagram) sockets provide no such guarantees - packets may be lost, duplicated, or arrive out of order. This makes TCP suitable for applications where data integrity is critical (like file transfer), while UDP is used where speed matters more than perfect delivery (like streaming video). This reliability difference is a key consideration in choosing between TCP and UDP sockets for IPC.

Q27. Consider implementing a distributed file system using RPC. Which of the following is a critical issue that must be addressed to ensure correct operation, and why?

B. Network speed variations

💡 Difficulty: easy | ✅ Correct: A

📖 Explanation:

When using RPC in a distributed file system, the client and server may use different data representations (big-endian vs little-endian). Without proper handling, integers might be interpreted incorrectly. RPC systems use External Data Representation (XDR) to define a machine-independent representation, which is marshaled on the client and unmarshaled on the server. This is a critical issue specific to distributed RPC that doesn't occur in local procedure calls. Network speed variations and file system types are handled at lower levels or are implementation details, not fundamental RPC issues.

Q28. In a RPC system using the 'at most once' semantic, a timestamp is attached to each message. The server maintains a history of processed timestamps. What happens if a client resends an old message due to network timeout, but the original message was actually delayed and eventually processed?

A. The server executes the message again, violating 'at most once'
B. The server checks the timestamp, sees it was processed, and ignores the duplicate ✅
C. The server crashes due to duplicate processing
D. The client is notified that the message was already processed

💡 Difficulty: easy | ✅ Correct: B

📖 Explanation:

In the 'at most once' semantic, the server maintains a history of timestamps of messages it has already processed. When a duplicate message arrives (same timestamp), the server checks its history, finds the timestamp, and ignores the duplicate. This ensures the RPC is executed at most once. The server doesn't need to notify the client (unless the client requests it), and it certainly doesn't crash. This demonstrates how timestamps and history mechanisms work together to prevent duplicate execution in RPC systems.

Q29. A server in an RPC system fails after receiving a request but before sending the ACK. The client resends the request. The server recovers and processes the request again. Which semantic is being violated and why?

A. Exactly once, because the request was executed twice ✅
B. At most once, because it was executed twice
C. Both exactly once and at most once
D. Neither, because the server failure wasn't the client's fault

💡 Difficulty: hard | ✅ Correct: A

📖 Explanation:

The 'exactly once' semantic is violated because the request was executed twice. 'At most once' allows a request to be executed zero or one time, but not more than once. 'Exactly once' guarantees the request is executed exactly once. With the server failure, the request was processed once before failure, and again after recovery. To implement 'exactly once', the server needs to maintain persistent state across failures so it can know which requests it has already processed, preventing duplicate execution even after recovery. This is a challenging problem that requires careful design of the RPC system.

Q30. A system implements RPC and uses a rendezvous (matchmaker) daemon for dynamic binding. What is the advantage of this approach over fixed port numbers, and what is the trade-off?

A. Fixed ports are more flexible; dynamic binding is faster
B. Dynamic binding allows port changes without recompiling; adds initial overhead ✅
C. Dynamic binding is more secure; fixed ports are simpler
D. Both approaches have identical characteristics

💡 Difficulty: medium | ✅ Correct: B

📖 Explanation:

Dynamic binding via a rendezvous daemon allows servers to change their port numbers without requiring client programs to be recompiled. Clients first contact the rendezvous daemon on a fixed port to get the current port address of the RPC service they need. This provides flexibility but adds overhead for the initial lookup step. Fixed port numbers are simpler and faster but lack flexibility - if the server needs to change ports, all clients must be updated. The trade-off is flexibility versus overhead and complexity. This is a classic design trade-off in distributed systems.

Q31. Consider a system where processes communicate via sockets. A client on host X (IP: 146.86.5.20) connects to a web server (IP: 161.25.19.8, port 80). The client is assigned port 1625. Another process on host X also wants to connect to the same web server. What port can it use?

💡 Difficulty: easy | ✅ Correct: B

📖 Explanation:

Each connection must be unique and identified by a pair of sockets: (client IP:client port) and (server IP:server port). If another process on the same host wants to connect to the same web server, it must use a different client port. Ports above 1024 are available for client use (ports below 1024 are well-known/reserved for servers). The new process cannot use port 1625 as it's already in use by the first connection. It also cannot use port 80 as the source port - that's the destination port. This ensures that each connection is uniquely identifiable.

Q32. A developer decides to use UNIX pipes for IPC between two unrelated processes on different machines. Is this feasible, and if not, why?

Q34. Consider the following communication scenario: Process A sends a message to Process B using synchronous send and synchronous receive. Process B then sends a reply using the same mechanism. Describe the entire interaction sequence.

Q36. In a message-passing system, which of the following is NOT a valid combination of send and receive semantics?

Q40. Consider a system where both shared memory and message passing are available. For an application that needs to exchange large amounts of structured data frequently between two processes on the same machine, which approach would be more efficient and why?

For large, frequent data exchanges on the same machine, shared memory is more efficient. Q41. What is the primary reason that shared memory suffers from cache coherency issues on multi-core systems, and how does message passing avoid this problem?

C. Shared memory uses virtual memory; message passing uses physical memory
D. Shared memory lacks hardware support; message passing has hardware support

💡 Difficulty: medium | ✅ Correct: B

📖 Explanation:

On multi-core systems, when shared data is accessed by multiple cores, the data can migrate between the different caches of each core. This is a fundamental difference in how the two models handle data, and it has significant performance implications on multi-core systems.

Q46. A system implements RPC with exactly-once semantics. During a network partition, the client sends a request that doesn't reach the server. The partition resolves and the client resends the request. What additional mechanism is needed beyond at-most-once for exactly-once?

A. Timestamp checking only
B. Client-server acknowledgments plus periodic resends ✅
C. Increased timeout values
D. Message prioritization

💡 Difficulty: easy | ✅ Correct: B

📖 Explanation:

Exactly-once requires more than just at-most-once. In addition to the server's history mechanism to prevent duplicate execution, the system needs: (1) The client must periodically resend the request until it receives an acknowledgment (ACK) from the server, and (2) The server must send an ACK to confirm execution.
