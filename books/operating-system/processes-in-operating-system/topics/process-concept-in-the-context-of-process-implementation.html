Q1. A user double-clicks a program icon, and the operating system loads the executable into memory. Which of the following sequences best describes the transformation that occurs?

🔹 A. The executable file itself becomes the process, and its text section is copied to the heap.
🔹 B. The program (passive entity) on disk is loaded into memory, becoming an active process with its own program counter, registers, stack, and data sections.
🔹 C. The CPU directly executes the file from disk without loading it into memory, making the file a process.
🔹 D. The operating system creates a new thread of execution within the kernel, and this thread represents the process.

💡 Difficulty: medium | ✅ Correct: B

📖 Explanation:

This question tests the fundamental distinction between a program and a process. A program is a passive entity, an executable file stored on disk. When loaded into memory, it becomes an active process, a program in execution. The process includes not just the code (text section) but also the current activity (program counter, registers), stack, and data section. Option B correctly identifies this transformation. Option A incorrectly associates the text section with the heap. Option C is incorrect because the CPU cannot execute a file directly from disk; it must be loaded into memory. Option D incorrectly describes process creation as the creation of a kernel thread.

Q2. Consider a system with multiple cores running a web browser with several tabs open. Each tab is a separate process. If a JavaScript error in one tab causes its renderer process to crash, what is the most likely outcome for the other tabs and why?

🔹 A. All tabs will crash because they are part of the same web browser process.
🔹 B. Only the crashing tab will crash; other tabs and the browser process will continue running due to the isolation provided by the multiprocess architecture.
🔹 C. The entire operating system will crash because of the kernel-level error.
🔹 D. The browser will restart automatically, losing all tabs, to recover from the error.

💡 Difficulty: easy | ✅ Correct: B

📖 Explanation:

This question applies the concept of process isolation to a real-world scenario, the Chrome browser's multiprocess architecture. Each tab runs in a separate renderer process. This isolation ensures that a crash in one process does not affect others. Option B is correct because the architecture is designed to contain failures. Option A is the misconception that a single application is a single process, which is true for simpler browsers but not for modern ones like Chrome. Option C is an overestimation of the impact; user-space process crashes rarely crash the OS kernel. Option D is incorrect as the browser does not need to restart; only the crashed tab process is affected.

Q3. A programmer observes that a program running on an embedded device, which does not support multitasking, still requires the operating system to manage memory. How does the operating system perform this task without creating a separate user process?

🔹 A. It cannot; memory management is impossible without user processes.
🔹 B. The operating system schedules this internal activity as a process, even if it doesn't support user multitasking.
🔹 C. It uses a timer interrupt to pause the main program and execute memory management routines in the kernel's context.
🔹 D. It loads a special memory management module as a user process when needed.

💡 Difficulty: easy | ✅ Correct: C

📖 Explanation:

This question explores the concept that 'process' is a broad term for all CPU activities, including system tasks. In an embedded system without user multitasking, the OS still needs to perform internal tasks. Option C is correct because memory management is typically handled by the kernel, often in response to interrupts, without being a separate user process. Option A is false; memory management is a core OS function. Option B is incorrect in the context of a system that 'does not support multitasking'; while the OS code executes, it isn't a process in the user-space sense. Option D is incorrect as internal tasks are not loaded as user processes; they are part of the kernel.

Q4. A process in memory is often depicted as having a text section, data section, heap, and stack. If a recursive function is called deeply, which part of the process's memory layout is most likely to grow and potentially cause a stack overflow?

🔹 A. Text section
🔹 B. Data section
🔹 C. Heap
🔹 D. Stack

💡 Difficulty: medium | ✅ Correct: D

📖 Explanation:

This question tests understanding of the function of each memory segment in a process. The stack is used for temporary data like function parameters, return addresses, and local variables. Deep recursion pushes many stack frames, causing the stack to grow. Option D is correct. The text section (A) contains the program code and is fixed. The data section (B) contains global and static variables. The heap (C) is used for dynamically allocated memory. A stack overflow is a classic error related to the stack segment's growth exceeding its limit.

Q5. A program has multiple instances running, each with its own set of data. Which of the following statements is true regarding these instances?

🔹 A. They are considered the same process because they execute the same code.
🔹 B. They are separate processes because, although the text sections may be equivalent, each has its own data, heap, and stack sections.
🔹 C. They must share the same memory space to be considered processes.
🔹 D. They are considered threads of the same process, not separate processes.

💡 Difficulty: medium | ✅ Correct: B

📖 Explanation:

This question distinguishes between a program and multiple instances of it. Each instance of a running program is a separate process. While the text section (the code) is often the same, each process has its own independent data, heap, and stack. Option B correctly identifies this. Option A is incorrect; sharing code does not make them the same process. Option C is incorrect; processes can have separate address spaces. Option D is incorrect; multiple instances of a program are processes, not threads of the same process, unless explicitly designed otherwise.

Q6. A user opens multiple copies of a web browser program on a single-user system. The operating system has no built-in limit on the number of copies. Which part of the process's memory is definitely NOT shared between these copies?

🔹 A. The text section, as it contains the program code.
🔹 B. The heap, as it contains dynamically allocated memory for each instance.
🔹 C. The stack, as it contains temporary data specific to each execution.
🔹 D. Both the heap and the stack are independent for each process.

💡 Difficulty: easy | ✅ Correct: D

📖 Explanation:

This question tests the application of process memory structure to multiple instances. Each instance (process) has its own, independent memory segments. While the text section (code) could be shared in memory for efficiency, the heap and stack are always private to each process to maintain isolation. Option D correctly states that both heap and stack are independent. Option A is a distractor; text sections are often shared to save memory, but they are the one segment that could be shared. Options B and C are partially correct but not the most complete answer. Option D is the most comprehensive and correct.

Q7. If the program counter of a process is corrupted, what is the most immediate and critical consequence for that process's execution?

🔹 A. The process will continue normally as the instruction cache will correct the error.
🔹 B. The process will attempt to execute the next instruction from a random or incorrect memory address, likely leading to a segmentation fault or illegal instruction exception.
🔹 C. The operating system will automatically repair the program counter using its saved state.
🔹 D. The process will be terminated and its resources immediately deallocated.

💡 Difficulty: hard | ✅ Correct: B

📖 Explanation:

This question assesses understanding of the role of the program counter. The program counter holds the memory address of the next instruction. If corrupted, the CPU will fetch the next instruction from the wrong address. Option B correctly identifies this consequence. Option A is false; hardware does not auto-correct such errors. Option C is incorrect; the OS cannot repair a corrupted program counter; it can only handle the resulting exception. Option D describes the eventual outcome after an exception, but the 'immediate' consequence is fetching the wrong instruction.

Q8. A process is in the 'Waiting' state. Which of the following scenarios best describes why it is in this state?

🔹 A. It is currently being executed by the CPU.
🔹 B. It is waiting for its turn to be assigned to a processor.
🔹 C. It has finished execution and is waiting to be removed.
🔹 D. It is waiting for an I/O operation to complete.

💡 Difficulty: easy | ✅ Correct: D

📖 Explanation:

This is a direct recall question about the definition of process states. A process in the 'Waiting' state is blocked and cannot continue until some event, such as an I/O completion or a signal, occurs. Option D is the classic example. Option A describes the 'Running' state. Option B describes the 'Ready' state. Option C describes the 'Terminated' state.

Q9. An operating system using a preemptive scheduler has a high-priority process in the Ready queue. A low-priority process is currently Running. What sequence of state transitions must occur for the high-priority process to execute?

🔹 A. Running -> Ready -> Running
🔹 B. Running -> Waiting -> Running
🔹 C. Running -> Terminated
🔹 D. Running -> Ready (for low-priority) and Ready -> Running (for high-priority)

💡 Difficulty: easy | ✅ Correct: D

📖 Explanation:

This question applies the concept of process states to scheduling. In a preemptive system, the scheduler can interrupt the Running process and move it to the Ready state. The high-priority process then transitions from Ready to Running. Option D describes this two-step process. Option A is incorrect; the low-priority process doesn't go Running->Ready->Running without the high-priority process. Option B is incorrect; the low-priority process is not waiting for an event. Option C is incorrect; the process is preempted, not terminated.

Q10. A process is in the 'Ready' state. After a context switch, the operating system selects this process to run on the CPU. What happens to the process's state?

🔹 A. It transitions from Ready to Waiting.
🔹 B. It transitions from Ready to Running.
🔹 C. It transitions from Ready to New.
🔹 D. It remains in the Ready state.

💡 Difficulty: easy | ✅ Correct: B

📖 Explanation:

This is a direct recall question on state transitions. When the CPU scheduler selects a process from the ready queue, the process moves from the 'Ready' state to the 'Running' state. Option B is the correct transition. Option A is incorrect; that would happen if it requests I/O. Option C is incorrect; it's already past the 'New' state. Option D is incorrect; it is no longer waiting in the ready queue.

Q11. An application programmer observes that a program sometimes executes correctly and other times hangs, failing to respond. After debugging, they find a deadlock condition. This bug is most likely related to which part of the process?

🔹 A. The process's text section being corrupted.
🔹 B. The process's heap memory being full.
🔹 C. The process's stack overflowing.
🔹 D. The process's inability to access a shared resource due to a conflict with another process.

💡 Difficulty: hard | ✅ Correct: D

📖 Explanation:

This question links a real-world software bug (deadlock) to the process concept. Deadlock occurs when two or more processes are each waiting for resources held by the other, requiring cooperation and synchronization. Option D correctly identifies this as an inter-process issue. Option A is incorrect; code corruption would cause crashes, not hanging. Option B (heap full) or C (stack overflow) would cause specific errors, not a deadlock, which is about resource contention.

Q12. In a system with a single CPU, which of the following statements about process states is necessarily true?

🔹 A. At most one process can be in the Running state.
🔹 B. At least one process must be in the Ready state.
🔹 C. The number of processes in the Waiting state must be zero.
🔹 D. Only one process can be in the New state at a time.

💡 Difficulty: easy | ✅ Correct: A

📖 Explanation:

This is a direct recall question. On a single-CPU system, only one process can be executing at any instant. Therefore, at most one process can be in the 'Running' state. Option A is correct. Option B is not necessarily true; the ready queue could be empty. Option C is false; many processes can be waiting for I/O. Option D is false; multiple processes can be in the creation phase.

Q13. Which of the following is NOT typically stored in a process's Process Control Block (PCB)?

🔹 A. The value of the program counter.
🔹 B. The contents of the CPU registers.
🔹 C. The local variables of the currently executing function.
🔹 D. The list of open files for the process.

💡 Difficulty: medium | ✅ Correct: C

📖 Explanation:

This question tests the distinction between per-process information (stored in the PCB) and per-instance execution information (stored on the stack). The PCB holds the process's state, program counter, registers, scheduling info, memory management info, accounting info, and I/O status. Local variables of a function are temporary data stored on the stack of that process, not in the PCB. Option C is correct. Options A, B, and D are all classic components of a PCB.

Q14. During a context switch, the operating system saves the state of the currently running process. Where is this state saved?

🔹 A. In the CPU's cache memory.
🔹 B. On the stack of the new process.
🔹 C. In the Process Control Block (PCB) of the process being switched out.
🔹 D. In a special kernel register.

💡 Difficulty: medium | ✅ Correct: C

📖 Explanation:

This question tests the understanding of the PCB's role. The PCB is the repository for all information that varies from process to process. During a context switch, the CPU's state (program counter, registers) is saved to the PCB of the process being suspended. Option C is correct. Option A is incorrect; cache is volatile and not used for persistent state. Option B is incorrect; the new process's stack is for its own data. Option D is incorrect; there is no single 'kernel register' for this purpose.

Q15. The state field in the task_struct of a Linux process is being modified. Which of the following code snippets correctly changes the state of the current process to a new state, new_state?

🔹 D. this_process.state = new_state;

💡 Difficulty: easy | ✅ Correct: B

📖 Explanation:

This is an application question on how to manipulate a field in a Linux PCB. The Linux kernel maintains a pointer called 'current' to the task_struct of the currently executing process. Fields in a structure are accessed using the '->' operator. Therefore, current->state = new_state; is correct. Option B is correct. Option A is incorrect syntax. Option C tries to modify the structure definition. Option D uses a non-existent pointer.

Q16. A system is experiencing high overhead due to frequent context switches. A system administrator proposes reducing the time quantum to increase system throughput. What is the most likely outcome of this change?

🔹 A. Context-switch overhead will decrease, improving throughput.
🔹 B. The number of context switches will increase, potentially increasing overhead and decreasing throughput.
🔹 C. CPU utilization will increase as the CPU spends more time on processes.
🔹 D. Processes will spend more time in the Waiting state.

💡 Difficulty: hard | ✅ Correct: B

📖 Explanation:

This question tests the relationship between context switching, time quantum, and overhead. Reducing the time quantum means the scheduler must switch between processes more often. Each switch is pure overhead. Option B correctly identifies that this will increase the number of context switches and likely increase overhead. Option A is the opposite of what happens. Option C is incorrect; more switching means less CPU time for actual work. Option D is not the primary effect; the primary effect is on the Running and Ready states.

Q17. A developer is designing a new operating system and wants to minimize context-switch time. Which of the following hardware features would be MOST beneficial for this goal?

🔹 A. A large hard disk cache.
🔹 B. A high-speed network interface card.
🔹 C. Multiple sets of processor registers.
🔹 D. A high-capacity main memory.

💡 Difficulty: easy | ✅ Correct: C

📖 Explanation:

This question applies hardware concepts to minimize context-switch overhead. Context switching involves saving and restoring CPU register states. Having multiple sets of registers, as in the Sun UltraSPARC, allows the OS to simply change a pointer to the current register set for a new process, avoiding the time-consuming task of copying all register data to and from memory. Option C is correct. Options A, B, and D do not directly speed up the saving and restoring of CPU registers.

Q18. A parent process creates a child process. Which of the following statements is true about the relationship between them, assuming no resource restrictions?

🔹 A. The parent and child must run the same program.
🔹 B. The parent and child are completely independent and cannot share any resources.
🔹 C. The child process can be a copy of the parent or can load a new program.
🔹 D. The child process must always have a lower priority than the parent.

💡 Difficulty: medium | ✅ Correct: C

📖 Explanation:

This question tests knowledge of process creation mechanisms. A child process can be created as a duplicate of the parent (as in UNIX fork()) or as a new process with a different program loaded (as in Windows CreateProcess() or UNIX fork() + exec()). Option C correctly states these two possibilities. Option A is false; a child can load a new program. Option B is false; parent and child can share resources. Option D is false; priority is not inherently tied to this relationship.

Q19. In an operating system that uses the fork() system call, a parent process creates a child. What is the key difference in the return value of fork() for the parent and the child?

🔹 A. Both get the same process ID.
🔹 B. The parent gets the child's PID, and the child gets 0.
🔹 C. The child gets the parent's PID, and the parent gets 0.
🔹 D. Both get 0.

💡 Difficulty: easy | ✅ Correct: B

📖 Explanation:

This is a direct recall question on the fork() system call. The fork() call returns the process ID of the child to the parent, and returns 0 to the child. This allows each process to execute different code paths. Option B is correct. Options A, C, and D are all incorrect descriptions of the return values.

Q20. A programmer uses a fork() call in a C program. The child process successfully creates a copy of the parent. Then, the child calls exec() to load a new program. What happens to the memory space of the child process?

🔹 A. The child's memory space is unchanged and continues to execute the parent's code.
🔹 B. The child's memory space, including the parent's code and data, is overwritten by the new program.
🔹 C. The child's memory space is deallocated, and the new program runs in kernel memory.
🔹 D. The child's memory space is shared with the parent to save memory.

💡 Difficulty: medium | ✅ Correct: B

📖 Explanation:

This question tests the effect of the exec() system call. The exec() call replaces the calling process's memory image with a new program from disk. It destroys the old memory image (the text, data, heap, and stack) and loads the new one. Option B is correct. Option A is incorrect; that's what happens if exec() is not called. Option C is incorrect; the new program runs in the same process address space, not kernel memory. Option D is incorrect; the memory is overwritten, not shared.

Q21. A C program uses fork() to create a child. The child does NOT call exec() but modifies a global variable. What is the scope of this modification?

🔹 A. The modification is visible to the parent process immediately.
🔹 B. The modification is only visible to the child process, as they have separate memory spaces.
🔹 C. The modification will cause a segmentation fault.
🔹 D. The modification is visible to all other processes in the system.

💡 Difficulty: medium | ✅ Correct: B

📖 Explanation:

This question tests the concept of process address space isolation. When fork() is used, the child is a copy of the parent. They have separate, distinct memory spaces. Any changes the child makes to its data will not be visible to the parent. Option B is correct. Option A is incorrect; processes have separate memory spaces. Option C is incorrect; modifying a global variable is a normal operation. Option D is incorrect; memory spaces are private to a process.

Q22. What is the primary purpose of the wait() system call in the context of process creation and termination?

🔹 A. To create a new child process.
🔹 B. To load a new program into an existing process.
🔹 C. To allow a parent process to wait for the termination of a child process and collect its exit status.
🔹 D. To terminate the currently running process immediately.

💡 Difficulty: easy | ✅ Correct: C

📖 Explanation:

This is a direct recall question about the wait() system call. The wait() call is used by a parent process to pause its execution until a child process terminates. It also allows the parent to receive the child's exit status. Option C is correct. Option A describes fork(). Option B describes exec(). Option D describes exit().

Q23. A process terminates, but its entry in the process table remains. Its parent has not yet called wait(). What is this process called?

🔹 A. A terminated process.
🔹 B. A zombie process.
🔹 C. An orphan process.
🔹 D. A defunct process.

💡 Difficulty: easy | ✅ Correct: B

📖 Explanation:

This is a direct recall question on process termination states. A zombie process is one that has terminated but still has an entry in the process table because its parent has not yet read its exit status via wait(). Option B is correct. A terminated process (A) is a general term. An orphan process (C) is a process whose parent has terminated. While 'defunct process' (D) is another term, 'zombie process' is the standard term used in this context.

Q24. A long-running server process is designed to create many short-lived child processes to handle incoming client requests. If the server process forgets to call wait() for its terminated children, what is the most likely long-term consequence?

🔹 A. The system will run out of memory due to orphan processes.
🔹 B. The system's process table will become full of zombie processes, preventing new processes from being created.
🔹 C. The child processes will continue to run in the background.
🔹 D. The server process will crash due to a stack overflow.

💡 Difficulty: easy | ✅ Correct: B

📖 Explanation:

This question applies the concept of zombie processes to a real-world scenario. If a parent doesn't call wait(), the child processes become zombies. Their resources (memory, etc.) are deallocated, but their entries in the process table remain. Over time, a large number of zombies will fill the process table, preventing the creation of new processes. Option B is the correct consequence. Option A is incorrect; orphan processes are handled by init. Option C is incorrect; they have terminated. Option D is unrelated to this scenario.

Q25. A parent process terminates without waiting for its child processes. In a typical UNIX/Linux system, what happens to these child processes?

🔹 A. They are immediately terminated.
🔹 B. They become zombie processes.
🔹 C. They become orphan processes, and the init process becomes their new parent.
🔹 D. They continue to run as independent processes without a parent.

💡 Difficulty: medium | ✅ Correct: C

📖 Explanation:

This question tests the concept of orphan processes. When a parent terminates, its children become orphans. To prevent them from becoming 'processes without a parent' (which would be unmanageable), the init process (PID 1) is assigned as their new parent. Option C is correct. Option A is incorrect; they are not terminated. Option B describes a terminated process whose parent hasn't waited; an orphan's parent has terminated. Option D is incorrect; they are adopted by init.

Q26. Which of the following scenarios is the BEST example of a cooperating process, as opposed to an independent one?

🔹 A. A command-line calculator that computes a result and exits.
🔹 B. A simple text editor that reads and writes a file without interacting with other applications.
🔹 C. A web browser and a web server communicating over a network to fetch a webpage.
🔹 D. A system utility that checks for disk errors and logs the results.

💡 Difficulty: medium | ✅ Correct: C

📖 Explanation:

This question distinguishes between independent and cooperating processes. A cooperating process is one that can affect or be affected by other processes, often by sharing data. A web browser and server communicate using a network protocol, making them cooperating processes. Option C is the best example. Options A, B, and D describe processes that typically run in isolation and do not share data or coordinate with other processes.

Q27. Two processes are designed to solve the same computational problem. Process A uses a shared-memory model, and Process B uses a message-passing model. What is the primary advantage of Process A's approach?

🔹 A. Simpler to implement in a distributed system.
🔹 B. More secure, as it does not require kernel intervention for data exchange.
🔹 C. Potentially faster, as data access after setup is similar to routine memory accesses, avoiding system calls for each data transfer.
🔹 D. Easier to implement, as it handles all synchronization automatically.

💡 Difficulty: easy | ✅ Correct: C

📖 Explanation:

This question compares shared memory and message passing. Shared memory can be faster because once the shared region is established, all accesses are routine memory reads/writes, requiring no further system calls. Message passing typically involves a system call for each send/receive, which is more time-consuming. Option C captures this advantage. Option A is a disadvantage of shared memory (harder in distributed systems). Option B is incorrect; shared memory has fewer kernel calls but is not more secure. Option D is incorrect; shared memory requires explicit synchronization by the programmer.

Q28. Which of the following is a fundamental requirement for two processes to communicate using a shared-memory model?

🔹 A. They must both be children of the same parent process.
🔹 B. The processes must agree to remove the memory protection restriction that prevents one process from accessing another's memory space.
🔹 C. The operating system must copy the data from the sender's memory to the receiver's memory.
🔹 D. The communication must be synchronous.

💡 Difficulty: medium | ✅ Correct: B

📖 Explanation:

This question tests the foundational requirements for shared memory. The operating system normally enforces memory protection to prevent processes from interfering with each other. For shared memory, this restriction must be explicitly lifted for a specific region, and both processes must agree to attach to this region. Option B describes this. Option A is incorrect; unrelated processes can use shared memory. Option C describes message passing. Option D is incorrect; shared memory communication can be asynchronous.

Q29. In the producer-consumer problem with a bounded buffer, the buffer is empty when in == out. What is the condition for the buffer being full in the implementation described where at most BUFFER_SIZE - 1 items can be stored?

🔹 A. in == out
🔹 B. ((in + 1) % BUFFER_SIZE) == out
🔹 C. in == BUFFER_SIZE
🔹 D. out == BUFFER_SIZE - 1

💡 Difficulty: easy | ✅ Correct: B

📖 Explanation:

This question tests recall of a specific implementation detail of the bounded buffer. In the circular buffer implementation, to differentiate between the empty and full states, one slot is left unused. The full condition is ((in + 1) % BUFFER_SIZE) == out. Option B is correct. Option A is the condition for an empty buffer, which would be ambiguous if used for 'full' as well.

Q30. A producer process is writing to a shared buffer, and a consumer process is reading from it. The producer has just finished writing an item at the index pointed to by 'in' and has incremented 'in'. What condition could cause the producer to block or wait?

🔹 A. The consumer reads data faster than it can be produced.
🔹 B. The buffer is empty.
🔹 C. The buffer is full, i.e., ((in + 1) % BUFFER_SIZE) == out.
🔹 D. The producer has reached the end of the file it is reading from.

💡 Difficulty: easy | ✅ Correct: C

📖 Explanation:

This question applies the producer-consumer logic. The producer writes items to the buffer. If the buffer becomes full, the producer cannot add more items and must wait for the consumer to consume an item. The full condition is ((in + 1) % BUFFER_SIZE) == out. Option C is correct. Option A would cause the consumer to wait, not the producer. Option B would cause the consumer to wait. Option D is about the producer's input, not the shared buffer.

Q31. A consumer process in a bounded buffer system checks the condition in == out before consuming an item. What action should the consumer take if this condition is true?

🔹 A. It should proceed to consume the item, as the buffer is full.
🔹 B. It should wait or block until the condition is no longer true (i.e., the buffer is not empty).
🔹 C. It should terminate the process.
🔹 D. It should signal the producer to stop producing.

💡 Difficulty: easy | ✅ Correct: B

📖 Explanation:

This question applies the producer-consumer logic from the consumer's perspective. The condition in == out means the buffer is empty, and there is no item to consume. The consumer must wait for a new item. Option B is correct. Option A is incorrect; it means the buffer is empty. Option C is incorrect; it should wait. Option D is incorrect; it should wait for the producer to produce more, not signal it to stop.

Q32. Which of the following is a characteristic of direct communication in message passing?

🔹 A. Communication is done through a shared mailbox.
🔹 B. The sender and receiver must explicitly name each other.
🔹 C. A link can be associated with more than two processes.
🔹 D. The system handles all naming automatically.

💡 Difficulty: medium | ✅ Correct: B

📖 Explanation:

This question tests the definition of direct communication. In direct communication, the sender must explicitly name the recipient, and the receiver must explicitly name the sender (or use an asymmetric variant). Option B is correct. Option A describes indirect communication. Option C is a property of indirect communication. Option D is incorrect; naming is explicit in direct communication.

Q33. Which of the following is a characteristic of indirect communication in message passing?

🔹 A. Processes must explicitly name the recipient.
🔹 B. Communication is done through mailboxes or ports.
🔹 C. A link is associated with exactly two processes.
🔹 D. The system must ensure unique naming for processes.

💡 Difficulty: medium | ✅ Correct: B

📖 Explanation:
