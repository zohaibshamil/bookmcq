What is Design of Program Counter of Simple as Possible (SAP) I Computer?

The program counter in SAP-I is a -bit binary up-counter constructed from JK or D flip-flops that holds the address of the next instruction, automatically increments by after each fetch unless modified by a JMP instruction, and outputs its value to the address bus during the fetch cycle to access memory.

Q1. What is the primary purpose of a program counter (PC) in a CPU?

A.Store operand data
B.Hold address of next instruction ✅
C.Perform arithmetic operations
D.Generate clock signals
💡 Difficulty: easy | ✅ Correct: B

📖 Explanation: The program counter's job is to keep track of where the processor is in the instruction stream, so it must hold the address of the next instruction to be fetched. Option B states this directly, making it correct. Option A describes a register used for data, not control flow. Option C refers to the ALU, and option D describes a clock generator. Understanding the PC’s role clarifies how sequential execution proceeds.

Q2. Why does the program counter need to be incremented after each instruction fetch?

A.To reset the CPU, to prepare for interrupt handling, to point to the next sequential instruction, to store the result of the instruction
B.To point to the next sequential instruction
C.To reset the CPU ✅
D.To prepare for interrupt handling
💡 Difficulty: medium | ✅ Correct: C

📖 Explanation: Each time an instruction is fetched, the PC must advance so the next fetch retrieves the following instruction in memory. This sequential progression is essential for normal program flow, making option C correct. Resetting the CPU (A) or handling interrupts (D) involve other mechanisms, while storing results (B) is the job of registers, not the PC.

Q3. How does a conditional branch instruction affect the program counter?

A.It always adds a fixed offset, it loads the PC with a target address only if the condition is true, it clears the PC, it increments the PC twice ✅
B.It loads the PC with a target address only if the condition is true
C.It always adds a fixed offset
D.It clears the PC
💡 Difficulty: medium | ✅ Correct: A

📖 Explanation: A conditional branch evaluates a test; if true, the PC receives the branch target address, otherwise it continues sequentially. Option A captures this behavior precisely. Adding a fixed offset (B) describes an unconditional relative jump, clearing the PC (C) would halt execution, and incrementing twice (D) is not typical for branches.

Q4. A microcontroller uses a 16‑bit PC that wraps around after reaching its maximum value. If the PC currently holds 0xFFFE and two sequential instructions are executed, what will be the PC value after the second fetch?

A.0 ✅
B.1
C.65535
D.65533
💡 Difficulty: hard | ✅ Correct: A

📖 Explanation: The PC starts at 0xFFFE. After the first fetch it increments to 0xFFFF. After the second fetch it adds one more, producing 0x10000, which cannot be represented in 16 bits, so it wraps to 0x0000. Option A shows this wrapped value. Option B would be the result after only one increment from 0xFFFF, C leaves the PC unchanged, and D subtracts instead of adding. This illustrates wrap‑around behavior in limited address spaces.

Q5. Design a simple PC increment circuit using a binary adder. Which component is essential to ensure the PC correctly wraps from its maximum value back to zero?

A.Zero detector
B.Carry‑out reset ✅
C.Multiplexer
D.Flip‑flop
💡 Difficulty: medium | ✅ Correct: B

📖 Explanation: A binary adder will produce a carry‑out when the PC reaches its maximum (e.g., 1111…111). Resetting the PC to zero requires using that carry‑out to force the next state to zero, making a carry‑out reset circuit essential. Option B provides this function. A zero detector only signals when the PC is already zero, a multiplexer could select inputs but does not handle overflow, and a flip‑flop stores bits without managing wrap‑around.
